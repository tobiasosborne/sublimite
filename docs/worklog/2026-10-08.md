## bd quirks (bd 1.0.0, embedded Dolt)

- Init: `bd init --prefix edit --non-interactive --skip-agents`. It **commits by itself** (commit "bd init: initialize beads issue tracking") and installs hooks via `core.hooksPath=.beads/hooks`. `--skip-agents` kept it from writing AGENTS.md or touching CLAUDE.md and Claude settings.
- The Dolt DB (`.beads/embeddeddolt/`) is git-ignored. Issue data therefore exists only locally unless it is exported. A snapshot is committed as `.beads/issues.jsonl` (`bd export -o .beads/issues.jsonl`). Re-export it at the end of each session. It can be restored with `bd init --from-jsonl`.
- The embedded engine allows **one writer at a time**. A concurrent bd call fails with "another process holds the exclusive lock". Scripts must retry, and parallel workers must not run `bd` writes at the same moment.
- `bd ready` lists the open epics as ready. `--exclude-type epic` is silently ignored. **Use `bd ready --type task`.** `bd ready` also defaults to `-n 10`.
- Command forms that worked:
  - `bd create --type epic --title "P0 Bootstrap" --description "…" --priority 1 --silent` (`--silent` prints only the id)
  - `bd create --type task --title "P1.4 piece tree impl" --description "…" --priority 1 --labels mode:best,model:sonnet,review:codex --parent edit-4w1 --silent`
  - `bd dep add <bead> <depends-on>` (the bead is blocked by the second id; same as `--blocked-by`)
  - `bd list --parent edit-zzj`, `bd dep tree <id>`, `bd dep list <id>`, `bd dep cycles`, `bd label list-all`
  - Labels are set at create time with `--labels`; later changes use `bd label add <id> <label>`.
- `bd dolt commit -m …` reported "Nothing to commit" (writes were already committed in Dolt).
