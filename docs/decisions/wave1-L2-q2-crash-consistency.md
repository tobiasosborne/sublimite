# Save preparation without retaining the previous file

**REFUTED at target rename.** A saved snapshot can serve as the replay base for the buffer that produced it. A second buffer can have acknowledged text that still depends on bytes omitted from that snapshot. A synced PREPARED record identifying the correct new file and cutoff does not supply those bytes. This failure needs no concurrent edit, external writer, failed barrier, stale identity match or undo across the save.

## A crash that loses acknowledged text

Let the target be the only name for a file containing an arbitrary nonempty byte string `X`. Choose `X` longer than the BASE prefix and any fixed-size identity or digest. Buffers A and B independently open that file. Use the supported named BASE plus logical edits representation for both. B inserts a literal exclamation mark at the beginning and receives its edit acknowledgment. A deletes all its text, receives its acknowledgment and saves the empty snapshot. Sync the journal through PREPARED. At this point the old path plus the journal reconstruct A as empty and B as `!` followed by `X`. DELETE recorded a position and length. B's INSERT recorded the exclamation mark. Neither recorded the contents of `X`. The same-path obligation and this checkpoint representation are explicit in the oracle. [Journal save and rotation contracts](/home/tobias/Projects/sublimite-v1-oracle/src/journal/journal.h:169) · [Logical edit decoder](/home/tobias/Projects/sublimite-v1-oracle/src/journal/journal.c:409)

Rename the synced empty temporary over the target, then kill the editor at `FILE_STEP_RENAMED`. The kernel still names the new file. Process death releases the last old fd, mapping and snapshot. Recovery can verify the empty target perfectly and reconstruct A exactly. For B, verifying its BASE fails. Substituting the new file and replaying B's valid INSERT produces just `!`, silently dropping `X`. Skipping B's pre-cutoff history also loses its acknowledged insertion. The correct reader reports an unresolved BASE and preserves the journal, but cannot return B's acknowledged text. Moving the kill to just after successful target-directory sync gives the same loss on machine restart. The old file's identity, even augmented by a digest, can recognize supplied bytes but cannot reconstruct an arbitrary missing payload. The oracle explicitly substitutes *every* matching BASE during preparation for this reason. ## Durable state at each stop

`O` is the verified old named generation, `N` the completed temp inode containing A's snapshot `S`, and `s` A's last complete command boundary represented by `S`. “Old replay” starts each buffer at its own verified BASE and applies its complete groups. “New replay” starts A at `N` and applies only A's complete text operations strictly after `s`. Tab state, views, generation declarations, other buffers and other pending tokens have their own replay requirements. A session-wide skip to the byte following `s` would discard some of them.

Start with a durable target name, a durable journal name and a verified recoverable checkpoint. For this trace, fully validate the temp against `S`, assume correct recognition of either target, keep the journal cutoff addressable, and admit no old-generation reference in A's suffix. Distinguish the kernel-visible prefix after a process kill from the valid on-storage prefix after power loss. A complete accepted record in the named journal suffices for SIGKILL. A successful sync guarantees that prefix against power loss. A later complete group may also have reached storage. An incomplete group contributes no edit. The table assumes working storage and atomic crash recovery of the target rename to the old or new name binding. An unexpected binding or I/O error requires a conflict or recovery error. ## Where the cutoff and the by-value rule hold

For A, bytes at the new base equal bytes at `S`. A logical delete at a given offset and length, or a literal insert at a given offset, maps equal input texts to equal output texts. Induction over complete groups after `s` proves exact replay **if every operand is available**. Old-generation references used exclusively in A's folded prefix then cost nothing at recovery. A by-value undo of length `L` writes `L` payload bytes (P, sum of the emitted run lengths), plus record/group framing. Validate the held source through the final dependent load, finish journal acceptance through group commit, then expose the edited frame and successful ACK. Keep partial append progress and withhold success on error. This argument grants the saving buffer the intended common-case saving. The boundary for that proof is the **snapshot**, which precedes the proposal's synced PREPARED marker. If input can progress while the temp is written, let A delete a long contiguous `X`, capture empty `S`, then undo and acknowledge by BASE-range before PREPARED. After rename, the post-`s` suffix needs `X` and the new base is empty. Applying (b) from snapshot capture, serializing that interval against such publications, or durably converting the already accepted suffix before rename would close this separate hole. The same constraint applies to checkpoint encoders that can emit old BASE ranges. The sibling trace above allows the interval to be completely quiescent. ## In-place rewrite of the mapped inode

Rename-over can leave the held old inode readable. An in-place overwrite changes the source under the tree's existing ORIGINAL coordinates. Descriptors, snapshots and inverse spans can still exist while the old bytes they denote are gone. On detected change, mark the mapped source conflicted. Validate identity/change observations as well as the fault registration. Same-size writes may never fault. Hold the backing through the closing fault poll after the last dependent load. Abort an unpublished stale restore, including a yielded group, with the history cursor and journal group unchanged. Suppress dependent publication and offer conflict/reload. Reload installs a freshly acquired tree and history domain. Surviving old snapshots own their backings until physical release. The existing tree cannot rebind old offsets to the rewritten contents or publish substituted zeroes. Immutable COPY originals, private ADD and captured literal payloads retain their own bytes. A literal alone cannot validate the rest of a conflicted tree. [Mapped ORIGINAL guarantee](wave1-piece-pool.md#i-what-a-mapped-original-guarantees) · [Piece span provenance](../../src/piece/piece.h#L134) · [Closing fault poll](../../src/os/os.h#L366)

Detection copies **zero old bytes** (P, invalidating a source and aborting a provisional operation require no byte capture). For a deletion of length `L` described by `sᵣ` coalesced runs, capture `L` literal bytes only when `16sᵣ > L`. Otherwise the inverse records spans and copies zero deleted source bytes (G, signed inverse rule. P, 16 B per pair of 8 B words). Previously captured literal payload across reachable history is bounded by the sum of the corresponding deleted lengths (P, summing those captures, excluding allocator occupancy and ADD lifetime). A by-value journal restore copies only its validated restored runs when performed. Long stale ranges get a conflict. There is no post-overwrite history-copy procedure capable of restoring destroyed bytes. This history bound does not cover the independent live document B in the rename trace.
