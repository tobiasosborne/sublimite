# P1.5e — atomic undo group replay (edit-4w1.40)

This resolves BLOCKER 1 in `docs/reviews/P1.5-1.md` using the checkpoint on
main (`1f029d9`), under the frozen P1.3c amendment. It supersedes P1.5d's
failure/retry and clear/destroy semantics. No piece header/kernel, editor source,
build file, coordinator document or corpus is changed.

## Group transaction and undo scratch

Both directions begin one piece checkpoint before the group's first mutation.
At the group boundary, commit consumes it. A piece failure, capture admission
failure or failure to acquire a slice guard aborts it. Begin failure has no
document effect. An error returns with the current group entirely restored;
groups completed earlier in the batch remain committed. No inverse piece
operations run during rollback, so a persistent failing allocator cannot strand
the document. A rejected opposite replay/invalid caller request leaves a normal
slice transaction available for its owner to continue.

Undo saves the group's cursor, tail, applied/record counts, packed-storage mark
and the boundary state/index blobs before mutation. Each unknown capture in a
multi-operation group journals the full original span record in undo-owned
scratch before calling piece_delete. The unknown record's unused add_off word
stores its handle in that private copy. On abort, undo restores these records
in reverse, repairs their next neighbors, restores boundary indexes/states and
resets the appended span suffix. This discards every ref first produced inside
the aborted checkpoint, as P1.3c requires. Existing committed refs survive.
Known replay records need no backup: their refs and links do not change. A
single-operation group needs no capture backup because its successful mutation
and capture are followed immediately by the allocation-free, infallible commit.

Scratch uses a separate lazy edit_pool reserved by undo_init, with capacity
for every admitted unknown insertion. There is no heap allocation, group scan
or group-sized copy at replay begin, and no new allocation on editing's typing
path. Saving a capture is constant work in addition to its existing bounded
span expansion. Completion resets/decommits scratch without a record walk.
Abort's metadata restore visits the captures in that group; it allocates
nothing. All scratch slots and committed pages, including conservative charges
after failed decommit, appear in undo_stats; replay_records distinguishes these
temporary unpublished span copies. live_bytes/committed_bytes/reserved_bytes
include both mappings. G10f ownership calculations charge scratch records and
the rounding of each actually committed mapping. Scratch is not historical
retention, and inactive virtual reservation is not a physical charge.

While checkpointed, undo_maintain returns zero and trim is deferred. This keeps
saved handles and the expansion suffix stable. Maintenance resumes at the
boundary; the usual bounded retirement and whole-group cap policy still apply.
undo_get_stats reports undo/redo group position at the pre-group boundary while
the cursor is provisional. Capture expansion and scratch memory remain visible.

## Slices and exclusive mutation ownership

One checkpoint spans all slices of one group, including zero-budget/deadline
yields. UNDO_MORE still yields between piece mutations. Only the same replay
direction can advance it. Edits, explicit group begin, cap changes and opposite
replay return BUSY. No caller may invoke any direct piece mutation on this tree
between slices. Queries and immutable snapshots for workers remain allowed.
clear and destroy abort an open checkpoint before discarding history; the tree
must outlive the log.

To assert exclusive mutation ownership without scanning document bytes or
reading a private piece layout, undo retains a current-tree snapshot at yield
and checks its identity on resume/clear/destroy. The linked in-tree kernel caches
one immutable header until a mutation invalidates it. A retained owner prevents
cache eviction or address reuse, including on an empty tree. Retaking an
unchanged cached snapshot allocates nothing. This catches a same-length change,
even deletion/reinsertion of identical bytes; it also rejects a direct mutation
attempt that invalidates the cache before failing. Acquisition failure at yield
is an ordinary atomic replay failure, followed by checkpoint abort.

This assertion relies on an explicit implementation property of the current
kernel (`piece_snapshot_take`, `snapshot_uncache`, `owner_trim` in piece.c),
not a portable identity promise in the frozen piece.h. A replacement kernel
must preserve this property or supply a generation/ownership check before it
can replace this guard. No frozen header amendment is made by this bead.

A borrowed pre-group view remains necessary during normal sliced replay because
the mutable tree contains a provisional prefix. Render/save that view until the
boundary. The piece checkpoint is the rollback mechanism; the public view is
for rendering/saving only. The caller may retain the view beyond the boundary.
The identity guard is a separate intermediate snapshot, released before the
next mutation or terminal checkpoint operation.

Deadlines and operation budgets are checked before each mutation. As with
P1.5d, the piece API cannot preempt a costly individual mutation or snapshot
acquisition. Checkpoint terminal operations and the synchronous failure-metadata
restore are also indivisible; this API does not promise to interrupt them.

## Result contract and removed stand-ins

On success/MORE, change contains this call's successful operations/span records,
completed groups, their last boundary state and conservative dirty interval.
MORE's in-group operations are provisional. On error, change contains only
groups completed in this call; the failed group's operations, records, dirty
contribution and boundary state are discarded. If the failed group started in
an earlier slice, those earlier provisional counters must also be discarded.
Their accumulated dirty union still covers the bytes restored by abort. Retry
uses the uncompleted group count and starts at the pre-group cursor.

Removed P1.5d stand-ins:

- NOMEM's retained successful prefix/retry position and indefinite partial lock:
  replaced by checkpoint abort and undo metadata restoration.
- Retaining the pre-group rendering view across NOMEM as the only safe document:
  an error now restores the actual tree and releases the view/guard.
- clear/destroy's acceptance of an intermediate replay document: both now abort.
- The atomic regression's UNDO_TEST_REQUIRE_ATOMIC_GROUP environment gate and
  default SKIP message: review_1 is unconditional.

Retained UNDO_MORE, sliced entry points, operation counts and
undo_replay_snapshot: these implement actual normal slice yields and rendering,
so they are not redundant shims. No undo.h function signature changed and no
editor caller fix was required. The private caller-owned struct and statistics
gain checkpoint/scratch fields; callers rebuild through the existing includes.
