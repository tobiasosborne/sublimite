# P4.7 — standalone save and external-change controller (edit-457.7)

## Decision

`src/savectl/savectl.h` exposes a per-buffer controller. The UI owns its state,
revision counter, latest view offsets, and the live piece tree. Workers receive
only a piece snapshot and immutable task inputs. Worker results cross a
`src/work` mailbox, with a release/acquire completion flag as fallback if the
mailbox is full. Completion is released before the mailbox wake; after that
release the worker uses only its pool context/local message, never the controller.
This prevents a wake arriving with no visible completion and no later wake.
One operation is outstanding per controller. There are no new
module globals. `savectl_modified`, view updates, and idle ticks allocate nothing.

Save acknowledgement takes the snapshot, enqueues a bulk job, and changes the
model to `saving`. It does not stat, open, read, wait, or sync. A later mutation
increments the revision; completion clears modified only if the saved revision
still matches. Repeated Ctrl+S while busy returns BUSY rather than silently
promising to save a later revision. Save on an external conflict refuses until
keep/reload resolves it. Keep adopts the checked target identity, preserves the
buffer, and marks it modified: its contents differ from the adopted generation.

The worker calls the current public `file_save_write` core: temp in the target
directory, data fsync, identity validation, rename, and retained-directory fsync.
No implementation or header changes to file/journal/editor are needed. Target
identity is checked immediately before rename by the file core; a controller
epoch and optional source guard are checked before work, during writing, and
immediately before rename. An event invalidates that epoch without cancelling
the work handle: cancelling the handle would suppress the completion needed to
retire snapshots and recovery tokens. The caller separately invalidates find
and index generations as required by perf §2.14.

The states are idle, saving, saved, failed, external-changed modified/unmodified,
and reloading. The model carries literal status text, banner text, action
availability, modified/busy flags, file/journal errors, and errno. Errors before
rename leave the target intact. DIRSYNC means replacement happened but durability
is uncertain: the controller remains modified/failed and adopts the replacement
identity. It never reports saved on a failed durability or journal barrier.

## Journal transaction and ownership

With a journal, the save worker executes `journal_save_prepare`, then the file
core, then `journal_capture_base` and checks that the captured identity equals the
replacement. `needs_finish` returns the UI lease along with the new BASE and
retained save token. The UI supplies a COMPLETE CURRENT-session checkpoint to
`savectl_finish`; a worker calls `journal_save_finish`. The model becomes saved
only after finish succeeds. Without a journal, FILE_OK is sufficient.

The actual journal pool must be private and distinct from the controller pool.
The options require that pool pointer and reject equal/missing pools. The opaque
journal API prevents verifying that the supplied pointer really is its pool.
Prepare/finish may synchronously flush and submit retention jobs and drain that
pool; running them on the same single bulk worker would deadlock. They run on
the controller worker, never the UI. Only this controller can lease a given
journal at a time; the session router serializes save transactions across buffers.
All checkpoint records and data remain borrowed and immutable during their lease.

The caller must defer journal operations (across the WHOLE session) while
`journal_leased` is true. Edits may still update the UI tree, but deferred journal
records are not acknowledged as journaled until appended after the lease returns.
Flush the deferred operations into the retained generation before building the
finish checkpoint; include every buffer, view, tab, in-flight BASE and SAVE
marker. Do not mutate between checkpoint construction and its request call.
Edits during finish need the same deferred-record treatment after finish returns.
A capacity or journal error must surface recovery suspension, not discard edits.
The controller is not a complete session checkpoint builder or deferred-edit queue.

Failure retains the save token and previous generation; it does not delete the
retained path. Failed finish remains retryable (journal IO suspension may first
need off-path `journal_retry`). Failed prepare/file replacement with a retained
path requires the session recovery coordinator to reconcile/checkpoint the
retained generation, then replace this controller. Copy its token before destroy.
Reload/keep/new save are refused while that ambiguous recovery token exists.

## Reload

A worker opens and reads into private anonymous bytes in bounded chunks. It
checks the descriptor identity before/after reading and the current path before
publishing. No externally writable mapping is exposed by reload. The UI
`savectl_take_reload` creates tree metadata with the caller's allocator and
`piece_init_mapped` over that validated private copy. There is no second file-size
copy or scan on the UI; every non-snapshot piece operation stays on the UI owner.
The refcounted private backing survives controller destruction and live snapshots.
Its final release frees memory; it does no file IO. Cancelled copies are retired
by a worker. The caller's tree allocator must outlive the replacement tree and
support snapshot free from any thread; production supplies base-backed pools.

An unmodified external change schedules reload automatically. Modified content
retains the banner until an explicit action. Installation checks the revision
and event epoch again: edits even between worker completion and installation
prevent replacement. View offsets are the LATEST supplied offsets, not the ones
at reload request. Cursor, anchor, and scroll byte are preserved independently,
clamped only at the new EOF; scroll_x is unchanged. The old tree/undo/index are
retired by the editor only after a successful take. On read/allocation failure
the old buffer remains live. Repeated failed IO does not automatically retry
without a new event or explicit action.

Current reload intentionally uses private copy memory, including for large
mapped originals. This preserves consistency with the current file API but can
require file-size anonymous memory; it does not claim the mmap G10f memory bound.
UI metadata construction grows with chunk count and is not a measured foreground
slice gate here. A prepared safe mapping accessor from file would remove this
limitation without doing disk IO or file_attach/file_close on the UI.

## Integration contract

1. **Setup/open:** off the typing path, create one controller with the canonical
   target path, permission bits, the identity belonging to the original opened
   content (or a matching recovered journal BASE), actual source mode, reload
   allocator, and the work pool. Do not derive a replacement baseline by statting
   the path after an earlier original was loaded. For MMAP, supply a retained,
   worker-safe validator of the original inode AND fault epoch. Lifetime extends
   until all controller work completes. Current file.h cannot supply that token;
   see the accessor proposals below. COPY means independently immutable bytes;
   an anonymous immutable backing also qualifies.
2. **Successful mutation:** call `savectl_modified(s)` after each mutation,
   including undo/redo. This records a conservative revision-based modified bit.
   Keep current cursor/anchor/scroll with `savectl_set_view(s, offsets)`.
3. **Ctrl+S:** for no journal call `savectl_save(s, tree, NULL, NULL, 0)`.
   With a journal, first build a complete immutable PREPARE checkpoint at this
   same UI state, then pass the matching previous BASE and records. Retain those
   records until the lease returns. Request success is the ack; draw
   `savectl_get_model(s).status` immediately. Surface a request return error.
4. **Every frame/mailbox wake:** route matching messages with
   `savectl_receive(s, msg)` and forward unclaimed messages to their owners.
   Drain mailboxes, then call `savectl_tick(s)` even if no notification arrived.
   Before journal_pump/append/receive, observe the session journal lease. When
   needs_finish is true, append deferred operations, build a COMPLETE CURRENT
   checkpoint using `savectl_saved_base(s)`, then enqueue `savectl_finish`.
   Render status/banner and propagate the controller's modified bit to the tab.
   Try `savectl_take_reload(s, &new_tree, &offsets)` when state is reloading;
   BUSY means no replacement yet. On success atomically install new_tree and
   offsets, retire the old tree/undo/index safely, and journal the new baseline
   through the session checkpoint path. Neither this module nor its caller
   should call synchronous file_check/watch_poll/file_close on this frame path.
5. **File/focus events:** call `savectl_file_event(s)` once per coalesced event,
   including SIGBUS invalidation. It immediately invalidates an in-flight save
   or reload; tick enqueues identity checks. Cancel find/index over the original
   immediately too. Self-replacement events compare equal to the replacement
   baseline after completion and cause no spurious reload. Watch establishment,
   watch drain, and rearming are the caller's off-UI responsibility while the
   current file watch API remains synchronous. The controller does not own watches.
6. **Banner buttons:** call `savectl_keep` or `savectl_reload` when enabled.
   Both enqueue work; no action does synchronous disk work. On mapped-source
   invalidation, the validator can refuse keep (P1.7c cached newline safety).
   An unguarded mapped source refuses save/keep with SAVECTL_SOURCE_GUARD.
7. **Close:** call `savectl_close_begin`, keep the controller/pool/guard/checkpoint
   storage alive, and tick until `savectl_destroy` succeeds. BUSY is a return code,
   never a wait. Copy any retained recovery token for the session resolver first.
   Returned reload trees/snapshots may outlive the controller. The borrowed
   journal and work pools are never closed by savectl.

## Current API dependencies and proposed accessors

Blocking current APIs deliberately NOT called on UI: `file_save_begin` (stat,
source fstat and mutex), `file_check`, `file_resolve_keep`, `file_watch_poll`,
`file_attach` (close), `file_close` (cancel/wait/close), journal prepare/finish,
flush/retry/capture/close. The worker depends on blocking `file_save_write`,
journal prepare/finish/capture, and the reload's POSIX open/stat/pread/close.
`work_submit` itself uses the current bounded queue mutex; acknowledgement is
free of disk IO/waits but is not a lock-free primitive.

Propose to edit-4w1.42 (no header/implementation edits in this bead):

- A CPU-only `file_original_identity` export of the actual open baseline and
  permissions; not a fresh stat of the target pathname.
- A retained `file_source_guard` token captured without syscalls on the UI,
  with worker validation of original descriptor identity, source-generation,
  SIGBUS fault counter/recovery epoch, plus guard release. Validation must keep
  late faults/invalidation sticky even if pathname identity is restored. Feed
  it to `savectl_options.validate_source`; fstat of the pathname alone is unsafe.
- A worker-ready open/reload result with immutable mapping hooks, and asynchronous
  watch/close lifecycle. This allows the controller to preserve mmap memory bounds.

Propose to edit-4w1.53: a CPU-only `journal_pool_of` accessor to enforce the pool
constraint, or async prepare/finish with an explicit session lease and retained
transaction token. The current synchronous journal API is safe here only under
that exclusive ownership contract. Its internal retention work cannot be
physically cancelled by savectl; event invalidation prevents the subsequent file
rename, but prepare may finish its blocking IO before cleanup.

Residual consistency gap is the file core's last validation-to-rename window,
and undetected same-identity rewrites without an event (perf §2.14). No stronger
linearization against arbitrary external writers is claimed.

## Verification and TRACK measurement

Red-first test build: undefined `savectl_create/get_model/modified/destroy`.
Additional red behavioral tests caught source IO being reported as cancellation,
a reload tree allocator being invoked by a worker, an edit leaving a published
reload blocking keep, and notification preceding visible completion. All are now
green. The full-mailbox test waits for physical publication before inspecting
worker diagnostic counters; logical completion is deliberately earlier.
Tests cover save states, isolated snapshot/later edits, blocked bulk-worker ack,
pool refusal, failed IO preserving the old target, modified conflict banner,
silent/explicit reload, latest/clamped offsets, edits during/after reload,
notified/unnotified/restored-identity races before rename, source guard refusal,
UI-only tree ownership, close invalidation, journal prepare/finish failure,
retained recovery and replay of post-save edits, mailbox loss, and zero allocation
controller notifications. An optional linker-wrap test intercepts UI stat/fstat,
open/openat/fsync/pread/close, and holds work_publish after its mailbox wake
to verify result-before-notification ordering. No benchmark loops waiting for reduced load.
