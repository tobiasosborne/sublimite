## Boundary, follow and cancellation decisions (findings 1–4)

Terminator removal is bounded by the requested line's start. A trailing empty
LF/CRLF line therefore retains EOF as its End stop, including Shift+End.

Columns are exact, resumable results. A scanned prefix never becomes the final
cursor column. A fixed runtime ring retains certified byte/column seeds, clears
on tab-width changes/cancellation, and preserves strictly earlier seeds across
edits. An edit-point seed survives only when a local ASCII pair certifies it.
External providers are suppressed throughout the editing command. Byte-column
lookup retains a checkpoint strictly before its target, so local edits also have
an earlier seed if their new text destroys the edit-point boundary. Column-target
lookup seeds strictly before the target column; zero-width clusters retain the
same earliest-boundary semantics as the scalar reference.

True document-boundary/empty-edit no-ops preserve completed state. Cancellation
of movement restores its prior state; edited cancellation/errors keep the text
and a coherent byte-zero selection/viewport. P4's wrap flag survives that fallback;
visual top/soft-end affinity reset to the visible first row.

The current editor uses empty TYPE as an external-mutation repair/follow entry
point. The port initially exposed that conflict with the new no-op behavior.
View now remembers completed cursor/anchor and tree length: unchanged empty TYPE
is a no-op; a newly installed target or changed length invokes normalization.
Arbitrary external edits, including equal-length edits with unchanged endpoints,
still require explicit notify/restore and checkpoint invalidation.

## Cooperative line metadata (finding 7)

The older patch's unresolved frozen-query proposal is replaced for view-owned
queries by a demand-driven scanner using `piece_read`. It reads at most 256 bytes
(G) per chunk, caches certified line starts and exact byte/line query answers,
and returns MORE before scanning an unbounded prefix. EOF answers to nonexistent
line requests cannot be mistaken for actual line starts. Nearby byte queries can
subtract newline bytes from an exact cached prefix. Checkpoints also certify
logical line membership and can skip a known line's prefix before mutation.

TYPE, document commands and char movement no longer eagerly seek the current
line's end. Vertical/page motion seeks the destination's start and clamps at
actual EOF; it never requests the total line count. Column destinations stop at
logical LF/CRLF without first finding the complete destination line's end. Smart
Home and word motion stop on their required local context. Selection-line,
normalization and following metadata all have resumable phases.

Protected-tail tests cover initial unindexed TYPE, repeated Down continuations,
cancellation, exact completion and page motion. These are deterministic read
bounds, not wall-time gate measurements.

Inherited limitation: P4's `layout_visual_row[_fresh]` uncached path still calls
opaque piece line queries inside `src/layout/wrap.c`. This bead preserves that
API/code as instructed. The view-owned query fix does not certify a whole-editor
slice through that inherited layout path. A bounded layout query/index adapter
remains outside this bead.

## Bounded selection capture (finding 8)

The older proposal assumed atomic prepared replacement was necessary. The
existing view contract already exposes successful prefixes on MORE/errors, so a
view-only bounded implementation can use that contract without a frozen API
amendment. No worker mutates the UI tree.

Large selected ranges defer deletion capture. TYPE input up to 2,048 bytes (G) is
copied into runtime scratch during the initial call; no caller pointer survives.
Before the first capture, bounded preparation retains exact line/column prefix
metadata. A protected-prefix regression proves remote following does not reread
an earlier mapped prefix when certified checkpoints are available.

Each continuation captures/deletes at most 2,048 bytes (G), with a smaller chunk
when deferred insertion and preparation share the work budget. The first committed
tuple is `(lo, removed_chunk, inserted_len)`; later tuples are
`(lo + inserted_len, removed_chunk, 0)`, in that call's current tree coordinates.
A final capture yields before boundary repair/follow. Inspect and apply every
reported tuple exactly once; an aggregate can sum old lengths while retaining
the initial new length, as the test helper does.

Cancellation before mutation restores the selection/text unchanged. After any
commit it accepts the partial replacement and installs the byte-zero fallback.
All slices belong to one optional undo group; completion, cancellation and errors
close it. Tests cover complete replacement, partial cancellation with undo/redo,
input ownership, maximum deferred input, zero libc allocations, and truthful
failure prefixes. The allocation matrix fills an add chunk before deliberately
failing deletion capture; the inserted prefix and every original byte are checked.

This is a progress operation, not a reserved atomic transaction. The original
atomic/prepared replacement proposal would still require a piece amendment.
Larger TYPE input remains synchronously consumed/inserted under the old API;
selection capture remains sliced. Failure due to insufficient piece/undo reserve
can accept a reported prefix, as documented.

## Slice, undo and external-state decisions (findings 9–11, 14–15)

The view work limit is 4,096 charged bytes (G), segmentation chunks are at most
256 bytes plus UTF-8 lookahead (G), and the conservative deadline is 200 us (G).
Clock checks occur after bounded work chunks, avoiding a scheduling-only yield
in tiny operations while retaining cooperative deadlines for long decoding.
Bulk capture charges copied input/capture bytes and leaves room for local seed
reads. These bound owned work; scheduling, page faults and opaque operations can
still exceed the complete UI slice's 500 us gate (G).

`view_set_undo` optionally routes through the existing undo insert/delete APIs.
Each editing command owns one explicit group; before/after blobs contain cursor
then anchor. Actual mutations invalidate redo. Attached TYPE does not automatically
coalesce separate view commands into typing bursts. Detachment/replay ownership
and the need to clear history after bypassing the log are public contracts.

All nonnull change outputs clear before argument/busy validation. Unedited
failures preserve the prior complete state; edited failures retain the coherent
fallback. Fault tests exercise direct and undo-backed insert/delete/replacement,
retry, continuation, later commands and layout integration.

`view_notify_edit` rebases both endpoints with explicit BEFORE/AFTER affinities,
repairs joined clusters in that direction, resets preferred column and normalizes
viewport/following. `view_restore` clamps untrusted offsets and repairs forward.
Both reuse continue/cancel, emit no mutation, and allocate no libc storage. Cancel
before external mutation and invalidate external providers before normalization.

## Benchmark and fuzzer decisions (findings 12–13, 16)

Default/`--track` reports TRACK. `--gate` requires an AC stamp and eligible load,
then checks necessary module G1/G3 limits, per-call/maximum 500 us limits (G),
dropped samples, incomplete commands and missing samples. These are necessary
module checks, not a render/request-to-frame verdict. The 50 us target remains
an estimate (E).

Initial/continuation timings are separate. Fixtures include deep TYPE,
unindexed TYPE, substantial selection replacement, and one active snapshot reader
versus three submitted jobs (G), of which two queue behind the active reader.
The original measured label `three-queued` meant three submissions; it is now
corrected to `three-submitted`. Logical work and setup each stop at 1,024 calls
or 100 ms (G); incomplete work/setup is explicitly reported, never hidden as a
completed timing. The single TRACK run exposed remote post-capture prefix replay;
that was fixed with the deterministic protected-prefix test, without rerunning
benches for quieter numbers. That measured run therefore predates the final
prefix-retention fix; its incomplete replacement durations are lower bounds.

Benchmark initialization segments the complete source resumably. It falls back
to the last certified stop for a pathological setup cluster and independently
validates endpoints before/after commands. A prefix is never declared EOF.

The fuzzer independently owns bytes, cursor, anchor, preferred column, viewport
and approximation state. It models movement/selection from complete bytes,
applies each committed tuple to its own buffer, and checks cancellation before
and after commit. Structured cases exercise long combining chains, exact
checkpoint motion and continuations. Synthetic wrong movement at a valid boundary
is rejected, unlike the old boundary-only oracle.

## Coordinator-main fix-up: anchored visual motion

The coordinator's rebased tree exposed a port regression in visual motion from
a trailing soft-row endpoint. `visual_command` cleared `state.visual_end`, then
the resumable preferred-column phase returned through `P_VISUAL_SETUP`. That
second row lookup interpreted the same origin byte with leading affinity and
moved from the following row. Shift still retained its anchor, but the cursor
went to the wrong visual row. This affected fresh preferred-column discovery in
both directions, including discovery spread across continuations.

Origin row lookup now reads `before_state.visual_end`, the immutable affinity
captured at command start. Destination affinity still clears and is recomputed
from the destination row. This needs no new fields, allocations, query passes
or API changes and preserves bounded column scanning and cancellation restoration.
The existing P4.1 wrap expectations are correct and remain unedited.

`view_test wrap-selection` covers Smart Home to a trailing endpoint, anchored
Shift+Down/Up and reversal, preferred-column retention, and fresh Shift+Up with
a backward selection. Hidden separator whitespace remains part of visual End;
a screen-column destination before that hidden endpoint has leading affinity.
`view_test wrap-port` additionally covers long-cluster column continuations from
a trailing endpoint, cancellation before motion completes, retry, anchored
reversal and the existing edited-cancellation fallback. Its adjacent rows are
cached so this regression tests exact view motion rather than uncached layout
phase approximation.
