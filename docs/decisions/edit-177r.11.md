# edit-177r.11 — isolation-aware Windows suites

Tests derive capabilities from `GetProcessWindowStation` and `GetThreadDesktop` names. `WinSta0` / `Default` is live; `WinSta0` / `sublimite-test-*` is the runner's private desktop; a non-`WinSta0` station with desktop `quiet` is its private station. Other names and query failures are unknown and fail before window work. An environment value cannot grant clipboard permission. `quiet_run_test` checks the requested mode against these actual names and also tests deliberately false environment values.

The platform suite guards every clipboard entry, including its child-owner selector, with private-station capability. Layout loading, layout-dependent keyboard cases, and real expose delivery require the private desktop in the input station. Station and desktop passes together retain the existing assertions. Native foreground injection remains an explicit live-only case. The `--live-only` selector never enters clipboard cases.

D3D native resources and exact pixel fixtures use WARP under isolation. A test-only inclusion of the production backend drives its snapshot/draw functions and maps its staging texture without inventing a Present or any completion timestamp. Each query is consumed before the next draw. The same fixtures still test damage, retained rows, caller metadata reuse, concurrent disjoint atlas append, scrolling, region changes, resize, pending shutdown, debug messages, live children, and same-HWND reinitialization. Presentation/T5/T6/statistics assertions remain in the live path. Native isolated adapter retries assert a pending frame, no fabricated hooks, no device failure, and no rebuild across deliberately expired deadlines. The private-desktop pass checks actual `DXGI_STATUS_OCCLUDED`; the station checks hidden-window suspension. A deterministic native-vtable regression covers expired occlusion retries independently of desktop state.

Two production bugs were reproduced before fixing them. A station returns zero from `GetDoubleClickTime`, so clipboard retry expired immediately. The fallback is the documented Win32 default: 500 ms (P: [`SetDoubleClickTime(0)` documentation](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setdoubleclicktime)); no user setting is changed. Occluded Present returned BUSY only until its completion deadline expired, then requested a healthy-device rebuild. Occlusion now rebases that deadline, leaving the same frame retryable; the separate visible-progress timeout remains unchanged.

`WIN_CHECK_JOBS` bounds suite workers. Its default is eight (E: sixteen CPUs in the assigned lane divided into two CPU slots per concurrent suite group); measurements are in the worker report. Each suite's release, sanitizer, and extra desktop passes stay serial, including clipboard cases: the unnamed service window station can have a repeated per-logon name. Distinct suites use process-specific scratch and IPC names; the reparse fixture is read-only during suites. Full output and per-run duration go to `build/win/check-logs`, with SKIP occurrences counted by reason on the final check line. No automatic rerun hides failures.

The reparse helper sends every `cmd.exe` and descendant console utility through the station/job runner. `check-live` compiles both configurations, checks `WIN_LIVE_OK=1` before executing, and invokes only live selectors. The worker only builds these binaries and prints the dry-run plan. Killing a WSL relay uses the existing kill-on-close Windows job; test evidence is in the report.
