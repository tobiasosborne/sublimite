# P1.1c utf8 follow-ups (edit-4w1.18)

## What
- Generator emits real GCB=Control (`UCD_CONTROL`) and InCB (`UCD_INCB_CONSONANT/LINKER/EXTEND`); `grapheme_next` follows UAX #29 15.1 fully (GB3..GB13 incl. GB9c). Passes all 1187 GraphemeBreakTest.txt cases (vendored, byte-identical to a fresh unicode.org 15.1.0 download, sha256 in SHA256SUMS).
- Segmentation state is an explicit plain struct (`gstate`) with `gstate_start`/`gstate_join`, so P1.1d can suspend and resume a cluster scan.
- `utf8_grapheme_prev(base, off)`: scan back by units to the nearest certain break (invalid byte, CR, Control, LF after non-CR), then segment forward to `off`. Valid because break decisions depend only on left context. Total: for a non-boundary `off` it returns the start of the containing cluster.
- `utf8_cluster` / `utf8_cluster_width`: rule in utf8.h (first scalar with width>0; Hangul block 2; narrow ExtPict + VS16 or ZWJ-ExtPict 2; keycap 2; Control/invalid 1). Fixes man-ZWJ-woman-ZWJ-girl = 2 (not 6), Prepend+letter = 1 (not 0), Hangul L V T = 2.
- Not done (optional item 4): two-level per-code-point class table. Gates hold with the range tables; grapheme_next is TRACK only.

## Why the oracle matters
The pairwise left-context oracle (tests/utf8_test.c, fuzz/utf8_fuzz.c) caught a real bug during development: an InCB lookup guarded by `cp >= 0x900` dropped InCB=Extend marks below U+0900 (U+0308) and split a conjunct.
