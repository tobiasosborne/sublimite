`bench/find_bench.c` for the two P1.10 implementations and best-of. The reference

## 6. Decisions

- Byte semantics over an immutable piece snapshot or contiguous byte range;
  offsets are absolute within that source. No UTF-8 decoding, normalization,
  locale, or case folding. Snapshots are borrowed for a synchronous call; the
  job owner retains them through publication/acknowledgement.
- Literal matches are leftmost and non-overlapping. Empty literal means zero
  matches. Exact `uint64_t` count plus the first 4096 ascending offsets; result
  fits 64 KiB (G). Failures/cancellation clear counts and match descriptors.
- Single-match `find_literal_next` / `find_regex_next` permit incremental
  highlight streaming, pagination beyond 4096, and replace-all enumeration.
  Regex captures can also be rerun anchored at a known offset. A worker
  publishes batches/handles through `work_publish`; the UI applies replacement
  edits from the immutable source right-to-left in one undo group. Find does
  not own UI state, allocate replacement storage, mutate, or publish itself.
- Caller-owned, aligned compile and scratch storage (suitable for `edit_arena`).
  Compile copies all necessary pattern data, searches allocate nothing, and an
  immutable program can be shared with separate scratch. Program storage is
  bounded to 64 KiB and per-call scratch to 256 KiB (G design bounds); queries
  let callers reserve exactly the implementation needs. Tests that reuse storage
  across compiled programs reserve the public maximum rather than assuming the
  reference's constant scratch size. The state-limit error fixture uses >256
  fixed-width byte classes without a literal prefix, so it does not assume
  how many epsilon/tag states a compiler uses for plain literals. Prefix query supplies
  a sound mandatory common prefix, possibly empty; maximality is not required.
  Plain leading unquantified literals without top-level alternation must expose
  a nonempty prefix (also exercised by the prefixed benchmark row).
- Regex subset: byte classes/ranges and negation, dot except LF, concatenation,
  alternation, capturing parentheses, `*+?`, multiline `^$`. Quotes escape one
  byte; actual LF is required for LF. Nullable expressions/branches/groups and
  nullable loops are allowed. Explicit SYNTAX/UNSUPPORTED/LIMIT/MEMORY/ARGUMENT
  codes cover malformed/unsupported patterns and caller errors. Bound program
  to 256 states, 8 captures, 4096 pattern bytes, 32 levels of nesting (G design
  bounds). Group/state limits may be reached sooner than depth/byte limits.
- Whole regex matches are leftmost-longest, then non-overlapping. Empty matches
  advance one byte and include EOF. Capture ties use ordered tagged Thompson
  closure: earlier alternation arm and consuming repeat arm first, first visit
  to a state at a boundary wins. Captures retain the last participating group
  iteration; never participating/unused groups are UNSET. This avoids full
  POSIX subgroup disambiguation and backtracking. Tests include ambiguous
  alternation/repetition, optional/unmatched/empty/nested captures and cycles.
- Cancellation ORs `work_should_stop`, atomic flag, and generation mismatch.
  Poll before/after and at most 1024 combined comparison/state/candidate work
  units, including long verification and epsilon closure. Production kernels
  must additionally honor the <=5 ms worker CPU slice (G6c). No partial exact
  count is publishable. `work_cancel` plus `work_publish`/drain handle work-epoch cancellation after
  return. Flag/generation changes alone need caller rechecking/filtering at
  publication/consumption, or a corresponding `work_cancel`; the work mailbox
  does not know an app-owned atomic flag/generation.
- Reference literal search tries every candidate with bytewise verification:
  O(N*M). Snapshot access uses zero-copy span reads across pieces. Reference
  regex uses a byte-class Thompson NFA with ordered tagged closure and prefix
  rejection. Restarting at each candidate can be O(N^2 * states) on a failed
  unbounded expression; this is intentionally a slow semantic reference.
  P1.10 must improve the kernels without changing the frozen tests/bench.

Rejected: overlapping literal counts (incompatible with replace-all and perf
s2.7), empty literal matching every boundary (bad find-as-you-type default),
POSIX capture ordering (larger tagged-NFA contract), backtracking regex
(exponential paths), heap ownership hidden inside search (typing-path law),
4096-only replacement (loses matches), `periodic.txt` as a zero-match G6v input
(it actually has dense matches), and scaling full gates in quick mode.

Benchmark protocol, fixture counts and run defaults:

Default: `build/bench/find_bench` (31 samples). `--samples N` accepts 1..1000.
`bench/find_bench.args` contains `--quick`: 3 samples on the first 8 MiB of each
fixture, with ALL performance rows TRACK (zero gates). Quick mode cannot claim
G6/G6v; full mode prints MISS and exits 1 on gated misses. Correctness failures
always exit nonzero. `bench/harness.h` supplies nearest-rank p50/p99/median CI.
Three samples in this reference report are indicative, with p99=max; neither
that sample count nor concurrent workers is sufficient for quiet-box tail
acceptance. Coordinator should rerun defaults on AC and an idle box for P1.10.

Every timed row starts before `work_submit`, makes a NEW private mapping in the
worker, searches with its work context, and ends after publishing a handle to
the bounded result through `work_publish`. Search, page faults, queue dispatch,
and publication are included. `munmap`, completion wait/drain, regex compile,
scratch setup, fixture generation, warming and independent KMP oracle are
outside the interval. Warm each file/range with sequential read before timing;
no warm mapping survives into a sample. Compare exact counts AND every stored
offset to the independent oracle. Never drop failed samples.

- Cancellation TRACK: real work job on all-a near-miss, timed UI logical cancel
  and worker-search return after cancel. Requires cancelled result cleared and
  stale publication suppressed. Logical target 1/5 ms and next CPU slice <=5 ms
  (G); worker-return wall time is TRACK, not a CPU-time proof or cleanup gate.
