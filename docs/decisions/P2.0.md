# P2.0 — frozen cell-grid renderer contract (edit-e6x.14)

`src/render/render.h` is the shared contract for P2.4 GL, P2.5 CPU raster and
P3.1 layout. Changing it after this bead requires a new bead. Backends use the
common adapter in `render.c`; `render_null.c` is the reference implementation.

## Representation

A cell is **20 bytes (P)**: uint32 glyph identity, uint32 atlas-table slot,
uint32 foreground/background, uint16 attributes, uint16 reserved. Identity is
caller-defined and can name a shaped/precomposed cluster, rather than a Unicode
scalar. The slot points to `render_glyph`, which gives page and integer pixel
rectangle. `RENDER_NO_SLOT` is background only. This covers font's baked
95-cell-wide R8 ASCII page and its runtime 1024-square R8 pages without reserving
a special page number or assuming identical texture dimensions. GL derives UVs;
CPU uses the same rectangle and page stride. Page numbering is local to the
frame; layout maps `font_atlas_alloc`'s page/x/y output to it.

Layout uses `font_place_in_cell`/equivalent composition to apply bearings and
baseline before packing an image. Combining marks merge into one cell image;
wide glyphs may use a two-cell-wide image. Bold/italic choose glyph images in
layout. Both backends blend opaque sRGB channels with R8 coverage using rounded
integer arithmetic `(fg*a + bg*(255-a) + 127)/255`; inverse swaps colours,
underline covers the bottom pixel row, cursor/selection colours come from
layout. Backgrounds precede glyphs and decorations. Wide-right cells draw no
second glyph, and must match the left's colours and non-width attributes.
Layout replaces clipped half-wide glyphs at viewport edges with blank/replacement
cells. Any change to an image used by retained cells damages their rows.

The actual baked atlas metrics, rather than an approximate 300-column estimate,
give these exact capacities at 2880×1800:

| Atlas px | Cell pixels (P) | Grid (P) | Cells (P) | Cell bytes/frame (P) | Typing row bytes (P) |
|---|---|---|---|---|---|
| 15 | 8×15 | 360×120 | 43,200 | 864,000 | 7,200 |
| 30 | 16×30 | 180×60 | 10,800 | 216,000 | 3,600 |

Alternatives rejected: embedding page/UV/metrics in every cell increases the
per-frame payload; uint16 slots/identities unnecessarily limit runtime clusters;
raw codepoints cannot name combined glyphs or fallback faces. No font/header
changes are needed. Full shaping and rasterisation stay in their later beads.

## Damage and ownership

Grid cells and dirty uint64 words are caller-owned, contiguous row-major memory
or base-arena storage. Dirty row bits become the minimal full-width contiguous
row runs, without allocation; gaps split strips, empty damage produces no
strips. Padding bits are ignored. The helper reports required capacity before
writing anything, so a short output buffer is retryable. `ceil(rows/2)` strip
slots suffice (P). Full-frame damage overrides row bits. Initial submit and
submit after resize require the full flag. Damage is cleared by begin, never by
submit, so errors remain retryable. Successful frame IDs are strictly increasing,
nonzero uint32 to match trace; wrap requires restarting a quiescent instance.

Successful submit consumes or snapshots **cells, strips, glyph table and page
descriptors** before returning. Layout may immediately fill frame N+1 in its own
storage. CPU MT4 jobs use the backend-owned immutable snapshot and publish their
results through src/work mailboxes; only UI dispatch changes adapter state.
R8 pixel memory alone may remain borrowed: referenced rectangles stay immutable
and alive through T5, with disjoint new glyph rectangles allowed. This avoids
mandatory whole-atlas copies on typing (up to eight 1024² runtime pages =
8,388,608 bytes (P), versus a 7,200-byte typing row (P) at 15 px). Null consumes
all input synchronously; real backends may cache/upload/copy the pixel data.

One backend frame remains active until both T5 and T6. A second submit returns
BUSY and is never enqueued; layout may coalesce more edits while waiting.
`present` can return BUSY while CPU raster work is unfinished and is retried on
work events. Failed submits do not consume frame IDs or retain jobs/pointers.
All backends preserve undamaged pixels, including buffer-age repair if buffers
alternate. Zero-damage frames still follow the present/acknowledgement lifecycle.

Init capacities include cells, glyphs, pages, aggregate atlas bytes and maximum
surface width/height. Pixel extents are necessary because a cell-count bound
alone cannot bound an XShm framebuffer when font/cell size changes. Backends
reserve resources at init and reject over-capacity resize/submit. Adapter stats
count damaged cells (including backgrounds/continuations), strips and successful
frames; counters saturate at UINT64_MAX.

## Threads, fallback and trace

Factories/query use exclusive storage. Init runs on a worker and may block,
load GL or create/detach contexts. Its result crosses the work mailbox before UI
uses the instance. State memory is caller-provided with factory-reported size
and alignment; an optional init-only base arena holds larger backend resources.
Any failed GL init leaves no acquired resources; caller can select the CPU
factory with fresh state, or select it initially for `--cpu`.

Resize, submit, present, event dispatch, adapter signals and stats are UI-only.
GL binds the transferred context on UI. Worker fence/raster results go through
src/work; UI routes them using `RENDER_EVENT_WORK` and the original frame ID.
Native fence/Present callbacks use DEVICE_DONE/PRESENT_COMPLETE events. Shutdown
is **quiescent UI-only** after input stops, and may block: `work_cancel` is
UI-only, as is the transferred GL context. It cancels/drains owned jobs/fences
before returning and suppresses pending hooks. It must not shut down a shared
work pool. Keeping shutdown on a worker was rejected because it would violate
work.h's cancellation ownership. Nothing allocates or prints on the typing path.

Successful present records TRACE_T4_PRESENT_SUBMITTED exactly once. T5 is the
later of matching-frame device fence completion and T4, not XShm source reuse.
T6 is separate matching-frame Present completion. Immediate signals inside
present are withheld until success; their timestamps cannot precede T4. The
null backend's completions are artificial acknowledgements, not display evidence.
Hook delivery can be asynchronous on UI via event dispatch. Default trace hooks
also support direct invocation on a registered recording worker; this only writes
that thread's trace ring and must not mutate the adapter. Explicit timestamps
must be correlated to CLOCK_MONOTONIC; raw X UST is not accepted as that clock.
Backends without matching-frame completion/fence support fail init with
UNSUPPORTED rather than strand the one-frame slot.

## Conformance and measurement

`tests/render_test.c` runs unchanged for future backends with
`-DRENDER_TEST_EXTERNAL` and a linked driver implementing the three documented
prepare/pump/cleanup functions. That driver supplies platform/work resources and
routes real asynchronous events; common validation, stats and hooks are exercised
identically. The delayed synthetic backend independently tests early/late and
out-of-order completion, retries, stale/duplicate signals, copied snapshots and
shutdown. The null run checks 10,000 typing frames under the real release malloc
guard. ASan owns malloc, so the counting check is explicitly skipped there.

The RED suite, benchmark and seeded fuzzer were built/run against error stubs
before implementation. The fuzzer compares arbitrary row patterns, dimensions,
full flags, dirty-word padding and output capacity against an independent naive
row model. Verification includes release tests, all ASan/UBSan tests, all fuzzer
builds, and a 60-second render fuzz run. The sandbox's ptrace restriction prevents
LeakSanitizer process inspection; sanitizer execution therefore runs outside the
sandbox, with leak checking still enabled.

Benchmark rows are TRACK only: all-cell fill plus strip computation, and one-row
fill plus strip computation, at both actual atlas sizes. They use the project's
harness, 10,000 samples (P, sampling contract), nearest-rank p50/p99 and median
confidence interval. The G3 **5.0 / 5.56 ms (G)** context is for the complete
render pipeline; this benchmark covers grid work only, so it cannot demonstrate
G3. Numbers are indicative under concurrent worker builds; the coordinator must
remeasure on a quiet machine. Run-specific (M)[bat]/[AC] evidence is in the worker
report, not a new render gate.
