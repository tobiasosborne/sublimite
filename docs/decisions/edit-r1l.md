# edit-r1l: evict runtime glyphs without changing valid text

Finding 34 (review identifier, not a budget) in `docs/reviews/editor-2.md` has no cross-reference. The runtime owner returned baked `#` both when its descriptor table filled and when a bounded hash probe refused admission. The red regression reproduced the latter before descriptor exhaustion.

Use a bounded LRU of exact cluster keys, with printable ASCII permanently baked. The descriptor ceiling comes from `FONT_RUNTIME_MAX_GLYPHS`, rather than a second literal. The hash table retains the inherited three-quarter occupancy sizing (P: integer rounding of the existing load ratio) and searches through the table instead of substituting artwork after `FONT_CACHE_MAX_PROBES`. Backward-shift deletion preserves wrapped collision chains without accumulating tombstones. A linked recency list needs no clock or ever-growing counter.

Each request slot owns a key region of `FONT_CLUSTER_MAX_BYTES`. Published pages are divided into narrow-cell tiles; a wide glyph occupies adjacent tiles in the same row (P: wide width is twice narrow width). Physical capacity derives from `FONT_ATLAS_MAX_PAGES * floor(FONT_ATLAS_PAGE_DIM / cell_width) * floor(FONT_ATLAS_PAGE_DIM / cell_height)` (P: physical packing). Occupancy metadata is capped by the descriptor capacity times wide width plus the possible odd-row tail per request (P: each wide rectangle can leave at most one trailing narrow tile). LRU eviction reclaims both descriptors and tiles; width changes may need further evictions to form a contiguous rectangle. Vacant descriptors use an intrusive free list. Neither keys nor rectangles accumulate across scrolling. Arenas from `src/base` reserve and pre-touch published pixel pages at initialization.

The worker uses the existing compositor through `font_cache_render`, without admitting a key or consuming a private atlas rectangle. It writes the selected slot's tile and publishes its descriptor through the existing authenticated mailbox. Unsupported glyphs still use completed Unicode replacement artwork. Cache pressure cannot turn a supported glyph into replacement artwork. UI lookup and submission allocate no heap memory.

Frame start pins existing composed and text grids. Every lookup pins its slot for the incoming frame; pending requests are also ineligible for eviction. If the backend is active, prior pins survive. Full replacement may release outgoing pins only after backend retirement, retaining incoming lookups. The editor does this lazily when admission otherwise has no legal victim. Partial frames keep the outgoing cells pinned. A request with no legal victim returns `FONT_MORE`, allowing retirement or outstanding glyph work to proceed; it never returns `#` as a cache-capacity result. The renderer's existing simultaneous descriptor/pixel limits remain; this bead handles documents whose distinct glyphs exceed resident capacity through navigation, rather than enlarging renderer frame limits.

The regression derives its distinct-key count from `font_async_limits` minus `LAYOUT_ASCII_GLYPHS`, plus an overflow key (P: capacity arithmetic). The red fixture appended different counts of default-ignorable U+034F to a supported accented glyph. The final fixture encodes the capacity-derived binary digits using default-ignorables U+034F and U+FE0F, keeping keys compact while preserving the same expected pixels without depending on CJK fallback installation. It also exceeds physical tile capacity at `EDITOR_FONT_MAX_PX` (P: the existing editor size ceiling) and exercises width-changing reuse. It checks forward and reverse navigation, a retained different glyph, return to an evicted key, and frame-retirement pin separation. Existing Unicode/editor tests cover pending submission, adoption, combining marks, wide cells, tab titles, zoom and allocation guarding.

## Release allocator correction

The lander's release failure showed that first CJK fallback discovery can overlap the guarded clipboard typing window. Sanitizer success cannot establish this contract because its counting allocator is inert. Preserve asynchronous first-request/pump timing and use the existing `edit-cx8` calling-thread exemption around libc's `posix_spawn` actions/attributes setup, spawn and destruction in `query_child`. These opaque library calls run on the discovery/glyph worker; the exemption ends before child-output parsing, cancellation polling, font loading, arena use, composition or mailbox publication. The actions-init failure path also ends the exemption. Other threads remain counted. Moving a particular fixture's lookup into startup would not cover newly typed supported scalars or revisiting an evicted key.

The existing fallback test now opens the real guard before worker submission and closes it after authenticated adoption, without prewarming discovery. Its expected allocation count is zero (P: law 2 after exempting the worker's opaque library calls). The existing release clipboard test remains the production-path oracle. Reported measurements and red/green evidence are in the worker report.

## Frame pin work bound

`editor_begin_frame` calls `font_async_frame` only when starting a clean frame; repeated calls while `e->dirty` return before pin work. An owner with no admitted runtime descriptors now returns before either grid scan. Clearing uses `owner->count` bytes rather than `ASYNC_ENTRIES`; the populated descriptor prefix is the only region that can have pins. Active-backend normalization already uses the same populated prefix.

For a populated owner, the work bound is (P) `N + Cg*Rg + Ct*Rt`, where `N = owner->count <= FONT_RUNTIME_MAX_GLYPHS - LAYOUT_ASCII_GLYPHS`, and each grid's columns and rows come from its allocated dimensions. The byte clear is (P) `N * sizeof(uint8_t)`. In editor integration, `Cg,Ct <= max_cols`, `Rg <= max_rows`, and `Rt <= max_rows + 1` (P: the existing extra text row covers partial-row scrolling); thus the cell visits are bounded by (P) `max_cols * (max_rows + max_rows + 1)`. These are inherited allocation/viewport bounds, independent of document length and distinct glyphs visited. No latency budget is inferred from this arithmetic. Scanning both grids is necessary: partial composition can retain older text cells, while the composed grid contains title/chrome glyphs absent from the text grid. Omitting either would permit overwriting pixels still borrowed by a frame. Keep this local traversal rather than introducing new slot bookkeeping into every editor mutation path.
