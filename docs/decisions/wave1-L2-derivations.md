# Wave 1 persistence and headless editor derivations

These rulings answer [the harvest, §6](wave1-L2-L5-harvest.md#6-open-derivations--for-a-reviewer-astra-not-for-a-worker). The crash oracle starts from a verified recoverable pre-state. A process kill before command acknowledgment permits the pre-edit or whole edit. A kill after acknowledgment requires the whole edit, including for an untitled buffer. A foreign source change, storage failure and power loss have distinct outcomes. [PLAN §4.2](../PLAN_V2.md#42-l2-edit-kernel-journal-publish-point--sigkill-kill-oracle)

Evidence tags apply to quantities. **(P)** denotes a deduction from a layout or operation, **(G)** a chosen format or signed contract, **(M)** an observed value, and **(E)** an estimate. Question, amendment, fixture and version identifiers name their sources. This is a static derivation against `4346194`, the amended undo contract, and oracle `6fec2e8`.

### Q1 — SETTLED · Journal-local generation key

A key names one source generation throughout a journal lineage, across buffers and rotations. Allocate monotonically from a journal-local LE u64 (G, the signed restore field). Reserve zero for absent, carry the allocation high-water mark across compaction, advance past later declarations on reopen and refuse exhaustion before reuse. Journal lineage scopes lookup when restoring several sessions. The range record stays **64 B** (G layout, P = 32 B record header + four 8 B fields for destination, key, source offset and length).

A GENERATION declaration precedes use. Its payload in wire order is key, source identity, prefix length, prefix CRC32C, location kind, location byte length, location bytes, then artifact identity for a private copy. Identity encodes volume, low inode, high inode, size (LE u64 each) and mtime_ns, ctime_ns (LE i64 each). The lengths, CRC and kind are LE u32 (G, same word widths as the record length and CRC). The location is raw path bytes without NUL. Kind **0** means canonical absolute BASE path; kind **1** means unique private leaf relative to the held journal directory (G, one discriminator per permitted location). Reject embedded NUL, unsafe leaves, wrong field lengths and unknown kinds. A copy carries **its own fd-captured identity** as well as the original source identity. Its length and prefix witness must agree with the source. Capture the prefix over min(size, 4096 B) (G, existing BASE prefix rule, oracle `journal_capture_base`). A copy has a different inode even when its bytes match.

Each checkpoint declares every reachable generation before its records, including live future restore sources, captured leaves and all pending SAVE tokens. Relocate a key from named BASE to verified private copy by publishing a complete rotation before replacing the path. Reject conflicting declarations in one image and unresolved keys. Startup retirement follows declarations as well as BASE/SAVE. An unreadable, leased or unknown dependency keeps candidate artifacts pinned. **Alternative.** Using the current BASE record sequence alone fails when compaction rewrites that record at a new sequence while an older inverse still holds the key. Preserving and redeclaring the original sequence would already require a persistent namespace. [Piece-pool, journal encoding and durable source lifetime](wave1-piece-pool.md#iii-span-sequence-inverse)

### Q2 — SETTLED · Retain during save preparation

Before a journaled save can displace an existing named BASE, PREPARING secures it unconditionally for the prepared transaction, even with empty undo history. Reuse an already secured generation. Also cover every other live/recoverable source for which this rename removes the verified name. Untitled or absent BASE has no old file to copy. Use an exclusively created private artifact in the journal directory. Clone from the held, verified source fd with `os_file_clone`. On `OS_E_NOTSUP` (includes cross-device), copy from that fd with bounded scratch on the bulk worker. Propagate read, space and sync errors. Check the source across acquisition, compare the expected identity and prefix, verify the resulting length/prefix, and use the artifact's final fd identity. For mapped reads hold the backing through the single closing fault poll after the last dependent load and require matching registration and pristine epoch (G, A19). A same-size in-place write also needs the live source validator.

Order the barriers: sync artifact data and metadata, secure its name with directory sync, publish and sync the complete PREPARED rotation, then permit file replacement. A failed or ambiguous barrier retains dependencies and prohibits advancing to the next destructive step. **Alternatives.** A hard link changes ctime, can fail across devices or under protected-hardlink policy, and leaves a foreign writable fd able to rewrite the retained bytes after our rename. A hard-link syscall seam buys no independent copy. An inverse-count-only retention test loses the old BASE needed for a kill between target rename and journal finish even when undo is empty. Plain worker copy is a correct fallback and writes the whole source on a filesystem supporting cheap clone. ### Q3 — NEEDS-MEASUREMENT · Recover against the declared source

Use the checkpoint BASE as the tree's sole ORIGINAL. Validate record CRC, group completion, key, source fd and witness, source bounds, destination bounds and resulting length with checked arithmetic **before publication**. Process runs in document order, including backward and repeated source offsets. Matching tree ORIGINAL permits `piece_replace_spans` with absent newline hints. For another generation, a worker reads verified ranges in chunks and the UI owner applies them by value into ADD on an unpublished recovery tree or under an unlogged-tree checkpoint. Check the held source across the read, including the closing poll for mapped loads. A missing artifact, identity mismatch, short read, taint or resource refusal leaves the group unapplied and the recovery source intact for retry. A committed mixed group is adopted whole. No worker mutates a piece tree. [Frozen piece model and thread ownership](../../src/piece/piece.h)

**Alternative.** Delete the old ORIGINAL, save empty, then undo. Installing its old offset into the empty ORIGINAL has no valid source byte. Opening on the old generation can optimize this particular trace, but a checkpoint mixing both generations still requires conversion of at least one source. The general by-value path costs at least L retained ADD payload bytes for L bytes inserted from a foreign generation (P, `piece_replace` appends its input). Chunking bounds transfer scratch only.

**Outstanding.** On the PLAN large-file class (G, 10 GiB), measure peak ADD extents, piece nodes, staging/scratch, RSS and temporary disk during saved-empty recovery and a mixed-generation checkpoint with repeated ranges. Verify exact bytes and retry after insufficient memory. Stamp power, load and available RAM/disk. Compare with streaming the resolved output run sequence to a private file and mapping that as the sole ORIGINAL. If the simple path exceeds the supported machine's resources, select the file-backed path for that workload. If an explicit minimum machine or disk allowance is needed, the advisor takes that product limit to Tobias. No RAM threshold follows from the record size.

### Q4 — SETTLED · Acknowledgment requires a recoverable name

Save preparation pays retention on ordinary saves. Return the journal lease to the UI as soon as durable preparation completes, before file-only writing. Normally an undo can use its existing declared and verified named BASE or private artifact. If external rename leaves only a valid old fd, hold the pending command at its pre-edit boundary, display “Securing recovery source”, and secure and declare a private generation off path before permitting publication. Revalidate at use. If the inode was overwritten in place, a pristine fault poll cannot recover the old bytes. Use a separately verified source where the operation supports it or report source conflict. An I/O failure is visible and withholds success.

After RAM acceptance, keep append progress, fence new-text frames and success ACK through the final accepted journal record, and preserve the live edit on error. Service completions and status on the last published view during the wait. **Alternative.** Deferring every own-save copy until Undo and acknowledging the change from a live fd loses the only copy when the process dies. Waiting at Undo instead can put an entire source copy ahead of the next input even though save preparation already had the fd and worker. ### Q5 — SETTLED · A versioned journal preamble

Use this fixed preamble in creation and every rotation temp before any records. Field order is ASCII `SJNL`, LE u32 format version, LE u32 required features, LE u64 generation high-water at creation of this image (Q1), LE u32 CRC32C over the preceding fields. Total **24 B** (G layout, P = 4 + 4 + 4 + 8 + 4). Use version **1** (G, first SJNL schema), features **0** (G, the generation declaration and BASE-range record are mandatory in this schema). Reject any unsupported required bit. Record lengths, CRCs, sequence and PAD alignment use record-stream offsets relative to the end of the preamble. Charge the preamble separately in file-size and repair-offset arithmetic. A header-only owned journal is logically empty.

Validate the preamble before writable open/append, replay, repair, discovery, or retirement. For unknown versions/features, malformed headers and short existing files, report and set aside under the session lease with bytes intact. Preserve possibly referenced artifacts. A new file is initialized under its creation lease. Session lock files carry only the lease and get no header. Recognize v1 `JNL1` only for a separate read-only importer into the v2 namespace. **Alternative.** Per-record inference lets the older scanner encounter an unknown generation record after a valid prefix and truncate an otherwise valid journal there. The retirement magic probe must recognize the journal family even when this build cannot decode the version. [Harvest §2.4](wave1-L2-L5-harvest.md#24-the-wire-format-what-v1-has-and-what-v2-changes-most-of-it-is-an-open-derivation)

### Q6 — NEEDS-MEASUREMENT · Keep the bounded page-cache append

Sanction one `os_file_pwrite_once` per encoded record on the UI journal path (G, the OS primitive issues one attempt even on EINTR). A complete record in the named journal's kernel page cache suffices for process-kill acceptance. A multi-record command waits through GROUP_COMMIT. Short/zero/error retains the whole encoded record and its offset, latches recovery suspension and withholds success. Repair the gap off path without reapplying the edit. Sync, rotation and retention stay off the typing path. A12's libxcb read prohibition and the live allocation guard still apply. **Alternative.** Kill just after ACK of a userspace enqueue, before the worker writes. The edit is absent. An anonymous memfd also vanishes when the killed editor owns its last fd. A worker writing the named journal could supply the same oracle only if its completion fences the ACK.

**Outstanding.** Linux regular-file writes can block. On the release typing path record G1 input-to-submit and time inside the append, median and tail under the project's existing G1 gate, with ordinary typing and under dirty-page/writeback contention, power and load stamped. Use the live allocation guard and separately exercise short writes and SIGKILL. The attempt bound proves no time bound. Keep this implementation unless the G1 result requires comparing worker completion latency. ### Q7 — SETTLED · A shared pool with a single UI consumer

The UI submits, cancels, routes bound mailbox completions and returns journal ownership. It quiesces journal transport before granting an exclusive prepare/finish/rotation lease. The bulk job performs its own retention, flush and rotation steps inline. UI adopts PREPARED, returns the lease, then submits file-only write. Finish uses an exclusive lease and a **current** complete checkpoint. Slice independent counting work and resume it through the pool. Queue pressure defers admission while the owner keeps the cutoff and intent. A full mailbox retains an immutable completion for later publication without repeating its file operation. Bound UI drains must also advance other clients. Release job inputs on failed submission or physical completion, including cancellation.

Capacity is finite: **64** slots and **256** messages per worker (G, `WORK_MAX_JOBS` and `WORK_MAILBOX_CAP`). Available bulk slots are the shared slots less occupied/undrained slots there, after subtracting enabled foreground and raster reserves (P, `work_submit_batch` admission). Save, checkpoint and count requests from many buffers can exceed this. Admission must progress after drain with the existing capacities. For the overlap fixture, a prepare job, an independent checkpoint intent and a count job give at most three bulk job handles (P, one per operation, fewer while the journal lease serializes them). Separately fill the actual shared slots or a worker mailbox with unrelated work, drain, and require progress through cancellation and lease return under TSan. During sliced undo UI continues routing jobs, keeps provisional text out of captured leaves and queues a forward command (Q15).

**Alternative.** With the configured single bulk worker (G, `pool_init`), waiting inside save for a submitted bulk flush can deadlock. Giving the journal another pool and draining it on the save worker violates the UI-only lifecycle and single-consumer mailbox contract. [Work ownership and admission](../../src/work/work.h)

### Q8 — SETTLED · Supplied undo contract

Undo owns the logged tree's checkpoint. After an `undo_replace` error the caller may only abort. Stage privately after the last replace and before commit. Commit's only failure is source CONFLICT. (Superseded wording, D1' 2026-11-24:) No undo call ever closes a checkpoint by itself (D1', advisor 2026-11-24): after any result other than OK or MORE from undo_begin, undo_replace, undo_replay_prepare (initial or resumed) or undo_commit, the owner releases its provisional pins and calls undo_abort; undo_abort is valid after any failed call and does nothing if that call opened no checkpoint. Publish staging only on success. A yielded replay owns its checkpoint until the group resolves. Q7, Q10 and Q15 use that boundary.

### Q9 — SETTLED · Give an unresolved preparation its own phase

Add `RECOVERY_PENDING` to **save_phase**. The four axes remain phase, external state, lease and close state (G, PLAN §4.4). Preserve the token, cutoff and dependencies on ambiguous prepare or failed pre-rename write with a prepared token. Disallow a fresh save. With no verified replacement this phase admits recover-cancel only. Cancel syncs the target namespace and durably checkpoints CURRENT without depending on the token before release. It never marks Saved. A failure with no token or possible publication can return to IDLE with an error.

A proven target-directory barrier failure uses DIRSYNC_RETRY, followed by fd/path verification. A verified replacement can enter FINISHING. On journal writeback loss there, retain the verified fd-captured BASE and use recover-finish via fresh-inode complete CURRENT rotation, rechecking the target before adoption. Retrying dirsync alone cannot restore lost journal bytes. Any post-rename foreign mismatch, including on retry and without a journal, goes to CONFLICT_CANCEL. Expose no finishable BASE, preserve dirty and post-cutoff text, and leave the foreign file alone. Preserve recovery evidence through failed reconciliation and close.

**Alternative.** Treating every retained token as CONFLICT_CANCEL makes a successful, verified replacement followed by journal writeback loss indistinguishable from a foreign rename. Letting both finish recreates X2. Letting neither finish loses the verified recovery path. ### Q10 — SETTLED · Track the saved and in-flight content boundaries

Edit owns content IDs within a buffer incarnation. Assign a fresh ID to each committed nonempty forward command, including a burst extension. Publish only on successful commit. Leave the ID unchanged on no-op, conflict, abort or provisional replay. A verified save installs the **captured cutoff** ID. Dirty means the saved state is unknown or its ID differs from current. Start a new identity domain on reload. Break joining at a save cutoff so undo can reach it.

Only states against which equality will be tested need bookmarks: current, saved and any still-owned cutoff. Keep an ID and its reachable group boundary for each such owner. Derive boundary position as evicted prefix count plus applied group count (P, `undo_get_history`). On a committed branch invalidate bookmarks in the discarded redo suffix before that depth can recur. On a join invalidate the replaced endpoint. On trimming, remove reachability outside the surviving boundary interval, retaining the ID of any still-owned cutoff for finish. Reset positions on log clear/replacement. At **completed** replay boundaries restore the ID of a matching reachable bookmark. An unobserved boundary can receive a fresh ID when revisited, since no saved/cutoff equality depends on its prior ID. All observers that retain an ID for later comparison must retain its bookmark. Use checked ID allocation without wrap. This uses the existing cursor-state payload and needs no parallel history ring.

**Alternative.** Save “a”, type “b” in a joined burst: `group_serial` can stay constant across distinct text. Or save on one branch, undo and type different text to the same depth. Serial or naked depth would mark the wrong text clean. A save completing after further typing must leave current dirty, and Undo back to its cutoff must clear it. [Harvest §4.5(e)](wave1-L2-L5-harvest.md#45-v1-structure-edit-must-not-carry)

### Q11 — SETTLED · Path selects affected buffers; generation owns bytes

Maintain stable generation ownership across all buffers that can name it. Live history, including redo, current and captured leaves, save tokens/jobs, and durable journal/checkpoint images can independently need an artifact. With frozen undo, the owning tree/log may conservatively hold its ORIGINAL claim for its lifetime. Transfer or drop claims on teardown and physical completion. Retirement needs both no live claim and a durable replacement of every on-disk dependency, across the rename/dirsync window and under the retirement lease. Unknown references pin. A private leaf cannot be recycled by path or key collision between sessions.

At verified FINISHING, reconcile **every** same-target buffer into CURRENT against the written fd's BASE. Preserve each buffer's text, history and post-cutoff edits. Only the saving buffer acquires that cutoff's clean ID; a sibling with independent text needs its own delta and stays dirty. Index same-target membership at open/rename/close to avoid a per-open scan over unrelated buffers (A17). **Alternative.** A and B share old generation X. A saves generation Y and closes. Retiring X by pathname or saving-buffer lifetime strands B's undo and its recoverable checkpoint. [Piece-pool ownership table](wave1-piece-pool.md#revision-ownership-in-v2)

### Q12 — SETTLED · Refuse mapped admission visibly on slot exhaustion

On `OS_E_NOSPC`, release the unpublished map/fd and report fault-registry exhaustion. Reload keeps the old tree, registration, history and visible text intact. A later user retry can succeed after actual final release. With **256** available registrations (G, frozen `OS_FAULT_SLOTS`, inherited v1 table size), the **257th** simultaneous distinct mapping fails (P, capacity + one). Snapshots of the same backing share its slot. Reload requires a distinct registration while old readers survive. Physical slot use counts live backings, independent of tab count. Report fd exhaustion separately.

**Alternative.** Forced COPY can require the entire large file in private memory when a mapped open needed only descriptor storage. Unregistering the old backing first strands a snapshot still reading it. Neither fallback follows from the copy threshold or tab limit. [Fault-lease integration](wave1-os-fault-lease.md#l2-and-l1-integration)

### Q13 — SETTLED · Reproduce the oracle's case table

Harvest the generator with an explicit input-version check, a registered, non-writing `--check` that compares all emitted bytes, and the generated table in its consuming module. The oracle's `tools/view_case_tables.py` iterates Python scalars for full `str.upper/str.lower`, derives maximum encoded width from the mappings, and builds word classes from general categories L/M and N. The checked-in header identifies Python UCD **15.0.0** (M, static header inspection). Cased/Case_Ignorable use vendored **15.1.0** DerivedCoreProperties (M, source file version line) filtered to code points assigned in the generator's Python repertoire. Preserve that combination, contextual Final_Sigma in the consumer and lower-based sorting. Pin the generator environment/data, fail clearly on the wrong version, and check that v1 output reproduces before relocating it. The utf8 module keeps its own vendored UCD version.

**Alternative.** An unchecked invocation on host Python can silently extend word classes when an unassigned code point becomes a letter. A simple single-scalar lowercase/uppercase table also misses expansions such as ß → SS. Copying the header alone loses both the provenance check and its capacity derivation. [Vendored UCD inventory](../../vendor/ucd/README.md)

### Q14 — SETTLED · Present carries a complete os_stat

Make the comparison type an explicit ABSENT or PRESENT(os_stat). Stat errors are a separate result. Use the file API's absence policy for missing path components. Access denial or I/O failure refuses the operation. Full stat supplies kind, permission bits, owner and group as well as both inode words, volume, size, mtime and ctime. One file change classifier compares presence then these fields and returns the applicable change flags. Use the same classifier for target and fd checks. A journal generation uses the explicit wire projection in Q1 and its prefix witness. Never synthesize a complete stat from a partial BASE. An expected absent target requires atomic NOREPLACE; report conflict on existence and refuse if the primitive is unsupported.

**Alternative.** The tagged stat survives. A zero-filled stat for errors can authorize creating over an inaccessible target. A second comparator that omits the high inode word can approve a replacement that file's own comparator rejects. The projected generation fields have stable encodings independent of C padding. [OS identity and stat](../../src/os/os.h) · [Harvest §1.2](wave1-L2-L5-harvest.md#12-public-api-to-carry-and-what-changes)

### Q15 — SETTLED · Apply admitted input in global FIFO order

Start Open by installing BUF_OPENING and scheduling acquisition. That command has dispatched. A switch to a ready small tab followed by Save may run while the large open continues (R18). If the FIFO head requires an opening buffer's text, an unavailable journal lease, or a logged tree in yielded replay, leave it at the head. Continue open/replay/mailbox progress from the non-reentrant loop, independently of input dispatch. Resolve targeting against the ordered tab state and stable buffer incarnation. If the open fails, visibly refuse dependent input before advancing. A busy close with a defined refusal can complete as refused at the head. On admission pressure report a refusal and preserve the order and target of accepted trailing events (R29).

**Alternative.** Park a key for opening A, then dispatch switch-to-B and Save from another queue. A's key has been overtaken; delaying only same-buffer Save still violates A9. Conversely, treating *any* pending open as a global lock unnecessarily blocks R18. A forward key arriving during a yielded replay stays queued. Calling `undo_begin` during the yield violates its precondition, and cancelling the earlier Undo to dispatch that key changes input semantics. ### Q16 — SETTLED · External headless command completion

Give the real headless binary an explicit command-stream mode over an inherited connected descriptor adopted with `os_stream_adopt`. The parent drives the other end. Decode framed requests with a command ID, command kind and checked payload into the production app FIFO. Reserve reply space at admission. Emit a matching applied ACK only after production edit commit and acceptance of the last required journal record, including group commit and source dependencies. A refusal or suspended recovery has a distinct response. Distinguish save-request admission from **completed save**, which requires verified durable finish. Handle partial reads/writes and backpressure via the waitset without blocking input→submit or repeating a command.

The parent can kill before waiting for a reply or immediately after receiving the matching success, relaunch against the same disposable session, then compare recovered bytes independently, including untitled text. No forced flush, graceful quit or frame is needed. The GUI inspector can later witness the corresponding submitted action frame. **Alternative.** EDIP's callback OK acknowledges open intake. Kill after that callback but before the edit group reaches the journal and post-ACK recovery can still be pre-edit. An in-process injection hook alone cannot witness the real binary across death. Reuse the OS transport and production dispatcher; EDIP retains its open/wait protocol. [IPC callback semantics](../../src/ipc/ipc.h) · [Contract recovery oracle](wave0-contract-design.md)

## Q7 amended (exclusive grant requirement)

E2 reopens only Q7's exclusive prepare/finish/rotation section. An exclusive journal grant covers no sync, and no write whose size depends on buffer, peer or session content (G, advisor's E2 ruling). The following publication protocol is proposed for signature.

**Admission and the crash contract.** A key that needs writer admission stays at the head of the session FIFO during a save grant. It changes neither RAM text nor the journal. The user sees the last published frame and pending/save status. The loop continues dispatching completions. On return, edit admits the head against current generation policy, reserves before undo commit, and makes the changed frame and success reply eligible after the complete named-journal append. This also applies to a completed undo group. During the temp write and sync, ordinary keys can reach submit. K reads the kernel-visible journal name and requires every acknowledged command. M may choose either binding before its parent barrier and must retain every previously guaranteed durable command. [Edit through submit](wave1-edit-spec.md#one-keystroke-through-submit) · [K and M traces](wave1-L2-q2-protocol.md)

**(i) Finish and rotation by tail carry.** Let B be a complete pinned session boundary, and let T be the number of encoded bytes needed to translate all records since B, including complete groups, metadata, image-local positions, pending tokens and generation declarations. The proposed final grant costs **T bytes, one journal rename and zero syncs** (P, it writes that suffix and switches the name). A paste or T4 undo after B makes T depend on content. K works on successful I/O *if* the old fd remains the only append destination until the new image contains the entire acknowledged prefix and writer routing changes atomically with rename. K before rename reads old; K afterwards reads new, including each subsequent acknowledged append. A name switch during an unfinished command or a late write to the old fd breaks that proof.

M refutes the unconditional claim. Build and sync the private image at B. Append an undo with literal X on old, ACK it, and complete an old-journal durability barrier through that undo. Carry the undo into new in page cache and rename. Lose power before new's tail sync. M can retain the new name with only its prefix through B. The old barrier had guaranteed X. Even an unbounded exclusive copy cannot transfer an old inode's sync to the new inode. Conversely, an edit after B which has *only* a page-cache ACK has ordinary M exposure. Holding SAVED until directory sync cannot retract another operation's earlier durability promise.

**Corrected switch, also used for (ii).** The worker writes a private complete CURRENT from B, including both replay branches of unresolved saves, then repeatedly translates complete published suffixes outside the grant. Pin the old image and descriptors/owners needed to read those suffixes. For a finish, incorporate the verified fd-based BASE, saver cutoff ID and reconciled peer targets. For a pending peer checkpoint, keep the old transaction/binding semantics and add the by-value group instead. Replay-equivalence at the same logical boundary includes metadata, membership, other transactions and history-independent saved identities. Account for complete commands whose physical positions move; copying raw sequence numbers is incorrect. An invalidated binding, membership decision or source check discards the candidate.

Seal the private prefix at a wire PAD boundary and sync it **before** attempting a switch. Record its covered edit/metadata watermark and image generation. The journal arbiter serializes image switches and durability completions. Acquire at a complete boundary with no active append/reservation and no outstanding old-inode durability operation. Compare the candidate's covered watermark, source image, dependency/policy epochs and current published root with the writer's current values. This is an indexed version check, including every published change, even undo back to the same ID. On any miss release immediately, catch up and sync privately again. On an exact match, perform the journal rename and switch fd, sequence allocator and boundary mapping as one writer handoff before admitting another command. A failed or uncertain rename keeps admission suspended until the named inode is identified. Defer further image switches and syncs of the newly active journal until its parent barrier succeeds. Keys may append on the identified new fd while the parent barrier is pending. Perform the parent sync off grant, recheck target evidence and only then acknowledge finish or allow use of a new peer checkpoint to displace G. Directory failure retains both branch descriptions and a retry obligation. A writeback-loss repair builds a fresh inode from validated live state; ordinary ACKs remain suspended while continuity is uncertain.

At the corrected switch **zero journal data bytes, zero sync calls, one rename** (P, the candidate is already synced through the matched boundary; the only filesystem mutation is the name switch). A failed comparison has zero of each (P, it only releases the grant). K sees all ACKs on the unique active name before and after the switch. For M, either possible image covers every old durability promise; only later unsynced edits have ordinary exposure. Any new durability promise, including a synced PREPARED relied on by a target rename, waits for the new name's successful parent sync. Private work can be file- or session-sized and can repeat. Continuous changes can defeat an optimistic match indefinitely. This construction establishes safety and progress at quiescence; it gives no finite completion or key-latency bound under continuous writes. The frozen lower contracts do not supply this switch.

**(ii) Peer checkpoints before the grant.** Capture each dependent peer at a published boundary b, including closed-kept and recovered drafts. After temp sync, write its contiguous checkpoint group into that *private* image. Cover exactly the peer's bytes at b, translate the complete suffix after b and retain its independent metadata. The capture-time VALUE_ONLY embargo ensures later restores of G carry literals. Worker bytes per group are L + 40k + 132 + D (P, L literal bytes in k INSERT slices with header and offset, plus BEGIN, descriptor and COMMIT, and optional encoded TARGET of size D; journal.h, CHECKPOINT_BY_VALUE). Sync the groups before PREPARED. Use the corrected switch and secure its journal parent before relying on them. Take or validate the session-wide membership fence at a complete boundary. If another G dependency appeared, release and cover it first. Hold that membership reservation through target publication, allowing ordinary edits under the embargo. Identity checks and checkpoint coverage must still hold when authorizing rename.

If no peer needs protection, preparation skips the peer-image build. Otherwise the construction can write a complete session image even for a single peer. At a private partial group, old still supplies the original T2/T3 peer and G stays named. At peer-image rename K sees the complete peer plus suffix. M may still see old; G remains named in either case. Once the peer image is durably named, PREPARED can be appended; until PREPARED is also durable the target remains untouched. At target rename M can select G or the synced output, and **both** recover the peer. Closed membership replays independently. Thus the pre-grant construction survives K and M with the private-image switch and the displacement fence. A pinned snapshot alone supplies neither. Passing the named writer token per record fails: between CHECKPOINT_BY_VALUE and its COMMIT an unrelated acknowledged INSERT makes the group invalid. K loses that key; M can lose it even after a purported sync of the malformed group. Holding admission across the group instead writes L-dependent bytes. The record maximum bounds only a single member. [Contiguous group rule](../../src/journal/journal.h) · [Peer cuts](wave1-L2-q2-protocol.md)
