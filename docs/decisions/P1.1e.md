# P1.1e utf8 budgeted cluster width (edit-4w1.30)

## What
- `utf8_cseg` + `utf8_cseg_init` + `utf8_cluster_step(c, p, n, budget, eof, &used, &width)`: `utf8_grapheme_step` with the `utf8_cluster` width rule folded in. Same budget/eof/`*used` contract; `*width` is written on `UTF8_G_END` only, then the state resets.
- After each segmentation call the span just consumed (whole units) is folded into the width state: the first scalar with width > 0 fixes the base width; then only VS16, keycap and ZWJ+ExtPict flags can change it. A `DONE` latch stops scanning once the answer is fixed (wide base, Hangul block, narrow base that is neither ExtPict nor [0-9#*], or the flag already seen). The rest of the cluster is segmented but not scanned.
- Printable ASCII before ASCII returns END/width 1 without touching the segmenter (same fast path as `utf8_cluster`).
- Result equals `utf8_cluster` for every budget {0,1,2,3,5,4096} and every chunk size (tests: samples x budgets x all chunk sizes, 3000 random sequences, four long clusters; fuzz op with random budget/chunk).
- tests/utf8_test.c `place()` now rotates over 8 exact-size heap blocks, so up to 8 live results no longer alias (`t_place_alias`).

## Why not
- Re-scanning the whole cluster after END (the old `cluster_width_slow`): linear and unbounded; 531 us p50 on the 49 KB combining cluster (M)[AC].
- A separate width-only state machine over raw bytes: duplicates decode; scanning the already-validated consumed span is simpler and shares the unit boundaries.
- Changing `utf8_cluster` / `utf8_cluster_width`: left as the unbounded one-shot oracle.

## How layout (P3.1) should switch
Replace `utf8_cluster(p, n, &w)` with a `utf8_cseg` per cluster: `utf8_cseg_init`, then loop `utf8_cluster_step(&c, p + len, n - len, UTF8_GRAPHEME_BUDGET, eof, &used, &w)`; `len += used`; on `UTF8_G_BUDGET` check the slice deadline and either continue or yield with `c` and `len` saved in the layout cursor; on `UTF8_G_MORE` refill from the next chunk (do not consume the tail). The cluster is `[p, p+len)` with width `w` at END. `utf8_cseg` is a plain 12-byte struct, safe to keep in the cursor.

## Numbers (M)[AC], box shared with other workers, indicative; coordinator re-runs on a quiet box
One call at budget 4096, p99 (G <= 500 us): combining 49 KB 44.6 us, prepend 40 KB 65.5 us, ZWJ 35 KB 21.3 us. p50 23.3 / 59.1 / 17.5 us. Prepend is slower than the plain step (29 us p50) because the U+0600 run is Cf (width 0) so the whole 4 KB span is scanned; 2x, still 7x under the gate. Unbounded `utf8_cluster_width` for comparison (TRACK): 531 / 568 / 274 us p50. Existing gates unchanged (decode+width 500: p50 1.75 us, p99 3.3 us; ASCII skip 46 GB/s).
