## Model and resource ownership

`tabs_set` is caller-owned. `tabs_init` reserves one page-rounded `src/base` arena
for open-capacity plus closed-capacity stable records and the display, closed, and
free-slot index vectors. All subsequent operations use that reserve. There are no
module globals, resource callbacks on switch, file operations, buffer queries,
layout calls, or font allocations. Errors are return codes. Failed operations
preserve state and outputs; init failure leaves the caller's previous control
block unchanged. Init must not be called again on a live set without fini.

Each stable record contains borrowed `piece_tree *` and `undo_log *` handles,
`view_state`, copied title/path, modified status, a monotonically increasing ID,
and intrusive MRU links. The caller owns buffer and undo allocation, mutation,
save policy, worker cancellation, and retirement. Shared handles are permitted;
the caller must account for all references before retiring them. Undo logs remain
at their original addresses and are never copied by tabs. A tab pointer remains
stable through selection and drag reorder, and while retained closed; it becomes
invalid after eviction, reuse, or fini. IDs survive close/reopen and are never
reused during the initialized set's lifetime. ID exhaustion is a capacity error.

Display order is an index vector. Drag reorder moves one index to its final
position, preserving active identity and other records. MRU is independent of
that order. Ctrl+Tab follows the links without promotion while Ctrl is held;
Ctrl+Shift+Tab walks backwards, both directions wrap. Release promotes only the
last visited tab. Successful open/select/close/reopen/reorder first commits a
pending cycle; failed operations and rename/modified updates do not commit it.
Closing the active tab selects the MRU survivor, and closing an inactive tab
preserves active identity. Closing the last tab produces an empty live view with
preferred column unset. No replacement untitled buffer is created implicitly.

The closed stack is bounded by the init argument. It retains the entire record,
including view, modified status, and resource handles, so reopen performs no I/O
and restores undo history. Reopen inserts at the saved display index, clamped to
the current end, and activates the record. Full open capacity makes reopen fail
without popping. Close returns any oldest evicted record by value; zero closed
capacity returns the just-closed record. No eviction or shutdown silently destroys
resources. The stack bound caps tab metadata; it does not cap borrowed buffer
memory. The application must choose a retention policy consistent with G10.

Title/path lengths exclude NUL, must fit the declared fixed limits, and embedded
NULs are rejected. Paths are opaque. Arbitrary title bytes are accepted; malformed
bytes and controls render as replacement characters. Renaming supports inputs
aliased to the existing names, including exchanging title and path. Live state
and output records/IDs must not overlap tab storage or each other.

## Strip and bounded switching

Title segmentation and cell widths are cached on open/rename using
`utf8_cluster`/`utf8_decode`. A compact cache stores cluster lengths and packed
widths, with a replacement flag. The switch path performs no title segmentation
or width calculation. Its work is saving/loading `view_state`, choosing a stable
record, adjusting MRU links, then filling visible strip cells. The saved record's
state is the most recent switch-time snapshot; the loop's live state is
authoritative for the active tab between switches.

The strip is one row's specified column range. Uniform `tab_cols` determines
rendering and `tabs_strip_hit` geometry. The caller chooses `first_tab`; for a
simple paging policy use `(active_index / visible_slots) * visible_slots`, where
`visible_slots = max(1, col_count / tab_cols)`. A clipped final slot is supported.
At normal widths there is leading padding, title, an optional `*`, and a final
`|`. The modified marker takes priority at tiny widths. Titles truncate by whole
grapheme clusters with U+2026; wide glyphs are paired with glyph-free continuation
cells. Orphan zero-width clusters are skipped. Active highlight uses caller colors.
Empty remainder cells are filled with the inactive background.

The caller supplies a resident precomposed cluster-to-glyph lookup and binds the
atlas/glyph table on the grid beforehand. It must be bounded, allocation-free,
I/O-free, and must not mutate the grid/set. A missing glyph becomes background;
the caller should prepare titles, replacement, ellipsis, `*`, and `|` before
making the tab visible. An out-of-range or identity-mismatched callback result
also becomes background. Atlas images stay immutable through the frame's T5 as
required by frozen render.h. No callback results or atlas-slot identities are
cached in tabs, so changing frame bindings does not stale the title cache.

Rendering requires an initialized begun grid and damages only the strip's row.
It does not begin/submit frames or mark a full frame. It refuses a subrange that
would leave an old wide half in an untouched neighboring cell. All glyph and
atlas geometry validity remains the caller's frozen-render-contract obligation.

## Integration contract

All calls below run on the UI thread; workers never access a live `tabs_set`.

1. Before input starts, call `tabs_init(&tabs, open_capacity, closed_capacity)`.
   Initialize the loop's live `view_state`. Create buffers with the existing
   piece/file APIs and initialize their stable undo logs separately. Reserve
   their pools/arenas and resident title glyphs outside switching/typing work.
2. To open a prepared buffer, call `tabs_open(&tabs, &desc, &live, &id)`.
   `desc.state` is the initial per-tab view. Open appends/activates and copies
   names synchronously; on error retain ownership of the prepared resources.
3. Before any operation that may change the active tab, finish or cancel pending
   `view` work on the outgoing buffer (`view_cancel`). Publish any successful
   mutation prefix and modified status first. Keep `live` synchronized with the
   runtime view state. Call `tabs_select` for clicking/programmatic selection;
   call `tabs_mru_step` for each Ctrl+Tab press/repeat, with reverse true for
   Ctrl+Shift+Tab. On Ctrl release, focus loss, or cancellation of the held
   shortcut, call `tabs_mru_release`. Release changes MRU, not view state.
4. After a successful activation, get `tabs_active()`. Bind its buffer and undo
   to the loop. To rebind the existing view runtime using only main's APIs,
   `view_init(&runtime, active->buffer, &config)` then assign `runtime.state =
   live`; the persistent state is not overwritten. This is a fixed runtime reset,
   not file I/O or layout. Rebind per-buffer cached viewport/index/checkpoint
   handles in the application. Layout/redraw only the newly active viewport;
   retain other UI geometry and cached content.
5. Ctrl+W: resolve save/discard/cancel policy before `tabs_close`. Obtain the
   current index with `tabs_active_index`, call close with `live` and a distinct
   caller-owned `tabs_tab evicted`, then rebind the surviving active tab as above.
   `evicted.id == 0` means no retirement; otherwise retire its borrowed resources
   only after every tab/worker/pending-frame reference is quiescent. Empty sets
   render an empty strip and the loop's empty viewport policy.
6. Ctrl+Shift+T: call `tabs_reopen(&tabs, &live, &id)` then rebind as above. No file
   reload or new undo log is necessary. Empty/full errors leave the UI unchanged.
7. Mouse strip coordinates map with `tabs_strip_hit`; drag from/to final display
   indices calls `tabs_reorder`. The loop owns capture, drag preview, and pointer
   events. Reorder does not switch view or touch buffers.
8. After editing/undo/redo/save/change detection, the application computes dirty
   status and calls `tabs_set_modified`. Rename/Save As calls `tabs_rename` with
   bounded names after ensuring needed resident glyphs. Tabs does not infer dirty
   state from undo or saved tree identity.
9. For a frame, call `render_frame_begin`, bind resident atlas storage, call
   `tabs_strip_render`, and perform existing viewport layout/submit. On tab
   switch call `render_mark_full` as frozen render.h requires. No sidebar or other
   UI module is relaid out by tabs. The loop owns invalidation and presentation.
10. On shutdown, enumerate `tabs_at` and `tabs_closed_at` to account for all
    borrowed handles, retire resources after worker/frame quiescence, and call
    `tabs_fini`. Tabs does not save files or free trees/undo logs.

## Verification and evidence

The deterministic test and libFuzzer share an independent packed-array/ID-vector
oracle (in tests/tabs_test.c, included with TABS_MODEL_ONLY by the fuzzer), never
the implementation's linked-slot representation. They check each operation,
including view-state preservation, structural changes during held cycling,
bounded eviction, and errors. Separate tests use real small piece trees and undo
logs, validate resident Unicode strip cells using `render_grid_validate`, and
check range preservation, damage, fallback glyphs, and hit geometry. The release
malloc guard covers selection, strip fills, MRU and closed-stack/reorder work;
the ASan run explicitly labels its guard inert.

Red before implementation: `make build/tests/tabs_test` failed with undefined
references to tabs APIs. A later alias regression failed:
`tests/tabs_test.c:273: assertion failed: strcmp(names->title,"path")==0 && strcmp(names->path,"title")==0`.
Both are green after implementation/fix; test output ends `tabs_test: all passed`.

G3 full-frame target A is p50/p99 5.0/5.56 ms (G). This module gates only its
share (select/state swap plus strip fill), p99 <= 500,000 ns (G). It does not
claim the full-frame or whole-app G10 verdict. Benchmark samples include elapsed
scheduler delays; none are dropped. Warmup precedes samples. Frame begin,
resource setup, and power/load reads occur outside timed spans.

The initial uncached-title run, Charging [AC], load1=14.36, measured viewport
p50/p99 36,962/3,056,211 ns (M) and all-visible p50/p99 384,325/3,616,598 ns (M):
module-share MISS. This motivated caching title segmentation/widths rather than
re-running the same code to seek quieter scheduling.
