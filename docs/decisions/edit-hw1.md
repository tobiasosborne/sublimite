# edit-hw1 — Save As onto an open target

Apply the coordinator's narrow policy before writing the destination. A
modified peer refuses Save As with `<name> is open and modified in another
tab`; neither buffer nor the destination changes. Use the saved-history
marker, as clean external reload does, and the existing path comparison so
canonical aliases receive the same protection.

A clean open peer adopts the saved bytes through the existing clean-source
reload path. That path preserves logical tab identity and view clamping,
replaces undo history, and checkpoints the replacement BASE. The saving tab
keeps the ordinary Save As behavior. All setup remains retired-frame
maintenance; no new allocation enters typing.

The admission check precedes even the existing same-target ordinary-save
shortcut. Before reloading, stage peer BASE identities together so each
reload's complete checkpoint validates the whole session. Retained closed
tabs keep the preceding reconciliation policy; this change targets open peers.

This introduces no journal protocol. Transactional PREPARE for Save As and
the edit-o20 synchronous-maintenance limitation remain outside this bead,
as does edit-fi2's immutable recovery original.

The crash regression uses the existing journal rename seam to kill immediately
before checkpoint publication in the dirty-peer case. Refusal never reaches
that seam and is killed immediately after the command. The clean-peer case
is killed after Save As completes, before a later checkpoint. Fixture byte
lengths derive from literal text; path capacities reuse IPC_PATH_CAP. Pipe
ends, tab indexes, empty values and boolean initializers are structural (P).
