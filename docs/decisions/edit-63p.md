# edit-63p: prefix publication must not couple typing to window retirement

Keep the submission guard and fix the scroll fast path. A completed scroll
follow/place already certifies the visible top independently of the old
snapshot's resident worker windows. When that top has an exact label, index
prefix growth cannot invalidate its byte or ordinal. Refresh its extent with
the pure scroll policy; if the top remains READY, plan the frame and attempt
physical retirement without making retirement a presentation dependency.
An EOF clamp that requests another top still uses the resident resolver.

Keep the existing approximate-label publication checks: lazy prefix growth
does not relabel early, and exact publication still resolves an approximate
top. This preserves edit-agh's byte-jump placement and publication policy and
edit-jf9's separation of certified bytes from estimated ordinals. The existing
edit-3kk edit transform/follow continues to own the displayed top. Layout and
submit readiness checks still prevent stale cells; the closing snapshot and
its bridge remain leased until the worker physically finishes. No allocation
or new error path is needed.

The held-worker cancellation fixture dispatches the key through the real key
handler, then refreshes its edited index chunk before stepping the editor.
This deterministically orders edit/seek, prefix publication, then scroll/submit.
It retains the BLOCKED diagnostic and PROBE_RETRIES (E: inherited fixture
retry bound, no new duration). The submitted frame must appear in the first
turn after dispatch (P: the next scroll/layout/submit opportunity). A redraw
while held and a full redraw after retirement must preserve every prepared
text cell (P: the existing viewport's cell capacity).
