## Design choices made while coding

**Where the provisional count lives.** The count is kept in the checkpoint's restore header (its *cell*), not in the
tree or the core. A take while a checkpoint is open records `cell = t->checkpoint` and increments the cell's
`inside`; that header's last release, on any thread, decrements it. While the checkpoint is open the headers naming
the cell are exactly its live provisional snapshots, so abort drops the cache's ownership and then asserts
`piece_cell_live(t->checkpoint) == 0`. Commit only closes the checkpoint: the headers keep naming their cell, which
no open checkpoint names any more, so their later releases (a worker's included, concurrent with a commit) cannot
reach a later checkpoint's count.

- *Invariant.* A header is the restore view of a checkpoint with inside takes at most once. An inside take never
  hits an ordinary cached header, so it replaces the cache, and the cache is only ever set to a new header. Begin
  asserts `piece_cell_live(s) == 0` for the header it reuses.
- *Simplest alternative and why it fails.* One core-wide counter tagged with a checkpoint generation: a worker that
  read "generation g is open" can be preempted across commit g and begin g + 1, and its decrement then lands on the
  new checkpoint. Packing generation and count into one 64-bit CAS word leaves 16 generation bits once the count
  has its 48 (live headers < 2^56 / 400 B, P), so 65,536 begin/commit cycles inside one CAS window can repeat the
  word: a timing-dependent false death or a missed one, which A15 forbids.
- *Lifetime.* A cell's identity must not be reused while a header still names it. Holding an owner on the cell
  would chain: in the edit flow every candidate becomes the next restore view, so each published snapshot would keep
  its predecessor's whole revision alive. Instead only the cell's 400 B slot lingers: physical retirement sets
  `PIECE_CELL_RETIRED` and frees the slot only when the count is zero; the release that drops the last name of a
  retired cell requeues it on the core's inbox, and the next drain frees the slot (or the core's last owner takes it
  with its extents). At most one lingering slot per checkpoint with surviving inside pins, freed by their release.

**Undo phases.** A failed call with an open checkpoint is one of two phases, `UNDO_FAILED` (forward: pending records
to discard) and `UNDO_REPLAY_FAILED` (replay: undo's guard and pre-group view to release), so `undo_abort` keeps the
two cleanups apart. `undo_abort` on an idle log returns. For replay phases undo releases its own views before
`piece_checkpoint_abort`.

**One rule, initial prepare included.** The D1′ pass text says the uninterrupted later-record failure in
`later_group_refusal` "still returns idle". The brief carries the advisor's later ruling, "undo_replay_prepare on
NOMEM, RANGE or CONFLICT (initial or resumed), return their error and leave the checkpoint open", and the edit spec
records "one rule, no case split". Implemented the ruling: a first call that fails after `begin_replay` leaves the
checkpoint open; one that fails before it (empty history, the initial trust check, a refused begin) opened nothing.
`later_group_refusal` now aborts as owner.

**Erratum (i).** A take records `add_length`. Capture ends the cached take (`piece_uncache`) without touching the
live revision, so a cache hit needs only the lifetime test; revision and ADD length match by construction.
