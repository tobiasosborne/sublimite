# P4.5 minimap — edit-457.5

## Dependency change

The coordinator dropped the bead's dependency on the editor loop (edit-zzj.3).
This implementation is a standalone module against headers on main. Editor-loop
and tab integration are deferred to a separate follow-up bead. Only this bead's
module, test, benchmark, fuzzer and decision files are changed.

## Representation and density

`minimap` owns no memory: its state and row summaries belong to the caller.
`minimap_init` binds pre-reserved summaries; `minimap_fini` clears the state.
Fill, stale queries, and hit mapping never allocate or lock. Grid/byte/index
pointers are borrowed only during calls. Summary and grid storage must be
non-overlapping. Initial allocation can use a caller's `edit_arena` from base.

Each active row covers K consecutive logical lines, K=ceil(lines/grid.rows).
Unneeded bottom rows are blank. Empty buffers contain one empty line, matching
piece and lineidx. Density summaries are cached while revision, readiness, total bytes/lines and
height match. Scroll/theme/column-width changes repaint from those summaries.
Any stale event or edit forces regeneration on the next ready fill. This avoids
resampling dispersed mapped pages on each scroll frame.

The strip covers a caller-selected half-open column range
across the grid's whole height. All cells have RENDER_NO_SLOT, no glyph, no
attributes and zero reserved bytes. Density determines occupied width and
interpolated opaque sRGB background colour. A viewport band tints every column
in each row intersecting the visible half-open line range. Fill marks all rows
dirty using the frozen render API, including when stale.

Small files require both <=64 KiB and <=20000 lines. This conservative threshold
bounds an exact rescan when density is invalidated. Count non-space bytes per line, clipping
at 80, then average the clipped counts per row and scale to [0,255] with integer
floor. Space is the explicit ASCII set HT/LF/VT/FF/CR/space, independent of
locale. UTF-8 is counted as bytes; this is a density map, without shaping or
font dependence. Fragmented span sources produce the same counts as contiguous
ones. Final unterminated lines and the empty line after a trailing LF count.

Invalidated large-file fill uses at most 256 representative nominal chunks,
sharing each density sample across adjacent logical-line buckets. Let
C=ceil(source.len/LINEIDX_CHUNK), A=active_rows, S=min(C,A,256). Row r uses group
g=floor(S*r/A), sampled at floor(C*g/S)*LINEIDX_CHUNK. Each group reads at most
256 bytes, once per fill. Skip the boundary's partial line, then count the first
sampled line with the same space/clipping rule. Boundary zero starts a line
already. If there is no LF in the sample, use its clipped long-line fragment.
A sample may end before a complete line; its count is a bounded approximation.
Density uses sample ink*255/80, without averaging unsampled lines. `sampled`
distinguishes this approximation from exact small counts. Viewport/hit positions
still use every logical-line bucket; nonuniform file regions can make the
representative byte sample differ from the bucket's precise byte position.
Limiting scattered reads is a deliberate spatial-resolution tradeoff, avoiding
thousands of mapped-page touches on a tall strip after each edit. Empty sources
with an estimated line count defensively use an empty sample at byte zero.

The frozen-on-main lineidx header exposes chunk size, count, total bytes and
line counts, but no per-chunk starts, byte lengths or newline counts. After
edits chunks can merge and shift. Therefore these are **nominal** boundaries,
not a claim to expose actual edited chunk records. The bounded line-length
sampling fallback is permitted by the bead. Existing line_to_byte and
byte_to_line queries can scan whole chunks, so fill does not call them per row.
Large fill is O(min(C,H,256)*256 + W*H), independent of file length and chunk count; small
fill is O(source bytes + W*H) with the stated size bound. H is grid rows, not
necessarily physical pixels. The acceptance bench uses cell_h=1 and H=1800.

## Proposed accessor (not implemented)

A future lineidx bead could expose a read-only chunk summary accessor returning
actual start/end byte offsets, prefix newline count, chunk newline count,
built flag and a generation. An O(1) cached overall readiness/count query would
also avoid lineidx's derived-summary rebuild inside UI queries after edits.
Neither accessor is required by this module and src/lineidx is unchanged.
With summaries, a future minimap bead can replace nominal samples with actual
chunk mean line lengths without scanning bytes or changing the render contract.

## Staleness and errors

The caller supplies source, total line count, a monotonically changing revision
and `index_ready`. Revision changes for every mutation, including same-size edits
and undo/redo. Readiness means the index describes those bytes/revision, is
complete and is not building. Index publication/readiness belongs to the
existing loop/index owner; fill never polls, builds, refreshes, waits, or
queries the index. This keeps index work outside the bounded minimap slice.

`minimap_stale` compares readiness, revision, byte length and line count plus
stored stale state. Pending-index fill reads no source bytes and paints retained
summaries when heights match, otherwise a blank strip, with a stale tint.
The stored stale flag clears only on successful fresh fill. Old revision hits
are rejected, never interpreted as current byte locations. Bad arguments leave
state and grid untouched. A broken span or inconsistent small-file line count
invalidates summaries and returns MINIMAP_ERR_SOURCE before modifying the grid.
All errors are return codes; the module has no logging/global state.

## Integration contract

All calls occur on the UI thread, which exclusively owns minimap, current buffer,
index and grid. There is no internal worker and no cross-thread minimap state.

1. At buffer/tab open reserve `max_rows` summaries in caller storage (e.g. a base
   arena), keep them alive with the minimap state, and call `minimap_init`.
   On a height increase beyond capacity, rebind larger pre-reserved storage via
   init before rendering. A rebind invalidates the old density until next fill.
2. Maintain a revision counter per buffer and change it on each mutation, before
   consulting minimap or submitting another frame. Update the line index using
   its existing owner workflow. Do not call blocking build/cancel/destroy APIs
   from inside a minimap fill. Source span must be nonblocking, allocation-free,
   expose current immutable-for-call bytes, and return a valid contiguous span
   at the requested offset. No release hook is invoked by minimap.
3. On index progress/work mailbox events, let the existing UI index owner call
   `lineidx_poll`, query `lineidx_line_count`, `lineidx_complete` and
   `lineidx_building`, and verify `lineidx_len == source.len`. Construct
   `minimap_input` from those results and the matching current source/revision.
   These index operations are **outside** minimap fill's timing budget; in
   particular lineidx may derive summaries after an edit. Before publication of
   the current revision's completed index, set index_ready=false.
4. In a begun render frame, after layout has reserved the strip's columns, call
   `minimap_fill` with source input, grid, first column/width, viewport's first
   logical line and visible logical line count, and theme colours. The strip
   must not cut a wide-cell pair belonging to text layout. Renderer uses its
   normal dirty-strip/submit flow; stale tint is drawn by fill, and `m.stale`
   or `minimap_stale` can drive an additional status indicator. Include this fill
   in the complete G3 frame measurement when integration lands: target A
   (G) full-frame p50/p99 <=5.0/5.56 ms, with this module's (G) p99<=0.5 ms slice.
5. Between fills, call `minimap_stale` after edit/index events before relying on
   retained summaries. To repaint a stale tint, fill with index_ready=false.
   After readiness becomes true, fill again; merely querying does not clear it.
6. For click/drag, convert pointer-relative pixel y to a grid row using cell_h,
   including negative coordinates, then call `minimap_hit` with the same current
   input and matching index. Out-of-strip y clamps to the first/last active row.
   Scroll the viewport to returned line (or use returned byte as a line start).
   Small hits use cached exact starts. Large hits make one existing index
   line_to_byte query on demand; this is outside the fill budget and may scan a
   chunk. Reject stale hits and request a fresh fill. `minimap_row_for_line`
   provides the inverse bucket mapping for a fresh state.
7. At tab close call `minimap_fini`, then release caller storage. Keep existing
   grid/atlas lifetimes through renderer submission as required by render.h.

## Verification and performance

The test was first run against an error-returning stub and failed at the init
assertion; after implementation the density/hit/staleness/allocation suite passes.
Tests independently count small-file density, verify fragmented input, large
bounded sampling and exact index hit resolution, viewport colours, dirty rows,
real same-size edits, sample-cap/read bounds, resize invalidation, invalid capacities
and broken spans. The release malloc
interposer guards fills in both modes; the sanitizer guard is inert by base's
existing design. The fuzzer generates random line-length/whitespace vectors,
source fragment sizes, strip heights/widths, compares independent counts and
samples, checks hit round trips and stale/refill transitions.

`bench/minimap_bench.c` measures warm fills with matching cached density summaries on a
small fixture at the exact byte threshold and the existing log_1g corpus. A separate gated TRACK row measures invalidated fills following actual edits. It
checks real edits, stale fill without source reads, index refresh and independent
recomputed density. It prints power/load evidence and p50/p99 in nanoseconds,
with (G) p99 <=500000 ns. Either a warm-fill or after-edit-fill gate miss returns nonzero. Shared-box results are
TRACK only; quiet-box gate verdict and combined G3 frame budget belong to the
coordinator. The standalone bead does not implement an editor-loop G3 frame.
