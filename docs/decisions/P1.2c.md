# P1.2c — work/scan review fixes (edit-4w1.50)

Scope: work-scan-1 §§10–13,16. No implementation or public-header changes.
Self-checks below are synthetic contract tests, not performance measurements.

## §10 — accepted: G6c measured the wrong interval

Fix: time caller request immediately before `work_cancel` through its return;
gate logical acknowledgement at 1/5 ms (G). Independently measure polling gaps
with CLOCK_THREAD_CPUTIME_ID immediately after every stop check, including the
check that observes cancellation; any maximum above 5 ms (G) fails, even outside
p99. Bounding every consecutive polling interval bounds the next CPU slice
without attributing UI/worker descheduling or I/O wall time to worker CPU time. Assert both suppression
of a queued pre-cancel message and rejection of publication after stop. Wall-time
physical retirement and idle submit/start are TRACK. This synthetic scan job
validates benchmark instrumentation, not every production worker's polling.

`build/bench/work_bench --self-check-cancel`:
```text

GREEN work_bench self-check §10: PASS delayed return rejected=1 CPU slice rejected=1
```
The red used the original internal-cancel-to-observation interval and omitted
CPU gating; the regression supplies a 20 ms caller interval and a 6 ms CPU slice.

## §11 — accepted: failures could hang

Fix: validate both submitted handles; deadline start, observation, and actual
slot retirement waits (2 s safety deadline). A failure immediately invalidates
the entire run with nonzero status rather than discarding a sample. Run the pool
in a child supervised by a monotonic 60 s deadline covering init, cancel, drain,
and shutdown. Kill/reap a stuck fixture; the parent never joins its broken pool.
The deadline self-check exercises absent events, refused/valid handles, an
already-signalled event, a stuck busy slot, and stuck cleanup.

`build/bench/work_bench --self-check-deadlines`:
```text

GREEN work_bench self-check §11: PASS missing waits/refusal bounded=1 cleanup bounded=1
```
The red wait never completed and the self-check supervisor terminated it.
**Proposal outside this bead's file allowance:** give `tests/work_test.c` waits
deadlines and isolate shutdown-dependent failure cases in a supervised child.
Leave that change and work STATUS ownership to the parallel P1.8c worker.

## §12 — accepted: arbitrary p99 regressions passed

Fix: preserve P1.2's >=12 GB/s p50 primitive criterion and add >=12 GB/s p99 (G)
for both primitive rows. This chooses an explicit pure-scan p99 module budget of
89.48 ms per 1 GiB (G), with 25% throughput slack below the 16 GB/s G6 basis.
A separate `scan_count_G6_basis` row enforces >=16 GB/s p50, >=12 GB/s p99 (G);
all rows affect process status. Invalid/zero/nonfinite samples also fail.
Use nearest-rank latency quantiles expressed as speeds. Synthetic boundary and
15 GB/s basis samples verify acceptance and rejection independently of load.
The buffer is cached anonymous memory: these rows do not prove G6/G7's request,
new-mapping faults, and publication endpoints. No hot path changed here; those
end-to-end runs remain for the respective module owners/quiet-box coordinator.

## §13 — accepted: self-derived oracle concealed prefix scans

Fix: accumulate independent newline/non-ASCII expectations while generating the
fixture, including its final-byte overwrite. Warm-up and every timed result must
match the counts and/or exact last pointer `buf+SIZE-1`. The self-check rejects a
64 KiB prefix, wrong pointers, and incorrect non-ASCII counts; a correct result
passes. Unit tests check all APIs on an 8 MiB+17 range at all 16 offsets, including
newlines and a first matching byte beyond 64 KiB, against scalar/analytic oracles.

## §16 — accepted coverage defect; no implementation overread found

Fix: exact nonempty heap bounds, all 16 alignments, and an ASan assertion that
`p[n]` is poisoned. Empty heap fixtures use a one-byte allocation only where
necessary; inaccessible empty ranges are checked separately. Map protected pages
on both sides of writable storage; check every length 0..8192 with ranges ending
exactly at the right PROT_NONE page and ranges starting at the left page. New
`fuzz/scan_fuzz.c` compares all three APIs with scalar oracles, guards range
boundaries, splits ranges, and covers all byte values, empty ranges, SIMD/chunk
boundaries, larger ranges, and extreme ranks. It introduces no module changes.
