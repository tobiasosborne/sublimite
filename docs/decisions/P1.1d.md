# P1.1d utf8 resumable grapheme segmentation (edit-4w1.19)

## What
- `utf8_gseg` (public plain struct: UAX #29 left context + `started`) and `utf8_grapheme_step(g, p, n, budget, eof, &used)` returning `UTF8_G_END | UTF8_G_BUDGET | UTF8_G_MORE`.
  - Budget is in bytes, checked before each unit, so a call consumes `budget` plus at most 3 bytes. Budget 0 means 1 (progress guarantee).
  - State survives across calls; chunked == one-shot for every split and budget (GraphemeBreakTest 1187 cases x every split x budgets {0,2,4096}; unit tests; fuzz).
  - Truncation never manufactures a boundary: with `eof == 0`, a truncated multi-byte tail (a proper prefix of a valid sequence, `partial_tail`) returns `UTF8_G_MORE` and is not consumed; only bytes that are invalid whatever follows (E0 80, lone 80, ...) are invalid units. With `eof != 0` the tail is invalid bytes, matching `utf8_grapheme_next`.
  - On END the state is reset, ready for the next cluster.
- `utf8_gprev` + `utf8_grapheme_prev_step`: resumable, budgeted `utf8_grapheme_prev`. The backward walk is NOT bounded by itself (the nearest certain break can be arbitrarily far: 'a' + 24,576 marks), so there is a two-phase state machine (back scan, forward replay) sharing one byte budget per call. Result equals `utf8_grapheme_prev` for every offset and budget.
- `utf8_grapheme_next`, `utf8_cluster`, `utf8_cluster_width` unchanged (one-shot, unbounded, reference for the step API). `gstate` is now a typedef of `utf8_gseg`.

## Default budget
`UTF8_GRAPHEME_BUDGET` = 4096 bytes per call. Measured (M)[AC], box shared with other workers: 29-38 us per call at p50, p99 32-47 us on the three pathological clusters (G p99 <= 500 us), i.e. >10x under the slice. Unbounded call before: 358 us p50, p99 585 us on the 49 KB combining cluster (over the 0.5 ms gate). 4096 is also a convenient size: <= 500 shaped chars * ~4 B is ~2 KB of normal text, so ordinary clusters never hit it.

## Alternatives rejected
- Budget in scalars: bytes are what the caller already has (chunk sizes, snapshot spans) and bound the decode cost directly.
- Hard cap on cluster length (force a break after N scalars): changes segmentation, violates UAX #29 / the oracle, and the cursor would no longer move by user-perceived characters.
- Rewriting `utf8_grapheme_next` on top of step: a few ns per cluster for the extra control flow on the 500-scalar TRACK rows; kept separate and used as the oracle.

## Numbers
Total across calls (TRACK): 5.9-9.1 ns/byte (M)[AC], same order as the unbounded call (7.3-9.6 ns/byte); the budget costs nothing measurable.
