# P2.3d (edit-e6x.13): recover safely from raster arena exhaustion

## Decision

The per-raster stb allocator now uses a C `setjmp`/`longjmp` error boundary.
If an arena allocation fails, it leaves stb immediately instead of returning
NULL. `font_raster_glyph` clears stb userdata, rewinds the arena to its entry
mark (including the unfinished bitmap), leaves `out->pixels` NULL and returns
`FONT_ERR_NOMEM`. Successful calls keep the bitmap and rewind only scratch.
The bitmap byte multiplication is checked for overflow before allocation.

This replaces the P2.3b assumption that stb always handles a NULL allocator
result. Its heap scanline dereferences NULL, and its active-edge allocator
asserts on NULL. Both are protected, as are outline, contour, point and edge
allocations, including recursive composite outlines and CFF glyphs.

A bbox-only scratch estimate does not bound outline complexity: overlapping
contours and composite components can add work without increasing the bbox.
The error boundary handles the actual allocation failure without speculative
scratch reservation, an outline-counting pass or a vendor modification.

Unwinding is safe here because every stb allocation is arena-owned and
`STBTT_free` is already a no-op; stb holds no other resources on this call
chain. There are no variable-length arrays to unwind. The error branch uses
only the unchanged function parameters and entry mark, never automatic values
modified after `setjmp`. The per-call context is stack-owned and the font is
usable after failure. The existing single-thread ownership requirement for a
`font_t` is now explicit in the public raster comment.

No libc allocation, arena resize or allocation outside the supplied arena is
introduced on the typing path. `bench/font_bench.c` and its gate are unchanged.
