# P4.11 — Unicode rendering completeness (edit-457.11)

The existing UTF-8/layout path already supplies exact grapheme boundaries and
cell widths. This bead supplies the missing `layout_glyph_fn`: an append-only,
monochrome cluster cache using the embedded face and the two discovered system
faces. No renderer contract, layout implementation, Unicode width table, or
font parser is changed.

## Composition and widths

`font_cache_glyph` takes the width supplied by `utf8_cluster[_step]`; it does
not infer a width from font advance or duplicate East Asian Width tables.
Combining marks share the base's cell image. Coverage is the maximum of each
outline's R8 coverage, preserving base pixels wherever the mark bitmap is
transparent. A negative-bearing mark is placed relative to the base advance;
a positive-bearing mark is cell-relative (the embedded Mono combining marks
have positive bearings). All faces use the primary face's ascent as their
baseline. CJK W/F and emoji images span the two cells chosen by utf8; layout
continues to emit and clip valid WIDE_LEFT/WIDE_RIGHT pairs.

VS15/VS16, supplementary variation selectors, ZWJ/ZWNJ and emoji tag scalars
are invisible sequence controls. They do not require a font glyph. Zero-width
standalone clusters retain P3.1's behavior (dropped). Visible marks require
coverage; a missing visible component returns MISSING for the cluster. Missing
clusters retain layout's `?` replacement. Zero-ink covered glyphs return
RENDER_NO_SLOT. The raster output is exclusively R8, including emoji; color
emoji is rejected by the existing fontconfig discovery.

**Invalid bytes: one inverse `?` cell per invalid byte.** This preserves the
strict decoder's one-byte invalid units and P3.1's layout convention. Valid
U+FFFD is a normal glyph, not an invalid-byte marker. The screenshot explicitly
checks overlong and truncated sequences alongside valid U+FFFD.

No bidi, IME, script shaping or emoji ligature engine is introduced. Covered
spacing components of a ZWJ/Hangul cluster overlay at their origin; this is
scalar monochrome composition, not a promise of ligature artwork or contextual
Arabic shaping. Width remains the exact existing cluster width. The existing
layout composition limit is retained; clusters larger than its fixed window
still draw `?` with approximate=true. The fallback-covered acceptance set is
explicitly the embedded font plus the discovered CJK and monochrome emoji
faces, not every font installed on the machine.

## Discovery, ownership and allocation

Discovery remains `font_fallback_discover` / `font_fallback_job` on WORK_BULK.
The new `font_family_load` is INIT/worker-only: after acquire-observing discovery,
it reads fallback files into a caller arena and selects each fontconfig TTC
index with `font_init_index`, at the primary pixel size. Empty paths gracefully
leave the primary available. File/init errors propagate while retaining usable
faces; malformed-input parser paths were left unchanged. The tests and new
bench setup run discovery and loading on an actual work-pool worker, publish a
mailbox result, then join before using the family on UI.

`font_cache_init` reserves all runtime page pixels, exact-key bytes, a fixed
hash table, glyph descriptors, a two-cell composition image and raster scratch
from the caller arena. Initialization is transactional on exhaustion. Runtime
pages are pre-touched at INIT. No cache call opens a file, discovers fonts,
requests memory from libc or grows an arena. Cold raster scratch uses only the
reserved subarena and is rewound after every call. A cache hit (including a
cached MISSING) does not allocate from even that subarena.

Keys include exact UTF-8 bytes and supplied cell width; hash collisions are
checked with byte equality. Storage is append-only, with no eviction or slot
reuse: referenced atlas rectangles remain immutable through the renderer's T5
bound, including when new fallback pages open. Exhaustion returns NOMEM;
already cached entries continue to work. Missing clusters are negatively
cached, but ARG/INIT/NOMEM are not. Caller chooses resource bounds and keeps
family sizes/bytes stable for the cache lifetime. One cache binds one grid;
`font_cache_bind` sets page/table pointers, and successful appends update its
counts. Bind again to switch grids. No globals or new threads are introduced
in the font module; its family/cache remains exclusively UI-owned after INIT
worker handoff. Invalidation/size changes require a fresh cache at quiescence,
not editing images still referenced by frames.

GREEN headless tests use both baked sizes and compare every pixel of a small
computed screenshot against both scalar and SSE2 CPU raster buffers. The
expectation is made from separately rasterized outlines with the existing
placement API and independent color blending, without using cache pixels or
layout's cell contents. It covers base+mark, CJK, monochrome emoji, U+FFFD,

corpus is laid out in batches of full viewports; every grid validates and every
covered visible cluster must avoid the placeholder. Unique covered/uncovered
scalars are enumerated by the test from the actual loaded fonts. Page growth,
immutable retained images, width-sensitive exact keys, hash-table exhaustion,
init rollback, missing discovery and negative caching have separate assertions.
