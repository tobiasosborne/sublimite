## Contract

The appended **P1.3c amendment** in `src/piece/piece.h` is binding:

```c
typedef struct piece_checkpoint piece_checkpoint;
int  piece_checkpoint_begin(piece_tree *t, piece_checkpoint **out);
void piece_checkpoint_commit(piece_checkpoint *c);
void piece_checkpoint_abort(piece_checkpoint *c);
```

- All calls are UI-thread only. At most one checkpoint is active per tree;
  independent trees may each have one. The tree outlives the checkpoint.
  Commit and abort consume a live handle exactly once; using a consumed handle
  or destroying its tree first is caller error.
- Begin returns `PIECE_OK` and a handle, or `PIECE_ERR_NOMEM` with unchanged
  content and a NULL output. It may reserve through the existing allocator.
  A NULL tree, NULL output argument or nested begin returns `PIECE_ERR_RANGE`;
  every failure clears the output when an output pointer exists. A rejected
  nested begin leaves the original checkpoint active.
- Commit keeps the current content, ends the checkpoint, makes no allocator
  allocation requests and cannot fail.
- Abort restores the exact pre-begin bytes, length, line counts, piece counts
  and all other public query results, plus append-coalescing/control state.
  It makes no allocation requests and cannot fail, even if every allocator
  request after begin would return NULL. Restoration does not revive tree
  iterators invalidated by intervening edits; abort itself is a mutation.
  Begin and a commit without edits do not break an append run.
- Snapshots and refs from before begin survive either outcome. A snapshot
  taken inside keeps its own intermediate content across abort, later edits
  and tree destruction. Refs first produced inside a committed checkpoint
  retain their normal validity.
- Refs first produced inside an aborted checkpoint are invalid, even when
  they describe older add bytes. Callers must discard them. Cheaply detectable
  invalidity must return `PIECE_ERR_RANGE` without changing content: in
  particular, spans beyond the restored logical add high-water mark are
  invalid even when a snapshot retains their physical storage. The frozen
  `piece_ref` has offsets, not generations; old-range aliases, empty refs and
  offsets subsequently reused need not be identifiable. Using these invalid
  refs is caller error, with no guaranteed return value. Implementations must
  document any further detection limitations.
- All transaction reservations, retained roots, copied paths and add bytes
  count under G10f while active. The retained root gets the existing snapshot
  path-copy allowance. Abort reclaims transaction-only ownership and returns
  copied nodes to pools; any bounded cache remains charged. Repeated aborts
  without surviving intermediate snapshots must fit the restored tree's
  bound, without accumulating aborted typed/deleted-byte allowances. Storage
  required by an intermediate snapshot remains charged as retained snapshot
  content/path copies until its release; its immutable bytes cannot be reused.
- Inactive-checkpoint overhead is at most **one predictable edit-path branch
  (G)**. Checkpoint support adds no allocation, copy, traversal or accounting
  to that path when inactive.

This explicitly narrows P1.3b's append-only add-buffer/ref-lifetime wording
for aborted, unpublished transaction results. It does not change `piece_ref`
or any pre-existing declaration.

## Rationale and intended implementation

Undo review `docs/reviews/P1.5-1.md` section 1 is blocked on atomic group
replay. An operation after a successful prefix may fail permanently. Undo must
be able to restore the existing tree, rather than merely keep a readable
snapshot of the prior document.

The following rationale is carried forward from the **piece.h amendment
proposal** in `docs/decisions/P1.5d.md`:

> Why an undo-only fix cannot work: `undo_init` receives an opaque existing tree,
> not its allocator or reservation handles. Undo's pool/arena cannot satisfy
> requests made through that tree's private allocator. The only byte-changing
> piece calls (`piece_insert`, `piece_delete`, `piece_insert_ref`) may fail with
> NOMEM, including the inverse of an already successful replay operation. A
> persistent failing allocator can reject the second forward operation and every
> rollback operation. Warming the current kernel is no guarantee in piece.h;
> private free pools may be trimmed, shared paths may require new copies, and
> bulk/ref flattening may need add storage. A snapshot can read the prior bytes
> but cannot restore the existing tree. Replacing `u->tree` with a clone would
> leave callers' existing tree pointers changed/incorrect and requires a second
> storage budget. None of these operations gives a no-fail restore primitive.

Intended kernel design (informative in the header, binding in spirit for
edit-4w1.37): retain the root as a snapshot and save the add-buffer high-water
mark, counts and control metadata. Edits copy paths while that root is held.
Abort transfers the retained root back, truncates the logical add tail and
returns discarded paths to the pool. Commit drops the retained root.

Physical truncation must respect snapshots of intermediate content. A snapshot
cannot share a transaction tail that later edits overwrite, and abort cannot
allocate a detached copy to rescue it. The kernel must establish the necessary
ownership before abort, and retain only the storage those owners still need.
Generation fields or per-edit ref registries are not required solely to detect
the documented caller-error aliases.

Undo can then begin a checkpoint per replay group, stage its own capture and
cursor/history bookkeeping, commit both at the boundary and abort the tree on
failure. Previously completed groups in a batch stay completed. This bead
does not change undo or implement that integration.

The memory fixture repeats **64 cycles (G, fixture)** with a **262161-byte
insert (G, fixture)**, exceeding the restored tree's fixed slack. It enforces
the existing G10f expression, with **1920 B per edit (G)** for the checkpoint's
retained root while active. It permits charged, bounded node/chunk caches;
it rejects retention of an aborted add tail or cumulative trial-edit credit.
The failing allocator wraps the suite's existing counting hooks using the
persistent `armed`/`remaining` pattern from `tests/piece_mt_test.c`.

`tests/piece_model.h` implements checkpoints by allocating a flat copy at
begin, freeing it at commit, or transferring it back at abort. Its allocator
is independent of kernel failure injection, and its terminal operations do
not allocate. It is an oracle, not a candidate kernel implementation.

`fuzz/piece_checkpoint_fuzz.c` supplies random begin/edit/commit-or-abort
sequences, single-request and persistent NOMEM injection, nested begin,
delete/reinsert refs and retained snapshots. Successful edits update the model;
failed edits must leave the same bytes. Abort compares with a saved pre-begin
model and piece count; commit compares with the edited model and current piece
count. Both terminal calls are checked for zero allocator allocation requests.
A mandatory healthy begin/retry prevents a permanent-NOMEM stub from passing
the fuzz checks vacuously. Input ending mid-group is aborted and checked too.

## Implementation — P1.4e / edit-4w1.37

The link stub is removed. `piece.c` retains an ordinary snapshot at begin and
saves the tree's counts, initialization flag, append-run and cursor state,
together with its logical add high-water mark. Abort transfers the retained
root back and drops the discarded root; commit drops the retained snapshot.
Both terminal operations issue no allocator allocation requests.

Begin reserves a directory for the saved add prefix, sharing its chunks.
Snapshots pin their own append-only directory. Before publishing an inside
snapshot that observes a transaction tail in the saved boundary chunk, snapshot
take prepays a writable saved boundary copy. Abort swaps directories and seals
and prunes the abandoned view to the highest ADD offset actually referenced
by its surviving roots. It uses the prepared boundary only while a surviving
transaction snapshot needs it; otherwise it frees the copy and shares the
original boundary again. The restored edit path needs no deferred checkpoint
allocation or copy. The sole inactive checkpoint branch is in snapshot take;
ordinary edits need no checkpoint branch or transaction counters.

The existing node header's otherwise-unused live free-link word caches each
subtree's ADD high-water mark. It adds no node bytes and also bounds snapshot
storage ownership. Original data/mapping epochs are retained by snapshot
headers, so initialization inside a checkpoint may be aborted and retried
without invalidating its snapshots or leaking mapping owners. Cursor reuse
is restored only if every saved path node remains exclusive; otherwise the
saved append run continues through ordinary COW.

Abort force-trims unused node reservations even when a pre-begin snapshot
survives. Snapshot final release synchronizes with owner reservations and
reclaims unused slabs without waiting for another tree query, including when
the tree still caches a current-version header. All storage is allocator-hook
owned; surviving snapshot storage remains charged until release.

The frozen ref layout detects spans outside the restored logical high-water
mark. Old-range, empty and reused-offset aliases remain the caller errors in
the amendment; no additional alias detection is claimed.

All frozen checkpoint rows and the added lifecycle/thread regressions are
green. P1.4e.md records the evidence and unresolved G10f contract conflicts,
including the funding needed for immutable boundary storage. The fixed header
has not been changed; this implementation must not be described as satisfying
its constant snapshot funding at arbitrary depth or for every boundary copy.
