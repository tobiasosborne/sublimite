## Scope and contracts

Integrates keys, tabs, indent, minimap, IPC and P4.1 wrap into the P3.3 loop.
The standalone implementations and headers in keys/tabs/indent/minimap/ipc
are unchanged. **Contract gaps requiring standalone-module amendments: none.** Layout
changes are additive paint callbacks only; no CRLF or 4 GiB layout fix is included.
The finisher changes no Makefile or frozen header and runs no git writes or
bead commands; only the explicitly allowed read-only git log/diff were used.

## Ownership and activation

The window owns its workers, platform, backend, atlas, grid, layout and fixed
input/journal/decorations scratch. Each buffer has a stable heap control block,
an open-time base arena, tree, noncopied undo log, history metadata, file/index,
detected indent style, revision and caller-owned minimap summaries. Tabs borrow
those stable tree/log handles. The active loop aliases its buffer rather than
copying undo or owning module state. Default bounds are 128 live and 16 retained
closed tabs; bounds can be supplied at open. An independently reserved empty
buffer implements the empty-window policy. Opening is an allocating setup/IPC
operation, not a key mutation. Ctrl+N remains an unimplemented counted action.

Tabs save/load the complete pointer-free view_state. Activation requires idle
view work, resets the runtime with view_init, binds the shared reserved layout
via view_wrap_file, restores the retained state/override, and starts full redraw.
This preserves visual_byte, soft-end affinity, selection and per-file wrap. Begin establishes the incoming gutter/text width before querying a visual seed; resize normalizes the stored seed to the new visual row. A regression switches between one-line and four-digit gutters while scrolled within a wrapped line.
Activations perform no file open/save, allocation, worker creation or index
build. Key queue ordering finishes any pending view repair before switching;
IPC draining waits for idle view work, an empty input queue and submission of any pending key frame. A delayed-backend/socket regression proves that setup allocation cannot overlap input-to-submit or steal its frame attribution. Layout continuations can be discarded
when replacing the active viewport. A held MRU sequence freezes its ordering;
Ctrl release, focus/keymap changes or a different command commits it. Shift
modifier presses preserve the held sequence. Pointer capture maps uniform strip
slots through tabs_strip_hit and tabs_reorder. The active slot stays visible.

Close defaults to retaining the buffer for reopening; a caller allow_close
callback can cancel or implement a save/discard policy before tabs_close.
The log, history and view survive close/reopen. minimap_fini runs on close;
its reserved rows survive with the retained buffer and are reinitialized on
reopen. Evicted resources are retired during IO pumping after rebinding the
layout; index/file jobs are joined before their trees/arenas are destroyed.
Shutdown retires both live and retained buffers and finalizes tabs afterward.
Dirty state tracks the saved history position, with a sticky flag when that
position is evicted. Undo back to the initial state clears the modified marker.

## Keys, indentation and paint

keys_lookup is the sole shortcut table. Prefixes and cancelled chords consume
input. State resets on focus, keymap and tab changes. Supported dispatch includes
view navigation/selection, deletion, insertion, undo/redo, indexed/adjacent tabs,
MRU, close and reopen. P4.3's UNIMPLEMENTED bit describes executor availability
when that table landed; the loop explicitly supports its now-integrated editor
and undo actions. REDO_OR_REPEAT remains unimplemented because command repeat has no executor; it is consumed/counted as the contract requires. Every other matched action is consumed and increments
unimplemented_actions. Unmatched ordinary UTF-8 uses the same undo mutation path;
shortcut modifiers suppress text, while AltGr text is permitted.

Enter deletes any selection, queries indent_on_enter on the resulting tree and
inserts exactly the returned bytes. A brace deletes the selection, queries
indent_on_close_brace before insertion, deletes its dedent range, then inserts
its returned brace exactly once. All operations share one explicit undo group.
The history/journal delta covers the contiguous replacement, including selection
and dedent. Queue admission reserves three journal operations, so a full queue of selection/dedent/insert groups yields to submission instead of dropping a command. Each successful operation updates revision, line count, index and
layout. A mutation error closes the group and accepts its successful prefix,
then stops the loop with a negative error. Query/capacity rejection is counted;
any successful selection deletion is repaired and recorded as that group's
prefix. Enter scratch is reserved at open (512 KiB); larger insertions are
explicitly rejected, never truncated or allocated on the input path.

The compact viewport is laid out first to determine its actual byte window.
indent_bracket_match and indent_trailing_ws_ranges then populate frame-owned
storage. A second row pass applies layout_set_paint before cursor/selection
colours. Brackets and trailing whitespace use UNDERLINE plus background/colour;
no render attribute/header amendment is needed. Decorations still run on the remaining cells of a cursor tab and a soft continuation even where repeated cursor styling is suppressed. Source and mate must both occupy
visible cells; clipped mates do not highlight the source. EOF rows use their
end offset when their next-row sentinel is VOID. Every cursor/text/viewport
change invalidates the decoration pass; no old offsets survive a mutation.
The no-wrap preparation window is capped at LAYOUT_BYTE_BUDGET so an unused
long-line tail cannot trigger an unbounded indent scan. Very deep unindexed
horizontal positions omit unresolved bracket decorations; cropped trailing runs
are omitted by indent's existing contract. Frame range capacity is max_rows;
CAPACITY keeps its documented valid prefix. These are explicit bounded-paint
limits, without changing the separate long-line/CRLF layout work.

P3.3's undo edits happen outside view_command. Its empty TYPE repairs grapheme
boundaries but does not mark the view as edited. The loop therefore uses a fresh
visual-row query when following a mutation into newly appended wrapped rows;
this also preserves the existing scrolled-undo regression without modifying view.

## Composition and index publication

The full window grid contains one tab row, a compact text viewport, and an
eight-column right strip. Text and minimap have independent compact strides and
open-time maximum capacities, so layout never cuts a wide pair at the strip.
Each physical frame begins all grids, finishes text/decorations, calls
minimap_fill, copies composed cells, renders the strip and submits once. Only
changed copied rows acquire damage; tabs/minimap never submit their own frame.
At a one-row window the tab strip is hidden to retain a text row; below 24
columns the minimap display is hidden while its reserved summaries remain valid.
Resize reuses the reserved wrap descriptors and all grid/scratch capacities.

Every mutation increments the buffer revision. Readiness requires a complete,
nonbuilding index of matching length; pending revisions use retained density
with stale tint and a `!` in the top row. Visible logical lines, rather than
wrapped row count, drive the viewport band. Pixel click/drag uses minimap_hit,
clamps beyond the strip, and scrolls the viewport without relocating selection.

Index polling/query/maintenance is outside minimap_fill. Editing cancels an
initial index build; edited chunks are refreshed one per turn. If unbuilt
untouched chunks remain, lineidx_seek_line advances the prefix by at most its
existing LINEIDX_CHUNK budget per turn. That work is runnable until completed,
checks input every turn, allocates nothing and causes a fresh minimap frame on
publication. This avoids a permanently stale minimap after interrupted startup.
An integration test constructs an unbuilt public index deterministically, then
checks recovery solely by driving the loop. No lineidx implementation was changed.

## CLI, IPC and journals

main parses every argument with ipc_parse_args and reads stdin before role
selection. --new-instance bypasses both server and client setup. An incumbent
receives one client_send handoff and the process exits after ACK/closed; no
window, journal or backend is created by that branch. Other role errors are
propagated. There is no automatic handoff retry after possible acceptance.
The primary owns server_init before opening its local request and frees args
after synchronous acceptance. Empty requests open untitled; stdin creates an
additional exact binary payload buffer, including an empty payload.

An editor-owned epoll descriptor combines worker eventfd and ipc_server_fd.
It is polled directly by the null loop and passed to the existing platform work
slot for raster; epoll_wait consumes readiness and ipc_server_drain runs on the
UI thread. No X11 header or implementation amendment was necessary. Open
callbacks prepare every resource/path/position before publishing tabs. Capacity,
name and ID bounds make publication allocation-free; preparation failure frees
all prepared resources and leaves existing tabs/activation unchanged. Asynchronous
file-open errors are scoped to the pending file instead of poisoning the existing
window. Requests are borrowed only during the callback; paths/payloads are copied.
Line/column coordinates are one-based display columns, clamp at line/end bounds,
and land on certified grapheme boundaries through utf8_cluster_step. Column
positioning also sets horizontal or visual scroll so the target is visible. A
position requiring more than VIEW_SCAN_BOUND inspection returns CAPACITY /
IPC_LIMIT before any tab is published; it is never silently truncated or put
inside a cropped UTF-8 unit/cluster. Wait membership includes every new request tab and stdin;
only closing the last member reports_closed. Reopening does not reacquire a
completed token. Shutdown finalizes the server after editor_close; unclosed wait
clients receive disconnection, not a false closed response.

Journal staging includes the stable buffer ID so coalesced keys across switches
cannot replay into another buffer. Bases/initial untitled bytes are registered
before publication. Journal errors stop further opens/the loop; accepted append
prefixes are preserved, following existing nontransactional journal policy.
Main retains its XDG session journal and quiescent trace-dump behavior. Saves,
recovery UI and a journal transaction protocol remain separate work.

## Rebase finisher, 2026-10-09

### Failure and fix

Main moved file lookup into the asynchronous prefix worker. The inherited loop
tested the return from `file_open_begin` and UI-thread `errno` for ENOENT before
the lookup happened. The worker's missing-path completion was consequently
treated as an open error. The reported raster failure also reproduced with
the null backend here; it is a file completion mismatch, not a raster defect.

`editor_buffer_prepare` now waits for mailbox decoding, checks the installed
`file_errno` on the failing file, closes that file handle and initializes the
new named buffer from its supplied bytes only for FILE_ERR_IO/ENOENT. Other
failures still free the prepared resources without publishing a tab. The error
remains local to the pending open, so subsequent requests can succeed.

The tab regression uses a unique temporary directory and deliberately sets
UI-thread errno to EACCES before missing `.c` and `.md` opens. It checks their
initial contents and wrap defaults. The request regression sets errno to
ENOENT before a nonregular-file failure, checks rollback, then successfully
opens a missing path with errno set to EACCES through `editor_open_request`.
Both paths are exercised with null and raster backends.

Rebase checks: `open.c` allocates the over-aligned editor with
`aligned_alloc(_Alignof(editor), sizeof *e)`, zeroes it, then sets `poll_fd=-1`
and `drag_tab=SIZE_MAX`. Both the main alignment fix and WIP initialization
survived. `src/layout/STATUS.md` retains main's CRLF/large-column and P4.1
verification plus the additive P4.I paint notes; it makes no claim that this
integration implemented those main fixes.
