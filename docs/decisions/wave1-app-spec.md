`app_result` has a disposition and an optional diagnosis. OK completes the synchronous action or admits its stated asynchronous continuation. WAIT transfers nothing and identifies a dependency whose progress permits retry. REFUSED completes the command with its error. The diagnosis retains the originating app or lower service, its exact result code and any native error. Refused admissions preserve output parameters and input ownership except where entry explicitly transfers custody. An `app_buffer` is an indexed owner entry with a stable address through its borrowers' retirement. An `app_draft` owns the immutable import material described under app_buffers. The `app_disposition` choices are KEEP and DISCARD. An `app_destination` is a scoped claim containing the retained target and its displaced key. The caller returns the target reference when savectl has accepted or refused the request. The index owns the reservation through that decision and, if admitted, through settlement. Polling a previously admitted operation uses its existing correlation, never a new intake.

## app_loop.h

An `app` is the sole UI owner of the command stream, FIFO, wait set, shared work pool, process piece reserve, session and buffer index. A FIFO item owns its command ID, decoded arguments, receipt timestamp, resolved owner when known, and reserved reply storage. An open in progress has a stable request identity until it resolves to an owner or fails. A turn's *runnable* work can make progress now. A waiting operation becomes runnable on a specified dependency, fd event or absolute monotonic deadline. A pending worker alone supplies no deadline. `app_step_result` is MORE while the owner lives and DONE after orderly shutdown and reply delivery or stream disconnection. An error that prevents continued service carries its originating service code and OS diagnosis.

| Declaration | Caller and contract |
|---|---|
| `app_result app_create(app **out, int command_fd, const char *journal_path)` | Headless main supplies its inherited connection and its namespaced session path. Adopt the descriptor, initialize shared resources and start recovery. Transfer the descriptor on entry, unwind setup on failure and return no partial app. |
| `app_step_result app_step(app *a)` | Main calls after readiness or when work is runnable. Execute one ordered turn, including consuming wait-set readiness, without waiting for an operation to finish. |
| `bool app_work_pending(const app *a)` | Main asks whether to enter another turn immediately. |
| `uint64_t app_next_deadline_ns(const app *a)` | Main takes the earliest enabled absolute deadline from the same cluster readiness calculation, or OS_DEADLINE_NEVER. |
| `void app_destroy(app *a)` | Main consumes the stopped owner after DONE, or after a terminal startup failure with its resources retired. |

Main's wait uses the app's owned wait set (private composition shared with main). It captures events for the next step. Use `os_stream_adopt/read/write`, `os_waitset_add/modify/remove/wait`, `work_pool_wake` and `os_wake_fd`. Register the stream for input only with admission space, for output only with unsent replies, and register file watch fds while owned. Check runnable work after registration to avoid lost wakeups. On an idle editor the sole blocking point is the outer wait set. On partial output resume at the exact byte cursor. A blocked FIFO head, pending sync, closing controller or occupied worker cannot keep the loop awake by itself. Work completion, returned capacity, receipt of input and an explicit retry each invalidate the corresponding wait. Physical completion must wake retirement even when logical cancellation suppressed delivery. [OS wait and stream](../../src/os/os.h) · [work](../../src/work/work.h)

**Turn order.**

1. Assert outside the step, enter it, collect ready input and give the oldest admitted input its opportunity. Stay in global FIFO dispatch order. Resolve the active target in that order. OPEN starts acquisition and selects an opening entry. A dependent key waits there through open and cannot be overtaken by SWITCH or SAVE. If OPEN fails, report failure to those dependent commands without applying their bytes to the fallback tab. A SWITCH at the head to a ready tab may proceed while another file opens. A yielded command retains its own continuation. Service its dependency even with a full FIFO.
2. Route a bounded ordinary `work_mailbox_drain` through one dispatcher. Offer journal-owned envelopes to `journal_receive`, controller-owned envelopes to the matching `savectl_receive`, file acquisition envelopes to `file_msg_decode` exactly once, and count results to the issuing owner. Registered per-handle receivers may perform the same delivery. Route by immutable recipient/lease identity, including retired recipients, before dereferencing any object. A stale delivery consumes its retirement credit and cannot install into a reused slot. A callback only delivers a result. It cannot pump the pool or re-enter a step. A ready watch/focus hint schedules `savectl_file_event` off the key path.
3. Give **at least one ready record of each producer class** a service opportunity on each turn (G, A28 rule 6). Rotate the starting class and the ready instances within a class. These include continued edit command records, checkpoint literals and boundaries, and independent save/session controls. Drive `edit_continue`, `savectl_tick`, index and session continuations as applicable and `journal_service` every turn with a live writer. The journal schedules its own ready producers. Once each ready class has had service, issue ready barriers, including checkpoint, save and name durability. A blocked class forfeits its opportunity for that turn. Budget the head and mailbox so an unbounded input burst or full mailbox cannot starve any of these steps. Calls submitting directly to the writer obey the same order, including barrier submissions made inside tick/service. This is a fairness requirement under progressing storage and workers, with no millisecond bound.
4. Publish eligible replies. For each newly published text revision, obtain `edit_read` and deliver `savectl_content_identity` exactly once even when Undo restores an equal ID. Reserve reply/leaf capacity before mutation. Take `edit_take_change` after submit (in headless mode, after reply delivery). Continue draining ready work even when output is backpressured. At idle boundaries after submit/open/activation perform count adoption and `edit_maintain`. Retire physical holds, clear the step guard on every return and recalculate readiness. An input-to-submit guard includes queue residence for the latency observation and covers production mutation through ACK for Law 2.

The execution guard has **two values**, outside and inside (P, one entry and exit), and no nested service mode. Main obtains stopping state from session. `edit_read` supplies edit's phases. WAIT before admission preserves the head, MORE resumes admitted work, FINAL_PENDING retains the original request and previous public snapshot, and READY permits the change/ACK once. On SUSPENDED report the causal failure without completing the key as applied. The session drives `journal_state/reconcile` on progress events. No second mutation or RAM rollback follows a possibly written final. [Signed edit](wave1-edit-spec.md) · [Q15/Q16](wave1-L2-derivations.md)

## app_buffers.h

An *owner* is a nonzero journal buffer ID, stable across keeping and reopening and never recycled in its lineage. A slot is reusable storage and supplies no identity. A *binding* is a canonical destination with a tagged expectation of absence or presence with full stat. Identity lookup on present files uses volume and **both** inode words. Keep absence, an untitled target, a detached former target, and a failed observation distinct. A *generation* is a journal-lineage key for a particular source. A dependency means replay of a draft's selected origin or suffix could require that source. The set can contain several owners of independent text associated with the same former target. The index owns membership, intended binding and operation reservations. The writer owns range eligibility and durability. The file owns actual stat observations. An immutable leaf contains owner, copied path, position in session order, membership, origin/dependencies and view data, and retained published snapshot or preserved unresolved evidence. A saved snapshot is retained only for an actual saved-reference consumer. A leaf describes one decision boundary. Neither workers nor detached leaves hold a live app-buffer pointer.

|---|---|
| `app_result app_buffers_open(app *a, const char *path)` | OPEN starts a checked acquisition. NEW passes NULL for an empty untitled BASE. The active FIFO request receives the selected owner or asynchronous opening result. |
| `app_result app_buffers_import(app *a, app_draft *draft)` | Recovery or a draft import offers owned text/evidence and copied provenance, target and membership. Success consumes the draft. Refusal leaves it with the caller. |

A destination claim is scoped to one intake attempt until capture, then to the admitted saver/token. Release an unadmitted claim in the same serialized decision. Reserve an absent canonical destination by name and a present one by name and identity. Revalidate after asynchronous observation and before publication. A collision with a live owner is deduplicated on open. On Save As it requires the peer-displacement protocol before ownership can transfer. Hard-link aliases unify live ownership, but displacing one name does not declare every alias renamed. Check the actual binding and the named generation. An unresolved alias or a generation that cannot yet be classified defers displacement. Independent destinations can proceed concurrently.

**Four entry states** (P, each owns different resources and admits different commands).

| State | Entry and exit |
|---|---|
| BUF_OPENING | A provisional open or reopening admission awaits acquisition, identity reconciliation or recoverable registration. On success enter LIVE or select the already indexed owner. On failure unwind its claims and settle the waiting request. |
| BUF_LIVE | The open entry owns an editor and controller. A recovered unresolved entry can be listed and kept as evidence but cannot enter an editable LIVE incarnation until materialized. A peer may be live and detached. Reload progress is read from savectl. |
| BUF_CLOSING | A logical close settles admitted commands, save effects, metadata and leases. The disposition identifies its destination. A failed settlement retains its resources and is visible/retryable. |
| BUF_KEPT | Closed membership retains its order, view, provenance, published bytes or evidence, validator custody and any required independent recovery representation. There need be no editor, history or controller. Reopen through OPENING or explicitly evict through CLOSING. Unresolved recovered drafts can be kept here. |

### Membership fence and checkpoints

The callback context is the stable controller-to-entry association. Keep it alive until controller destruction and the retirement of every borrower. Its buffer identifies the saver. Token and displaced key vary per save. `target` carries the particular binding decision for this checkpoint. No callback needs another saver or peer ID argument.

* **At capture.** Distinguish the saver's prior source H from the destination generation G. Before `savectl_save_request`, finish any provisional command that can still commit a reference to G; finish the saver's own command too. With the signed edit header the conservative proof is to let already admitted provisional commands with unknown provenance finish and to retry admission on their publication. No provisional abort hook is assumed. Serialize this check, destination recheck, capture and edit bookmark installation on the UI. From capture onward journal enforces permanent VALUE_ONLY for G across cancellation, reopen, undo and redo. A fence gates membership, never the typing of independent literals.
* **Acquire before enumeration.** For the pair (saver, token), reserve G before taking the first member. For absent G there is no generation to cover; the destination claim still applies. Check both old and proposed dependencies at every open, import, reopen, rebind/reload, close/keep, discard/eviction and Save As, including completion of an admission started earlier. Conservatively defer affected membership changes until release; permit the fence owner's own reconciled disposition. Prevent intersecting reservations before admitting a capture, so two savers cannot each hold what the other requires. On a competing reservation refuse/defer the new request before acquiring a partial set of claims. Target observations can invalidate proofs and must still be serviced.
* **Enumerate under the reservation.** Visit every *other* dependent, including closed-kept entries, detached recovered siblings and imports admitted before acquisition. Capture its last published snapshot and current/saved IDs with its required TARGET in one UI decision. For a kept peer use the immutable leaf and its backing validator even if its live editor has gone. An unavailable owner/evidence-only draft cannot certify coverage. Defer or return SOURCE with diagnosis, retain the old name, and keep other work runnable. A live fd alone cannot serve recovery after death.
* **Fund and cover.** Both the callback for the saver's own request and the peer path call `journal_checkpoint_request(j, owner, snapshot, goal, target, validate, ctx, out)`. The callback transfers the request to savectl. The index owns requests for peers. A zero minimum is allowed when any independent boundary suffices; otherwise use the required writer-issued owner/image position. At BEGIN, text and IDs must be from the same published boundary. Read `journal_request_result`. On VISIBLE COMMIT ask `journal_sync` through its position. Record coverage only on OK/DURABLE for that sync request in the same image epoch with credited file_end at least the COMMIT end. The embargo makes subsequent restores independent of G. A newer compatible checkpoint plus its independent suffix suffices. Changed binding or saved decision invalidates that proof; submit replacement, revoke stale delivery authority even if its funding fails, and recheck. SUPERSEDED requires current coverage. POSSIBLE uses the original request through reconciliation. Release each request reference once. Hold validator context through physical retirement, including abandoned producers.
* **Return and release.** Recheck the reserved peer set and coverage against current decisions before returning OK. Repeated calls for the same token reuse progress. Keep the reservation through PREPARED durability, actual rename and any uncertain rename. Apply installed-branch peer detachment/rebase and new live-owner registration as a single index publication. Prior branch retains prior owners. Newer independent decisions prevail. Release only the matching settled reservation. A durable terminal with failed binding verification consumes the token and leaves conflict protection owed. It never supplies authority to mark clean or overwrite the foreign file.

The fence has **three logical states per displaced generation** (P, no reservation, owned with coverage outstanding, owned with coverage satisfied). Store the reservation and its outstanding proof obligations. Derive readiness from them. A failed attempt leaves its exact obligations and diagnostic, with no fourth mode. Suffix edits do not restart a satisfactory checkpoint simply because the current revision advanced. Protect the incoming identity as well as the displaced one before allowing a concurrent OPEN to become LIVE. The prepared output has an fd-derived identity. An OPEN via an alias to that output during uncertain publication must await classification if the index cannot rule out collision. [A23 rules 3–6](wave0-plan-amendments.md) · [Signed callbacks and seam table](wave1-savectl-spec.md) · [Runtime checkpoint goals](wave1-journal-wire-amendment.md)

For example, saver A is bound to H. Its Save As would replace G. B is an open dependent and C is a closed-kept recovered draft of G. Capture A and embargo G. Checkpoint B and C; a key on B may finish between B's checkpoint members. An import depending on G arriving after enumeration waits at membership admission. If C's validation fails or only B's COMMIT has covering durability, A cannot rename. After both barriers, sync PREPARED and publish. A kill now uses each peer's own checkpoint and independently recoverable suffix. On the verified installed branch detach still-displaced bindings and give A the destination. Reassess the held import against the actual branch before admitting it; a surviving name alone cannot validate its former source.

## app_save.h

A save *admission* identifies an asynchronous attempt against the published snapshot and content ID. The client command ID identifies its reply stream. The controller's request ID identifies the admitted capture for this owner. An outcome reports the controller's observation of that attempt. Only SAVED proves verified durable finish. A *resolution* is an explicit request to perform the sole eligible retry or cancellation in the current controller phase. All inputs name either a user decision or an existing owner.

| Declaration | Caller and contract |
|---|---|
| `app_result app_save_request(app_buffer *b, const char *destination)` | SAVE passes NULL for the current binding. SAVE_AS passes its destination path. Obtain an index claim and the current published boundary, then request capture. Return admission or a classified refusal. |
| `savectl_err app_save_action(app_buffer *b, app_save_action_kind action)` | KEEP, RELOAD and RESOLVE select respectively `savectl_keep`, `savectl_reload` and `savectl_resolve`; report their result and continue servicing admitted work. |
| `void app_save_service(app *a)` | The dispatcher ticks eligible controllers fairly, adopts typed notifications and completes pending command replies. A closing controller remains eligible. |

There are **zero additional save phases** (P, the adapter owns only destination/reply/borrower obligations). `savectl_get_model` returns eleven phases crossed with two closing dispositions, **22** reachable states (P, A27). `savectl_target_identity` supplies the currently accepted expectation. The adapter may correlate a command, owner and token with a reply/held bookmark. Storing a mirrored dirty bit, saved ID, phase, external-change flag or journal health would create a second authority.

* Capture from `edit_read` at a complete boundary. Pass its borrowed snapshot and content ID, the validated file target and the displaced key to `savectl_save_request`. On admission send `edit_save_boundary(EDIT_SAVE_CAPTURED)` in that dispatch, before another input, then give the client the admitted token. Retain claim/correlation until definite settlement. A refusal changes no bookmark. File writes the immutable cutoff while later input may publish a different ID.
* Route results through `savectl_receive` and drive `savectl_tick`. The controller owns temp custody, PREPARED, rename, directory retry, verification, declaration, FINISHED/CANCELLED and their barriers. The adapter never submits a second file save, syncs a temp, or appends a terminal. SAVED adopts `EDIT_SAVE_INSTALLED` for that token, even when the current text is newer. Definitive failure/cancellation releases via `EDIT_SAVE_RELEASED`. A possibly written effect keeps its bookmark. Never infer release from SAVE_FAILED alone. A foreign binding after complete FINISHED yields IDLE_CHANGED, unknown saved ID, dirty text and SAVE_FAILED/CHANGED immediately; conflict protection can continue after that report. There is no second terminal.
* Apply any eligible peer binding change with `savectl_rebase_target` under index protection. A detached peer retains its own text/history and former target in its leaf. Drain any conflicting peer disposition first. A changed/missing binding forbids treating it as clean. After Keep, verify the checkpoint decision is current. After `savectl_take_reload` install the offered new tree and source, new edit history and identity domain, clamped current selection/view, watch and index claim together before dispatching input. Retire old count jobs and source holds physically. A revoked reload result never installs after typing, including Undo back to an equal ID.
* Shutdown calls `savectl_close_begin` and continues resolving already admitted obligations, including retries while closing. Call `savectl_destroy` only on the eligible action; BUSY preserves the object and its ctx. `edit_destroy` requires IDLE, settled cutoffs, and secured kept text or authorized discard.

## app_session.h

A session is the exclusive owner of one named journal and the publication of its membership, active order and view metadata. It uses the buffer index as the sole mutable membership authority. A recovery item is the writer's tagged delivery of an unlogged tree, a selected control or preserved evidence. A closed-kept draft is a recoverable member even when its tab and editor have been removed. A rotation is an ordinary compaction of the same logical session into a new named image. A shutdown is the user's decision to settle that session and retire its writer.

| Declaration | Caller and contract |
|---|---|
| `app_result app_session_start(app *a, const char *journal_path)` | App creation supplies the session path to `journal_recover`. On admission own the writer and recovery request. |
| `app_result app_session_rotate(app *a)` | COMPACT requests ordinary compaction. Retain the intent across admission WAIT and the original request across publication and name durability. |
| `void app_session_shutdown(app *a)` | QUIT or loss of the command connection closes fresh admission and requests orderly settlement idempotently. |
| `void app_session_service(app *a)` | The dispatcher advances recovery, metadata publication, small-buffer protection, compaction and close as their dependencies change. |

**Three owned lifetime states** (P, startup import, command service and shutdown settlement): RECOVERING, SERVING and DRAINING. A successful close consumes the writer and ends this lifetime. A shutdown during recovery enters DRAINING and still retires the recovery cursor. The rotation request and a metadata publication are ordinary owned operations, with progress supplied by their journal results. The UI retains originals through ambiguity. A suspended writer or damaged source is an observable result from journal, never another session mode.

**Pull startup.** Call `journal_recover(&j, path, pool, reserve, &r)`. Continue routing and servicing while `journal_request_result(r).status == JOURNAL_WAIT`. On OK, DAMAGED or SOURCE drain `journal_recovery_next(r, &item)` to false in bounded turns. BUFFER transfers its tree to staging, including NULL for unresolved text. CONTROL delivers selected BASE/TARGET/VIEW/TABS and open-token decisions in effective order after the referenced buffers. EVIDENCE supplies reason, name and immutable image bytes. Copy borrowed controls/names/bytes or secure independent evidence custody before release. Build a candidate index and adopt each draft via the same admission as a live import. Only a verified binding can install a saved ID. Preserve a foreign FINISHED origin as dirty/changed; reconcile any open token before accepting another displacement there. Duplicate target drafts keep distinct IDs, text and metadata; at most one owns the live identity. Where the effective decisions do not select an owner, use the first verified OPEN candidate in recorded order and detach the other drafts. Prioritize unsaved entries under capacity, preserving their relative order, kept positions and active selection when possible. Set aside the source intact on a partial restore, and report unrepresented entries. If staging or evidence preservation fails, keep the old root and recovery custody for retry. Other terminal request errors have empty cursors and must be reported. Release `r` once after exhaustion or deliberate abandonment (release disposes of unclaimed trees). Admit ordinary commands only after installing the recovery decision or explicitly reporting its failure. Never replay a byte on a mismatched BASE.

**Publish, keep and evict.** On the UI copy changed metadata into an immutable leaf, retain its published snapshot and keep the old leaf alive for each admitted reader through physical release. If allocation fails, keep the prior leaf and refuse any operation requiring the newer publication. Preclaim typing-path storage. Encode effective controls with the public `journal_*_encode` functions and submit via `journal_append`. Use the complete ordered TABS list with open/closed-kept membership and active index; copy opaque VIEW bytes with their owner/version. Headless selection comes from edit. An unknown VIEW version is preserved or defaulted according to its owner's contract. Capture durable session metadata at explicit membership boundaries rather than emitting a VIEW on each key. A close KEEP secures the text, binding, view and selected TABS before dropping the live validator/tree; a genuinely independent recoverable representation suffices. Otherwise request its by-value checkpoint, obtain covering sync, and keep enough immutable material and validating custody to supply future peer protection. A kept owner can be reopened from its leaf without rereading a replacement path as the draft's text. DISCARD/eviction settles pending effects and publishes omission from TABS before releasing the old member. No automatic capacity eviction discards unprotected dirty text. Keep committed old membership until the new decision is visible and obtain covering durability before irreversible release/confirmed durable close. Serialize conflicting TABS publications; a stale whole-list append could resurrect an evicted owner. A membership ACK covers its advertised publication. Typed replies tell the driver whether durability was required.

For eligible small buffers with an acknowledged edit, schedule the off-input-path by-value checkpoint with an independent suffix and covering sync. Use the runtime owner's self-contained size and the existing per-owner checkpoint slot. Do not delay the initial edit ACK on that sync. Protection against machine loss begins when covered. A23's T5 interval remains visible to recovery for an unprotected draft. Conflict protection is triggered for larger buffers too. [Rotation and size brief](../briefs/L2-2b3-journal-rotation.md)

**Rotate and shut down.** Call `journal_rotate` only on ordinary compaction demand. Retry admission WAIT on dependency changes. A live command, cutoff, token, checkpoint or old-inode durability promise can defer it. The journal compares candidate identity/epoch, watermark, membership and policy before switching; VISIBLE means switched, DURABLE after the journal-parent barrier permits the compaction success reply. Leave exceptional writeback recovery to `journal_reconcile`, retain evidence and suspend ACKs while continuity is lost. On QUIT, retain the open versus kept order for next startup, stop new admissions, finish/abort provisional work by its owner's rules, settle pending saves, secure required checkpoints and final metadata, and sync the selected state. Retiring live machinery on exit does **not** encode a user close of every tab. Cancel and retire count work, retire controllers, release requests, snapshots and cutoffs in dependency order. Call `journal_close(j)`; WAIT retains the writer, so continue its ordinary receive/service and retry after actual progress. Only success consumes it. Then retire the shared pool and destroy the reserve after all backing readers have gone. A failed sync or unresolvable source is reported with its evidence retained. Do not emit successful QUIT or spin on an unchanged error. Keep status and eligible resolution accessible during DRAINING; a closed transport cannot require a successful write to a dead peer.

## Headless command and reply contract

The proposed invocation is `sublimite-v2 --headless-fd FD`. Main selects the v2 journal in the namespaced DATA directory. A parent creates a connected stream pair, passes one end across exec, and uses disposable XDG data/config/runtime roots. No display, platform backend, synthetic keystroke driver or second edit engine is involved. Restart is a fresh invocation against the same root. [Q16](wave1-L2-derivations.md#q16--settled--external-headless-command-completion)

For signature, use a length-delimited stream. A frame is a netstring containing consecutive netstrings, one per field (G, the outer length delimits a frame and the inner lengths preserve raw bytes). A netstring is an unsigned decimal byte count, a colon, exactly that many bytes and a comma. Use canonical unsigned decimal without leading zeroes except zero; identifiers and byte coordinates fit uint64. OS/service diagnostics retain their signed code. The first fields are command ID and verb, or the same ID and reply kind. IDs increase strictly within a connection; duplicates cannot repeat effects. All subsequent fields are in the order below. Paths are nonempty OS path bytes without NUL. Text and evidence are arbitrary bytes. Check overflow, frame arity, ranges and available space before mutation. Refuse excess payload/queue capacity visibly at a frame boundary; malformed framing terminates the connection with a protocol diagnosis. Reserve a bounded reply at admission or stop reading until space returns. A long byte read can be split by the client into requests. A slow reader owes no synchronous wait on the UI thread.

Commands on text and saves address the **active** owner at their FIFO position. LIST and STATUS identify owners across a restart. Owner IDs in SWITCH/REOPEN/EVICT may refer to inactive entries. NEW/OPEN may return an intermediate OPENING with the command ID; OPENED carries the final deduplicated owner. Unknown owner, failed open or closed admission has a distinct refusal. APPLY replies carry owner, published content ID and revision; no-op commands can reply at the prior boundary. Operations that depend on a possibly written record can report SUSPENDED plus origin, service code and native error as an interim diagnosis. Retain their original command correlation until definitive settlement. A pre-admission refusal is final. Emit a single success for each logical completion.

| Request fields after ID | Observable response |
|---|---|
| `NEW` or `OPEN path` | OPENED(owner), after recoverable registration or selection of an existing owner. |
| `SWITCH owner` or `REOPEN owner` | SELECTED(owner), after live selection or kept-draft reinstallation in its recorded position. |
| `SELECT cursor anchor` | APPLY after `edit_select`; endpoints are byte offsets within the published text. |
| `TYPE bytes` | APPLY after ordinary `edit_replace` at the current selection with receipt time from the monotonic clock. |
| `DELETE off length` | APPLY after a production forward deletion of that interval. Empty insertion carries no bytes. |
| `REPLACE off length bytes` | APPLY after a separate replacement through `edit_apply_plan`; collapse selection to the insertion end. Supports paste and tests a complete replacement group. |
| `UNDO` or `REDO` | APPLY after `edit_replay` and any `edit_continue` reach publication for the whole group. Requests can yield to the turn after an available unit using an absolute replay deadline at current time. |
| `SAVE` or `SAVE_AS path` | ADMITTED(owner, token) on capture, then SAVED(owner, token, saved_id) only on verified durable finish. Report CANCELLED or SAVE_FAILED with owner, token and exact failure. Correlate later resolution with the same attempt even after an interim failure. |
| `KEEP`, `RELOAD` or `RESOLVE` | ACCEPTED(owner) on asynchronous admission, then SETTLED(owner, outcome) on the actual Keep, reload installation, retry or cancellation decision, or the service diagnosis. KEEP accepts observed disk binding with local text; CLOSE_KEEP below changes membership. |
| `CLOSE_KEEP`, `CLOSE_DISCARD` or `EVICT owner` | CLOSED(owner, KEPT or REMOVED) on secured membership disposition. EVICT applies to a kept entry. |
| `LIST` | ENTRY(owner, OPEN or CLOSED_KEPT, binding kind, path) for each effective member in order, then END(active owner or zero). Copy the observed membership once for this reply. |
| `STATUS owner` | STATE(entry state, edit phase, savectl phase, closing, current_id, saved_id, dirty, request_id, outcome, journal condition, origin, service error, native error). An unavailable lower object yields an empty field; preserve any recovery diagnostic in the response. |
| `READ owner off length` | BYTES(content_id, raw bytes) from that published snapshot, including a kept draft. Check bounds and backing identity before delivering. An unresolved source returns SOURCE with its evidence name; never substitute empty text. |
| `LINE_BEFORE owner off` or `LINE_START owner line` | RANK(exact, newline count) or START(exact, offset, preceding count) from `piece_lines_before/start` on the published view. The driver can observe adoption without forcing an edit or scanning text on the UI. |
| `COMPACT` | COMPACTED after verified new-image durability, or a classified refusal/error. |
| `QUIT` | CLOSED_SESSION after successful settlement and journal close. Then drain this reply to the parent and exit. |

An empty field denotes unavailable data, bools are decimal zero/one (G, false/true), enum values are their declared names and REFUSED carries the origin, service error and native error. Response arguments each occupy their own field. Recovery failures/evidence are available on startup as session diagnostics before command replies (reserved command ID zero, G, outside the positive client ID space). Emit reason and preserved name; the test may inspect preserved artifacts in its profile. Evidence-only entries remain identifiable. Command-stream framing, verbs and reply names are proposed L5 choices. EDIP open intake and its existing protocol keep their own completion semantics.

## Why each coordination mechanism exists

| Mechanism and invariant | Simpler alternative and defeating trace |
|---|---|
| One ordered dispatcher with a shared readiness/deadline calculation keeps input ordered and waits on the actual blocker. | Drain an open synchronously or park its keys. The first blocks a ready small-tab save; the second allows Save to overtake typing on the opening tab. Separate “busy” and “runnable” masks make close spin on a running worker. |
| Producer rotation with closed-operation credits and barrier service gives finite admitted work opportunities under sustained input. | Always take the next key first and return. The peer's final and sync never run; an accepted save can never rename. |
| The command ACK and saved bookmark refer to distinct verified boundaries. | ACK the FIFO enqueue or mark current text clean on save completion. Kill just after enqueue loses a key; type during temp write and the new key is marked saved although absent from disk. |
| Index by identity, with separate owner IDs and dependencies, permits hard-link dedup and distinct recoverable drafts. | Compare path strings or merge all same-target records. Opening a hard link creates two writers; merging two restored drafts destroys one independent suffix. |
| A claim protects intersecting operations before capture; the token's fence freezes affected membership through actual publication. | Scan open tabs once before PREPARED. Import a G-dependent kept draft after the scan, or reopen one between check and rename. On restart its original source is gone. Two overlapping displacements can otherwise each wait on a peer owned by the other. |
| Compatible BEGIN-bound checkpoint plus covering same-image sync proves a peer independent at displacement. | Trust worker completion or the most recent sync anywhere. A stale delivery after replacement, short watermark or switched inode can authorize rename while the required COMMIT exists only in RAM. |
| Immutable leaves and physical retirement keep stable bytes, metadata and validator contexts through cancellation. | Hand a worker a tab pointer or free the validator on logical close. Reuse the slot during an outstanding mapped read; the late result reads freed storage or mutates a new tab. |
| Count the held backing off-path and adopt only into the still-matching tree; edit owns later maintenance. | Rescan the mapped file per query or apply stale counts by tab index. A large delete makes key cost scale with the file or a reload's line answers describe its predecessor. |
| A staged pull recovery installs one complete membership decision and retains evidence. | Immediately attach each tree on receipt. An early BUFFER has no selected TABS yet; another draft for its target arrives later or its binding proves foreign. |
| Closed-kept membership and confirmed discard have distinct durable effects. | Drop the index entry when its tab disappears. A closed dirty draft is missed by displacement and cannot reopen after restart. |
| Compaction checks the source before switching; shutdown preserves the writer through its last obligation. | Switch on stale worker success or free the writer on QUIT. A newly ACKed suffix can vanish or a late sync can refer to freed custody. |
| An inherited framed stream supplies an independent observation of the real command and its completion. | Call editor internals in-process or count OPEN intake as edit success. Neither establishes which bytes the relaunched executable must recover after the parent sees a particular ACK. |
