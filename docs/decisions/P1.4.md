## Pareto front
`tools/pareto.py` over every gated-or-tracked cell's p99 plus `.text`: **all four non-dominated in all three runs** (cells won, run 1: flat 40, bptree 28, hybrid 21, rope 8). Restricted to the gates:
- **flat** misses a real gate by design: per-op p99 ≈ 82 µs at ~1.5 × 10^5 pieces (tail memmove; crosses 50 µs at ≈ 9 × 10^4 pieces), and snapshot_take is O(pieces). It wins size, open/mem, typing.
- **bptree, rope, hybrid** pass every gate except `line_jump_1e7`, which is a flawed row (caveat 1). Among them bptree beats rope on nearly every latency cell (rope wins snapshot memory and .text); hybrid wins undo and delete-heavy cells but has open spec deviations (caveat 3).

## Caveats (read before choosing)
1. **The `line_jump_1e7` row is mis-specified** (bead edit-4w1.20). `log_1g.txt` has ≈ 8.95 M lines, so line 10^7 is past EOF and the cell measures a full 1 GiB newline count on a fresh mapping (perf G7 index territory, 80/125 ms), not G7j. The coordinator mapped G7j onto it in the P1.4a brief; that was wrong. Three variants spawn 8–12 pthreads inside `piece_line_to_byte` to approach it, which conflicts with CLAUDE.md (shared state crosses only through `src/work`) and with perf's "cancellable worker scan" (indexing belongs to P1.6 lineidx). Decision needed: retarget the row and forbid in-kernel threads.
2. Law 9: the bptree and hybrid workers did not show a skeleton red run (bptree passed first compile; hybrid's first real runs failed instead). Recorded, not re-run.
3. **hybrid spec deviations** (from its NOTES): `piece_map_hooks.acquire` is called once per tree, not once per snapshot (the header requires one per owner); OOM in the middle of a multi-chunk delete or large `insert_ref` can leave partial content (header: "on failure the tree content is unchanged"); chunk lookup is a linear table scan (fine at ~4k chunks, poor beyond ~10^5). These must be fixed before hybrid could ship.
4. rope deviates from "leaves are pieces" (one piece per AVL node, 64 B) to stay under 96 B/piece; iteration re-descends from the root per span (slowest read_viewport).
5. Variants live in `variants/P1.4/<name>/` (git-ignored by policy), each with `NOTES.md`.
