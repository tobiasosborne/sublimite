# Wave 1 decision proposal · A witness for mapped source bytes

**For advisor signature.** Proposed P1 blocking the Wave 1 exit. MF-A can be resolved for an acquisition that obtained its witness before displacement. MF-C can be closed for the reported rename-window rewrite by removing the own-rename stat exemption and requiring the old backing to pass the same content check before reuse. Both conclusions use the save protocol's CRC32C standard of evidence. A CRC match is a fingerprint match. Distinct byte strings can have the same CRC32C.

## What the witness identifies

Give each mapped `file_source` a volatile `file_witness` of the **original file**. Use the acquisition fd's volume, both inode words, size, and CRC32C of every byte in offset order. Start at CRC zero and use round 2's `crc_table` and `crc_update`, which also compute the save witness. Read the held fd with positional reads. An unlinked inode is a valid input. Keep the acquisition stat immutable, with a separately published accepted ctime as in `source_baseline`. Link count is observational. A successful recheck advances only the accepted source ctime. It never changes the original fingerprint.

Three values can legitimately describe three different byte strings: the original backing, the prepared temp containing edited snapshot S, and the current destination. File owns the first two in distinct objects. Savectl owns acceptance of the named binding. Using the temp CRC for the source fails on the first edit. Hashing the replacement path authenticates the wrong inode. A GENERATION prefix CRC misses a rewrite beyond the prefix. A private copy needs no source scan. Recovery cannot recover a lost inode from its checksum. ## Source state and ownership

Each row is a value of one exhaustive enum in file. The source, including its retired incarnation held only by a snapshot or a borrower, owns its state. The UI owns the file's work slot and the operation waiting for evidence. The worker owns a slice while running it. No `ready`, `needs_hash` or `own_rename` booleans coordinate these lifecycles.

| State | Evidence and allowed transitions |
|---|---|
| COPY | Private ORIGINAL. Keep the existing copy-mode contracts. No witness job. |
| PENDING | Newly registered map. The acquisition stat is the only authority. Ordinary use can pass the existing live fd/fault check. Opening, painting and typing do not await the initial CRC. The first worker slice must match the acquisition stat in full and find a pristine fault registration, then enters CAPTURING. |
| CAPTURING | Partial CRC, next offset and starting fd observation belong to this source. A stable complete scan anchored to acquisition installs the original witness and enters VALID. Drift before installation enters CONFLICT. A transient read/stat error discards partial progress, retains PENDING and reports the native error for explicit retry. |
| VALID | Original fingerprint established. A matching accepted fd stat and pristine poll take the fast path. An eligible ctime drift requires REVERIFYING on demand. A conclusive disqualifying change enters CONFLICT. |
| DISPLACING | A worker about to attempt our rename that may displace this source invalidates existing read tickets and scan candidates before entering the syscall. The old backing cannot authorize a dependent commit in this interval. |
| NEEDS_RECHECK | Our rename succeeded or may have succeeded. The original witness survives. The first dependent use must request a scan even if timestamp granularity hides the move. No read of the old file is required just to finish installing the new file. |
| REVERIFYING | One cursor compares the held fd against the stored original witness. A stable eligible match advances the accepted ctime and returns to VALID. A stable mismatch or fault enters CONFLICT. A newer eligible observation discards the partial result and starts again at zero. A transient I/O failure retains the witness and returns to NEEDS_RECHECK with the diagnosis. |
| CONFLICT | This acquisition cannot establish its original bytes. Preserve the old baseline, tree, history and usable evidence. Refuse dependent operations. Reload creates a new registered acquisition and fresh history. |

Drive transitions with exhaustive switches under `-Wswitch-enum`. File's scan and publish code serialize changes per source. A worker-only mutex can protect the cursor, the transition and one slice at a time. Release it between invocations and across the rename syscall after publishing DISPLACING. Competing worker requests join at the source and can advance its cursor. A scan never waits on its own pool queue. UI validators inspect atomics, take the existing fd observation and fault poll, and perform no lock wait, scan, allocation or submission. Publish a versioned state/accepted-ctime observation with release/acquire ordering. Reject an in-progress or changed version in a bounded read. Version accepted-content changes, invalidations and rename attempts. Retire on counter exhaustion before reuse. Worker-private cursor progress alone does not invalidate a reader of a still-pristine acquisition.

The original CRC belongs to the backing because a reload can install B in the same `file` while a worker or undo still holds A. A per-file CRC would validate A using B's evidence. A per-request cursor would read the same large inode once for every coincident Keep, Save As and checkpoint. The source holds one offset, CRC accumulator/table, start stat and attempt identity. Slices use bounded scratch. Each worker borrowing the source retains it through physical completion.

### Evidence required to advance ctime

1. Observe the **held fd** and poll the registered fault id. Apply Q14's `file_expectation_diff`. For re-verification, require PRESENT, same volume and both inode words, regular kind, size, mtime, permissions, uid and gid as the accepted source. Inspect the members of the grouped `FILE_CHG_METADATA` flag to isolate ctime. Permit any nlink. NEEDS_RECHECK permits an otherwise identical observation. Any shorter size is truncation. Report observation failure as I/O with its actual cause.
2. Read exactly the acquisition length with bounded `os_file_pread` calls. Positive short reads advance by their actual length. Premature EOF disqualifies the pass. At completion repeat the fd observation and fault poll after the last read. Require stable compared fields including ctime across the pass, and the same source, attempt and unrevoked version at installation. For initial capture both observations must match acquisition. For recheck both must match the same eligible candidate. Only then compare the CRC. A stable mismatch refuses the source. A move during a scan cannot install either a success or a mismatch against a newer candidate.
3. Every operation consuming mapped bytes binds its first and last dependent load to **one accepted source version**. Before the first load, check the fd and fault epoch and take a read ticket. After the last load, check the ticket, fd and closing fault poll before exposing bytes, COMMIT, or a synced prepared temp. Preserve the ticket over yields. A rebaseline revokes earlier tickets. Discard an unpublished temp or abandon a provisional group and restage it if its ticket expires. Run the inexpensive closing check at adoption when an earlier worker result is still conditional. The boolean backing validator remains a point check. A fresh successful point check alone cannot certify bytes copied before re-verification. A writer can temporarily alter bytes, a copier can ingest them, and a later scan can find the original contents restored.

Fast validators can signal work owed with a return code or false. Only a worker records a conclusive scan transition. A caller that sees disqualifying drift or a fault refuses immediately. Carry a detected disqualification to the source owner for retirement, without allowing an older completion to reverse it. Native errors leave the obligation available for a later observation. Drift seen during initial capture cannot be repaired by hashing the new contents as an original. These rules rely on the same observable fd changes and fault service as round 2. A writer invisible to both observations, a CRC collision, or writes after the closing check are outside the evidence a stable pass supplies. ## Cost and service order

Let N be the mapped file size, P = min(N, FILE_PREFIX_MAX) and Q = 65,536 B. Reuse the round-2 verifier's 64 KiB pread quantum (E, its existing scratch versus syscall tradeoff). Start **after** first submission of the prefix-backed viewport and full map registration. A headless or nonvisible open uses the published ready boundary in place of a frame. The existing acquisition reads P bytes and maps the fd. The new worker independently reads [0,N), including the prefix. This makes the acquisition anchor and both ends of the witness pass easy to audit.

| Logical work (P, per stable completed pass) | 256 MiB map | 10 GiB map |
|---|---:|---:|
| Existing prefix read, P = min(N, 2²⁰) | 1,048,576 B | 1,048,576 B |
| Added background open read, N | 268,435,456 B | 10,737,418,240 B |
| Total open reads attributable to acquisition and witness, P + N | 269,484,032 B (257 MiB) | 10,738,466,816 B (10 GiB + 1 MiB) |
| Re-read for one stable unexplained ctime move, N | 268,435,456 B | 10,737,418,240 B |
| Full-sized read quanta per scan, ceil(N/Q) | 4,096 | 163,840 |

The columns use 256 × 2²⁰ and 10 × 2³⁰ bytes respectively (P, binary file sizes). Added witness reads on the input path and before first viewport submission are **zero** (G, submission precedes witness admission and all slices use WORK_BULK). Repeated observations of an accepted ctime cost only the ordinary stat/poll. Multiple moves seen before a pass can coalesce. A move at the last byte of an unstable pass can waste N bytes before a new N-byte pass. With continuing changes there is no finite total retry bound. A stable mismatch can cost the full N. Size/fault disqualification or absence of an anchored witness requires zero rehash bytes. The later by-value copy, save-output verification, viewport loads and independent line count have their own costs.

Each invocation issues at most one Q-byte pread and CRC update, checks cancellation and returns via `work_continue` at the tail of the bulk FIFO when more bytes remain. Use the pool's existing CPU cancellation budget within CRC processing if required. The first paint has no scan dependency. The host admits acquisition and viewport work first and schedules witness work after submit; a pending protection/restore has priority over launching a new speculative open scan. No bulk job occupies a foreground or raster lane. Give input first service between mailbox drains. Publish one terminal notification per attempt rather than waking the UI for every chunk. On mailbox pressure retain and redeliver the immutable completion; on submit refusal retain the obligation and retry on capacity. A paused source never ties up the sole bulk worker waiting for another job.

These are logical byte counts. Cache residency can reduce physical device reads, and readahead can increase them. Cold scans contend with subsequent opens, line counts and journal I/O for the bulk worker, page cache, storage and memory bandwidth. Even one in-flight pread can stall. Slicing bounds issued work between scheduling points; it supplies no wall-clock latency guarantee. The implementation bead should measure cold/warm first submit and ingress-to-submit p50/p99 with a scan in flight, under ordinary typing and heavy writeback, stamped [bat]/[AC] plus load. Count actual scanned bytes, callbacks, and UI allocations separately. Preserve A13's eligible delete/undo ORIGINAL-read bound of 2 × 65,536 B = 131,072 B (P, the two boundary chunks), and its inverse-copy bound min(length, 16 × spans) B (G, literal versus span descriptor). The extra scan contributes zero to those foreground counters. A whole-file loop on the sole bulk worker, even with cancellation checks, can queue another file's prefix behind a cold 10 GiB read. ## Interleavings and expected outcomes

| Input | Required result and discriminating observation |
|---|---|
| Foreign rename before the first slice, halfway through capture, or after its last byte before installation | The opening fd stat is the anchor. Missing witness plus ctime drift yields CONFLICT; invalidate any queued capture and refuse Keep, mapped save/restore and dependent checkpoint. A path-only change leaving the held source valid still takes the ordinary fast path. Never seed from a post-drift fd. |
| Foreign rename after VALID, edited snapshot still contains mapped spans | Keep the new path observation as a conflict. Scan the old fd even if nlink is zero. On stable equal CRC, advance source ctime. Keep can secure the draft against an explicitly accepted target, Save As to an absent name and a lent-source save can stream the edited snapshot, and the conflict producer can emit the original spans by value. Check the actual saved/checkpointed bytes against the edited snapshot and preserve the foreign destination. |
| A second move during re-verification | If it moves the held inode's ctime, drop the scan and start from zero against the newest eligible candidate. A second replacement of the already displaced pathname may leave that fd unchanged. Its source result can stand; the earlier path decision is stale. Re-observe and supersede any Keep/target-specific checkpoint before adoption. |
| Same-size rewrite through another link or fd; restore mtime and leave mode unchanged | A pristine fault poll and eligible ctime send VALID to the worker. A differing stable CRC enters CONFLICT. No successful dependent save, undo ACK or checkpoint COMMIT. With identical resulting bytes and a stable matching fingerprint, a rebaseline is allowed. |
| Truncate during capture, verification or copying, then regrow | Short fd, premature EOF, failed poll or any nonzero fault epoch dominates CRC equality. A repaired mapping can read as zeros. Never bless those zeros. Abort the dependent consumption, preserve usable literals/evidence, and require a fresh registered reload. The existing A22 refusal on fault-slot exhaustion still applies. |
| Our save intervenes | At prepare, if the mapped source may be displaced by this save, finish the acquisition witness while still anchored, before returning a synced temp for PREPARED. Other saves can use the fast path on a pristine pending source. A prepare discovering foreign drift follows the ordinary source rule. Before a potentially displacing rename retire older attempts/tickets and enter DISPLACING. Serialize competing publishers of that source. On definite non-install restore the prior eligibility only after a fresh matching fd/poll; otherwise classify the new observation. Success or uncertainty enters NEEDS_RECHECK. An unrelated Save As retains the existing source and uses its independent destination expectation. |
| MF-C at the RENAMED hook | Map A via a name with a second hard link. Save edited S over the first name. Between rename and the old after-fstat, rewrite the second link at equal length and restore mtime. Allow the installed output and parent barrier to settle under their own checks. First use of old ORIGINAL, including undo by value, requests the old CRC. On stable mismatch both ctx forms of the validator refuse; no foreign literal reaches a committed undo. With an intact second link's contents, the same restore succeeds after one scan. If the old backing is never used, post-rename source scan cost is zero. |

For MF-C, putting a check only in the journal's restore encoder is too late and too narrow. Undo, checkpoint, Keep, copy-out and further saves can all authorize that backing. Gate the first dependent operation, then use cheap read tickets until the next drift. The first lazy restore may wait for bulk work and must resume or restage against its original command boundary. Ordinary unrelated input does no hash work. Screen redraw from a live external mapping has the existing display semantics. The signature concerns committed by-value text and source validation. At file detection keep distinct the accepted path, an old source merely awaiting its own-rename check, and a proven stale source. A verified self-save followed by an idle watch poll must not generate a foreign **destination** conflict solely because its old fd awaits lazy verification.

### Why nlink and mode cannot classify the move

Start with names A and B for the same regular inode, link count two. Rename another inode over A. In one run stop there. In the other, a writer uses B to overwrite original bytes at the same length, restores mtime and leaves mode, owner and group alone before the observer takes its stat. Both observations say same held identity, same size/mtime/mode, nlink two to one, ctime advanced. No observed timestamp specifies which operations happened between stats. With one initial link, an already open writable fd gives the same counterexample at nlink zero. An inode notification also misses shared-mapping stores. The original witness distinguishes the differing-content fixture under the CRC evidence model. [Review probes](../reviews/wave1-L2-1-opus-recheck.md#new-findings-must-fix)

**Contracts attached to those declarations**

- `state_of` is a pure atomic query. VALID describes the last accepted observation. A fresh fd/poll is required at use. `of_backing` borrows the actual file-created mapped source from a pinned tree/snapshot, applying the same callback, ctx, extent and fault-id checks as round 2's null-ctx validator. Return NULL for a private or unrecognized backing. Only private text can omit source validation. This lets restart and detached consumers request a scan after the acquisition owner has gone away.
- `read_begin` and `read_end` are cheap point checks around a consumer's reads. Keep the source pinned across both. Begin writes a ticket only on FILE_OK. End also checks the captured version. Version binds the accepted fd baseline: unchanged accepted fields plus that version identify the opening observation; any rebaseline or entry to DISPLACING permanently invalidates old tickets. A ticket invalidated after copying demands discard/restage even if a new begin succeeds. Initial witness promotion on an unchanged fd need not advance the accepted-byte version. Return FILE_ERR_BUSY for a required scan with an anchored witness or a disposition in progress, FILE_ERR_CHANGED for stale ticket, pre-witness drift, hard mismatch or fault, and FILE_ERR_IO with `oserr` for failed observation. The bounded point check samples a consistent version around its stat/poll and fails closed on a racing transition.
- `step` is worker-only. It starts or continues the source-owned pass described above. FILE_MORE returns to the scheduler; FILE_OK means the pass is sufficient for the current observation (also the COPY no-op). A competing publisher in DISPLACING gives FILE_ERR_BUSY, with retry on disposition. FILE_ERR_CHANGED and FILE_ERR_IO have the meanings above. All status-only consumers recheck before reading. A synchronous off-input caller may drive steps directly; code on the shared bulk lane returns to the FIFO between steps. Cancellation releases the job pin at physical retirement. A partial cursor may be resumed only with the same source and a fresh matching start observation; otherwise discard it under the state rules.
- `witness_begin` is the UI scheduling adapter. It retains the specified backing and submits the `step` continuation. The host calls it once after first submit for an installed map (including adopted reload/recovery). A subsequent dependent operation may request or join it. Same source already in flight joins its existing notification; another source in this slot returns BUSY and is retried after retirement. A refused submission releases its pin and leaves a schedulable obligation. `file_msg_decode` checks slot/epoch/generation, maps status and native error to `file_msg`, and wakes dependents to re-observe. Use the initiating generation for a joined job. Full mailbox re-delivers the sealed result only. Close cancels and waits for this handle too. Decode, cancellation and close release the pin exactly once after physical use. The result belongs to the specified source. Reload/supersession cannot adopt it into a new incarnation. A borrower without `struct file` can instead drive `step` on its own pinned source and work slot. No pool call comes from the point validator.

## Savectl, journal and edit handoff

- **Enter IDLE_CHANGED immediately** on confirmed foreign binding, including a rejected complete FINISHED. Preserve the prompt, published text/history and intended TARGET. Forget a lost saved ID. Report SAVE_FAILED/CHANGED immediately for that complete FINISHED and release the edit bookmark as specified. Retain the journal cutoff, protection obligation and index fence until covered. FINISHED has consumed its token. A pending or slow witness cannot postpone this transition or authorize another terminal.
- **Request conflict protection in that turn.** The controller keeps the ordinary checkpoint intent on its operation slot. File owns evidence for the pinned source. If the source requires a recheck, drive it on bulk, yield the producer before reading/committing mapped literals and retry on notification. A successful check releases the source dependency only. At BEGIN use a current published boundary, capture snapshot/IDs and conflicted TARGET, establish the independent suffix and use null-ctx validation for its actual backing. Bracket all dependent reads with one ticket through the final source check. An invalidated producer can leave provisional members; withhold COMMIT and replace it under the existing journal supersession rules. A stable mismatch, fault or pre-witness drift reports SOURCE and preserves evidence; report a real I/O failure separately. Neither case silently accepts foreign text.
- **Distinguish protection from Keep.** A complete checkpoint COMMIT on the named journal inode protects process restart. Its covering DURABLE sync protects machine loss. Retire only matching holds. Reverification or a complete conflict checkpoint alone leaves IDLE_CHANGED. Explicit Keep re-observes the current destination, secures a by-value checkpoint with the accepted TARGET, and rechecks decision epoch, source and target at adoption. Only its matching durable result enters IDLE_CLEAN with saved ID unknown; later typing and history survive. On a newer observation supersede the target-specific request, including an already pending barrier. A compare-only Keep can otherwise accept replacement C with a checkpoint describing replacement B. T5's exposure until independent protection remains.
- **Save As admission needs a narrow signature decision.** File-level Save As and a standalone save with a lent source can use an independently validated fresh destination after source proof. Signed `savectl_save_request` currently requires IDLE_CLEAN even for Save As. Explicit Keep followed by Save As already fits that rule. To support **direct** Save As from IDLE_CHANGED, admit an explicitly distinct, canonical ABSENT target after the conflict checkpoint is durable, previous token/claim obligations have settled, and the same published source is usable. Use ordinary snapshot/cutoff capture, destination-index checks and atomic NOREPLACE. Preserve the conflicted target and unknown saved association until verified durable adoption of the new destination. If a failed transaction returns to idle, re-observe the original binding and retain its prompt. A source match or a newly appeared destination cannot authorize overwriting the foreign file. This is an amendment to the existing admission row, requiring advisor signature.
- **Lazy restore.** The edit owner checks the actual old source before the first dependent mapped read. On BUSY it retains/restages the requested command at its valid boundary and schedules proof after yielding. If the bool callback refuses during provisional replay, abort provisional journal/undo work before retry. Close the read ticket before final/ACK, including across yielded literal records. Refusal restores the prior history cursor and offers reload on conclusive SOURCE. A23's VALUE_ONLY embargo is monotone. A volatile CRC cannot reopen RESTORE_BASE_RANGE. A worker delivering an equal CRC during a newer watch, reload or close only wakes service; check owner incarnation, revision and effective decision before resuming. At restart verify the selected wire origin, preserve EVIDENCE for unresolved text and use erratum 5's source of the recovered map. A previous process's volatile proof carries no authority.

These are changes to caller contracts for the implementation bead. Savectl needs no parallel witness/“safe” flag or additional stored phase. An outstanding worker, capacity dependency or explicit retry leaves the loop quiescent until progress. Treating “waiting for source” as a final SOURCE would reproduce MF-A; treating it as VALID would let a restore consume the MF-C fixture.
