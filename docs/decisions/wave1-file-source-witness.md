# A witness for mapped source bytes

**Decision status.** The advisor signed the original-inode witness, content check on ctime drift, lazy verification after our rename, and precedence of faults and short reads. This pass specifies their integration for signature. Implement **v2-hy8 after savectl lands**. It blocks the **Wave 2 exit at the 10 GiB gate**. [Advisor brief](../briefs/source-witness-pass2.md)

## Identity and trigger

File keeps a volatile original-source witness on each witnessed mapped acquisition. Its fields are the acquisition fd's volume, both inode words, size and CRC32C over offsets [0, size) of **that held descriptor**, seeded with zero. An unlinked original is still readable through the fd. The acquisition stat is immutable. File publishes the accepted source ctime separately. Savectl owns the named destination decision. The prepared temp has its own witness of the edited snapshot. The journal GENERATION prefix serves its existing wire purpose. Neither identifies all bytes of the original. A matching CRC is the save protocol's fingerprint evidence and admits collisions. [Review findings MF-A and MF-C](../reviews/wave1-L2-1-opus-recheck.md#new-findings-must-fix) · [A23](wave0-plan-amendments.md#a23-the-save-protocol-no-retention-rules-17-t5-is-a-stated-product-contract-advisor-2026-11-23)

**The first committed edit of a mapped buffer starts the first pass.** On the first successful nonempty owner commit, record the work owed against that acquisition and make it runnable on bulk at the first scheduling opportunity. This includes a committed edit whose journal final is awaiting repair. The host performs pool submission. Edit performs bounded bookkeeping and never waits for the scan. A provisional mutation, aborted command, selection change, open, first paint or clean reload creates no obligation. Keep, a save or a checkpoint needing proof of that original joins the same pass, including when its first submission was refused. Later edits do not restart it. On a fresh acquisition apply the trigger afresh. For recovery use the actual registered origin and any outstanding recovered committed edits when installing the buffer. A previous process supplies no volatile proof.

**An unedited mapped buffer never scans for a source witness.** On a foreign change the session reloads through registered acquisition. Clean reads use the existing fd/fault authority. If a caller streams an unedited map it still brackets its loads. The output stream and any required output verification have separate costs. A clean own-save that displaces an unwitnessed original also revokes that old map. Acquire the verified installed file afresh for subsequent use of the clean text. A publisher must serialize this clean disposition with the first edit's commit/admission so that an intervening committed edit gets the edited-source protocol. Never replace a newly dirty tree on the strength of an earlier clean cutoff.

## Five states of a mapped source

A pinned source owns its evidence even when a reload installs a different backing in the same file object. The following calls distinguish all five states. In the table a pristine observation matches the accepted fd stat and has a successful fault poll at epoch zero. A scan step means one worker invocation on demand for an edited acquisition.

| State | Distinguishing call and transition |
|---|---|
| UNWITNESSED | On a pristine fd, `file_source_read_begin` succeeds for ordinary reads, including the command that makes the first edit. A requested witness step on that fd starts or continues capture from the acquisition anchor. A foreign move of the held inode before installation of the first proof yields CHANGED and enters CONFLICT. A stable complete pass installs the original witness and enters VALID. |
| VALID | The same pristine read succeeds and a witness step returns OK with zero reads. On eligible ctime drift, read admission returns BUSY, revokes the prior version and enters RECHECK_OWED. The same drift without a witness gives CHANGED. A disqualifying change or fault enters CONFLICT. |
| DISPLACING | Enter immediately before our potentially displacing rename, retiring earlier tickets and scan attempts. Even on a pristine fd, read admission and a witness step return BUSY. Only the publisher can settle the disposition. On definite non-install, re-observe and classify against the prior evidence with a fresh version. On installation or uncertainty enter RECHECK_OWED if the original witness exists. An unwitnessed clean old map then has no further read authority and enters CONFLICT. |
| RECHECK_OWED | Read admission returns BUSY even on an apparently unchanged fd. A witness step can now read the held fd, including at unchanged ctime after our rename. A stable fingerprint match enters VALID and accepts the candidate ctime. A stable mismatch or fault enters CONFLICT. A newer eligible candidate restarts this comparison at zero. |
| CONFLICT | Read admission and a witness step return CHANGED, including on a subsequently pristine observation. Preserve the tree, history, literals, baseline and usable evidence. Registered reload creates a new acquisition. |

On a healthy multi-quantum original the discriminators are thus read admission, a step on an unchanged fd and admission after eligible drift. They distinguish an initial capture from a cheap VALID hit, an eligible recheck from a blocked rename, and a retryable obligation from permanent refusal. Starting a worker changes none of these decisions. PENDING and CAPTURING collapse into UNWITNESSED. NEEDS_RECHECK and REVERIFYING collapse into RECHECK_OWED. The existing `file_mode` selects private copies outside this enum.

**One scan slot per original.** File keeps the job lease, initiating generation, attempt identity, starting observation/version, next offset, partial CRC, scratch and pending completion in a job slot keyed by the retained source. Queue admission, running, continuation and result delivery are job facts. A source with no active job retains only its evidence and any owed scheduling intent. Consumers joining the same original use the existing slot. A snapshot of A cannot join B's pass after reload. Serialize worker access to one slice and the conditional evidence install. UI readers take a bounded coherent observation of the published state, version and accepted ctime. They neither wait on a worker lock nor drive a scan. Publish invalidation before the rename syscall, release worker locks across that syscall, and reject completions for retired attempts. A racing reader fails closed. Versions never wrap into reuse.

### Accepting an observation

1. Observe the held fd and poll its registered fault id. Initial capture requires the acquisition's compared fields, ctime included, at both ends. For recheck require PRESENT, the original volume and both inode words, regular kind, size, mtime, permissions, uid and gid. Inspect the members of Q14's grouped metadata flag to isolate ctime. Link count is observational. On stat or read I/O error preserve the native cause, discard the partial cursor and leave the outstanding proof retryable.
2. Read the acquisition length in offset order. For each bounded pread require the **entire requested count**, including the smaller final request. Any short read, failed fault poll, nonzero fault epoch or observed truncation disqualifies the source even if a CRC matches. At the last byte repeat fd observation and fault poll. Install only on the same source, attempt and version, with identical compared fields at both ends. Initial drift forfeits the acquisition anchor. During recheck a newer eligible ctime discards the candidate before any CRC verdict. A stable match advances only accepted ctime and read authority. Preserve the original fingerprint. Record observed disqualification against its incarnation so an older completion cannot resurrect it. [Q14](wave1-L2-derivations.md#q14--settled--present-carries-a-complete-os_stat)
3. Bump the read version when authority is withdrawn or re-established following drift or displacement. Initial promotion on an unchanged anchor preserves outstanding pristine tickets. A writer could alter bytes during a copy and restore them before a later successful scan. Therefore all mapped-byte consumers bind the whole operation to one version. The witness supplies evidence within the fd/fault observation model. It cannot detect a writer invisible to both observations or guarantee future bytes.

### Why link count and mode do not settle MF-A or MF-C

Open an inode with names A and B. Rename a different inode over A. In one run the original bytes stay intact. In the other a writer uses B to replace bytes at equal length, restores mtime and leaves mode and ownership alone. Both runs can show the same held identity, falling link count, advanced ctime and otherwise identical stat. With only one name, an already open writer gives the same counterexample at link count zero. Observing both sides of our own rename still admits the intervening rewrite. Verify the old fd on its first dependent use. [Review probes](../reviews/wave1-L2-1-opus-recheck.md#new-findings-must-fix)

## Read tickets through the signed interfaces

A ticket is a pinned source identity and its accepted read version in **the validator's context**. The L2 owner obtains it before the first possible mapped load. The callback compares the supplied backing with the ticket's source (including file provenance, extent and fault registration), checks that very version around the live fd observation and closes with the fault poll. It cannot renew the ticket. The owner keeps it through all slices, yields and the final validation before accepting a dependent result. Lower-level closing polls remain in place. A private ORIGINAL or ADD slice needs no mapped ticket of its own. An unknown mapped backing cannot pass as private.

| L2 owner | Opening, borrowing and closing the context |
|---|---|
| **Edit, one command** | Edit embeds a validator context with its command ticket and the caller's original `edit_options.validate/ctx`. It passes its wrapper and the stable address of this context to `undo_create`. The wrapper checks the active ticket and the caller's original identity predicate. Context storage outlives the log. Edit activates the ticket before forward mutation or the first replay preparation and reuses it across turns. Its calls to `piece_snapshot_read_span` receive the same wrapper and context. Undo's last validation and fault poll in `undo_commit` close the mapped reads after all provisional journal members. On refusal edit aborts the journal command, drops provisional snapshot pins, then calls `undo_abort`. On successful RAM commit issue the funded final without yielding. Repair a short final from its retained frame. Clear the active ticket after commit or abort. |
| **Session, one checkpoint producer** | At a published boundary pin the offered snapshot and resolve its actual mapped backing, including a recovered one. Preflight proof, acquire the ticket, and pass a request-lifetime context to `journal_checkpoint_request`. Journal borrows it for each dependent read and validates that same ticket and polls after the last load before COMMIT. A join keeps the first producer's callback and context. Retire unused candidate context on refusal or join. Supersession revokes write authority immediately. Keep the original snapshot/source, owner reference and context through terminal status and the last physical delivery. Each replacement gets its own context. |
| **File, one save stream** | In `temp_prepare_core` resolve the backing of the pinned snapshot. Verify any mapped lender against it, including the null-lender case by deriving file provenance from the snapshot. File owns the ticket in the prepare operation's context from before the iterator's first load through all CRC and write accesses. At the end of streaming check that ticket and the closing fault poll before accepting a synced temp. A conditional worker result is checked again at handoff while it still depends on that authority. Discard failed unpublished output and restart streaming at offset zero after proof. A retained source for later displacement has a separate custody lifetime. |

Use the same enclosing check for any other operation accepting bytes from a map across loads or turns. A callback refusal keeps the lower layer's signed CONFLICT or SOURCE result. L2 uses its preflight and ticket diagnosis to distinguish proof owed, expired operation, native error and terminal source conflict. It can schedule proof and restage an aborted request at a still-valid boundary. A later successful check cannot validate previously refused bytes. Neither renewal nor scheduling occurs in a point validator.

**L1 signature delta is empty.** The shared type is `bool (*piece_validate_fn)(void *ctx, const piece_backing *backing)`. The landed `piece_snapshot_read_span(s, span, skip, dst, capacity, written, validate, ctx)` calls it after copying a mapped slice. On CONFLICT, written is zero and the destination slice is discarded. Landed `undo_create(out, tree, cap_bytes, validate, ctx)` borrows it for the log. The signed producer `journal_checkpoint_request(j, owner, text, goal, target, validate, ctx, out)` borrows it for the request. Each accepts the existing callback and context exactly as declared. File's legacy null-ctx point validator still resolves the backing of a recovered map. An operation needing a ticket resolves the same backing and passes a real context to the ticket-aware adapter. ## Cost and service order

Let N be original length, P = min(N, 2²⁰) the existing open prefix, and Q = 65,536 B the round-3 verifier's read quantum. The table counts logical bytes on a stable fd with full reads. A scan reads [0,N), including the prefix. Joins share that work.

| Operation | 256 MiB map | 10 GiB map |
|---|---:|---:|
| Open, existing prefix P | 1,048,576 B | 1,048,576 B |
| Added witness reads at open or over a never-edited map's lifetime | 0 B | 0 B |
| First committed edit, one background capture N | 268,435,456 B | 10,737,418,240 B |
| Prefix plus completed first capture P + N | 269,484,032 B | 10,738,466,816 B |
| Keep, save and checkpoint joining the same initial pass, additional scan bytes | 0 B | 0 B |
| One stable eligible ctime recheck, or first dependent use after our displacement, N | 268,435,456 B | 10,737,418,240 B |
| Subsequent uses at accepted ctime, or displaced original never reused | 0 B | 0 B |
| Pread quanta per complete pass, ceil(N/Q) | 4,096 | 163,840 |

The first edit adds zero foreground witness bytes. Further uses take ordinary fd/version/fault checks. A reload pays ordinary acquisition cost. An observed fault or ineligible stat can stop a pass early. A move immediately before recheck installation can waste up to N bytes before another N-byte pass. Continuous changes have no finite retry bound. Output reads, by-value journal writes, line counts and display loads have separate ledgers. The eligible A13 delete/undo bound remains 131,072 foreground ORIGINAL bytes and inverse copies bounded by min(length, 16 × spans) bytes. [A13 and A22](wave0-plan-amendments.md)

Each WORK_BULK invocation issues at most one Q-byte pread and CRC update, polls cancellation within the pool's 5 ms CPU budget and returns via `work_continue` to the class FIFO if more bytes remain. Joins never enqueue independent full scans or block the sole bulk worker waiting on another job. Publish one sealed terminal result. If `work_publish` refuses for fullness, retain that result, call `work_continue` and return. The continuation parks on its producer. A UI mailbox drain that reclaims space makes it eligible to retry delivery only. Check input between bounded drains. On submit refusal retain owed work and retry on capacity wake. Pin arguments until `work_handle_finished`, including cancellation and close. Measure actual bytes, allocations and cold/warm ingress-to-submit p50/p99 on the Wave 2 gate, under typing and writeback, with power and load stamps. One cold pread can stall. Slicing bounds issued work between scheduling opportunities. [Work §1.32](../../src/work/work.h)

## Interleavings and acceptance traces

| Input | Required outcome |
|---|---|
| **First committed edit, then a foreign move of the held inode before the first pass completes** | **CONFLICT.** This includes before the first slice, halfway through and after the last read before proof installation. A partial CRC, a pristine fault poll or the new path's bytes cannot supply the missing acquisition proof. Preserve edits and history, refuse dependent Keep/save/restore/checkpoint, and preserve usable evidence. |
| Foreign change before any committed edit | Reload the clean buffer. Count zero source-witness jobs and bytes, including for the new clean map. |
| Edited, VALID source displaced by a foreign rename | Record the changed destination independently. Read the original fd even if unlinked. A stable equal CRC permits the conflict checkpoint to emit exact edited text by value. Explicit Keep can secure the accepted TARGET. Once durable Keep returns to IDLE_CLEAN, Save As can use an independently observed destination. |
| Second move during recheck, or after a target-specific checkpoint starts | On eligible old-fd drift restart comparison at zero. A second replacement of the already-displaced path can leave the old fd unchanged. Re-observe the binding and supersede stale target-specific work, including an outstanding barrier. |
| Equal-size rewrite through another fd or link, mtime restored | A stable differing CRC enters CONFLICT. Withhold dependent save, undo final/ACK and checkpoint COMMIT. Equal stable content can pass subject to the CRC evidence model. |
| Short read or truncate/regrow during capture, comparison or copying | Reject on short read, observed truncation or failed/nonpristine fault poll even with a matching CRC. Discard the speculative result. Repaired zero pages cannot become committed literals. Retain A22 refusal on fault-slot exhaustion. |
| Own rename of an edited source | Join capture before exposing PREPARED if the save could displace that original. Immediately before rename enter DISPLACING. Settle successful or uncertain displacement into RECHECK_OWED, including uncertain rename and barrier retry. A definite non-install still revokes pre-attempt tickets. A verified output can finish without reading the old fd. |
| MF-C at the RENAMED hook | Save edited S over A, rewrite through second link B at equal length and restore mtime between rename and the old after-stat. The first restore of old ORIGINAL must compare against the original CRC. Mismatch refuses the restore before commit. With B intact the restore succeeds after one scan. If a concurrent copier holds a pre-rename ticket, even a subsequent successful source check cannot authorize its copied bytes. |
| Close, reload or cancel with a scan or result outstanding | Compare source, slot, epoch, generation and attempt before installation or delivery. An old result can wake its own waiters only. Check logical supersession at adoption and wait for physical release before reusing storage. |

## Public file.h delta against review/l2-1d

Keep the round-3 public entry points for acquire, validation, prepare, publish, retry, verify/recover and save. Add the following at the source lease declarations. Only mapped sources enter the witness FSM. Check `file_source_mode` before querying it.

```c
typedef enum file_source_witness_state {
    FILE_SOURCE_UNWITNESSED = 0,
    FILE_SOURCE_VALID,
    FILE_SOURCE_DISPLACING,
    FILE_SOURCE_RECHECK_OWED,
    FILE_SOURCE_CONFLICT
} file_source_witness_state;

typedef struct file_source_read {
    const file_source *source;  /* pinned by the caller */
    uint64_t version;
} file_source_read;

file_source_witness_state file_source_witness_state_of(const file_source *source);
file_source *file_source_of_backing(const piece_backing *backing);
int file_source_read_begin(file_source *source, file_source_read *out,
                           os_err *oserr);
int file_source_read_end(const file_source_read *read, os_err *oserr);
bool file_source_read_validate(void *ctx, const piece_backing *backing);
int file_source_witness_begin(file *f, file_source *source, uint32_t generation);
```

- `state_of` reads the last published tag. `of_backing` borrows the file-created mapped source using round 3's callback/ctx, extent and fault-id provenance checks on a pinned backing. `read_begin` writes its output only on OK. `read_end` checks the saved version without consuming or replacing the ticket. `read_validate` takes the address of the active ticket as ctx. An edit context wrapping an existing owner validator can delegate to both checks. Keep both legacy meanings of `file_backing_validate` (installed file ctx and null ctx). Passing a ticket to the legacy file-pointer form would misinterpret its storage.
- Extend the contracts of `file_source_validate` and the read helpers with BUSY for proof/disposition owed, CHANGED for conclusive source refusal or an expired ticket, and IO with the native cause. A waiter re-observes before use. The point callback reports false on any refusal. `file_source_stat` returns acquisition fields with the latest accepted source ctime.
- `file_source_witness_begin` is the UI admission/join adapter on the first commit or a qualifying demand. Record a refused submission as owed. A same-source join uses the initiating generation. Give `struct file` a witness job reference (retained source, handle and generation) for the lease it submits. Keep the actual shared scan cursor, worker progress and result in that source's **job slot** in file's private implementation. Add `FILE_MSG_SOURCE_WITNESS = 0x46490008u` after RELOAD_FAILED. Decode by handle/epoch/generation. Wake dependents to re-observe their own source and revision. Close cancels its submitted lease and checks physical retirement before release. A joiner does not cancel the owner's lease. A surviving borrower can reschedule an owed pass after cancellation. A detached or synchronous save can drive the same serialized, source-keyed slice helper on its pinned backing off the input thread. The shared bulk worker always yields between slices. The helper and its “more bytes” result are private.
- In `file_check` keep Q14 path reasons, old-fd evidence and native observation failures distinguishable. Lazy old-fd proof after a verified own-save alone must not set a foreign destination conflict. `file_resolve_keep` requires full mapped acquisition, preflights the actual backing, joins any proof owed and returns BUSY pending it. Retry against a freshly observed target. A failed check preserves the old binding.
- `file_temp_prepare`, `file_save_write` and the async prepare path consume the real snapshot source under the save ticket. FORCE affects destination policy only. For a potentially displacing rename, include the actual target or conservatively gate the old map when FORCE makes the stored expectation unreliable. Recheck eligibility at publication. A save to a proven distinct destination leaves old-source authority alone.
- Remove round 3's public `file_source_pair` and `file_temp.pair`. Replace `source_rebaseline` with source disposition around rename. Drop the `pair_foreign` veto in `temp_verify_installed`, reached on publish and barrier retry. Keep the temp's retained source and the output fd/path, witness, original-directory barrier, HELD custody and uncertain-rename reconciliation. `FILE_PUB_CONFLICT` describes foreign or unverifiable output. Old-source failure is delivered to its dependent consumer. `witness_check` for verify/recover still checks the named output. Source scans share the CRC/read quantum and use the held original alone. Update the header's IDENTITY, STATE, THREADS, save and close clauses accordingly.

## Savectl and journal adoption

On confirmed foreign binding of edited text, including a rejected complete FINISHED, enter IDLE_CHANGED immediately and request conflict protection that turn. Retain the cutoff, independent suffix, protection obligation and index fence until covered. A complete FINISHED consumes its token. Report SAVE_FAILED/CHANGED, forget the lost saved association and release the edit bookmark. A pending witness gates the dependent by-value producer. It cannot postpone the state transition. A matching source comparison releases only its source dependency. At BEGIN capture the current published snapshot, IDs and conflicted TARGET together. On failed validation, withhold COMMIT and preserve evidence.

A complete checkpoint COMMIT protects process restart. Its covering DURABLE sync protects machine loss. Explicit Keep re-observes the destination, requests by-value text with the accepted TARGET, and checks source, target and decision epoch at adoption. Only its matching durable result returns the controller to IDLE_CLEAN with saved ID unknown. History and later edits survive. **From IDLE_CHANGED the route to Save As is Keep, durable adoption, then ordinary Save As.** Direct Save As is inadmissible. Reload remains the clean foreign-change path. For restore, hold the input head on proof owed, pump the worker, and restage only at the original valid command boundary. VALUE_ONLY remains monotone. At restart verify the selected wire origin and retain unresolved text as evidence.
