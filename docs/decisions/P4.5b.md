# P4.5b — review fixes (edit-457.22)

## §5 — cache identity (valid; fixed)

Cache validity now compares source context and span callback as well as revision,
bytes, lines and height. Pending fills cannot retain another source's density.
`minimap_bind` adds a stable opaque buffer token for adapters which recycle one
context across tabs; changing the binding invalidates exact offsets. Bind both
UI and worker states to the same token. Contexts which identify one buffer for
its lifetime need no binding; reinitialise or bind when recycling a context.
This is an additive integration obligation, with no existing prototype changed.
Publication checks the token, source identity and revision. The equal-size,
equal-revision tab-switch test verifies the second buffer's exact offset, and
also tests context recycling with explicit binding.

Red: `minimap_test:215: minimap_hit(&m,&in,NULL,1,&hit) == 0 && hit.exact && hit.byte == 1`

Green: `review 5: equal-size tab switch exact byte=1: ok`

## §6 — indent typing work (valid; fixed)

Enter and brace boundary scans are limited to `INDENT_TYPING_BYTES` (8192 bytes
in each direction). Missing either boundary returns the added `INDENT_ERR_LIMIT`
with cleared results and no output writes. Successful results remain exact;
no truncated indent or guessed terminator is returned. Prefix counting and
output copying also fit the bound, so total byte accesses are at most four
bounds plus constant CRLF probes. No line-index queries or allocations occur.
Protected mapped pages verify both scan directions, including zero-capacity
Enter. Tests and fuzz operations cover long blank lines; the bench adds a
long-line Enter and brace rows including zero-capacity Enter calls. Existing prototypes
are unchanged. Integration addition: handle LIMIT by explicitly rejecting or
deferring the command, without mutation; do not retry synchronously in a loop.
This bounds byte work, not storage-fault latency of mapped indent bytes.

Red: `tests/indent_test.c:188: assertion failed: indent_on_enter(t,0,out,sizeof out,&n)!=INDENT_OK && n==0`

Green: `review 6: long-line typing/zero-capacity work bounded: ok`

## §7 — sidebar damage (valid; locally mitigated, rectangle proposal outstanding)

Fill compares whole cells, writes only changes, and marks only changed rows.
A cached typing-frame fill preserves the original typing row; a blink frame
with unchanged strip cells has zero damage. The regression checks canonical
submission strips and actual backend submitted-cell counters rather than fill
timing alone. Existing fill's column and
viewport semantics are unchanged; damage becomes minimal within the frozen API.

True strip-only submission is impossible through frozen `render_strip`, which
contains full-width row runs, and `render_backend_submit` requires exactly
those canonical strips. A changed sidebar row therefore still submits text
columns. Proposal for a render/backend bead: add column ranges or pixel
rectangles to damage and canonical submission, preserving dirty text rows;
update CPU copy/raster and GPU submission to consume those rectangles. Then
verify submitted cells/pixels equal strip width times changed rows, and measure
integrated typing/blink cost. No frozen header/backend/other module was changed.

Green: `review 7: cached fill preserves typing/blink damage: ok`

## §8 — incomplete-index navigation (valid; additive path fixed, wiring proposed)

A pending fill with no compatible summaries paints an approximate scrollbar
and viewport band rather than a blank strip. `minimap_hit_approx` adds current
byte-based dragging without cache/index/source access. It clamps rows and maps
the endpoints to zero and EOF, reports an estimated line and `exact=false`,
and handles full-width uint64 lengths without overflow. `minimap_fill_cached`
always shows this current approximate map on a cache miss, rather than old
density. Exact `minimap_hit` retains its original stale-error meaning. Tests
cover pending paint, clamping, midpoint drag, length changes and zero source
calls; the bench checks sidebar correctness before starting indexing.

Integration proposal (no editor/view changes here): while index/summaries are
pending, use hit_approx and the loop's byte-based scrolling path, never treat
its byte as an exact line start. Switch to existing exact hit mapping after
publication. Existing public prototypes and exact-hit semantics are preserved.

Red: `minimap_test:237: cells[1].bg != model_blend(style.background,style.stale,128)`

Green: `review 8: pending index paints current byte scrollbar and drag works: ok`

## §9 — foreground sample faults (valid; additive path fixed, worker wiring proposed)

`minimap_prepare` / `minimap_prepare_source` build summaries into exclusively
worker-owned, caller-reserved state from retained immutable snapshot bytes.
The latter separates snapshot byte access from stable UI source identity.
`minimap_publish` copies summaries on UI only after buffer identity, revision,
length, line count and readiness checks; caller also checks requested height.
`minimap_fill_cached` never calls span or dereferences source bytes, even on an
edit, resize or initial miss; it uses the current approximate map until a new
preparation arrives. Protected sample pages prove both fresh and invalidated UI
fills cannot read source; tests reject stale publication and check allocation
freedom. The bench requests eviction of its own small file fixture and records
foreground major faults and span calls for fresh and invalidated cached fills.

Integration proposal (no src/work/editor changes here): reserve separate worker
summary storage at open/resize, capture an immutable piece snapshot on UI,
queue preparation using the existing worker/mailbox owner, retain snapshot and
job storage through publication, and discard superseded buffer/revision/height
results. UI calls cached fill and approximate hits while waiting. Worker rows
must remain immutable during publication and must not overlap UI rows.
Legacy synchronous fill retains density semantics and may fault: it requires
resident bytes when used on UI. Its original nonblocking callback requirement
alone cannot guarantee residency. Large exact legacy hits may also scan an
index chunk; use approximate byte hits for a fault-free UI drag path. This bead
supplies the safe APIs but does not claim the existing editor loop is wired.

Red (legacy UI fill): `minimap_test:257: f.calls == 0`

Green (cached UI fill): `review 9: UI deferred fill reads no dispersed samples: ok`
