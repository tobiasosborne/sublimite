# P2.4 GLX — render adapter backend

GLX context creation and all library loading run during worker init. The module
loads libGL and libX11 dynamically, uses a separate Xlib connection to the same
xcb-owned window, and chooses a double-buffered FBConfig matching its visual.
An Xlib-xcb bridge is unnecessary: X resources can be addressed from another
connection to the same server. There are no GL/Xlib link dependencies. Init
requests a 3.3 core context, detaches it before mailbox publication, and UI calls
bind it. Missing GLX context/profile/OML/Present/swap-control support returns
UNSUPPORTED and cleans up so the application can choose CPU rendering.

Each dirty cell becomes one 32-byte instance in init-reserved base-arena storage;
cell position follows the strip's first index and instance ID. GLSL 330 computes
exact rounded integer sRGB-channel coverage, inverse and underline. A wide-right
cell samples the continuation of its left cell's image, without drawing another
whole glyph. No caller cell/glyph/page metadata survives submit. R8 pixels are
copied into a cached, packed, power-of-two-width R8 2D texture; unchanged pages
are compared with the cache and require no GPU upload. Packed page offsets and
row stride support both the ASCII atlas and padded runtime pages.

The retained RGBA8 FBO is reserved at maximum dimensions during init. Dirty
strips draw with scissors, then a full FBO blit repairs the swap back buffer.
This handles partial and zero-damage frames without depending on buffer age.
Its cost is paid even for typing; buffer-age damage repair is a future alternative.
The sampler-buffer prototype was rejected after a measured quick test showed
much slower full-frame rendering. A conventional R8 texture performed better.

`EDIT_GL_VBO=orphan` (default) replaces VBO storage per damaged frame, then uploads
only dirty instances. `EDIT_GL_VBO=persistent` uses coherent persistent mapping
with [ARB_buffer_storage](https://registry.khronos.org/OpenGL/extensions/ARB/ARB_buffer_storage.txt).
Absent extension support falls back to orphan and reports `glx-orphan(fallback)`.
The common adapter holds the sole frame slot through both T5 and T6, so mapped
storage is never overwritten while in flight. The backend allocates its CPU
storage only at init. Session 5 moves first UI context binding, texture uploads
and GL error checks from submit to present: submit is entirely CPU snapshot work.
The release test scopes the base counting hook to begin/edit/damage/submit,
including the first submit and 10,000 subsequent typing submissions. This follows
the settled law-2 scope; it does not count exempt GL/XCB present/event internals.
There are no X requests, reply waits, or GL calls in submit.

Swap interval 1 uses GLX_EXT_swap_control, or GLX_MESA_swap_control. T4 is recorded
only by the common adapter after successful present. The FBO is rebound before
SwapBuffers and the subsequent glFenceSync/Flush, to avoid triggering needless
back-buffer acquisition. T5 comes from zero-timeout glClientWaitSync polls on UI;
there is no blocking GL fence wait. Shutdown may block and drains GL before
releasing resources.

T6 is an actual PresentCompleteNotify routed through plat.on_present_complete.
Init creates a temporary special-XGE selection and verifies that a real GLX swap
produces a PIXMAP completion on this window whose serial is the next
[OML swap-buffer count](https://registry.khronos.org/OpenGL/extensions/OML/GLX_OML_sync_control.txt).
Failure to establish that mapping fails init, rather than inventing completion.
The temporary selection is removed without consuming platform events. Subsequent
swap serials map to the original adapter frame ID; stale/duplicate callbacks are
rejected. The current Mesa DRI3 path delivers these events directly, so no
NotifyMSC surrogate is used. MSC differences are displayed-refresh differences.
UST is never passed as CLOCK_MONOTONIC: T6 uses callback observation time and is
held/clamped through observed T5 to satisfy the frozen suite's ordering check.
This is observation timing, not calibrated scanout timing.

The benchmark drives submit/present/event through render.h, routes native Present
messages through WORK events, initializes through a work-pool mailbox, and uses
an override-redirect plat window to prevent the WM shrinking the 2880x1800
fixture. It renders deterministic printable ASCII (approximately 70% non-space),
varied colours, both baked sizes, and scrolls the cell grid. The minimap is absent;
its reserved 0.18 ms (E) is not included in measured timings. Warm gates remain
5.0/5.56 ms (G); idle and startup rows are TRACK. All results are indicative under
concurrent worker activity; the coordinator must rerun on a quiet box.

The frozen render_test.c is included unchanged with RENDER_TEST_EXTERNAL and its
main renamed. The driver supplies platform preparation, event pumping and cleanup.
Additional pixel tests compare every channel of a 4x3 grid, coverage, inverse,
underline, backgrounds, wide continuation, padded multiple pages, overwritten
metadata, retained rows over multiple swaps, and atlas changes after T5. Failure
paths cover no DISPLAY, missing 3.3 context, and persistent extension fallback.
No GL fuzzer is needed: this bead has no document/input parser; the common grid
validation is already fuzzed in the render module.

## Session 5 decisions and limits

Keep the inherited GLX transport, shader, atlas packing, instanced strip draws,
retained FBO, both VBO modes, and frozen render conformance inclusion. No whole
implementation was reverted or restarted. Replace the old whole-lifecycle
allocator measurement with the settled input-to-submit assertion, defer all GL
calls from submit to present, and reject zero-MSC completions. Benchmark startup
failures now clean up their worker/platform resources and emit a SKIP for every
affected row. Battery/unknown-power warm/scroll results are TRACK automatically;
`EDIT_GL_BENCH_TRACK=1` also selects TRACK on a loaded AC run. Quiet AC runs keep
the normal gates and nonzero exit on a gated miss.

Xvfb on this machine supplies Mesa llvmpipe GL 4.5 core, but its negotiated GLX
extensions omit OML sync control and EXT/MESA swap control. The production
factory therefore returns UNSUPPORTED before rendering and releases everything.
Do not substitute NotifyMSC for a displayed PIXMAP completion. No real user
display was used in this session. Real T6/MSC and G3/G3z/G3i require the
coordinator's display-capable quiet AC rerun.

To still test the renderer under the binding Xvfb-only test rule, gl_test.c
compiles a renamed local copy of gl.c with GL_READBACK_TEST. This compile-time
diagnostic bypasses only the unavailable startup presentation requirements;
it uses the same shaders, buffers, atlas, FBO, swap, fence, and callback routing.
The driver acknowledges frames synthetically via a native WORK message after
observing the real GPU fence. Tests explicitly label that T6 synthetic and the
production displayed path SKIP; the benchmark always links the production
factory. There is no runtime diagnostic switch in the shipped library. Real
Present testing automatically runs when the production factory is supported.

The frozen suite is included unchanged. Test-local wrappers scope only its
allocator assertion to the settled law, leaving lifecycle, validation, stats,
ownership, and trace checks in place. The diagnostic driver also verifies zero
MSC, wrong serial and duplicate rejection, then routes its synthetic completion
through the actual native-message handler. Pixel tests trace their hooks and
load the src/trace dump to check original frame ID, exactly one T4/T5/T6 and
monotonic observation times. Benchmark observer hooks also call the src/trace
T5 and T6 helpers, since custom observer hooks replace the adapter defaults.

The test reuses one platform fixture across phases to avoid the already reported
intermittent Xvfb platform/XKB reinitialisation failure. Under ASan only, its
local diagnostic dlopen retains GL library modules with RTLD_NODELETE. Otherwise
Mesa/LLVM's two 56-byte process caches appear leaked after driver unload and lose
symbol attribution. LeakSanitizer remains enabled; production dlopen/dlclose and
resource destruction are unchanged. Release tests do not retain modules.

### 6. Decisions

The decisions above keep the existing GLX design, enforce the settled law-2 scope,
retain real Present verification for production, keep unsupported Xvfb timing
explicitly skipped, and use a compile-only diagnostic to verify real rendering
and fence code. A NotifyMSC surrogate was rejected because it cannot establish
that this GLX swap was displayed. Default VBO remains orphan; both modes remain
available for the coordinator's Pareto comparison.

### 7. Out of scope findings / coordinator action

- Existing intermittent Xvfb `plat_init`/XKB failures are recorded in HANDOFF;
  no platform source was changed. Reusing one GL fixture reduces exposure.
  Full-suite Xvfb uses `-noreset` so repeated clients do not trigger the failing
  server-reset startup sequence.
- Mesa/LLVM process caches after unload affect diagnostic LSan attribution;
  test-only module retention addresses this without disabling leak checking.
- Xvfb lacks the negotiated GLX extensions needed for this production backend.
  A display-capable quiet AC run is required to establish G3/G3z/G3i, successful
  startup cost, real native Present serial/MSC mapping and production T6 timing.
- `src/x11/x11.c:347` unconditionally records T6 with the native Present
  serial before calling `on_present_complete`. The renderer hook correctly
  records the original frame ID, so a real integration may contain extra or
  misattributed T6 records; serials can collide with current/future frame IDs.
  The Xvfb synthetic callback diagnostic cannot certify global real-display
  trace uniqueness. The platform file is frozen for this worker and was not
  changed. Coordinator change needed: add `bool render_owns_present_trace` to
  `plat_callbacks`, and guard that raw serial trace with
  `if (!cb->render_owns_present_trace)`. Renderer drivers would set the flag
  true and let the adapter's hooks emit the sole original-frame T6. This is a
  plat.h/API addition requiring the platform owner; no Makefile change.
- All hardware gate verdicts belong to the coordinator. No new user permission
  or hardware setup is requested by this worker.

### 8. Makefile changes needed

None. Existing glob rules and x11 module link flags suffice; libGL/libX11 stay
worker-loaded via dlopen. No `-lGL`, `-lEGL` or `-lX11` addition is needed.
