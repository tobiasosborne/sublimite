## Accessors and ownership

- `plat_native_x11(const plat *)` returns a typed snapshot with `void *connection`, fixed-width `window`, `visual`, `depth`, and `argb`; it contains no protocol typedefs. Renderer consumers use it during exclusive initialization. Tests and the pending RandR migration can also borrow these native handles.
- `plat_present_available(const plat *)` preserves the renderer capability check without exposing Present fields.
- `wayland_display(const plat *)` lives alongside the existing Wayland surface/window accessors.
- `x11_private(const plat *)` lives only in `src/x11/private.h`, for backend implementation and existing white-box test state injection.
- `plat_config.work_wake` borrows `const struct os_wake *`; each native loop obtains its fd through `os_wake_fd()` internally. NULL means absent.
- X11 allocates its private block once during init, after connection succeeds, and releases it during shutdown. Existing input/XI/clipboard allocations remain unchanged. Wayland extends its existing init allocation. No allocation is added to the typing path.
- The editor currently passes an epoll aggregate (workers, IPC, watches, config and signals), rather than a worker eventfd. Preserve that readiness source with a borrowed `os_wake` view owned by the editor; never signal, drain or close that view. Replacing it with only `work_pool_wake()` would lose Linux wake sources. Its W2 OS migration is outside this bead.

## Scope of backend edits

Input and XI decoding files do not access `plat` fields and remain untouched. Event dispatch, input ordering, timers, clipboard protocol, polls and native request order remain the same. The non-field-access edits are limited to the private include/state declarations, native accessors, init allocation/failure cleanup, shutdown freeing the private owner after its resources, empty-state guards needed for the new indirection, and the `os_wake_fd()` config translation. Detailed final file/line references are in the worker report.

White-box tests and the X11 reference tool use the typed private accessor for protocol metadata or fault injection. Tests that copied `plat` by value now copy their private fixture block explicitly; tests that fabricated `plat` attach stack/fixture-owned private storage. Resource-unwind assertions now check that the opaque owner is NULL, preserving their no-resource expectation.
