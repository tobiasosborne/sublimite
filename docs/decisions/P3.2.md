# P3.2 view: cursor and selection (edit-zzj.2)

## Interface and state

`src/view/view.h` is the only public header. `view_state` is a pointer-free per-tab
payload: one `view_selection` (cursor, anchor, preferred cell column), first
visible line and byte, horizontal cell offset, and an approximation flag. A later
multi-selection implementation can use an array of `view_selection`; v1 has one.
Journal writers should encode these integer fields explicitly rather than dump
C struct padding. `view` also holds caller-owned runtime scratch and callbacks;
that part is not journal data. No undo coupling was added: P3.3 owns grouping and
the frozen undo API only has a 16-byte opaque state (cursor + anchor fit).

Every command returns a `view_change` describing `(offset, old_len, new_len)`
when the document changed. Feed that to layout/undo integration after the call,
even on `VIEW_MORE` or error. The view mutates the supplied piece tree directly.
No renderer or layout dependency is introduced; P3.3 can pass the state to
`layout_set_cursor`, `layout_set_selection`, and a layout viewport.

`VIEW_MORE` means resume with `view_continue`; a different command is rejected
with `VIEW_ERR_BUSY`. The tree and callback configuration must stay unchanged
while work is pending. TYPE copies its input during the initial call and retains
no input pointer. `view_cancel` discards pending movement. For pending post-edit
repair it accepts the already reported mutation and leaves the selection at 0.
The caller should resume repair before drawing for the normal editing experience.
If undo or an external mutation changes the tree, cancel first and supply valid
cursor/anchor boundaries in state before issuing the next command.

## Semantics chosen

The brief is the behavioral contract. Sublime's public
[key-binding documentation](https://www.sublimetext.com/docs/key_bindings.html)
identifies command bindings but does not specify every boundary case; the
following choices are tested explicitly.

- Left/Right step full UAX #29 grapheme clusters, including one CRLF cluster.
  An unshifted Left/Right with a selection collapses to its low/high endpoint.
  Ctrl+Left/Right move from the active endpoint and discard a selection unless
  Shift is held. Shift always keeps the existing anchor, including when an
  extension passes through it or changes direction.
- Word classes: ASCII separators `./\\()"'-:,.;<>~!@#$%^&*|+=[]{}` plus backtick
  and question mark; horizontal whitespace SP, TAB, VT, FF and Unicode 15.1
  White_Space scalars above ASCII; CR/LF stops; everything else is a word character,
  including underscore, other non-ASCII, NUL and invalid bytes. A cluster's first
  decoded scalar chooses its class; invalid bytes form word clusters. The set
  follows [Unicode PropList 15.1](https://raw.githubusercontent.com/unicode-org/unicodetools/main/unicodetools/data/ucd/15.1.0/PropList.txt).
  Forward word movement skips
  horizontal whitespace and then consumes one word or separator run; backward
  skips horizontal whitespace and consumes the preceding run. Line ends are
  explicit stops; a subsequent command crosses the CRLF/LF cluster. Lone CR is a
  separate stop too. Consecutive lone CRs are separate stops. No camel-case split:
  the requested Ctrl word keys consume runs, not the separate Alt subword keys.
  Ctrl+Backspace/Delete use the same destinations as word movement.
- Preferred column is measured in cells after tabs and cluster widths. Horizontal
  moves, selection commands and edits reset it to `VIEW_PREFERRED_UNSET`; the
  next vertical command computes it once. Vertical movement retains it when a
  short line clamps the cursor. When a requested cell lies inside a tab or a
  wide cluster, choose the cluster's start. Up on the first line goes to byte 0;
  Down on the last line goes to EOF, retaining the preferred column.
- Page commands move by the configured number of text rows and shift the first
  visible line by that amount, retaining the screen row when document bounds
  permit. Other movements minimally shift the viewport so the cursor cell fits.
  Viewport rows/columns exclude gutters; zero config defaults to 24/80. Tab width
  zero defaults to four.
- Home goes to the first cluster outside the horizontal whitespace class, then toggles to the line start
  when already there. On an all-whitespace line it first goes to the content end.
  End excludes LF and the CR of a CRLF. Ctrl+Home/End use document boundaries.
- Ctrl+A selects `[0,len)`. Ctrl+L expands to whole lines including newline;
  an endpoint already at the next line start excludes that next line from the
  initial expansion. Repeating on complete lines adds one following line.
  Expansion sets a forward selection even when the input selection is reversed.
- Ctrl+D selects the containing class run (including a separator/whitespace run)
  and leaves an existing selection unchanged. At a content end, EOF or an empty
  document it is a no-op. Selecting subsequent matches is outside v1.
- Edits replace any selection. Without one, char/word deletes use the matching
  movement destination. Insertion and deletion can join previously separate
  clusters; the resulting cursor is repaired forward to the first real boundary
  at or after the raw insertion/deletion endpoint. Anchor then equals cursor.

## Bounded work and allocation

Every command/resume consumes/examines at most **65,536 byte work units (P)** in
view: UTF-8 consumed bytes, four bytes of initial scalar classification and four
bytes of boundary lookahead per completed cluster,
one-byte inspections, and the backward seed window. The `scanned` counter is
asserted by unit tests and fuzz after every call. `piece_read` uses a fixed 4,100
byte window (4 KiB plus a scalar tail); copying a window is not a second scan.
The step refuses new work with fewer than 264 units remaining (256 units
for command/follow metadata and eight for scalar/boundary lookahead), avoiding
unsigned underflow when a large cluster begins exactly at the budget edge.

Columns use `utf8_cluster_step`, never an unbounded cluster-width scan. When
column or smart-home fallback consumes the remaining call budget, use the last
completed boundary and mark `state.approximate`. It never invents a boundary in
an unfinished cluster. Thus lines over 64 KiB are bounded even without layout
checkpoints; shorter highly non-ASCII lines may also approximate due to lookahead
charges. The flag describes the current command, not a promise of a global exact
column index. A clamped preferred column remains the chosen column across moves.

`view_checkpoint_fn` supplies an exact `(byte,column)` seed on the requested
line, at/before a byte or cell target. Its contract requires a real cluster
boundary, exact tab-expanded column, bounded index lookup, and no allocation.
It supplies stored seeds; scanning from a seed belongs to view and its budget. The view
validates the seed range; semantic validity belongs to the provider. A 4 KiB
checkpoint layout adapter can satisfy it without either module knowing the
other's structs. Layout files were not edited. Invalidate checkpoints after every
reported mutation before the next command. A command which mutates suppresses
checkpoint lookup for its repair/follow and all its continuations, because the
caller has not yet had a chance to invalidate the provider.

Exact char/word movement and post-edit repair yield `VIEW_MORE` for pathological
clusters/runs instead of returning a split cluster. Backward char motion seeds
from a certified nearby ASCII-pair boundary, or replays from line start. A fixed
window edge is never assumed to be a boundary. Backward word movement and
word selection can seed at a nearby ASCII class-run start certified by its
preceding ASCII pair on both sides of the class transition; otherwise they replay resumably from line start. This
avoids replaying a huge ordinary line to move over a small word at its end.
During post-edit repair the
selection is temporarily at 0, which is valid in every possible resulting text.

**Frozen API limit:** this bound is on view scanning, not opaque piece operations.
The reference P1.3 kernel's line count/line-to-byte/byte-to-line queries scan the
file, and deleting a huge selection can copy it for undo references. They cannot
be sliced through frozen piece.h. The synthesized kernel/index is required for
the final editor's overall typing budget. Likewise, arbitrary TYPE input length
is copied by piece_insert, outside view segmentation work.

View makes no allocation calls. The typing tests and bench supply the piece tree
with a pre-reserved `src/base` arena; the reference kernel's hook allocations use
that arena. The real release malloc guard covers the entire command (piece calls
included) for 10,000 keys and must report **0 (G, law 2)**. The guard is ASan-inert,
so sanitizer tests are supplemented by release tests and the bench allocation row.

Replacement inserts first, then deletes the old selection. This avoids deleting
text on insertion failure. If the subsequent delete fails, the change reports
only the successful insertion and places the selection at 0. No rollback is
promised: frozen piece.h lacks transaction/reservation APIs. P3.3 must inspect
successful prefixes even on errors, as undo's own documented partial contract
requires. Simple failed piece mutations leave text unchanged.

Rejected alternatives: malloc-backed line strings; cutting clusters at window
edges; synchronous scans of an unbounded cluster; unbounded exact column scans;
embedding layout or undo ownership in the per-tab state; fallible rollback after
a partially successful replacement.

## Scripted key logs and verification

One line is `KEY|typed bytes|cursor|anchor|preferred|expected text`. `Shift+` prefixes
any movement key name, and `-` means unset preferred column. Typed and expected
fields decode `\n`, `\r`, `\t`, `\xHH` and `\\`; literal UTF-8 is preserved.
Names include `Ctrl+Left`, `Ctrl+Right`, `Ctrl+Home`, `Ctrl+End`, `Ctrl+A`, `Ctrl+L`,
`Ctrl+D`, `Ctrl+Backspace`, `Ctrl+Delete`, the plain navigation/delete keys, and
`Type`. Every line asserts the whole document plus all three selection fields.
Use `\x7c` to include the pipe delimiter in a field and `\x00` for NUL.
Additional arbitrary-byte cases are exercised directly and by fuzz.

Tests additionally cover a 200 KB combining cluster, bounded continuation,
busy-command rejection, edit joins, exact checkpoint columns, suppression of
stale checkpoint callbacks after edits, minimal scroll, page screen-row retention,
Prepend attached to ASCII punctuation, the exact scalar-budget edge, and the
real 10,000-key malloc guard. Fuzz compares edits against an independent
full-copy byte model using one-shot UTF-8 oracle segmentation (not view's scanner
or returned edit offset), checks both endpoints after each command/resume, and
checks the byte-work bound. Random input includes binary and malformed UTF-8.

Bench rows are **TRACK**, with a provisional **p99 <= 50 us (E)** target and each
p99 printed as a percentage of the **1.0/2.0 ms G1 (G)** typing budgets. Whole
logical commands include all continuations; samples rotate keys within each
class, and use fresh mapped trees two clusters into the first line. They exclude
setup and rendering. The allocation row is separately gated at 0. These are warm
start-of-file fixture measurements, not deep-file or request-to-frame verdicts.
Battery/shared-box results are indicative only; the final run starts on AC
after the laptop begins charging, and remains indicative under concurrent load; a quiet AC coordinator run is
needed. Exact RED/GREEN, full check tail, all bench rows and fuzz evidence are in
[`src/view/STATUS.md`](../../src/view/STATUS.md).
