# edit-xgcn: Direct3D 11 backend

The frozen `src/render/render.h` is unchanged. The backend is C11 and calls COM through C vtables. Its implementation is wholly guarded by `_WIN32`; Linux sees an empty translation unit. The existing X11 presenter in `raster.c` is wholly guarded out on Windows, leaving the portable raster kernel and RGB blitter available to the Windows test.

The factory fills the common descriptor. The caller queries its storage requirements, allocates zeroed state, attaches that storage to `b.state`, and calls `render_d3d11_backend_for_window(b, hwnd)` before `render_backend_init` with the same storage. This avoids any dependency on the future Win32 `struct plat` layout. The frozen config still requires a borrowed, non-NULL platform identity: the test supplies its own opaque `struct plat` stub; production supplies its platform object. Init failure clears the adapter's state pointer, so callers reattach storage and bind the window again before retrying.

Device creation requests the hardware driver first, then WARP if hardware creation fails. The diagnostic option can force WARP. Feature level 11.0 is required for the shader profiles used. Init first requests the debug layer; `DXGI_ERROR_SDK_COMPONENT_MISSING` retries without it. Device resources, compiler loading, and shader compilation happen on the exclusive init worker. Test initialization and failure/retry results cross a `src/work` mailbox while UI dispatches Win32 messages, because swapchain creation may synchronously message the window.

HLSL source is compiled with `D3DCompile` obtained from runtime-loaded `d3dcompiler_47.dll`. There is no build-time shader tool, committed bytecode, C++ source, or global COM/vtable state. Both ordinary and background init avoid diagnostic presentations; the existing common adapter holds the first real frame until its completion is observed. No second init phase is needed.

The swapchain uses BGRA UNORM and flip-sequential presentation. Its buffer count is two (P: the flip-model minimum). `SetMaximumFrameLatency(1)` and the common adapter's single active frame enforce queue depth one (G: frozen contract and port brief). Present uses the waitable latency object and zero-time readiness polls, then nonblocking `Present1`. The UI can acknowledge a latency signal consumed by its own wait set through `d3d11_notify_latency_ready`. It must retry BUSY presents and poll completions on a finite event-loop timeout while active; no idle polling or backend worker wake is necessary.

Each damaged cell becomes one instanced quad. Continuations discard their fragments; a wide-left quad spans both halves, whose colours and attributes the adapter already validates. An integer R8 texture packs page pixels without stride padding; per-instance image offsets preserve independent page dimensions. Submit consumes metadata into value-only instances, strips, packed coverage and copied RGB region storage. No caller pointer survives submit. All application storage and GPU draw resources are reserved at init; submit makes no native calls. Resize may recreate native swapchain buffers while idle, within the configured bounds.

A retained scene texture holds cells and an overscan row. A composition pass applies the CPU kernel's exact Q8 two-row colour mix in the text clip, leaving chrome/sidebar fixed. A retained output texture preserves undamaged rows across rotating swap buffers. The independent RGB region is composited after text; native margins repaint independently of cell damage. Every presentation copies retained output into the actual back buffer. Diagnostic readback, enabled before init, reserves staging storage and snapshots that back buffer immediately before presentation; its blocking map is test-only.

The pixel tolerance is zero LSB (G: exact equality with the portable CPU kernel). This is stricter than the brief's allowable one-LSB rounding tolerance for floating coverage blending. The reason is arithmetic identity: both paths compute `(fg*a + bg*(255-a) + 127)/255` in integer encoded sRGB channels (P: R8 coverage has values from zero through 255). The Q8 pass first samples quantised scene colours, then computes `(a*(256-f) + b*f + 128)/256`, matching `raster_row_scrolled`. UNORM storage represents the resulting byte divided by 255; no sRGB texture conversion or hardware alpha blend is enabled.

T5 requires the frame's `D3D11_QUERY_EVENT` to signal before Present succeeds. Query readiness is polled across BUSY retries, never spun on UI. The later UI event observation supplies `os_now_ns`; the adapter clamps to T4 and delivers the original frame ID once. T6 requires `GetFrameStatistics` or `GetFrameStatisticsMedia` to return the exact count captured by `GetLastPresentCount` for that presentation. Its timestamp is the monotonic UI observation of that matching record. `SyncQPCTime` is retained diagnostically, not mistaken for the matching frame's scanout time: it describes `SyncRefreshCount`.

The waitable object supplies readiness only, never an uncorrelated T6. Early experiments returned successful all-zero statistics even in a minimal standalone DXGI probe. Later verification returned matching nonzero statistics for every fixture on both drivers. The cause of the earlier empty records was not established. The final test temporarily requests that the display remain on, restores that thread request on exit, and requires matching statistics with a nonzero synchronization QPC. The backend treats missing completion as terminal after the inherited GL recovery window of 3,000,000,000 ns (G: `GL_COMPLETION_TIMEOUT_NS`; recovery policy, not a performance limit).

Quiescent shutdown suppresses callbacks through the adapter, clears bindings, flushes and drains the last device query, then releases COM resources, the latency handle, compiler library and any owned arena. The test inspects debug messages before/after resize and pending shutdown, then reports live device children. Its diagnostic interfaces deliberately retain the device itself; internal references with external Refcount zero are excluded from the leak census.

Hardware and WARP use identical rendering, damage, timestamp and teardown paths. Both produced exact CPU-oracle pixels and matching DXGI statistics in release and ASan/UBSan verification (M, [AC, desktop Spiral]; command evidence and load are in the worker report). WARP differed only in driver selection; neither needed relaxed tolerance. The hardware-unavailable fallback branch exists but was not forced by device absence on this machine.

The reserved lane has one bulk worker (P: there is one active adapter frame and at most one DWM synchronization job). It allocates only at init and sleeps while idle. Completion polling drains this private mailbox, so W1.1 need not dispatch a second work pool: it integrates the borrowed latency handle and uses a finite event-loop timeout while active. `DwmFlush` and diagnostic init work may block on workers; submit/present/event do not wait for them. Shutdown joins the private lane before reclaiming its storage.

Native Present must be allowed to progress while its rendering query is pending. Ordinary-init testing reproduced a healthy hardware query stuck before Present (M, [AC, desktop Spiral]; report includes the failing run); a C-vtable test pins that dependency. T4 records successful native submission. T5 is delivered only after both successful T4 and actual `D3D11_QUERY_EVENT` readiness, on UI. This implements the frozen contract's `max(device completion, T4)` definition; Present readiness itself never supplies T5. T6 still requires the exact `GetLastPresentCount` result in DXGI statistics after worker synchronization. No latency signal, DWM return, different present, or raw `SyncQPCTime` substitutes for T6.

W1.1 calls `d3d11_set_suspended` for session lock/disconnect, suspend/resume and known display/compositor unavailability. Hidden/minimized windows are also detected without notification. Before native Present the copied frame remains retryable. For an already committed frame, a resumed but unobservable record, unsupported statistics, skipped record, or expired active observation requests recovery. `d3d11_recovery_required` distinguishes that healthy-device rebuild from device removal. The adapter retains the frame and emits no invented completion. The caller removes borrowed wait handles, stops input, performs quiescent shutdown, reinitializes on a worker while pumping the HWND, then starts a fresh grid/backend lifetime with full repaint. Unsupported ordinary init selects the platform's fallback. The inherited completion window remains the existing GL policy (G: `GL_COMPLETION_TIMEOUT_NS`, 3,000,000,000 ns), not a new performance target.

The HWND survives physical init completion, any failed-init cleanup, and successful shutdown. A close during init defers `DestroyWindow`, discards adoption, waits for physical completion, and shuts down a successful result. WM_SIZE coalesces while a frame is active and resizes only after the slot retires. This initial implementation supports GDI/CPU bootstrap on the same HWND; a bootstrap flip chain must be fully released/flushed before D3D11 initial init. It does not share or transfer that chain.
