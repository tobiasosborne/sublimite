# Save and journal recovery without retaining the replaced file

**T1–T4 hold for editor-ordered replacement. T5 breaks at the foreign rename.** In the failing execution both the editor's journal and its saved file have already passed their sync barriers. A foreign writer removes the last name for the saved file. Killing the editor before it checkpoints leaves a durable description of which bytes to recover, with no durable source for those bytes. The same checkpoint works on both triggers, but only the editor's own rename can wait for it. Conflict detection still works in the failing execution.

## What a stop means

Start with a durable journal name, a verified recoverable pre-state and successful storage operations except at the explicitly failed or unfinished steps. **K** means a process kill. Recovery sees kernel-visible names and the valid prefix of the named journal. A completed edit record, or the commit of its whole group, must reach that file before the changed frame or success ACK. **M** means loss of the machine. Recovery sees the valid surviving prefix, guaranteed through the last successful journal sync. Later whole edits may survive. Before an ACK a command may be absent or whole. Only K promises every acknowledged command without an intervening sync. For the namespace proof, assume the filesystem recovers a same-directory atomic rename to the old or new binding until parent sync, and to the new binding after success, absent another writer. The tables give allowed results, including when K and M coincide. [PLAN §4.2 and §4.4](../PLAN_V2.md#42-l2-edit-kernel-journal-publish-point--sigkill-kill-oracle) · [A22](wave0-plan-amendments.md#a22-rulings-on-the-l2-derivations-advisor-2026-11-23-docsdecisionswave1-l2-derivationsmd) · [v1 journal append contract](/home/tobias/Projects/sublimite-v1-oracle/src/journal/journal.h:249) · [OS file and directory barriers](../../src/os/os.h#L215)

Let A be the saver, S its immutable snapshot, and s the last complete journal command boundary represented in S. Capture S, s, its content ID and the source-generation policy in one publication boundary (G, rules 2–3). A provisional undo or partially drained group cannot be part of S. N is the synced output inode whose contents equal S. G is the generation the rename displaces. For Save As, A's original source H and G can differ. A generation key identifies bytes within a journal lineage. Device and inode select a live owner. A pathname identifies a replaceable binding. Recovery needs all these distinctions. Digits in trace names, rules, questions, source lines, version names and record names are identifiers. Quantities marked **G** come from a specified contract, **P** from the stated construction. This is a source derivation at v1 pin `6fec2e8`. [Q1, Q5 and Q10](wave1-L2-derivations.md) · [Snapshot ownership](wave1-piece-pool.md#revision-ownership-in-v2)

Read the valid journal structurally first. Resolve tokens, checkpoint cutoffs and dependencies per buffer before opening a BASE. For the expected old destination, replay A from its previous checkpoint through all its complete edits (**old replay**). For verified N, start A at S and replay A's complete text commands strictly after s (**new replay**). Equal text at s plus equal operands for each subsequent command gives equal text at every committed boundary (P, induction on the suffix). Select the latest applicable checkpoint for each peer independently. Replay lifecycle, target and view metadata on their own terms. Skipping a whole session prefix at s or opening every historical BASE before selecting the branch breaks this proof. A foreign or missing *required* generation leaves an unresolved conflict. Preserve the journal and any independently recoverable text. Use the written fd for the N witness. It must recognize the rename transition and verify the candidate bytes. A strict comparison with pre-rename ctime can reject our own N. Device/inode and a short prefix alone can accept changed bytes. One realization uses device/inode, length and a full-content digest accumulated over the validated saved stream, checked on a stable opened candidate under the digest's collision-resistance assumption. Live finish takes the post-rename identity from the written fd and verifies the path against it. The impossibility below holds even with perfect recognition. At the old branch validate the old BASE and the expected destination independently. An explicitly absent destination uses atomic NOREPLACE and an old checkpoint for A, including the empty BASE of an untitled buffer. The file hooks identify separate interruption points even when their recovery results coincide. The journal prepare barrier now belongs **after writing and syncing the temp, before target rename**. While the file worker writes, ordinary journal edits may proceed. Pin s and its image starting at capture. A rotation while s is needed must preserve, or translate, both replay branches, their suffixes, all pending tokens and the value-only policy. Deferring compaction while a cutoff is pinned is sufficient if admission can refuse or defer before exhausting space. A raw offset into a discarded image cannot be replayed. Use an exclusive journal publication boundary for CURRENT so no already-accepted suffix disappears at journal rename. ## T2. Save As over a dirty peer — HOLDS

A opens H and saves an empty S to a different path p. Dirty B owns G at p. Let G contain arbitrary X and B have a synced, acknowledged insertion of `!` at the start. B must recover `!X`. A continues to own its previous target on the old branch. Adopt p as A's target only on the verified new branch. B keeps its own buffer ID, text, view and dirty status. Its remembered destination p may now conflict. It cannot also own N in the open-file identity index.

Let C be B's self-contained checkpoint at its complete command boundary b. Encode its entire current text by value, stream bounded slices, and validate total coverage and group commit. Select C as a replacement for B's text through b. Preserve B's complete suffix even if it precedes C physically in the log. Serialize membership changes and the check authorizing rename so every G-dependent state at that cut is covered. Mark the **displaced** G for all encoders of subsequent G restores, including B and checkpoint writers. This is what applying rules 3–4 to a generation entails in Save As. Marking only A's H would allow B to checkpoint after deleting X, acknowledge an undo of X by range, then lose X at rename. A historical checkpoint alone does not establish that B's *current* recorded state is self-contained.

| Stop immediately after | Guaranteed state on storage | K reads and produces | M reads and produces |
|---|---|---|---|
| Capture S,s, create temp, mid-write, finish writing, sync temp | H and G remain reachable at every cut. Only at the last cut is N's content guaranteed. | At each cut old A from H, B from G plus insertion. | Same for this synced fixture. |
| Capture B,b, then begin C or write any proper prefix of C | B's old representation and G remain usable. | Ignore incomplete C. Return old A and `!X`. | Same, even if some slices survive. |
| Complete C before its sync | G remains named. Old B representation still available. | Use whole C plus B's suffix. | Use surviving complete C or G plus B's edits. Same B text for each surviving prefix. |
| Sync C | C durable, G still named. C no longer needs G. | Old A and C plus suffix for B. | Same. |
| Partial, complete, then synced PREPARED and destination recheck | Before and after the marker barrier, C is durable. Successful barrier covers marker and preceding groups. | At every cut old A, checkpointed B. | Same. |
| Rename N over p | Marker and C durable. Current binding N. | New A, B from C plus suffix. | Old binding gives old A, new binding gives new A. Both give checkpointed B. |
| Sync target parent, verify N, write and sync finish image | N durable. Named journal still PREPARED. | New A, checkpointed B. | Same at each cut. |
| Publish finish image, then sync journal parent | Between barriers either complete image may persist. After parent sync CURRENT is durable. | CURRENT preserves both texts, A's saved cutoff and B's dirty status. | Both possible images reconstruct both buffers. After sync use CURRENT. |

A journal sync through PREPARED can also cover a preceding complete C in the same journal (P, prefix ordering). The separated syncs expose the checkpoint cut. On checkpoint failure, keep G named and suspend or cancel the save. With independently committed journals the saver needs durability evidence from each owner. An unavailable owner cannot count as checkpointed. An index confined to live tabs proves less than rule 4. Worst-case literal payload is exactly the peer's current byte length (P, sum of checkpoint slice lengths), potentially larger than the old file when it contains insertions. There is no such payload for an ordinary save with no peers. ## T3. A closed-but-kept state — HOLDS

Close B in the T2 fixture with its recoverable state kept. Sync its closed membership, view, ID and dirty state. The intended result is a **closed, reopenable** B with `!X`, even if its live tree has been released. On the old binding its journal and verified G suffice to materialize C on the worker. Reopening, evicting or importing a state during preparation must participate in the same membership boundary. A durable eviction can remove a dependency. Closing a tab alone cannot.

## T5. Foreign replacement racing our save — BREAKS at the foreign rename

Let p be the only name for G containing arbitrary X longer than the recorded prefix and fixed-size witnesses. A inserts a literal `!` at the end, acknowledges it, and syncs the journal. Save S = `X!`. X itself has never been journaled by value. There are no peers. Choose the foreign file F to contain unrelated text. The following cut occurs even if every identity comparison is correct.

| Stop immediately after | Guaranteed state on storage | K reads and produces | M reads and produces |
|---|---|---|---|
| Capture S,s, create/write/sync temp, append/sync PREPARED | G remains named throughout. At the last barrier marker and N's contents are durable. | Old replay returns `X!` throughout. | Same. |
| Our rename, then our target-dir sync | At rename the M alternatives are G and N. After sync p durably names N. The working temp name was consumed. | N gives `X!`. | Either valid branch gives `X!`, then N is guaranteed. |
| **Foreign writer renames F over p before our path verification or checkpoint** | Journal still PREPARED. Its operands are identities, s and the literal `!`. No durable checkpoint contains X. | **p names F. Neither G nor N has a name.** Fails both witnesses. Report conflict with A unresolved. Process death drops remaining fds and maps. | N may survive and recover S, or F may survive and produce the same unresolved conflict. |
| Foreign writer syncs p's parent | F durably named. No source for X. | Same failure. | **Same failure guaranteed** for this sequence. |
| Live editor detects mismatch and enters CONFLICT_CANCEL, or partly writes C | The durable inputs above are unchanged. A valid pinned live source can still supply the contents for C. | Incomplete C ignored. A still unresolved after kill. | Same after the foreign barrier. |
| Complete C for current A including its post-s suffix, before journal sync | F durable. C may survive. | Complete committed C recovers A dirty, retaining the conflict with F. | If C survives, recover A. Otherwise unresolved. |
| Sync C, then durably resolve/cancel the token in CURRENT | C guaranteed. Cancellation records the conflict and preserves dirty text. | Read C even with PREPARED outstanding. Recover A, leave F alone. | Same from the checkpoint barrier onward. |

At detection the live controller has no finishable BASE, exposes recover-cancel, and keeps post-cutoff typing. A successful later checkpoint fixes later cuts only. A live fd, a stronger digest, faster notification or an additional post-rename verification cannot supply the missing X to restart. For exact recovery against arbitrary external replacement, a sufficient representation must already survive independently *before the external writer can act*. At an arbitrary cut this can cost the full missing current text (P, arbitrary incompressible X). Applying this only during our saves would still leave the ordinary external-replacement interval. The alternative product contract is explicit unresolved-source conflict for that interval, with preservation of every recoverable journal byte. That is a different verdict from exact text recovery. A foreign rename **before** PREPARED can similarly remove G during the temp write. Detection can stop our save and checkpoint while the old inode is readable, with the same detection-to-checkpoint gap. If the change arrives between our final check of an existing destination and REPLACE, the syscall can overwrite the foreign binding. The OS seam supplies no compare-and-replace by expected inode. An earlier check cannot promise to preserve a racing writer's file in that ordering. A post-rename mismatch on retry or during finish takes the same conflict path. ## Identity ownership and in-place rewrite

**Rule 6.** At the pin, ordinary Open compares canonical paths, then device/inode, and selects the existing live tab. IPC also deduplicates within one request. Ctrl+O takes this path. The fixture checks hard links, symlinks and relative spellings against the same tree, cursor and edited text. Recovery deliberately bypasses reuse: independently recorded sessions can have divergent drafts for the same target, and the user gets access to both drafts without replaying either over the other. Reopen also reactivates a kept tab directly. The ordinary-open behavior is precedent for v2. Universal live identity uniqueness requires handling restore, reopen and Save As too. Keep one owner indexed by the identity acquired from the opened fd (G, rule 6). A conflicting draft can remain separately recoverable as detached dirty text carrying its former target. Merging solely by path loses a draft. A kept state stays in the generation dependency index whether it currently owns a live file identity or not. **Rule 7.** In-place overwrite can destroy bytes in an inode that is still open and mapped. A same-size write may raise no fault. The file owner checks identity/change observations, holds the backing through the last dependent load and checks the registration and pristine epoch at the closing poll. On detected change, reject affected unpublished checkpoint/save/restore work, abort provisional undo without moving its history cursor, and surface conflict. Reload acquires a fresh tree and history domain. Independently captured literal and COPY bytes survive. Any remaining stale ORIGINAL prevents publishing the whole text as verified. This is a detection contract. Reconstructing destroyed bytes from a stale span is impossible. ## Records for L2-2

These are logical wire requirements. The table uses one checkpoint descriptor with existing INSERT slices and group commit, and a phased SAVE record. This keeps whole-text checkpoints streamable within the record limit. CURRENT is a complete journal image. Capture of S and the value-only transition are owner actions. The sole required saving-buffer prepare record is SAVE(PREPARED) (G, rule 2). No intent marker written before the temp exists can identify its completed contents.
