# edit-pgr: journal action commits

Use `JOURNAL_GROUP_BEGIN` and `JOURNAL_GROUP_COMMIT` after the legacy record enum. Existing wire values, data records, CRCs, sequence checks and PAD framing remain unchanged. Both markers have empty payloads and the session buffer ID sentinel. Groups cannot nest. A commit follows every data record of its action, including records in later batches.

The journal parser validates through commit before delivering grouped data to any visitor. Streaming recovery then rereads the validated span using its existing record arena; its memory requirement is independent of action length. Byte-image recovery borrows the image. An unfinished or damaged trailing group stops the accepted prefix before begin, and streaming replay truncates that suffix using its existing corruption policy. Legacy journals without markers replay as before. Callback or BASE errors retain the source and require the caller to discard partial recovery state, as before.

The staged-op drain is in `src/editor/input.c` in this tree. Automatically bracket a staged action if it spans operations or INSERT slices. Clipboard and find replacement continuations keep that group open across turns. Queue an outstanding commit in the existing reserved op array, so existing input, submission and save fences also wait for commit admission. Reset this state after a successful complete checkpoint.

Defer session snapshot publication during continuing clipboard/find actions and while a journal group remains open. Defer save checkpoint requests and finishes across the same boundary, so a rotation cannot persist an intermediate action as an ungrouped complete checkpoint. No recovery.c change is needed: neither strict streaming replay nor its tolerant byte-image pass delivers uncommitted data to restore_record.

(P) A marker has no payload, so its byte cost is `JOURNAL_HEADER`, the existing header: magic32 + length32 + type32 + CRC32 + sequence64 + buffer64 = four uint32_t fields and two uint64_t fields = 32 bytes. BEGIN plus COMMIT therefore adds 32 + 32 = 64 bytes per grouped action, excluding existing page-alignment PAD packing. A single-record keystroke emits no markers: zero additional bytes, allocations, write calls or sync calls. Its existing INSERT costs that header plus an offset uint64_t plus its UTF-8 bytes. Marker append uses the existing bounded protected admission and page-cache write; worker fsync policy is unchanged, with no explicit new flush or sync on the typing path.

(P) Test boundary fixture length is the existing `JOURNAL_INSERT_SLICE_BYTES` plus strlen("tail"), requiring an additional final INSERT. The initial pre-action replacement is strlen("x"). Parser tests cut at every byte of an independently read wire image, with an explicitly flushed PAD inside the group, and corrupt each byte of COMMIT. Crash tests use the existing append-write seam, killing immediately after DELETE and before COMMIT's write. Successful complete actions are killed after settling. The copied campaign probe retains its original fixture and numeric literals under the byte-identity requirement.
