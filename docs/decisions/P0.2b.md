# P0.2b: malloc_guard inert under ThreadSanitizer

- What: `src/base/malloc_guard.c` now compiles out its malloc/calloc/realloc interposition under TSan, the same as under ASan. The inert stubs return `active == false`, so zero-malloc tests skip the count rather than fail.
- Why: linking the interposer into a `-fsanitize=thread` binary crashed the TSan runtime at startup (segfault, exit 139), because TSan owns malloc and must intercept it itself.
- How detected: `__SANITIZE_THREAD__` (gcc) or `__has_feature(thread_sanitizer)` (clang), OR-ed with the existing ASan check into `EDIT_GUARD_ASAN`.
- Release builds are unchanged: the guard stays active and counts libc malloc calls.
