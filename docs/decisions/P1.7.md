# P1.7 file module: decisions (bead edit-4w1.7)

- **Open split.** UI thread: realpath, open, fstat, one pread of min(size, 1 MiB), EOL/BOM scan. Everything else is one work job (copy: chunked pread with cancel polling; map: mmap PROT_READ + madvise WILLNEED on the first 64 MiB). Workers never touch the piece tree: the job posts FILE_MSG_OPEN_READY and the UI calls `file_attach`. Files that are copy-mode and fit the prefix submit no job (`file_open_ready()==1` at return, no message; work_publish is worker-only).
- **Threshold** min(256 MiB, RAM/32) via sysconf; `file_open_opts.copy_threshold` overrides. size < threshold -> copy, size >= threshold -> mmap.
- **Mapping lifetime.** Refcounted `file_map` (munmap + close in the last release, possibly on a worker). The file object holds one ref, the tree and each snapshot one each via piece_map_hooks.
- **Change detection.** Identity (dev, ino, size, mtime_ns), stat of the canonical path; plus fstat of the mapped inode against the mapping length (FILE_CHG_TRUNCATED). inotify is optional and polled by the UI (`file_watch_*`); events only trigger the stat check, so our own save (identity updated under the file lock before events are read) is not a false positive. Sticky `changed` until `file_resolve_keep` or a successful save. Save refuses with FILE_ERR_CHANGED unless FORCE; the worker repeats the identity check under the lock immediately before rename (residual race: the rename syscall itself).
- **SIGBUS: out of scope.** Stat detection only. A process-wide handler is a global and needs sigsetjmp in every mapped reader (iterators in the kernel, scan workers); that belongs with the kernel synthesis (edit-4w1.21). Follow-up bead recommended. Truncating a mapped file under the editor can still SIGBUS between checks.
- **Save.** Ack = change check + piece_snapshot_take + work_submit (returns 0). Worker: temp `.<base>.edit-<pid>-<ns>.tmp` (O_EXCL, 0600) in the target directory, write 256 KiB chunks (cancel polled), fchmod to the original mode, fsync, [lock: stop+identity check, fstat, rename], fsync(dir), post SAVE_DONE. Failure/cancel before rename unlinks the temp; SIGKILL can leave a stray temp (never named as the target; documented). Saving to the canonical path resolves symlinks (the link is preserved). Ownership/xattrs are not copied (follow-up).
- **Step hook** is a field in `file_save_args` (and `file_set_step_hook`), not a global; the durability test forks and calls `file_save_write` directly (no pool in the child), killing itself with SIGKILL at each of 6 steps: temp created, mid-write, temp written, fsynced, renamed (= before dir fsync), dir synced. Target is whole-old before the rename and whole-new after.
- **file_close waits** for the file's queued/running jobs (cancelling them). A queued job behind a long job holds the UI until the worker pops it; acceptable now (jobs poll cancel), revisit with a deferred-free scheme if it shows.
- Rejected: reading the prefix on a worker (adds a hand-off to the G5 path); mmap on the UI thread (cheap but not needed); inotify on the parent directory (more events, no extra information vs stat).

## Numbers (bench, gcc, [bat] Discharging, other workers compiling, indicative)
G5 prefix publish p50 ~2.0 ms / p99 3.0-5.9 ms on sparse 10 GiB, oneline 1 GiB, log 1 GiB (G 6/9 ms). G8s ack p50 24 us / p99 2.0 ms (G 2/5 ms) on a lightly edited tree (M)[bat]. G8d 1 MB p50 7.8 / p99 14 ms (TRACK, gate 10/50); 1 GB 4.3 s (TRACK, gate 1.5/2.5 s; stub kernel + disk state).
