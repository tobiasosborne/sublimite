# L2-0a · os seams for persistence: the directory-change watch and the fd-to-fd metadata copy

Dossier bead L2-0 (`wave1-L2-L5-harvest.md` §1.3, §7), first part. v1 `file` made these
kernel calls itself (`v1:src/file/file_posix.c`). v2 forbids that: only `os` enters the
kernel (`tools/system-symbols.txt`). This bead moves them into `os` as two seams.

Out of scope, as the brief requires:

- `os_link_at`, and anything about retention: A22 Q2 is undecided.
- `os_file_clone`: not touched.

The callers (L2-1 `file`) do not exist yet. Nothing outside `os` and the tests changed.

## 1. The directory-change watch (`os_watch`)

**API** (`src/os/os.h`, "directory-change watch"):

- `os_watch_init(w, slots, cap)`, `os_watch_close`, and `os_watch_fd`. The fd is
  borrowed into `os_waitset_add`.
- `os_watch_add(w, dir_path, &id)` and `os_watch_remove(w, id)`.
- `os_watch_read(w, ev, cap, &n)`, which fills caller storage with
  `{id, what, name}` events.
- `what` is one of CREATE, DELETE, MOVED_OUT, MOVED_IN, MODIFY, ATTRIB or ENDED. An empty
  name means the directory itself. Queue overflow is its own return code,
  `OS_E_OVERFLOW`, which is new in `os_err`.

**Invariants.**

- **(W1) No global.** The watch is a value its caller owns. v1's `file_watches`
  (`v1:file_posix.c:27`) becomes the object that `app_buffers` creates and passes to
  `file` (§0.3 of the harvest). One thread owns it, the same rule as `os_waitset`.
- **(W2) A hold is never silenced by another holder.**
  - Each `os_watch_add` that succeeds is matched by exactly one `os_watch_remove`.
  - The kernel watch ends only at the last remove.
  - Two adds of the same inode, by any path, return the same id. (P) The kernel returns
    the existing wd for an inode already watched on the queue
    (`fs/notify/inotify/inotify_user.c`, `inotify_update_existing_watch`).
- **(W3) Records are attributed by wd, never by slot.**
  - A record whose wd matches no held slot with a live wd is discarded. That covers a
    removed watch's queued records and its IN_IGNORED. An ended slot's wd is −1, and
    −1 is no wd: before the send-back round, a record carrying −1 was attributed to an
    ended slot. The fuzzer found this (§4).
  - A slot freed and reused for a new directory gets the new wd, so it cannot receive
    the old directory's late records. (P) wds are allocated cyclically
    (`idr_alloc_cyclic`), so a removed wd is not handed out again before the counter
    wraps.
- **(W4) Nothing is lost between calls.**
  - The object keeps the unread rest of its one `read(2)` buffer.
  - `*n < cap` with `OS_OK` means the object holds nothing undelivered, so the fd's
    readiness covers everything still pending.
  - `*n == cap` or `OS_E_OVERFLOW` means the caller must call again before waiting.
  - Each call makes at most one `read(2)`. A continuous producer therefore returns to the
    loop, which is v1's property (`v1:file_posix.c:97-98`).
- **(W5) The end of a watch is reported, not hidden.**
  - IN_IGNORED marks the slot ended (wd −1) and is delivered as `OS_WATCH_ENDED`.
  - The holds stay until removed, so the holder's bookkeeping is unchanged. The holder
    adds the path again to resume.
  - Removing an ended hold makes no kernel call.
- **(W6) Zero allocation.** No call allocates. The hold table is caller storage, and the
  buffer and the event names live in the object. `law2_os_persist_test` checks this.

**Mechanism and its derivations.**

- Each slot is `{int wd; uint32_t holds}`. add, remove and the per-record lookup each scan
  the slots linearly.
- `cap` is the caller's derivation. v1's bound was 4096 + 4096 members (P: editor_open's
  live and retained maxima, `v1:file_posix.c:13-18`). Distinct directories cannot exceed
  members, so L2-1 can reuse it.
- The scan is off the typing path: the UI loop dispatches watch events between frames.
- `OS_WATCH_BUF` is 4096 bytes. (G) This is inherited from v1 (`v1:file_posix.c:96`), not
  derived. (P) It must hold one maximal record of 16 + NAME_MAX + 1 = 272 bytes
  (inotify(7)), or `read` returns EINVAL. A `_Static_assert` enforces that. The size
  bounds how many records one read takes, not correctness.
- The mask is v1's (`v1:file_posix.c:64-65`) plus `IN_ONLYDIR`. `IN_CLOSE_WRITE` maps to
  MODIFY, because a write through a shared mapping raises no IN_MODIFY. IN_UNMOUNT maps
  to DELETE "".

**Simplest alternative 1: expose the raw wd, with no holds.** The id is the kernel's wd,
and remove calls `inotify_rm_watch`. *Counter-example:*

1. Two buffers open files in the same directory, so both get the same wd.
2. Closing one removes the kernel watch.
3. The other buffer silently stops seeing external changes, so stale text is on screen
   and a later save overwrites a foreign edit.

v1 avoided this with `watch_release`'s peer scan (`v1:file_posix.c:35-46`), but only for
members it knew of. The red mutation `holds_uncounted` reproduces the bug:
`os_persist_test.c:372: FAIL calls[W_RM] == 0`.

**Simplest alternative 2: one inotify instance per watched file.** Removal is then close,
and there is no sharing. *Counter-example:* (M) this box allows
`fs.inotify.max_user_instances` = 1024 per user, a limit shared with every other process
of that user (`/proc/sys/fs/inotify/max_user_instances`, read 2026-11-23). The kernel's
default is 128 (P, `inotify_user.c` `inotify_max_user_instances`). v1's (P) member bound of 8192 needs one queue. A queue per file also
puts 8192 fds into the one wait set.

**Simplest alternative 3: filter by name inside os**, so a member is a file path and os
matches its leaf. *Counter-example:* the member table would need a name of up to 256
bytes per member, which is about 2 MiB at v1's bound. Matching names is also the
caller's policy (`file` decides which name is its file). The event carries the name, and
`file` compares it.

**Overflow as a return code.** It is input-producible (A15): enough filesystem activity
causes it. It also means something different from any one event: "recheck everything".

- An event kind can be ignored by a `switch` that has a no-op case. A distinct `os_err`
  is the loud form.
- The *n events before the overflow are still delivered.
- Reading continues after it. IN_IGNORED records that follow must still reach (W5),
  because a rescan cannot discover that a watch ended.

The real-overflow test fills the kernel queue past (M) `max_queued_events` = 16384 on
this box. It reads exactly 16384 records and then the overflow, which matches (P)
`fsnotify_insert_event`: the overflow record is queued once `q_len >= max_events`.

## 2. The metadata copy (`os_file_copy_metadata`)

**API:** `os_file_copy_metadata(dst, src, scratch)`. It gives `dst` the owner of `src` and
the whole extended-attribute set of `src`.

**Invariant (M1).** On `OS_OK`:

- `dst`'s uid and gid equal `src`'s.
- `dst`'s listable xattr names are exactly `src`'s, each with `src`'s value. The one
  exception is a name whose set was refused while `dst` already held the identical
  value; that also satisfies the equality.

On any failure, `dst`'s metadata is partly copied and the caller discards `dst`. That is
v1's "refuse the replacement" (`v1:file_posix.c:179-182`).

**Order and rules.** All are kept from v1.

1. **fchown first, and only when the owner differs.**
   - An unchanged owner needs no privilege: an unprivileged editor saving its own file
     never calls fchown, which the test checks.
   - fchown comes before the xattrs because a change of owner clears
     `security.capability` (the kernel's ATTR_KILL_PRIV).
2. **Remove names on `dst` that `src` lacks.** These are inherited, for example from a
   default ACL. This is v1's "remove inherited xattrs absent on the source".
3. **Set each name from `src`.** If the set fails while `dst` already holds the same
   value, it counts as copied. This is v1's "tolerate a matching immutable label"
   (`v1:file_posix.c:244-252`). Any other set failure returns the set's own errno: the
   value comparison never masks why the set failed.
4. **No namespace allowlist.** Every name the process can list is copied: `user.*`,
   `system.posix_acl_*`, `security.*`, and `trusted.*` when privileged.

**Zero allocation.** v1 used `malloc` for each list and each value
(`v1:file_posix.c:154, 230, 242`). v2 takes a caller-lent `os_xattr_scratch`:

- `names`: the source name list, alive for the whole call.
- `a`: the target name list, which is dead after step 2 and then holds each source value.
- `b`: the target's current value, used only for the tolerance check.

(P) `XATTR_LIST_MAX` = `XATTR_SIZE_MAX` = 65536 (`include/uapi/linux/limits.h`). The
kernel returns E2BIG past either (`fs/xattr.c`, listxattr and getxattr). So each buffer
is 65536 bytes, and the scratch is (P) 3 × 65536 B = 196608 B = 192 KiB. `os.h` states
this beside `OS_XATTR_MAX`, and `os_posix.c` checks it at compile time
(`_Static_assert(OS_XATTR_MAX == XATTR_LIST_MAX && OS_XATTR_MAX == XATTR_SIZE_MAX)`, and
the struct is exactly three buffers). Because each buffer is the kernel maximum, every
list and get is one call without a size probe. A list or value past the kernel limit is
`E2BIG`, which now maps to `OS_E_RANGE`.

The scratch holds no state between calls. L2-1 lends one per save worker.

**Simplest alternative: 192 KiB of stack.** *Counter-example:* `os` cannot know the
caller's stack. The UI thread and worker stacks are their owners' choice. A worker
started with a small stack would overflow, by a fault rather than a return code.

**Second alternative: probe the size with a `NULL` buffer, then use a bounded stack
buffer.** *Counter-example:* the bound is still 64 KiB per list, and the probe adds a
race (the list grows between probe and read, giving ERANGE) that v1 had to handle.

**One change from v1: an unsupported descriptor has the empty set.**

- v1 accepted "unsupported on both" and refused "unsupported on the source, supported on
  the target" (`v1:file_posix.c:209-215`).
- v2 treats an unsupported `flistxattr` as the empty list and applies M1 uniformly:
  - Both unsupported: nothing to do, and no set or remove call is made. v1's rule is
    this special case.
  - Source unsupported: `dst`'s inherited names are removed, so `dst` is as bare as the
    source.
  - Target unsupported while the source has names: the first set fails `ENOTSUP`, and
    the call returns it.

*Why:* M1 then has one statement and no case table.

*Counter-example sought, none found:* an unsupported source has no attributes to lose.
The names removed from `dst` came from its directory, not from the file being replaced.
The mutation `unsupported_refused` (v1's rule restored for the source alone) turns
`meta_rules` red at `os_persist_test.c:731`.

**One change at the boundary: the owner comes from `src`'s fstat, not a passed
identity.** v1's `file_metadata_copy` took the captured `file_id`'s uid and gid
(`v1:file_posix.c:287-293`). Its caller already re-stats the source fd before and after
the copy and refuses on any identity difference (`v1:file.c:880-919`, `metadata_capture`
and `metadata_apply`). With an fd-to-fd primitive, the source fd is therefore the single
truth, and a foreign chown in between is still caught by the caller's identity guard.

**Error mapping added to `map_errno`.** `ENODATA` now maps to `OS_E_NOENT`, for a name
removed from `src` during the copy. `E2BIG` now maps to `OS_E_RANGE`. No existing `os`
call returns either errno (the mapping previously sent them to `OS_E_IO`).

## 3. What of v1 is kept and what is cut

| v1 | v2 |
|---|---|
| Process-global `file_watches` with `os_once` install (`:20-33`) | **Cut.** An owned `os_watch`. No global (W1). |
| Peer scan in `watch_release` (`:35-46`) | **Kept as holds** in os (W2). Every holder is covered, not only the members `file` registered. |
| Fixed `files[]`/`paths[]` member arrays, and `file` pointers inside the os-level service | **Cut.** os holds only `{wd, holds}`. The member-to-file map belongs to L2-1. |
| Name matching and `check_requested` in dispatch (`:93-125`) | **Moved to L2-1.** Events carry the name. |
| Overflow sets every member's `check_requested` | **Kept as `OS_E_OVERFLOW`**, handled once by the caller. |
| IN_IGNORED / DELETE_SELF / MOVE_SELF → `watch_refresh` | **Kept as events:** `OS_WATCH_ENDED`, DELETE "" and MOVED_OUT "". Refreshing is the caller's policy. |
| One 4096-byte read per call | **Kept** (W4), plus the rest of the buffer survives a full caller array. |
| xattr rules, fchown-if-different, order | **Kept** (§2). |
| `malloc` for lists and values | **Cut.** Caller scratch. |
| "Unsupported on source only" refusal | **Changed:** unsupported is the empty set (§2). |
| `file_pread_once`, `file_native_error`, and the no-op `file_metadata_prepare`/`check` stubs in `file_posix.c` | Not in this bead. They are `file`'s and go to L2-1 or are deleted there. |

## Tests

`tests/os_persist_test.c` (lane san) wraps `inotify_init1 inotify_add_watch
inotify_rm_watch read fchown fstat flistxattr fgetxattr fsetxattr fremovexattr`
(`OS_PERSIST_TEST_WRAPS`). It runs eight cases:

- **`watch_events`:** real events under `build/` for a watched file and its watched
  parent, each compared exactly per id:
  - create;
  - modify, both the write and the writer's close;
  - attribute change;
  - rename within the parent, out of it, back into it, and over the file (the save
    shape);
  - delete.

  It then checks the parent's own attribute change and rename, then holds (the same
  inode by a second path, the first remove keeps it, the last ends it). Last comes
  rmdir, which gives DELETE "" then ENDED, and the remove of that ended hold makes no
  kernel call. Readiness goes through `os_waitset`.
- **`watch_capacity`:** slot exhaustion withdraws the new kernel watch (the
  `inotify_rm_watch` count). A full caller array is continued with no second `read`.
- **`watch_overflow`:** a real kernel queue overflow, (M) 16384 records then the
  overflow, and the watch still works afterwards.
- **`watch_faults`:**
  - `inotify_init1` EMFILE;
  - `inotify_add_watch` ENOSPC;
  - `read` EINTR (restarted), EIO, and a forged truncated record (`OS_E_IO`, native 0,
    the object drained);
  - `inotify_rm_watch` failure.
- **`watch_misuse`:** death tests for two ASSERTs (A15): removing an unheld id, and init
  without slots.
- **`meta_roundtrip`:** real `user.*` xattrs, including an empty value and a 4000-byte
  value. Overwrite and inherited removal are checked, no fchown is made for the same
  owner, and an empty source empties the target. A refused `user.*` fixture fails the
  lane closed and names the requirement.
- **`meta_owner`:** a forged foreign owner (fstat of `dst` reports uid+1) makes the one
  fchown happen. fchown EPERM gives `OS_E_ACCESS` with nothing after it, and fstat EIO
  gives `OS_E_IO`.
- **`meta_rules`:**
  - a matching label tolerated, and a differing one refused, with its errno;
  - an inherited name that cannot be removed;
  - the three unsupported cases;
  - ENODATA → NOENT;
  - E2BIG → RANGE;
  - EACCES and EIO;
  - a malformed list;
  - EINTR restarted.

Every injection is asserted to have fired, both per case (`FIRED()`) and after each case
in `main`.

`tests/law2_os_persist_test.c` (lane law2) checks init, add, read, copy and
remove+close, each in its own window under the live release guard. It fails closed on an
inert guard and on a refused xattr fixture.

## 4. Send-back round: the watch fuzzer (Law 1)

The watch parses kernel records and keeps state (the hold table), so it ships
`fuzz/os_watch_fuzz.c` (lane fuzz, seeds in `fuzz/corpus/os_watch/`).

**The seam: wrap `read(2)` in the fuzz link, not a factored decoder.**
`OS_WATCH_FUZZ_WRAPS` is `read inotify_add_watch inotify_rm_watch`.

- A read of the watch's descriptor returns the bytes the input forged, or EAGAIN. Every
  other descriptor reads the kernel.
- `inotify_add_watch` and `inotify_rm_watch` still reach the kernel, on directories that
  always exist (`.`, `/`, `/usr`, `/etc`). They are wrapped only so the harness learns
  the kernel's wd and counts removals.

*Why a wrap:* it drives the shipped decoder together with its cross-call cursor (W4),
which a factored `decode(bytes)` function would leave out. That function would also be
an export, or an `OS_TEST_HOOKS` variant, that only the fuzzer calls. The fuzz link rule
links no test-hooks object.

*Counter-example to the wrap:* libFuzzer's own static objects also call `read`. The wrap
forwards every descriptor except the watch's, so they are unaffected.

**What one input does.** It interleaves three operations, add, remove and read, against
a model of the hold table (three slots for four directories, so both a free slot and
exhaustion are reachable).

- A read forges one buffer, either verbatim bytes or structured records:
  - Each record's wd is either one the model holds, the last add's, or any 32-bit value
    (including −1).
  - Its mask is any of the asked-for bits, IN_IGNORED, IN_UNMOUNT, IN_Q_OVERFLOW, a bit
    never asked for, or a raw word.
  - Its name is absent, NUL-padded, missing its NUL, or has a length past the bytes that
    follow.
  - The tail may be truncated.
- The harness reads the buffer out with input-chosen caps. It compares the flattened
  events with an independent reference decoding, including where `OS_E_OVERFLOW` and
  `OS_E_IO` fall.
- It requires that `OS_OK` with *n < cap leaves nothing in the object: the next call
  must read.
- Each add must return the held id of a live wd, else the first free slot, else
  `OS_E_NOSPC` with exactly one withdrawal. Each remove must call `inotify_rm_watch`
  exactly at the last hold of a live slot.

**Red, a real defect.** The first build ran the seeds against the landed `os_posix.c`.
The seed `ended_then_wd_minus_one` feeds IN_IGNORED for a held watch, then a CREATE
record with wd −1. It fails as follows (`build/L2-0a-evidence/fuzz-red/real-defect.log`):

```text
os_watch_fuzz.c:283: FAIL next < ref_n && ref[next].kind == REF_EVENT
==957279== ERROR: libFuzzer: deadly signal      exit 77
```

`watch_slot` matched the ended slot because its wd was −1. The fix is that `watch_slot`
returns "none" for a negative wd. The kernel sends −1 only with IN_Q_OVERFLOW, which is
handled before the lookup, so this was latent, not reachable from a real kernel.

**Red, deliberately broken decoders.** `build/L2-0a-evidence/fuzz-mutate.sh` builds a
mutated copy of `os_posix.c` with the fuzz flags and replays the committed seeds
(log `fuzz-mutation-reds.log`). All six exit 77.

| Mutation | Caught at |
|---|---|
| `no_length_check` (len past the buffer accepted) | `:283 next < ref_n && …` |
| `no_nul_check` (name without NUL accepted) | `:283` |
| `overflow_ignored` | `:283` |
| `partial_header_ok` (a truncated header read as end) | `:293 next == ref_n && !ref_malformed`. The seed `partial_header` was added for it: no earlier seed ended mid-header. |
| `residue_dropped` (the rest of a full caller array discarded) | `:305 n == 0 && next == ref_n && !forged_ready` |
| `unmount_named` (IN_UNMOUNT keeps its name) | `:286 ev[k].id == r->id && …` |

**Green.** `build/fuzz/os_watch_fuzz -runs=0 fuzz/corpus/os_watch` exits 0 over 10
seeds. A diagnostic exploration (not a lane, with its corpus under `build/`) ran
`-max_total_time=60`: 72660 runs, cov 212, ft 1093, no failure (M, [AC], load 0.9).
