# v2-1sg viewport decisions

The implementation follows the signed [Wave 2 viewport and layout contract](wave2-viewport-layout-spec.md) and [A29](wave0-plan-amendments.md). It keeps the signed public declarations and the PLAN §2 layer order. The viewport cursor owns only intent state and prepaid scratch. The caller owns the snapshot, read cancellation, row certificates, final placement and presentation.

## Mechanisms

| Mechanism | Invariant | Simplest alternative and counterexample |
|---|---|---|
| Intent and acceptance | Begin copies the intent. A MORE step preserves its next request and leaves the caller's answer untouched. Acceptance compares buffer incarnation, text and geometry, and intent serial before installing top and selection. | Check the byte and geometry alone. A second edit or tab bind can produce the same byte and geometry while the first read is outstanding. |
| Rebase | The replacement maps interior points and insertion ties according to gravity. The old right edge of a nonempty deletion travels with the unchanged suffix. | Treat the right edge as consumed. Before-gravity would move an anchor at the first surviving suffix byte to the beginning of its replacement. |
| Pixel plan and scroll | The plan covers the intersecting row intervals, including a partial bottom row. Hit inversion uses that same Q8 origin. Relative scrolling uses floor division with a nonnegative modulus. Splitting the dividend before adding the remainder covers the entire signed delta domain. | Use C's signed division directly or store a row fraction. A step above a row boundary produces a negative remainder in C, and a saved pixel offset changes size after zoom if it is interpreted as a fraction. |
| Grid and cluster motion | A row certificate gives the canonical display-line start. A stage walks from there through LF or the next aligned raw grid, including only the fixed UTF-8/CRLF halo. It preserves short raw windows and segmentation state across grants. The signed S1 bound is D = 2S + 4, with S = 32,768 from A29. | Restart from an arbitrary caret or split at the raw grid. The 2S + 2 witness shifts the cut by three bytes inside a valid four-byte scalar, and a CR at the previous byte can need the LF at the grid. A stray continuation is a single invalid unit. |
| Directed word walks | The first scalar gives the pin's cluster class. Synthetic seams reset segmentation and leave word runs connected. Reverse traversal stages a display line once and visits its cluster starts and classes backwards. Select Word completes the right side and uses a saved seam to continue the left side without restaging the active line. | Stop words at seams or scan repeatedly from the physical line start. The first cuts a continuous identifier and the second repeats segmentation inside the same line and can walk an unrelated prefix. |
| Physical LF bounds | Rank/select results are used when exact. For a nonempty selection the high occupancy probe is the byte before its exclusive end. Reverse scan for the low bound and forward scan for the high bound consume disjoint ranges. An inexact forward select can advance the scan to its exact prefix when that prefix proves the next LF is still ahead. Repeat extends by one line. | Always scan for LF or treat an inexact select as an exact start. The former walks a long line even when E4's index knows the answer. The latter can stop inside the first unknown piece. |
| Selection and affinity | Plain motion collapses the mark. Shift retains it. Horizontal motion clears preference. Vertical motion latches the source screen column, including indentation, and uses the destination row to choose seam affinity. End uses the drawable end before the terminator. | Treat one byte as one screen position. At a shared wrap or synthetic seam its trailing and leading positions belong to different visual rows. |
| Visual displacement | Page moves the caret and top once each by the count of fully visible rows, bounded per operand by the frame's admitted R. For fractional scroll, the partial first and last rows contribute to R but have no whole-row credit. Placement receives the resulting top and committed-selection proposal. | Move by R including overscan. From a fractional first row this crosses a page's worth of fully visible text and the clipped rows as well. |
| Future callers and link isolation | The public symbols are reserved against the signed specification. The pre-existing isolated L4 link test exercises the viewport header and wrap default. The executable smoke path reaches the existing render smoke directly after the removal of the viewport placeholder. | Keep a viewport smoke export taking a render dependency. It would add a public symbol to the signed API and put rendering back on the viewport dependency path. |

## Questions for the advisor

1. **Snapshot length and inverse column evidence.** Which requests should carry these facts? The header has neither a length-query tag nor a byte-to-column tag. The implementation uses a zero-byte `VP_WINDOW` at `UINT64_MAX` for length metadata and reads the source screen column from `VP_ROW.count`. `VP_COLUMN.point` supplies the documented destination byte. The signed declaration describes `count` only for logical rank/select. Layout and viewport need the same agreement before wiring the port.
2. **Physical Home dispatch.** S1 says Home uses the active visual row in both modes. S2 and E4 also require a physical-line Home and the signed action enum has one Home. The implementation uses physical smart Home in clip and visual smart Home in wrap, following the pin's mode distinction. Clip resolves the hard start through rank/select and reads its first display row for the nonblank position. Should a separate intent select the physical behavior on folded clip lines?
3. **Reflow width and wrap transitions.** The frame gives new metrics and the intent carries one wrap value. Reflow clears the preferred column. Acceptance detects a wrap transition against the installed state and clears the preference and horizontal origin, and wrapped motion plans use zero horizontal origin. Should the placement owner supply old width or explicitly distinguish a height-only reflow?
4. **Saturation and a clamped page.** A neighbor certifies the resulting row but does not say how many rows it crossed. The cursor retains Q8 modulus for placement, except that a negative scroll from known BOF sets it to zero. If a vertical displacement ends on the same row, the caret moves to the document edge. A page clamped at a different row still uses the preferred column on that row. Should the port report the exact displacement to distinguish reaching a bound from overshooting it?
5. **Follow and final placement.** Where should the requested margin and final remainder travel? The frame has no margin field and the layout geometry has one. Viewport passes Follow's committed selection, affinity and rebased origin through. Layout owns margin, minimum reveal, EOF backfill and final saturation. A neighbor probe supplies a candidate top for zoom and relative scroll. The frame's overscan is the partial row intersecting the clip.
6. **Joined-cluster snapping.** The signed rebase function has only byte coordinates and gravity. It transports offsets. The owner with current text evidence must snap joined clusters when applying the edit or resolving that result. Which integration call should own this step for a rebased top?
7. **Staging ownership.** S4 describes two retained staging sets for placement. The opaque motion cursor contains one source and reverse-summary set with a bounded resident window. Its lifetime is independent of placement scratch in this implementation. Can layout reuse its own staging allocation across the motion and placement phases under the signed opaque-cursor API?
