# P4.2 — standalone indentation and visible whitespace

## Dependency change

The coordinator dropped this bead's dependency on the editor loop (edit-zzj.3)
and tabs, following the consultant's standalone-module decision. Editor-loop
integration and layout painting are deferred to follow-up beads. This change
adds only the indent module, its test/bench/fuzzer, and its decision/status docs.
It uses the frozen piece API already on main and does not edit other modules.

## Public contract and choices

`src/indent/indent.h` defines synchronous pure queries, caller-owned outputs,
explicit error codes and byte offsets. There is no persistent state, hidden
global, allocator, initialization or finalization. All functions allocate
nothing. Mutable tree queries belong to its owning UI thread; immutable
snapshot detection can run on a worker. Input and output storage must not alias.

Enter copies exactly the current line's leading spaces and tabs preceding the
cursor, including mixed indentation. There is no optional extra level after
`{`, `(`, `[` or `:`. When Enter splits indentation, only the whitespace before
the cursor is copied. A line ending is taken from the current line's terminating
LF/CRLF; at unterminated EOF it is taken from the preceding line, otherwise LF.
A cursor between CR and LF is rejected. An empty final line after a newline
copies no indentation. Capacity errors report the full required length and do
not write a partial insertion. Caller buffers are never grown internally.

Brace handling is computed **before** typing `}`. The returned edit replaces
`[lo,hi)` with the single byte `}`. On a line consisting entirely of spaces and
tabs (excluding its CRLF terminator), it removes indentation before the cursor
back to the preceding visual stop at the supplied width. A partial stop is
removed to the previous stop; tabs advance to the next stop. The width accepts
values from one through sixteen; stored bytes, rather than the advisory
`uses_tabs` flag, determine dedent. Whitespace after the cursor is preserved.
A nonblank line receives a plain insertion without dedent. No language parser
or search for an opening brace is involved.

Bracket matching chooses the bracket at the cursor, then the immediately
preceding byte if needed, provided that source is visible. It balances that
bracket's own type, in either direction, and returns only a visible mate.
Quotes, comments and other bracket types are ordinary bytes. This deliberately
permits lexical false positives; syntax-aware matching is a future enhancement.
The input window is half-open, and even source probing stays inside it.
UTF-8 bytes require no decoding because all supported brackets are ASCII.

Trailing whitespace means spaces and tabs before a visible newline or EOF.
CR in a CRLF terminator is excluded; lone CR is ordinary content. Range starts
are clipped to the window. A run at a cropped right edge is omitted until a
newline or actual EOF can establish that it is trailing. Passing a window
through complete visible line endings avoids that omission. Results are
ascending, with the required count and the first `cap` ranges returned even
on a capacity error. The layout worker will paint these ranges later.

Detection reads at most the first 64 KiB. Complete nonblank indented lines
vote tabs when any leading tab exists, otherwise spaces; ties select spaces.
Space-only indentation widths have their greatest common divisor taken as
the width, falling back to four when evidence is absent or exceeds sixteen.
Tabs have no intrinsic measurable display width, so a tab-only file defaults
to four. Blank lines do not vote. A prefix-cut final line does not vote.
This is a deterministic heuristic, not a language-specific style inference;
for example a space continuation can reduce the inferred width to one.
The bytes API applies the same prefix cap as the snapshot API.

## Work bounds and ownership

Forward reads use zero-copy piece iterators, clipping spans before examining
bytes. Reverse reads copy fixed stack blocks through `piece_read`. There are
no line-count or byte-to-line queries: those can trigger lazy indexing of
mapped files. Bracket and trailing-whitespace scans touch only their supplied
window; detection touches only its bounded prefix. Enter and brace handling
inspect the current line (and its immediately preceding terminator), so very
long single lines can cost more than ordinary source-code lines. Their output
storage comes from the caller, reserved outside the typing path if necessary.

## Integration contract

All steps below that operate on the mutable tree run on its owning UI thread.
The loop must check return codes before mutating the tree or publishing results.

1. On open, take a piece snapshot on the UI thread, call
   `indent_detect(snapshot, &style)` synchronously on that thread or on a worker,
   then release the snapshot after the call. Retain it until worker completion
   if handed off. Store the returned style in caller-owned per-buffer state;
   discard a worker result if its buffer/generation is no longer current.
   `indent_detect_bytes(prefix, length, &style)` is an alternative when file
   loading already supplies bytes. A configured user style may override detection.
2. On Enter, after resolving the selection to the intended pre-insertion tree
   and cursor, call `indent_on_enter(tree, cursor, bytes, cap, &length)`. On OK,
   insert exactly these bytes once with the loop's existing undo insertion path,
   and advance the cursor by `length`. Selection deletion and insertion belong
   to the same group. On CAPACITY, use already-reserved larger caller storage or
   reject/defer the command explicitly; do not truncate the bytes or allocate
   on the typing path. The module stores nothing between a size query and retry.
3. On a `}` text event, call `indent_on_close_brace(tree, cursor, style, &edit)`
   **before any brace insertion**. Begin one explicit `undo_group_begin`, call
   `undo_delete(log, edit.lo, edit.hi-edit.lo, UNDO_DELETE, ...)` when nonempty,
   then `undo_insert(log, edit.lo, edit.bytes, edit.length, ...)`, and finish
   with `undo_group_end`. Do not also insert the original key byte. The resulting
   cursor is `edit.lo + edit.length`; the suffix remains in place. Integrate
   selection removal into that same group before computing this edit. Undo's
   existing API guarantees individual operations rather than a transaction;
   the loop must handle any successful prefix on a mutation error and close
   its group appropriately. Indent queries themselves make no mutations.
4. After text/cursor/scroll/viewport changes, call
   `indent_bracket_match(tree, cursor, viewport_lo, viewport_hi, &mate)` before
   composing the frame. Select the source using the documented at-cursor then
   preceding-byte rule. Highlight source and mate only when mate is not
   `INDENT_NONE`. Invalidate both highlights on any text or viewport change;
   returned offsets apply only to the queried tree version.
5. During visible-line preparation, call
   `indent_trailing_ws_ranges(tree, viewport_lo, viewport_hi, ranges, cap, &count)`
   using caller-owned frame storage. Convert the returned byte intervals to
   cell decorations in the follow-up layout integration. If CAPACITY is returned,
   the first `cap` ranges are valid and `count` gives the required capacity.
   Keep newline bytes within the query window when complete trailing runs are
   desired. Never retain raw iterator pointers across a mutation (none are exposed).

The module has no callbacks, thread creation, publication, locks, undo state
or lifecycle calls. The editor loop owns per-buffer style, insertion scratch,
frame ranges, error handling, generation checks and undo grouping.

## Verification

The unit suite was written first and run against error-returning stubs; its
first Enter assertion failed. The implemented suite then passed in release
with the allocation guard active. Tests cover empty input, EOF, CRLF, mixed
indentation, UTF-8 byte positions, fragmented pieces, output exhaustion and
cross-block scans. Protected-page fixtures prove that viewport reads do not
reach adjacent inaccessible file regions and that detection does not read
beyond the prefix, both for raw bytes and an unindexed mapped snapshot.

The fuzzer compares Enter, brace edits, bracket matches and trailing ranges
with independent byte-buffer oracles, and compares snapshot/bytes detection.
It varies raw/structured bytes, cursors, viewport edges and piece boundaries.
The release benchmark uses a source-code viewport with three hundred rows,
varies Enter positions and forward/backward bracket sources, and checks its
allocation guard. Detection benchmarks the existing mapped log_1g.txt snapshot,
with setup outside the timing samples and all scans restricted to the prefix.
The gates are p99 <= 20 us (G) for each typing query and p99 <= 1 ms (G) for
detection. Shared-machine measurements are TRACK; coordinator quiet-box runs
own gate verdicts. Run evidence is recorded in `src/indent/STATUS.md`.
