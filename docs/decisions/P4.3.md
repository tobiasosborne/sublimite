# P4.3 — Sublime Linux key data

This bead defines command intent only. It does not execute commands, mutate
views, interpret grammars, or implement config overrides.

## Reference and scope

The reference is the first-party installed package
`/opt/sublime_text/Packages/Default.sublime-package`, member
`Default (Linux).sublime-keymap`, from build 4200 (2025-05-21). The member's
SHA-256 is
`442461ff5e28fb888658c1f75db31cc30bcc46f731db5016277fea02546657ef`.
Pinning the reference makes future updates deliberate. Upstream release
history is at <https://www.sublimetext.com/download>.

The table includes every unconditional normal-editor default, with later
duplicate bindings winning, plus the ordinary-editor Ctrl+Enter/keypad-enter
add-line macros and the default `shift_tab_unindent=true` Shift+Tab override.
All Linux keys, including dedicated Open/Save/Close/Cut/Copy/Paste/Undo/Redo/
Find keys, are represented. Commands without a complete `view.h` operation
remain data with `KEYS_ARG_UNIMPLEMENTED`. This includes editing commands,
multiple cursors, and the reference's file/window/search/layout/build commands.
No unavailable command falls through to text insertion on a match.

The event-only interface cannot decide Sublime's conditional panel, overlay,
completion, snippet-field, selection-dependent Tab, tab-multiselect, or
grammar overrides. Those contexts are deferred; the table specifies the
normal editor fallback for their keys. In particular, Escape's normal action
is cancel, Ctrl+D is add-next-occurrence (not merely select-word), and Tab
inserts a tab. Grammar-dependent tag/auto-pair/auto-indent behavior does not
take over punctuation or Enter. The comment-toggle action records line vs
block intent without embedding any grammar logic. A future context resolver
will be needed before implementing those Sublime overrides.

The installed defaults use Ctrl+Shift+J for join-lines and Ctrl+J as a chord
prefix. Ctrl+J, Ctrl+J identifies Sublime's `primary_j_changed` notice; it is
kept as an unavailable action rather than silently substituting an older
keymap. Alt+Shift+Up/Down select adjacent lines with multiple cursors and are
recorded as column-selection intent with direction. Ctrl+Alt+Up/Down are not
invented Linux bindings. Mouse column selection belongs to pointer handling.

## Representation and lookup

`keys.h` exposes action IDs, compact scalar arguments, and a caller-owned
chord byte. `keys_defaults()` exposes a private const array with process
lifetime. Each row is exactly modifiers, keysym, action, args; args include
the chord namespace and explicit unimplemented flag. No mutable module
globals, initialization work, sorting, allocator, or X connection is needed.

Rows are strictly sorted by `(args.chord, modifiers, keysym)`. Lookup uses
binary search with exclusive upper bounds and overflow-safe midpoint
calculation: O(log n), constant space, zero allocation. There are separate
root, Ctrl+K, and Ctrl+J namespaces. Prefix rows return `KEYS_PREFIX` and the
next namespace in `args.value`; ordinary rows return `KEYS_MATCH` with a
pointer to const data.

A chord lasts until its next non-modifier press. A missing continuation or
Escape consumes and cancels it without replaying a standalone command.
Ctrl+K, Ctrl+K is a completion, not a restarted prefix. Bare modifier presses
preserve pending state. The caller ignores releases and resets on focus,
keymap, or active-view changes (and may impose a timeout). An invalid chord
byte is reset before searching; it is never used as an array index. Invalid
API pointers produce `KEYS_ERR_ARG`; otherwise output is cleared on no match.

Caps/Num lock bits are ignored; extra unknown bits, AltGr, and unexpected
Ctrl/Alt/Super combinations do not alias ordinary shortcuts. ASCII letters
fold to lowercase for Caps/Shift. ISO_Left_Tab and nonnumeric keypad
navigation normalize explicitly, while keypad Enter remains a distinct
binding and NumLock digits remain printable. US shifted shortcut punctuation
normalizes to its named base (e.g. Ctrl+Shift+`?` to block-comment), retaining
Shift. Ctrl+Shift+`+` matches the reference's literal Ctrl+`+` font increase.
Unshifted punctuation and unrelated Unicode keysyms do not transliterate.

## Execution boundary and future proposals

No changes to `view.h` or `input.h` are needed for this data API. Actions
without the unimplemented flag correspond to the existing view keys:
LEFT/RIGHT/UP/DOWN, WORD_LEFT/WORD_RIGHT, PAGE_UP/PAGE_DOWN, HOME/END,
DOC_HOME/DOC_END, SELECT_ALL/SELECT_LINE, BACKSPACE/DELETE,
WORD_BACKSPACE/WORD_DELETE. `KEYS_ARG_EXTEND` supplies view_command's shift
argument. INSERT corresponds to VIEW_TYPE with the ASCII byte in args.value
(tab or newline). The editor owns this dispatch; this module executes none
of it. Prefix actions are handled within the lookup.

Proposals for later beads:

- Add command executors for flagged IDs, including select-next-occurrence,
  subwords, line operations, case, comments, undo, and clipboard dispatch.
- Add context input/resolution for Sublime's conditional overrides when their
  corresponding features exist; do not guess contexts from modifier bits.
- For layout-independent shifted punctuation shortcuts, extend platform input
  with the key's unshifted XKB symbol (or a physical binding token). Current
  `plat_event.keysym` has modifiers applied, so the module can only provide
  explicit US punctuation normalization, not recover arbitrary layouts.
- P6.4 config overrides should use a caller-owned immutable sorted table or
  equivalent bounded lookup. This bead does not reserve mutable global state
  or allocate override storage.

## Verification and performance

`tests/keys_test.c` independently transcribes the reference's semantics in
source/command order. It never derives expected rows from the implementation.
Each expected binding is looked up, including its prefix when present, and
checked for action, flags, and value. Reverse coverage requires exactly one
expectation per table row; strict sort checks catch duplicate/ambiguous keys.
Every row also runs with uppercase ASCII and both lock bits. Additional cases
exercise normalization, chord cancellation, isolation, corrupt state, invalid
arguments, and the counting allocator guard in the release configuration.

`bench/keys_bench.c` times individual lookups over a mixed stream of
1,000,000 events (G fixture size), retaining one sample per event, including
both successful and failed chord paths. Stream generation is outside the
timed interval; clock overhead is included and never subtracted. Power and
one-minute load are captured before timing. The gate is p99 <= 1 us (G),
derived as a small share of G1's 1.0 ms (G) typing budget; no tighter gate is
imposed. Allocation count must also be zero (G). Shared-box results are TRACK
only; the coordinator supplies quiet-box gate verdicts.

`fuzz/keys_fuzz.c` accepts arbitrary seven-byte event packets, mixes random
symbols/masks with known bindings and chord sequences, injects corrupt chord
bytes, and compares canonical lookup/state transitions with an independent
linear reference. ASan/UBSan check bounds and lifetime errors. It does not
touch or regenerate `/tmp/edit-corpus`.

The Makefile's `src/*/*.c`, test, benchmark, and fuzz globs automatically pick
up all new files. XKB constants need headers only; existing x11 link flags
already link the test's XKB name parser. No Makefile or LDLIBS change is needed.
