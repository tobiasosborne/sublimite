# v2-jj1 · Common render service and null backend

Implements R-A and R-B from the [signed Wave 2 render contract](wave2-render-spec.md) and A30 in [the plan amendments](wave0-plan-amendments.md). The font directory and layout publication are UI-owned. Render receives them through the public adapters. The null driver receives the same immutable packet the native driver SPI will use.

## Invariants and counterexamples

| Mechanism | Invariant | Simpler alternative and counterexample |
|---|---|---|
| Admission and arena | The binding fits both common storage and driver caps. Products use the actual target pitch, visible cells plus the optional extra row, and the largest double-cell tile. Open pays for both copies and touches reserved storage. Failed open restores the entry mark. A failed bind preserves the last viable binding. | Size backing from the visible grid. A fractional client margin increases native pitch beyond the grid allocation, and the final Q8 successor can live in the extra row. |
| One-call prep | The run directory is checked before any row reads. Accepted ancestry and the current READY paint stamp qualify inherited rows. Prep checks and copies each supplied cell, RGB element and selected tight R8 byte. Seal rechecks the saved stamp and epoch before constant-time release/acquire handoff. | Borrow the producer payload and let the backend validate it. A slot reassignment or fixed RGB repaint between acceptance and consumption changes bytes under the accepted identity. Full-grid validation would also touch unrelated rows on ordinary typing. |
| Delivery FIFO | A slot has one node. Its ordinal belongs to the current epoch, and it owes delivery when that ordinal exceeds the accepted watermark. Reassignment updates an owed node in place. Eviction unlinks it. Successful acceptance advances the head and watermark for the whole prefix. | Mark a slot sent when its bytes are copied. If the final paint check rejects the offer, a later accepted frame can keep naming an image the backend never received. Unlinking a whole prefix one node at a time would put additional work in commit. |
| Retained scene and atlas | The backend applies every tile delta and all cell patches before drawing. A cell samples only its installed slot and expected version. Padding outside sampled extents is transparent. For a nonempty tile batch, packet tags drive one traversal of the retained source cells, including old-version users. Tile-free packets skip that traversal. | Sample by slot and trust depth one. The new cell can be accepted while its replacement tile is still behind the grant. A slot-only test shows the old ink. Redrawing only new-version references leaves old-version users with stale coverage after the slot is overwritten. |
| Damage and footprints | Full-width runs preserve adjacent wide pairs. The current clip and optional extra row define the Q8 source transform. Region moves and removal cover the prior extent, and changed text transforms cover both clips. The null oracle records ink, cell attributes and physical damage independently. | Damage only the new overlay rectangle, or map the final fractional scanline through the next visible grid row. A moved overlay leaves stale pixels, or fixed chrome contaminates the last text row. |
| Depth-one retirement | An accepted epoch/frame owns packet storage until the independent device and presentation axes are terminal and the physical lease is released. Early evidence is private until ISSUED. Discard is terminal with no display time. | Free on a fence or any display result. A matched display may arrive while a worker still uses the packet. A fence can also arrive ahead of a discarded present, with no valid T6. |
| Loss and replay | LOST blocks admission and begins quiescence. Old notices cannot retire a newer flight. Quiescence clears credits. A successful fresh bind installs its sheet, requires a full packet and replays at most the granted number of current runtime identities per idle pump. | Preserve delivery credit across restart. A partially applied packet can credit ink the new backend never installed. Restart without epoch authentication lets a late event release a different frame with the same frame number. |

## Questions for the advisor

1. **Live directory.** Should `render_image_changed` take the current identity/state directly, or should setup provide a generation-qualified reader as implemented? The signed notification has only generation and slot. The setup reader supports immediate O(1) eviction and version replacement, and also supports recovery. The call-scoped offer adapter uses the same font directory.
2. **Recovery entry point.** Should bounded rescan be stepped by the caller through a typed PUMP, as implemented, or should a different existing slot schedule it? The pump uses a positive setup grant and allows a full submission while replay remains outstanding. A dormant or vacant slot takes one inspection and zero R8 work.
3. **Binding and font activation.** Should successful `render_bind` adopt IDLE_FULL immediately, as the lifecycle table specifies, or does font's scale transaction need a second viable render binding through first-full acceptance? The service commits a ready bind. A failed first submit preserves the accepted base of that new binding. Keeping the old logical binding through first acceptance would require overlapping ownership.
4. **Source span and palette.** Should current-identity metadata also carry span and the ASCII slot inventory? The signed IDs contain only slot/version. The implementation validates a tile's declared span and both marker entries, and clips coverage to each cell footprint. It relies on the producer to supply the matching current identity and populate its ASCII sheet.
5. **First candidate exceeding the remaining grant.** Should invalid tile metadata refuse even if the tile would otherwise exceed the remaining bytes? The implementation validates the first inspected candidate before trusting its tight extent and stops on the first valid candidate that will not fit.
6. **Real trace correlation.** Should EDTRACE pair on `{epoch,frame}`, or should native integration assign an independent trace identity? `trace_record_at` currently stores only a `uint32_t` frame. Common stats and notices carry the full identity. Null evidence is labeled synthetic and bypasses real traces.
7. **Native evidence and setup types.** Is `RENDER_NOTICE_RELEASED` the desired way to route a separate physical work proof, and should `plat_native.h` expose `struct plat_native` as the borrowed setup type? The platform directory is empty in this checkout. The SPI treats release as an explicit lease outcome and takes an opaque native pointer pending platform integration.
