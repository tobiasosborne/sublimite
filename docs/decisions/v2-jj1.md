# v2-jj1 · Common render service and null backend

Round 2 implements RV-1 through RV-5, Q4 and Q5 from the [signed render contract](wave2-render-spec.md), A30 from the [plan amendments](wave0-plan-amendments.md), and the [Astra review](../reviews/wave2-render-astra.md). The header comments describe the UI and owner interfaces. Native owner and font/layout integration remain separate.

| Mechanism | Invariant | Simpler alternative and counterexample |
|---|---|---|
| Admission | The binding fits common and driver caps for actual target pitch, visible cells plus overscan, and a maximum double-cell tile. Open prepays writable storage and both wakes have owners. A terminal open error restores the arena mark. | Size from visible cells or accept a missing UI wake. Native pitch can exceed the grid allocation, and a WAIT can leave the UI asleep indefinitely. |
| One-call validation | A single live stamp authenticates a non-reentrant immutable source. Every release cell is copied with structural, slot-range and whole-wide-pair checks. Sanitizer and explicit identity-assert builds also consult the live image directory. | Query the runtime directory on every release cell. A full grid repeating one image spends one indirect metadata lookup per cell. An in-range stale identity still contributes zero ink when the backend's installed version differs. |
| Candidate binding | Bind validates and copies the ASCII sheet and both settled markers, prepares a candidate FIFO, and leaves active ancestry, backdrop and credit untouched. A first accepted full packet selects the candidate and lets the owner bind it. | Switch the backend and accepted stamp at bind. An offer refused on a stale paint serial then leaves a new atlas paired with the previous displayed cells and hits. |
| Queue and replay | Each active or staged bank has one node per runtime slot. Pending membership uses the bank's epoch and accepted watermark. Replacements keep place. After all fallible prep, an input-free acceptance credits its copied prefix and scans up to its directory grant to queue subsequent delivery. | Spend credit when each tile copies. A malformed second tile could cancel the whole attempt after the first tile's obligation had been spent. Mutating the replay cursor before successful prep similarly changes future FIFO order on refusal. |
| Byte admission | Read a head's dimensions and span to price the whole tight tile. A valid head beyond the remaining bytes stays owed. Validate the page, identity and addressing when the tile fits. | Check page backing before budget. A head with legal extents and unreadable backing could forbid delivery of an earlier valid prefix even when the head cannot enter that packet. |
| Owner handoff | Commit release-publishes the immutable packet and signals a dedicated owner wake. Only the presentation owner takes the slot, binds the new sheet, consumes and polls. A packet keeps storage through driver quiescence. | Drive consume or poll from a UI event. Native issue, driver allocation and waiting would then happen on the UI thread. |
| Retained scene | The common owner-side implementation installs images, applies patches, marks source rows and expands output damage. A driver supplies the actual atlas writer. A positive tile count scans the complete retained source once, including references to older versions. Test observers sample this real scene on demand. | Give each backend a different patch/damage implementation, or redraw only current-version users. A newly installed glyph would leave old-version ink on screen, and an off-by-one Q8 overscan row could sample fixed chrome. |
| Evidence and retirement | One recorder accepts independently typed device and presentation evidence and publishes early outcomes only at issue. Both terminal axes initiate physical retirement. Only the driver's quiesce/close return can authorize reuse. Frame numbers never repeat during the service lifetime. | Treat a mailbox result as physical finish or reset frame numbers at rebind. A parked worker may still reference the packet, and EDTRACE can pair the wrong display across epochs. |
| Loss | Explicit epoch loss is authenticated with frame zero and is valid even while idle. Per-flight loss must match a live frame. Both disable admission until quiescence and invalidate credits. A fresh full picture and capped current directory replay restore residency. | Treat a late loss message for any retired frame as a disconnect, or ignore every loss without a live flight. The former discards a healthy epoch and the latter can accept a patch onto a disconnected device. |

## Interface choices in Round 2

- The owner receives the port during driver open. A native implementation can retain a packet through owner-side MORE/WAIT and report results via the work mailbox. The UI retries opening with the handle, front-door admission while retiring, bind after epoch loss, or close after the corresponding wake. Quiesce distinguishes retiring a packet from stopping a native epoch.
- Recovery is appended at the successful commit of an input-free offer. The same offer can deliver an already-owed prefix. Newly discovered tiles can ship in the next repair. This keeps failed offers from advancing the recovery cursor and keeps input-bearing offers free of replay work.
- The staged sheet owns one checked set of tight views and texels. The retained scene keeps installed identity metadata and delegates atlas writes. Null uses RAM and native drivers can write device storage without a second runtime R8 copy. On successful full adoption the UI publishes the new identity and exact hit association together.
- Debug current-image checks use the authoritative offer adapter for both sheet and runtime entries. Pending work and reject telemetry carry no authority over the accepted scene or input stamp.
