# P1.3 piece tree spec (edit-4w1.3)

Frozen: `src/piece/piece.h`, `tests/piece_model.h`, `tests/piece_test.c`, `fuzz/piece_fuzz.c`. Reference stub (flat array, O(n), snapshot = O(pieces) copy): `variants/P1.3/stub/piece_stub.c`.

## API choices
- Opaque `piece_tree` (UI-thread owned) and `piece_snapshot` (immutable, any thread, outlives the tree). Constructor takes a `piece_allocator` (alloc / sized free / ctx); all memory goes through it (law 2). `piece_default_allocator()` wraps malloc for tests only.
- Two init modes: `piece_init_copy` and `piece_init_mapped` with `piece_map_hooks` (acquire per owner: tree and each snapshot; release when it dies).
- Lines are '\n'-delimited; '\r' is an ordinary byte, so CRLF and LF count identically; empty buffer = 1 line. `line_to_byte(line >= count)` = len; `byte_to_line` clamps.
- `piece_delete` copies deleted ORIGINAL bytes into the add buffer (mapping independence, HANDOFF 3.7). Undo is caller-side inverse ops: `piece_read` before delete, re-insert later. (Superseded by P1.3b below: a ref handle is now exposed.)
- Errors are return codes (`PIECE_ERR_RANGE`, `PIECE_ERR_NOMEM`); failed ops leave content unchanged.
- Iterator is zero-copy; spans valid until next tree mutation (tree) or snapshot release (snapshot). Span boundaries are unspecified (need not be merged).
- `piece_piece_count` is exposed so the suite can check the G10f formula
  `peak <= 1.25*S + 64 KiB + 96*pieces + 1.25*(typed+deleted) + 4 KiB` (mapped: `<= 32 B * ceil(S/64KiB) + 2 MB`).

## Free to vary in P1.4
Node layout (B+ tree 384 B SoA recommended in perf 2.6, or other), pooling strategy, add-buffer chunking, lazy newline counts, how snapshots share structure (must be O(1)-ish and thread-safe for read/retain/release), span granularity from the iterator, internal fixed costs within the 4 KiB slack.
Not free: any signature or semantic in `piece.h`, the test suite, the model.

## Build and run (any implementation file)
```
FLAGS="-std=c11 -Wall -Wextra -Werror -Wshadow -Wconversion -D_GNU_SOURCE -pthread -fsanitize=address,undefined -O1 -g"
clang $FLAGS -Isrc -Itests tests/piece_test.c <impl.c> -o /tmp/piece_test && /tmp/piece_test
clang [--gcc-install-dir=/usr/lib/gcc/x86_64-linux-gnu/13 if -lstdc++ is missing] -std=c11 -D_GNU_SOURCE -fsanitize=fuzzer,address,undefined -O1 -g -Isrc -Itests fuzz/piece_fuzz.c <impl.c> -o /tmp/piece_fuzz && /tmp/piece_fuzz -max_total_time=60
```
The stub takes ~70 s under ASan on the 10^5-op test (1 MiB flat model dominates); a real implementation is dominated by the model too.

## P1.3b amendments (edit-4w1.13)
- **Append coalescing is mandatory.** An insert whose bytes follow the previous insert's bytes in the add buffer and whose offset equals that insert's end extends the existing piece. Any other mutation breaks the run. Test: 10 000 single-byte inserts at the cursor give <= 2 pieces. Rationale: without it, typing costs one piece (~72 B) per keystroke and breaks G10f at scale.
- **Reinsert by reference.** `piece_delete(t, off, len, piece_ref *ref)` (ref may be NULL) reports where the deleted bytes live in the add buffer as up to `PIECE_REF_SPANS` (8) `(add_off, len)` spans. Original bytes are copied there at delete time (as before); add bytes already live there. If more spans would be needed, the whole range is copied once into a single span, so a ref is always complete. `piece_insert_ref(t, off, ref)` creates pieces over those bytes with no copy. Undo/redo can therefore avoid storing the text; the add buffer is append-only so refs stay valid for the tree's lifetime. G10f accounting is unchanged (a delete appends at most `len` bytes). The overflow path needs a transient `len`-byte allocation through the allocator hooks.
- **Allocator backing.** `piece_allocator` hooks should be backed by `src/base` `edit_pool` / `edit_arena`.
- Tests: `t_coalesce`, `t_ref` in `tests/piece_test.c`; fuzz op 5 (delete+insert_ref) in `fuzz/piece_fuzz.c`.
