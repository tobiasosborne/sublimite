# W0.6a contract process containment

`Sandbox(base, RunTarget(role, executable, build_dir, sha256), display=...)` owns one case on Linux. The run manifest provides the trusted absolute build directory and executable, the SHA-256 digest, and the namespace role (`v1` or `v2`). The runner checks the selected file and digest at each launch and retains an fd to its original inode. Linux procfs lets the subprocess execute the pinned file without inheriting the fd. It also lets the parent dial the exact Unix socket inode it has verified. The implementation uses Python 3.11 or newer for the standard-library file hashing API.

The case owns its HOME, XDG directories, TMPDIR, cwd, fixtures, Xauthority, and fontconfig configuration. Its allowlist supplies a fixed UTF-8 locale and a standalone fontconfig file using system fonts and the private XDG cache. The X driver supplies a verified positive local display and may populate the private Xauthority file. Headless launches require an absent ambient DISPLAY. Primary and restart can pass explicit inspection fds. The relay inherits only its standard streams.

The case reopens the directory chain using no-follow directory opens and verifies the identities of the root and its original profile directories. It rejects symlinks throughout the case, as well as hardlinked regular files, foreign ownership and unexpected special files. Default profile and runtime locations are computed from the original environment without resolving them on disk. Cleanup reaps the case's children and removes entries using directory fds rooted in the verified tree.

For a named primary, call `start()` and then `record_server()` after a causal readiness signal. Recording verifies the filesystem socket and lock, checks the listening peer's UID and PID, and retains an fd to each inode. `connect()` and `relay()` verify the record before handoff. The editor retains responsibility for reclaiming its stale socket. The sandbox permits that launch after a reaped SIGKILL only when both recorded inodes remain in place and the socket refuses the connection. An orderly zero exit may restart with its recorded lock and no socket. Call `record_server()` again after the restarted primary is ready.

The case assumes a trusted, cooperative test binary and a driver that owns the selected display. Editor and display integration use the same case settings. X server creation, display ownership verification and inspector protocol handling belong to their respective workers.

`make check-contract-sandbox` runs the stub-only unittest suite. Its negative controls assert that invalid case paths and unrecorded endpoints fail before process launch or an IPC dial. The foreign-PID control dials a synthetic listener inside the case to verify rejection at the credential check.
