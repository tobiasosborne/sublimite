## §14 — journal preparation before acknowledgement

**Confirmed; proposal, no journal change.** The isolated untitled checkpoint
oracle observes preparation's UI directory barrier even without base retention.
Moving journal_save_prepare into a file job is unsafe: journal is UI-owned,
checkpoint payloads are borrowed, and flush/retain/rotate submit BULK jobs and
wait/drain them. Calling that protocol on the sole BULK worker deadlocks and
violates work_submit's UI-only contract. Returning early from prepare would
authorize replacement before recovery is durable and discard post-cutoff edits.

**Required amendment:** a joint caller/journal/file transaction must capture an
immutable complete-session checkpoint, saved piece snapshot and accepted cutoff
on UI, acknowledge enqueue, then retain/flush/rotate and replace on workers.
Appends after the cutoff need independent batches/generation bookkeeping and
must survive rotation, including other buffers and shared BASE/SAVE tokens.
File commit must depend on successful durable preparation. Editor caller changes
are outside this bead; a comment-only journal edit would not fix the stall.

## §15 — synchronous physical close

**Confirmed; proposal, existing safe close retained.** Queued save behind a
blocked job prevents return until that unrelated job is released. work_cancel
invalidates its epoch; worker_main skips cancelled queued callbacks entirely.
There is no cleanup/finalizer notification, and a saturated pool can refuse a
separate cleanup job. Shutdown also skips queued callbacks. Refcounting the
current callbacks alone would leak skipped jobs; freeing UI state immediately
would create use-after-free. A file-owned global retire list or extra threads
would violate the required architecture.

**Required work amendment:** accept an immutable job with a guaranteed finalizer
for completed, skipped-cancelled and shutdown-discarded jobs, reliable completion
ownership and terminal-delivery retirement. Then file_close can cancel all
publication, release UI ownership immediately, and let the last physical owner
destroy descriptors/mappings/snapshots off UI. Work is outside permitted edits.

## Fix-up — journal/file mailbox contract (edit-4w1.42)

**Cause.** The journal save fixture assumed that `file_open_begin` returned a
ready small file. P1.7d intentionally acknowledges enqueue only; even an empty
or small copy becomes ready through live mailbox receipt. The assertion returned
without `file_close`, leaking the file and its worker-owned prefix result (the
coordinator's LeakSanitizer stacks point at those allocations). Production
`src/journal` has no `file_open_begin` call. A second fixture assumption also
needed removal: `journal_flush` waits for journal durability, and may return
without decoding a file save's preparation/commit/completion messages.

**Choice.** Preserve asynchronous file open and its non-installing getters.
Update the caller to drive the pool on the UI thread, routing every live message
to `journal_receive` or `file_msg_decode`. Blocking fixture/startup callers must
wait for decoded OPEN_READY/OPEN_FAILED before attachment and independently wait
for decoded SAVE_DONE plus physical completion. Readiness polling alone does
not advance either pipeline. This contract does not depend on whether journal
append writes synchronously to the page cache or batches writes on a worker.

Every permitted journal-side change in this fix-up:

- `tests/journal_test.c`: expand `save_message`/`save_route` to observe prefix,
  open success/failure, SAVE_PREPARED, REPLACED and SAVE_DONE while always calling
  `file_msg_decode`, including for internal notifications.
- Add `save_drain` to deliver both journal and file messages. Add the bounded
  `save_open` mailbox wait; failure/timeout closes its file, nulls the returned
  pointer, then drains stale notifications through work's epoch filter.
- Add `save_wait` and use it after `journal_flush` in `save_test`, independently
  waiting for file completion. Assert receipt of the required open/save phases.
- Give `save_test` a common assertion-failure cleanup path: release the paused
  worker before closing the file, destroy live trees, close the journal before
  freeing its fault-I/O context, free other allocations, close any descriptor,
  discard stale mailbox entries, stop the pool, and unlink private fixtures.
  All resource owners are initialized before an assertion can take that path.
- Add `file_mailbox_test`, selectable as `--file-mailbox` and included in the
  normal suite. It covers copy, mmap, empty-file readiness, mixed journal/file
  delivery, independent save waits when the journal is already flushed,
  asynchronous open failure, and closing unread copy/mmap prefix results.
- `src/journal/STATUS.md`: document the composing caller's mailbox obligations
  and the focused regression command. No journal implementation/header changes.
- `src/file/STATUS.md`: record the resolved integration failure. No file
  implementation/header changes in this fix-up.

Ownership audit: `save_open` owns its file until successful receipt transfers
it to the fixture; failure/timeout closes and nulls it. Unread worker descriptors
and prefix bytes are reclaimed by `file_close` after cancellation/physical wait;
work drops cancelled messages before callbacks can dereference the old file.
Attached private/mapped bytes remain reference-counted by the tree until its
destruction. File close releases in-flight save snapshots/transaction resources.
Fixture cleanup releases the pause first, preventing a join on its own blocked
worker. Journal fault-I/O context and handler storage outlive journal close.
