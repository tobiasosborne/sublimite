## §1 — registry publication and reuse

Confirmed, fixed. A slot has FREE/RESERVED/LIVE/RETIRING phases and lock-free
reader pins in one atomic word. Acquire publication exposes immutable address,
length and page size together. A handler pins LIVE before reading metadata,
holds the pin through `MAP_FIXED`, and releases it afterward. Retirement blocks
new pins and waits for existing pins before unmap/reuse. The synthetic self-check
poisons reservation metadata and pauses a pinned recovery while another thread
retires/reuses the slot; adjacent foreign pages remain intact. It calls the real
recovery/mmap path off-signal, with no persistent test hooks.

## §2 — previous SIGBUS action

Confirmed, fixed. Classify SIG_IGN/SIG_DFL before interpreting the handler union.
Ignore preserves recovery; default explicitly raises SIGBUS on the same thread
after restoring SIG_DFL. Initialization queries the previous action before
installing recovery. Its mask, SA_NODEFER, SA_ONSTACK and SA_RESTART are retained
on the wrapper; an atomic one-shot state gives SA_RESETHAND semantics for foreign
signals without consuming it for registered recovery. Fresh exec children test
ignore, default, masked one-argument, three-argument, one-shot and nested
SA_NODEFER delivery, with a registered truncation between foreign deliveries.
The service owns the disposition after installation; concurrent/later foreign
sigaction replacement is not supported. Flag semantics follow the
[Linux sigaction contract](https://man7.org/linux/man-pages/man2/sigaction.2.html).

## §4 — late source invalidation

Confirmed, fixed. Each save captures the actual original inode identity, mapping
recovery epoch and UI source generation. The last pre-rename validation, under
the existing commit lock, checks all three and sticky changed state. Recovery
increments its epoch BEFORE anonymous zeros become visible. FORCE accepts the
state at acknowledgement, but cannot bless another fault/change after it.
The source inode is checked even after an earlier save retired it from the path.
Tests cover the exact old-fd/two-save/zero-fill repro, old-inode overwrite without
a UI check, a detected change followed by keep/metadata restoration, and another
fault on an already faulted forced-save generation. Temps are removed on refusal;
the target stays intact. Last-validation-to-rename remains the documented race.

## §5 — keep and cached newline counts

Confirmed; file-only containment implemented, full keep/rebase deferred. Keep
now returns FILE_ERR_CHANGED and preserves changed state for a modified/faulted
mapped backing, rather than accepting bytes with stale tree/snapshot metadata.
Changes to a separate pathname generation may still be accepted while the mapped
original is intact. The regression witnesses the cached counts in both tree and
snapshot, overwrites newlines in place, and requires refusal.

The frozen piece contract requires original bytes to remain immutable while any
owner is live. There is no operation in the pointed code/public contract to
invalidate all snapshot caches or atomically rebase a tree and its consumers.
**Proposal, not implemented:** review a transactional piece rebase/generation
API that rebuilds byte/newline metadata over independent validated backing while
preserving edits, and invalidates dependent snapshots/indexes before publishing
the replacement. Retained immutable snapshots also require an independent
backing generation *before* external mutation; simply recounting the current
tree cannot repair them. Alternatively, change file acquisition to independent
stable reflink/copy generations using existing piece hooks, after evaluating the
open/storage contract. The coordinator must settle that design with piece,
undo and index consumers. This bead does not amend their headers/modules. The
present UI resolution for compromised mapped backing is reload, as documented
in file.h.

## §9 — signal safety

Confirmed, fixed. Compute/validate a positive power-of-two page size during
initialization, copy it into immutable registration metadata, and verify every
handler atomic (state, fault epoch, previous-action reset) is lock-free off-path.
No sysconf/once/lock/allocation is reachable in production recovery. The wrapped
sysconf oracle compares call count immediately around an actual truncation fault.
Supported recovery is Linux with glibc's
[AS-Safe mmap](https://sourceware.org/glibc/manual/latest/html_node/Memory_002dmapped-I_002fO.html)
and lock-free atomics; mmap is not a general POSIX signal-safety guarantee. The
previous callback retains its own signal-safety responsibilities. Clang
ASan/UBSan recovery/chaining is exercised with leak detection disabled in this
sandbox; this is observed compatibility, not a guarantee for arbitrary sanitizer
interceptors/libcs. Other targets must validate these prerequisites or reject
mapped registration.

## §10 — mutable globals and proposed exception

Confirmed. Consolidated the four mutable globals into exactly one bounded
process SIGBUS service; the object-symbol self-check is
`python3 src/file/check_signal_globals.py build/rel/src/file/file.o`.
**Proposed binding exception (not an amendment to CLAUDE.md):** “The file module
may own one process-wide SIGBUS service containing only a fixed mapping registry
with lock-free reader pins/fault epochs, the previous signal action and its
one-shot state, cached page size, and one-time installation state. Mapping
metadata is immutable while published; retirement excludes handler readers
before unmap/reuse. All per-file state remains UI-owned and worker results cross
through work publication. No additional module globals are permitted.”

Justification: the process signal ABI supplies no object/context argument for
registered readers in other modules. Those readers and frozen contracts cannot
be changed in this bead. One statically initialized service is owned by file,
installed once on first registration, retained for process lifetime, and has no
per-file UI data/test hook globals. Installation is serialized by pthread_once;
registrations and retirement have explicit lifetimes (§1). The coordinator must
approve/adopt this narrow exception; the earlier P1.7 decision is not authority
to silently change the binding global rule.
