# P2.2f XI2 scroll decoding review fixes (bead edit-e6x.20, review docs/reviews/x11-1.md #16 #17 #20 #27)

All four findings confirmed; each has a red-then-green case in tests/x11_xi2_test.c (`test_e6x20`) and XI2 ops in fuzz/x11_input_fuzz.c. Red = old code, green = new (lines in docs/worker-reports/edit-e6x.20-s6.md).

Data model change (xi2.h): `xi2_dev` now holds up to `XI2_MAX_AXES` (4) `xi2_axis` entries {num, dir, preferred, inc, last, rem, last_ok} instead of one slot per direction. Nothing outside xi2.c touched the old fields.

## #16 first smooth-scroll delta discarded: confirmed
QueryDevice now also reads master ValuatorClass (type 2, current value at +28) and seeds `last`/`last_ok` of the matching scroll axis (same source and valuator number), independent of class order inside the reply. A rescan after XI_DeviceChanged therefore re-seeds. XI_DeviceChanged still clears history (the rescan reply is what re-seeds); events between the DeviceChanged and the reply prime as before. Not done: seeding from the classes carried inside the DeviceChanged event itself (x11.c would need to hand them over; the QueryDevice route already covers it).

## #17 fractional movement lost: confirmed
Per-axis remainder `rem` (units of 1/256 notch, kept within [-0.5, 0.5]): `u = delta/inc*256 + rem; iu = round(u); rem = u - iu`. Conserves under reversals; 1024 x 1/1024 gives exactly one notch. Reset on DeviceChanged.

## #20 malformed structures, partial commit: confirmed
- xi2_parse_query_device: padded name extent checked even with zero classes; parses into a scratch table and assigns `*x` only on success (on -1 the old table survives). ValuatorClass values are held in a 64-entry scratch array.
- xi2_decode: all valuator extents are validated and new values staged before any history is touched; a rejected event returns false with `*x` unchanged and `*r` zeroed. Commit is one pass afterward.
- Proposal for x11.c (not edited, owned by e6x.19/e6x.18): the caller of xi2_parse_query_device ignores a -1; on -1 it should keep the old table (now guaranteed intact) and may log/retry. No hook is required for correctness.

## #27 multiple scroll classes overwrite: confirmed
All scroll classes of a master are kept (up to 4 per device, extras ignored). Events carrying any one axis work. When several axes of one direction move in the same event, the axis flagged XIScrollFlagPreferred (flags bit 1) supplies the delta, otherwise the first moved axis in class order; all axes still advance their history so none double counts later. The no-emulation flag (bit 0) concerns legacy button emulation, which we do not consume (we read valuators directly), so it does not filter axes.
