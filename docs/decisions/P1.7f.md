## §29 — process visibility is not power-loss durability

**Verdict: valid; full fix deferred because it needs the forbidden `src/file` syscall seam.** A temporary LD_PRELOAD mutation returning success without doing either fsync still passed the original suite:
```text
LD_PRELOAD=/tmp/p17f/no_fsync.so build/tests/file_test
file_test: ok
MUTATION section=29 FAIL omitted fsync barriers survived process-kill tests
```
The new standalone kill test strengthens exact old-before/new-after-rename and temp-count assertions and labels them **live-kernel visibility**. Green visibility evidence, **not green durability evidence**:
```text
file_kill_test: PASS visibility/cancellation; power-loss barriers unverified
```
No barrier-order/durable-image fix is claimed. Existing `file_test.c` remains untouched so P1.7c can add its tests independently.

**Concrete proposal:** mirror `journal_io` with an instance-owned `file_io` pointer in `file_save_args` and optional per-file hooks, installed only while no job is active. Callbacks with POSIX return/errno semantics should cover temp open, write, fchmod, sync(ctx, fd, directory), renameat, unlinkat, and source pread; NULL entries use real syscalls. Context must outlive worker cleanup/messages, and operations must retain the same parent-directory descriptor. Use no globals. This requires changes to `src/file`, so it is a proposal only.

The seam's test records real successful data-sync → rename → parent-directory-sync → successful completion, independently of `FILE_STEP_*` labels. Its durable-image model commits temp bytes only on successful data sync and namespace only on the matching parent-directory sync. Before rename: old target. After rename/before directory sync: live new, durable old/new allowed. After directory sync: durable new required. Mutants omitting either barrier or moving data sync after rename must fail even when step labels remain. Compose every boundary with `journal_save_prepare` and replay of the retained base; add edits after the cutoff, then require `journal_save_finish`/replay to restore saved base + later edits. Include data/directory barrier failures, retain prepared recovery state on any failure, and reject finish before a successful durable file completion. These checks cannot be implemented faithfully by the existing step-only API.
