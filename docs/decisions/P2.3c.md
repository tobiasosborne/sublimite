# P2.3c (edit-e6x.10): bounded font loading, TTC index, fallback lifecycle

## Decision
stb_truetype is not patched; `font_init_index` validates before `stbtt_InitFont`:
TTC header (version, numFonts <= (len-12)/4, index < numFonts, face offset),
sfnt tag, directory (numTables*16 inside len), then cmap/head/hhea/hmtx/maxp and
glyf+loca (or CFF) records inside len (uint64 math). Scalars: numGlyphs>=1,
unitsPerEm>0, ascent>0, descent<=0 (so cell_h>0 and no unsigned wrap in
`font_set_px`), 1<=numberOfHMetrics<=numGlyphs, hmtx length covers lsb array,
loca format 0/1, loca length, loca monotonic and <= glyf length (one pass,
init only). Failure clears the whole `font_t`.
Per-lookup paths stb reads lazily are replaced or pre-validated:
- cmap: own bounded lookup (formats 0,4,6,12,13) replaces `stbtt_FindGlyphIndex`;
  glyph ids >= numGlyphs are "missing". Format 4 follows the spec (idDelta applied
  to indirect ids); the bake-consistency test confirms equality with stb for ASCII.
- glyph header (metrics): 10-byte header must fit the loca range.
- glyph outline (raster only): `shape_ok` walks end points (strictly increasing),
  instruction skip, flag run-lengths, x/y delta bytes, off-curve-last-point read,
  composites (XY form only, depth 6, 256 components per root) inside the glyph's
  loca range. Returns FONT_ERR_INIT. The P2.3d setjmp boundary covers allocation
  exhaustion only, not reads, so this validation is needed.
TTC: `font_init_index`, `font_t.face_index`; `font_fallback.{cjk,emoji}_index`
from FcPatternGetInteger("index"); values with the variation-instance bits set
(>0xffff) are rejected. CJK query lang changed "zh" -> "zh-cn" (fontconfig then
picks the SC face, index 2 here, instead of JP index 0).
#10: `font_fallback_reset` (clears done with release, results too) is called by
the owner before resubmitting; discover calls it first. Rule documented in font.h.
#5: malloc guard is inert under ASan, so the binding gate is
`font_raster_mallocs` in bench/font_bench.c (gcc release, guard active), exit
non-zero if != 0.

## Residual risk (not closed)
CFF/OTTO outlines (Noto CJK is CFF): table records and cmap are bounded, but stb's
CFF parser uses a 512 MB buffer limit (not len) and asserts; a corrupt CFF can still
read past len. Fuzzer seed is TrueType only. Needs a CFF validator or vendor patch
(follow-up bead). TT contour count in the stb vertex pass and kern/GPOS unused.

## Numbers
Raster e-acute 30 px p50: before 3.3-3.4 us (M)[AC] same box state, after 3.5-5.4 us
(M)[AC], box loaded by other workers, gate 50 us (G); shape_ok adds one pass over
the glyph's flag bytes. Zero mallocs over 20000 rasters (M).

## Fuzz finding: stb asserts
First 150 s fuzz run hit `stbtt__rasterize_sorted_edges` assertion (outline points
outside the header bbox; abort). stb's `STBTT_assert` is now routed to the P2.3d
error boundary (longjmp code 2 -> FONT_ERR_INIT) via a `_Thread_local` pointer set
only during `stbtt_MakeGlyphBitmap` (stb's macro carries no context): a deliberate
exception to "no globals". Alternative rejected: validating all coordinates against
the header bbox (composite transforms make this inexact). Reproducer kept in the
seed corpus run (regress-assert). Second run: 695758 execs, 641 s, 0 crashes.
