# P4.6 find/replace panel — edit-457.6

Standalone `src/findui/`, phase P4 M1. `findui.h` is the public interface.
The editor wiring bead owns integration; this bead changes no editor, main,
find, undo, layout, frozen header, or build-system file.

## Design

`findui_panel` is an opaque, UI-owned handle into caller-supplied `edit_arena`
storage. Initialization reserves query/replacement buffers, range caches and
worker program/scratch storage. Query edits, toggles, cursor movement, result
consumption, highlighting, replacement and painting allocate no libc memory.
The source is a retained immutable `piece_snapshot`; live tree bytes are never
read by findui on the calling/UI thread. UI loops inspect only query bytes,
render cells and bounded worker-produced ranges. There are no module globals.

Query, options, source revision and visible window identify a request. Changing
any search input cancels all old handles, advances a nonwrapping generation,
clears old ranges, and submits the latest request as `WORK_BULK`. Cancellation
invalidates existing mailbox publications through `work_cancel`, as well as
future UI consumption through generation filtering. Input does not wait for
physical completion. The G6c logical acknowledgement ends after invalidation,
cancellation and submit/coalescing; its gates are (G) p50/p99 1/5 ms. Workers
inherit the frozen find core's (G) 1024-unit cancellation polls; pattern
transformation also polls at that bound. Regex compilation itself has the
frozen bounded pattern/state limits but no cancellable compile API.

There are (G) two immutable job-input slots: one running and one queued/latest.
A queued predecessor can be cancelled and retired immediately. A running
predecessor retains its snapshot, query, program and scratch until the work
pool's physical completion is observed. If both argument slots or the shared
pool are unavailable, the latest request stays pending; `findui_service` retries.
Rapid edits coalesce without allocation or waiting. See the proposed work
accessor below for the one lifecycle observation that lacks a public helper.

The worker calls `find_literal_next` or `find_regex_next` from the chosen
P1.10 simd-filter-verify core. It publishes the first match immediately, then
small inline batches through `src/work` mailboxes. Batch payloads are (G) at
most 48 bytes, with an owner token, absolute ordinal and up to two ranges.
No worker writes panel state or UI range storage. Full mailboxes are retried
with a short sleep and cancellation poll; no matches or completion messages
are silently dropped. The owner must continue draining the pool. Physical
completion alone does not make the count exact: only the completion message
does. Before completion, the displayed count is a lower bound (`+`).

The first-match cache and visible-window cache together are bounded to (G)
64 KiB of ranges. The worker continues counting after the first cache fills
and still publishes matches intersecting a late visible window. Navigation
wraps using the exact total; an uncached ordinal starts a fresh worker request.
This is lazy fetching with a full worker rescan under the existing frozen API.
An updated window also starts a worker request, preserving the selected ordinal.
Rendering can therefore show late matches without retaining all earlier ones.
An overflowing visible cache is explicit (`visible_overflow`, `!`, and
`FINDUI_ERR_LIMIT`); it is never presented as a complete set. Hosts should size
that cache for their visible byte window and worst-case empty regex matches.

Default options are literal, case insensitive, whole word off. All matching
has byte semantics. Case-insensitive literals become escaped ERE-lite atoms;
ASCII letters become two-case classes. Regex case folding validates the
original expression with the core first, expands literal letters and class
membership, and then compiles the transformed expression on the worker.
Negated classes are complemented **after** case expansion. No document copy,
Unicode normalization or locale-dependent folding is involved. Case-insensitive
literal queries inherit the regex program/state/pattern representation limits;
a representational limit returns `FIND_ERR_LIMIT`. Original regex syntax errors
retain their original byte offset; a transformed-program limit points to query
end. Whole word means surrounding bytes are not ASCII letters, digits or `_`.
Rejected word candidates resume at start plus one, so an overlapping valid
candidate is not lost. Accepted matches use the core's nonoverlap/empty-match
advancement policy. An empty query disables matching in both modes.

Replacement bytes are literal, including in regex mode; capture substitutions
are outside this bead. Replace-one uses the selected worker-produced range.
Replace-all requires a completed, untruncated first-match cache. A capacity
error precedes any mutation or group opening. Both begin functions open one
explicit undo group and apply nothing. `findui_replace_step` walks right-to-left,
with caller-provided match/deadline budgets, and closes that one group at end.
Cancellation closes the applied prefix as the same undo group. Allocation faults
also close the successful prefix, including a possible delete whose subsequent
insert failed, and return `FINDUI_ERR_UNDO` plus the underlying error. Tests show
one undo restores the original bytes even in that case. The current undo API
cannot make a delete+insert or an entire replacement transaction failure atomic;
the proposed accessor/transaction API below records that limitation without
editing the in-flight undo module. Single piece operations are not interruptible.

After any successful replacement mutation, findui drops its bound source and
all results. The host must bind the resulting document snapshot/version before
search resumes. This prevents old offsets from being reused. A no-op empty
replacement of an empty regex match creates no undo history. No source byte
comparison is used to detect staleness: version correctness belongs to the host.

Panel painting fills and damages only its supplied bottom row range in a begun
`render_grid`. It resolves glyph identity from host-provided ASCII atlas slots,
uses existing cursor attributes, and never changes the atlas, dimensions,
backend, or rows outside that range. Query/replacement cursor positions are
byte offsets; control/non-ASCII bytes display as `\xHH`, with horizontal scrolling
to keep the focused cursor visible. Status shows toggles, selected ordinal,
count/lower bound, limits and pattern/undo errors. A closed panel paints blank
rows so the host can erase it. The renderer adds no new frozen attribute bits.

## Integration contract

1. **Lifetime and ownership.** Reserve an arena and initialize a zeroed panel
   with the editor's existing work pool. The arena, pool and optional hook context
   outlive successful disposal. The panel never initializes/shuts down that pool.
   Retain the original mapping through the piece snapshot/map hooks. Before
   resetting/reusing arena addresses, dispose, then drain stale work messages.
   Pool shutdown can precede final disposal: it joins cancelled jobs and leaves
   their slots observable. Do not reinitialize a pool while panels retain handles.
2. **Binding.** On panel open/tab switch/document mutation/undo/redo, obtain the
   active buffer's immutable snapshot and its monotonically changing version.
   Call `findui_set_source(panel, snapshot, revision)` and release the host's
   temporary snapshot owner. The same undo log must operate on the tree that
   produced this snapshot. Versions must change on equal-length mutations too.
   Suggested editor accessor: `editor_find_binding` returns a retained snapshot,
   document identity/version, active undo log, and guaranteed undo record limit.
   This is a proposal for the wiring bead, not a definition in a frozen header.
3. **Input.** Route query byte insert/delete to `findui_edit_query`, cursor moves
   to `findui_set_query_cursor`, and toggles to `findui_set_options`. Each query
   edit is accepted as `FINDUI_OK` even if submission is deferred. `searching`
   stays true. Query/source/toggle changes return `BUSY` during replacement;
   finish or explicitly cancel that group first. Replacement text/cursor and
   focus have their own setters. Closing the panel cancels its search.
4. **Mailbox dispatch.** Preserve the central dispatcher: call
   `findui_accept(panel, msg)` for the `FINDUI_MSG_*` kinds. It returns false for
   another panel/module and true for owned stale messages it intentionally drops.
   Do not give this module a private drain that consumes unrelated render/index
   results. After bounded drains and between input checks, call `findui_service`;
   `MORE` means retry after input/work activity. The normal pool eventfd wakes
   the editor for published matches and completion. Poll service while a request
   remains pending even if a cancelled queued job published no notification.
5. **Visible painting.** Ask layout for an absolute half-open byte window covering
   the text rows, including partially visible graphemes/wrapped rows, and call
   `findui_set_window` only when it changes. Suggested layout accessor:
   `layout_visible_byte_window` returns those bounds without scanning text.
   Request ranges using `findui_highlights` for that window or a subset. While
   `searching`, paint the available incremental ranges and invalidate text rows
   as batches arrive. On an input generation change, erase prior highlights.
   `visible_matches` includes overflowed matches; a limit response has no output
   writes. For an empty byte window, nonempty matches are excluded; empty matches
   are caret ranges, including the endpoint/EOF caret. Suggested layout overlay
   accessor: `layout_set_byte_overlays` accepts sorted byte ranges, a selected
   range and resolved match colors before cell construction. Apply match colors
   beneath selection/cursor colors; use the existing render attributes/colors.
   No `RENDER_ATTR_FIND` or frozen-header amendment is needed.
6. **Bottom panel.** Reserve the last text-independent grid rows before layout.
   After text layout, call `findui_render` on those rows, then collect canonical
   dirty strips and submit. Provide the grid's own ASCII glyph slots and colors.
   A suggested editor accessor supplies the begun grid, reserved row range and
   ASCII slot table. One row displays find/status, a second displays replacement
   or status, and extra rows display action hints/blank background. Layout must
   exclude these rows from document text. A state/focus change damages the panel;
   a match batch also damages affected visible text rows.
7. **Navigation.** `findui_next` accepts direction +/-1. `OK` supplies the selected
   absolute range; reveal it through the existing view/layout scroll wiring.
   `MORE` means wait for the uncached selection's new generation; reveal
   `get_state().selected` when its ordinal arrives. `BUSY` means the exact count
   is not ready yet. Empty completed results return an unset range.
8. **Replacement.** Check that the editor's active binding/version still matches;
   pass that version, its matching undo log, boundary state blobs and a guaranteed
   retained record limit. The current API conservatively admits existing records
   plus (G) nine records per match (eight delete spans plus an insert). The host
   must guarantee this limit is no larger than the log's configured current cap
   and admission capacity. Do not inspect or modify private undo fields. During
   `replacing`, defer document edits, tab switches, save/replay, new source binding
   and disposal; pump `replace_step` with a small match/deadline budget between
   input checks. Publish the final dirty document range and bind a new snapshot
   after end/error/cancel. `*replaced` counts whole matches completed in that call;
   on error an additional partial match may be present in the undo group. Supply
   conservative boundary blobs, and clamp their cursor offsets when applying
   them to the final/replayed document after a partial command. Overflow/insufficient history capacity returns `LIMIT` before
   mutation. Larger replace-all needs a separately authorized paged plan/undo
   transaction capacity; this module does not silently replace only cached hits.
9. **Shutdown.** Stop issuing panel changes, finish/cancel an open replacement,
   and call `findui_dispose` until `OK`, servicing/draining the editor pool between
   retries. `MORE` is physical cleanup, not a G6c miss. Only then release its
   arena and hook state. A closed panel can keep its arena for reopening.
10. **Trace.** Supply `scan_hook(user, generation)` to the worker-only observation
    points before every source search or boundary read. Record the actual thread
    identity alongside generation. The unit test compares it with the calling
    pthread; the benchmark independently counts calling-thread scan observations.
    The existing trace enum has no find-scan event. Suggested trace/editor hook:
    record a distinct find begin/read event in a dedicated worker ring or extend
    the event schema in its owning bead. Do not label it as an input/render event.

### Proposed work/undo accessors

- `work_handle_finished(pool, handle)`: UI-only physical retirement query. True
  when the handle's slot has a different reusable identity, or its `busy` flag
  has cleared with acquire synchronization. A cancel bump alone is **not**
  completion. Today findui isolates this observation in `slot_finished`, reading
  the documented public work slot atomics; it does not write any work internals.
  This is needed because cancelled work publications are suppressed, and a
  cancelled queued callback may never run. Replace that helper with the accessor
  when available; the lifecycle semantics stay the same.
- `undo_group_capacity(log, &retained_limit, &admissible_records)`: UI-only
  conservative admission/retention query, avoiding any private-field dependency.
  Until then the editor tracks the init/set-cap budget it owns and supplies the
  conservative record limit required by the current findui API.
- `undo_replace_atomic(log, off, delete_length, bytes, length, time, before, after)`
  or group transaction begin/commit/abort: keep content/history unchanged if an
  insert fails after a delete, while preserving earlier history. Raw piece
  checkpoint rollback alone is insufficient because undo records must roll back
  too. P4.6 uses only the existing begin/delete/insert/end/stats APIs and reports
  the successful-prefix behavior explicitly.
