# P2.3e - bounded CFF validation (edit-e6x.15)

Problem: stb_truetype's CFF parser (stbtt__cff_*) bounds itself with a hard-coded 512 MB
buffer, not the font length, so a corrupt CFF/OTTO font (system Noto CJK is CFF) could read
out of bounds, or run for ever (subr recursion), during glyph raster.

## What
1. `cff_validate` in src/font/font.c, called from `font_init_index` after the sfnt/CFF-table
   checks and before any stb call. It walks Header, Name/Top DICT/String/Global Subr INDEXes
   (offsize 1..4, monotone offsets, last offset inside the table), the Top DICT operands we rely
   on (CharStrings, CharstringType, FDArray, FDSelect, Private, with integer-only operands),
   each Private DICT and its local Subrs INDEX, FDSelect format 0/3 (ranges ascending, fd < nfd,
   sentinel == nglyphs), and requires CharStrings count >= numGlyphs. Failure -> FONT_ERR_INIT.
2. `EDIT PATCH P2.3e` in vendor/stb_truetype.h (3 lines, `stbtt__run_charstring`): step budget
   `STBTT_CFF_MAX_STEPS`, so a "subr bomb" (10 nested subrs x 20 calls each) ends with an error
   instead of 20^9 steps. Recorded in vendor/README.md.
3. Synthetic OTFs (fuzz/font_cffseed.h, 3 variants: plain+subrs, subr bomb, CID-keyed) shared
   by tests/font_test.c and the fuzzer. Nothing is vendored; bytes are generated.
4. fuzz/font_fuzz.c: `FONT_FUZZ_SEED_DIR=<dir> build/fuzz/font_fuzz` writes the 3 seeds as
   files and exits; run the fuzzer with that dir as corpus.

## Why validator + 3-line patch
The validator makes every offset stb will follow in-bounds. It cannot bound charstring
*execution* (subr recursion depth is stb's 10, but fan-out is exponential), so a budget inside
the interpreter is the minimal fix; a wrapper cannot reach it.

## Rejected
- Reimplement the CFF reader: large, duplicates stb.
- Reject all CFF: Noto CJK fallback needs it.
- Patching stb's 512 MB constant to the real length: stb has no length field in its buffers.
