# Wave 0 executable behavioral contract design

**Decision for v2-he7.5.** Run the same input scripts and expected user outcomes against an explicitly selected executable. Use a private X server for input and an optional, read-only observation of the submitted frame. Give each assertion its own oracle. In particular, comparing v2 with a v1 screenshot would accept v1's data-loss bugs and reject harmless changes to the display.

The baseline is **6fec2e8 + inspector patch** for the inspected X11 cases. Retain a stock-pin control for ordinary CLI, disk and clipboard behavior. This is a design against the source, with no new run results. Paths and symbols below refer to the pinned v1 unless marked v2. R and X identifiers come from the [inventory](wave0-contract-inventory.md), bug dispositions from the [pin investigation](wave0-known-bugs.md), and wave numbers from [the execution plan, §§4.2 and 6](../PLAN_V2.md). Identifiers, protocol literals, source coordinates and wave labels are names. Quantitative gates below have a stated derivation.

## Decisions and evidence

- **A** uses an unmodified binary. Assert fixture bytes, exit/wait status, clipboard transfers, public IPC handoff or recovery through an ordinary relaunch. The X title identifies the application. V1 sets UTF-8 and legacy names and its PID in `src/x11/x11.c:x11_plat_init`; it does not publish a reliable active-tab title there. Select All and Copy are real commands. They change selection and can move the viewport. Read CLIPBOARD after the scroll/caret assertion, use fresh selection ownership, and use disk for binary or encoding-sensitive assertions. V1's `src/editor/clip.c` even expands LF for CRLF transfers.
- **B** tests what a person can see on a frame. Read final composition, including overlays, crop and caret. In `src/editor/editor.c:submit`, `editor_compose` precedes `editor_status_overlay`; a busy or rejected submit can return without publishing. Neither the document nor a second layout is a screen oracle. The status row sometimes contains ordinary text. `src/editor/paint.c:compose_chrome` clips the strip around the active tab. Expose just the titles actually drawn.
- **The minimap requires more than cell text.** `src/editor/paint.c:compose` explicitly fills its backing cells with background. `compose_map_pixels` submits a separate region, and `src/minimap/minimap.c:minimap_pixels_window` clips the box at the short document's end and draws ink *inside* the box. Inspect final box and ink geometry. A blank text strip alone would green R21 even with the original defect. Wave 4 design shots have a different job.
- **C** covers deliberately constructed shapes, syscall cut points and worker occupation. Report the visible companion separately. In `tests/editor_large_test.c:starved_follows`, `hold_lane` actually owns a bulk worker. Starting navigation during an open exercises the real workload but cannot prove which thread is busy. Conversely, a disk mismatch after Undo needs no line-index hook. Tier refers to the evidence for an assertion, even when an inspector helps a driver synchronize setup.
- **One input stream needs one fence.** `src/ipc/ipc_posix.c:process_peer` reads an EDIP open request; `flush_peer` sends small accepted/closed replies. `src/main.c:editor_main` can forward and exit, and ordinary `--new-instance` bypasses the named listener. Neither a successful EDIP reply nor an X server round trip acknowledges editor input. A new asynchronous request on that listener would also need a cross-stream fence, output storage, backpressure and an enablement capability. Keep normal IPC for testing actual forwards. Send the inspection request on the *same X connection* as the input and return its result on a private inherited channel. No public snapshot endpoint.
- **Wait for an outcome.** V1's `docs/decisions/edit-mvro.md` distinguishes a durable publication from an expired wait, and lasting Save As adoption from a transient busy flag. The edit-5mmh record concerns an unreproduced os_test SIGBUS under load. It does not establish a sleep as that failure's cause. Preserve failures on the first run, including their synchronization evidence.

## Driver and inspector protocol

### Process and display containment

Use a Python standard-library runner for subprocesses, pidfds/waitpid, selectors, fixture generation and byte assertions. Use one persistent, independently linked C11 XCB/XTest helper for XKB key mapping, focus, button/motion, clipboard ownership/conversion including INCR, and ordered ClientMessages. The helper services selection requests while waiting. It never links editor libraries. This avoids a shell pipeline spawning a distinct X client for each key, fence and selection read. `tools/keyinject.c` supplies input/Present practice, not a general editor command interpreter; `tools/mkcorpus.c` supplies reproducible data. Neither trace replay nor v1 journal decoding is a contract dependency.

1. Require an absolute `SUBLIMITE_BIN`, a declared target role and an approved build identity in the run manifest. Resolve only within the designated oracle build or v2 build, reject the installed daily executable and missing inputs; never look up an editor on PATH. Record executable digest, pin, patch digest, fixture recipe/digest, effective configuration, display geometry, seed, target and expected case IDs. Case scripts contain no target-specific expected text.
2. Create a fresh owner-only root with `mkdtemp`. Place HOME, absolute XDG_DATA_HOME, XDG_CONFIG_HOME, XDG_RUNTIME_DIR, XDG_CACHE_HOME, XDG_STATE_HOME, TMPDIR, working directory, Xauthority and fixtures below it. Mode 0700 (P, owner rwx only) for private dirs. Build child environments from an allowlist, including for secondary forwards and independent selection clients. Drop inherited Wayland display/fd, D-Bus address, startup tokens, alternate displays, IPC test hooks, trace settings and fds. Pin font inputs to redistributable fixtures/system assets. Never import a user profile. The writer and restart share the case's profile; different cases have fresh roots.
3. Before **every** spawn/connect, validate the pinned root and owner/mode of each ancestor below it using directory fds and no-follow opens. Resolve missing leaves relative to a verified parent. Refuse any symlink escape, relative/unset variable, app-dir or socket matching a default or inherited live location, abstract address, unknown identity, pre-existing unexpected endpoint or fallback. Construct forbidden default names lexically from the original home, UID and inherited XDG roots; do not open or stat the live profiles. Containment in the new root is mandatory even for a non-default name. Recheck pinned identity at restart. After verified SIGKILL/waitpid, allow the normal server startup to reclaim only the previously recorded dead socket inode inside that same private runtime. A changed inode or a listening peer fails the restart. Only the creating process cleans up its verified tree. This extends `tests/ipc_isolation.h:test_ipc_isolate`, which sets runtime and a namespace, but leaves data/config to its caller.
4. In v1, `src/os/os_posix.c:os_app_dir`, `src/journal/path.c:journal_default_dir` and `src/config/config_posix.c:config_path` select DATA/sublimite and CONFIG/sublimite/config.toml. Config also consults state for the desktop palette. `src/ipc/ipc_posix.c:display_suffix/resolve_dir/resolve` construct RUNTIME/sublimite-<decimal uid>-d<lowercase hex of the literal DISPLAY bytes>.sock through a pinned directory fd. The namespace variable affects only the abstract branch when runtime is **absent**; `resolve_fallback` can then select /run/user/<uid>. Supplying a bad but present runtime returns an error. Require the filesystem branch, including on relay launches; confirm the actual socket is a socket in the pinned directory and its SO_PEERCRED uid/pid is the owned server before any handoff. Apply the v2 identity sublimite-v2 to both directories and both IPC naming paths as §1 specifies. Never discover the server by a global socket search.
5. Start our own Xvfb with an explicit positive local display number, `-noreset`, private cookie and `-nolisten tcp`. Use the filesystem socket, lock and abstract bind probes in `tests/x11_xvfb.h:xvfb_explicit_display`; Xvfb arbitrates the final claim. Use its readiness fd with the **explicit number**, verify the returned number, owned process and authenticated connection. Reject :0 in every spelling, inherited servers, an occupied number and accidental reuse. Never remove a global X socket/lock or signal a foreign PID. Discover a mapped top-level child of this root via MapNotify/QueryTree and _NET_WM_PID; Xvfb need not run a WM. Set and verify focus on that window before XTest. Keep the helper connection open through restarts. A different PID/window requires a fresh binding. Cleanup kills/reaps only owned processes.
6. Ordinary Tier A waits use causal public events, e.g. SelectionNotify from the owned window after replacing a sentinel owner, or an already-armed directory watch followed by opening and comparing the **destination**. Include initial reads after arming watches to close registration races. Drain events until the predicate, child exit or deadline; record outstanding predicate, last response, key sequence and disk outcome on failure. A timeout is an error. Derive watchdogs from loaded, power-stamped full oracle runs with explicit headroom in the bead report; a watchdog is a hang guard, never evidence of correctness or a latency target. No sleep-based settle, image equality, retry-to-green or global “all workers idle” check.

### Inspection capability and wire revision

One explicit launch-only option, `--inspect-fds=M,S`, on the release-optimized executable. M is a fresh grow/shrink-sealed writable memfd with the agreed byte capacity. S is one end of a connected nonblocking AF_UNIX SOCK_SEQPACKET socketpair created by the parent. Validate types, seals, distinct fds, mapping size and peer credentials at startup, set CLOEXEC immediately, forbid forwarding this capability, reject invalid combinations before touching profiles. If the launch would forward, fail; a separate ordinary relay can still forward into an inspected owner. No environment switch, socket listener or mode-dependent editing behavior. With the option absent, callbacks remain null and no observation storage, queue or output exists. The driver holds the other endpoint and reads the mapping only after a completion packet. One outstanding transaction (P, a single consumer and one reusable reply mapping); a slow reader cannot stall the editor.

**Request envelope.** On the private display send a direct X11 ClientMessage to the owned window, type `_SUBLIMITE_CONTRACT`, format 32 (P, X11 ClientMessage data32). The five X-order words are wire revision, operation, nonzero ticket, previous submit serial and reserved zero (P, the X11 data union holds five words). Revision 1 is the initial schema. Operations in wire order from zero are ARM, SNAP and NEXT. Allocate increasing tickets, reject reuse/wrap, wrong window, unknown revision/op, bad fields and concurrent requests. An ARM and its matching SNAP share one ticket; an unarmed SNAP uses a fresh ticket. Reject a NEXT carrying an unknown future serial. Only recognize the atom when the capability was supplied. On S send exactly one packet per response: ASCII magic SCEL followed by little-endian unsigned 32-bit words revision, ticket, result, submit serial, payload byte count. Result codes in order from zero are OK, ARMED, VERSION, ORDER, SIZE, INVALID. Unknown codes fail. Error and ARMED packets have empty payload. Each OK publishes a new mapping payload. Serial is per process, increments on every successful submit; zero denotes no submit. Exhaustion, truncated control/data, peer closure, unexpected descriptors or failed nonblocking send fail the transaction. Close the channel on an unrecoverable protocol error so the runner sees it. No compatibility guessing.

**Causal sequence.** For a first-frame regression, ARM before input and wait for ARMED; then send XTest actions and SNAP in server order, without input from any second automation connection. For a settled view, send the actions and SNAP. V1 `src/x11/x11.c:drain` empties translated input before it dispatches the next raw event, even across bounded slices. Deliver the marker there, never from an independently polled fd. Do not insert the marker in the lossy/coalescing input ring. Stop sending further actions until completion. At the marker all earlier X events have reached normal ingress; their editor actions may still be parked. Drain the accepted prefix through the normal queue and foreground continuations (including paste transfer, wrap/scroll follow, replay, resize and staged journal group). A public refusal counts as disposition, never as a successful edit. Keep the usual submission fences. Do not wait for unrelated indexing, discovery, highlighting, minimap warming or save completion.

Return the first successful ordinary submit **after** the marker and prefix disposition. If all its changes already submitted, or an action had no damage, request one ordinary repaint of the current view, once, under normal layout/backend gates. Busy, rejected, dropped or merely composed frames cannot complete SNAP. An armed transaction also retains the first successful **natural** frame containing the armed key/action, even if it preceded the marker; use the existing ingress/frame sequence to distinguish blink from action. Return both frames with their serials. An absent first-action frame is an explicit missing witness and fails assertions that require it. A repaint must never supply that witness. This distinction matters for R2. For NEXT, wait for a newer natural submit than the supplied serial; if it already occurred, schedule a current-frame snapshot through the same fence. Read only until the named visible predicate (e.g. results row actually present or a save notice). A frame ACK witnesses a submit, not compositor presentation, successful Ctrl+S, a file barrier or background quiescence.

### Snapshot representation

**Payload.** Binary, little endian, no C struct padding. Counts, lengths, coordinates and tags are unsigned 32-bit words (P, same range as X coordinates carried in data32 and v1 render dimensions); the fractional vertical translation alone is signed 32-bit, in units of 1/256 pixel (P, existing Q8 render transform). A string is a byte count followed immediately by that many UTF-8 bytes, without NUL. Rectangles are x, y, width, height with exclusive right/bottom. All cells use zero-based window coordinates including chrome. A zero-area rectangle denotes absence. Encode, in order:

- Frame count then frames, first-action if captured followed by settled (one or two, derived from the two observation points). Each frame begins with witness kind (settled = 0, first-action = 1), submit serial, window width/height in pixels, grid columns/rows, cell width/height in pixels, document rect in cells, scroll transform and its affected rect in cells. For a fractional viewport include the clipped contributing overscan row after the nominal rows, indicated by an extra-row count. Crop operations and hit coordinates apply the transform. Keep physical geometry out of parity assertions unless the regression itself concerns geometry.
- Cells in row-major order, exactly columns × (rows + extra-row count). Each is kind, attribute bits, foreground class, background class, text string. Kind values in order from zero are blank, painted text, wide continuation, unresolved artwork. Empty strings for blank/continuation/unresolved; retain every cell including trailing blanks. Attribute bits in increasing order denote drawn caret, underline, wide lead. Color classes are equality labels local to a frame (e.g. first-seen labels), sufficient for “token painted differently” without requiring a particular palette. The decoder exposes the drawn caret cell(s), or absent during blink, directly from the mask. A focused field's drawn underline is separately observable. No selection/cursor byte offsets. Preserve replacement artwork as seen. The settled witness is the current focus frame; any first-action check names its triggering input. For chords, send and fence modifier-down before ARM, then send the triggering key and subsequent releases so a modifier-only frame cannot satisfy the check.
- Visible tab count followed by a cell rect and active flag per visible tab, then bottom-row rect. Read each title and the bottom text from the transmitted cells in its rect; covered text stays covered. No hidden tabs, full paths, unpainted notice messages or tab IDs. Viewport travel is determined by fixture line labels and their placement. No scroll-model line number. A bottom row can be document, panel or notice.
- Minimap region and painted viewport box as window-pixel rects, then a count and sorted disjoint half-open vertical intervals (start y, end y relative to region) of scanlines carrying miniature text ink. Merge consecutive inked scanlines; omit background, viewport wash/edge and the stale indicator from ink. In v1 decode the *submitted* region with the actual palette used for that composition, including the pending and hovered variants of `minimap_pixels_window` and the retained `minimap_pixels` path. Clipped or absent regions stay clipped or absent. Use a known nondegenerate theme for box/ink assertions; if colors alias and a role is ambiguous, encode observation failure. V2 can project its final draw commands to the same geometry. No raw colors, pixels or sidebar hash enter the expected outcome.

Resolve v1 text while its submitted font binding is still valid. `src/render/render.h:render_cell` explicitly gives `glyph_index` caller-defined identity. `src/font/async.c:font_async_glyph/font_async_event` use baked ASCII slots and request-key bytes for resident shaped clusters, including slot reuse and blank adoption. For a ready, successful image use the bound slot's artwork key, for baked/placeholder/known replacement artwork its actually drawn character, for NO_SLOT or known inkless space a blank. Mark a non-invertible image unresolved. Never cast arbitrary glyph IDs to Unicode or read bytes under the caret to fill holes. The PDF case can assert its painted ASCII header through unrelated unresolved cells. A required text match crossing an unresolved cell fails. The protocol describes displayed text and widths, not lossless document Unicode.

**Lifetime and bounds.** Validate the record in both directions: checked arithmetic, enum/flag validity, UTF-8, dimensions, rects, payload length, frame order, ticket, serial and end-of-record. The parent sizes M from test window dimensions, per-cell fixed fields plus the fixture's maximum artwork-key length, visible tabs bounded by columns, ink intervals bounded by region height, and the requested frame count. Use checked sums of those wire fields, including maximal overscan and prompts/chrome in the fixture bound. An oversized real frame returns SIZE, never truncation; a run with an undersized mapping is a harness failure. Reserve and prefault scratch/mapping once at launch. Hold immutable bytes for each requested witness until reply consumption (the next request releases them). On the UI thread, only when armed, project/copy the just-submitted draw surface before any storage can be reused. Keep any lookup tables prepaid. No malloc, printf, filesystem I/O, waiting on a client or borrowed pointer crossing a frame. Issue just the fixed nonblocking completion packet after submit. The disabled path is a null callback. Keep the live release allocation guard active across input through submit with inspection on and off; separately exercise a stalled/disconnected reader. G1 measurement uses the normal release path.

### SIGKILL and durability

Use identical disposable fixtures and an independent expected-byte model. Begin from a verified durable pre-state. For the grouped-edit case use a single atomic paste/replacement or undo of a replacement; individual keypresses in a typing burst are separate commands. Arm a pidfd for the actual editor. In the pre-ACK case inject the action, flush X and kill without waiting for the application. A raced completion is legal; require exact pre-edit **or** whole-edit text, never a prefix or mixed bytes. In the post-ACK case wait for a natural submitted action frame containing the unique changed text (or a public command completion with equivalent semantics), then SIGKILL immediately. Require whole-edit on restart, also for an untitled tab. A marker-only repaint, server key delivery and an EDIP open ACK are insufficient. Do not call quit or force a flush to make this pass. Record WIFSIGNALED/SIGKILL and the distinct new PID. Read restored buffers by clipboard or Save As to fresh files, including deferred tabs through the normal reopen command. Source disk and recovered buffer are distinct oracles.

For an in-progress save arm an external directory watch first, inject Save and kill at an observable creation/publication or immediately on injection. Compare target to the complete old or new generation; after completed-save acknowledgment require complete new bytes. A directory event may arrive after the worker finishes. Record the witnessed event, never assign a syscall phase on timing grounds. The deterministic cases in `tests/dataloss_test.c:kill_at_step/torn_undo_child` inspect `FILE_STEP_*` or intra-group progress. Wave 1 public-header tests interpose the actual OS calls with `-Wl,--wrap`, block at each save boundary, fail file sync and directory sync separately, and exercise suspended-recovery reporting without discarding or duplicating accepted edits. No contract test links `file_set_step_hook`, parses a journal or imports a v1 fixture journal. Power loss is a separate fault model from process death.
