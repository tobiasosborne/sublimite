# Wave 1 decision study — publishing SAVE by exchange

**Decision (P). The proposed strengthening of A23 breaks.** N1 does identify a real improvement at the publication syscall. If another writer wins the last-check race, exchange moves its file to the staging name with its link intact. But kill the editor immediately afterward. The signed journal identifies our output at the destination and contains no staging basename or record of what was displaced. Recovery can finish a save whose live publisher would have reported a conflict. Independently, once the expected old inode has been unlinked, a foreign rename over our output recreates the original T5 loss of source bytes. Keep the signed file round 2 target and the present fallback. [N1](../reviews/wave1-L2-1-opus.md) · [A23 and A28](wave0-plan-amendments.md) · [SAVE payload layouts](../../src/journal/journal.h)

**Evidence convention (G).** As in the [cut protocol](wave1-L2-q2-protocol.md) and [Law 4](../../CLAUDE.md), (G) identifies a specified contract or an explicitly stated model assumption. (P) identifies a consequence derived from it or from cited source. T1/T5, amendment numbers, identifiers and kernel release tags name sources or cases. This is a derivation without measurements.

## What has to survive

**Invariant (G).** A verified prior binding permits prior replay. A verified installed output permits replay of snapshot S plus complete commands after its cutoff s. A foreign binding permits an independently usable checkpoint plus suffix, or a reported unresolved BASE with available literals preserved. A saved ID requires verification of the actual binding. The proposed extra obligation is to distinguish displacement of the expected old file from displacement of a foreign file, preserve the latter, and report it even across restart. The same obligation must survive any allowed cut before a terminal decision. [Signed SAVE interpretation](wave1-journal-wire-amendment.md) · [WRITING and recovery](wave1-savectl-spec.md)

**Names and barriers (G).** Write p for the destination, t for its same-directory staging name, G for the expected old inode, N for our synced output, F for an unrelated file. K loses all process state but sees kernel-visible names and the valid prefix of the named journal. M guarantees only the prefix through the last successful covering journal barrier. Later complete records in its surviving prefix also count. Give exchange the favorable crash model of the Q2 proof extended to a swap: recovery sees either namespace before or after an unsynced exchange, and the exchanged pair after a successful parent sync absent further operations. The syscall specifies live atomicity. A mount would also have to satisfy this crash model to claim the M result. File sync alone does not make t durable. A failed or uncertain barrier proves no new durability. [Q2 stop model](wave1-L2-q2-protocol.md) · [A28 save cuts](wave1-journal-write-model.md) · [Linux rename semantics](https://man7.org/linux/man-pages/man2/rename.2.html)

**Two histories (P).** Start with p=G, t=N and durable PREPARED. In the ordinary history exchange yields p=N, t=G. In the racing history a foreign rename after our final check gives p=F, t=N, then exchange yields p=N, t=F. K before inspection or unlink. The signed recovery inputs for this decision are identical: same token, prior expectation, cutoff, output witness and matching p=N. The live decisions required by the proposal differ. For M, let the exchanged namespace survive, or let another holder sync the directory before the loss. Both histories again admit the same observation at p. Even perfect recognition of N cannot tell which file moved to t. [N1](../reviews/wave1-L2-1-opus.md) · [Restart erratum 5](wave1-app-spec.md)

**What PREPARED records (G/P).** The SAVE layout stores the token, prior and reserved new generation keys, snapshot sequence and saved content ID, expected destination presence and wire identity, N's volume/inode, size and whole-stream CRC32C, and **the destination path p**. Its path length delimits that single path. FINISHED repeats the destination path. CANCELLED refers to a checkpoint or usable prior representation. None gives the reader t. On `review/l2-1b`, `file.c` stores the created leaf in `file_temp.tmp` and passes it to `os_rename_at`. K loses it. The signed restart operation opens **p** against the witness. It has no instruction or authority to find, unlink, restore, or use a displaced object under t. A directory scan by filename pattern can pick another transaction's file. Even a future recorded t would identify a mutable name, not its owner. The output witness identifies N, whereas the post-exchange object at t is precisely the one that needs classifying. [Wire amendment retaining the layouts](wave1-journal-wire-amendment.md) · [Wire §6 and journal_save](../../src/journal/journal.h) · [File restart custody](wave1-app-spec.md)

## T1 — ordinary save without an external writer

**Derivation (P).** Assume distinct regular G and N and an unchanged parent. Compare each surviving p with the signed branches. Old replay starts at the verified prior origin and applies its complete edits. New replay starts at S and applies complete commands finalized after s. Both reconstruct the same text for a given surviving command prefix. The table separates text recovery from settlement of t. It uses exchange, inspection, unlink of expected G, then parent sync. An intervening parent sync is shown separately because it changes the M result. The finish cuts use append-only A28, which supersedes Q2's finish-image construction. [T1](wave1-L2-q2-protocol.md) · [A28 §1.6](wave1-journal-write-model.md)

| Stop immediately after (P) | K | M |
|---|---|---|
| Capture S,s and embargo G. Create t, partly write it, finish writing, then sync N. | At each cut p=G gives old replay. Ignore t, even if complete. | Same old replay. N's data is guaranteed only after its sync. Its new name can still be absent. |
| Partial PREPARED, complete PREPARED, covering journal sync, then final source/destination/fence recheck. | Ignore a torn tail. A complete open token with p=G selects prior replay. | Prior replay for absent, partial or complete marker. At successful barrier the complete marker and preceding prefix are guaranteed. Failed prepare or validation prohibits publication. |
| Exchange, then inspect t=G, before unlink. | p=N gives new replay. G remains linked at t through either cut. Recovery has no cleanup locator. | Prior namespace gives old replay. Exchanged namespace gives new replay with G at t. If the parent was synced between exchange and unlink, only the exchanged pair survives that barrier. |
| Unlink expected G, before target-parent sync. | p=N, t absent. New replay. If G had no other link, process death loses the last held fd. | Without an earlier parent barrier allow the old target or the installed target. With N installed, cleanup may or may not survive. With an exchange barrier first, p=N is guaranteed and t can still reappear. |
| Parent sync after cleanup, then fd/path/content verification. | At each cut p=N, t absent. New replay with PREPARED. | Same names and replay after successful sync. A failed sync keeps the preceding alternatives and a barrier obligation. A live retry syncs the original parent and re-verifies, without republishing. |
| Append installed GENERATION, partial FINISHED, complete FINISHED, covering sync, then reverify/adopt and announce. | An orphan declaration or torn terminal leaves PREPARED+N. Complete matching FINISHED activates origin and cutoff together. Only a verified binding carries the saved ID at s. Later edits survive as the suffix. | Before terminal sync the surviving prefix selects either depiction with the same text. From that sync FINISHED is durable. Adoption or notification adds no disk evidence. |

**T1 result (P).** Ordinary text replay holds. A kill after exchange can leave the entire prior file linked indefinitely under an unrecorded staging name, even if replay correctly reconstructs the new text. A parent sync can make that artifact durable. Calling it a temp does not satisfy A23 rule 1's no-retention and no-retirement-scan decision. [A23 rule 1](wave0-plan-amendments.md)

## T5 — foreign publication before and after exchange

**Fixture (P).** Let G contain arbitrary X beyond its recorded prefix, with no other link and no independent checkpoint. The journal contains a synced insertion of `!`, so S is `X!`. N is the only complete saved copy of S. F contains unrelated bytes. A witness can recognize an available candidate but cannot reconstruct arbitrary X. Each row uses the same prefix rules as T1. [T5 fixture](wave1-L2-q2-protocol.md)

| Stop immediately after (P) | K | M |
|---|---|---|
| Capture, each temp-write cut, temp sync, partial/full/synced PREPARED, final recheck, with p still G. | Prior replay yields `X!` throughout. | Same for the synced edit. |
| F replaces G before the exchange. | If observed before publication, refuse. At a stop with p=F the reader preserves F, reports unresolved BASE and offers the literal. This applies even during temp writing or before PREPARED. The signed reader cannot adopt an unpublished N. | If G survives, prior replay works. With F surviving, same conflict as K. A foreign parent sync makes F durable. |
| F arrives after the last check, then we exchange. Kill before inspecting t, or after inspection but before durable reporting. | p=N gives new replay. F's bytes are linked at t. Restart loses the displacement diagnosis and can finish against N. A generic cleanup by temp name could destroy F's last link. | If exchange survives, same lost diagnosis. If it does not, the surviving prior binding (G or F according to preceding barriers) decides prior replay or conflict. A synced exchanged pair guarantees p=N, t=F until changed. |
| Ordinary exchange gives p=N, t=G, then F replaces N **before** unlink. | p=F, t=G. The old bytes may still exist, but the signed reader has no verified origin at t. Refuse replay onto F. A live fd for N dies with the process. | Before foreign parent sync a surviving G or N at p gives its usual replay. A surviving F gives conflict. After that sync the pair p=F, t=G is durable if cleanup has not run. |
| Ordinary exchange, unlink G, sync parent, then F replaces N before any independent checkpoint. | **Original breaking cut.** p=F and t is absent. Neither G nor N has a surviving name. Report unresolved BASE, offer `!`, leave F alone. | Before foreign parent sync N may survive. If F survives, same failure. After foreign parent sync the failure is guaranteed for this trace. |
| Detect mismatch during verification, barrier retry, before FINISHED, or while the conflict checkpoint is partial. | Detection and partial literals do not commit a checkpoint. The preceding conflict remains. Preserve the open token, dirty suffix and any usable live source. | Same for the durable foreign binding until a complete independently usable group survives. |
| Conflict checkpoint COMMIT, covering journal sync, reconciled namespace, partial/full CANCELLED, covering terminal sync. | From complete checkpoint in the named journal recover its snapshot plus complete suffix, dirty. A partial cancel leaves the token open. Complete cancel consumes only that token and never grants a saved ID. | Before checkpoint sync, whole checkpoint or unresolved. From that barrier the text is protected even with open PREPARED. Before cancel sync either token state may survive. After it the cancellation is durable. |
| F arrives after complete FINISHED and before its durable adoption, or after completed save. | Reverify p. Complete FINISHED consumes the token. Report changed and unknown saved association, request protection, and issue no second terminal. A later replacement after adoption starts an idle conflict. Text depends on surviving sources as above. | If FINISHED survives, apply the same binding rule. Otherwise select the open-token branch. A covering finish barrier guarantees the terminal, not N's continued existence. |

**Limits of rollback and cleanup (P).** Having found F at t, leave both entries and report their observed locations while live. Even if p=N when checked, another writer can put H there before a compensating exchange. Swapping back would move H out of its chosen path and expose it at t to cleanup. Likewise, checking that t names G and then calling `unlinkat(t)` removes a foreign replacement if a writer can replace t between those calls. Holding G's fd pins the inode, not the name. These are separate races. The first needs only a writer to p. The second needs a writer to t in the same directory. A later design that assumes exclusive control of the staging namespace must establish that premise; the ordinary shared target directory gives no such guarantee. [OS unlink and rename interfaces](../../src/os/os.h)

**A23 result (G/P).** The first foreign-arrival case gains a link for F at the syscall boundary. The second still loses X on both crash models. A by-value checkpoint with an independently replayable suffix protects either case once visible for K or durably covered for M, including qualifying small buffers. The initial interval before their first such checkpoint remains exposed. Keeping G longer as a recovery source would be a retention policy and would still require generation validation. [A23 T5 ruling](wave0-plan-amendments.md) · [A28 conflict cuts](wave1-journal-write-model.md)

## The mapped old inode

**Operation-local evidence (G/P).** File round 2 permits re-baselining the original backing only from an fstat pair on its held fd immediately around our own rename. The before observation must agree with its accepted acquisition, the rename must have the classified effect on that inode, and the after observation must agree in the fields the operation cannot explain. Keep, retry, later path verification and restart cannot recreate that pair. On Save As the source H can differ from the displaced G. Only the backing actually affected can receive such an adjustment. The written fd supplies N's installed identity separately. The branch under review compares ctime in `file_source_validate` but `file_resolve_keep` can adopt it on path divergence. The review's same-size write through another hard link with restored mtime defeats that adoption. [MF5/MF6](../reviews/wave1-L2-1-opus.md) · [Backing and fd custody errata](wave1-app-spec.md)

**Two metadata changes (P).** For distinct regular files let G start with L links. Replacing p normally leaves L−1. Exchange gives G a name at t in the same operation that takes away p, so its count remains L. Its ctime can nevertheless move: ext4's exchange updates both inodes' ctimes. A later unlink of t gives L−1 and can move ctime again, including when other links remain. Thus a validator requiring a link-count drop *at exchange* rejects intact bytes. A pair around exchange cannot explain a subsequent unlink. Stretching the pair across inspection, cleanup or a retry would absorb unrelated writes. Refuse unexplained changes under the signed rule. Any future allowance for a proven own unlink needs its own tightly bracketed observations and explicit ruling; even matching link counts and restored mtime cannot exclude a concurrent in-place write within that bracket. A missing observation or ambiguous effect grants no re-baseline. The current `os_stat` exposes ctime but omits link count. A future design that needs to observe L must extend the stat seam. [Linux ext4 exchange](https://github.com/torvalds/linux/blob/v6.12/fs/ext4/namei.c#L3912-L3920) · [os_stat](../../src/os/os.h)

## Filesystem choice and fallback

**Capability (P).** Use the operation on the actual mount as the authority. In Linux v6.12, the native ext2 driver rejects flags outside NOREPLACE, the NFS client rejects nonzero rename flags, and the SMB/CIFS client rejects flags outside NOREPLACE. Thus those implementations lack EXCHANGE. The ext4 and VFAT handlers in the same release explicitly implement it. These are versioned examples; different drivers can serve the same disk format, and a userspace filesystem can supply its own semantics. A kernel without `renameat2` also lacks the operation. NOREPLACE support and live exchange support do not establish exchange crash durability. [ext2](https://github.com/torvalds/linux/blob/v6.12/fs/ext2/namei.c#L300-L315) · [NFS](https://github.com/torvalds/linux/blob/v6.12/fs/nfs/dir.c#L2550-L2561) · [SMB](https://github.com/torvalds/linux/blob/v6.12/fs/smb/client/inode.c#L2194-L2195) · [ext4](https://github.com/torvalds/linux/blob/v6.12/fs/ext4/namei.c#L3966-L3971) · [VFAT](https://github.com/torvalds/linux/blob/v6.12/fs/fat/namei_vfat.c#L1094-L1106)

**Present destination (G/P).** The simplest alternative is the current final recheck of the source, expected destination and membership fence, followed by rename-over, parent sync and held-fd/path verification. Its defeating input is F installed **after the check and before REPLACE**. REPLACE can drop F's last link and a later verification can correctly find N and report success. Keep this path for round 2. In a future optional exchange implementation, allow this fallback only after a definitely unperformed, unsupported exchange, then revalidate. The OS layer can classify an unavailable syscall, unsupported-operation error or flag rejection on otherwise valid inputs. Permissions, a disappeared destination, I/O failure and ambiguous completion do not establish lack of support. Retain custody and reconcile an uncertain effect; repeating a possibly completed exchange can reverse it. [N1](../reviews/wave1-L2-1-opus.md) · [rename implementation](../../src/os/os_posix.c) · [Linux rename errors](https://man7.org/linux/man-pages/man2/rename.2.html)

**Absent destination (G/P).** EXCHANGE requires both names to exist. For an expected absence use atomic NOREPLACE. A racing creator wins with EEXIST and keeps its file. Unsupported atomic exclusion refuses the save. On success t is consumed, and the ordinary PREPARED/installed, parent-sync and verification rules apply. Conversely, disappearance of an expected-present p is a changed binding, with no authority to create a new target. [Signed WRITING row](wave1-savectl-spec.md) · [Linux rename flags](https://man7.org/linux/man-pages/man2/rename.2.html)

## Header and brief disposition

**Round 2 (G).** Proceed with signed errata 4 and 5, the existing WRITING row and the signed L2-3 brief. No exchange change follows from this verdict. The following are dependencies of any later proposal limited to preserving or reporting a pre-exchange displacement.

| Contract | Required delta and defeating input (P) |
|---|---|
| OS | Add an EXCHANGE **mode** to `os_rename_mode` and the Linux `rename_fds` switch. The existing `os_rename_at(from_dir, from, to_dir, to, mode)` already has both directory/name pairs. No new rename function is required. Its result must distinguish definitive unavailability from uncertainty; an ambiguous result cannot authorize fallback. [OS header](../../src/os/os.h) · [POSIX implementation](../../src/os/os_posix.c) |
| file.h, erratum 4 | Separate custody of written N and its pinned parent from the disposition of the displaced name. Reaping, close, discard and barrier retry must preserve the evidence and obey the single-publication rule. Only a proved safe namespace operation could retire t. Parent durability must cover the final intended namespace, including cleanup. [Held-output contract](wave1-app-spec.md) |
| file.h and restart, erratum 5 | Keep validation attached to each mapped backing's own source.
