# P4.1 word wrap — edit-457.1

## Contract and integration

Wrapping is opt-in on the existing layout interface. Existing layout/view
initializers and positional configuration/viewport initializers keep compiling;
wrap-off continues through the original renderer. The layout header's original
no-wrap description describes that default path. Font and frozen headers are
unchanged.

At buffer open, reserve `layout_wrap_init(&layout, &arena)`, initialize the view,
and call `view_wrap_file(&view, &layout, path)`. NULL/empty paths (untitled),
`.md`, `.txt`, and `.tex` enable wrap; other extensions disable it.
`view_state.wrap` is the per-buffer flag. `layout_set_wrap` / `view_set_wrap`
provide explicit overrides; config.toml remains P6.4. Layout setters require an idle layout; view setters require an idle view. Call `layout_begin` after toggling or changing geometry. Reserve row
capacity for the maximum grid height at open; excess heights return an error.

The editor continues to call begin/run/edit and the existing cursor/selection
interfaces. Wrapped horizontal scroll is ignored. For scrolling within a logical
line, query `layout_visual_row` at `view.state.visual_byte` and supply its
result to `layout_begin_visual`. Keep query geometry consistent with the current
text width (gutter excluded) and tab width. `first_byte` / `first_line` retain
their logical-line meanings. `visual_byte` identifies the first visual row.

`view.state.visual_end` is trailing cursor affinity at a soft-row endpoint.
Pass it to `layout_set_cursor_visual`; ordinary `layout_set_cursor` retains
leading affinity. End returns the byte after the row's last cluster, including
trailing separator whitespace; Home/Up/Down then continue from that same row.
For a full row the trailing cursor styles its last cell (both halves if wide);
otherwise it draws a blank cursor cell in the remaining space. A cursor/selection
move still requires relayout of the affected screen rows, including the preceding
row for a trailing soft endpoint. Query calls never modify cells or damage.

## Wrap decisions

- `src/layout/wrap.c` owns partitioning, row metadata, dirty-row movement,
  and layout queries. `wrap.h` is private. Layout.c has dispatch hooks plus
  private access to its existing window refill, consumption accounting, and
  bounded cluster decoder/cache. Wrap-off's scan/render logic is unchanged.
- Prefer a break after ASCII space/tab clusters. A word longer than the available
  row hard-wraps at a grapheme boundary. Separator whitespace at an exactly full
  row belongs to that row and is consumed without producing cells. Tabs expand
  from the absolute logical column, including hidden separator cells, rather
  than restarting tab stops on each row.
- Continuations repeat the logical line's leading space/tab indentation as
  synthetic blank cells. Cap it at half the text width; text widths at most
  two cells use no continuation indent. This ensures useful progress on deeply
  indented text. Continuation gutters are blank and logical line numbers appear
  once. Empty lines and the final empty line retain their gutter/cursor behavior.
- Reuse `utf8_cluster_step` across slices and window refills. Printable ASCII
  spans have a separate fast path, but the ASCII immediately before non-ASCII
  takes the cluster path, so bases with following combining marks stay intact.
  A two-cell cluster that does not fit moves intact to the next row. At a
  one-cell text width it draws a one-cell `?`, explicitly approximate; a
  two-cell image cannot fit that viewport. An oversized cluster still segments
  exactly, with the existing contiguous-glyph scratch limit and approximation.
  CRLF's CR contributes no cell and visual End points before it.
- Caller-arena storage is two `layout_wrap_row` arrays per viewport row, rather
  than a copy of the cell grid or an allocation per logical line. The normal
  begin/run/edit/relayout/query paths make no allocation calls. No new globals.
- A newline-free edit performs a sliced descriptor-only pass over the affected
  logical line's visible rows. Once its new row count is known, move the cached
  suffix with memmove, then render only that line. No other logical line is
  decoded, except newly exposed bottom rows when a line shrinks. If the count
  stays unchanged, damage is just the affected group. Newline changes redraw
  from the affected logical line to the bottom. Geometry changes and edits
  during a busy layout retain the original full-restart contract. Edits cutting
  the viewport anchor return `LAYOUT_RESET`. Edits beyond the visible suffix
  do no rendering, with a small right-context margin for the final decoded
  unit/CRLF. A single logical line filling the viewport necessarily
  reflows all of its visible rows when edited.

## Long lines and navigation bounds

Cached visual-row descriptors and an exact next row seeded from them provide
visual Home/End/Up/Down and page movement. Preferred columns are screen columns,
including synthetic continuation indent; short rows clamp without forgetting
the preference. Tabs/wide clusters resolve a target inside them to their start.
Shift movement retains its anchor; logical/document/word commands keep the
existing view semantics. After mutations, `layout_visual_row_fresh` suppresses
stale row/checkpoint data while view repairs/follows the cursor.

Wrap never scans an unused long-line tail. Deep uncached queries binary-search
P3.1b's caller-owned column checkpoints, then scan locally with the same bounded
wrap scanner. Checkpoints certify cluster boundaries and absolute columns;
they do **not** certify width-dependent word-wrap phase. Such a query explicitly
reports an approximate local wrap phase. A caller can retain a visual descriptor
as a scroll seed, and subsequent layout stays local. A deep unindexed ASCII
fallback certifies a nearby boundary using an ASCII pair and reports an estimated
column/phase. Arbitrary Unicode window edges are never assumed to be boundaries.
An unresolved pathological cluster returns a certified earlier position with
approximation, rather than manufacturing an interior cursor position.

Each layout run consumes at most LAYOUT_BYTE_BUDGET plus the final scalar's
UTF-8 tail, and respects `slice_clusters`; queries have a cumulative scanner
budget. Byte/line lookups remain opaque piece API calls. The view's existing
byte counter measures its own column/grapheme scanner, not opaque layout queries;
a page command can make multiple bounded row queries. Exact global deep word-wrap
phase would require a width-dependent visual-break index, beyond the existing
column index; no claim of exact uncached phase is made here.


Green release tests exercise word/hard wraps, indentation, tabs, CJK/combining
clusters, narrow widths, cursor/selection, CRLF, gutters, snapshots, file defaults,
soft End affinity, navigation across logical/viewport boundaries, newline changes,
indent removal, alternating row-count changes against fresh layouts, checkpoint
seeks in a long line, and both relayout and mutation allocation guards.
Fuzz adds wrap on/off, changing widths, insertion/deletion, row-start comparisons, and wrapped deep
checkpoint queries with independent one-shot boundary certification.

Benchmark rows are appended in a separate P4.1 function. Existing P3.1 gates
are unchanged. Wrapped Unicode and long ASCII prose use 300 x 360 viewports,
300 us p50/p99 gates (G), typing rows TRACK, and an indexed deep ASCII row.
The ASCII prose is the existing oneline_1g.txt; no corpus is regenerated.
`layout_bench /tmp/edit-corpus '' --wrap-only` isolates the added rows.
All shared-box results are TRACK evidence, not the coordinator's quiet verdict.
Final results are recorded below and in `src/layout/STATUS.md`.

Additional red regressions found during verification:

```text
FAIL wrap_test:224 f.cells[4].attrs&RENDER_ATTR_CURSOR
FAIL wrap_test:239 memcmp(a.cells,b.cells,5u*sizeof(render_cell))==0
```

The first covers a cursor on invisible separator whitespace after an exactly
full row; it now styles the row endpoint. Preferred columns clamp to the visible
width when separator cells are hidden. The second changes a continuation byte
of the next UTF-8 unit into a Thai combining mark. That changes the final visible
cluster even though the edit is just beyond the viewport. Incremental layout
therefore retains a four-byte right-context margin. A fuzzer-generated CRLF
lookahead artifact also reproduced before that fix and replays cleanly after it.
