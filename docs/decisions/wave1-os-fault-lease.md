# Wave 1 L0 decision — pinned mapped-file fault lease

A successful pin buys the right to poll one registration and to finish reading its still-registered view. **Retirement returns `OS_E_BUSY` while any caller holds a pin.** The owner keeps the mapping and can retry after the readers release it. Successful retirement closes admission and drains signal handlers before giving the owner permission to unmap. This lets a completed line index keep its invalidation token without retaining a piece-tree revision.

The reference throughout is v1 at `6fec2e8`. Paths starting with `src/` and the named v1 decisions/tests refer to that checkout. The architectural constraints are v2 `CLAUDE.md`, `docs/PLAN_V2.md` §§2, 4.1, 4.3 and the Wave 1 L0/L1 harvest dossiers.

## Public contract

Proposed complete fault subsection of `src/os/os.h`. It uses the header's existing `os_map`, `os_err`, `<stddef.h>` and `<stdint.h>`. These declarations specify the interface only.

```c
#define OS_FAULT_SLOTS 256

typedef struct os_fault_id {
    uint32_t slot;
    uint64_t gen;
} os_fault_id;

typedef enum os_fault_lease_state {
    OS_FAULT_LEASE_EMPTY,
    OS_FAULT_LEASE_HELD
} os_fault_lease_state;

typedef struct os_fault_lease {
    os_fault_lease_state state;
    os_fault_id id;
} os_fault_lease;

#define OS_FAULT_ID_INIT    { .slot = 0, .gen = 0 }
#define OS_FAULT_LEASE_INIT { .state = OS_FAULT_LEASE_EMPTY, .id = OS_FAULT_ID_INIT }

os_err os_fault_register(const os_map *view, os_fault_id *out);
os_err os_fault_pin(uint32_t slot, uint64_t gen, os_fault_lease *out);
os_err os_fault_poll(const os_fault_lease *lease, uint64_t *epoch);
os_err os_fault_unpin(os_fault_lease *lease);
os_err os_fault_retire(os_fault_id id);
os_err os_fault_test_trigger(const os_map *view, size_t off);
```

`OS_FAULT_SLOTS = 256` (M, source count) preserves the capacity of v1 `src/os/os.h:OS_FAULT_SLOTS`. Its historical source is `src/file/file.c:FILE_GUARD_SLOTS` in the parent of migration commit `1d7d786`. At the oracle pin only the OS definition remains. The table bounds both resident storage and the handler scan. `uint32_t` is the project's existing fixed-width slot-word type in `src/os/os_posix.c:fault_slot` and represents every index. Index zero is usable. Generation zero denotes absence so zero-initialized storage suffices (P, one distinguished non-issued identity). Epoch zero means no fault has been claimed. The first accepted fault advances it by one, one count per recovery attempt, as in v1 `fault_recover`. The unsigned widths and their limits are addressed below.

All calls are ordinary thread calls. They take caller-owned storage and allocate no C heap memory. The only mutable process global is `os_fault_service`, including its static normal-thread mutex, once control, slots and installation data. The kernel can allocate VM metadata on a fault. Admission/teardown are distinct from polling on a read path.

| Function | Ownership, success and failure |
|---|---|
| `os_fault_register` | Mapping owner, before exposing any bytes. Pass a fresh output cell and a live, read-only private file view from `os_map_file`. Returns a copyable ID, with one logical owner authorized to retire. OS borrows the page-rounded extent until successful retire. Reject a null pointer, empty/null view, unaligned base, or unrepresentable logical/rounded end with `OS_E_INVAL`. Under the registry mutex reject any overlapping rounded extent, including duplicate registration, with `OS_E_EXIST`. Distinct views of the same inode are fine. On valid input an unavailable installation gives `OS_E_NOTSUP`; no reusable slot gives `OS_E_NOSPC`. On failure write the absent ID if the output pointer is valid. No registration was transferred. |
| `os_fault_pin` | Any thread with a published ID and exclusive access to an initialized EMPTY destination. Under the mutex test LIVE and the **same** generation, then increment the persistent count before unlocking. On success output owns one HELD pin. Invalid slot, zero generation or null output gives `OS_E_INVAL`, a held destination gives `OS_E_BUSY`, a well-formed but absent, retired or superseded identity gives `OS_E_NOENT`. Count at its type maximum gives `OS_E_RANGE`. Failure preserves the destination and counts. A faulted LIVE registration can be pinned and immediately reports its nonzero epoch. |
| `os_fault_poll` | Any borrower of a HELD lease. Concurrent const polls with separate epoch outputs are allowed. The owner must synchronize the end of all borrows before unpin. Returns `OS_OK` and the saturating cumulative epoch, including prior faults. A null argument, EMPTY lease or malformed fields give `OS_E_INVAL` and leave the output untouched. No mutex, registration scan, allocation, or native call on success. |
| `os_fault_unpin` | Exclusive lease owner on any thread after the last byte access and poll. Under the mutex drop exactly one persistent pin and reset the object to EMPTY. Null, malformed or already EMPTY gives `OS_E_INVAL` with no mutation. Last unpin leaves the owner’s registration LIVE. |
| `os_fault_retire` | Registration owner on any ordinary thread, once ordinary unpinned owner reads have ended. Check ID under the mutex. Malformed gives `OS_E_INVAL`, missing/superseded/already retiring gives `OS_E_NOENT`. Persistent pin count above zero gives `OS_E_BUSY` immediately and leaves admission and recovery open. Otherwise close admission and wait only for handlers already admitted. `OS_OK` consumes ownership. The owner can now unmap. No caller can force retirement or unmap after BUSY. |
| `os_fault_test_trigger` | Test thread with a live view and SIGBUS unblocked. Keep a pin or exclusive owner lifetime through return. Preserve v1 `src/os/os_posix.c:os_fault_test_trigger`'s thread-directed native delivery. Null view/base, out-of-view offset or address overflow gives `OS_E_INVAL`. A failed send returns the translated native error via the regular OS error mapper. `OS_OK` means delivered if the disposition returned. A valid unregistered test range deliberately exercises chaining and can terminate the child. |

An ID can outlive its mapping as inert data. A lease is a linear resource in caller-provided storage. Publish it through an owning object and the usual mailbox/retained-object synchronization. A struct copy, fabrication, concurrent unpin/poll, two retires by competing owners or manual field modification violates ownership. Ordinary release followed by accidental reuse of the **same lease object** is detectable via EMPTY. There is no table of lease-object addresses or promise to detect forged copies. Public error returns use the existing `os.h` native-error convention. The bare `os_fault_epoch(int)` is removed. File code that needs an epoch has to hold a lease too.

## State and lifetime

Use exhaustive enum switches under `-Wswitch-enum`, including when decoding the slot control word. The private slot enum is `SLOT_FREE, SLOT_RESERVED, SLOT_LIVE, SLOT_RETIRING, SLOT_EXHAUSTED`, in that order from zero. The public lease enum is above. The counts measure outstanding obligations, independently of phase. Service installation has enum states `FAULT_COLD, FAULT_READY, FAULT_UNAVAILABLE`, with `pthread_once` serializing the transition from COLD. The prior one-shot disposition uses an atomic enum `CHAIN_ARMED, CHAIN_CONSUMED`. No reset API. The mapping and the registration have separate owners only in the sense that the service borrows the mapping. It never unmaps the caller's view.

| Slot before | Event and actor | Slot after, lease effect and linearization |
|---|---|---|
| FREE | Register, owner thread | Under the normal mutex choose the lowest available index, reserve it, issue the next generation and initialize the range, counts and epoch. RESERVED → LIVE at release publication. The owner then receives the ID. All fallible validation/installation precedes reservation. |
| RESERVED | Register publication by claimant | Only that claimant may advance to LIVE. The handler skips it. The mutex excludes another ordinary operation from seeing partial initialization. |
| LIVE | Pin, ordinary reader | LIVE. A generation match and count increment in one mutex critical section turn EMPTY → HELD. |
| LIVE | Poll, holder or synchronized borrower | LIVE and HELD. The epoch load is the observation point. |
| LIVE | Unpin, exclusive holder | LIVE. Decrement under mutex, HELD → EMPTY. Only explicit retire can close registration. |
| LIVE | Signal on any thread | The handler conditionally acquires a short reader count in the atomic control word, checks the address, handles or skips and drops that count. The slot may become RETIRING while it runs. No public lease changes. |
| LIVE | Retire, owner | With long pins, BUSY at the mutex check. Otherwise a CAS closes LIVE → RETIRING preserving the short count. No new handler or pin enters. Release the normal mutex before waiting. |
| RETIRING | Previously admitted handler finishes | Release its short count and notify the retiring owner on the last departure. Other deliveries skip the slot. |
| RETIRING | Owner completes drain | Under the mutex publish FREE if another generation exists, else EXHAUSTED. The mapping may be released after the owner's success return. |
| FREE, RESERVED, RETIRING, EXHAUSTED | Signal scans slot | Skip at admission, continue scan or chain. A reader legally accessing file bytes always has a LIVE registration via its pin or owner. |
| EXHAUSTED | Subsequent register scan | Permanently skip this index. A register scan also skips other unavailable slots. Exhaustion of the table gives NOSPC. |
| Any | Process exit | The kernel drops mappings, signal disposition and all storage with the process. Ordinary application shutdown first stops admission to jobs, joins/reaps work, drops pins, retires and unmaps. No handler uninstall, table reset, forced unpin or exit-time spin for an abandoned lease. |

For other state/event combinations apply the public errors above. In particular pin and retire require matching LIVE, poll and unpin require HELD, and pin into HELD is illegal. A valid HELD object implies LIVE throughout each operation. The process boundary ends all IDs and leases. No ID is serialized or sent to another process.

## Signal delivery and recovery

**Installation.** Harvest v1 `src/os/os_posix.c:fault_install`, `fault_handler`, `fault_chain` and `fault_recover` with the changes below. Only `fault_install` may install the service. Query page size once, require a positive power of two and cache it. Before installation verify lock freedom at the actual addresses of every atomic touched by the handler (control, epoch, prior-action selector and one-shot enum). Refuse unsupported targets. Initialize a process-local unnamed drain semaphore per slot to zero (P, no pending last-reader notification). Roll back partial semaphore initialization on install failure. Publish prior-action data before making the handler callable. A failing platform check, semaphore setup or either `sigaction` leaves the once result UNAVAILABLE for the process. No slot can become LIVE.

**Slot admission.** The atomic control is an unsigned 64-bit word. Five phase values require three low bits (P, the smallest power of two covering the enum). The remaining 61 bits count transient handler references. Increment/decrement by the first bit above the phase mask, preserving phase. Normal-thread mutex ownership exclusively protects generation and the separate persistent count. The handler never reads either field or takes this mutex, including when it interrupted its owner.

* Save thread-local `errno` on entry. Accept only SIGBUS with valid signal information and code `BUS_ADRERR` or `BUS_OBJERR`. Positive codes on other signals, user-generated `raise`/queue codes, alignment faults and unmatched addresses take the chain.
* For each slot acquire-load control. In LIVE use an acquire CAS to add a transient reference, retrying with updated control on contention (failure order relaxed). Check phase and room on each attempt. Read **all** plain range metadata only after winning the CAS. The acquire reads the LIVE release publication or its RMW release sequence. A stale candidate control value that happens to match a new LIVE word grants access only to the current metadata. No pre-CAS range is carried across this boundary.
* Compare the supplied address to the logical interval using `a >= base && a - base < len`. An unmatched reader releases immediately and continues scanning. Checked disjoint extents ensure one eligible registration per address. Count saturation must never carry into phase or skip a matching range as if it were absent. On supported Linux ABIs it is unreachable (P, each simultaneous increment requires its own live signal frame occupying more than eight distinct bytes in a process with at most a 64-bit address space, so fewer than 2^61 admissions can be outstanding). Treat an impossible overflow as an unrecoverable delivery and chain.
* On a match, publish a saturating epoch increment by atomic CAS, success `memory_order_seq_cst`, failure relaxed. At `UINT64_MAX` leave it permanently tainted. Order the publication before entering the kernel with a sequentially consistent fence. Round the fault address down using the cached page size. Replace from that page to the logical end (the kernel rounds length up) by read-only anonymous private zero pages using v1's `MAP_FIXED | MAP_PRIVATE | MAP_ANONYMOUS | MAP_NORESERVE`, anonymous fd and zero offset. The borrowed rounded extent covers exactly the possible replacement. Prefix bytes survive. Concurrent overlapping suffix repairs within this registration all install the same zero contents. Failed replacement leaves the epoch tainted and takes the chain.
* On **every** exit from an admitted slot, subtract the short reference with an acq_rel RMW. If its prior value was RETIRING with exactly this reference left, `sem_post` that slot's drain semaphore. This is the final handler operation on behalf of the slot. The retire CAS is acq_rel on success, acquire on failure. If it captured a nonzero count, the retire owner must consume exactly one post (`sem_wait` outside the mutex, retry EINTR). A captured zero count requires no wait or post. The semaphore lives for the process lifetime. RMW release sequences, successful wait where needed, and the final acquire observation of closed/zero precede publication of FREE/EXHAUSTED. This handshake supports an interrupted registrar and a descheduled handler without spinning or recycling an outstanding wake. Retirement uses the editor's cooperative cancellation discipline through the wait.
* Restore interrupted `errno` before returning or calling the previous action, and restore it on return from chaining. Signal context uses only stack locals, kernel-provided signal information, protected immutable service data, verified lock-free atomics, the AS-safe drain notification, the recovery mapping primitive and the disposition operations below. No allocation, logger, file object, clock/page-size query, mutex, wait, lazy initialization or piece/work callback. Linux/glibc documents `mmap` as AS-safe. POSIX alone does not guarantee that property for `mmap`. An implementation without an audited AS-safe replacement returns NOTSUP at installation. [GNU C Library, Memory-mapped I/O](https://sourceware.org/glibc/manual/latest/html_node/Memory_002dmapped-I_002fO.html)

**Chaining.** Preserve the one-installer contract in v1 `docs/decisions/edit-177r.2.md` §8 item 1, §3.6 and §9 item 7. Query the previous action into immutable service storage. Publish its selector with release order. Install the new `SA_SIGINFO` action with a single replacing `sigaction(SIGBUS, &new, &old)`, inheriting the prior mask and `SA_ONSTACK`, `SA_NODEFER`, `SA_RESTART` flags as in v1. If publishing the returned action, put the complete struct in the other immutable cell, then release-store its selector. Two cells (P, one safe to read during installation and one for the actual returned action) suffice. A concurrent third-party disposition change breaks the installation contract. Do not install a file-layer handler or rewrite a cell visible to handlers.

`fault_chain` acquire-loads the selector. For `SIG_IGN` return as in v1 (continuing a genuine unrepairable hardware fault this way provides no recovery guarantee). Dispatch a previous custom handler with its proper calling convention, preserving the original siginfo and ucontext for `SA_SIGINFO`. For `SA_RESETHAND` use an acq_rel exchange from ARMED to CONSUMED before the call, so only the first chained delivery invokes it. For `SIG_DFL` or an already consumed one-shot action install the default with `sigaction` and re-raise on the faulting thread with `raise`. A blocked re-raise takes effect on handler return. Failure to establish/default-deliver the fatal action must terminate via async-safe `_Exit(EXIT_FAILURE)` instead of returning into a fault loop. Release every short reference before chaining, including before a previous handler that exits or performs a nonlocal transfer.

## Identity and reclamation proof

**Issue.** Under the mutex, FREE records the last generation issued, initially zero. Register advances it once per successful publication. `uint64_t` matches v1's fault-epoch width and gives `UINT64_MAX = 2^64 − 1` valid nonzero generations per index (P, exact-width unsigned type minus the absent value). On retirement of that final generation, the index enters EXHAUSTED. No increment of a maximum value and no wrap assumption, even for an arbitrarily long process. Indices may repeat after successful retire. An issued pair never repeats within the process.

**Hold.** With generation and phase validation plus the persistent increment in one critical section, the race has two outcomes. A winning pin makes retire return BUSY. A winning close excludes the pin even if reuse has already occurred when the pinner gets the mutex. A retire using an old ID cannot affect a new registration. The persistent count is `uint64_t`, checked before increment and before decrement (P, one unit per independent HELD object). A borrowed poll of a legal HELD object therefore needs only the slot's atomic epoch, with no generation recheck or speculative read/reset race. Application-level publication of the lease establishes visibility of its fields.

**Read.** Poll brackets the epoch load with sequentially consistent fences and uses an acquire load. This orders both prior mapped-byte reads and subsequent reads at the validation boundary on the supported Linux target. Release publication of LIVE orders epoch initialization. Recovery orders its increment before making zero pages visible. A consumer checks for pristine zero before scanning and again after its last byte access, before accepting the result. Equal nonzero values are already compromised, including at saturation. Exactness is as of the validating poll. The next query/adoption polls again. This protocol detects service faults, not arbitrary concurrent writes that generate no SIGBUS.

**Reclaim.** Closing the handler gate and testing its short count in the same atomic transition means an admitted handler completes all range reads, epoch changes and VM replacement before retirement returns. The long count separately covers readers that have not faulted yet. After a BUSY refusal, a holder can still take a real fault and recover. After success a stale saved ID can neither re-pin nor retire the next tenant. The owner remains responsible for preventing raw pointer reads after close and for calling `os_unmap` only after success. A slot pin also excludes owner unmap by contract. It does not retain a C pointer to a file object for the caller.

## Characterization and acceptance tests

These are implementation acceptance oracles. Write the public tests first, record the red and green runs in the implementation bead. Against v1 the new declarations are absent. Also demonstrate a behavioral red with a bare-index adapter or a deliberately omitted pin/generation check in the test build: a stale ID reaches a new tenant, a pinned retire succeeds, or an old epoch resets. The suite must detect each broken invariant independently. Link layer archives, include public headers only and keep fixture files disposable.
