# P2.5 CPU raster backend (edit-e6x.5), Session 5

## Continuation audit and choices

Kept the previous workers' scalar reference, exact four-pixel SSE2 blend,
partitioning, backend-owned snapshots, MT4 WORK_RASTER jobs, diagnostic timings,
XShm storage, off-screen pixmap, X Sync device fence, matching-serial PresentPixmap
completion and IdleNotify tracking, frozen conformance inclusion, tests and bench.
No restart or wholesale revert. Superseded inherited worker-issued uploads
(rollback side effects) and query-after-present ordering (unnecessary T5 window-copy
latency), while preserving the underlying resources and exact kernels. The old
STATUS/decision description referred to GetInputFocus/NotifyMSC; actual
inherited code had already replaced both. Those descriptions are superseded here.

Changed upload ownership: strip workers only raster and publish completion through
work_publish. The UI's event handler uploads each completed strip to the retained
off-screen pixmap, allowing upload to overlap later raster jobs. This prevents a
partially accepted, then cancelled submit from modifying retained pixels. A new
interposed-XShm regression proves that completed workers issue no uploads before
UI mailbox routing. present stays BUSY until all strip results have been handled,
then submits exactly one PresentPixmap at T4. Pixels never reach the window early.

The per-job colour cache now has 64 entries, each with 256 exact pixels generated
by the original SSE2 blend. Glyph coverage is freshly read on every raster: the
cache contains colours only, never atlas-derived glyph images. A maximum of 64
table rebuilds per job bounds adversarial colour churn; subsequent misses use the
original direct SSE2 cell kernel. Cache storage is reserved in caller-owned backend
state at init, separately owned by each of the four jobs, and retained between
frames. Scalar, direct SSE2, streaming SSE2 and cached paths remain pixel-exact.
The cache's rebuild count is reset per job; no allocation happens on that path.

Rejected the eight-pixel, three-channel SSE2 experiment after alternating paired
measurements put it behind the original kernel (15 px median ratio 1.118, 30 px
1.053 (M)[bat], loaded). Removed its code. Kept the inherited streaming kernel as
a tested benchmark candidate; the paired run did not justify making it default.
Expanded the palette from 32 to 64 slots: the deterministic bench's 16 colour
pairs collide in two 32-slot buckets, and occupy distinct 64-slot buckets. General
workloads are protected by the rebuild bound, rather than a benchmark-specific key.

Fence polling rechecks XCB's reply queue after any event progress, because an event
poll can consume the socket and leave the fence reply in XCB's internal queue.
It sleeps only after a pass makes no progress; cancellation/deadline remain bounded.

## T5, T6 and allocation scope

T5 is an asynchronously observed X Sync QueryFence reply, not source-buffer reuse:
reset/trigger the device fence after every staged upload, then AwaitFence/QueryFence,
then queue PresentPixmap with that wait fence. Query is deliberately before the
scheduled window copy: the device endpoint concerns uploaded raster pixels, while
T6 concerns display. A second request-sequence regression first failed on the
inherited query-after-present order and passes with query-before-present. Worker polls nonblocking and publishes its
observation; UI routes it to render_backend_signal. The common adapter clamps T5
to T4. No *_reply wait occurs on input, mutation, layout, submit, present or event;
blocking X setup is confined to init, which runs on a worker.

T6 uses PresentCompleteNotify with matching frame serial and PIXMAP kind, observed
in CLOCK_MONOTONIC time (raw UST is retained diagnostically, never passed as a
monotonic timestamp). Frame completion waits for IdleNotify as well, ensuring the
single retained pixmap is no longer in use before N+1 can upload it. The benchmark
skips nonadvancing MSC or skipped pixmaps; Xvfb scroll observations are TRACK only.

Law 2 follows the settled user amendment D: our code allocates zero times from
input through mutation/layout/submit; libxcb's internal packet/reply allocations
are exempt. The included frozen conformance suite disables its whole-frame guard
as requested; dedicated release tests and the bench assert zero allocations from
grid mutation through submit. Present-path interposition reports libxcb allocation
counts separately. No frozen render/work/font/platform headers or tests were edited.
