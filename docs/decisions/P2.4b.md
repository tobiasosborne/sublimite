# P2.4b — cell upload experiment (edit-e6x.9)

Status: candidates prepared; real-display latency measurements and pick belong
to the coordinator. The EGL pick in P2.4/P2.4-egl remains in force. No production
caller is switched and `render.h` is unchanged.

## Selection and controlled comparison

`EDIT_GL_UPLOAD=subdata|orphan|persistent` is read only at backend init. Unset
preserves the existing expanded-instance renderer, its default orphan upload,
and its `EDIT_GL_VBO` persistent/fallback behavior. Invalid new modes are errors.
An explicit new persistent request requires ARB_buffer_storage; it does not
silently benchmark orphaning. The GL context remains 3.3 core plus that extension.

The three new candidates share the raw `render_cell` shader and metadata path:

* (a), `variants/P2.4b/a`: layout writes a CPU cell array. Submit snapshots the
  damaged rows into init-reserved CPU storage; present uses glBufferSubData.
* (b), `variants/P2.4b/b`: same CPU layout and snapshot. Present first calls
  glBufferData with NULL, then glBufferSubData for each damaged row run.
* (c), `variants/P2.4b/c`: full layout writes directly into a coherent mapped
  cell region. Submit consumes that region without a cell copy or instance
  expansion; present issues draws against that region's byte offset.

(a) is the cell-array/subdata baseline for this controlled comparison, rather
than the old shader's expanded-instance ABI. All three opt-in shaders derive
position from the row-major instance index, read fg/bg/attrs directly from the
frozen cell, and resolve atlas_slot through a small RGBA32UI texture buffer.
Glyph metadata and referenced atlas pixels still have CPU snapshots/uploads;
“zero-copy” describes the cell grid, not all renderer resources. Ordinary
caller-owned grids submitted to (c) retain copy-on-submit behavior; the bench
uses its mapped lease to exercise the direct path.

Each candidate's `gl.c` includes the shared source with its init default.
`src/gl/gl.c` contains only selection and a forwarding include: the shared
legacy/experimental renderer is in `variants/P2.4b/renderer.inc`. Force-add that
include along with the candidate directories; the source shim depends on it
until a promotion bead moves the chosen renderer back into src/.
`build.sh` links the identical bench/test objects against each candidate; there
is no benchmark fork. Object .text includes all runtime branches, so size is
not a dead-code-eliminated size prediction for a future promoted winner.

## Fence ring, ownership, and coherence

(c) allocates one immutable GL buffer with three max_cells-sized regions at
init. Storage and mapping use GL_MAP_READ_BIT | GL_MAP_WRITE_BIT |
GL_MAP_PERSISTENT_BIT | GL_MAP_COHERENT_BIT. READ is necessary because frozen
validation and partial-frame preservation read CPU-written mapped cells too.
No map/unmap or allocation occurs during typing. Mapping and GL resources are
created on the init worker; context binding, uploads and draws remain in present.

`gl_cells_acquire(backend, grid, preserve)` is a UI-only, CPU-only lease. It
requires an idle adapter and a free next region. It inspects cached fence state;
it returns BUSY instead of binding GL, waiting, or overwriting a pending region.
Full layout uses preserve=false and initializes every active cell. The backend
initializes all regions to valid blank cells at init. Partial layout uses
preserve=true: it copies the previous submitted grid between mapped regions,
then layout writes just the changed rows. That retained-grid copy is timed and
is an explicit limitation of this experiment, not hidden zero-copy typing.
The frozen validator checks every cell, including undamaged rows.

`gl_cells_submit` calls the ordinary validating adapter. On success it revokes
writable access by setting grid.cells=NULL; the next frame must acquire again.
Saved pointer aliases must not be written after successful submission. On a
validation error the lease remains writable and the same frame can be repaired
and retried. An acquired but abandoned lease can be retried or discarded at
quiescent shutdown; there is no cancellation API in this experiment.

Each region gets its own resource fence immediately after draws that read it,
before blit/swap can fail. Present retries replace that fence with a later one
in the same GL command stream. A failed fence creation poisons reuse. Events
poll each outstanding region fence once with zero timeout; only signalled
fences are deleted and mark a region free. TIMEOUT leaves it read-only;
WAIT_FAILED returns DEVICE. The separate existing post-swap fence supplies T5,
and matching PIXMAP Present completion supplies T6 with the original frame ID.
Thus ring reuse and displayed-frame completion are separate concerns. Shutdown
binds the context, finishes pending work, deletes both types of fences, unmaps,
and destroys storage. Resize still requires idle and the next frame is full.

Coherent CPU stores performed before a draw on the same UI thread become visible
to GL without glFlushMappedBufferRange or an explicit client-mapped barrier.
Coherence does not remove write-after-read hazards: region ownership and fences
provide that exclusion. Native calls and fence polling remain outside the
input-to-submit allocation boundary. The frozen adapter still permits only one
submitted frame until T5 and T6; three storage regions do not enlarge that queue.

## Frozen contract proposal, if promoted

The ordinary render.h API says callers own their grid storage and can modify it
immediately after submit. A borrowed mapped lease cannot carry that promise.
This experiment exposes ownership transfer only through the GL-specific paired
acquire/submit API, while ordinary CPU grids keep the frozen guarantee. It is
not wired into the editor's generic backend selection.

A promotion bead should propose backend-neutral acquire/cancel/submit-lease
operations in render.h: backend-owned writable storage before submit, revocation
on success, retryable validation failures, explicit cancellation, and reacquisition
only after resource fences. The same bead should specify retained-row storage
or damage-only lease validation to avoid the mapped-to-mapped full-grid copy on
partial edits. No frozen header is modified here.

## Expected effects and measurement limits

(E) Full frames should avoid the CPU snapshot, expanded-instance construction,
and cell upload calls in (c). (a)/(b) send smaller cell records than the legacy
expanded instances. (E) The shader adds glyph-metadata texture-buffer fetches;
that GPU work may offset CPU savings on full frames. Orphaning may avoid implicit buffer reuse synchronization
but costs storage replacement; queue-one/T5 retirement already reduces that risk.
(E) Partial frames may see little gain, or a loss: the coherent mapping is read
by validation and preservation, the retained-grid copy remains, and (c) creates
an additional resource fence. Hardware memory/cache behavior decides the pick;
no speedup is claimed from software rendering or object size.

The focused benchmark uses the same deterministic synthetic full-grid layout
and single-row typing change in each candidate, with timing starting before
acquire/preservation/layout/validation/submit. G3 ends at T5; the typing strip
ends at T4. It excludes actual input ingress, document mutation, source decoding,
and minimap work, so the typing row is a G1 microbenchmark, not an end-to-end G1
verdict. Full frame reference target A is 5.0/5.56 ms p50/p99 (G); typing reference
is 1.0/2.0 ms (G). Every sampled frame counts allocations through submit. These
candidate runs report TRACK even on AC; they never choose a winner automatically.
