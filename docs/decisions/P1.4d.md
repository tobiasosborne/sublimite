Scope: findings §1, §2 and §11 in `docs/reviews/P1.4-1.md`, on the persistent
B+ synthesis described in `P1.4-synthesis.md`. The public header and frozen
conformance suite are unchanged. Findings §3–§10 remain separate beads.

## Design

Snapshot headers keep their existing `atomic_uint` layout and impose a hard
`UINT_MAX` owner cap. Retain uses a relaxed checked CAS loop; a retain or cached
take at the cap returns NULL, the existing snapshot failure representation.
No mapping acquire happens on refusal. Release decrements normally, so a
subsequent retain can succeed once capacity returns. The cap includes the
tree's cache owner. This avoids both wrap and permanent pinning, without a
new public error or a larger pool slot. Callers must still hold an existing
owner while retaining, as required by the lifetime contract.

Both insert APIs preflight logical growth before invalidating the snapshot
cache or cursor, allocating, copying, or changing a node. `piece_insert`
checks the remaining `uint64_t` capacity. `piece_insert_ref` validates each
physical span, checks the sum of its actual span lengths, then checks that
sum against the document capacity; it does not trust the redundant `ref.len`
field. Unrepresentable growth returns `PIECE_ERR_RANGE`. Empty operations
remain successful at EOF, including EOF equal to `UINT64_MAX`.

Internal document, subtree, leaf-piece, add-buffer and reference-span length
additions use checked arithmetic. An internal overflow is an invariant
assertion: public preflight and the existing add-buffer reservation bounds
prove these additions fit before mutation begins. The normal branches are
never taken on valid content. Chunk rounding uses quotient and remainder
instead of an unchecked `length + CH_MASK`. These changes add no allocations
or globals to production paths.

The high-offset test found an additional failure inside this boundary scope:
`ent_data + off - start` in cursor deletion forms an invalid intermediate
pointer near `UINT64_MAX`. Compute `off - start` before pointer addition.
The cursor deletion/rebalancing policies from findings §3 and §8 are unchanged.

Private hooks are guarded by `PIECE_TESTING` (including the existing ASan
auto-enable). Normal release objects contain no `piece_test_*` exports. The
owner hook temporarily supplies fake owners without mapping hooks; tests
restore the real count before final releases. A repeated-byte fixture uses
ordinary refcounted shared children and an exact partial rightmost path to
represent lengths up to `UINT64_MAX` with bounded storage. Its newline counts
are zero and its leaf spans still reference a real add-buffer byte. Tests must
not exhaustively iterate/count its astronomical number of logical pieces.
A separate rejection-only physical-add-length hook permits overflowing span
sums without allocating an enormous add buffer; it is restored before reads
or successful mutations. A refusing allocator protects even the red probe
from enormous reservations.

## Permanent coverage

`tests/piece_bounds_test.c` is discovered by the unchanged Makefile. It covers
saturating retains/takes and mapping balance, fast cursor and snapshot COW
growth refusals, exact maximum lengths, multi-span sums, no-op EOF operations,
and tree/cache/cursor/append-state identity on refusal. Its ordinary public-API
fixture replays a 64 KiB payload reference 65,538 times, exercising reads,
line maps, iterators, mutations, range refusals and snapshot survival across
the 32-bit boundary. `tests/piece_mt_test.c` races four retainers for the last
owner slot and requires exactly one winner.

The fuzzer adds full-width decodes, frequent EOF/maximum/high-bit positions,
snapshot/tree queries and iterator starts, saved references that may be
replayed repeatedly, and test-only near-maximum growth fixtures. Model growth
from repeated replay is bounded; the maximum-length fixture uses small shared
nodes rather than a flat model. This preserves useful fuzz throughput without
large physical files. `/tmp/edit-corpus` was used unchanged for the quick bench.
