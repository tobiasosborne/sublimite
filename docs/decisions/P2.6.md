# P2.6 — paired reference window and phase-locked key injection (edit-e6x.6)

The reference draws one baked ASCII glyph through `render_cpu_backend`, the
same raster, XShm, X Sync fence and Present adapter used by the editor. The
optional EGL reference is not implemented. No backend, frozen header or
Makefile changes are needed.

## Window and timing boundaries

`tools/refwin.c` uses `plat_init` to create a bare xcb window with the baked
glyph's cell dimensions. Its event loop consumes raw xcb key presses directly;
there is no editor buffer, mutation, layout or toolkit. The default glyph is
ASCII `a`, and the default keycode matches `a` in the tested Xvfb keymap. Use
`--glyph` and the matching `--keycode` for another keymap. Each press swaps the
glyph's foreground/background, guaranteeing a visible change even when the
same key is repeated. The window requests `_NET_WM_BYPASS_COMPOSITOR`; the
compositor is free to ignore this request.

Storage, baked atlas descriptors, workers and backend resources are reserved
at startup; backend initialization runs on a worker. Each raw press runs an
allocation guard over mutation through `render_backend_submit`. Present
requests, libxcb event/reply allocations, metadata replies and CSV writes are
outside that guard. The reference does not allocate or print between handling
the press and submitting its frame. Timestamp hooks only retain the original
frame ID's timestamps. Startup has its own frame and is excluded from samples.

T4 is the common adapter's exact `submitted_ns`. T5 is its matching-frame hook:
fence/device completion bounded by submission. T6 takes the earliest matching
Present observation from the platform connection and the backend hook, just
as the editor trace loader's first-occurrence rule does. Both completions must
be at least T4. The reference waits for both backend hooks even when the
platform observation supplied the earlier T6 timestamp. Their observation
order can differ, so the harness does not invent a T5-before-T6 constraint.
All timestamps are `CLOCK_MONOTONIC` nanoseconds.

The injector sends key down and key up, flushes them, and then sends reference
metadata using a tool-only property and ClientMessage. The server orders these
on one connection. The reference submits on the key itself, without waiting
for metadata, and joins the metadata only after completion. A completed-frame
property acknowledges the row; a consumed property lets the finite reference
exit without racing the injector's final read. CSV writes happen after both
completion hooks and before that acknowledgement. No more than one injection
is in flight. Protocol storage is local to each tool instance.

## Injection, MSC and pairing

`tools/keyinject.c` loads `libxcb-xtest.so.0` with `dlopen`. This host has the
runtime library but lacks `xcb/xtest.h` and the `xcb-xtest` pkg-config package.
The tool declares the narrow FakeInput ABI locally and uses existing global
`-ldl`/xcb libraries. It checks XTEST availability and press/release request
errors. If unavailable, it sends directed XSendEvent key events and prints the
synthetic-input caveat. `--send-event` forces that fallback for verification.
Fallback observations are TRACK, never a physical-input/optical gate verdict.

Focus and its roundtrip precede phase sampling. For an editor target, a bounded
setup wait drains focus/cursor presentations before injection. Exact identity
is still verified offline; this wait alone cannot prove that a frame contains
the key. NotifyMSC serials use the upper serial range to avoid collisions with
ordinary editor/reference frame IDs. This matters because other Present
listeners on the window can also observe NotifyMSC events.

Present NotifyMSC supplies UST/MSC. Linux Xorg/Xvfb UST is used as monotonic
microseconds and converted to ns; a future UST or an implausibly distant clock
is rejected. This is a local-display clock assumption, not a clock-correlation
implementation for remote X servers. `clock_nanosleep` with an absolute
monotonic deadline schedules the chosen offset after the MSC anchor. The
refresh period is explicitly configurable; the default period of 16,666,667 ns
is (E), not a measured physical refresh rate. The coordinator must configure
the real display's period for its later run.

`msc` is the observed MSC phase anchor, not a counter extrapolated from the
configured period. `actual_phase_ns` retains injection minus anchor UST without
wrapping: a missed refresh remains visible and makes a joined run fail. The
injection timestamp is taken immediately before enqueuing the press, not at a
physical switch or the X server's delivery time. Xvfb has no real vblank; its
MSC phase locking is approximate and cannot establish G2c.

With `--editor-window`, the driver uses the same keycode and requested phase
for both targets, with target order reversed on alternate pairs. Otherwise
separate runs can use matching `--first-pair`, `--seed` and period settings.
Without `--phase-ns`, a seeded PRNG chooses a phase once per pair. Failed or
timed-out runs return nonzero and retain an incomplete CSV; the join requires
the expected pair count, including the final pair. Samples are not silently
dropped or retried to obtain favorable timings.

## CSV and offline join

Both tools use this header (all integer timestamps/offsets are ns):

```text
pair_id,target,inject_ns,msc,t4_ns,t5_ns,t6_ns,frame_id,phase_ns,period_ns,actual_phase_ns
```

Reference rows contain all timestamps. Editor injection rows initially have
zero T4/T5, the observed next Present serial as `frame_id`, and an informational
T6 observation. Zero means unavailable, never zero latency.

`tools/refwin_pairs.py` reads the editor's native EDTRACE1 rings and requires
exactly one key dequeue (T1) between an editor injection and the next injection
in the combined run. Its frame ID must equal the captured Present serial.
Then it supplies that frame's traced T4/T5/T6. A focus/blink frame, coalesced
keys, missing endpoints, duplicate rows, unmatched metadata, invalid clocks,
phase slips or missing pairs cause failure. The optional reference CSV is
cross-checked against injection metadata and any existing endpoints.

The coordinator supplies `--phase-tolerance-ns`; the join checks both requested
phase equality and actual phase matching. The headless test uses a loose
16,000,000 ns tolerance (E) solely for Xvfb's functional check. This is not a
real-display matching tolerance or a latency gate. The helper validates the
entire run before writing its complete timestamp and difference CSVs.

For each pair and stage it computes
`(editor_stage - editor_inject) - (reference_stage - reference_inject)`.
Negative differences remain negative. It reports nearest-rank percentiles of
those differences, rather than subtracting marginal percentiles. T6 is a
Present endpoint, not photodiode evidence. G2c's optical p50/p99 limits are
1/3 ms (G); the coordinator-announced real-display run remains outstanding.

## Commands (headless display only)

```sh
DISPLAY=:99 EDIT_DISPLAY=:99 make all
DISPLAY=:99 EDIT_DISPLAY=:99 ASAN_OPTIONS=detect_leaks=0 make check
DISPLAY=:99 EDIT_DISPLAY=:99 make fuzz
DISPLAY=:99 EDIT_DISPLAY=:99 build/tests/refwin_test --send-event
```

`refwin` prints a numeric window ID to `--ready-fd` (stdout by default), only
after the startup frame completes. CSV requires its own named file. To use an
already launched headless editor with `EDIT_TRACE_DUMP` set, substitute its
window ID and the numeric reference ID:

```sh
DISPLAY=:99 EDIT_DISPLAY=:99 build/tools/refwin --pairs 12 --csv /tmp/reference.csv
DISPLAY=:99 EDIT_DISPLAY=:99 build/tools/keyinject \
  --window REFERENCE_ID --target reference --wait-reference \
  --editor-window EDITOR_ID --pairs 12 --seed 42 --csv /tmp/injections.csv
# Close the editor normally so its quiescent EDIT_TRACE_DUMP is written.
python3 tools/refwin_pairs.py /tmp/injections.csv \
  --reference-frames /tmp/reference.csv --editor-trace /tmp/editor.trace \
  --pairs 12 --phase-tolerance-ns 16000000 \
  --csv /tmp/complete.csv --differences /tmp/differences.csv
```

The fixture counts and phase settings in these commands are functional-test
configuration (E), not a gate-sized measurement. No real display was used.

The failing test was written and run before either tool existed:

```text

```

The test compiles the exact tool sources into both its release and sanitizer
binary, so `make check` works without a prior release tools build. It launches
the actual editor API in another process, alternates injections, verifies the
editor received the expected text, joins its quiescent trace, and checks both
targets' complete/monotonic CSV. Missing final pairs and deliberately wrong
Present serials are negative controls. XTest and forced XSendEvent work on :99.
The release reference's real allocation guard passes; ASan's guard is inert.
