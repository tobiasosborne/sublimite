# P2.3b (edit-e6x.8): font fallback discovery, no-malloc raster, 15 px atlas

## Decisions
- **stb allocations**: `STBTT_malloc/STBTT_free` are defined in font.c before the stb include. malloc takes `info->userdata`, a `font_stb_ctx{arena, failed}` living on the stack of `font_raster_glyph`; userdata is NULL otherwise, so any stb allocation outside a raster call returns NULL (metrics paths never allocate in stb, verified by the guard test). Scratch is allocated after the bitmap and released by rewinding to a mark; free is a no-op. Arena exhaustion inside stb gives `FONT_ERR_NOMEM`.
- **Guard test**: `tests/font_test.c` asserts 0 libc malloc/calloc/realloc over 600 rasterisations. The guard is compiled out under ASan, so the assertion is enforced by the release binary `build/tests/font_test`; the san binary prints a skip. Red: 3300 mallocs (5.5 per glyph) before the change; green: 0.
- **Atlases**: `font_ascii_atlas` struct (px, cell, metrics, pixels). 15 and 30 px are baked. `font_ascii_atlas_for_px(px)` selects by px. `font_t.atlas` is set in `font_set_px` only if all 95 baked metrics and the cell equal the live font's values, so a different face (CJK fallback) never inherits DejaVu pixels. The old no-argument `font_ascii_*` API stays, bound to the 30 px atlas. atlasbake got an optional symbol suffix (`_15`); generated tables are `static const`. Re-baking 15/30 through the new arena path gives byte-identical pixels.
- **Discovery**: `font_fallback_job` (work_job fn) calls `font_fallback_discover(fb, "libfontconfig.so.1")` on a worker, then publishes `FONT_FALLBACK_MSG_KIND`. Fixed storage in caller-owned `font_fallback` (paths <= 512 bytes, `done` atomic with release/acquire). Local Fc prototypes, dlsym-bound; if the library or any symbol is missing, `have_fontconfig = 0`, empty paths, no error. Queries: U+4E2D with lang zh; U+1F600 with color=false, rejecting colour fonts and verifying the match's charset (FcFontMatch always returns something). FcConfigDestroy + FcFini run after copying paths (else LSan reports ~295 KB); the dlopen handle is not closed. Fontconfig itself mallocs; that is off the typing path.
- **TTC**: `font_init` uses `stbtt_GetFontOffsetForIndex(ttf, 0)` so `.ttc` collections load. Noto CFF outlines rasterise fine with the vendored stb.
- `font_load_file` reads a font file into an arena (no malloc).

## Box results (M)[bat], loaded
CJK found: /usr/share/fonts/opentype/noto/NotoSansCJK-Regular.ttc. Emoji (monochrome): /usr/share/fonts/truetype/dejavu/DejaVuSans.ttf (DejaVu has U+1F600 as a monochrome glyph; the colour Noto emoji is correctly rejected). Discovery ~19-30 ms. Raster p50: e-acute 4.0 us (gate 50 us), U+4E2D 4.4 us.

## Not fixed
- `font_init` reads stb tables without bounds checks against `len`; a corrupt system font could read past the buffer. Needs a fuzz target (fuzz/font_fuzz.c) and a pre-validation pass of table directory offsets.
- Discovery picks index 0 of a TTC (JP in Noto CJK); the lang query's index is ignored.
