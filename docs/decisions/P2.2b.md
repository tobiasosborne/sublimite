## Clipboard (src/x11/clip.c)
- INCR both directions. Serving: chunks of at most 256 KiB (CHUNK_MAX, also bounded by max request length) from an immutable refcounted snapshot, so a replacement mid-transfer does not corrupt it; up to 16 concurrent serves, 8 jobs. Receiving: chunks appended to a bounded buffer. Bounds: 64 MiB per buffer (DATA_MAX), 128 MiB owned budget. Nothing blocks the loop; all progress is event/poll driven.
- MULTIPLE (ATOM_PAIR, max 64 pairs), TIMESTAMP, STRING fallback (Latin-1, converted per chunk without splitting UTF-8), per-selection property atoms so concurrent receives do not collide.
- Request timeout 5000 ms (E: ICCCM gives none) for every phase (owner confirmation, convert, each INCR chunk, serve stall, SelectionClear ack). Driven by x11_clip_deadline() folded into the existing poll timeout in plat_run_for; expiry runs in x11_clip_poll. A stalled peer therefore costs a table slot for at most 5 s, never the loop.
- CLIPBOARD_MANAGER SAVE_TARGETS on plat_shutdown: bounded wait of 1000 ms for the manager's reply (x11_clip_save_on_exit), skipped when nobody owns CLIPBOARD_MANAGER or we own nothing; data served to the manager via INCR if large.
- #6 stale SelectionClear/Request timestamps are checked; #7 unsolicited SelectionNotify rejected, INCR reply no longer wedges the owner.

## Test infrastructure root cause (plat_init "intermittent failure")
x11_clip_test failed at its second plat_init in the same process (rc -1 = PLAT_ERR_NO_DISPLAY, i.e. xcb_connect failing). Cause: the private Xvfb in tests/x11_xvfb.h reset itself when the last client disconnected (plat_shutdown of the first plat), and a reconnect inside the reset window is refused. plat_init was correct. Fix: start Xvfb with -noreset. Evidence (M): without -noreset 24 of 30 runs failed (loaded box; 5/30 on a quieter box), with -noreset 0 of 50. The remaining flakes (20 MiB INCR checks, 6/50) were test timeouts under ASan on a load-average-15 box; limits raised to 10 s / 30 s (pump_until returns early, so no cost when fast). Same cause explains gl_test's second-init failure in the e6x.4 worktree: use -noreset.
