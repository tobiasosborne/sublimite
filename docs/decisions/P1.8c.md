## §3 — epoch reuse

Verdict: confirmed. Retire a slot before incrementing past its last valid
submission identity; reserve the final increment for cancellation. Shutdown
saturates instead of wrapping. Test retained epoch 2 across the injected wrap
boundary, final submission/cancellation, and refusal when all slots retire.
**Semantic clarification:** identities never repeat within an initialized
pool lifetime. All handles become invalid at shutdown/reinitialization and
must be discarded; they may never be passed to another incarnation or pool.
Reinitialization deliberately resets identities. Widening existing fields

## §7 — bulk cancellation and foreground capacity

Verdict: confirmed. Serialize submit selection and cancellation with worker
dequeue. Cancel compacts the matching queued entry in place, preserving FIFO,
and releases busy immediately; dequeued jobs retain busy until return.
**Semantic change:** with raster workers, bulk may use only the shared prefix;
the final `WORK_MAX_RASTER + 1` slots are reserved for a complete foreground
worker batch plus completion. Raster prefers the reserved suffix, then uses
shared slots. Bulk-only pools retain the original full capacity. Cancellation
now takes the queue mutex and performs a bounded ring scan/compaction rather
than a lock-free O(1) operation. Tests cover cancellation churn, uncancelled
bulk saturation, live raster execution while bulk is blocked, and FIFO removal
at first/middle/last entries across ring wrap.

Finishing run: the authorized cross-module test adjustment is now applied to
`tests/journal_test.c` (old assertion at line 1069 after rebasing; previously
line 935). Replace `submitted==WORK_MAX_JOBS-2` with the exact equality
`submitted==WORK_MAX_JOBS-WORK_RASTER_RESERVE-1`. The configured raster worker
puts the other module's job in the reserved suffix; its slot does not reduce
the shared bulk quota. The unread journal completion still reserves one
shared slot. Filling the remaining bulk slots must therefore leave exactly
that one slot unavailable. Equality is retained, so premature release of the
journal completion's reservation still fails the test. Submission/cancellation
setup and the subsequent `journal_flush(j)==0 && other_count==1` check are
unchanged: the journal must flush successfully under bulk saturation and

## §8 — UI drain slices

Verdict: confirmed. Add `work_mailbox_drain_bounded` (examined-message limit,
absolute monotonic deadline) and `work_mailbox_pending`. Count stale messages
against the limit too. Rotate mailboxes between consumed messages so a busy
bulk mailbox cannot starve raster delivery. Re-arm eventfd whenever backlog
remains, including zero-count or already-expired slices.
Notification reads/writes retry `EINTR`; `EAGAIN` on re-arm means eventfd is
already readable.
**Semantic change:** existing drain now uses a finite message limit and the
(G) 0.5 ms between-callback deadline; it may return a partial count or zero
while stale backlog remains. Callers check input between calls and continue
on readiness/pending. Individual callbacks must themselves be bounded; a
single callback or OS descheduling can overrun the deadline. No clock-based
claim of a hard maximum for arbitrary callbacks is made. Tests exercise count,
expired deadline, stale-message budget, fairness, continuation readiness, and
post-shutdown cleanup. No cross-module implementation changes were required.

```text
RED   work_test: section8 slice_delivered=256 continuation_ready=0
GREEN work_test: section8 slice_delivered=1 continuation_ready=1
GREEN work_test: section8 explicit_budget_fairness_shutdown_drain ok
```

Finishing-run full-suite verification also exposed the same contract change in
`tests/raster_test.c:787` (`strip_delivered`). Its saturated-mailbox fixture
publishes unrelated traffic before essential strip/fence/Present messages.
The collection loop may stop when the worker finishes, and one final bounded
drain need not reach the essential messages. After confirming the worker is
finished, both final collection steps now drain while
`work_mailbox_pending(&pool)` is true. There are then no active producers, so
this consumes the remaining finite backlog using the public continuation
contract. Full-ring setup, publication retry, exact message counts, strip
slot/epoch identity, and fence-before-Present order checks are unchanged.
No raster or work implementation change was required. The focused existing
review test was reproduced RED before the test-only fix and GREEN afterwards.
