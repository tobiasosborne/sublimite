Source: `docs/reviews/P2.5-1.md`, sections 1–8, 15 and 17 only.
No frozen headers, work implementation, benchmark, or other modules were edited;
`render.c` changes are solely the section-6 submission budget/validation work.
New test functions are appended after the existing raster tests. A private backend

## 1 — valid; fixed ownership authentication

Match work slot, epoch and generation against the owned strip/fence handle before
changing state or uploading SHM. Strip index must identify an actually submitted
job. Explicit completion flags handle duplicates even with zero-duration timings.
Foreign messages return UNSUPPORTED in raster; the frozen adapter still rejects
stale frame IDs with FRAME before dispatch. The paused-worker fixture rejects
foreign strip, fence, Present and failure messages, verifies no upload/state
change, and exercises authentic and duplicate strip/fence/Present results.

## 4 — valid; proposed work primitive, NOT fixed

`work.h` exposes only single-job enqueue and logical cancellation. Returning
without waiting after partial enqueue would retain owned jobs, violate frozen
failed-submit semantics, and allow snapshot/SHM reuse while workers still run.
Reading free-slot counts is not an atomic reservation and must not be used as one.

Propose `work_submit_batch(pool, jobs, count, handles)`: UI-only, allocation-free,
reserve slots (including undrained-message ownership) and queue capacity under
work's mutex, initialize every job, then publish the whole batch. Capacity or
shutdown failure must enqueue nothing and leave output handles unchanged. Raster
would replace its submission loop/rollback with this call. Add work-module tests
for saturation, cancellation, pending messages, and worker wakeup after full
publication. This requires another module, so no implementation was made here.

`--review 4` remains an explicit expected-RED probe, excluded from normal tests.
It models an owned cancelled slot queued behind unrelated work; a helper releases
it after 100 ms. The UI cannot meet even this loose 20 ms test bound (G). Power
before the probe: Full [AC], 1-minute load 4.26. The sleeps are fixture controls,
not performance acceptance evidence.

RED: `raster_test:552: FAIL elapsed < UINT64_C(20000000)`

GREEN: unavailable until the proposed work primitive lands. No false closure.

## 5 — valid; fixed essential-message delivery

Strip, fence, Present and failure publication share cancellation-aware retry with
worker-side backpressure. A full mailbox cannot lose the completion; UI draining
permits delivery, cancellation/shutdown stops retry. No new private shared flags
or UI waits. Tests inject repeated failures, exercise cancellation while blocked,
and saturate a real single-raster-worker mailbox before strip and fence work;
after draining unrelated messages, all essential results arrive with authentic
work handles. Delivery through work also retains the slot until messages drain.

RED: `raster_test:570: FAIL review_message_count == 1 && review_publish_calls == 4`

GREEN: `P2.5b section 5: GREEN`

## 6 — valid; fixed glyph work ceiling and duplicate validation

CPU frames may bind at most `RASTER_FRAME_GLYPH_LIMIT` = 4096 descriptors (G,
implementation work bound), including unused bindings and zero-damage frames.
Reject oversize tables before scanning or copying them. Init capacity does not
increase this per-frame limit. Snapshot copying is consequently bounded too.
The adapter validates atlas metadata once; the shared cell-validation helper
preserves the frozen requirement to validate ALL active cells. Public
`render_grid_validate` still validates the entire atlas and grid as documented.

Regression: the valid 500,000-entry review repro is rejected without activation
or frame-ID consumption; the exact cap submits, cap+one fails even with no
damage, an invalid unused last descriptor is rejected, and a one-row frame at the
cap has no guarded submit allocation. The adapter-only case uses null operations
with the raster capability, keeping capacity/error checks independent of X.
An optional Target-A viewport `--review budget-track` self-check also uses actual
CPU snapshot/enqueue operations with a paused deterministic scheduler; it times
mutation/damage/validation/snapshot and checks allocations. It is TRACK, not G3.

Layout must bind a compact frame-local table within this ceiling. Exporting such
bindings from layout is outside this bead; no silent clipping/remapping was added.
An incremental atlas/cell validation contract permitting larger tables would
require a frozen render-header amendment and a new bead. The hard ceiling is
usable now; quiet-hardware calibration/integration remains the coordinator's work.

RED: `raster_test:606: FAIL rc == RENDER_ERR_CAPACITY`

GREEN: `P2.5b section 6: GREEN`

## 7 — valid; fixed bounded cancellation tiles

The worker uses a new exact cached/SSE2 cancellable kernel. Tiles contain at most
256 output pixels (G, work bound), combining pixel rows for narrow cells and
splitting wide rows. Check before each cell and tile; palette generation is also
fixed-size. Thus neither cell dimension determines the cancellation interval.
No partial cancelled strip completion is published/uploaded. The large-row
regression stops inside a row, checks an initial write and untouched tail. The
fuzzer compares completed tiles with scalar output, interrupts arbitrary tile
checks, independently bounds stores between checks, and checks stride padding.

RED: `raster_test:622: FAIL tail_untouched && began && review_stop_calls >= 3`

GREEN: `P2.5b section 7: GREEN`

## 8 — valid; fixed immutable work handoff

Remove the private `armed` atomic and post-enqueue field writes. Fence jobs read
only a fully initialized backend-owned snapshot of connection/special-event
resources, pixmap, frame and query sequence, handed off by `work_submit`.
UI retains an issued-presentation phase on capacity failure and retries only
snapshot enqueue, so PresentPixmap is never duplicated. The test fails the first
enqueue, checks one issued Present, retries, and executes the worker *inside*
the successful submit boundary before it returns: both completions are correct.
No new work primitive is needed for this retained phase; section 4's atomic batch
proposal is independent. Snapshot storage is retained until worker quiescence.

RED: `raster_test:633: FAIL review_presents==1`

GREEN: `P2.5b section 8: GREEN`

## 15 — valid; fixed row-local destination documentation

Keep the established row-local convention used by raster, tests, fuzzer and bench.
`raster.h` now explicitly requires the first pixel row of the requested cell row
and gives the full-surface offset formula. Changing the kernels to a surface
origin would break those existing callers, including the separately owned bench.
A declaration self-check is the RED for this documentation change; independent
full-surface tests verify distinct row backgrounds, placement, untouched rows and
stride padding for scalar, SSE2, streaming and cached entry points. The placement
checks use an explicit caller offset rather than differential agreement alone.

RED: `raster_test:651: FAIL strstr(doc,"first pixel row of the requested cell row") != NULL`
