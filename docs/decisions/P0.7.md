# P0.7: token-budget stop hook for workers (edit-yy5.7)

## What it does
`tools/hooks/token_budget.py` runs as a PostToolUse hook (project settings `.claude/settings.json`,
matcher `*`, `python3 -I "$CLAUDE_PROJECT_DIR/tools/hooks/token_budget.py"`, timeout 5 s). After each tool
call it reads the hook JSON from stdin, measures the calling agent's context, and if a Haiku worker
has reached 80,000 tokens (Sonnet 160,000) it returns:

    {"hookSpecificOutput": {"hookEventName": "PostToolUse",
      "additionalContext": "Token budget reached (<used>/<limit>): stop now. Make the tree build, write STATUS.md in your module, report what is missing."}}

`additionalContext` is injected into the model's context (per the update-config skill's hook output
schema). Opus, Fable and unknown models never trigger.

## Measure: latest-message context size, not a sum
Used = `input_tokens + cache_creation_input_tokens + cache_read_input_tokens + output_tokens` of the
LAST assistant message that carries a usage block in the agent's transcript.

Why not a sum: each API call re-reads the whole cached context, so summing `cache_read_input_tokens`
over all messages counts the same context again on every turn and grossly over-counts.

Check against the real Haiku worker transcript
`.../b66f98cd-.../subagents/agent-a66abaacf007e9cf9.jsonl` (20 assistant messages):
last usage = 2 + 787 + 53,856 + 25 = **54,670**. Harness report: 55,770. Gap 1,100 (2%), within the
"roughly" the bead asks for; the cause is not identified (likely a few tokens of harness overhead
not written to the transcript). The naive sum over all messages would be several hundred thousand.

## Subagent transcript finding
- The subagent transcript rows carry `agentId` (e.g. `a66abaacf007e9cf9`) and `sessionId`; the
  subagent file lives at `<session>/subagents/agent-<agentId>.jsonl` next to the parent `<session>.jsonl`.
- The update-config skill's hook stdin documentation lists only `session_id`, `tool_name`,
  `tool_input`, `tool_response`. It does NOT document `transcript_path` for hooks or any agent-id
  field, so the exact stdin of a subagent's tool call is NOT verified here.
- The script is written defensively for both cases: if stdin has `agent_transcript_path` (existing
  file) it is used; else if stdin has `agent_id` and `<transcript>/subagents/agent-<id>.jsonl`
  exists, that file is used; else `transcript_path` is used. If the harness passes the parent's
  transcript with no agent id, a worker would be measured against the parent session (open item:
  verify once from a live worker's hook input; the dry run and tests use the subagent file directly).

## Thresholds and overrides
Haiku 80,000; Sonnet 160,000; env `EDIT_BUDGET_HAIKU`, `EDIT_BUDGET_SONNET` override (invalid value →
default). `EDIT_BUDGET_OFF=1` makes the hook a no-op. Model family from `message.model`
(contains "haiku" / "sonnet"); anything else never triggers.

## Fail-open policy
Any exception (missing file, bad JSON, unknown format, malformed usage) → exit 0 with no output. Below
threshold → exit 0 with no output. Reads are tail-only: a growing backwards read from the last 256 KB
until the last assistant usage line is found (capped at 64 MB), never a full parse.

## Tests
`tools/hooks/test_token_budget.sh` (fixtures in `tools/hooks/testdata/`): real transcript dry run
(54,670, no trigger), synthetic Haiku over (trigger, exact emitted JSON), Haiku under, Sonnet over
160K, Opus over 200K (no trigger), env overrides, `EDIT_BUDGET_OFF`, fail-open cases.

## Disable
Set `EDIT_BUDGET_OFF=1` in the environment, or delete `.claude/settings.json`'s PostToolUse entry.
