## §8 — foreground slab trimming

Verdict: confirmed. Replace pool enumeration with occupancy bits and intrusive
partial/empty slab queues under the existing recursive pool mutex. Slot return,
reservation, reuse and reclamation share that lock. Trimming visits completed
slabs only, proportional to reclaimed storage; no live slab or slot is scanned.
Queries/takes consume at most 64 completed slabs (G, bound) per call, even
with a tree-sized queue of worker returns or an empty document. Bulk insertions
reclaim their unused reservations on the originating call. Mutation, failure
and last-owner cleanup drain the same queue in proportion to reclaimed
storage, including with pinned snapshot roots.

Keep the two-slot allocation and its 16-byte tail (G, layout). Free slots hold
queue links; the tail holds doubly linked slab-list pointers plus occupancy bits.
A high pointer tag identifies the tail from either slot in constant time using
only the adjacent immutable kind halfword, never its concurrent atomic owner
count. Snapshot padding is initialized once; pool classes never mix object
kinds. This encoding explicitly targets the repository's little-endian 64-bit
user-space addresses and allocator's 16-byte alignment. Partial slabs are reused
first. No per-slot allocation/header growth or node-size change is needed.
A trial with separate slot prefixes failed the unchanged version-header memory
bound; that representation was removed. Actual slab overhead stays charged.

## §9 — range traversal

Verdict: confirmed. Tree/snapshot range reads, deletion collection and fallback
copying use a call-local ancestor stack. Seek enters one root path; advancing
climbs that path and enters the next subtree without restarting at the root.
Each intersected node is entered once per pass. No allocation, persistent
snapshot link or mutation of shared traversal state is introduced.

The frozen public iterator's four scratch words cannot retain that stack.
Its existing traversal remains intact; changing its representation would need
an approved header amendment. This finding's range APIs and collection require
no such amendment. The regression checks one-byte fragments, exact binary
content, partial snapshot ranges, collection/fallback and byte-exact reinsertion.

## §10 — reference replay newline recounts

Verdict: confirmed. ADD storage keeps newline prefixes at 512-byte boundaries
(G, layout), using 128 u16 entries and a u32 current/full-chunk total (G).
Interior prefixes fit in u16; a full chunk of newlines needs the separate wider
total. Append copies/counts new bytes once and updates completed prefixes.
Replay and ADD entry splitting use prefix differences: full chunks recount
zero bytes; partial endpoints scan at most 1022 bytes per span (G, bound),
independent of payload length. Same-block fragments scan only their own bytes.
Descriptors are inserted in batches of up to fourteen entries (G, layout),
sharing each batch's descent and splice; this is bounded bulk insertion, not a
claim of arbitrary-length constant-cost tree joining. Reservations still
precede content changes, and caller-supplied span/growth checks stay intact.

Checkpoint root/directory ownership and begin/commit/abort semantics remain
intact. A prepaid boundary copy includes the saved newline prefixes; abort
restores the ordinary boundary total immediately. Ordinary edits consult no
checkpoint state and acquire no checkpoint allocation/traversal/accounting;
the sole inactive checkpoint branch remains in snapshot take. Tests cover
aligned large replay, partial/overlapping spans, deep COW bulk insertion,
all-newline full-chunk totals and prefix rollback with/without pinned inside
snapshots. A larger prefix-cache trial failed tiny retained-owner G10f; the
compact cache passes the original bound without changing its funding. A replay may
also query one existing ADD entry split at its insertion boundary; that query
has the same fixed endpoint bound and is included in the byte counter.
