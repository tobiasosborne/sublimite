# P2.2e — X11 review fixes (edit-e6x.19)

Scope: findings 2, 3, 7–12, 18, 19, 26, 29, 30 in `docs/reviews/x11-1.md`.
No changes to `clip.c`, `xi2.c`, `plat.h`, frozen headers, or another module.
Tests include the implementation for narrowly scoped setup/dispatch fault injection;
ordinary input/live/stall tests also link the production library. The optional
`local_overflow`, `wheel_pending`, and `xi_mask_pending` order-test arguments are
explicitly failing integration repros for files reserved to parallel beads; they
are excluded from the default passing regression suite.

Initial red input/order runs: (M)[AC], BAT0 Full, load 4.09. Delayed-reply/XI2
reds: (M)[AC], BAT0 Full, load 3.96. Literal counts/timestamps in assertions are
fixtures, not performance measurements. Green lines below name the binary/case
that exercises each assertion. Leak detection is disabled in this sandbox;
counted compose-table unrefs verify the targeted cleanup immediately.

## §2 — raw burst ring overflow

Confirmed; fixed for raw ingress. Drain queued translations before taking the
next raw event, so every raw key/button transition has ring capacity. Motion is
delivered incrementally too. Tests assert exact edit/release/completion counts for
a burst, motion before a later key, and local requests made from key callbacks.
Red: `x11_order_test: FAIL §2 raw burst preserves every edit`.
Green: `x11_order_test: all ok`.
**Partial, excluded clipboard branch:** `FAIL §2 accepted local completion is never lost`
remains reproducible with `local_overflow`. `clip.c` ignores a failed push while
returning `PLAT_OK`; no finite larger ring can guarantee arbitrary local calls.
Proposal: reserve completion capacity before accepting each local/deferred request,
return `PLAT_ERR_FAIL` on saturation, and leave undeliverable deferred completions
pending for a later slice. The clipboard bead must implement this in `clip.c`.

## §3 — direct callback order

Confirmed; fixed by the same ingress/delivery interleaving. Each earlier translated
input reaches the application before dispatch of focus, close, resize, expose,
or Present, including before focus resets platform state. Tested key→focus,
key→close, button→resize, and key→expose through the live X queue.
Red: `x11_order_test: FAIL §3 preceding input reaches callback first`.
Additional red: `x11_order_test: FAIL §3 reply polling preserves preceding queued input order`.
Reply polls now recheck the platform queue before dispatching newly buffered raw events.
Green: `x11_order_test: all ok`.

## §7 — repeat modifier state

Confirmed; fixed. Save post-transition XKB modifiers/group, preserve the repeating
key across modifiers, and refresh state from XKB StateNotify/pointer/server-repeat
observations. Separate locked Caps/Num masks when synchronizing XKB. Unobserved
modifier presses (held before focus) are primed before their release. Tests cover
Shift/Ctrl release, Shift press during repeat, and Caps Lock cycles; ordinary
press/release text still uses the event's pre-transition state.
Red: `FAIL tests/x11_input_test.c:277: §7 shift release updates repeat`.
Additional red: `FAIL tests/x11_input_test.c:304: §7 second caps press clears repeated lock`;
the final test checks the complete second lock cycle, matching XKB's effective
Lock modifier while the lock key is held.
XKB action filters initially allocated lazily: the single bench caught one
allocation, then the fresh-state/all-core-keys test reproduced growth:
`FAIL tests/x11_input_test.c:417: §7 cold key transitions made 3 allocations`.
Prepare XKB state and prime simultaneous core key actions at setup/on the worker,
then release all keys and reset masks. State adoption remains allocation-free.
Green: `x11_input_test: ok` (including the release counting-allocator cold test).

## §8 — drain starvation

Confirmed; fixed. A slice stops after 64 operations or 1 ms (E: scheduling policy),
checks quit/deadline between operations, and polls ready timers/work without
sleeping while buffered work may remain. Clipboard expiry/reply polling also
runs between slices. Callback-produced input and a perpetually ready raw queue
are tested in child processes with an independent parent watchdog; timers/work
must fire and the bounded run must return. Quit prevents later callbacks.
Red: `x11_order_test: FAIL §8 bounded drain services timers/work and returns under sustained callbacks`.
Green: `x11_order_test: all ok`.
An individual application callback, XCB transport backpressure, or an individual
clipboard handler can still take time; clipboard bulk slicing is separate §13.

## §9 — release insertion text

Confirmed; fixed. Clear `utf8_len` for every delivered release while preserving
keysym/modifiers. Compose-consumed releases stay consumed. Table rows for both
layouts and the final composed key's release assert empty insertion text.
Red: `FAIL tests/x11_input_test.c:55: §9 us/a: release has no insertion text`.
Green: `x11_input_test: ok`.

## §10 — repeat rate bounds

Confirmed; fixed. Clamp configuration to 1000 Hz (E: maximum), also clamp inside
the pure poller, and independently limit emissions to four per loop turn (E).
Zero disables repeat; changing an active configuration restarts its delay.
Tests cover the boundary/large integer rates and public setter changes.
Red: `FAIL tests/x11_input_test.c:306: §10 rate 1000000001 advances deadline`.
Green: `x11_input_test: ok` and `x11_order_test: all ok`.

## §11 — detectable autorepeat negotiation

Confirmed; fixed. Initialization requires a reply with the detectable flag both
supported and enabled. Reject refusal, missing reply, and an actual XKB error
reply; existing initialization cleanup owns the keyboard allocations.
Red: `x11_order_test: FAIL §11 negotiation refusal rejects init`.
Green: `x11_order_test: all ok`.
This deliberately returns `PLAT_ERR_FAIL` on servers lacking the required mode;
no legacy release/press-pair fallback is introduced.

## §12 — blocking runtime rescans

Confirmed; fixed within X11. XI QueryDevice uses one outstanding cookie and
`xcb_poll_for_reply`; mapping invalidations coalesce into one bulk-worker build
on a separate X connection, using the existing `src/work` API without modifying
that module. The worker constructs both keymap and XKB state; the UI adopts a
validated result without allocating, emits KEYMAP after earlier queued input,
and cancels repeat. New invalidations discard obsolete results and trigger one
replacement job. Shutdown shuts down the worker connection before joining, so a
server grab cannot wedge teardown. Failed rebuilds keep the last valid map.
During a pending refresh, input uses the last published map; KEYMAP marks adoption
of the replacement. No new promise of instantaneous layout switching is made.
Red: `x11_order_test: FAIL §12 delayed keymap reply cannot block input/shutdown`;
`x11_order_test: FAIL §12 delayed device reply cannot block input/shutdown`.
Green: `x11_order_test: all ok` (includes successful/coalesced worker publication).

## §18 — timestamp wheel deduplication

Confirmed; **proposal only**, because the canonical selector/decoder is in the
explicitly excluded `xi2.c`. Keep that file and its header untouched rather than
creating a competing decoder in dispatch. Proposal: select XI ButtonPress/Release,
expose detail, sourceid, and pointer-emulation flags in `xi2_result`, route genuine
XI button notches and smooth valuators once each, suppress emulated XI buttons,
and use core buttons only when XI2 is unavailable. Remove `xi_scroll_ms` logic
when this lands. Test independent devices near the same timestamp and both event
orders. Retained repro: `x11_order_test wheel_pending`.
Red: `x11_order_test: FAIL §18 independent legacy notch near smooth timestamp survives`.
Green: unavailable; blocked by the bead's file restriction, not disputed.

## §19 — extended held buttons

Confirmed; **partial**. Core buttons through 32 now retain their transitions in a
separate held mask, which core motion/key/button events combine with buttons 1–5.
Focus reset clears it. Tests cover back/forward press, drag, release, and the
highest supported bit without contaminating modifier/group bits.
Red: `FAIL tests/x11_input_test.c:319: §19 core button 8 held after press`.
Green (core): `x11_input_test: ok`.
Excluded decoder repro: `x11_order_test: FAIL §19 XI motion preserves held button 9`
(`xi_mask_pending`). Proposal for the XI2 bead: decode button bits through 32,
including the second mask word for button 32; only core button bits 1–5 may be
shifted into `r.mods`. Extended held bits must remain solely in `r.buttons`.
Green (XI2): unavailable until `xi2.c` changes.

## §26 — compose-state allocation failure

Confirmed; fixed. A supplied table without a successfully allocated compose
state makes init fail before taking the caller's keymap; the consumed table is
unref'd and fields are cleared. A targeted compose-state failure checks both the
return code and exactly one table release.
Red: `x11_order_test: FAIL §26 compose allocation failure rejects init and releases table`.
Green: `x11_order_test: all ok`.
