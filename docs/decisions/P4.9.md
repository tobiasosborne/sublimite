# P4.9 — CLI, standalone single-instance IPC, XDG

## Dependency change

The coordinator dropped this bead's dependency on the editor loop
(edit-zzj.3) and tabs. Integration is a separate follow-up bead. This module
uses only the base arena API already on main. It does not modify main.c,
editor code, any other module, or the Makefile.

## CLI and ownership

`ipc_parse_args(argc, argv, &args)` initializes a caller-owned, zero-initialized
`ipc_args`. It snapshots the launching process's cwd. `ipc_args_fini` releases
its arena; failed parses release it themselves. Do not parse over a live args
object. Paths are absolute: existing prefixes resolve through symlinks;
missing trailing components normalize `.` and `..`. This supports opening a
new file while preserving the caller's cwd and symlink semantics. The cwd and
canonical paths travel with the request; the server never changes its cwd.

Positions are one-based, defaulting to line/column one. An **existing whole
filename wins**: an existing `a:1` opens that file at the default position.
Otherwise the last numeric suffix denotes the line; two numeric suffixes
denote line and column. Thus `a:b:12` means path `a:b`, line 12; `a:12:3`
means path `a`, line 12, column 3. Zero or overflowing numeric coordinates
are errors; nonnumeric suffixes remain part of the path. Precedence applies
to the whole argument, not shorter existing colon-containing prefixes.
Ambiguous literal paths can be made to exist before invocation; `--` only
ends option recognition, it does not disable suffix parsing.

`--wait`, `--new-instance`, `--`, and a unique `-` are accepted. Unknown options
are errors; options can appear between paths until `--`. After `--`, names
beginning with `-` are paths, while the exact `-` still means stdin. A literal
file called `-` can be written as `./-`. `ipc_args_read_stdin` reads a blocking
fd into arena storage, preserving arbitrary bytes including NUL. An empty
stdin still requests an untitled buffer. Failed stdin reads require fini and
reparse before retry. There is no executable CLI entry point in this bead.

Bounds: 128 paths, 4096 bytes per path/cwd including NUL, 1 MiB for the entire
wire frame, and 32 simultaneous connections (including waiting clients).
Oversize input returns `IPC_LIMIT`; stdin capacity is the frame bound minus
metadata. Payload transport was selected over descriptor passing to keep
ownership and malformed-message testing simple. Larger stdin or more clients
requires a future bound change or fd-backed transport. No temporary payload
files are created.

## Transport and lifecycle

The filesystem endpoint is `$XDG_RUNTIME_DIR/edit-<uid>.sock`; an explicit
runtime argument overrides the environment. The directory must be absolute,
owned by the caller, and private (no group/other permission bits). The socket
is mode 0600. If XDG_RUNTIME_DIR is unset, Linux abstract `edit-<uid>` is used.
An invalid configured runtime is an error, not a silent fallback. Both sides
check Linux SO_PEERCRED for the same uid; the protocol is local-user IPC.

A persistent, mode-0600 `edit-<uid>.lock` file protects binding, ECONNREFUSED
stale cleanup, and shutdown unlinking. Never unlink this lock file while any
instance might exist: replacing its inode defeats serialization. Startup
checks the old socket while holding flock: a successful connection yields
`IPC_EXISTS`; only ECONNREFUSED authorizes removing an existing owned socket.
Other connection errors do not authorize unlinking. Bind's EADDRINUSE handles
abstract-socket races. Exactly one simultaneous first launch gets `IPC_OK`.
Shutdown checks socket device/inode under the same lock, so an old owner
cannot unlink a successor. Init/fini wait on this lifecycle lock for at most
IPC_LOCK_TIMEOUT_MS (1 s, edit-457.21 §12): init then returns IPC_TIMEOUT and
fini leaves the socket for the next startup's stale recovery. Drain and
report_closed never block. A crash releases flock automatically;
an abstract socket disappears with its final fd.

`ipc_server` is caller-owned, initialized explicitly and finalized after a
successful init. One init-time base arena reserves the receive pool (16 x 64 KiB + 2 x 1 MiB
= 3 MiB, edit-457.21 §14; the original 33.5 MB arena is gone, and an
exhausted pool answers an IPC_BUSY ACK) and the peer table; idle pages are not touched. Drain/report_closed allocate no memory and
use nonblocking syscalls. The single public fd is an epoll fd aggregating the
listener and client sockets, including partial input and output. There are no
hidden globals, worker threads, or editor/tab dependencies; the only timer is
a timerfd armed while an incomplete request exists.
Draining takes at most two batches of readiness events; retained readiness
wakes the loop again; one drain call is also bounded in bytes (256 KiB), callbacks
(8) and accepts (8). Incomplete clients hold a slot for at most
IPC_REQUEST_DEADLINE_MS (5 s), and under slot pressure peers idle longer than
IPC_EVICT_IDLE_MS (500 ms) are evicted; no periodic wakeup exists (edit-457.21
§10, §11). At slot exhaustion with nothing evictable a connection is closed
and the client gets an error rather than a false ACK. Callback work and payload copying belong to the integrating loop's
own budget. Client handoff is a startup-only blocking function, not a typing
path API.

## Wire format

All integers are little-endian and are read bytewise, without unaligned casts.
The request header is 24 bytes: `EDIP`, version byte 1, flags byte (bit 0 wait,
bit 1 stdin), two reserved zero bytes, then u32 total length, path count, cwd
length, and stdin length. The body is a NUL-terminated absolute cwd, followed
by path records `(u32 length, u32 line, u32 column, NUL-terminated absolute
path)`, then opaque stdin bytes. String lengths include their terminator.
Embedded string NULs, unknown flags/version, nonzero reserved fields, invalid
positions/counts, truncation, and surplus decoder bytes are rejected as
`IPC_PROTOCOL`, with a zeroed output. Decoder output borrows wire storage.
The encoder validates before writing and does not serialize new_instance.
One frame is permitted per connection; observed surplus stream data is rejected.
The client sends exactly one encoded frame and never needs to half-close.

(Details and red/green evidence of the review fixes: [P4.9c](P4.9c.md).)

Replies are eight bytes: `EDIR`, kind `A` (ACK) or `C` (closed), one byte
ipc_result, and two reserved zero bytes. ACK means the callback accepted the
request. A rejected callback sends its error instead. --wait gets a successful
ACK followed by a closed reply only after report_closed; the client remains
blocked between them. Broken connections return errors, never success.
The handoff timeout bounds connection/send/ACK readiness waits; the post-ACK
wait has no deadline. IPC token zero is invalid; tokens monotonically increase
within the server and disconnected/stale tokens are rejected.

## Integration contract

All server calls and the open callback run on the editor loop's UI thread.
No server object may be accessed concurrently. A callback must not recursively
call drain or fini; report_closed from the callback is explicitly supported. Before entering the UI loop:

1. Parse args; read stdin if requested. Honor new_instance by bypassing BOTH
   server_init and client_send for that isolated process. It must not replace
   or compete for the shared endpoint. An isolated process that needs --wait
   uses ipc_server_init_isolated (no endpoint) plus the launcher pair below.
2. Call server_init before opening the initial request. IPC_OK owns the
   endpoint. IPC_EXISTS calls client_send, frees args, and exits after ACK
   (or closed for --wait). Propagate other errors. If an incumbent exits
   between role detection and handoff, a bounded startup retry can repeat
   init/handoff; never retry after a received ACK, which could duplicate opens.
   --wait on the primary or an isolated launch (edit-457.21 §16): main calls
   ipc_launcher_pair before starting the UI and fork()s; the child (UI) calls
   ipc_server_adopt_wait(fd) and associates the token with the initial
   request's tabs; the parent blocks in ipc_launcher_wait and exits with its
   result when the closed reply arrives (IPC_IO if the UI exits first).
3. The primary opens its local parsed request through its own tab-opening code
   and then frees args. An empty request can mean the normal default untitled
   tab. Stdin means an additional untitled buffer containing exactly the payload.

Add ipc_server_fd to the loop's poll set. On POLLIN call ipc_server_drain with
an open callback and caller context. The callback opens/focuses each requested
path at its position and creates a stdin buffer if requested. It returns
IPC_OK only once the request has been accepted. Its strings and payload are
valid only during the callback; copy them to loop-owned storage before return
if opening asynchronously. Keep the token only for wait requests. The loop
associates it with **all tabs/buffers belonging to that request**, including
stdin. When the last associated tab closes, call ipc_server_report_closed on
the UI thread. Immediate closure from inside the callback is supported. A
successful report queues/sends the closed reply and arranges writable interest;
calling drain afterward is harmless, and normal fd polling handles backpressure.
A wait client that gives up before its closed reply raises `server.wait_drops`
and its token stops being live: after every drain that raised it, sweep the
token associations with ipc_server_token_live and discard dead ones (at most
IPC_MAX_CLIENTS are live; report_closed on a dead token returns IPC_INVALID).
Tab-open
failure should return an error, not ACK success. The loop owns partial-open
rollback and association storage. On final loop shutdown call server_fini;
unclosed wait clients get disconnection errors, not a false closed reply.

Five-line main.c wiring sketch (parsed `args`, a successful startup branch,
callback, ctx, poll array, and error handling belong to the follow-up):

```c
ipc_server server = {0}; ipc_result role = ipc_server_init(&server, NULL);
if (role == IPC_EXISTS) { ipc_result rc = ipc_client_send(NULL, &args.request, 2000); ipc_args_fini(&args); return rc == IPC_OK ? 0 : 2; }
fds[ipc_slot] = (struct pollfd){ipc_server_fd(&server), POLLIN, 0};
if (fds[ipc_slot].revents & POLLIN) (void)ipc_server_drain(&server, open_request, ctx);
ipc_server_fini(&server);
```

The sketch's primary branch must check role == IPC_OK before constructing its
poll entry; new_instance bypasses this sketch. The separate tab-close hook is
`ipc_server_report_closed(&server, token)`. No changes to this module are needed
for that integration.

## Desktop registration

`tools/edit.desktop` uses `Exec=edit -- %F` and declares text/code/JSON/XML/
Markdown MIME types. `tools/xdg-install.sh` is an explicit user action, requires
edit on PATH and xdg-mime, installs under XDG_DATA_HOME/applications (default
~/.local/share/applications), refreshes the desktop database if available, and
sets user MIME defaults. Neither tests nor builds invoke the script.
Desktop activation becomes functional once the follow-up wires the CLI into
main.c. The registration script is intentionally not run during verification.

## Test isolation — edit-457.17

`EDIT_IPC_NAMESPACE` is an opt-in test hook for abstract sockets only: both
server and client use `edit-<uid>-<namespace>`. Unset preserves `edit-<uid>`;
empty values return `IPC_INVALID` and overlong names return `IPC_LIMIT`.
Filesystem endpoints and their lifecycle locks keep their existing names.
Each ipc_test process derives its namespace from its private mkdtemp directory;
forked clients inherit it. No test binds or probes the real per-user abstract
endpoint. Tests verify the exact abstract address, incumbent detection, a
second namespace's independent server/client round trip, and invalid hook
values. `ipc_test --parallel` runs the requested concurrent reproduction.

The original parallel reproduction had 8 failures over 80 runs (M)[AC],
power Full, pre-run load1=7.34, all at abstract endpoint initialization.
The separate callback failure is also a test race: `next_token` increments
on accept, before receipt of the complete request or callback execution.
The old test could block in waitpid before draining the request. A controlled
partial peer and pipe barrier reproduced child `ipc_result=6` (`IPC_TIMEOUT`)
instead of `IPC_REJECTED`, exit 2 (M)[AC], power Full, pre-run load1=6.50.
The parent now drains until the callback's own counter records completion,
then reaps the client and asserts the expected result kind. Client and ready
waits allow 30000 ms, with a suite watchdog of 120 seconds (G, hang bounds,
not performance assertions); no scheduling latency decides correctness.

The fixed release parallel loop had 0 failures over 80 runs (M)[AC],
power Full, pre-run load1=5.03. No bench rerun is needed: changes affect
endpoint construction at startup and the test harness, not the typing path.
The ASan/UBSan parallel loop also had 0/80 failures (M)[AC], Full,
load1=11.17. Gcc `make all` passed (M)[AC], Full, load1=5.03; `make fuzz`
built 19 fuzzers (M)[AC], Full, load1=6.32. IPC decoder fuzz completed
2,619,395 runs in 61 seconds with no findings (M)[AC], Full, load1=11.17.
Sanitizer runs use detect_leaks=0; the coordinator retains the leak-on check.
