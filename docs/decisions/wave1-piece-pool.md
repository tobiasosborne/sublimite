# Prepaying the piece tree's copy-on-write pool

**Decision.** Place one working reserve in the UI-owned app instance and replenish it between commands. Each buffer owns its actual tree, retained snapshots and physically retiring storage. A saved revision can remain live from one save to the next while the UI changes every leaf. Each new path copy then becomes occupied storage. The next edit gets fresh working space without waiting for the saved revision to be released.

Sources identified by v1 symbols are pinned at `6fec2e8`. (P) marks arithmetic or a consequence of a specified representation. (G) marks an admission or product contract. No throughput assumption enters the sizing.

## Revision ownership in v2

PLAN §2 assigns modules; §§4.1–4.5 and amendment A6 determine which operations need immutable text. The unit of node accounting is the physical node. Count it once even when several roots reach it. For headers, count each actual uncached take; a retain of an existing handle adds an owner. A restored root can acquire a new header after abort. Revision numbers alone cannot deduplicate either allocation.

V1 evidence **excluded as independent v2 holders** includes the raw buffer pointer in the old session graph, the copied metadata fields themselves, tabs' borrowed tree/undo pointers, the separate resident `scroll_snapshot` in `src/editor/scrollctl.c` `editor_scroll_retire`, the old full-buffer map job in `src/editor/minimap.c` `editor_map_service`, and v1-specific large-file warm/goto/find jobs (`src/editor/large.c` `editor_large_start`, `editor_large_goto_byte`, `editor_large_find_begin`). The old `findui` slot array, clipboard desired/primary/command slots and separate direct save entry points are not fixed seats in the v2 architecture. Their useful behaviors are covered by the named owners above. The v2 plan defines no piece-wide concurrency limit for them.

A mapped snapshot retain also acquires the backing via the map hooks. A lineidx fault token can outlive all revision headers. Worker last-release in `src/piece/piece.c` `snapshot_drop` can enqueue retirement; `reclaim_drain` and `piece_reclaim` return the physical node and header slots. Keep queued and detached objects charged until this return. The process allocator and its return path outlive all its cores, including final releases after UI buffer close.

## Tree geometry and mutation reserves

**Document size and height.** Use `D = UINT64_MAX = 2^64 − 1` logical bytes as the supported **L1 piece-document maximum** (P, width of `piece_tree.len`, subtraction-before-growth checks in `piece_insert` and `piece_insert_ref`, and the exact-EOF fixture in v1 `docs/decisions/P1.4d.md`). Repeated references can describe more document bytes than there are physical ADD bytes. Source offsets have a separate tag bit (`TOP`, `add_reserve`). PLAN specifies a **10 GiB** mapped-file integration case (G, Wave 2 exit fixture) and gives no universal maximum for files the application must open. The integrated path also has address-space, backing and index limits. For example, v1 `src/lineidx/lineidx.c` `lineidx_create_reserved` requires chunk count plus spare entries below `UINT32_MAX`; `lineidx_create` supplies 64 spare entries (P, default call argument). Its largest representable dense open with that default is `(UINT32_MAX − 1 − 64) × LINEIDX_CHUNK` bytes (P, last admissible entry count times chunk width), even before considering available memory. `D` sizes the piece arithmetic without promising a mapping of that size or imposing a new application file cap.

Let `F = FAN = 16` (P, branch children and leaf entry arrays), `h` be the number of branches on a root-to-leaf path (leaf root has `h = 0`), and `p` the count of nonempty pieces. For nonempty text `p ≤ length ≤ D` (P, at least one byte per entry). At full fanout a height `h` holds `F^(h+1)` pieces. A packed rebuild of even the most fragmented document therefore needs at most `h_pack = ceil(log_F D) − 1 = 15` branch levels (P, `16^16 = 2^64`). For an initial mapping substitute `ceil(length / CH_SIZE)` for `p` in the packed calculation; `build` and `piece_init_mapped_step` pack from the leaves up. Subsequent typing can create byte-sized pieces.

**Height gate and reachability.** Full fanout bounds the packed representation. `maybe_merge` leaves a small child beside a full sibling, and the builder can leave a short right edge. V1 does not maintain a half-full minimum after deletion. Accept height through `H = h_pack + 1 = 16` (G, the packed maximum plus a split level); check prospective root growth, including delete and bulk operations. `H + 1 ≤ MAXH = 32` (P, leaf-inclusive traversal stack in `piece.c`). A height-`H` tree is valid. Only growth **above** it needs off-path dense rebuilding and revision-validated retry. Preserve piece order, ADD offsets, snapshots and append state. Height is a structural constraint with its own result, never a “memory is full” diagnosis.

**Lower bound.** Starting empty and using mutations alone requires at least **16** calls to `root_grow` (P, initial height zero, each grow adds one, promotion only subtracts). Even initialization from the largest representable original gives at most `ceil(log_F ceil(D/C)) − 1 = 11` (P, at most `2^48` original chunks), hence at least **five subsequent root splits** on that route. At the first mutation growing to height 16 the two old-root halves have at least eight children each (P, `splice` on branch overflow). In a public-operation tree those 16 child subtrees are disjoint within this revision, each height 14 and containing at least 14 branches and one leaf. Thus at least `(1 + 2 + 16 × 14) × 400 + 16 × 272 = 95,152 B` of live node payload is necessary at that instant (P, new root, two halves, minimal surviving paths). This intentionally weak lower bound cannot establish impossibility. Snapshot COW shares across roots; the test-only shared-DAG builder does not establish public reachability.

**Constructive public fixture.** The following sequence reaches the gate within a 47-bit user-address budget (P below). It uses one real ADD byte, no snapshots and no synthetic tree. The fixture parameter is the height at which to thin completed subtrees, `t = 8` for target height 16 (G, mid-height to bound both halves of the construction).

1. Insert a byte and delete it into a `piece_ref`. Repeatedly prepend that same ref with `piece_insert_ref(tree, 0, ref)`. Each call creates one descriptor; the original ADD byte suffices throughout. All splits follow the leftmost spine. A split on overflow leaves nine entries on the left and eight on the right (P, `splice` divides 17 at its upper midpoint).
2. Each time the leftmost node of height `t` splits, remember its new immediate right sibling. Continue prepending until the left node has 16 children again, **before** its next split. In that right sibling keep just its first byte: call `piece_delete` on the suffix ending exactly at the sibling end, with a null output ref. Track the two byte extents by the split rule in the fixture's independent shape oracle. The operation only deletes ADD spans and does not append data. At each level within the sibling, `del_rec` drops the other children, leaving a unary chain. Above it, `maybe_merge` can merge the trimmed sibling with its right neighbour if their counts fit. Its left neighbour is full, so the insertion spine survives. The newest pair always remains together even if its parent splits, since it occupies the first two positions. The very first pair can be children of the root.
3. Each older trimmed sibling is a root over unary paths. Repeated mergers accumulate at most 16 such paths in one sibling (P, branch fanout); after that a further unary child cannot merge with it. Hence repeats eventually add another child to the parent. When that parent splits its new left half starts with nine children and pruning can remove at most one, leaving at least eight. Higher ancestors therefore do not merge on that pruning pass. Subsequent splits propagate upward by ordinary leftmost insertion. Stop on the first root growth to 16, even if a thinning step is pending.

The byte operations can be generated without inspecting private nodes. Put `q = F/2 = 8`. In the initial unpruned prepend run the first growth to height `j` occurs at `g(j) = (15q^j − 1)/7` entries (P: `g(1)=17`; the new root starts with two children and needs 15 more splits, one every `q^j` prepends). At the first split of the cut-level node its right sibling has `s = q^(t+1)` bytes: every right-of-spine node has exactly `q` entries. The left needs `d = (F−9)q^t` more prepends to fill. Make the first cut after `g(t+1)+d` prepends, with prefix length `L=g(t+1)−s+d` in the left sibling. Delete `s−1` bytes at offset `L+1`. Repeat **the identical delete range after each further `s` prepends**, stopping at the desired growth. Pruning leaves the left spine intact, so its carry schedule repeats and no global edit counter need wrap. For cut one this is first cut after 193 prepends, delete 63 bytes at offset 130, repeat every 64 prepends (P, substitute `t=1`). This small instance checks byte positioning and merge order in the public fixture.

For the address bound, before the last split the height is at most 15; immediately afterwards the new root has two children. Thus at most `2 × 16^7` nodes of height eight are present at either point (P, maximum fanout from the two height-15 roots). Apart from the active subtree and its newest untrimmed sibling, each contains at most `1 + 16 × 8 = 129` nodes. Each of the two dense exceptions contains at most `(16^9 − 1)/15` nodes (P, full tree through height eight). Upper nodes number at most `1 + 2 × (16^7 − 1)/15`. Even charging a whole largest slab, `816 B`, per live node, the sum of those three bounds times 816 is **below 64 TiB** (P, geometric sums; `64 TiB = 2^46 B`). The remaining half of the stated address budget suffices for bounded per-operation reserves, allocator pages and the fixed ADD store with packed slab backing and reuse on free. Byte length also fits `D` since each leaf holds at most 16 single-byte entries. This is an address-space witness, not a RAM requirement for CI.

Make this parameterized sequence the public growth fixture. For routine red/green use the same split/trim sequence with a low height gate and cut (e.g. gate three, cut one, G, exercises a trimmed node, its parent and root growth). Exercise a further growth request at the gate, repack and retry, and assert preserved bytes and prior snapshots. The full-depth parameters specify the reachability witness; the scaled run checks the algorithm on ordinary test hardware. No full-depth execution or new measurement is claimed.

**One shared descent.** `cow` copies a shared node once and increments child refs when copying a branch. Exclusive nodes are reused. A fully shared point update copies `1 + h` nodes and `272 + 400h` payload bytes (P, one `LEAF_SZ` plus `h × BRANCH_SZ`). The exclusive `cursor_extend` can consume zero node slots. A split sibling and `root_grow` are additional allocations. `del_rec` can visit both boundaries, drop whole middle subtrees and copy a merge neighbour via `merge_children`; even removing bytes from the middle of a full leaf can split it. A reference insertion can touch many chunks. No single descent describes every edit.

At `h = 4` the path is `1,872 B`; with the `80 B` header and amortized slab tails it is `1,872 + 80 + (4 + 2) × 8 = 2,000 B`. At `h = 15` the path alone is `6,272 B` (all P, substitution into this layout and the two-slot slab below). These are the cases in `tests/piece_mem_test.c` `deeper_snapshots` and `docs/decisions/P1.4e.md`, “Unresolved frozen contracts”. The header's `1,920 B` is the historical G10f allowance (G, `src/piece/piece.h` MEMORY BOUND).

**Free slots required at entry.** The table transcribes `src/piece/piece.c` `reserve_insert`, `reserve_delete` and `piece_snapshot_take`. Every numeric expression is (P) from those branches. `f` means `root->cnt == FAN`, `r` is the current root count. These are free-slot requests; unused slots remain available when the call returns.

| Operation and condition | Leaf slots | Branch slots | Header slots |
|---|---:|---:|---:|
| Insert, `h = 0` and `n ≤ floor((F − r)/2)` | `1` if root shared, else `0` | `0` | `0` |
| Other insert, `h = 0` | `2n + 1` | `n + 1` | `0` |
| Other insert, `h = 1` and `n = 1` | `3` | `3` if `f`, else `1` | `0` |
| Other insert | `2n + 1` | `(2h + 3)n + 1` | `0` |
| Delete, `h = 0` | `2` | `1` if `f`, else `0` | `0` |
| Delete, `h = 1` | `4` | `3` if `f`, else `1` | `0` |
| Delete, `h ≥ 2` | `4` | `4h − 1` | `0` |
| Uncached snapshot (also a checkpoint's initial take on a miss) | same as delete | same as delete | `1` |
| Cached take / retain | `0` | `0` | `0` |

For a nonempty insert, `n = ceil(((add_len mod C) + len)/C)` with `C = CH_SIZE = 2^16 B` (P, `CH_SHIFT` and `piece_insert`). For `piece_insert_ref`, sum that expression over nonempty spans using each span's ADD offset and length. V1 reserves against the **segment count** even though it inserts up to `REF_BATCH = FAN − 2 = 14` descriptors per descent (P, `ins_batch_rec` needs room for the split existing entry). Validate span extents, growth, all products, class counts and rounding before any mutation. Zero-length no-ops take no reserve. Header owner saturation still follows the checked refusal in `piece_snapshot_retain`.

**Private ADD boundary.** `piece_checkpoint_begin` retains a restore view at the ADD mark. On the first uncached inside take for which the mark is unaligned, the root's `add_high` exceeds the mark, and the restore boundary is still shared, `checkpoint_snapshot_storage` installs a private writable copy in the restore view *before* publishing the snapshot. It copies the prefix bytes and newline prefixes and restores the prefix newline total. Prepay **one complete `sizeof(add_chunk)` per open checkpoint that may publish such a view** (P, `boundary_private` makes this once per checkpoint). On the pinned ABI this is `65,800 B = 65,536 + (65,536/512) × 2 + 4 + 4` (P, data, `uint16_t nl_prefix[]`, `nl_total`, refcount). Bill the actual aligned allocator stride. An aligned mark, unobserved extension or cached take requires no new private chunk. The ordinary pre-begin take itself does not trigger the copy.

On abort the UI restores the logical mark, swaps the directory and repairs the restored tail's newline state. A surviving inside snapshot continues reading its original bytes, including the transaction tail, while new edits can append at the restored mark. On commit the unused restore view is dropped. If the last observer is gone at abort, the ordinary boundary can be reused. Older detached chunks and directories remain charged until physically freed, across any number of subsequent checkpoints. Prepay the checkpoint descriptor, restore-view metadata and any private directory path needed for the boundary exchange as well. For the v2 shared directory require a prepaid, bounded path for that exchange and a constant-time retain at begin. V1 `add_store_prefix` allocates a pointer table and retains every prefix chunk at begin; plain take retains the existing `add_store`.

## Pool sizing and admission

**Size for one command.** Use leaf, branch and header counts. Let `O_L,O_B` be the physical occupied nodes across active and retained roots and deferred retirement, and let `S` be occupied snapshot headers, including cache and deferred returns (P, allocated slots minus physically free slots). Unconsumed claims for a suspended transaction are also unavailable to another command. At open, a packed original has `max(1,ceil(ceil(length/C)/F))` leaves; round up by `F` at successive levels to get its branches (P, `build`). Account for construction scratch at open.

For the full **ordinary command** reserve a checkpoint begin, selection deletion, single-segment insertion and publication of the result. At current height `h`, evaluate the table through `b = min(H,h+2)` (P, delete and insert may each grow the root once). Call the maximum single-segment insertion vector through that height `I`, and the maximum deletion vector `Dₑ`. Then the conservative working vector is **`W_nodes = Dₑ + I + Dₑ`**, entrywise in the leaf/branch classes, plus **two free headers** for the begin and final take (G, command contract). Begin needs delete-class free space but consumes only a header. The sum allows the mutations to consume their full entry reserve and leaves the final take's delete-class space intact. At `b=2` this gives `(11,22,2)` (P, leaf sum `4+3+4`, branch sum `7+8+7`); at `b=16` it gives `(11,162,2)` (P, branch sum `63+36+63`).

The logical capacity target is **`(O_L,O_B,S) + W`**, plus outstanding claims (G, one UI command at a time). The physical purchase also accounts for partial slabs stranded in another core. An older revision affects occupancy; the update copies any one shared node once regardless of its refcount (`cow`). For an operation touching other paths, the reserve table and command sequence already include them. There is no correctness counterexample requiring an extra path per older revision. Remove `(R−1)U` from the target. The default extra batching allowance is zero (G, buy the exact deficit); a future refill-frequency change belongs to allocator policy. Services decide how many revisions to hold. Distinct new headers increase `S`; two owners retaining the same cached header do not.

**Conversion to bytes** (P). V1 `slot_size`, `pool_grow` and `slab_tail` use two same-class slots and a `16 B` tail per slab. One slab request is `2 × 272 + 16 = 560 B` for leaves, `2 × 400 + 16 = 816 B` for branches and `2 × 80 + 16 = 176 B` for headers. For a single destination with slot requirements `N`, the slab request in bytes is

`B_nodes = 560 ceil(N_leaf/2) + 816 ceil(N_branch/2) + 176 ceil(N_header/2)`.

**One UI-owned process reserve.** The app instance owns unassigned *whole* slabs of each class and a spare private boundary chunk. On admission lend whole blocks as needed to the destination core; installed slabs containing live slots stay with that core. Count a locally free slot only for its owning core; return unused whole slabs to the common supply. A slab taken for a snapshot or a chunk installed on abort can remain attached across commands: charge the occupied result, return the unused claim, then replenish the common supply. This trades independent simultaneous mutation guarantees and instant access to every inactive tab's headroom for the single UI writer in PLAN §2. A background job reads an immutable revision. A transaction yielding across commands keeps all live objects and the reservation required for its infallible abort; either retain a further explicitly funded claim or preflight its next slice on resume. No double lending. Switching buffers, session publication for another buffer and shutdown follow the same admission and retirement rules.

For empty tabs with the example working height above, the **process** working reserve from scratch is `6 × 560 + 11 × 816 + 176 + 65,800 = 78,312 B` (P, round `(11,22,2)` by class plus one boundary). The former per-tab proposal was `52,848 + 65,800 = 118,648 B`, or `11,864,800 B` across 100 tabs (P, multiplying the previous proposal). The incremental **per-empty-tab working reserve is zero** (P, shared supply). A bare v1-layout empty core still owns a `560 B` leaf slab (P, `piece_create` installs one root); a published empty text also occupies a header slab of `176 B` if it is that core's first header (P, `piece_snapshot_take`). Thus a hundred bare empty trees plus one working reserve request `100 × 560 + 78,312 = 134,312 B`; with each empty text published, `100 × (560+176) + 78,312 = 151,912 B` (P). All comparisons use raw allocator request bytes and exclude core/tree/view structures, metadata, ordinary ADD and allocator page rounding. With class alignment of 16 bytes the boundary stride is `65,808 B` (P, round `sizeof(add_chunk)` up to the alignment). Count real strides and mapped pages for physical accounting.

### Refill contract

- **Invariant and owner.** After every committed command's submit and before dispatching the next ordinary input, the UI must fund the active buffer's working vector and one available private boundary, or record the base allocation failure for that attempted refill (G). Apply the same check initially, on a buffer switch, after abort or yielded replay, and after any snapshot admission that used the reserve. Do not rely on an idle timer, a future cancel or an empty input queue. The UI serializes dispatch and reserve ownership; a worker can publish a return but cannot spend or mutate the UI's pool. Keep an allocator owner alive through orphaned cores and arrange safe final draining or synchronized finalization after UI shutdown.
- **Amount.** For each of the node/header classes let `f` be *actually available*, unclaimed slots in the destination and `u` the number of available whole unassigned slabs of that class. Obtain `max(0,ceil(max(0,W_class−f)/2)−u)` additional whole slabs (P, two slots each). For the boundary, obtain one block if due and none is available; an already pledged boundary belongs to its checkpoint. Credit physically returned storage before asking for more. A fresh uncached service take has its own delete-class entry requirement, header and possible boundary need. Admitting it must preserve or restore the next foreground guarantee. A non-mutating cached retain uses no new pool slots.
- **Source.** Use app-owned fixed classes backed by `src/base/base.c` `edit_pool_init/get/put` for the slab request sizes and complete ADD chunks, and `edit_arena_init/alloc` for scoped variable scratch. Keep independently lived snapshot/directory objects in storage valid through their last owner. Base pools have fixed capacity per VM reservation. When a segment fills, try a further base extent for the missing blocks; exhausting a locally chosen batch is not a terminal OOM. Budget and obtain its bookkeeping from base too. Stage whole blocks, make their pages writable and touch the pages needed for the hot operation in maintenance, then publish their counts. In v1 Linux `base.h` documents lazy first-touch on writable `MAP_NORESERVE`; a reserved address or a `fresh` index alone is not evidence of residency. The admission guarantee concerns recoverable allocator refusals, not survival of a kernel OOM kill.
- **Ordering and bulk.** Ordinary refill runs **after submit, outside the preceding input → submit guard, before the next input is consumed**. At admission use the exact request if it exceeds the ordinary envelope: compute per-class maximum of prior possible consumption plus the next step's entry reserve, including reference segment counts, all mandatory takes/guards, ADD and directory paths, undo and journal staging. A smaller operation may already fit even if speculative funding for the next maximum failed. For a known bulk command fund its exact requirement in advance. If the need is first discovered after input, retain the command and its payload in order, ahead of later edits, with no mutation or acknowledgment. Dispatch its exact deficit to base-backed maintenance, keep input → eventual submit covered by the Law 2 guard, and resume once funded. Fallback may obtain base VM extents; no libc allocation, guard exemption, artificial submit or loss of the input. Revalidate revision, selection and destination before use. Include this wait in input → submit latency. Joined completion or a worker's return merely wakes this path; refill has priority even with continuous input.
- **Failure.** Try the actual deficit against returned blocks and the base allocator. If a preferred larger extent fails, try the necessary amount. Only a base refusal of necessary storage after this check permits the user-visible memory error. A speculative refill failure, a queued refill, an occupied service revision or a different class of spare slab cannot by itself refuse an edit. Return unused claims on every error; a partly funded refill may retain valid free blocks for the retry. Under a permanently pinned BASE, each committed disjoint edit can raise `O`. The mandatory next refill buys the resulting deficit while capacity is available.
- **V1 comparison.** `src/piece/piece.c` `pool_reserve_class` calls `pool_grow` synchronously until free slots meet the request, under the pool lock. That happens in `reserve_insert` / `reserve_delete` before mutation and in `piece_snapshot_take` before publishing a fresh header. A cached take skips growth. In `tests/piece_mem_test.c` `deeper_snapshots`, `mem_alloc` counts every hook request; the live-byte baseline is sampled **after** the take and before the insert, so slab prepayment at take is already in the baseline and any further growth during insert still counts. In `tests/piece_test.c` `t_random` the counting hooks are installed from creation. Separately, `tests/piece_mt_test.c` `typing_allocator_test` warms the arena-backed tree, then starts the libc malloc guard around edits and takes. Slab growth via an arena hook can occur inside that interval with zero libc calls. Neither test demonstrates a between-command refill invariant in v1.

**Companion ADD budget** (P). At admission count physically occupied chunk slots across all views, including sealed or retiring ones. Add ordinary *new* chunks required to append the operation's bytes at the current tail, and one additional free private-boundary slot for a transaction that might expose its partial mark (G, recommended to reserve at begin). Multiply the resulting chunk count by `align_up(sizeof(add_chunk), class_alignment)`. An occupied private slot is already in the first term. Reserve the ordinary COPY/ADD payload, ref fallback, directory nodes, view/checkpoint descriptors, undo records and journal staging in their own classes, outside `B_nodes`. In particular, a requested deletion ref with more than `PIECE_REF_SPANS = 8` runs (P, `src/piece/piece.h`) may append **the entire range**, including existing ADD bytes (`piece_delete`, `collect`); use length as its safe append bound. A new chunk reservation for appended data and a private boundary serve different purposes and can both be due. For v2 directory metadata use the actual chosen layout's maximum touched entries/levels and allocator strides; its representation has no frozen byte size at this pin. A class admission failure anywhere rejects the transaction before externally visible work.

## Exhaustion and verification

Use an exhaustive `enum piece_pool_state` with `PIECE_POOL_READY`, `PIECE_POOL_REFILL_PENDING` and `PIECE_POOL_EXHAUSTED` (G, funded, deficit awaiting service, and actual base refusal). The UI owns transitions and records the destination, revision, claim and allocator outcome. A failed warm-up has no user command to reject.

| State and event | Result and next state |
|---|---|
| READY, request fits | Claim the full sequence before publishing or mutating; release unused slots after use. At submit run the mandatory readiness check. A deficit enters REFILL_PENDING. |
| READY or EXHAUSTED, valid request exceeds current supply | Enter REFILL_PENDING, preserve the ordered input and try its checked deficit. A previous error for a different request cannot reject this one. A cached retain or small edit already funded can go straight to READY and proceed. |
| REFILL_PENDING, capacity obtained or physically returned | Revalidate the pending command and its complete claim. Enter READY and execute it once. Pending work is never reported to the user as memory exhaustion. |
| REFILL_PENDING, base refuses the necessary request | Enter EXHAUSTED. Failed piece begin sets its output to null, a new snapshot returns null, and a mutation returns `PIECE_ERR_NOMEM`. For a user edit show **“Edit not applied — buffer memory is full.”** Preserve text, selection, undo cursor, saved cutoff and journal sequence. An optional service may defer or shed its own work. Range errors and owner-count saturation remain distinguishable at admission from allocator pressure. |
| EXHAUSTED, resources return or new demand arrives | UI credits actual frees, tries any remaining base deficit and uses REFILL_PENDING → READY on success. Preserve the saved BASE; workers may still be reading cancelled work. A visibly refused edit is complete with an error. Only fresh user input can retry that edit. |

Preflight precedes the PLAN §4.2 journal acceptance point. Abort of an unfinished checkpoint remains allocation-free; previously committed replay groups survive. After RAM acceptance use the journal/frame fence and recovery rules. A deficit cannot reach `pool_get`'s free-list assertion.
