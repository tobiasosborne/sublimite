# Prepaying the piece tree's copy-on-write pool

**Decision.** Give each buffer separate prepaid leaf, branch and snapshot-header classes. Admit an edit against the free count in **each** class and against a separate ADD reservation. Count a node once while any root reaches it and continue charging it until it returns to the allocator. A snapshot can survive edits to every leaf in the buffer. Its cost can therefore grow from a header to an entire old tree, even if the number of snapshots stays constant.

The source references below are to v1 at `6fec2e8`. (P) denotes arithmetic or a structural consequence of the cited layout. (G) denotes an explicit contract, admission gate or recommended policy enforced by a gate. The decisions below require no workload estimates or new measurements.

## Revision ownership

Count per piece core. A revision here is a particular immutable tree and its source views. Equal text, equal editor revision numbers after rollback, or the same file backing are insufficient to establish identity. Repeated `piece_snapshot_take` on an unchanged tree normally returns the cached header via `piece_snapshot_retain`. Sharing a header adds an owner, sharing a root adds no path, and sharing just a subtree saves its nodes. Charge independently allocated headers even if an abort followed by a take reproduces the same root. In the following table “UI” means the tree owner.

| Holder | Acquisition, release and possible sharing |
|---|---|
| Active tree and cache | UI creates or installs the root and changes it on mutation. `src/piece/piece.c` `piece_snapshot_take` retains the root in `cached_snapshot`; UI `snapshot_uncache` drops the cache on mutation, and `piece_destroy` drops tree ownership. At take the cache and active root coincide. Workers can keep the old revision and its allocator alive beyond an edit, reload or buffer close. Charge a replacement staging tree to its own core while the old core drains. |
| Forward edit checkpoint | UI `piece_checkpoint_begin` saves the pre-edit root through a snapshot, ADD high-water mark and control state. A nested begin is refused. UI `piece_checkpoint_commit` drops the saved state; `piece_checkpoint_abort` transfers the old root and restores the ADD view. The begin root equals the active revision until mutation. Any snapshot exposed inside the checkpoint has its own lifetime across either endpoint. |
| Undo log and partial replay | `src/undo/undo.c` `append_edit`, `capture` and `replay` record operations, offsets and ADD spans. Retained history consumes record and ADD storage but **zero tree roots** (P, no root field in an undo record). UI `begin_replay` takes `replay_view` for a multi-record group immediately before beginning the checkpoint; both own the same cached pre-group header. UI `replay` can also take `replay_guard` on an in-group yield. That is the intermediate active revision, distinct from the pre-group view. `release_guard` precedes the next mutation. `commit_replay`, `abort_replay`, clear and destroy end the applicable holds. A caller keeping an intermediate view after resume must obtain an independently admitted hold. |
| Published session leaf and saved BASE | UI `src/editor/session.c` `publish` installs `leaf->snapshot` for current text, reusing the old snapshot for metadata-only publication. Independently, `leaf->reference` retains `b->saved_snapshot` for checkpoint diffs. The buffer keeps that saved reference across edits until UI `src/editor/checkpoint.c` `editor_saved_reference` replaces or clears it, or the buffer dies. A leaf can lag the active tree, and an older leaf can retain an older BASE. `replace`, `node_release`, `editor_session_forget` and `editor_session_close` drop graph ownership; leaf refs disappear only with the last owning graph. |
| Captured session graph / journal checkpoint | UI `capture` or `editor_publish_start` retains the then-current graph. This pins **both** text and reference of each included leaf, even for a buffer other than the save target. A later `publish` can replace either. `publish_worker` or `src/savectl/savectl.c` `worker` calls session `release` when done reading; failed handoff or pending teardown releases on UI. The selected `capture.snapshot` aliases the captured leaf text. `src/journal/journal.c` `journal_rotate`, `journal_save_prepare`, `journal_save_finish` and `journal_save_cancel` consume encoded records. A journal cutoff, batch or file-retention job adds no piece root of its own. |
| In-flight save / Save As | UI `request_buffer` retains the selected capture as `b->save_snapshot`. The worker can release its input while the buffer still needs the cutoff through finish or blocked reconciliation. A finish `capture` may select newer leaf text while `capture.reference` aliases the original save cutoff. UI `editor_save_tick` / `save_snapshot_drop` release on terminal resolution or transfer that very handle to `saved_snapshot` after a tracked save. Thus previous saved BASE, written cutoff and current text can all differ. `src/editor/commands.c` `save_as_adopt` / `save_as_free` similarly transfer or release the command snapshot, with a second owner for the writer. |
| Find | `src/find/find.h` `find_source` borrows immutable bytes for a call. `src/findui/findui.c` `findui_set_source_leased` retains the UI panel's source; jobs retain it on submission. Replacement can leave old panel leases and jobs on earlier revisions. UI `retire_source`, `reap` and `findui_maintain` dispose of them, returning job holds after physical completion. A flat-byte search has no tree hold. |
| Line index | UI passes an owned immutable `lineidx_src` to `src/lineidx/lineidx.c` `lineidx_build_start_owned` or prepaid restart. On refusal the caller still owns it. On acceptance `job_free` invokes its release hook on UI after `job_done` / `reap`, or an already-complete build releases immediately. Cancelled work can still read. A replacement build can diverge from a find or save source. `lineidx_bind_snapshot` keeps only a **backing** reference until `lineidx_destroy`; completed index metadata needs no revision slot. |
| Other readers | UI `src/editor/highlight.c` `editor_hl_request` and `src/editor/minimap.c` `editor_map_service` take on request and release on UI retirement. `src/editor/scrollctl.c` retains the resident scroll source through `editor_scroll_retire`. `src/layout/checkpoint.c` `layout_checkpoint_request` retains the long-line source and `checkpoint_worker` releases after reading. `src/editor/large.c` `editor_large_start`, `byte_seek_fn`, `editor_large_find_begin` cover warming, navigation and large-file search, with queued, running and physically retiring owners (worker last-read release or UI cleanup). `src/editor/clip.c` `editor_clip_selection`, `editor_clip_poll`, `clear_job` cover desired primary selection, primary job and copy/cut job; these can name different revisions until superseded or retired on UI. They can all share if submitted on unchanged text. Synchronous indent detection and index binding in `src/editor/buffers.c` release their temporary takes on UI. |

The lower-level save entry points are also producers. `src/file/file.c` `file_save_begin` takes on UI and `save_job` drops after reading; `src/savectl/savectl.c` also has a direct tree-take path. Route these through the save seat if exposed alongside session save. A reload's private mapping, an encoded clipboard payload and a completed find result hold no tree unless their owning caller still holds a source.

Under `docs/decisions/wave1-os-fault-lease.md`, a public mapped snapshot retain acquires the backing through the map hooks. A token detached for lineidx keeps the mapping and its validated fault ID alive independently of the revision. In v1 `src/piece/piece.c` `snapshot_drop` can queue the final worker return; `reclaim_drain` and `piece_reclaim` retire headers and nodes in batches. A cancel message, a last logical release and a physically free slot are different accounting events.

**Recommended v2 admission per buffer** (G). Allow one open edit checkpoint (forward or replay), one captured session graph across save/finish/plain publication, one save cutoff shared with Save As, and **two distinct service revisions** across all other consumers. The service limit lets interactive find/navigation and a bulk index build use different revisions simultaneously. Submitted, queued, desired and retiring sources all count. Fan-out on an admitted revision can reuse it, including across services; its service hold must still be registered before other owners can leave. Coalesce newer unsubmitted requests without taking a snapshot. Once workers finish, retire the oldest superseded source and schedule the latest request. Save recovery and publication have dedicated seats.

A conservative live root ceiling is `R = 1 + 1 + 1 + 2 + 2 + 1 + K = 8 + K = 10` (G, seats respectively for active, checkpoint, buffer's saved BASE, published leaf text/reference, captured leaf text/reference, in-flight cutoff and `K = 2` service revisions). This sum allows a lagging leaf; it is an upper bound, not a claim that every seat usually names different text. Acquire replacements before publishing them. New leaf fields alias the active text and buffer BASE, and a new capture initially aliases published fields. Serialize capture replacement through physical handoff; a still-running superseded graph consumes its seat. The replay guard aliases active until released. Cache headers, temporary publication headers, and physically retiring objects still enter the allocator ledger below. Embedders retaining an additional inside-checkpoint snapshot must take a service seat or explicitly raise and fund `K`.

## Tree geometry and mutation reserves

**Document size and height.** Use `D = UINT64_MAX = 2^64 − 1` logical bytes as the supported **L1 piece-document maximum** (P, width of `piece_tree.len`, subtraction-before-growth checks in `piece_insert` and `piece_insert_ref`, and the exact-EOF fixture in v1 `docs/decisions/P1.4d.md`). Repeated references can describe more document bytes than there are physical ADD bytes. Source offsets have a separate tag bit (`TOP`, `add_reserve`). PLAN specifies a **10 GiB** mapped-file integration case (G, Wave 2 exit fixture) and gives no universal maximum for files the application must open. The integrated path also has address-space, backing and index limits. For example, v1 `src/lineidx/lineidx.c` `lineidx_create_reserved` requires chunk count plus spare entries below `UINT32_MAX`; `lineidx_create` supplies 64 spare entries (P, default call argument). Its largest representable dense open with that default is `(UINT32_MAX − 1 − 64) × LINEIDX_CHUNK` bytes (P, last admissible entry count times chunk width), even before considering available memory. `D` sizes the piece arithmetic without promising a mapping of that size or imposing a new application file cap.

Let `F = FAN = 16` (P, branch children and leaf entry arrays), `h` be the number of branches on a root-to-leaf path (leaf root has `h = 0`), and `p` the count of nonempty pieces. For nonempty text `p ≤ length ≤ D` (P, at least one byte per entry). At full fanout a height `h` holds `F^(h+1)` pieces. A packed rebuild of even the most fragmented document therefore needs at most `h_pack = ceil(log_F D) − 1 = 15` branch levels (P, `16^16 = 2^64`). For an initial mapping substitute `ceil(length / CH_SIZE)` for `p` in the packed calculation; `build` and `piece_init_mapped_step` pack from the leaves up. Subsequent typing can create byte-sized pieces.

**A height guarantee requires a shape rule.** Full fanout gives the capacity of a given height. It does not bound the height of an arbitrary sparse tree. `splice` splits around half full, but `maybe_merge` can leave a small child beside a full sibling, and the build can leave a short right edge. There is no v1 minimum-half-full invariant to use in this proof. For v2 set `H = h_pack + 1 = 16` (G, the packed maximum plus one root-split level of slack). Check the prospective height before installing any growing root, including delete splits and steps inside bulk edits. At the ceiling preflight growth, or stage it under an allocation-free rollback checkpoint with sufficient traversal stack for the candidate. Refuse the whole uncommitted operation on overflow. Maintenance can repack the same piece descriptors in order, preserving ADD offsets, counts, append semantics and all older readers, then retry against a validated current revision. A full packed representation always fits below `H`. Keep `H + 1 ≤ MAXH` (P, leaf-inclusive cursor and walk stacks; v1 `MAXH = 32` entries). Stack length alone provides no such admission check. This gate avoids adding redistribution to every v1 mutation.

**One shared descent.** `cow` copies a shared node once and increments child refs when copying a branch. Exclusive nodes are reused. A fully shared point update copies `1 + h` nodes and `272 + 400h` payload bytes (P, one `LEAF_SZ` plus `h × BRANCH_SZ`). The exclusive `cursor_extend` can consume zero node slots. A split sibling and `root_grow` are additional allocations. `del_rec` can visit both boundaries, drop whole middle subtrees and copy a merge neighbour via `merge_children`; even removing bytes from the middle of a full leaf can split it. A reference insertion can touch many chunks. No single descent describes every edit.

At `h = 4` the path is `1,872 B`; with the `80 B` header and amortized slab tails it is `1,872 + 80 + (4 + 2) × 8 = 2,000 B`. At `h = 15` the path alone is `6,272 B` (all P, substitution into this layout and the two-slot slab below). These are the cases in `tests/piece_mem_test.c` `deeper_snapshots` and `docs/decisions/P1.4e.md`, “Unresolved frozen contracts”. The header's `1,920 B` is the historical G10f allowance (G, `src/piece/piece.h` MEMORY BOUND).

**Free slots required at entry.** The table transcribes `src/piece/piece.c` `reserve_insert`, `reserve_delete` and `piece_snapshot_take`. Every numeric expression is (P) from those branches. `f` means `root->cnt == FAN`, `r` is the current root count. These are free-slot requests; unused slots remain available when the call returns.

| Operation and condition | Leaf slots | Branch slots | Header slots |
|---|---:|---:|---:|
| Insert, `h = 0` and `n ≤ floor((F − r)/2)` | `1` if root shared, else `0` | `0` | `0` |
| Other insert, `h = 0` | `2n + 1` | `n + 1` | `0` |
| Other insert, `h = 1` and `n = 1` | `3` | `3` if `f`, else `1` | `0` |
| Other insert | `2n + 1` | `(2h + 3)n + 1` | `0` |
| Delete, `h = 0` | `2` | `1` if `f`, else `0` | `0` |
| Delete, `h = 1` | `4` | `3` if `f`, else `1` | `0` |
| Delete, `h ≥ 2` | `4` | `4h − 1` | `0` |
| Uncached snapshot (also a checkpoint's initial take on a miss) | same as delete | same as delete | `1` |
| Cached take / retain | `0` | `0` | `0` |

For a nonempty insert, `n = ceil(((add_len mod C) + len)/C)` with `C = CH_SIZE = 2^16 B` (P, `CH_SHIFT` and `piece_insert`). For `piece_insert_ref`, sum that expression over nonempty spans using each span's ADD offset and length. V1 reserves against the **segment count** even though it inserts up to `REF_BATCH = FAN − 2 = 14` descriptors per descent (P, `ins_batch_rec` needs room for the split existing entry). Validate span extents, growth, all products, class counts and rounding before any mutation. Zero-length no-ops take no reserve. Header owner saturation still follows the checked refusal in `piece_snapshot_retain`.

**Private ADD boundary.** `piece_checkpoint_begin` retains a restore view at the ADD mark. On the first uncached inside take for which the mark is unaligned, the root's `add_high` exceeds the mark, and the restore boundary is still shared, `checkpoint_snapshot_storage` installs a private writable copy in the restore view *before* publishing the snapshot. It copies the prefix bytes and newline prefixes and restores the prefix newline total. Prepay **one complete `sizeof(add_chunk)` per open checkpoint that may publish such a view** (P, `boundary_private` makes this once per checkpoint). On the pinned ABI this is `65,800 B = 65,536 + (65,536/512) × 2 + 4 + 4` (P, data, `uint16_t nl_prefix[]`, `nl_total`, refcount). Bill the actual aligned allocator stride. An aligned mark, unobserved extension or cached take requires no new private chunk. The ordinary pre-begin take itself does not trigger the copy.

On abort the UI restores the logical mark, swaps the directory and repairs the restored tail's newline state. A surviving inside snapshot continues reading its original bytes, including the transaction tail, while new edits can append at the restored mark. On commit the unused restore view is dropped. If the last observer is gone at abort, the ordinary boundary can be reused. Older detached chunks and directories remain charged until physically freed, across any number of subsequent checkpoints. Prepay the checkpoint descriptor, restore-view metadata and any private directory path needed for the boundary exchange as well. For the v2 shared directory require a prepaid, bounded path for that exchange and a constant-time retain at begin. V1 `add_store_prefix` allocates a pointer table and retains every prefix chunk at begin; plain take retains the existing `add_store`.

## Pool sizing and admission

Use the following vector in **(leaf, branch, header) slots**. It specifies the initial purchase, a refill target and the exact unit used at admission. L1 supplies the class sizes, checked reserve calculations and occupancy. The buffer owner supplies already backed storage from `src/base`. Merely reserving virtual addresses or allowing the allocator to fall back to libc does not fund an edit.

- `O` (P) is the physically occupied vector at provisioning time. Per class it equals installed slots minus slots actually on its free list. It includes the union of active and retained nodes, all cache/other live headers, and detached returns still to be reclaimed. This counter is available without walking every root. At open the packed tree's leaves are `max(1, ceil(ceil(length/C)/F))`; repeatedly round up by `F` to get each successive branch level, stopping at the root (P, `build`). Provision open/build scratch separately, then read actual occupancy. On refill include outstanding reservations made to another operation exactly once.
- At open or refill use a sizing height `b = min(H, current_height + 2)` (G, a selection replacement can grow the root once on its deletion and once on its single-segment insertion). Evaluate each class maximum over all root occupancies and heights through `b`. This avoids paying maximum-depth branch costs on every empty tab. Admission always uses the actual operation and height; a bulk edit can require an earlier refill.
- `U` (G) is one ordinary primitive's divergence credit per potentially older revision. Take the componentwise maximum of single-segment insert, arbitrary range delete and a fresh take through the sizing height. At `b = H = 16`, `U = (4, 63, 1)` (P, maximum of the reserve table at `n = 1`: insert requests at most `(3, 36, 0)`, delete `(4, 4H − 1, 0)`, and a fresh take adds its header). This credit lets a newly divergent revision keep a mutation's nodes. An old root may pin many further paths; those consume available credits and are included in `O` at the next refill. Repeated edits to disjoint leaves with just one saved BASE can eventually require a refill.
- `W` (G) is protected space for one foreground command. The recommended ordinary command covers begin, a selection deletion, one segment of insertion and publication of the edited snapshot. Reserve `W = (11, 162, 2)` at `H` (P): the initial uncached take needs delete-class free space but consumes only a header. Allow the delete to consume `(4, 63)`, insertion `(3, 36)`, and leave `(4, 63)` free for the final uncached take; allow both headers. The later sum already supplies the node-class free space required by begin. This is conservative, including at a full root. Services may borrow existing snapshots but must leave the foreground reserve available on admission. Once an edit succeeds, its live nodes become occupied and may reduce headroom for the next one.
- **Provision `N = O + (R − 1) U + W` slots**, componentwise (G, one initial divergence credit per possible non-active revision plus one foreground command). At the maximum sizing height with the recommended seats, headroom above `O` is `(47, 729, 11)` (P, `9 × (4,63,1) + (11,162,2)`). `R`, the number of credited primitives per older revision (default one), and the command envelope are policy. This is a finite initial reserve with checked exhaustion. For a service contract that promises unlimited subsequent edits while a snapshot is pinned, a path credit per revision is insufficient. In the worst case the retained storage grows to a whole disjoint tree per revision, plus growth of the active tree. The editor makes no such prepayment promise.
- For an actual command, test **available** class counts against its entire sequence before journal acceptance. For a larger paste, chunk-crossing typed input, `piece_insert_ref`, replacement or atomic replay group, substitute the actual `n` values and include every mandatory snapshot. A conservative requirement for each class is the maximum over steps of **earlier possible slot consumption plus that step's entry reserve** (P, prefix high-water mark). Bound consumption by entry reserve for mutations and by one header for a new take; use `H` for intermediate heights if unknown. Use checked sums across a group, including any guard taken on a yield. Sliced replay can instead preflight each slice under the original rollback checkpoint with sufficient space to yield or abort the unfinished group; preserve already completed groups. Larger commands can use free capacity or request their computed refill off-path. These gates never split an acknowledged edit into a partial success.

**Conversion to bytes** (P). V1 `slot_size`, `pool_grow` and `slab_tail` use two same-class slots and a `16 B` tail per slab. One slab request is `2 × 272 + 16 = 560 B` for leaves, `2 × 400 + 16 = 816 B` for branches and `2 × 80 + 16 = 176 B` for headers. Consequently

`B_nodes = 560 ceil(N_leaf/2) + 816 ceil(N_branch/2) + 176 ceil(N_header/2)`.

For example, a freshly created empty tree has `O = (1,0,0)` and `b = 2` (P, leaf root plus the replacement's two possible growth steps). The table gives `U = (4,8,1)` and `W = (11,22,2)` (P, the branch sum is `7 + 8 + 7`). The recommended initial target is `(48,94,11)` slots, or **`24 × 560 + 47 × 816 + 6 × 176 = 52,848 B`** in slab requests (P, rounding each class separately). This excludes ADD and core storage. Retain installed capacity or trim only off-path above the funded target. Never let `pool_trim_locked` hand prepaid capacity back to an allocator that must malloc to replace it. For a base allocator that rounds requests further, substitute actual slab strides and round each mapping to its page size for committed footprint. Report occupied, prepaid free and uncommitted bytes separately; free committed slots still cost memory. These new reserves need explicit funding alongside the historical G10f accounting, particularly when the private ADD boundary is due.

**Companion ADD budget** (P). At admission count physically occupied chunk slots across all views, including sealed or retiring ones. Add ordinary *new* chunks required to append the operation's bytes at the current tail, and one additional free private-boundary slot for a transaction that might expose its partial mark (G, recommended to reserve at begin). Multiply the resulting chunk count by `align_up(sizeof(add_chunk), class_alignment)`. An occupied private slot is already in the first term. Reserve the ordinary COPY/ADD payload, ref fallback, directory nodes, view/checkpoint descriptors, undo records and journal staging in their own classes, outside `B_nodes`. In particular, a requested deletion ref with more than `PIECE_REF_SPANS = 8` runs (P, `src/piece/piece.h`) may append **the entire range**, including existing ADD bytes (`piece_delete`, `collect`); use length as its safe append bound. A new chunk reservation for appended data and a private boundary serve different purposes and can both be due. For v2 directory metadata use the actual chosen layout's maximum touched entries/levels and allocator strides; its representation has no frozen byte size at this pin. A class admission failure anywhere rejects the transaction before externally visible work.

## Exhaustion and verification

Use a UI-owned `enum piece_pool_state` with `PIECE_POOL_READY` and `PIECE_POOL_EXHAUSTED` (G, one state admitting the nominated request and one recording its unmet requirement). Switch exhaustively, with no default. Record the request's class deficits or seat/height constraint and the revision against which it was planned. Workers can return holds or complete a refill; only UI adopts capacity or changes this state.

| Current state and event | Result and next state |
|---|---|
| READY, all required slots and companion resources available | Claim them before mutation or publication, consume from the claim and return surplus. Remain READY. |
| READY, a required resource is short | Enter EXHAUSTED for that request. A fresh snapshot is refused before publication (`NULL`); a failed checkpoint begin leaves a null handle; a piece mutation returns `PIECE_ERR_NOMEM`. A height/size range violation is distinguished from byte-pool depletion (`PIECE_ERR_RANGE` for unrepresentable input). A service request is deferred and retains only a request identity. For an unfunded user edit report **“Edit not applied — buffer memory is full.”** The text, cursor/selection, saved marker, undo cursor and journal sequence remain at the last committed edit. Keep rendering and saving available under their own admission rules. |
| EXHAUSTED, cancellation issued or return still queued | Remain EXHAUSTED while the recorded shortfall persists. Cancel a superseded service and release any idle panel/desired source. Keep saved BASE, save cutoff and checkpoint rollback ownership intact. No wait on a worker from the typing path. |
| EXHAUSTED, owner reclaims slots, an operation relinquishes its claim, maintenance installs funded slabs/chunks, or a repack completes | Recompute the full requirement for the current revision. Move to READY when it fits. An independent smaller request may run if its own preflight succeeds and protects any outstanding claim; re-evaluate the blocked request separately. Coalesced background work may restart with a fresh revision. A visibly refused user edit is retried only on fresh user input, so an old keystroke cannot appear at a moved cursor. |

Refusal in L2 precedes the PLAN §4.2 journal publish point. A failure inside an uncommitted checkpoint consumes its allocation-free abort path. Once journal RAM has accepted the group, ordinary journal fencing/recovery applies. Capacity pressure must never reach v1 `pool_get`'s free-list assertion, abort the process, or discard undo data solely to obtain a tree node.

**Implementation acceptance** (G). Extend v1 `tests/piece_test.c` `t_checkpoint_abort_nomem` and `t_checkpoint_snapshots`, `tests/piece_mem_test.c` `deeper_snapshots`, and `tests/piece_mt_test.c` `checkpoint_mt_test`, `reclaim_typing_test` and `reclaim_lifetime_test` with the oracles below. These are proposed red/green tests. Use public operations and a sized, refusing allocator; white-box counts can come from the test-build `piece_test.h`. The release integration path must observe an active Law 2 guard with zero mallocs (G, `CLAUDE.md` Law 2). Test success, refusal, recovery and the next ordinary edit.

## Corrections to the plan and harvest dossier

- PLAN §4.1 as amended and amendment A4 correctly classify `1,920 B` (G, v1 MEMORY BOUND). The dossier §0.2 and §4.2 still use it as a physical multiplier. Its nominal node layout in `piece.h` TARGET LAYOUT is guidance; use the compiled classes in `piece.c`. Plan's short list also needs the edit/replay checkpoint, the leaf's **current text**, and both fields of any older captured leaf. In `src/editor/session.c`, `publish` allocates the session graph leaf; `request_buffer` sets the buffer's in-flight cutoff; finish `capture` retains that cutoff as its reference.
- A fresh `piece_snapshot_take` reserves the **delete** vector plus a header. That does not guarantee an arbitrary subsequent insert, ref replay or compound edit. `add_store_prefix` walks the directory during **checkpoint begin**.
