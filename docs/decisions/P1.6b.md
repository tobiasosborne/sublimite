## §1 — capacity fallback / truncation / bulk refresh

**Verdict: fixed locally with explicit capacity refusal.** Every nonempty chunk
is at most `LINEIDX_CHUNK` bytes. Edit preflights all required entries before
cancellation or mutation; insufficient capacity returns `-1` with the old model
intact. It never creates an oversized approximate scan unit. Refresh counts at
most one chunk per call; a paste's remaining chunks stay approximate and can be
built asynchronously. This chooses rejection rather than accepting an edit
whose geometry cannot be represented. `lineidx_create_reserved` supplies an
explicit edit reserve on the allocating path (default create reserves 64).
A caller must reserve/recreate on its
allocating path before committing/retrying such an edit; no caller is changed
in this bead. Synthetic newline input also checks an exact total above
`UINT32_MAX`, without allocating the content.

## §3 — epoch wrap / premature source retirement

**Verdict: fixed locally.** Replace unsigned ordering with equality checks for
the live epoch and its wrapping cancellation successor. While busy, either
epoch must keep the lease alive; a later lease can exist only after the old
worker released the slot. A full ABA cycle conservatively delays retirement
rather than freeing a live lease. Preserve the callback's final `fn_done`
acknowledgement and pool-shutdown check. Deterministic span barriers cover both
completion-threshold wrap and cancellation-to-zero; release stays false until
the worker resumes and makes its last access.

Red (`--review=3`):
```
tests/lineidx_test.c:169: FAIL running
lineidx_test: 1 failure(s)
```
Green: `lineidx_test: ok`.

Follow-up API proposal (no `src/work` edits): expose a wrap-safe lease-complete
query, including skipped queued callbacks and slot reuse. Replace the remaining
direct slot-field observations when that API lands. Queued destruction latency
is still §11, outside this bead.

## §12 — owned memory / 10 GB G10f

the index object, allocated entry/summary capacity, all job objects/arrays and
declared retained source bytes. Unknown source ownership returns `SIZE_MAX`
instead of a falsely small number. `lineidx_build_start_owned` lets adapters
declare their retained bytes without changing `lineidx_src` or existing callers.
Ordinary start treats release-hook sources as unknown; borrowed sources count
zero extra bytes. Use initial chunks + 64 entries, rather than twice the chunks

restart refuses while retirement is incomplete and keeps caller ownership.

cancelled/retired job, explicitly owned source storage and complete deallocation.

## §13 — result transport bypasses generation-filtered mailboxes

**Verdict: confirmed; deferred because a complete fix needs another module.**
The deterministic opt-in regression (`--review=13`) pauses the first scan,
cancels its work handle, resumes it and drains the pool. No validated message
is delivered, yet poll adopts counts and the index becomes exact:
```
tests/lineidx_test.c:267: FAIL lineidx_poll(x) == 0
tests/lineidx_test.c:268: FAIL !lineidx_complete(x)
lineidx_test: 2 failure(s)
```
There is no green claim: this expected-red probe stays opt-in, outside the
passing suite. Existing transport is unchanged.

**Proposal:** add a selective `src/work` receive/dispatch API keyed by work
handle/generation (without draining other clients' messages), and explicit
lease-completion/retirement acknowledgement. Publish sealed immutable result
blocks or inline batches through that API, retain blocks until adoption or
discard acknowledgement, and bound UI adoption separately (later §8 bead).
Mailbox-full publication must retry/yield or retain an explicitly acknowledged
sealed block; dropping a wake-up cannot become dropping the only result.
Poll then consumes only validated batches and never consults `res`/`done_n` as
an independent cross-thread result channel. This preserves existing poll callers,
including the untouched benchmark. Alternatively, an application dispatcher
could route messages into a new lineidx entry point, but that requires changing
other modules/callers too. Both paths need coordinator authorization/scope.
