# P1.4a: buffer-kernel bench matrix (edit-4w1.16)

`bench/piece_bench.c` is the frozen referee for the P1.4 competition (bptree, rope, flat piece
array, hybrid line-gap). Variants implement `src/piece/piece.h` in `variants/P1.4/<name>/` and are
measured by this file unchanged. Run: `tools/bench_variant.sh variants/P1.4/<name> [args]`; compare:
`python3 -I tools/pareto.py a=a.log b=b.log`. Evidence tag for numbers from this box: (M)[bat] unless
the log header says `[AC]`; the header line `# piece_bench ... power=` stamps it.

## Output format

```
BENCH row=<row> col=<col> p50=<v> p99=<v> unit=<ns|us|ms|B|MB|GB/s|count> n=<samples> gate=<expr|none> status=<PASS|MISS|TRACK|SKIP|TIMEOUT>
```
Single-valued cells (memory, counts, one-shot totals) print p50 = p99. `unit=count` is an addition to
the brief's list (for `pieces`, `ops_done`). Gate expr: `p99<=50us`, `p50<=63ms,p99<=84ms`,
`p99<=<bytes>B`. Exit code is non-zero if any gated cell is MISS or TIMEOUT, or a row crashes, is killed
by its backstop, or fails an internal correctness check (exit 2). TRACK cells never fail. Human tables
(`== row ==` blocks) follow each row. Lines starting `#` are headers. `tools/bench_variant.sh` adds
`BENCH row=build col=text_size` (sum of `.text` from `size` over the variant's own objects).

Flags: `--quick` (counts and sizes /64, floor 4; corpus files are not shrunk, mapped rows still open the
full 1 GiB lazily), `--huge`, `--rows=a,b`, `--cap=SECS` (default 60), `--corpus=DIR`, `--selftest`.

Isolation: each row runs in a forked child (its own allocator counters, no state leaks between rows).
`--cap` is a soft per-phase wall cap checked between ops (every op in timed passes, every 4096 ops in
untimed batches); a capped cell prints TIMEOUT with the samples gathered so far. A hard per-row
backstop of 12 x cap + 60 s (page-cache warm-up) kills a child stuck inside a single call and prints `col=row_total ... TIMEOUT`.

## Determinism

xorshift64* with fixed seeds per phase (identical op sequence on every variant and every pass).
Offsets uniform over the current length. Inserted text: printable ASCII, ~1 newline per 60 bytes,
1-64 bytes (paste: 1 MiB). Deletes 1-64 bytes. All timers are `CLOCK_MONOTONIC` ns.

## Cells: what is measured (start -> end)

Every generic row (code_1m, log_1g, oneline_1g, oneline_10g, dense_short, random_edits_1e5,
typing_1e4, undo_1e4, undo_1e5) runs the same four phases:

1. **open / first_op** (reps: 20 code_1m, 10 dense, 5 log/oneline, 3 edit rows): fresh tree per rep.
   `open` = `piece_init_copy`/`piece_init_mapped` call only. `first_op` = start of init -> return of a
   1-byte `piece_insert` at offset 0 (so it includes open). `piece_create` is outside both.
   Mapped rows: the file's page cache is warmed once by a sequential `pread` pass; mapping page faults
   are not pre-populated and are inside the cells. `mem_open` = counting-allocator peak right after
   rep 0's init (before the first_op insert).
2. **batch_total** (rows with a batch): untimed (no per-op clock reads) run of the whole op batch on a
   fresh tree, same seed, wall time of the op loop only (open excluded). Reps: 11 for typing_1e4 and
   undo_1e4, 3 for random_edits_1e5 and undo_1e5.
3. **insert / delete (/ insert_ref)**: one timed pass on a fresh tree, one sample per op (clock around
   the single call). Memory counters are reset at the start of this pass; `peak_mem` and `pieces`
   (`piece_piece_count`) are read at its end.
4. **queries** on that edited tree (so pieces > 1): `read_viewport` = `piece_iter_begin` at the byte of a
   random line (looked up outside the timer) through the iteration until 300 newlines or 76 800 bytes
   (300 x 256, bounded so a one-line 1 GB file costs the same as code), each byte counted with
   `memchr`. `byte_to_line`, `line_to_byte` = one call each at a uniform random offset/line.
   `piece_line_count` is called once untimed first (a variant that indexes lazily pays that outside the
   cells). Counts: 2000 mini-phase ops for the open rows (code_1m, log_1g, oneline_*, dense_short),
   300 viewports, 1000 byte_to_line, 1000 line_to_byte (each kind has its own cap window), all /64 under `--quick`.

Row specifics:
- `code_1m` ascii_code.c via init_copy; `dense_short` dense_short.txt via init_copy; `log_1g`,
  `oneline_1g` mmap + init_mapped. `oneline_10g` only with `--huge` and only if the file already exists
  (never created); otherwise SKIP.
- `random_edits_1e5`: 10^5 ops, 50/50 insert/delete, on a log_1g mmap.
- `typing_1e4`: 10^4 keys on code_1m, cursor starts at len/2 and advances; ~1/20 keys is a backspace
  (1-byte delete, cursor--), ~1/40 inserted bytes is `\n`. Coalescing makes `pieces` tiny.
- `undo_1e4` / `undo_1e5`: per op, `piece_delete(off,len,&ref)` then `piece_insert_ref(off,&ref)` at the
  same offset on log_1g. Delete is timed into `delete` (gated), the reinsert into `insert_ref`. In the
  timed pass the bytes are read before and after (outside the timers) and compared: a variant that
  restores different bytes aborts the row. There is no `insert` cell for these rows.
- `paste_1m`: 20 reps (5 quick), each on a fresh code_1m copy, one 1 MiB `piece_insert` at a random
  offset; generation of the text is outside the timer. `peak_mem`/`pieces` from the last rep.
- `snapshots_100`: code_1m copy; 100 snapshots (one every 100 edits, the first before edit 0) alive
  while 10^4 random edits run (each edit timed into insert/delete); every 100 edits one random live
  snapshot is read through `piece_iter_begin_snapshot` (`read_viewport`, same definition via snapshot).
  `snapshot_take` = the call. `snapshot_release_all` = releasing all live snapshots (total, TRACK).
  `pathcopy_ref` = 1920 B x edits (perf 2.6 reference, TRACK, printed for comparison with `peak_mem`).
- `line_jump_1e7` (historical name retained; amended by P1.4a-b below): count log_1g through
  `piece_line_count` on a disposable tree, then target floor(0.9 x line_count), /64 in quick mode.
  Print `line_count` and `target_line` as TRACK. Five fresh trees and mappings measure
  `line_to_byte_cold` (no prior query, TRACK). Five more fresh trees each run an untimed first jump
  and `piece_line_count`, then repeat the jump as `line_to_byte_indexed` (G7j warm gate).
  `open` measures init for the cold samples (TRACK). On the last tree, `line_to_byte` samples random
  lines within +-10 % of the target (clamped below line_count) and `byte_to_line` samples random
  offsets; both remain TRACK. Every timed target result is checked by byte-to-line round trip
  outside the timer. The page cache is warm; cold means new mapping and unresolved tree counts,
  not cold device I/O.

## Gates (copied from perf/01-perf-target.md; nothing else is a gate)

| Cell | Gate | Source |
|---|---|---|
| `insert`, `delete`, every row | p99 <= 50 us | 2.6 "A PB ~ 8 us; budget 50 us" (inside G1). Context printed: UI-slice ceiling 0.5 ms (s3) |
| `undo_1e4 batch_total` | p50 <= 63 ms, p99 <= 84 ms | G9 10k-step undo, Target A (s0.2, 2.9). G9 includes a full frame: kernel passing is necessary, not sufficient |
| `paste_1m` | p50 <= 5 ms, p99 <= 15 ms | G9 1 MB paste, Target A (s0.2). Same note |
| `mem_open`, unedited copy | <= 1.25 S + 64 KiB | G10f (s0.2, s2.12), hard maximum |
| `mem_open`, unedited mmap | <= 32 B x ceil(S/64 KiB) + 2 MB | G10f |
| `peak_mem`, edited | <= base + 96 B x pieces + 1.25 x (typed + deleted) | G10f; base = the unedited bound of that source (the original is still owned) |
| `line_jump_1e7 line_to_byte_indexed` | p50 <= 30 ms, p99 <= 50 ms (G) [AC, prov] | G7j warm, Target A (s0.2); kernel query after counts are known, per P1.4a-b |

Everything else is `gate=none status=TRACK`: `open`, `first_op` (context only: G5 open warm 6 / 9 ms, an
end-to-end gate including a frame), `snapshot_take`, `snapshot_release_all`, `insert_ref`, queries, `pieces`,
`undo_1e5`, repeated line jumps, `snapshots_100 peak_mem`, all non-gated `batch_total`.

## Interpretations (flag if wrong)

- **Edited memory gate includes the base term.** The brief lists only 96 B x pieces + 1.25 x (typed + deleted)
  + path copies; the header of piece.h (and G10f's own text) has the original's footprint as well, so the
  base is added (copy: 1.25 S + 64 KiB; mmap: 32 B x ceil(S/64 KiB) + 2 MB). The `+ 4 KiB` fixed overhead
  of piece.h is not added. `deleted` counts every deleted byte (upper bound on deleted-original bytes), as
  in piece.h. The 64 B/undo term belongs to the undo module and is left out. Gated on `peak_mem` (peak over
  the timed pass, not the end value). snapshots_100 `peak_mem` is TRACK (path copies are unbounded by
  formula).
- **Memory gate in undo rows**: ref-reinsert grows pieces; counted via `pieces`.
- **`insert_ref` is TRACK**, not folded into the insert gate: the brief gates "insert and delete"; a
  reinsert is neither an insert call nor named. Moving it under the 50 us gate is a one-line change but
  would be inventing a gate.
- **Percentiles of few samples**: batch_total has 3-11 reps and first-query has 5, so p99 is effectively
  the max. Gated batch cells (undo_1e4: 11 reps, paste: 20) therefore gate on the worst rep.
- **Percentile method** is the harness's nearest rank. Per-op timer overhead (~25 ns x 2) is inside per-op
  samples and outside batch_total.
- **Timeout** of a gated cell counts as a failure (exit 1); of a TRACK cell it only prints TIMEOUT.
- **A gated cell with no samples** (row skipped) is SKIP, never a failure (missing corpus never fails).
- The `unit=count` addition and the extra cells (`mem_open`, `ops_done`, `pathcopy_ref`,
  `snapshot_release_all`, `line_to_byte_cold`, `line_to_byte_indexed`, `line_count`, `target_line`, `insert_ref`) are the only deviations from the cell list.

## Untracked aspirations (NOT gates)

The bead text mentioned snapshot_take < 1 us and 10^5 random edits in a 1 GB mmap < 1 s. Neither number is

## Tooling

- `tools/bench_variant.sh <dir|src/piece> [args]`: release flags of the Makefile, `-I<variant>` before
  `-Isrc`, other `src/*/*.c` (not piece, not modules with an LDLIBS file) compiled as an archive (compile
  failures in other modules only warn). Output `build/variants/<name>/piece_bench` (`intree` for src/piece).
- `tools/pareto.py name=log ...`: markdown table, then non-dominated variants (dominance over p99 of all
  non-SKIP cells common to both, plus text size; TIMEOUT = +inf; `--tol=PCT` optional noise tolerance, default
  0), then per variant the cells it uniquely wins and its MISS/TIMEOUT count.
- `bench/piece_bench --selftest` checks the formatter, gate evaluator and pareto.py on canned logs (run from
  the repo root; it calls `python3 -I tools/pareto.py`).

## Caveats for `make bench`

`make bench` runs every bench with no arguments, i.e. the full matrix including three 1 GiB-mmap batch rows
and a 60 s cap per phase: with a slow kernel (the stub) that is many minutes and exits non-zero on MISS. Use
`--quick` for CI.


## Amendment P1.4a-b (edit-4w1.20)

Tobias's consultant decision unfreezes `bench/piece_bench.c` for this line-jump correction only.
The old full row requested zero-based line 10,000,000 in a fixture with only 8,947,842 lines.
It returned EOF after a full 1 GiB newline count: G7 index territory, rather than a correct viewport
jump. Applying G7j's 30/50 ms warm gate to that first unindexed count was the P1.4a mapping error
identified in P1.4.md caveat 1. The original variant comparisons are historical, not evidence
against the corrected G7j cell.

The row keeps its historical CLI name `line_jump_1e7` so existing callers still select it; its
printed `target_line` is authoritative. The target is exact integer floor(0.9 x line_count), with
no 10^7 cap (a cap would stop representing 90% on larger fixtures). The fixture's count comes from `piece_line_count` at runtime on a disposable tree,
outside all timers; that tree and mapping are destroyed before measurement. Actual count on
2026-10-09: 8,947,841 newlines / 8,947,842 lines (M)[AC], giving full target **8,053,057** (derived,
TRACK). Quick mode uses floor(8,053,057 / 64) = **125,829** (derived, TRACK); neither target is EOF.
The target calculation is covered for tiny counts, the measured count, counts above 10^7, and
UINT64_MAX without floating-point rounding or multiplication overflow.

`line_to_byte_first` is replaced by two unambiguous columns:

- `line_to_byte_cold`: first line query on each fresh mapping/tree, no counts queried first;
  gate=none, status=TRACK, never fails on latency. G7 index warm 80/125 ms (G)[AC, prov] is printed
  only as context. A soft cap still prints TIMEOUT without failing this ungated cell.
- `line_to_byte_indexed`: repeated same-target query on a tree after an untimed first jump and
  full `piece_line_count` resolve counts. This is the kernel proxy for "index published".
  Gate: **G7j warm, Target A p50 <= 30 ms, p99 <= 50 ms (G)[AC, prov]**, perf/01-perf-target.md s0.2.
  A kernel PASS is necessary, not sufficient for G7j's request-to-submitted-viewport endpoint.

The repeated random `line_to_byte` and existing `byte_to_line` cells remain TRACK; random line
requests also stay inside the counted range. Cold, indexed, and repeated-query phases have their
own cap windows. Mappings are remade between samples so preparatory counting cannot prepopulate
the cold sample's mapping faults. The stub does not cache counts, so an indexed full-query MISS
is an implementation limitation for the synthesis, not a reason to gate the cold count again.

Next to the existing THREADS paragraph, `piece.h` now states: "THREADS (P1.4a-b): no thread
creation inside piece_*; bulk counting of unindexed mapped bytes belongs to P1.6 lineidx on the
src/work pool." No API changes. In-kernel pthread counting is rejected: workers receive snapshots,
and shared state must cross src/work mailboxes; P1.6 owns the cancellable bulk scan.

`tools/bench_variant.sh` cleans only its `v/`, `o/`, `libother.a`, `piece_bench.o`, and `piece_bench`
outputs. It preserves sibling worker outputs (fuzz binaries and logs). Deleting the entire variant
directory is rejected. Regression command (after building the bench):
