# P3.4 — scroll state and integration contract (edit-zzj.4)

## Decision

Vertical scrolling lives in `src/scroll`, separately from the cursor/selection
owner in `src/view`. Every view/tab owns a `scroll_state`. `scroll.c` contains
pure state transitions; `index.c` is an explicit source/index adapter. There
are no module globals, clocks, velocities, timers, allocation calls or retained
source pointers. All failures are return codes. A failed adapter call leaves
the scroll state unchanged; an explicitly requested index seek may already
have published its bounded prefix. The caller owns the index and source lease.

The pixel accumulator uses integer Q8 pixels. `subrow_q8` is always less than
`row_height * 256`; `first_line` is stored separately, so multiplying a very
large file's line number by its row height cannot overflow. XI2/plat already
carry fractional wheel remainders and deliver 256 units per notch. Feed `dy`
directly to `scroll_wheel`: both core and smooth notches scale to three rows,
with no event rounding or second floating-point remainder. `scroll_pixels`
also accepts Q8 pixel deltas directly. Reversal is exact before endpoint
clipping. Endpoint clipping discards overshoot immediately, so reversal moves
immediately. No inertia in this version. Horizontal `dx` remains the caller's
existing horizontal-scroll policy; this module owns the vertical axis.

Exact line counts constrain the top row to `max(lines - rows, 0)`. Unknown
counts are estimates, never an upper bound on a requested deep line. The
pending physical row delta is stored independently from the estimated line
label: an estimated label reaching zero must not strand a byte viewport in
the middle of a file. Page keys move a full viewport and remove its fractional
offset. Home/end map to document motions only for the caller's Ctrl+Home/End
binding; plain Home/End continue through view's line motions.

For an unpublished region, relative scrolling walks physical newlines from
the current line-start byte. A bounded walk that cannot reach its target uses
byte density, then aligns to a real line boundary. Byte seeks also align in a
bounded suffix. A suffix without a newline retains a proven earlier boundary
(or zero); this can be a coarse position on a very long unindexed line. A
bounded look ahead/backtrack clips at EOF without requiring a full line index.
No foreground call scans the entire file.

Publication alone keeps `first_byte` and `subrow_q8` unchanged. It adopts an
exact line label when available. Consequently every physical row, including
the cursor's row, keeps its pixel position. Publication racing a pending
relative event applies the event's physical delta before relabeling. It does
not reinterpret the old density label as a new absolute target. Absolute
line-jump requests are different: the editor retains the requested line in its
job and can reissue `scroll_seek_line` when that target becomes exact.

`scroll_follow` accepts an already compatible row ordinal. The integration
entry point `scroll_follow_cursor` accepts the view's cursor byte instead:
exact index queries use the pure policy, nearby unpublished regions count
physical rows, and distant cursors use bounded line-start seeding/backtracking.
Margins shrink to `(rows - 1) / 2`. The top margin includes fractional clipping;
following the clipped boundary clears the fractional offset. Buffer ends take
priority over symmetric margins. Following runs only after motion/edit; pure
scroll and index publication never request following.

Byte scrolling may keep a coarse earlier boundary, but cursor following must
prove the cursor's actual line and the preceding rows needed for its margins
and EOF clipping. A suffix scan with no newline cannot prove that an earlier
anchor belongs to the cursor's line unless the scan covered the whole gap.
Exhausting the bounded scan/backtrack returns `SCROLL_MORE` with the entire
scroll state unchanged. The caller retains the completed motion's pending
follow intent and retries after enough index publication; a later pure scroll
cancels that intent. Publication alone never creates a new follow request.

## Integration contract

These are the calls for the scroll-wiring follow-up to edit-457.16. This bead
does not modify `src/editor`, `src/main.c`, `src/view`, `src/layout` or render's
frozen header. Scroll is the authoritative vertical viewport. View remains
the authoritative cursor and selection. Ignore view's built-in vertical
viewport changes after its commands; mirror scroll's values back before
layout. Keep view's existing horizontal cursor-follow changes.

The current adapter is for wrap-off logical rows. Do not silently apply these
logical-row deltas to a wrapped view. The visual-row adapter described below
is needed before routing wrapped wheel/page scrolling to it.

1. **Open/tab initialization:** obtain `lineidx_line_count(index)`; call
   `scroll_init(&tab.scroll, {visible_rows, cell_h, margin},
   {source.len, count.value, count.exact})` once. Storage is embedded in the
   tab/view, with no allocator. To restore a saved viewport use
   `scroll_seek_byte(saved_first_byte)` and `scroll_resolve(..., 0)`; saved
   line labels may be estimates. Restore a valid saved `subrow_q8` separately.
2. **Each core/XI2 wheel event:** call `scroll_wheel(&s, ev.dy)` once, then
   `scroll_resolve(&s, index, &current_source, 0)` once. Do not divide `dy` by
   the wheel unit. Platform XI2 filtering already owns emulated-core event
   suppression. Do not call `view_command` or any follow function. Mark the
   viewport/frame dirty if bytes, pixels or the displayed line label changed.
3. **Each PageUp/PageDown/Ctrl+Home/Ctrl+End key:** call
   `scroll_key_motion(&s, mapped_scroll_key, &motion)`, then
   `scroll_resolve(..., 0)`, then
   `view_command(&v, motion, shift, NULL, 0, &change)` exactly once. This returns
   `VIEW_PAGE_UP/DOWN` or `VIEW_DOC_HOME/END`; Shift remains view's selection
   argument. If `VIEW_MORE`, run one `view_continue` per allowed editor slice
   until completion or cancellation. Restore scroll's viewport fields after
   every view slice. On completion call `scroll_follow_cursor(..., cursor)`
   once. If it returns `SCROLL_MORE`, retain the cursor byte in a caller-owned
   pending-follow job and retry after publication. A new pure scroll cancels
   that job. Never follow view's temporary repair cursor during `VIEW_MORE`.
4. **Each other completed cursor motion:** the existing `view_command`/
   `view_continue` path runs normally. Call `scroll_resolve(..., 0)` then
   `scroll_follow_cursor(&s, index, &current_source,
   v.state.selection.cursor)` once at completion, retaining/retrying a
   `SCROLL_MORE` result as above. Selection extension is a motion; wheel-only
   selection preservation is not a motion.
5. **Each applied edit:** keep the editor's existing piece/index transaction
   and `lineidx_edit` ordering. Once the current source and index lengths agree,
   transform the old viewport byte through the replacement: bytes strictly
   before the edit stay fixed; bytes at/after `off + old_len` shift by
   `new_len - old_len`; bytes inside deleted content map to `off`. Obtain the
   new `lineidx_line_count`, call `scroll_set_extent`,
   `scroll_seek_byte(transformed_anchor)`, and `scroll_resolve(..., 0)` once.
   This also repairs an anchor whose preceding newline was deleted. After the
   edit's cursor repair/motion completes, call `scroll_follow_cursor` once.
   Partial edit prefixes reported with `VIEW_MORE` still need extent/anchor
   repair, but follow waits for the final cursor. Retain/retry a `SCROLL_MORE`
   result as above. Do not change selection here.
6. **Each resize/font-height change:** call `scroll_resize(&s, new_config)`
   once then `scroll_resolve(..., 0)` once, while layout/backend are idle.
   Resize preserves the pixel remainder (carrying it into new-height rows)
   and clips endpoints. Use the visible row count, not the overscan grid count.
   Resize alone does not follow; an explicit later motion/edit does.
7. **Index/work publication:** route/drain the existing work messages and call
   `lineidx_poll(index)` as the index owner already does. Before the next
   frame call `scroll_resolve(..., 0)` once, even without a pending wheel event.
   Compare the old/new line labels and approximation flag to decide gutter
   damage. Keep the existing byte anchor/pixel offset. Only retry follow if
   a completed motion/edit left an uncancelled `SCROLL_MORE` job.
8. **Absolute jump/byte scrollbar:** call `scroll_seek_line(target)` or
   `scroll_seek_byte(target_byte)` once followed by `scroll_resolve(..., 0)`.
   A requested line beyond the published prefix is explicitly approximate.
   Save a pending line-jump target in the caller's cancellable job. The caller
   may invoke `lineidx_seek_line` in bounded off-typing-path slices; alternatively
   `scroll_resolve(..., budget)` exposes that bounded foreground seek explicitly.
   Budget is at most `SCROLL_SCAN_BUDGET`; lineidx rounds a positive smaller
   budget up to one chunk. Reissue the saved target once its query becomes
   exact. Byte scroll and line-jump requests leave the selection unchanged;
   cursor navigation/following is a separate motion decision.

**Each frame**, after publication/event handling and when the backend accepts
the next frame:

1. Call `scroll_resolve(..., 0)` once to adopt any newly exact label. No
   unconditional `scroll_follow*` call belongs in the frame loop.
2. Mirror `s.first_byte`, `s.first_line` and `s.approximate` to view's viewport
   fields without touching `v.state.selection`. For wrap-off, set
   `v.state.visual_byte = s.first_byte` as well.
3. Call `render_frame_begin`, then `layout_set_cursor` and
   `layout_set_selection`, then `layout_begin(tree, {s.first_byte,
   s.first_line, hscroll, s.extent.lines})` if the viewport changed. Keep the
   existing `layout_edit`/row-relayout path when its unchanged-viewport
   preconditions hold. Do not use `LAYOUT_LINE_UNKNOWN` to force a deep
   piece-tree scan of an unindexed file; the label is explicitly approximate.
4. Run `layout_run` one slice at a time, checking pending input between
   `LAYOUT_MORE` results. Complete the final consistent grid before submission.
5. Apply a drawing origin of `-s.subrow_q8 / 256` pixels, clip to the viewport,
   obtain canonical strips with `render_dirty_strips`, call
   `render_backend_submit` once and `render_backend_present` once. The existing
   asynchronous completion path owns retries and the one-frame queue slot.
   Sub-row-only changes damage the full viewport even when the byte is stable.

Step 5's pixel-origin operation is a required integration dependency, not an
existing render call. The current frozen grid/backend API draws integral rows.
Reserve one extra layout row at initialization to fill the lower clipped edge
when the offset is nonzero; scrollbar/hit testing must subtract the same origin.
Until a separately authorized renderer change lands, the scroll state is
pixel-exact but the current renderer can show only row-step movement.

### Proposed accessors/adapters (no edits in other modules)

- A future renderer API must accept a Q8 vertical origin and viewport clip,
  while permitting an overscan row without changing the visible surface
  geometry. It needs a separate frozen-contract amendment; an editor-only
  assignment to the current `render_grid` cannot achieve pixel translation.
- Wrapped integration needs an adapter that advances a caller-owned
  `layout_wrap_row` by signed visual rows and reports whether its boundary is
  exact. Existing `layout_visual_row` can seed/query adjacent rows but repeated
  calls are not a indexed arbitrary-distance jump. Proposed layout accessor:
  `layout_visual_advance(context, tree, row, direction, rows, budget,
  out_row, out_approximate)` with no allocation and an explicit continuation.
  Scroll's pure pixel accumulator can then use visual-row extents instead of
  logical-line extents. Neither view nor layout is modified by this bead.

## Verification and measurements

Red-first unit tests cover exact accumulation/reversal, extreme integer
deltas, page/document boundaries, fractional top margins, resize, independent
byte anchoring, publication between transition/resolution, EOF before the index
is built, bounded long-line behavior, error-state preservation and allocation
guards. The initial runtime red line was:

```
scroll_test:23: FAIL s.first_line == 103 && s.subrow_q8 == 0
```

The fuzzer uses an independent absolute-pixel model for pure transitions and
a scalar physical-line-start model for source/index sequences, including
publication racing an event and byte-based follow. Models do not call scroll
to derive their expected positions. Sanitizer allocation interposition is
inert; the gcc test's active guard is the allocation evidence.

`scroll_bench` uses the existing immutable `log_1g.txt` mapping, verifies its
line count and derives the target using an independent scalar oracle. This
warms every page outside the request timer. Each jump starts with an entirely
unbuilt index and includes `scroll_seek_line`, a synchronous
`lineidx_seek_line` partial-prefix scan stopping at the target chunk,
`scroll_resolve`, layout and a complete correct viewport submitted/presented
to the null backend. All viewport starts and ASCII cells are checked against
an independent oracle outside the timer. Open-time allocations are excluded.
This is a stronger endpoint than computing only the first correct row.

The synchronous partial scan is deliberately charged in full; it is not
advertised as the future cancellable editor job. The benchmark does not run
the full background build, prebuild an index, or reuse an indexed jump sample.
The last sample's published prefix is then reused for the cadence probe.

Cadence runs a changing mixed core/smooth stream, through module resolution,
layout, submit and null present on every step. It records every duration,
p50/p99, the maximum and the number exceeding half a refresh period. It does
not sleep to synthesize refresh timing. It cannot count displayed refreshes or
exercise renderer pixel translation: real G3z needs editor wiring and a real
display. No window is opened, and all verification uses display :99.

G7j comparison: p50 ≤ 30 ms (G), p99 ≤ 50 ms (G), target-A warm. G3z proxy:
zero over-budget steps in 10,000 (G), every step ≤ 4.166667 ms (G) at
120 Hz (G). These are comparisons on the shared box, not coordinator verdicts.
The benchmark's default exit code fails a miss; `--track` records all misses
and returns success only when the experiment and correctness checks complete.

## Fix-up after rebasing onto current main, 2026-10-09

The coordinator's failing assertion is valid under the existing `scroll.h`
contract. This was a scroll implementation omission, not a changed lineidx
reservation/capacity/publication rule or a work-pool rule. The fixture creates
an unbuilt index, performs no edit or background submission, and invokes no
work API. P1.6b still documents approximate real-line-boundary fallback; it
does not promise that a coarse boundary contains a distant cursor. P1.8c's
slot reservation and bounded-drain changes cannot affect this fixture.

`scroll_follow_cursor` previously reused the byte-scroll coarse fallback for
both its cursor seed and margin/EOF backtracking, then unconditionally
reported success. It had no `SCROLL_MORE` return path. The bounded suffix in
the reported case contains no newline; the retained earlier boundary is
valid for scrolling but does not prove cursor visibility. The adapter now
allows coarse positioning only for ordinary scrolling. Follow returns
`SCROLL_MORE` when the cursor seed or required preceding rows are unproven,
without publishing its temporary scroll state. A complete bounded walk from
the current anchor still proves a newline-free row. Index publication allows
the caller to retry using exact queries.

All assertions in `tests/scroll_test.c` now go through a cleanup label. Every
index-owning fixture destroys its index on success or failure, and guarded
fixtures end an active allocation guard before destroying the index. This
removes the assertion-exit leak rather than hiding it by weakening the test.
New regressions cover unchanged state/pixel offsets on `SCROLL_MORE`, a proven
nearby row, a proven distant seed, exhausted margin/EOF backtracking, and
retry after partial and complete publication. No lineidx/work implementation,
frozen header or build-file changes were needed.
