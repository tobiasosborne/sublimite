# W0.6c inspector wire revision 1

This specifies the bytes used by the v1 adapter and the native v2 adapter. The [Wave 0 design](wave0-contract-design.md) defines the submit fence and the adapter's capture responsibilities. The advisor's T1 and T2 trims use the same format. The v1 adapter returns INVALID for ARM, emits one settled frame for SNAP and NEXT, and leaves the minimap bit clear.

A word is an unsigned 32-bit integer (P, the X11 data32 element and the design's coordinate, count and serial type). Each byte has eight bits, so a word occupies four bytes. Request words use the X connection's byte order. Reply and payload words are little endian. The signed translation uses a two's-complement word. There is no padding or alignment, including after a string. Offsets below are byte sums of the preceding fields within the named record. A `rect` occupies four words in the order `x, y, width, height` with exclusive right and bottom edges. Enum values are sequential from zero in design order. Flag values are successive powers of two in the listed order.

| Record | Offsets and extent | Fields in wire order |
|---|---|---|
| X11 request | `0, 4, 8, 12, 16` · five words (P, ClientMessage data32) | `revision = 1` (initial schema), `operation` (ARM = 0, SNAP = 1, NEXT = 2), nonzero `ticket`, `previous_submit_serial`, `reserved = 0`. Use zero for `previous_submit_serial` on ARM and SNAP. On NEXT it is the exclusive lower bound and may be zero for no prior submit. |
| Completion packet on S | `0` magic, `4, 8, 12, 16, 20` words · 24 bytes (`4 + 5 × 4`) | ASCII `SCEL`, `revision`, `ticket`, `result` (OK = 0, ARMED = 1, VERSION = 2, ORDER = 3, SIZE = 4, INVALID = 5), `submit_serial`, `payload_bytes`. This is the entire packet. |
| Mapping payload on M | `0` count, `4` first frame | `frame_count`, then that many frames. One (settled only) or two (first-action followed by settled), from the two possible observation points. |
| Frame header | `0, 4` tags, `8, 12, 16, 20, 24, 28` dimensions, `32` rect, `48` translation, `52` rect, `68, 72` words · 76 bytes (`8 × 4 + 2 × 16 + 3 × 4`) | `witness` (settled = 0, first-action = 1), `submit_serial`, `window_width_px`, `window_height_px`, `columns`, `rows`, `cell_width_px`, `cell_height_px`, `document_rect_cells`, `scroll_y_q8` (signed), `scroll_rect_cells`, `extra_rows`, `provided_sections` (cells = 1, tabs = 2, bottom row = 4, minimap = 8). The section bodies immediately follow in that order. A clear bit omits the entire corresponding body, including any count word. |
| Cells section | `0` count, `4` first cell | `cell_count`, then that many cells in row-major order, including trailing blanks and the extra row. |
| Cell | `0, 4, 8, 12, 16` words, `20` string bytes · `5 × 4 + text_bytes` | `kind` (blank = 0, painted text = 1, wide continuation = 2, unresolved artwork = 3), `attributes` (drawn caret = 1, underline = 2, wide lead = 4), `foreground_class`, `background_class`, `text_bytes`, then exactly `text_bytes` UTF-8 bytes. |
| Tabs section | `0` count, `4` first tab | `visible_tab_count`, then that many tab records in display order. |
| Tab | `0` rect, `16` word · 20 bytes (`16 + 4`) | `visible_rect_cells`, `active` (0 or 1, the two states of the flag). The rectangle contains only the drawn part. |
| Bottom row section | `0` rect · 16 bytes (`4 × 4`) | `bottom_rect_cells`. |
| Minimap section | `0` region, `16` box, `32` count, `36` first interval | `region_rect_px`, `box_rect_px`, `ink_interval_count`, then that many ink intervals. Coordinates of both rectangles are in window pixels. |
| Ink interval | `0, 4` words · 8 bytes (`2 × 4`) | `start_y`, `end_y`, a half-open interval relative to the minimap region's top edge. |

**Transactions.** The driver sends one request at a time and allocates strictly increasing nonzero tickets without wrap. ARM and its matching SNAP share a ticket. The adapter echoes the ticket and sends the response in its wire revision. An OK packet for SNAP or NEXT has a positive `payload_bytes` within the mapping capacity. Parse exactly that prefix and require end-of-record. The rest of the mapping is spare capacity. The packet serial equals the settled frame serial. Each captured serial is nonzero and greater than the last accepted observation serial. During SNAP, the first-action serial precedes or equals the settled serial. One natural action submit can also be the first qualifying submit after the fence. NEXT returns only a settled frame with serial greater than the one it carries. ARMED is valid for ARM and may report the current serial, including zero before any submit. ARMED and error results have zero payload bytes. SIZE indicates an oversized frame and the driver treats it as a harness error.

**Geometry.** Window, nominal grid, and cell dimensions are positive. The origin of each nominal grid cell must fall inside the window; partial edge cells and unused window space are allowed. Cell rectangles use the nominal grid including chrome. A zero-area rectangle denotes absence. Its edges still fit their stated bounds. A positive `scroll_y_q8` moves the scrolled content toward increasing window y. Its absolute value is less than one cell height, expressed in Q8 units (P, `2⁸ = 256` units per pixel from the render transform). A nonzero translation requires a nonempty scroll rect. The rect bounds the affected area and clips scrolled content in window space. `extra_rows` is zero or one (P, a sub-cell displacement can expose at most one contributing row). It is zero when the translation is zero. The extra row, when present, is stored after the nominal rows. The cell count equals `columns × (rows + extra_rows)` and the product fits in a word.

**Cells and chrome.** Reject unknown section or attribute bits and unknown kinds. Text cells have nonempty strict UTF-8 without NUL. Other cell kinds have zero text bytes. A wide lead is painted text or unresolved artwork. Clipping or overlay can leave one part of a wide glyph visible. Color classes are unsigned equality labels local to the frame. The visible tab count is bounded by columns as specified in the Wave 0 design. Each visible tab rect is nonempty, and at most one visible tab is active. A present bottom rectangle is one row high, as it describes a single overlay row. An empty minimap region has no box or ink. A present box fits in the region. Ink intervals fit in the region height, have positive length, and are strictly separated, so adjacent intervals are merged before encoding.

**Python driver.** Import `contract.inspect` with `tests/` on the module path. `encode_request` returns integer data32 words for the X driver. `decode_reply(packet, mapping, request, after_serial=…)` takes the exact completion packet and readable mapping. Pass the last accepted observation serial, or zero at session start. The transport owns `recvmsg` flag and ancillary-data checks and keeps the mapping stable during the call. The result owns the decoded data. A malformed packet or payload raises `ProtocolError`. Adapter error results raise `ReplyError`, with `SizeError` for SIZE. A first-action assertion uses `require_first_action=True` on a SNAP decode or reads `snapshot.first_action`, both raising `MissingWitnessError` if absent.

`Frame` accessors raise `UnprovidedSectionError` on an omitted section. Text reads use logical row and column indices, with half-open column ranges. They retain blanks as spaces, emit no text for wide continuations, and raise `UnresolvedCellError` when the requested range crosses unresolved artwork. Tab titles and bottom-row text read from the corresponding rectangles and require cells for any nonempty rect. Tabs with multirow rectangles return one string with newline-separated rows. An explicitly provided empty tab list or absent bottom rectangle yields an empty observation. `active_tab` returns the visible active tab record or `None`. The minimap accessors return the box rectangle and the relative ink intervals. `decode_payload` and the test-only `encode_payload` operate on exact mapping records without the packet.

The hex conformance vectors in `tests/contract/vectors/` label packet and payload records separately. `next-reply.hex` uses `single-payload.hex`. SIZE has no payload vector because its length is zero.

## Module name (coordinator, at landing)

The client is `tests/contract/snapwire.py`, not `inspect.py` as the design table names it: a module called
`inspect` in `tests/contract/` shadows the standard library's `inspect` for every script run from that directory
(`dataclasses` imports it), which broke `test_sandbox.py` once both landed.
