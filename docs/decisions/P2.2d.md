# P2.2d clipboard review fixes (bead edit-e6x.18, review docs/reviews/x11-1.md #1 #4 #5 #6 #13 #14 #15 #28)

Files: src/x11/clip.c, src/x11/clip.h (added x11_clip_mem, x11_clip_set_budget, x11_clip_max_slice), tests/x11_clip_test.c.
Every fix has a test written first and seen red on the old code (red lines below, green = whole suite `x11_clip_test: ok`, 5/5 runs under ASan+leaks).

## #1 forged SelectionClear (BLOCKER) - confirmed
Fix: a SelectionClear with the SendEvent bit (0x80) is ignored. The server generates Clear for every real ownership change, so nothing legitimate is lost; the equal-timestamp / uncertain paths still verify with GetSelectionOwner. The old test that expected a forged Clear to succeed now takes the selection with a second client instead.
Red: `forged SelectionClear raised a loss event`, `forged SelectionClear destroyed the clipboard data`. Genuine takeover check stays green.

## #4 local completions expose another selection's data (BLOCKER) - confirmed
Fix: a confirmed local request only counts (`local_ready[w]`); x11_clip_poll queues the completions when the input queue is empty, one selection per call, after pointing the paste buffer at that selection's blob. Requests made inside callbacks therefore cannot overwrite the data of events still queued. The paste buffer is now a refcounted blob shared with the owned blob (no copy, see #13). x11.c needs no hook: the wake comes from x11_clip_deadline (local_at).
Red: `a local completion exposed another selection's data` (dual local pastes plus a request issued from the first callback).

## #5 confirmation discards a real ownership loss (BLOCKER) - confirmed
Fix: owner_finish rechecks ownership (GetSelectionOwner) whenever a Clear was deferred, also after a successful confirmation. Local pastes arriving during claiming or a pending recheck are held (`local_requests`) and flushed by flush_local() when the answer is in: still ours -> delivered locally, lost -> sent to the real owner. Timeout of the recheck keeps the previous "still ours" assumption.
Red: `takeover after confirmation reports the loss (lost 0)`, `paste after takeover returned stale data (4 bytes)`.

## #6 truncated INCR reported as success (BLOCKER) - confirmed
Fix: the advertised lower bound is kept (`lower`), raw property bytes are counted separately from STRING expansion (`raw`); a terminating empty chunk below the bound fails the receive. Our own server announces 0 for STRING (shrinking), unchanged.
Red: `INCR one byte below a 4096 lower bound must fail (ok 1, failed 0)`, same for immediate terminator and STRING INCR; control (bound met) stays a success.

## #13 bulk work between input checks (MAJOR) - partly fixed
Fixed: local paste no longer copies (shared blob; was up to 64 MiB). Every x11_clip_poll has a 1 MiB byte budget (SLICE_BYTES, (E) about 0.2 ms): MULTIPLE jobs convert pairs incrementally (job state 3 resumes next poll), INCR serve chunks and receive pages wait for room, and at least one unit always runs so progress is guaranteed. x11_clip_max_slice() reports the peak for tests.
Red: `local paste moved 20971520 bytes in one slice`, `MULTIPLE moved 12800000 bytes in one slice`. Green: both under the limit.
NOT fixed (needs a design call, no worker exists for it): large receive buffers still grow by realloc (glibc mremaps big blocks; ASan copies), plat_clip_set still memcpy's up to 64 MiB on the caller's slice, and Latin-1 conversion stays on the UI thread (bounded by chunk). Moving these to a work/ mailbox worker is the follow-up the review asks for.

## #14 memory budget (MAJOR) - confirmed
Fix: one `mem` counter covers owned blobs, serve snapshots (shared), the paste buffer and receive buffers (by capacity; the final buffer is shrunk to length). A receive grows only if old+new capacity fits the budget (default 128 MiB, x11_clip_set_budget for tests) and fails otherwise; plat_clip_set rejects what does not fit, counting the blob it replaces as free when unshared, and drops an idle paste buffer (empty input queue) before giving up. Known cost: a pasted 64 MiB item counts until the next paste.
Red: `second 600 KB set must exceed the 1 MiB budget`, `a receive that would exceed the budget must fail`, `failed receive released its buffer`.

## #15 STRING fallback deadline (MAJOR) - confirmed
Fix: rx_convert renews the phase deadline. Red: `late UTF8 refusal then timely STRING must succeed (ok 0, failed 1)` (600 ms limit, 400 ms per phase).

## #28 MULTIPLE notification order (MAJOR) - confirmed
Fix: jobs carry an arrival sequence; a finishing job (success or failure) whose tuple (requestor, selection, target, time) matches an older unfinished job parks in state 4 and is notified by release_held() in arrival order. Immediate refusals use the same path (refuse()). Residual: with all 8 job slots busy a refusal is sent at once.
Red: `MULTIPLE notifications out of order: 0 0 251 (want none, p2, none)`.
