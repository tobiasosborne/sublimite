# v2-677 Preserve mode on metadata copy

A replacement temp created by `os_file_open_at` with `OS_OPEN_CREATE | OS_OPEN_EXCL`
starts with owner read/write permissions (`0600`, subject to umask).
`os_file_copy_metadata` applies the source descriptor's permission and special
mode bits (`st_mode & 07777`) after ownership and ACLs, which can change those
bits. A private `0600` source keeps a private temp from creation through copy.
A failed `fchmod` returns the mapped OS error (A15), and the caller discards
the partly updated temp.

Passing the source mode to the create call would look simpler. A `0755` source
saved under umask `0077` would give the replacement `0700`. Applying the mode
by descriptor after copying metadata preserves `0755` in that case.

At the v1 pin `6fec2e8`, `src/file/file_posix.c:278–281` creates the temp with
`os_file_open_at`, which requests `0600` at `src/os/os_posix.c:316`.
`src/file/file.c:907–908` selects `0644` by default for an absent destination
and honors an explicitly supplied mode. Line 919 applies it before rename via
`fchmod` (`src/os/os_posix.c:424–428`). Umask applies to temp creation. The
explicit final mode bypasses umask.

The v2 OS test uses umask `0200` to check that exclusive creation gives
`0600 & ~0200 = 0400` and that rename carries that mode to the new name.
Final-mode selection for an absent destination belongs to the L2-1 save path.
