# edit-q0g — X11 input review decisions

Scope: docs/reviews/P2-1.md §§6, 21–25, 36–37, 39. No IPC endpoint changes from edit-og2 were copied; its diff was read before editing.

- Allocate the runtime owner and clipboard work pool with `aligned_alloc(_Alignof(T), sizeof(T))`, then initialize storage. The C type's size is a multiple of its alignment. Allocation remains at setup/pool creation, not per key.
- A keymap notification establishes a boundary. Deliver already translated input, cancel repeat, retain later raw events in XCB's queue, and wait asynchronously for the worker's prepared keymap/state. Disable X-fd input readiness while waiting so the retained queue does not cause polling spin. A failed replacement stops the loop rather than translating with stale state. This supplies bounded backpressure without a new staging allocation. **Remaining:** the existing worker connection fetches the server's current map, not an exact snapshot for each historical notification. Multiple map changes already processed by the server can therefore require a separate ordered snapshot/delta design. The consecutive-generation reproduction is retained as `map_generations_pending`.
- Repeat remains pending when a bounded drain reports buffered input or the X fd is readable. Blink and work callbacks retain their bounded service opportunities.
- Keep XI2 buttons through button 32 in their separate mask. Only buttons 1–5 enter core-state bits; extended buttons cannot enter keyboard group bits.
- Select/decode XI2 button press/release and use source identity plus `XIPointerEmulated`. Suppress smooth wheel emulation only for a source with scroll axes. Ignore native core button duplicates when XI2 is active; retain explicit core SendEvent input and native core fallback when XI2 is unavailable. Timestamp proximity no longer decides whether an independent notch survives.
- Tag live axis samples with a per-instance sequence. Capture the sequence when an asynchronous QueryDevice is sent. On adoption, preserve newer matching source/number/direction/increment history and remainder. DeviceChanged class values seed changed axes at their ordered event boundary; unrelated sources retain history. Parsing and adoption remain transactional.
- CLI window-deadline expiry is failure after display preflight. The default CLI test includes a forced-timeout negative control; it must fail rather than skip. A test-local backend factory wraps the real raster initializer with a bounded delay on the real initialization worker, restores backend identity, and records a test marker. Production main must complete the delayed session and normal shutdown; no production fault switch or global state was added.
- Production owns frame-zero startup ingress at `main` entry: capture monotonic time, initialize/register tracing, and record T0 before argument/IPC/journal setup. This avoids extending editor configuration outside the assigned files and avoids duplicate T0 recording at platform initialization. It measures entry to main, not launcher/exec loader time. The existing optional platform `exec_ns` API remains unchanged.
- The force-included display guard delegates classification to `editor_runtime_display`, sharing the production numeric-display policy and alternate-display validation. Tests exercise zero aliases without connecting to them. All live verification uses `DISPLAY=:99 EDIT_DISPLAY=:99`.

No globals were added. XI2 per-instance fields and existing test fixture fields carry the new state. The typing/translation additions use stack/retained state only. The release allocator guard remains part of verification; sanitizer checks run with `ASAN_OPTIONS=detect_leaks=0` because LeakSanitizer cannot run in this sandbox. The coordinator must repeat with leak detection enabled.
