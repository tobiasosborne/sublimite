# edit-czn: bounded editor line-start reuse

The G1 deep-file failure is a view-repair prefix replay, rather than the suspected synchronous layout scan. After an editor-owned mutation, the legacy empty TYPE repair enters `view_restore`, which invalidates nonzero line anchors. Its cooperative `line_query` then starts at byte zero. Layout stays busy while that repair is unfinished. The trace places the long interval before T2; T2-to-T3 is small. Exact piece line queries in the old row wrapper were a second unnecessary dependency on global line metadata.

Reuse the layout's certified, already rebased logical-line anchor in the existing fixed view cache immediately after repair yields, and before an ordinary movement/deletion query. Restart a pre-anchor query through that cache. Never use an estimated line number as a certified view answer. A left/backspace crossing the viewport boundary also gets the preceding certified anchor from a backward scan capped at 64 KiB (G). A deletion ending at the old viewport start carries a separate certified repair anchor through the layout reset; its line number follows from the deleted newline count. These are UI-owned editor fields, with no new globals or heap allocations.

For no-wrap layout, retain row starts already computed by `layout_begin`, `layout_edit`, and the previous row's bounded scan. Remove the unconditional per-row `piece_line_to_byte` call. When a clipped tail leaves the next row unresolved, a forward scan examines at most 64 KiB (G) beyond a proven preceding scan endpoint. If that cannot resolve the row, use the existing `lineidx_line_to_byte` partial result and mark layout approximate. Existing clipped-long-line first-frame/edit/undo behavior remains covered by the editor review regression. There is no lineidx API or implementation change.

The editor accesses view's existing fixed line cache and query continuation fields because this bead permits editor changes, not a view API redesign. A future public cache-import API can replace this localized bridge. The bridge leaves phase/target interpretation to view's own query restart. No index rebuild/restart policy, metadata maintenance, undo-history policy, renderer, or other module is changed.

The benchmark adds opt-in `--partial-index` setup, deadline diagnostics, and quiescent trace export/phase summaries through `EDIT_TRACE_DUMP`. Diagnostics run after editor close joins workers and outside the typing allocation guard. The trace ring may overwrite early records in the full key campaign; sample counts are printed, and benchmark percentiles use the separate complete sample arrays. Native EGL is unavailable on Xvfb and is labeled as raster fallback.

Measured results, pasted red/green evidence, loaded-box gate limitations, and final validation are in [the worker report](../worker-reports/edit-czn-s9.md). G1 remains 1/2 ms p50/p99 (G); no single noisy sample run establishes that gate.
