# edit-cde: editor clipboard integration

Copy publishes the selected bytes to CLIPBOARD and PRIMARY. Nonempty selection changes publish PRIMARY; collapsing a selection preserves its last PRIMARY text, following X selection conventions. Shift+Insert uses the paste action's CLIPBOARD; middle-button press pastes PRIMARY at the clicked text position. The headless backend keeps the same immutable buffer objects in editor-owned storage.

Clipboard orchestration lives in `src/editor/clip.c`. Input dispatch delegates the existing clipboard actions. Shared input helpers keep mutation, undo accounting, line-index invalidation, layout repair and journal staging on the existing editor path. Clipboard replacement opens an explicit undo group, deletes and inserts bounded chunks, then closes the group after cursor repair. Partial replacement frames are withheld. Other edit commands remain queued until the command completes; close still stops immediately. Worker waits use the existing mailbox/eventfd machinery and do not wait synchronously on the UI thread.

The bulk requirement is >= one MiB (G, supplied bead), derived as binary KiB multiplied by binary KiB. In practice, both selection capture and paste normalization move to WORK_BULK above `VIEW_SCAN_BOUND`, the existing view scan bound. Worker continuations and UI mutation chunks reuse `VIEW_SCAN_BOUND` and `VIEW_MUTATION_BOUND` respectively, rather than introducing a timing budget. UTF-8 bytes are preserved and CRLF becomes LF. The middle-click column scan also preserves decoder state across view windows; it uses logical columns for tabs and wrapped rows and stops at CRLF even across a window boundary.

The X protocol remains responsible for selection ownership confirmation, requests, INCR, MULTIPLE and timeouts. Its owned-buffer factory gains allocator/release callbacks and a length accessor. The editor supplies a mutex-protected arena recycler; the release callback remains alive through platform shutdown, including deferred worker frees. Native XCB packet operations use the existing editor IO instrumentation boundary. No new global state is introduced.

Clipboard admission keeps the existing X protocol payload maximum and ownership budget. The payload maximum derives from the preexisting `DATA_MAX = 64 * 1024 * 1024` bytes; the ownership budget derives from the preexisting `OWN_BUDGET = 2 * DATA_MAX`. The arena reservation is `2 * (OWN_BUDGET + DATA_MAX + sizeof(clip_block) + sizeof(editor_clip))`: platform owner bytes plus editor receive staging, with doubling for power-of-two recycler classes and headers. This is an init-time virtual reservation, not a new latency or physical-memory target. Recycled blocks avoid accumulated allocation for repeated copy operations.

Worker snapshots pin their source editor buffers until physical lease completion. Buffer retirement checks clipboard leases. Shutdown cancels and acknowledges clipboard jobs before reclaiming buffer arenas, and frees clipboard storage after X selection shutdown. Obsolete PRIMARY worker results cannot overwrite a newer selection or explicit copy.

Failure handling follows the editor's existing successful-prefix mutation contract. Admission failures before mutation reject the command. Clipboard normalization and transfer failure preserve the document. Native transport and comparison-drive verification remain coordinator work because this sandbox denies the X socket and local IPC socket creation.
