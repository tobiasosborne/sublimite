## Review §5: cursor before CRLF

**Verdict: confirmed.** View's End/Right stop is before CR. Wrap-off layout
consumed CR and compared the cursor only with LF; wrap-on already retains the
logical CRLF endpoint. The wrap-off completion check now resolves that logical
endpoint while keeping LF as the scanner/checkpoint position and preserving
next-row offsets. It normally uses the existing window; an exact checkpoint
seek starting at LF needs one preceding-byte read, counted in `bytes_read`.
There is no new storage or allocation and no offset translation in view.

Regression tests hand actual view-command cursor bytes to layout with a fixed
viewport, covering LF, CRLF, lone CR and EOF, wrap off/on, sliced/one-shot.
Separate tests cover a published end checkpoint, partial relayout and snapshots.

## Review §6: horizontal scroll representation

**Verdict: confirmed.** Widen `layout_viewport.hscroll` and `layout.hscroll` to
`uint64_t`, matching view state and the existing checkpoint/column arithmetic.
Field names, positional initializers and functions remain source compatible;
callers must rebuild for the changed struct layout. Wrap-on continues to ignore
horizontal scroll. No frozen header or other module was changed.

The regression uses a compact real piece tree: one checkpoint stride of tabs
with `UINT32_MAX` tab width, then nine ASCII characters. A real snapshot worker
publishes exact columns; its callback seeds view's Ctrl+End. The resulting scroll
exceeds `UINT32_MAX` without a large fixture or an unbounded UI prefix scan. The
test checks viewport/runtime preservation, EOF cursor visibility, partial
relayout, and wrap-on visual descriptors with large absolute columns. `_Generic`
allows the same regression to compile against the old narrowing header and
fail at runtime under the required conversion warnings.
