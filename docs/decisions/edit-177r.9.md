# edit-177r.9 — Windows executable integration

The application link contains the Windows core archive, every editor translation unit and main; neither X11, Wayland nor GL enters the link. Release uses the GUI PE subsystem (`-mwindows`), so Explorer creates no console. Main attaches to an existing parent console when available, reopening only missing CRT streams (stdin uses CONIN$, outputs use CONOUT$). Inherited pipes/files remain usable, and main's return value remains the process exit status. The isolated executable test checks help/error output and status, and the `--wait` launcher/UI shutdown handshake.

The creator lease and both owned editor lease fields are `os_file` on both targets. Recovery duplicates the creator's portable lease and validates its identity against the named lock. Teardown releases the editor's own lease, preserving the creator's independent lifetime. The portable deferred-restore declaration lives in private.h. Legacy native-fd restore entry remains only for Linux test callers.

Newer Linux editor code exposed by the actual link now uses os_mutex, os_sleep_ns, os_yield, os_host_name and os_stat_path. RLIMIT_NOFILE remains POSIX-only: os.h explicitly documents that Windows kernel handles have no corresponding soft cap. Reverse newline search uses a bounded portable byte walk. Editor clipboard storage retains Linux's X selection handoff; Windows gives its native clipboard worker an owned copy and releases the editor arena blob.

## Presentation, suspension and recovery

Windows application initialization uses D3D11 background initialization: it creates resources without demanding a visible diagnostic present. Present timing remains unavailable until exact native statistics authenticate a real frame. The editor explicitly binds its real Win32 platform as the mailbox destination; standalone render_config.platform identities remain opaque. Exact statistics queue the application frame ID, monotonic observation time and observed present count through win32_plat_present_complete. The UI callback accepts only that backend lifetime's queued record and then signals T6. Latency readiness, submission, raw SyncQPCTime and DwmFlush alone never supply T6.

The editor borrows the latency HANDLE only while an observable frame is active, removing it before teardown/rebuild. The platform records consumed auto-reset source readiness before on_work; the editor wait set preserves that credit until the owner reads it. Existing level-triggered sources retain their drain ownership. No additional platform wait position is consumed.

Minimize, session lock/disconnect and power suspension/display-off are independent reasons, combined with OR. Matching restores clear only their reason. Windows notifications are registered against the owned HWND and removed on shutdown. RESIZE reads the HWND's recorded DPI, recomputes the current/default point sizes using editor_runtime_em_px, and adopts the worker-prepared font metrics through the existing frame-boundary font path.

A hidden or occluded surface must continue accepting input, layout, saves and close. A copied snapshot with no native draw or Present can be explicitly discarded without T4/T5/T6; the next snapshot requires full damage. A drawn/committed frame whose completion cannot be authenticated ends its whole backend lifetime: remove the borrowed HANDLE, quiescent worker shutdown while pumping, reinitialize once, then park native presentation. CPU snapshots continue through the real D3D11 submit implementation and retire without invented completion. Round 2 adds an unexplained-parking probe and retries on activation/focus/position/input/display events with full damage; genuine native suspension disables the probe. Healthy-device unobservability does not terminate the editor.

The journal PAINT record guards a crash during first paint. Deliberately discarding an unpresented snapshot clears that armed record without marking the buffer painted, so occlusion does not reopen recovered edits as a closed tab. The next actual paint attempt still arms the normal guard. The executable crash test waits until the protected edit and this clear are replayable before TerminateProcess.

## Test profile and posted input

On Windows, explicit `SUBLIMITE_PROFILE` resolves app directories below `<profile>/config/sublimite` and `<profile>/data/sublimite`, including the directory-lock namespace. Invalid/oversized overrides fail rather than falling back to the user's profile. Default known-folder resolution is unchanged. winrun.sh forwards this override. Full-suite runs also give Windows a private native TEMP; Linux clang keeps a separate Linux TMPDIR.

`SUBLIMITE_TEST_INPUT` enables two private HWND messages: WM_APP+0x51 sets the target UI thread's modifier state, and WM_APP+0x53 records a posted-message fence. Posted WM_KEYDOWN does not update GetKeyboardState, so the modifier hook is necessary for an isolated Ctrl+S; the actual key still traverses native translation and the ordinary editor command path. The executable sets a test-only readiness property after argv acceptance because HWND creation happens earlier, during worker initialization. Neither hook is enabled in ordinary launches. All HWNDs and processes belong to the private runner; no SendInput or focus manipulation is used.

## Measurement boundary

The Windows release campaign inherits Linux allocation_case's alternating insert/backspace count, uses real posted Win32 messages and the production D3D11 CPU submit, requires an active guard plus a positive-control allocation, and asserts zero counted allocations and exact mutation/content counts. It prints ingress-to-submit nearest-rank p50/p99 with derivation. The current Linux editor_test has no percentile G1 assertion (whole-project review / edit-hxa7). Its editor_bench measures real T4 with the existing (G) p50/p99 limits of 1,000,000/2,000,000 ns, whose derivation is perf/01-perf-target.md section 0.2. The Windows private-station suite prints those limits and explicitly skips native T4 G1; a CPU-submit percentile cannot enforce them. Occluded CPU-submit measurements cannot establish native T4 or displayed cadence. Live validation remains the coordinator's check-live, including “N edits give N frames”.

## Round 2 — review fixes

Native clipboard queue admission is distinct from publication. Every Windows write now has an increasing identity and a terminal success/failure event, including successful writes. The UI retains the cut's buffer identity, revision and selection until the matching result. Only successful publication of that payload permits deletion; failures preserve the document/selection and display a notice. Windows close resolves queued command/publication work before flushing or releasing buffers; a failed publication cancels ordinary close. Linux still uses its original X11 selection-ownership semantics. Native fault injection remains a test-TU replacement of OpenClipboard, never a release environment switch.

Win32 retains usable dimensions on genuine minimization/empty client rectangles. The D3D CPU reservation and snapshot implementation remain available while native device/swapchain creation is deferred; restoration creates the native resources on the lifecycle worker and requires full damage. Native resize also defers empty/iconic rectangles. A drawn lifetime is shut down before its state can be reused.

Unexplained parking has a bounded probe: (E) one existing D3D missing-completion observation window, 3 s (`D3D11_COMPLETION_NS`), after parking; frequency = 1 / 3 s, at most one parked probe per window. This reuses the renderer's established observation scale rather than introducing a typing/idle performance gate. Activation, focus gain, position change, input, expose and display-on request an immediate full-damage retry. The probe itself clears suspension and requests layout without rebuilding the device. Minimize/session/power suspension clears the probe deadline entirely; there are no parked-probe wakes in those states. Native missing-completion recovery, independently reproduced before drawing and after drawing, can still require replacing a backend lifetime.

The merged `DXGI_STATUS_OCCLUDED` branch correctly sets `occluded` and rebases the deadline while retaining the frame. It remains retryable in standalone renderer use. It is not the ordinary covering detector: [Microsoft documents that flip-model chains do not return that status](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/dxgi-status), and [DWM retains obscured content without requesting repaint](https://learn.microsoft.com/en-us/windows/win32/dwm/bestpractices-ovw). The event/probe policy covers missing-completion parking without depending on either OCCLUDED or WM_PAINT.

Windows renderer initialization and shutdown use a UI-owned lifecycle work pool with one serialized worker (P: these operations cannot overlap on a backend). Background file/index slots cannot prevent lifecycle admission or execution. Ordinary completions continue through src/work mailbox draining during these waits. Linux keeps its prior pool and synchronous shutdown behavior; the reviewed infinite admission-retry loop was Windows-only.

Windows blocking waits retain the index returned by WaitForMultipleObjects before probing other sources. The full-input-queue fallback returns consumed readiness to the normal source owner, including the D3D auto-reset latency credit. Linux epoll behavior is unchanged.

Windows resolves, creates and canonicalizes the journal directory before IPC selection. Its native volume/file identity, which resolves aliases to the same directory, enters both server and client namespaces. Invalid overrides fail before handoff. Linux has the analogous existing XDG_DATA_HOME versus display/runtime namespace gap; it is reported without changing Linux in this round.

Every deliberate CPU discard clears the first-paint guard while leaving `painted` false. When native unavailability is already known, a CPU-only submission does not transiently arm that guard; the next actual attempt rearms it. A refused clear retains an explicit UI retry obligation. The next native attempt continues to arm the ordinary guard.

Attached GUI launches reconnect missing stdin to CONIN$ and preserve inherited pipes/files. Captured usage tests assert content as well as process statuses; a mutation control removing the actual output calls fails. Console attachment is tested with native pipe/file descriptors and an attachment/CONIN$ seam without creating a console; physical console interaction remains check-live. A PowerShell console launcher remains outside this round.

`SUBLIMITE_TEST_INPUT` deliberately remains compiled into release (accepted). Its environment opt-in enables the posted modifier, barrier and readiness hooks; ordinary launches leave them disabled.

The Linux ck4 save/recovery failure was a test deadline bug, not a Linux product change. The old one-second filesystem poll fails identically on HEAD and the pre-W2.4c commit when the existing durability hook delays the save beyond that window. The test now waits for controller completion under the suite's established settle watchdog, then checks exact disk and replay bytes. Natural contention counts and controlled red/green runs are in the Round 2 worker report.

The executable crash/recovery oracle genuinely minimizes before its protected edit and kill, keeping hot-exit recovery separate from an intentional kill during native first paint. After relaunch a new protected marker and undo acknowledge restored edit readiness before save. Each profile uses its own target bytes. Platform handle-balance tests warm native session/power services with the existing lifecycle fixture, then keep their exact no-growth assertion on another complete fixture.

Lifecycle completion draining also requires exclusive backend-object ownership. Before scheduling shutdown, UI publishes `initialized=false` and `active=false` on its descriptor; the worker receives a private retiring copy and mutates only that copy. Physical work completion then publishes the retired descriptor back on UI. A worker-side test asserts it never receives the UI's live descriptor. This prevents completion callbacks or native event injection from racing with worker writes to backend fields while still allowing mailbox draining.

Posted-text executable fixtures explicitly reset modifiers before WM_CHAR, while chord helpers explicitly establish Ctrl. A held-Ctrl negative control demonstrates why startup keyboard state cannot be assumed to be zero. This uses the existing opt-in hook and changes no ordinary-launch keyboard behavior.

## Round 3 — review fixes

This section supersedes the Round 2 parking timer and first-paint descriptions above.

Clipboard terminal messages are retained in a separate UI-owned slot, outside `EDITOR_INPUT_CAP`. Win32 platform pumping continues at input capacity. Consuming the slot still respects the existing mutation/save/journal fences, so completion delivery cannot mutate through an outstanding save lease. A pending close runs cut replacement slices, view repair, undo completion and staged journal commit before flushing; errors return to the caller. Publication failure cancels window close with the existing text-kept notice.

Windows first-paint protection has separate CPU and native phases. Successful CPU composition clears PAINT before waiting for latency. Native readiness retains the auto-reset credit before PAINT is armed, so readiness cannot race an unguarded native draw. The guard names the submitted frame's source tab, including across tab activation. The first successful native draw clears it, independently of displayed-frame authentication. Safe CPU composition and safe native drawing are remembered per tab for the launch: a covered, never-authenticated tab does not append arm/clear pairs on repeated probes. These flags do not fabricate presentation or mark the tab displayed. The executable kill/recovery oracle is covered on its private station and explicitly non-minimized.

Parking exit always clears its deadline; queued exposes use the same helper as native/input recovery, and only `win_unavailable` deadlines participate in waits.

For G11, prefer native notifications. The renderer registers `IDXGIFactory2::RegisterOcclusionStatusWindow` on its factory and unregisters before releasing it. Registration is compatible with our flip-sequential chain: Microsoft's [Desktop Duplication sample](https://github.com/microsoft/Windows-classic-samples/blob/main/Samples/DXGIDesktopDuplication/cpp/OutputManager.cpp) uses that pairing. The [documented notification coverage](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/waiting-when-occluded) includes monitors off, disconnected sessions, exclusive fullscreen and inactive desktops; it does not promise ordinary overlap/uncover notification for our window. [Flip chains do not return DXGI_STATUS_OCCLUDED](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/dxgi-status). `DwmGetWindowAttribute(DWMWA_CLOAKED)` is also checked at actual native attempts, but [cloaking](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute) describes app/shell/inherited cloaking, not arbitrary covering. Existing [WM_WINDOWPOSCHANGED](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-windowposchanged) handles our window's geometry/Z-order changes; another window uncovering ours need not change our own position. Therefore these events cannot replace every owed-frame fallback.

There is no probe timer when the last presented frame remains valid and nothing is owed, and none during native suspension. Only an owed frame keeps an event-free retry. (E) Start at the existing missing-completion observation window, 3 s; double on failed retries, with four doublings to a cap of `3 s * 2^4 = 48 s`. At sustained covering this reduces probe frequency sixteenfold, from `1/3 Hz` to `1/48 Hz`; the explicit tradeoff is up to one cap interval before an eventless uncover retry. New input/native expose resets backoff and retries immediately. This is an engineering liveness/energy choice, not a battery measurement or a typing gate. The desktop has no battery; no Target B battery-life claim is made.

The actual HWND client rectangle is constrained to the existing surface reservation on UI before native init and on every size/DPI/restore path. Client limiting uses the HWND's current nonclient extents, preserving current-monitor DPI. (P) Additional surface allocation is zero; state is two `uint32_t` limits (`2 * sizeof(uint32_t) = 8 bytes`, excluding struct padding). Existing scene/target/swapchain reservations remain the bound, avoiding a new display-sized allocation after monitor removal. Native initialization resource failure preserves prepaid CPU snapshots, parks with a notice, and uses the owed-frame retry. `ResizeBuffers` out-of-memory requests the same lifecycle recovery instead of ending the loop.

Shutdown's worker publishes a lifecycle completion message transferring the retired descriptor. UI consumes that mailbox before adopting the descriptor; `work_handle_finished` only protects the stack/job lifetime. A test observes both publication and consumption, and still asserts exclusive descriptor ownership with the ordinary pool saturated. Linux retains its existing clipboard, guard, wait, renderer and shutdown behavior.
