# edit-177r.9 — Windows executable integration

The application link contains the Windows core archive, every editor translation unit and main; neither X11, Wayland nor GL enters the link. Release uses the GUI PE subsystem (`-mwindows`), so Explorer creates no console. Main attaches to an existing parent console when available, reopening only missing CRT output streams. Inherited pipes/files remain usable, and main's return value remains the process exit status. The isolated executable test checks help/error output and status, and the `--wait` launcher/UI shutdown handshake.

The creator lease and both owned editor lease fields are `os_file` on both targets. Recovery duplicates the creator's portable lease and validates its identity against the named lock. Teardown releases the editor's own lease, preserving the creator's independent lifetime. The portable deferred-restore declaration lives in private.h. Legacy native-fd restore entry remains only for Linux test callers.

Newer Linux editor code exposed by the actual link now uses os_mutex, os_sleep_ns, os_yield, os_host_name and os_stat_path. RLIMIT_NOFILE remains POSIX-only: os.h explicitly documents that Windows kernel handles have no corresponding soft cap. Reverse newline search uses a bounded portable byte walk. Editor clipboard storage retains Linux's X selection handoff; Windows gives its native clipboard worker an owned copy and releases the editor arena blob.

## Presentation, suspension and recovery

Windows application initialization uses D3D11 background initialization: it creates resources without demanding a visible diagnostic present. Present timing remains unavailable until exact native statistics authenticate a real frame. The editor explicitly binds its real Win32 platform as the mailbox destination; standalone render_config.platform identities remain opaque. Exact statistics queue the application frame ID, monotonic observation time and observed present count through win32_plat_present_complete. The UI callback accepts only that backend lifetime's queued record and then signals T6. Latency readiness, submission, raw SyncQPCTime and DwmFlush alone never supply T6.

The editor borrows the latency HANDLE only while an observable frame is active, removing it before teardown/rebuild. The platform records consumed auto-reset source readiness before on_work; the editor wait set preserves that credit until the owner reads it. Existing level-triggered sources retain their drain ownership. No additional platform wait position is consumed.

Minimize, session lock/disconnect and power suspension/display-off are independent reasons, combined with OR. Matching restores clear only their reason. Windows notifications are registered against the owned HWND and removed on shutdown. RESIZE reads the HWND's recorded DPI, recomputes the current/default point sizes using editor_runtime_em_px, and adopts the worker-prepared font metrics through the existing frame-boundary font path.

A hidden or occluded surface must continue accepting input, layout, saves and close. A copied snapshot with no native draw or Present can be explicitly discarded without T4/T5/T6; the next snapshot requires full damage. A drawn/committed frame whose completion cannot be authenticated ends its whole backend lifetime: remove the borrowed HANDLE, quiescent worker shutdown while pumping, reinitialize once, then park native presentation. CPU snapshots continue through the real D3D11 submit implementation and retire without invented completion. Idle needs no GPU retry timer while parked. A native resume/expose retries presentation with full damage. Healthy-device unobservability does not terminate the editor.

The journal PAINT record guards a crash during first paint. Deliberately discarding an unpresented snapshot clears that armed record without marking the buffer painted, so occlusion does not reopen recovered edits as a closed tab. The next actual paint attempt still arms the normal guard. The executable crash test waits until the protected edit and this clear are replayable before TerminateProcess.

## Test profile and posted input

On Windows, explicit `SUBLIMITE_PROFILE` resolves app directories below `<profile>/config/sublimite` and `<profile>/data/sublimite`, including the directory-lock namespace. Invalid/oversized overrides fail rather than falling back to the user's profile. Default known-folder resolution is unchanged. winrun.sh forwards this override. Full-suite runs also give Windows a private native TEMP; Linux clang keeps a separate Linux TMPDIR.

`SUBLIMITE_TEST_INPUT` enables two private HWND messages: WM_APP+0x51 sets the target UI thread's modifier state, and WM_APP+0x53 records a posted-message fence. Posted WM_KEYDOWN does not update GetKeyboardState, so the modifier hook is necessary for an isolated Ctrl+S; the actual key still traverses native translation and the ordinary editor command path. The executable sets a test-only readiness property after argv acceptance because HWND creation happens earlier, during worker initialization. Neither hook is enabled in ordinary launches. All HWNDs and processes belong to the private runner; no SendInput or focus manipulation is used.

## Measurement boundary

The Windows release campaign inherits Linux allocation_case's alternating insert/backspace count, uses real posted Win32 messages and the production D3D11 CPU submit, requires an active guard plus a positive-control allocation, and asserts zero counted allocations and exact mutation/content counts. It prints ingress-to-submit nearest-rank p50/p99 with derivation. The current Linux editor_test has no percentile G1 assertion (whole-project review / edit-hxa7). Its editor_bench measures real T4 with the existing (G) p50/p99 limits of 1,000,000/2,000,000 ns, whose derivation is perf/01-perf-target.md section 0.2. The Windows private-station suite prints those limits and explicitly skips native T4 G1; a CPU-submit percentile cannot enforce them. Occluded CPU-submit measurements cannot establish native T4 or displayed cadence. Live validation remains the coordinator's check-live, including “N edits give N frames”.
