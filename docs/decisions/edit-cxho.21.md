# edit-cxho.21: design scene-capture harness

- Fixtures: tools/design_fixtures/ (readme.md copy, hello.c, util.py, notes.txt). The 20000-line Markdown scene file is generated by awk at run time (pure function of the line index), not committed.
- Window: no WM under Xvfb, so the client picks its own size (1977x1442 here); the script forces 3296x2060 with xdotool windowsize (the editor relayouts). Screen 3296x2060x24, Xvfb -dpi 192 (the editor reads it as DPI; there is no sublimite -dpi flag).
- Themes: config.toml `theme = "dark"|"light"` already exists, so 8 scenes x 2 themes = 16 PNGs. Dark and light run as two lanes on private :91 and :92 in parallel.
- Settle: frame unchanged for 1.2 s (blink half period 500 ms, EDITOR_BLINK_NS; the editor stops blinking after 10 s idle with the caret visible). Polling uses xwd dumps (0.08 s vs 0.49 s for import), comparing from byte 3179 (107-byte header + 256x12 colormap; the colormap bytes vary between grabs).
- Determinism: PNGs written with `convert -strip` (date chunks differ otherwise). Pixels were identical even before; only metadata differed.
- Not in make check: one run is ~84 s, the test (two runs) ~180 s (M, battery, load 6); the existing tools/test_*.sh scripts are seconds. Run by hand: sh tools/test_design_shots.sh [binary].
- No keyboard focus call: keys go through XTEST to the window under the pointer (PointerRoot focus).
