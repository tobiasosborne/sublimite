## 1. BLOCKER — Sync retry can acknowledge bytes lost by failed writeback

**Locations:** [src/journal/journal.c:272](/home/tobias/Projects/editor/src/journal/journal.c:272), [src/journal/journal.c:368](/home/tobias/Projects/editor/src/journal/journal.c:368), [tests/journal_test.c:324](/home/tobias/Projects/editor/tests/journal_test.c:324).

After fdatasync fails, the batch retains `progress` and `cached`. Retry clears the error without invalidating either value. The worker consequently retries the sync while skipping the already-accounted bytes.

A writeback EIO can leave failed pages clean; the error is reported once, and a later sync on the same descriptor can return success without repairing those writes. The kernel documents this error-consumption behavior and the dirty-page lifecycle. [Linux VFS documentation](https://www.kernel.org/doc/html/latest/filesystems/vfs.html#handling-errors-during-writeback).

**Concrete argument:** Append `a`, force a batch, and fail its data writeback during fdatasync. At failure, `progress == sealed`. Receive, retry, and flush: the worker skips its write loop and calls fdatasync again. If that succeeds after consuming the earlier error, `durable_sequence` becomes 1 although recovery can still contain zero records.

The fault seam returns EIO *before* calling fdatasync, preserving all dirty bytes. Tests explicitly require no additional writes after retry, so they cannot expose this failure.

**Fix:** Distinguish writeback/sync failure from interrupted or partial append failure. After writeback EIO, require a complete checkpoint into a fresh inode before clearing suspension and acknowledging recovery. Rewriting only the current batch is insufficient because earlier unsynced batches may already have been released. Add a fault model where failed writeback loses bytes and a subsequent sync succeeds without restoring them.

## 2. BLOCKER — The editor submits edits before journaling them

**Locations:** [src/editor/editor.c:122](/home/tobias/Projects/editor/src/editor/editor.c:122), [src/editor/editor.c:129](/home/tobias/Projects/editor/src/editor/editor.c:129), [src/editor/input.c:145](/home/tobias/Projects/editor/src/editor/input.c:145).

Successful mutations remain in the editor’s RAM staging area through layout and render submission. `on_submit` runs before `editor_journal_staged`. P1.9g protects successful journal calls, but those calls have not occurred at this point.

**Repro:** Open an untitled editor with journaling. Inject `a`. In `on_submit`, when `frame->last_sequence != 0`, notify the parent and park. SIGKILL the child. The tree contains `a` and its frame has been submitted, while the journal contains only BASE. Recovery restores empty content.

The 1,000-trial test invokes journal operations directly and publishes its lower bound after their return. It cannot detect this integration gap. Editor tests flush after completing their scripts.

**Fix:** Establish the page-cache commit before publishing an edit’s completed/submitted state. Move journaling into mutation completion, preserving successful prefixes and explicit IO/FULL handling. Add editor-level kill points after mutation, during layout continuations, and at submit/present boundaries.

## 3. BLOCKER — BASE capture can describe different bytes from the loaded tree

**Locations:** [src/editor/open.c:75](/home/tobias/Projects/editor/src/editor/open.c:75), [src/editor/open.c:113](/home/tobias/Projects/editor/src/editor/open.c:113), [src/editor/open.c:119](/home/tobias/Projects/editor/src/editor/open.c:119).

The editor attaches file contents to the tree, initializes its backend, and only then captures the journal BASE from the pathname. It never verifies that this newly captured identity matches the original used by the tree.

**Repro:** Open a small copy-mode file containing `abc`. After `file_attach` but before backend initialization finishes, overwrite it with `xyz`. BASE capture records the valid identity and prefix CRC of `xyz`, while the tree still contains `abc`. Insert `!` at offset 3 and crash. Replay loads `xyz`, accepts its identity, and restores `xyz!` instead of the UI’s `abc!`.

This produces wrong content without a recovery conflict. Existing editor journal fixtures use untitled buffers; the named-base benchmark does not inject this race.

**Fix:** Capture an identity before loading and validate that same identity after attachment, or expose the file module’s original identity and bind journal BASE to it. A changed source must trigger conflict resolution or a checkpoint against retained immutable bytes. Add a controlled external-write test across this opening boundary.

## 4. BLOCKER — Successful appends can exceed both PRD power-loss limits

**Locations:** [src/journal/journal.c:497](/home/tobias/Projects/editor/src/journal/journal.c:497), [src/work/work.c:49](/home/tobias/Projects/editor/src/work/work.c:49), [docs/decisions/P1.9.md:935](/home/tobias/Projects/editor/docs/decisions/P1.9.md:935), [PRD.md:80](/home/tobias/Projects/editor/PRD.md:80).

Journal sync jobs queue behind the single bulk worker. Cancellation polling does not yield that worker to another queued job. UI writes continue succeeding into both batches while no journal sync executes.

**Repro:** Occupy the bulk worker for three seconds. Append 800,000 bytes, pump normally, then append another 800,000 bytes into the other batch. Both INSERT calls succeed. Timer pumping returns BUSY until the existing job finishes. A power loss after two seconds may recover none of those bytes: approximately 1.6 MB and more than one second are unprotected.

The decision record calls the thresholds qualified cadence targets; the PRD states maximum loss. `max_sync_bytes` measures worker-accounted chunks, not actual page-cache bytes awaiting durability. The kill test retains the kernel page cache and imposes no power-loss time/volume bound.

**Fix:** Reserve sync execution independently of long bulk jobs, track actual unacknowledged page-cache volume, and enforce admission against the selected loss bound. Add durable-image assertions during delayed-worker operation, including large records. Make the published requirement and qualified decision describe the same guarantee.

## 5. BLOCKER — First-run directory creation leaves the durable journal potentially unreachable

**Locations:** [src/main.c:13](/home/tobias/Projects/editor/src/main.c:13), [src/main.c:39](/home/tobias/Projects/editor/src/main.c:39), [src/journal/journal.c:348](/home/tobias/Projects/editor/src/journal/journal.c:348).

`make_directory` creates missing XDG directory components without synchronizing their parents. Journal setup fsyncs only the final directory containing the journal.

Synchronizing that final directory does not establish durability of its name in an unsynced ancestor. Namespace durability requires the relevant parent-directory barriers. [Linux fsync documentation](https://man7.org/linux/man-pages/man2/fsync.2.html).

**Concrete argument:** Start with an existing durable parent and a previously nonexistent `$XDG_DATA_HOME/new/sublimite` chain. Create it, append edits, and successfully flush the journal. A permitted crash image retains the journal inode and final directory contents while losing an ancestor’s newly created directory entry. The entire acknowledged journal becomes unreachable.

The fault model tracks one journal-name inode; it has no directory tree and cannot represent this outcome.

**Fix:** Create directories using retained directory descriptors and fsync each parent after adding a child. Require successful completion before enabling journal acknowledgements. Extend the durability oracle to verify reachability through every newly created directory component.

## 6. MAJOR — Retained BASE identity depends on metadata without a full metadata barrier

**Locations:** [src/journal/journal.c:683](/home/tobias/Projects/editor/src/journal/journal.c:683), [src/journal/journal.c:688](/home/tobias/Projects/editor/src/journal/journal.c:688), [src/journal/journal.c:231](/home/tobias/Projects/editor/src/journal/journal.c:231).

Retention captures the private inode’s `mtime_ns`, persists that exact value in BASE, and synchronizes the inode using fdatasync. Recovery requires exact mtime equality. fdatasync does not require persistence of mtime changes. [Linux fsync/fdatasync documentation](https://man7.org/linux/man-pages/man2/fsync.2.html).

**Concrete argument:** A conforming filesystem can preserve the retained bytes and required retrieval metadata while recovering an older mtime. BASE checking then returns `JOURNAL_BASE_CHANGED` for an otherwise intact private recovery artifact. An empty named base is a useful fixture: copying can update timestamps without introducing a size change requiring metadata synchronization.

The retained-copy tests record bytes and barrier calls, while the durable-image model stores no inode timestamps.

**Fix:** Use a full inode fsync for retained recovery bases before publishing their identities. Add a distinct metadata barrier to the syscall seam and model the metadata that BASE validation requires.

## 7. MAJOR — The UI append path has no time bound and already reports substantial paste regression

**Locations:** [src/journal/journal.c:410](/home/tobias/Projects/editor/src/journal/journal.c:410), [src/journal/journal.c:394](/home/tobias/Projects/editor/src/journal/journal.c:394), [docs/decisions/P1.9.md:1063](/home/tobias/Projects/editor/docs/decisions/P1.9.md:1063), [perf/01-perf-target.md:52](/home/tobias/Projects/editor/perf/01-perf-target.md:52).

Every record computes a scalar, byte-at-a-time CRC and performs buffered pwrite on the UI thread. A 1 MB paste executes both without input checks or a continuation boundary. Regular-file writes can block when device activity is required; adding O_NONBLOCK cannot establish the required bound. [Linux open documentation](https://man7.org/linux/man-pages/man2/open.2.html).

**Evidence:** P1.9g’s recorded paste enqueue measurement is 18.067 ms p50 / 36.239 ms p99, `(M)[AC]`, load 29.72. Those component costs exceed G9’s complete-operation 5/15 ms budget when included before protected completion. The record also reports both append rows missing the local 20 µs gate. These are existing measurements, not a rerun.

Moving journal work past the submit measurement leaves it delaying presentation or subsequent input.

**Fix:** Optimize CRC with a supported hardware path and fallback, and introduce bounded continuations for large encoding work. Validate complete protected edits under bulk and writeback pressure. The selected synchronous-write behavior also needs an explicit resolution of the incompatible hard no-stall requirement; bounded bytes and attempts do not resolve it.

## 8. MAJOR — Save preparation blocks the UI before save acknowledgement

**Locations:** [src/journal/journal.h:115](/home/tobias/Projects/editor/src/journal/journal.h:115), [src/journal/journal.c:709](/home/tobias/Projects/editor/src/journal/journal.c:709), [src/journal/journal.c:734](/home/tobias/Projects/editor/src/journal/journal.c:734), [perf/01-perf-target.md:69](/home/tobias/Projects/editor/perf/01-perf-target.md:69).

The documented protocol requires UI-owned `journal_save_prepare` to finish before `file_save_begin`, whose return supplies the save enqueue acknowledgement. Preparation blocks through flush, retained-base creation/copy, data and directory barriers, and complete-session checkpoint publication.

Its waits drain worker messages but do not service input. Copying a large base is unbounded by the UI slice budget.

**Repro:** Queue a three-second bulk job, then request preparation of even a small named save. Retention queues behind that job and the UI waits in `retain_base`. Save acknowledgement cannot meet G8s’s 2/5 ms gate, and incoming typing waits on the same UI thread.

**Fix:** Make save preparation an asynchronous state machine. Capture the immutable snapshot/cutoff and enqueue the pipeline immediately; perform retention and checkpoint IO on a worker, then publish completion through mailboxes before authorizing file replacement. Preserve later edits across checkpoint adoption. Add acknowledgement and input-progress tests with delayed retention.

## 10. MAJOR — Session payload corruption can pass the entire suite

**Locations:** [tests/journal_test.c:26](/home/tobias/Projects/editor/tests/journal_test.c:26), [bench/journal_bench.c:68](/home/tobias/Projects/editor/bench/journal_bench.c:68), [fuzz/journal_fuzz.c:13](/home/tobias/Projects/editor/fuzz/journal_fuzz.c:13).

VIEW, TABS, and WINDOW recovery tests count records without comparing their values. The benchmark prints `session_restored=1` based on these counts. The fuzzer ignores these records in its semantic model.

**Concrete regression that passes:** Encode every VIEW field as zero, encode tab active index as zero, and encode window dimensions as zero; calculate valid CRCs. Record counts, schema validity, text contents, and existing session assertions remain satisfied. Cursor, selection, scrolling, active tab, and window restoration are wrong.

**Fix:** Maintain independently expected session values and compare every field after ordinary replay, rotation, and crash recovery. Include reversed selections, nonzero scrolling, distinct tab IDs, a nonzero active index, and nonzero window dimensions.

## 11. MAJOR — Simultaneous save-token preservation has no contract test

**Locations:** [src/journal/journal.h:134](/home/tobias/Projects/editor/src/journal/journal.h:134), [tests/journal_test.c:445](/home/tobias/Projects/editor/tests/journal_test.c:445), [fuzz/journal_fuzz.c:95](/home/tobias/Projects/editor/fuzz/journal_fuzz.c:95).

Every save regression uses one `journal_save` token. Two restored buffers and a shared-base fixture do not exercise two overlapping prepared saves. The fuzzer never calls prepare, finish, or rotate.

**Concrete coverage hole:** A prepare implementation that drops existing SAVE records from its supplied checkpoint passes these fixtures because none supplies another in-flight SAVE marker. Preparing buffer B during buffer A’s save would then lose A’s required target-association metadata. Similarly, premature retirement of another token’s retained generation has no current oracle.

**Fix:** Prepare A, preserve its BASE/SAVE in B’s preparation, append deltas to both, and finish them in both orders. Inject failures around each publication and retirement boundary. Recover with no live tokens and verify both contents, target associations, cutoffs, and retained-base availability.

## 12. MAJOR — Retention returns shared state outside work mailboxes

**Locations:** [src/journal/journal.c:641](/home/tobias/Projects/editor/src/journal/journal.c:641), [src/journal/journal.c:695](/home/tobias/Projects/editor/src/journal/journal.c:695), [src/journal/journal.c:709](/home/tobias/Projects/editor/src/journal/journal.c:709).

Retention communicates `error` and `base` through a stack-owned shared structure and an atomic `done` flag. The UI polls that flag and reads the worker-written fields directly.

**Concrete argument:** `retention_worker` never calls `work_publish`; `retain_base` receives its result through acquire/release access to `r.done`. This directly violates the project rule that shared state crosses threads only through `src/work` mailboxes.

The atomic ordering avoids an evident race here; it does not satisfy the specified channel contract. Completion also lacks the mailbox’s eventfd notification and routing identity.

**Fix:** Publish a retention completion carrying an immutable result reference through `work_publish`, with storage retained until receipt. Route it using the operation’s handle/generation and adopt ownership in the UI completion handler.

## 13. MINOR — Failed PAD writes are reported as BUSY when submission fails

**Locations:** [src/journal/journal.c:491](/home/tobias/Projects/editor/src/journal/journal.c:491), [src/journal/journal.c:497](/home/tobias/Projects/editor/src/journal/journal.c:497).

A failed PAD write sets sticky IO and `append_errno`, but failed worker submission unconditionally returns BUSY, discarding `append_rc`.

**Repro:** Occupy every usable bulk slot, append `a`, inject EAGAIN for the PAD write, and force pump. Pump returns `JOURNAL_BUSY` despite the new IO failure. Callers that normally ignore BUSY do not receive the promised PAD error from this call.

A subsequent pump can also attempt the failed PAD again on the UI because `cached == used` remains true.

**Fix:** Return the PAD IO error ahead of scheduling BUSY, retain explicit failed-PAD state, and leave missing-tail retries to the worker. Test simultaneous PAD failure and slot exhaustion.

## 14. MINOR — Long valid BASE paths still cannot prepare a save

**Location:** [src/journal/journal.c:739](/home/tobias/Projects/editor/src/journal/journal.c:739).

Retention requires enough full-path space to replace the original basename with `.sublimite-base-XXXXXX`. Valid short filenames under very long parent paths fail this requirement.

**Repro:** Reuse the long-path fixture’s 4,093-byte parent directory with a one-byte base filename. Capture succeeds for the 4,095-byte path. Save preparation returns INVALID at the sibling-name length check, although the existing file and short temporary basename are valid filesystem objects.

The journal rotation version of the first review’s filename problem is fixed; the private-base path introduces the analogous restriction.

**Fix:** Store retained bases in a bounded-path recovery directory, using reflink where possible and worker copy otherwise, or provide another recoverable location when the sibling path cannot be encoded. Add a long-parent BASE save test alongside the long-journal-path test.
