**NOTE — partial open rollback.** On a hard error from the first `ops->open`, common resets the arena and returns no handle, even if the driver populated `*state`. No quiesce or close is called (`render.c:71–77,113–116`). A native partial-open must clean up before returning a terminal error or hand ownership to a defined cleanup phase. The current SPI does not assign this duty. Null allocates only from the rolled-back arena.

**NOTE — exact API inventory.** A whitespace-normalized declaration comparison against af0e95e found exact matches for all nine signed service signatures and all six callback signatures. There is one submit, all three factory prototypes are present, and the seven SPI operation names match. Cell order, widths, assertion, image ID and frame ID match. The signed value table gives meanings rather than exhaustive C declarations. Additions include tile span, target stride, explicit setup directory and recovery grant, PUMP and RELEASED, null draw samples/scan timing in the public notice and counters, and UNBOUND/BINDING/CLOSING staging states. Reported differences also include the native type, stats contract and actual owner of consume/poll above. Recovery reaches UNBOUND then reuses the driver on bind rather than explicitly going through OPENING; document which operation recreates a disconnected backend or requires close/reopen. Public selection is deferred to integration; only the null factory is implemented.

**NOTE — submit, delivery and recovery.** BUSY precedes source access. Prep checks canonical runs before reading rows, validates each supplied cell and tightly copies selected tiles into idle scratch. The final epoch/stamp/base check precedes ID assignment, O(1) prefix credit, accepted input association and publication (`render.c:282–337`). A refusal can overwrite scratch and produce diagnostics. Accepted data, output ID, input association and FIFO membership remain intact. UI commit never walks the credited nodes. Current-generation notification, in-place replacement, O(1) eviction, accepted watermark, fresh epoch and bounded cursor replay implement delivery §1–5. On exhaustion an idle pump requests quiescence before reuse.

**NOTE — pixels and retirement.** Null installs all deltas and applies all patches before drawing. It checks expected version at the installed slot; wide-right samples use their left owner, retain the original right cell and offset, and lose only ink on mismatch. The one R-A incidence scan visits V cells for any positive N, including old-version users; the following row-tag loop visits rows. N=0 bypasses the cell scan (`render_null.c:63–88,93–160`). Device and presentation are independent enums. Either can finish first; a lease is a third prerequisite. Early evidence stays private through issue, discard remains untimed, and authenticated **in-flight** loss waits for quiescence without manufacturing T5/T6. Rebinding clears credit, reinstalls the sheet, requires full and requeues current UI identities without glyph work. The restart suite exercises bounded replay after loss before and after issue. It uses a proxy around null, not a physical native device or a loss halfway through installing several deltas.

**NOTE — one implementation per rule.** The 20-byte cell, slot/version values and attribute masks live in render_types.h. Both sheet and runtime use the same checked tile-extent and tight-copy helpers. Prep validates the producer representation; the font service remains the authority on current identity. Backend installed-version equality answers a different question. No second font directory, segmentation, cluster-width, eviction or layout/hit policy appears here. Font and layout are not implemented at this revision, so end-to-end reuse is unverified. Keep producer-wide semantics and Q8 coordinates shared at adoption; reuse the backend row-damage and install/redraw logic when raster and GL arrive. The font-pending queue and render-delivery queue have distinct ownership and eligibility.

## Benchmark verdict · MUST-FIX at the largest admission

Sol’s 10,000-sample AC run separates UI submit from null retirement. One changed row at ordinary geometry took 1.790/1.959 µs p50/p99. The largest one-row case took 1.969/2.488 µs. At 360×300 plus overscan, full-sheet took 591.583 µs p50 versus 386.734 µs for the comparison copy. Full-runtime took 1,988.722 versus 482.092 µs. That is 108,360 cells and 2,167,200 bytes in one uninterrupted call. The difference of medians is about 1.89 ns/cell for sheet and 13.90 ns/cell for runtime. These are estimates of incremental cost: the separately timed memcpy targets another buffer after backend retirement. They are not matched per-sample costs.

**Hot loop.** `render_submit_prep.h:70–90` loads each 20-byte cell, validates color/reserved/attrs, validates its image, checks wide adjacency and copies the cell. The sheet case does the indexed version check at lines 62–63. Runtime adds an indirect `get_identity` and slot/version comparison at lines 64–67 **for every ink cell**. Sol’s runtime benchmark fills all cells with exactly the same runtime identity (`bench/render_bench.c:109–113`). It performs 108,360 redundant-or-first metadata lookups for that one image; all cell validations and the owned copy are still required. There is no R-A scan, R8 transfer, native wait or tile search in either timed full submit.

**Independent attribution.** I ran the same largest fixtures with 512 warm samples, GCC release optimization, AC, load1 19.3–19.7, with wall time and CLOCK_THREAD_CPUTIME_ID bracketing submit. Two unchanged-production runs gave sheet p50 wall **1,056–1,061 µs**, CPU **1,010–1,057 µs**; runtime wall **1,652–2,101 µs**, CPU **1,647–2,095 µs**. A checkout-only comparison remembered the last validated nonzero identity within each row of the immutable offer, preserving per-cell field, pair and right-half checks. Runtime CPU medians became **1,113 and 1,208 µs**. This diagnostic targets repeated identities; it does not establish unrestricted workload gains or a production fix. Builds and other host load were active. Clock sampling perturbs the measurements slightly.

**Verdict.** Full validation and copying in one UI slice scale with V by construction. Repeated runtime directory callbacks are avoidable on this fixture and explain much of its additional cost. Copy bandwidth already consumes most of the sheet allowance in Sol’s run. The CPU measurements rule out descheduling alone; they do not isolate CPU frequency, shared-memory contention or predict a quiet-box sheet median. The contract’s 238 µs copy estimate leaves 2.42 ns/cell with no other work; its illustrative 4 ns/cell already misses. A full-grid target miss has now been measured, the signed condition for reconsidering slicing. First measure a cheaper validated path on the target; if it still misses, the advisor must resolve full-frame scheduling/admission while preserving one atomic commit and refused-frame semantics. Native G1 cannot be inferred. Battery results and an idle-host control are outstanding.
