# L0 fault-ID review

Reviewed worker commit `6d8ffc3` against the signed Wave 1 decision at `40ba37b`, its sign-off and November 23 correction, amendments A5 and A15, and the project ASSERT convention. File and line citations below refer to the worker commit. This is a source review. The mutant and lane results are the worker's evidence at `docs/decisions/v2-0fv.2.md:110–164`. I did not build or run the code.

1. **Must-fix before landing — an ignored synchronous fault can loop forever.** A read past the end of a truncated, unregistered file reaches `fault_chain` at `src/os/os_posix.c:997–1009`. With a prior `SIG_IGN`, line 973 returns to the same instruction with the mapping and disposition unchanged. Failed fixed remap on a registered native fault can take that same exit after taint and departure at lines 949–959. The default-disposition child at `tests/os_fault_test.c:557–570` misses the ignored case. The ignored child at lines 572–581 queues a synthetic `BUS_ADRERR` to itself.

   **Ruling on the correction.** Preserve delivery to a prior callable handler with its original arguments, mask and one-shot semantics. Such a handler can take action on a genuine fault. Bypassing it for every positive code breaks the signed chaining contract, including the failed-remap oracle at `tests/os_fault_test.c:689–701`. Handle the exceptional case in the prior-`SIG_IGN` branch. For an unrepaired address, alignment or object fault, dispatch fatally. Reuse the existing install-default and thread-directed `raise` sequence at `src/os/os_posix.c:984–990`, including its `_Exit` failure path. This guarantees fatal dispatch even if there is no instruction to repeat. Honor IGN for ordinary `SI_USER`, `SI_TKILL` and `SI_QUEUE` deliveries. Keep recovery itself restricted to the two signed codes at line 1001.

   The sign of `si_code` does not establish that an instruction will fault again. On Linux, `SI_KERNEL` describes an unspecified kernel source. `BUS_MCEERR_AO` can notify a thread of an unconsumed memory error asynchronously. Honor the prior disposition for that notification. Treat action-required `BUS_MCEERR_AR` as a fault and use explicit fatal dispatch for an ignored, ambiguous `SI_KERNEL` rather than relying on a retry. Linux also permits a thread to queue a positive fault code to itself, exactly what `src/os/os_posix.c:1184–1192` does. Its unmatched synthetic `BUS_ADRERR` must follow the same fault policy as the indistinguishable native code. The generic nonpositive Linux codes include timer delivery, too. This sign convention is backend-specific. Darwin, for example, assigns positive values to both `SI_USER` and `SI_QUEUE`. Update the header at `src/os/os.h:294–302` and the correction to describe the disposition policy. [Linux signal codes](https://man7.org/linux/man-pages/man2/sigaction.2.html) · [Linux self-directed send implementation](https://raw.githubusercontent.com/torvalds/linux/master/kernel/signal.c) · [Darwin signal definitions](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/bsd/sys/signal.h)

   **Tests.** In a fresh exec child set IGN, install using a separate valid registration, truncate the stray file and perform the volatile read from line 567. Require death **by SIGBUS** in the parent at lines 1184–1189. The alarm, a normal exit or an assertion death must fail. In a separate IGN child send a genuine `sigqueue(getpid(), SIGBUS, value)`, require normal continuation and zero repairs, then trigger a registered fault and verify that service still works. This last check catches a handler that reset the disposition and merely returned. Keep tests for both prior signatures, the one-shot and failed remap. Exercise the positive action-optional notification separately from the synthetic address fault.

4. **Must-fix before landing — enforce exclusive SIGBUS disposition ownership at installation (worker issue 6).** `src/os/os_posix.c:1019–1029` queries A, builds the new action using A's mask and flags, swaps, then publishes the returned action. If another installer writes B after the query, a signal just after the swap can call A. After selector publication it can call B under A's mask and flags. A writer after the swap can displace the service entirely. `pthread_once` at line 1112 serializes the service's installers only. Unconditional second-cell publication is safe under the signed sole-writer contract. It cannot repair a concurrent external installation. Comparison alone cannot repair a delivery that already happened, either.

   **Change.** Make prior-disposition setup a single-threaded startup phase, completed before launching competing setup code. Seal ownership of SIGBUS for the service, including while first registrations race. Exclude delivery that could consume a previous `SA_RESETHAND` action during the query/swap handoff. ASSERT at the application-controlled disposition-setting boundary that setup is still open and on the startup owner. On this glibc target an explicitly pre-thread startup hook can also `ASSERT(__libc_single_threaded)` before handing off ownership. Place that check at startup, **outside** lazy registration. The signed first-register race at `tests/os_fault_test.c:1062–1089` must remain legal. If comparing query and swap results as a tripwire, compare disposition, relevant flags and signal-mask membership semantically. Whole-struct byte comparisons include padding. No local ASSERT can prove arbitrary third-party code will never change a process-wide disposition. [glibc single-thread detection](https://sourceware.org/glibc/manual/latest/html_node/Single_002dThreaded.html)

   **Tests.** A late application disposition writer must trip the ownership ASSERT in a child. Keep the concurrent first-registration test and its exact one-swap oracle. In the sigaction wrapper deliver an ordinary queued signal just after the real swap but before returning the replaced action to the installer. Verify the correct prior callback and inherited mask in that window and after installation.

5. **Must-fix before landing — delete `SLOT_RESERVED`.** `src/os/os_posix.c:1061–1097` selects and initializes the slot under the same mutex that excludes every other writer until publication. Poll only reads generation and epoch. The handler reads base and length only after an acquire CAS on LIVE at lines 906–920 and 939–942. Even a delayed CAS that sees a recycled LIVE enters the newly published tenant before reading its metadata. There is no interleaving that distinguishes RESERVED from FREE during initialization. Delete the enum member, store at line 1091, switch cases at lines 912 and 1074, and the matching comments and spec table row. Initialize in FREE and retain the release-store of LIVE followed by the SC generation store. Three phases still require two bits. Keep the count increment and mask.

   **Tests.** Keep lowest-free selection, overlap rejection, first-registration races and the relaxed-handoff admission test at `tests/os_fault_test.c:447–462,481–504,842–855,1073–1115`. The latter specifically avoids publishing the metadata via a test-side join before the handler reads it.

6. **Must-fix before landing — settle the disputed orders.** Keep the per-poll **seq_cst** fence at `src/os/os_posix.c:1132–1141`. The opening SC loads order subsequent mapped reads. The closing fence orders those earlier mapped reads before the closing validation. Without that backwards ordering, the closing epoch load can observe zero, the handler can increment and replace the suffix at lines 949–957, and a delayed byte load can then consume a replacement zero. Both validations would authorize a result computed from repaired bytes. Generation validation alone cannot detect this because the tenant never changed.

   For this landing use **seq_cst** for the departure RMW at line 930 and the retire control-word operations at lines 1162–1175, including the close CAS, failure reload, final observation and FREE store. Record this choice in the implementation and decision. The zero-at-close path explains the need for an actual synchronization edge. A handler can read ordinary range metadata, finish its remap and depart while still LIVE. The retiree then sees zero at close, skips the semaphore entirely, and permits reuse and new ordinary writes to base/len. A relaxed departure alone supplies no release of the old handler's reads to its successor. The close/observation must acquire the departures through the control-word RMW release sequence in this path. For a positive-count close, post/wait supplies an additional edge from the final handler. In particular, the final acquire load is not independently proved indispensable by weakening just that load while leaving the acquire close and post/wait intact. The worker's own report acknowledges the joins at `docs/decisions/v2-0fv.2.md:257–265`. Stronger orders here are a review ruling, not new evidence of a failure in the submitted acq_rel protocol.

   **Tests.** Keep the paused-remap and both early/late-post oracles at `tests/os_fault_test.c:809–828,883–994`. For departure, exercise a LIVE departure followed by zero-count close and immediate reuse **before joining the handler thread**. Use only a relaxed test announcement of completion and no pipe or wrapper synchronization furnishing a handler-to-owner edge. A TSan mutant dropping the departure release should expose the metadata reuse race. For the poll fence the existing pipe fixture establishes taint before remap. It does not prove reader-side load ordering. Use a weak-memory litmus with a replacement-visible flag modelling the byte load and forbid “pristine twice, replacement read”; a clean x86 run does not distinguish the orders.

7. **Note — the submitted identity and drain protocols meet A5 on the audited target.** At `src/os/os_posix.c:1095–1102,1135–1143,1153–1159`, all generation publications, invalidations, epoch resets and poll samples are SC. A successful poll's two equal, nonzero generation samples enclose its epoch load in one issuance interval. A stale poll may speculatively sample a successor's epoch between its checks, but cannot return it to the caller. The mutex stays held through consumption of exactly one post for a positive-count close, examination of closed/zero and publication of FREE at lines 1151–1177.    **Change and tests.** Preserve these properties. The relevant behavioral reds are at `docs/decisions/v2-0fv.2.md:116–134`. Strengthen `tests/os_fault_test.c:781–803` with one poll by the observer after an explicit reuse-complete handoff, requiring NOENT and untouched output. Currently the owner performs the synchronized post-reuse check and can stop the observer before it polls again.

8. **Note — handler calls and backend eligibility.** On the specified 64-bit Linux/glibc backend, the service-owned handler uses checked lock-free atomics, glibc's AS-safe `mmap`, `sem_post`, `sigemptyset`, `sigaction`, `raise` and `_Exit`. All range accesses precede departure, and errno is restored for a prior callback and on return. See `src/os/os_posix.c:928–959,966–995,997–1012,1037–1049`. A prior callback runs in signal context and carries its own async-signal-safety obligation. There is no handler-side mutex, wait, heap operation or logging in the submitted service. Lock-free is sufficient here for the atomic operations; it does not promise a bounded number of CAS attempts. [glibc mmap safety](https://sourceware.org/glibc/manual/latest/html_node/Memory_002dmapped-I_002fO.html)

   **Change and tests.** Document the callback obligation and ensure only the audited backend enables installation. The dynamic checks at lines 1037–1048 test atomic lock freedom and native setup; they do not certify another libc's mmap. If the source is built for an unaudited libc, take sticky NOTSUP before installing the handler. Retain the native truncation and remap-failure children at `tests/os_fault_test.c:530–547,689–701` and the active release allocation guard at `tests/law2_os_fault_test.c:34–52`. For an unsupported configuration, require absent ID and unchanged disposition. A zero-allocation run is evidence for that property only.
