# Wave 2 viewport derivation review · v2-1sg

**Disposition: MUST-FIX before sign-off.** The public declarations match. The implementation loses a preferred column on height-only reflow, maps two different scroll positions to the same answer, and can decode 16,384 bytes in a 4,096-credit step. ## Signed header, ownership and grid

**NOTE · header.** Compared the declaration-order table with all eight value structs and the 21 VIEWPORT_ actions. The code block from the opaque cursor through viewport_pixel_row is present verbatim, including both progress states, the six tagged request alternatives and union member types, evidence, port signature and eight public functions. The header adds standard includes and a guard as allowed. The semantic port issue above survives a successful declaration comparison.

**NOTE · §S2 ownership.** RESTORE and SEEK_BYTE clamp the requested top. FOLLOW forwards committed caret, affinity and transformed top. SEEK_LINE waits on inexact select. SCROLL_Q8 and REFLOW compute quotient/remainder. LEFT/RIGHT, word motions and SELECT_WORD walk certified display segments. END uses the row's drawable end and trailing affinity at a shared end. DOC_HOME, DOC_END and SELECT_ALL use the document bounds directly. UP/DOWN and both page actions query the neighbor and destination column, with an extra top request for a page. SELECT_LINE owns the two selection edges. Plain moves collapse the mark, Shift moves retain it, and acceptance checks buffer, text, geometry and intent serial. V proposes selection, L supplies row/column evidence and final placement, and L5 installs via edit. The HOME dispatch, REFLOW reset, saturation, preferred-column carrier and FOLLOW margin qualifications are recorded here and in the answers below.

**NOTE · §S1/A29 derivation.** For hard start h the first eligible nominal grid is S × (ceil(h/S) + 1), including S at BOF. This is the first grid with h ≤ g−S. For synthetic start s = g + k, 0 ≤ k ≤ 3, (floor(s/S) + 1)S retains the nominal phase. stage_begin implements both in O(1). Staging stops early at LF. stage_finish tests up to three strict candidate leads, leaves invalid continuations on their raw boundaries, preserves CRLF across the nominal grid and suppresses a synthetic EOF. A final LF still has a hard successor in the provider. With LF at 0 and a four-byte scalar starting at 2S−1 the span from byte 1 to 2S+3 is 2S+2, inside D = 65,540 including the conservative allowance. The original passed both additional seam probes. Reverse discovery begins with VP_ROW at the preceding byte. Layout owns the bounded search that produces that certificate. The eager flat directory cannot prove its production cost.

**NOTE · §S2/E4.** Physical Home ranks the endpoint, selects the hard start when rank is exact, and uses RAW_BACK only for a missing start. Reading the resulting first display row for smart Home is separate from finding the hard boundary. SELECT_LINE probes high−1 for a nonempty exclusive end, reuses a collapsed endpoint's exact rank, selects the successor and extends one line on repeat. Exact answers transition immediately. The inexact paths scan back from low and forward from the occupied high endpoint, and can skip a known prefix for a missing successor. The all-exact Select Line case returns with zero window bytes. The two mixed witnesses read six and three window bytes respectively. M6 and M10 distinguish these paths. The fixture's single counted prefix simplifies real piece evidence, especially exact rank inside an unknown chunk with a blocked backward select. A collapsed inexact low rank is requested again for the same high endpoint at viewport.c:460. Reuse that observation for the two missing bounds.

**NOTE · §S4 and §S9 scope.** The 10 GiB length-only witness proves two constant-work target motions. The D+2 assertion covers returned windows for one two-credit LEFT on the long-span fixture. Neither counts original-intent placement intervals (≤2R−1), real row-slot completions (≤R), total completions (≤3R−1), discovery bytes, decoder passes or the one indivisible piece operation per slice. Layout owns F. The unit freshness comparison replays FOLLOW, a pass-through, and checks only top byte, remainder, affinity and caret. The fuzzer compares every answer field under wide versus fragmented/delayed grants, with two fresh cursors on one eager row directory and varying count evidence. That gives motion evidence. Full S9 requires fresh versus incremental rows, cells, absolute hits, affinity and top under identical rank/paint inputs, including edits and eviction. It awaits layout. At the viewport boundary a stronger history test would reuse a cursor abandoned mid-walk and compare every answer field after a different intent.

## Answers to Sol's seven questions

1. **Open for the advisor.** §S2 requires length for DOC_END/SELECT_ALL and the source screen column including continuation indent for vertical motion. The public port provides length on evidence and a destination-byte column query. It specifies neither a length-only request valid on an empty snapshot nor a row-to-source-column result field. UINT64_MAX and VP_ROW.count are local conventions. Both owners need one signed interpretation.
2. **Open for the advisor** on dispatch of a *distinct* physical Home. Ordinary visual Home in both modes is decided by the text at §S1, with continuation/start and first-nonblank behavior in §S2/S5. §S2/E4 decides the physical hard-start algorithm when requested. The sole HOME tag has no independent physical selector. The text gives no blanket permission to bind physical Home to clip mode.
3. **Decided by the text at §S2** for behavior. Clear preference on width change, preserve it on height-only reflow, and clear preference and horizontal scroll on a wrap toggle (row contract). Reflow the saved Q8 pixels using the new height. The representation of old width or of the change indication is open for the advisor. Comparing installed wrap in accept handles a toggle but cannot recover a preference already cleared on height-only reflow.
4. **Decided by the text at §S1** for top saturation and remainder, and at §S2 for page displacement and column placement. Preserve the modulus after an in-range movement. Saturate an overshoot. A byte-zero top alone cannot decide which occurred. Reporting actual displacement is one possible protocol. That carrier and any distinct caret policy for a page that overshoots onto a different terminal row are open for the advisor.
5. **Decided by the text at §S2/§Q11/§Q13** for ownership. V supplies the follow inputs including the requested margin. L has margin_rows in its geometry, caps the margin at floor((visible_rows−1)/2), performs minimum reveal and EOF backfill, and resolves final top/remainder. L5 commits accepted top and picture together. viewport_answer.top.subrow_q8 carries the pixel remainder. FOLLOW currently carries the selection and origin only. Sharing layout geometry as the source of the margin needs agreement if it substitutes for the §S2 handoff.
6. **Decided by the text at §Q10/§S8** for the split. L5 transports top with before gravity in edit order. viewport_rebase has no text evidence. Resolving the mapped point against the new text requires a legal cluster edge at the requested affinity, with leading affinity for top. Layout can perform this while resolving the new top before publication. The text leaves the precise internal call open for the advisor.
7. **Decided by the text at §S2/§S4** for lifetime and bounds. Allocate the opaque aligned cursor in layout's arena, preserve both live cursors on MORE, charge a text walk separately, and retain the placement summaries/source through paint as specified. The API exposes the motion allocation size, with no interface to borrow its internal arrays. Layout can recycle fully retired storage if lifetimes are disjoint. Sharing live summaries, adding a scratch interface, or adopting a particular overlay is open for the advisor.

## Benchmark and integration

**NOTE · benchmark verdict.** bench/viewport_bench.c:38 times flat_motion from begin through DONE. On the supplied S+1 ASCII fixture I counted the initial zero-credit probe and **42 positive-credit steps** of up to 4,096 credits per motion. The reported **747.421 µs p50 / 820.424 µs p99** are whole-motion times from Sol's 1,000 samples. They establish neither a missed nor a met 500 µs single-step deadline. The harness immediately replenishes each grant in one synchronous outer call. The walker retains its state between steps. The flat port's inverse-column scan can execute unsliced within a step. Time each step including provider service and count decoder bytes before claiming G1.

**NOTE · app and DAG.** The removed viewport_smoke simply called render_smoke. app_smoke now calls the same public L3 render function directly, which calls L2 edit_smoke. render.h includes only stddef.h. This stays within the PLAN §2 downward DAG and L5's ban on x11, wayland, gl and raster headers/symbols. The main smoke path no longer exercises L4. Its separate whole-archive L4 link invokes viewport_wrap_default, and the isolated L5 link still uses main.o. The viewport implementation depends downward on L1 and has no layout/render include. The Makefile registers the focused benchmark and export check, the lanes register viewport for san/TSan and fuzz, and the tooling reserves its public exports.

**NOTE · out of scope.** Actual layout placement/cache work, emitted rows/hits, reader cancellation and retirement, backing validation, accepted render frames, the release allocation guard and whole G1/G5 timings need integration owners. Sol's earlier full-lane receipts are author-reported. No fault subject was exercised. No production change is part of this review.
