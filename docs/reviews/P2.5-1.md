## 1. BLOCKER — Foreign work messages can bypass raster ownership and cause SHM races

**Location:** [src/raster/raster.c:389](/home/tobias/Projects/editor/src/raster/raster.c:389), [src/render/render.c:360](/home/tobias/Projects/editor/src/render/render.c:360).

`cpu_event()` identifies messages using their small integer kind, frame ID and payload index. It never verifies `slot_`/`epoch_` against the backend’s owned job handles.

**Concrete argument:** A live, unrelated pool job can publish kind `1`, generation equal to the active frame, and a payload identifying strip zero. Routing it into the backend uploads strip zero and decrements `pending` while the real strip-zero worker is still writing. When the other three workers finish, `pending` reaches zero and Present proceeds. The server can read unfinished SHM pixels; T5 can also permit atlas reuse while the remaining worker still samples it. Foreign kinds `2` and `3` can falsely acknowledge device and presentation completion.

**Fix:** Authenticate every message against the appropriate owned handle’s slot, epoch and generation. Match strip index to that handle, require index `< metrics.jobs`, and track completion with explicit flags. Return `UNSUPPORTED` for foreign messages without modifying state. Add a foreign-message regression with a deliberately paused strip worker.

## 2. BLOCKER — Raster diagnostics read beyond another backend’s state

**Location:** [src/raster/raster.c:449](/home/tobias/Projects/editor/src/raster/raster.c:449).

Both diagnostic functions accept any initialized `render_backend`, then cast its state to `cpu_state`. There is no backend identity check or documented CPU-only precondition.

**Concrete argument:** Initialize the null backend using its reported four-byte state allocation, then call `raster_last_present()` with non-null outputs or `raster_frame_metrics()`. Both read fields far beyond those four bytes, potentially crashing or exposing unrelated memory.

**Fix:** Verify CPU backend identity before casting, using an implementation discriminator such as the CPU ops identity. Return false for other backends and add cross-backend diagnostic tests.

## 3. BLOCKER — Accepted X visuals can display incorrect colours

**Location:** [src/raster/raster.c:237](/home/tobias/Projects/editor/src/raster/raster.c:237).

Initialization checks image byte order and 32 bits per pixel, but does not validate the window visual’s colour masks. Every kernel nevertheless emits RGB888 pixels.

**Concrete argument:** A depth-30 TrueColor visual with ten-bit RGB masks can have 32-bpp storage and pass this check. Full-coverage white becomes `0x00ffffff`; the visual expects `0x3fffffff`. Those values produce different colours. `plat_init()` can fall back to the root visual when its preferred depth-32 visual is unavailable.

**Fix:** Validate the actual `pl->visual`, class, depth and channel masks. Reject unsupported packing with `RENDER_ERR_UNSUPPORTED`, or implement the corresponding conversion. Test a depth-30 or deliberately incompatible visual.

## 4. MAJOR — Failed submit can block the UI indefinitely

**Location:** [src/raster/raster.c:345](/home/tobias/Projects/editor/src/raster/raster.c:345).

After partially enqueuing its jobs, submit cancels them and sleeps until their worker slots become free. Cancellation does not remove queued jobs immediately.

**Concrete argument:** Occupy 63 pool slots with long-running/queued raster jobs. The first backend job occupies the last slot; the next submission fails. The cancelled backend job remains queued behind unrelated work, and UI submit waits until a worker eventually dequeues it. There is no timeout or input check. This violates the typing-path slice bound.

**Fix:** Reserve/enqueue the complete job batch atomically, returning capacity failure before starting any job. Add a saturated-pool test proving failed submit returns promptly and retains no jobs.

## 5. MAJOR — Mailbox overflow silently loses essential completion messages

**Location:** [src/raster/raster.c:74](/home/tobias/Projects/editor/src/raster/raster.c:74), [src/raster/raster.c:102](/home/tobias/Projects/editor/src/raster/raster.c:102).

All calls to `work_publish()` discard its failure return.

**Concrete argument:** With one raster worker, let another job fill that worker’s 256-message mailbox before UI drains it. A raster job can still use another free job slot, finish, and have its completion dropped. Draining the mailbox afterwards cannot recover that completion: `pending` stays positive and Present remains BUSY permanently. Losing a fence or Present message similarly strands the active frame.

**Fix:** Give essential completions reliable delivery through reserved capacity or cancellation-aware backpressure. Ensure publication failure produces a recoverable backend error through a reliable channel. Test full-mailbox strip and fence completion.

## 6. MAJOR — One-row typing work scales with the entire glyph table

**Location:** [src/render/render.c:288](/home/tobias/Projects/editor/src/render/render.c:288), [src/raster/raster.c:331](/home/tobias/Projects/editor/src/raster/raster.c:331).

Every submit validates the complete atlas table twice, validates every active cell, then copies every glyph descriptor—even for one dirty row or zero damage. Accepted capacities have no corresponding UI-time bound.

**Concrete argument:** A valid grid can bind 500,000 one-pixel glyph descriptors referencing the same one-byte page, while visible cells use only slot zero. Each key then performs roughly one million glyph-validation iterations and copies 12 MB of descriptors on UI. `max_atlas_bytes` does not constrain this work, and there are no input checks.

**Fix:** Bound the per-frame table to a measured viewport budget, export only necessary glyph bindings, and eliminate duplicate atlas validation. If incremental validation requires changing the frozen contract, do that explicitly in a new bead. Add a maximum-capacity typing test.

## 7. MAJOR — Worker cancellation checks are separated by an entire cell row

**Location:** [src/raster/raster.c:78](/home/tobias/Projects/editor/src/raster/raster.c:78), [src/raster/raster_kernel.c:240](/home/tobias/Projects/editor/src/raster/raster_kernel.c:240).

Cancellation is checked before a cell row and after the job, never inside the kernel. A cell row is not a bounded CPU slice under the accepted dimensions.

**Concrete argument:** The accepted extent limits permit one cell measuring 65535×32767 pixels. If initialization succeeds, that single kernel call writes about 8.59 GB before checking cancellation again. Even Target A’s theoretical 102.4 GB/s bandwidth gives about 84 ms of unavoidable traffic, exceeding `work.h`’s five-millisecond polling contract.

**Fix:** Raster bounded tiles or pixel-row batches, checking cancellation between them. Bound tile work independently of cell dimensions and test cancellation during a large row.

## 8. MAJOR — Fence inputs cross outside the required work handoff

**Location:** [src/raster/raster.c:135](/home/tobias/Projects/editor/src/raster/raster.c:135), [src/raster/raster.c:367](/home/tobias/Projects/editor/src/raster/raster.c:367).

The fence job is published before its frame and sequence inputs are initialized. UI subsequently writes those fields and publishes them through the private `armed` atomic.

**Concrete argument:** The worker receives mutable backend state, waits on a direct shared flag, and then reads fields written after `work_submit()`. Acquire/release provides C synchronization here, but this violates the project rule requiring snapshots and shared-state handoff through `src/work`.

**Fix:** Publish a fully initialized, backend-owned immutable fence-job snapshot through the work API. Use reservation or a retained presentation phase to handle enqueue failure without submitting Present twice.

## 10. MAJOR — G3z converts dropped frames and errors into successful skips

**Location:** [bench/raster_bench.c:266](/home/tobias/Projects/editor/bench/raster_bench.c:266), [bench/raster_bench.c:351](/home/tobias/Projects/editor/bench/raster_bench.c:351).

A skipped pixmap or nonadvancing MSC returns success without setting `fail`. Frame failure returns `-1`, which main only prints as a skip.

**Concrete argument:** A missed-refresh run followed by one SKIP completion discards the accumulated miss count and returns success. With `--idle 0`, a scroll-only frame error can likewise reach main’s successful exit. `--quick` also labels a 300-frame run as `scroll_10k_G3z`.

**Fix:** In gate mode, fail on frame errors, SKIP mode, invalid/nonadvancing MSC and incomplete runs. Permit fixture skips only in explicit TRACK mode. Prime a displayed baseline and verify the full required refresh interval count.

## 13. MAJOR — The partial-redraw pixel test undoes every tested change

**Location:** [tests/raster_test.c:272](/home/tobias/Projects/editor/tests/raster_test.c:272), [tests/raster_test.c:285](/home/tobias/Projects/editor/tests/raster_test.c:285).

The only partial-image readback occurs after ten identical XOR mutations.

**Concrete argument:** Ten toggles restore `cells[8].fg` to its initial value. Removing every partial upload would leave the initial full image on screen, matching the final scalar expectation. **Fix:** Read back after individual non-cancelling mutations. Test disconnected strips, partition boundaries and unchanged rows. Require readback failure to fail the live test instead of silently skipping comparison.

## 14. MAJOR — The required 10,000-submit allocation assertion is disabled

**Location:** [tests/raster_test.c:40](/home/tobias/Projects/editor/tests/raster_test.c:40), [tests/render_test.c:294](/home/tobias/Projects/editor/tests/render_test.c:294).

The external driver replaces `edit_malloc_guard_active()` with constant false. Its dedicated submit guard covers only ten frames.

**Concrete argument:** An allocation introduced at frame 1000 passes the external 10,000-frame loop because its assertion is disabled, and passes the dedicated test because that test only reaches frame 11. The law-2 addendum requires 10,000 input-through-submit checks while excluding completion handling.

The long runtime is consistent with 10,000 sequential Present completions: approximately 167 seconds at 60 Hz. The conformance window is also unmapped until the later live pixel test. This is largely presentation waiting, not kernel execution or repeated two-second timeouts.

**Fix:** Count and assert each input-through-submit window over all 10,000 frames, ending the window before pumping completion events. Use a deterministic driver for the exhaustive loop and a shorter mapped live lifecycle test.

## 15. MAJOR — Row kernels disagree with their documented destination origin

**Location:** [src/raster/raster.h:42](/home/tobias/Projects/editor/src/raster/raster.h:42), [src/raster/raster_kernel.c:48](/home/tobias/Projects/editor/src/raster/raster_kernel.c:48).

The header promises a destination whose row zero is the surface’s first pixel row. All kernels instead treat it as the requested cell row’s destination band.

**Concrete repro:** Use a valid 1×2 grid with 1×1 cells and distinct backgrounds. Call `raster_row_sse2(&scene, surface, 1, 1)`. It reads cell row one but writes `surface[0]`, leaving `surface[1]` untouched. The tests and fuzzer allocate/reset one destination band per call, so their differential comparisons cannot detect this contract error.

**Fix:** Make destination origin explicit and consistent across the header and callers. Either document row-local pointers or move the row offset into the public kernels and remove caller offsets. Add an independent full-surface placement test.

## 17. MINOR — T6’s timestamp is replaced with T5’s observation time

**Location:** [src/raster/raster.c:186](/home/tobias/Projects/editor/src/raster/raster.c:186).

The worker publishes `max(t6, t5)` as the Present completion timestamp rather than the timestamp recorded for that event.

**Concrete argument:** The first reply poll can return no reply; subsequent event polling can read the fence reply into XCB’s internal queue and observe Present completion. The next iteration observes the queued fence reply later. The reported T6 is then moved forward, obscuring the separate completion observations.

**Fix:** Preserve the recorded T6 timestamp. Keep the adapter’s T4 clamp, and test a Present observation preceding the fence-reply observation.
