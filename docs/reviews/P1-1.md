## 1. BLOCKER — The capacity fix rejects ordinary typing after the buffer has already changed

**P1.6b’s fix for lineidx-1 §1 is incomplete at the caller seam.** The editor commits `undo_insert` before calling `lineidx_edit`. Capacity refusal therefore leaves the buffer changed and the index unchanged; the editor returns an error before finishing the edit’s undo/render bookkeeping.

This is reachable after only 65 characters. Each insertion within a full first chunk creates another small chunk without coalescing the previous fragments, consuming the default 64-entry reserve.

```text

piece_len=65601 index_len=65600 chunks=65
```

The local refusal test checks index preservation, but does not compose refusal with an already committed buffer mutation.

**Fix:** preflight the complete buffer/index transaction before mutation, or provide coordinated rollback. Rebalance adjacent small chunks so ordinary typing does not consume one reserved entry per character. Add an actual file-backed editor test covering more than 64 successive insertions and refusal during undo/replacement.

## 2. BLOCKER — Detected mapping faults do not invalidate find or index results

Location: [src/file/file.c:109](/home/tobias/Projects/editor/src/file/file.c:109), [src/lineidx/lineidx.c:191](/home/tobias/Projects/editor/src/lineidx/lineidx.c:191), [src/find/find_int.h:14](/home/tobias/Projects/editor/src/find/find_int.h:14), [src/editor/editor.c:66](/home/tobias/Projects/editor/src/editor/editor.c:66).

**P1.7c’s containment for file-1 §§4–5 protects saves and rejects keep, but leaves the derived-result seam incomplete.** SIGBUS recovery increments the mapping’s fault counter before replacing bytes with zeros. Neither find’s control token nor lineidx’s publication generation incorporates that counter. P1.8d validates the work lease, not the backing generation.

The current editor does not connect mapping invalidation to index cancellation or reject results from faulted backing.

An executed anonymous-mapping fixture queued consumers before invoking the production recovery function:

```text

find_code=0 find_total=0 find_published=1
index_lines=1 exact=1
original_lines=32769 original_matches=32768
```

Both consumers published successful results for a source generation already invalidated by recovery. This is distinct from the documented *undetected* check/read race.

The file fault tests exercise reads and saves; the find and lineidx models do not compose recovery with their publication paths.

**Fix:** bind snapshots and derived jobs to a backing-generation token. Check invalidation during computation and immediately before adoption, cancel affected work leases, and invalidate already adopted metadata. Preserve physical mapping ownership until cleanup completes. Test faults during scanning, after computation, before publication, and while snapshots outlive the file object.

## 6. MAJOR — The first edit permanently disables index completion in the editor

## 7. MAJOR — Dense byte counting still enumerates every match

Location: [src/find/literal.c:358](/home/tobias/Projects/editor/src/find/literal.c:358), [bench/find_bench.c:213](/home/tobias/Projects/editor/bench/find_bench.c:213).

After storing 4096 offsets, the counting path still executes:

```c
while (mk) { mk &= mk - 1; r->total++; }
```

This contradicts perf §2.7’s explicit requirement to count the remaining matches by popcount.

The release-flags GCC assembly confirms a scalar decrement/AND/branch loop; it does not optimize this into popcount. An all-`a` 1 GiB search therefore executes approximately one billion iterations. Even granting one iteration per target A’s documented 5.2 GHz cycle exceeds the 125 ms gate, before scanning and publication.

The benchmark’s one-byte row searches sparse newlines. Its all-`a` rows search multi-byte near misses, so none exercises the required dense one-byte workload.

**Fix:** count remaining mask bits with hardware-dispatched or fixed-work software popcount. Retain enumeration only while filling offsets. Add a gated all-`a`/`a` row and a work-count regression proving dense output does not cause per-match iteration.
