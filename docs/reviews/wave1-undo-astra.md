### MUST-FIX — Burst promotion fabricates the carried record for the combined span

**Trace (P).** Start with a counted, contiguous ORIGINAL containing 16 bytes, all newlines. Delete the first 15 bytes, then delete the remaining byte at the same offset and time. The first inverse is literal because one 16 B pair costs more than 15 bytes. The second erase extends it at equality because 15 + 1 = 16. The iterator described the two parts separately, returning heads of 15 and 1. `join_runs` constructs a head of 16, `extend` installs it on ORIGINAL [0,16), and `apply` passes it to `piece_replace_spans`. No production iterator call described that exact span with its record. This also occurs when extending an existing span inverse. See `src/undo/undo.c:471,529,570,611,775`.

The source coordinates concatenate correctly and the arithmetic in this trace gives the correct newline total. The frozen precondition binds the record to the **exact span described by the iterator on a view of this tree** (G, `src/piece/piece.h:134`, decision `v2-0fv.7`, “Provenance and its debug check”). A sanitizer recount checks known values against bytes. It cannot establish how the caller obtained them. The fresh expected description in `tests/undo_test.c:337` likewise compares values. Preserve independently described records as separate edits in the same burst group whenever extension would require synthesizing a span record, or obtain an approved piece contract for composition with its own proof and tests. Keep the counted mapped replay guarantee when choosing the fix.

### MUST-FIX — A caller-owned forward checkpoint can rewind ADD underneath published history

**Trace (P).** Open a private-copy tree containing 16 lowercase `a` bytes with empty ADD. Begin the forward-command checkpoint. Through the log, insert 16 uppercase `B` bytes at EOF, then delete that insertion in a separate group. Each change skips the inner checkpoint because the tree is private and neither edit needs a literal capture. The deletion is a one-span equality case (16 × 1 = 16), so it publishes the coordinates ADD [0,16) and a known head of zero. The document already equals its pre-command text. Abort the outer checkpoint. The ADD mark returns to zero, yet both groups remain published. Capture the original lowercase bytes into ADD without changing the text, as the public piece API allows. Undo the deletion. Source bounds now pass, the newline recount still finds zero, and replay inserts 16 lowercase bytes instead of the 16 uppercase bytes that were deleted. The history cursor advances. Without regrowth, replay instead violates the piece bounds precondition. See `src/undo/undo.c:498,626,694,710,775` and `src/piece/piece.h:317,334,367`.

The other branch fails earlier. A mapped edit or literal capture calls `piece_checkpoint_begin` inside the caller's already-open checkpoint, violating its non-nesting precondition (G). The signed ownership table gives the forward checkpoint to the UI edit transaction, and “Undo and eviction” requires publication at commit and rewind on abort. The integration question in `docs/decisions/v2-0fv.8.md:64` therefore already affects L1. Give the forward transaction one checkpoint owner and a matching history commit/abort boundary. Defer redo detachment, eviction, burst mutation and publication until irrevocable commit, or restore them on abort. Exercise the trace above and a literal capture under the same outer command. An unrelated abort whose restored mark still covers every published byte is safe.

### SHOULD-FIX — Pin the byte-cap fixture to an independently derived cost

`typing_record` and `erase_threshold` derive their fixed charge from the implementation's first reported charge. Omitting the group charge would still satisfy these delta checks. On the candidate LP64 layout the expected slot is 264 B (P, 192 B inline arrays + 16 B tag/count prefix + 48 B record prefix + 8 B slab owner). A fresh one-byte key therefore charges 529 B (P, group and record each occupy a slot, plus the byte). Test an exact fit and a cap one byte below it. For an external vector, assert the incremental active charge as well as the held vector payload, using 24 B per entry (P, 16 B coordinates + 8 B edge counts). These are v2-derived oracles under A20.

### NOTE — The regular inverse choice and the history walk are bounded as specified

`prepare_inverse` counts canonical runs without reading payload, compares against floor(length / pair width), and describes exact clipped spans on the reference path. For a source gap, a different tagged store or a multi-run extension, `erase_extension` declines the merge. Short literal extensions also check the capture's ADD end. A backspace reconstructs capture segments in reverse capture order. Its maximum is 15 segments (P, combined one-run literal length below 16 B and each capture nonempty). The inverse threshold and the larger in-memory entry width serve their respective signed purposes.

`account` updates group, active and applied costs together. `trim` performs up to 16 individual oldest-group removals (G, inherited boundary budget), then detaches an eligible prefix using aggregate counters. It protects the open explicit group. `clear_redo` splices the suffix and resets its counters directly. The automatic maintenance pass visits at most 16 retired records (P, the budget passed by `edit` and the loop in `undo_maintain`). The unbounded drain is in explicit clear/teardown. I found no walk through an unbounded number of history records on a keystroke.

### NOTE — Sliced replay owns temporary views and publishes at the group boundary

`begin_replay` takes the multi-record pre-group view before opening the checkpoint. The first take and checkpoint share the pre-group revision. A mid-group yield takes the intermediate guard. Resume retakes the current snapshot, asserts pointer identity and releases both guard references before the next mutation. The retained guard prevents address reuse. Every checked error after begin aborts the checkpoint and drops the pre-group view. The public cursor and history counters move only in `commit_group`. The `completed` copy preserves earlier committed results on a subsequent failure. Ordinary records retain **zero tree roots** (P, `undo_record` contains links, offsets, lengths and the inverse union). The borrowed tree owns the core and must outlive the log. The temporary replay owners match the signed ownership table. See `src/undo/undo.c:54,91,365,789,851`.
