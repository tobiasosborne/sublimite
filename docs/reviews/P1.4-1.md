## 1. BLOCKER — Snapshot owner count wraps and permits premature reclamation

**Location:** [src/piece/piece.c:955](/home/tobias/Projects/editor/src/piece/piece.c:955), counter declaration at line 81; reclamation at line 261.

`piece_snapshot_retain` unconditionally increments a 32-bit `atomic_uint`. Cached snapshots let arbitrarily many owners share one header, so overflowing this counter does not require billions of allocations.

**Repro:** Take one snapshot: its count is two, including the cache owner. Execute 4,294,967,294 public retains. The probe reproduced `rc == 0`. One further retain produces `rc == 1`; releasing that owner enters the last-owner branch despite billions of outstanding owners and the tree’s cache reference.

The header is returned to the pool, which overwrites snapshot fields and poisons them in ASan builds. Existing owners and `cached_snapshot` now reference a reclaimed object. Atomic memory ordering does not prevent counter overflow.

**Fix:** Widen the counter and use a checked increment. Define and propagate a safe retain failure at saturation; invoke mapping acquire only after retaining succeeds. Add a counter-boundary regression using a private test hook.

## 2. BLOCKER — Content-length growth can wrap without returning an error

**Location:** [src/piece/piece.c:763](/home/tobias/Projects/editor/src/piece/piece.c:763), updates at lines 479 and 797; reference insertion at lines 902–919.

Neither insertion function checks that the resulting document length remains representable. `piece_insert` checks only `off <= total`; `piece_insert_ref` validates individual add-buffer spans but never checks their total against the document’s remaining `uint64_t` capacity.

**Concrete argument:** For a valid current logical length of `UINT64_MAX - 1`, inserting two bytes at the end passes the offset check. If the cursor extension path has room, it performs no allocation and wraps `t->len` to zero. Ancestor byte totals wrap too, making existing content inaccessible through ordinary queries.

Reference insertion can produce the same overflow because references may be reused and logical document length is independent of physical add-buffer length. This is a static boundary argument; a full-size tree was not instantiated.

**Fix:** Check resulting length before either fast paths or mutation. Sum reference lengths with checked arithmetic and reject an unrepresentable result without changing the tree. Test the checked arithmetic at `UINT64_MAX`, independently of enormous allocations.

## 3. MAJOR — Cursor deletion destroys the per-piece memory bound

**Location:** [src/piece/piece.c:830](/home/tobias/Projects/editor/src/piece/piece.c:830), especially lines 839–848.

The cursor delete path removes leaf entries without running `maybe_merge` or redistributing entries. It permits every non-root leaf to shrink to one piece. Trimming cannot reclaim these leaves because they remain live.

**Repro using public mutations:**

1. Prepend 10,000 separate one-byte `"x"` inserts.
2. Delete one byte at offset zero 15 times.
3. For `k = 1..1248`, insert and delete a temporary byte at `k + 1`, then perform seven individual one-byte deletes at `k`.

The temporary mutation primes the cursor cache in each successive leaf.

The probe ended with 1,249 pieces, one per leaf, and **489,808 B live (M)**. With 11,248 typed bytes and 9,999 deleted bytes, the frozen header permits only **216,094.75 B (G)**. This fails even its generous all-deleted-bytes formula.

**Fix:** Fall back to general deletion before a cached deletion makes a leaf underfull, or perform bounded ancestor rebalancing. Add this thinning sequence as a memory regression.

## 4. MAJOR — Versioned snapshot headers exceed the advertised snapshot allowance

**Location:** [src/piece/piece.c:948](/home/tobias/Projects/editor/src/piece/piece.c:948), node classes at lines 34–35; COW at line 221.

Each distinct snapshot version consumes a **272 B leaf-pool slot** for a roughly 40 B header. Caching bounds repeated takes of an unchanged version, but does not bound headers retained across edits.

**Repro:** Prepend 10,000 individual bytes, producing height four. Repeat 5,000 times:

```c
snap[i] = piece_snapshot_take(t);
piece_insert(t, 1 + i, (const uint8_t *)"x", 1);
```

These inserts coalesce, leaving 10,000 pieces. Each edit copies 1,872 B of nodes and retains another 272 B header. Slab bookkeeping adds approximately 24 B per version: approximately **2,168 B/version**, against **1,920 B/edit (G)**.

The stats-enabled probe measured **11,329,856 B live (M)** against **10,648,382 B (G)**. Its instrumentation adds only 48 B.

At height six, the node path alone costs `6*400 + 272 = 2672 B`, before headers or slab overhead.

**Fix:** Give snapshot headers a compact size class, include headers and slab overhead in accounting, and enforce the allowance at every supported depth. If retaining 1,920 B requires changing the supported layout or memory contract, record that decision explicitly. Add changed-version tests at greater heights.

## 5. MAJOR — Overflow deletes copy ADD data beyond strict G10f funding

**Location:** [src/piece/piece.c:869](/home/tobias/Projects/editor/src/piece/piece.c:869); benchmark accounting at [bench/piece_bench.c:603](/home/tobias/Projects/editor/bench/piece_bench.c:603).

When collection needs more than eight spans, deletion copies the entire range—even ADD bytes already stored permanently. The same fallback runs with `ref == NULL`, because a temporary reference is constructed.

**Repro:** Starting from an empty copied tree, insert and separately delete nine 64 KiB blocks, retaining their individual references. Reinsert those references in reverse order, then delete the entire range.

Only **589,824 bytes were typed**, and **zero original bytes were deleted**. The fallback nevertheless appends another 589,824 bytes. After deletion, the probe measured **1,182,288 B live (M)**. Even granting the header’s extra 4 KiB, the strict G10f budget is **806,912 B (G)** before the small undo-record allowance.

The frozen header requires fallback copying for requested references, while perf funds deleted-original bytes. Its claim that this leaves G10f unchanged is therefore false. Tests and the benchmark conceal the conflict by funding *all* deleted bytes.

**Fix:** Skip span-overflow copying when no reference is requested. For requested references, reconcile the contracts: either change the representation to reuse fragmented ADD extents, or explicitly fund fallback-copy bytes. Track deleted-original and fallback-copy bytes separately and gate this sequence against the binding formula.

## 6. MAJOR — Released snapshot storage remains charged after all snapshots disappear

**Location:** [src/piece/piece.c:262](/home/tobias/Projects/editor/src/piece/piece.c:262), remote returns at line 143; deferred trimming at line 269.

Final release returns nodes and headers to remote free lists but does not free their slabs. Once every external snapshot has been released, the live-snapshot allowance disappears while those allocator allocations remain live. Reclamation depends on a later owner call.

**Repro:** Initialize an empty copied tree, insert one byte, then take a snapshot and append one byte 32 times. Release all snapshots and inspect allocator live bytes before calling another tree function.

The probe measured:

- Core reference count: **1**, with no cached snapshot.
- Live allocation: **85,456 B (M)**.
- Frozen bound: **69,769.25 B (G)**.

Calling `piece_len` subsequently reduced live allocation to 67,792 B. The intervening query is what makes the bound pass.

**Fix:** Arrange synchronized slab reclamation when the last snapshot ownership disappears, with bounded owner bookkeeping. Add a memory test immediately after final release, before any query, including release from a worker thread.

## 7. MAJOR — Failed initialization retains large unused reservations

**Location:** [src/piece/piece.c:704](/home/tobias/Projects/editor/src/piece/piece.c:704), array allocation at line 706; failure return at line 752.

`build` reserves both node classes before allocating its temporary array. Failure does not roll back those reservations. The original pointer is cleared, but unused slabs remain allocated.

**Repro:** On a fresh tree, attempt a 1 GiB mapped initialization with an allocator permitting 274 further allocations and then returning NULL. The temporary array allocation fails:

```text
mapped initialization: NOMEM, content length 0, live 313904 B
subsequent init_copy(NULL, 0): success, live 313904 B
```

The successfully initialized empty copied tree permits only **69,632 B (G)**. A later query can trim the storage, but the failure and subsequent successful initialization return over budget.

Existing failure tests cover mutations on initialized trees, not initialization rollback.

**Fix:** Roll back newly reserved, unused slabs on every initialization failure. Preserve pre-existing roots and snapshot ownership. Add allocation-failure sweeps for create, copy initialization, and mapped initialization, checking live bytes before cleanup queries.

## 8. MAJOR — Slab trimming performs whole-tree work on the typing path

**Location:** [src/piece/piece.c:159](/home/tobias/Projects/editor/src/piece/piece.c:159), callers at lines 765, 895 and 942.

After only 64 returns, `pool_trim` scans every slab and every slot in both classes. Its cost scales with the entire allocated tree, rather than the current edit or reclaimed storage.

This work runs inside deletion and owner housekeeping used by insertion, `piece_len`, and snapshot taking. It also violates the snapshot API’s O(1) requirement.

**Repro:** Build one million pieces by individual prepends, invalidate the cursor through snapshot take/release, then perform ten 1 KiB prefix deletes. The fixture contained 31,251 leaf slabs and 4,469 branch slabs.

Every delete took **2.28–2.78 ms (M)[AC]**, before rendering. This exceeds the 50 µs kernel budget and already consumes more than G1’s 2 ms end-to-end p99 budget. These are ten adversarial samples, not an official full-matrix result.

**Fix:** Track occupancy per slab and reclaim completed slabs through bounded, synchronized queues. Remove enumeration of all live slabs from foreground mutations and snapshot taking.

## 9. MAJOR — Range reads re-descend from the root for every leaf

**Location:** [src/piece/piece.c:604](/home/tobias/Projects/editor/src/piece/piece.c:604), specifically line 607; range reading at line 616.

The walker remembers only the current leaf. At every leaf boundary it calls `walk_seek(root, pos)` again.

**Concrete argument:** Reading N one-byte pieces across a height-h tree performs approximately N/8 root descents in the normal split layout. Its traversal work is proportional to N·h, rather than the promised `O(log n + len)`. Snapshot reads share this implementation. Deletion collection and fallback copying repeat the same traversal.

The frozen read comparison checks bytes, but has no traversal-work assertion; benchmark viewports generally contain much larger pieces.

**Fix:** Implement range reads and collection with a local ancestor stack or range DFS, visiting each intersected node once. Add a one-byte-fragment regression that checks both content and traversal work.

## 10. MAJOR — Reference undo rescans the entire payload on every replay

**Location:** [src/piece/piece.c:917](/home/tobias/Projects/editor/src/piece/piece.c:917); frozen undo workload at [bench/piece_bench.c:504](/home/tobias/Projects/editor/bench/piece_bench.c:504).

Every reference insertion calls `nl_count` on every recreated chunk. Immutable ADD bytes are read again even though their newline counts were already known when inserted.

**Repro:** Keep `".."` as original content and capture a reference to a 1 MiB ADD insertion between the dots. After warming, repeat 10,000 reference insert/delete cycles at offset one.

The payload occupies only 1 MiB and remains unchanged. Reference insertion nevertheless recounts **10,485,760,000 bytes**. The batch took **1.391 s (M)[AC]**, ending with the correct two-byte original content.

The frozen undo matrix exercises only 1–64 byte ranges. It cannot expose this payload-size cliff against G9’s 63/84 ms budget.

**Fix:** Cache newline totals and prefix counts with ADD storage, and recreate chunk-spanning references through bulk tree insertion. Add a separate large-reference undo benchmark while preserving the frozen referee.

## 11. MAJOR — Permanent tests do not exercise the uint64_t offset contract

**Location:** [fuzz/piece_fuzz.c:22](/home/tobias/Projects/editor/fuzz/piece_fuzz.c:22), also lines 28, 37, 42 and 54; [tests/piece_test.c:248](/home/tobias/Projects/editor/tests/piece_test.c:248).

Fuzzer edit positions are decoded from only two bytes, so they never exceed 65,535. Its byte-to-line queries never exceed 765. Reference operations immediately reinsert the deleted range, preventing efficient growth of logical length through reference reuse.

The conformance suite’s largest initial buffer is 4 MiB. The optional 10 GiB benchmark is skipped in the standard matrix.

**Concrete coverage repro:** One 64 KiB payload, captured as a reference and inserted 65,538 times, creates a **4,295,098,368-byte logical document** with little physical storage. An anonymous probe passed tree and snapshot reads, line maps, and iterator starts across `2^32`, including snapshot reads after tree destruction. None of the permanent tests exercise this inexpensive case.

**Fix:** Add that fixture permanently. Exercise high offsets, chunk boundaries, EOF, `UINT64_MAX` range rejection, and the overflow arithmetic from finding 2. Extend the fuzzer with wide offsets and retained references that can be inserted repeatedly.
