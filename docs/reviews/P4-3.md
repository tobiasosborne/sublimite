## 1. BLOCKER — Restarting a cancelled large-file find can free a running worker’s argument

Locations: `src/editor/buffers.c:496`, `src/editor/large.c:213`, `src/editor/large.c:219`, `src/editor/large.c:222`.

Source-change handling clears `find_running` and logically cancels the handle. After a successful Keep, `editor_large_find_begin` is admissible again and immediately releases the old snapshot and frees `lg->find`, without checking physical completion.

Repro: run a find over a COPY buffer; detect an external change; Keep; start another find before the cancelled worker returns. The old worker can still read its snapshot, write `j->rc`/`j->result`, or access `j->released`. The atomic release flag does not retain the job object.

**Fix:** retain cancelled argument/snapshot storage until `work_handle_finished(old_handle)`. Unbind the old receiver before retirement and use separate reserved slots for active and retiring requests. Add a held-worker change → Keep → new-find regression.

## 2. BLOCKER — Public tab APIs can abandon a sliced undo checkpoint and expose provisional bytes

Locations: `src/editor/input.c:283`, `src/editor/buffers.c:259`, `src/editor/buffers.c:271`, `src/editor/buffers.c:293`, `src/editor/buffers.c:224`, `src/editor/editor.c:305`.

Sliced replay is represented by `EDITOR_ACTION_REPLAY_WORK`, independently of `view_busy`. Public tab/open/close APIs check only `view_busy`; activation then resets the action to NONE.

Repro: create a large typing group, begin undo, and let its first slice yield. Between `editor_step` calls, select another tab through the public API, then reactivate the original tab. Its undo checkpoint remains open, but the editor no longer resumes it or suppresses submission. Provisional tree bytes can be rendered without corresponding journal records. Subsequent edits can also fail with undo BUSY.

The ordinary queued-key path protects replay; these public entry points do not.

**Fix:** give every activation/mutation entry point a common replay-busy guard. Queue, refuse, or explicitly abort replay before switching. Expose committed reads through `undo_replay_snapshot` while partial. Test public APIs between replay slices with journal and frame assertions.

## 3. BLOCKER — The editor has no recoverable save path

Locations: `src/editor/input.c:380`, `src/editor/large.c:238`, `src/editor/large.c:243`, `src/editor/buffers.c:228`, `src/savectl/savectl.h:93`.

Ctrl+S is consumed as unimplemented. The available large-file save helper calls `file_save_begin` directly, without journal prepare/finish reconciliation, source-root capture, saving-frame acknowledgement, or saved-history bookkeeping.

Repro through the helper: open a journalled named file, edit, save successfully, make another presented edit, then crash. Atomic replacement removed the original BASE generation, while the journal still refers to it. Recovery cannot reconstruct the session. The existing editor-large save tests disable journaling, so they miss this failure.

**Fix:** wire save commands through `savectl_save_request`, using the published immutable session root and retained source/storage leases. Render and acknowledge the exact Saving frame, reconcile all buffers sharing the target, and finish the journal before installing Saved. Test crash points around replacement and post-cutoff edits.

## 4. BLOCKER — Reload and Keep resume editing without reconciling invalid journal BASEs

Locations: `src/editor/buffers.c:514`, `src/editor/buffers.c:520`, `src/editor/checkpoint.c:33`, `src/editor/editor.c:572`.

Keep updates the file layer’s baseline but leaves `b->base` and existing journal BASE records unchanged. Reload appends a new buffer’s BASE while retaining the old conflicting buffer and its earlier records.

Repro: open a journalled COPY file, externally replace it, choose Keep, and present another edit. Replay rejects the old BASE, whose bytes are no longer on disk. Reload has a related failure: replay encounters the obsolete BASE before reaching the newly opened generation. Ordinary successful flush does not rotate this away; failure checkpointing rejects the old BASE too.

Keep also leaves the tab’s clean-history marker unchanged despite kept contents differing from disk.

**Fix:** make source resolution a complete session checkpoint transition before accepting further edits or frames. Rebase kept bytes against the newly accepted disk generation, or remove/replace discarded generations on Reload. Preserve unrelated buffers and retained tokens; mark kept contents dirty. Add journal-enabled COPY and mapped source-choice recovery tests.

## 7. MAJOR — Healthy sessions never journal view, tab, or window changes

## 8. BLOCKER — Editor admission and scheduling still do not enforce the power-loss bound

Locations: `src/editor/open.c:176`, `src/editor/input.c:98`, `src/editor/editor.c:499`, `src/journal/journal.c:535`, `docs/decisions/P1.9h.md:34`.

The editor uses legacy append APIs without durability credit and shares its durability worker with bulk work. Pumping is additionally conditional on `!e->dirty`.

A pending layout/input frame can postpone sync scheduling indefinitely; a long bulk operation can postpone an already queued sync. Large replay staging can write far more than 64 KiB before a durability fence. Page-cache protection fixes process-crash loss, not the specified power/kernel-loss maximum.

This remains an unfulfilled editor integration obligation explicitly identified in P1.9h.

**Fix:** integrate independent durability execution/admission capacity, pump independently of frame dirtiness, and enforce complete-record credit against received durability fences. Resume large journalled edits in protected slices without blocking input. Test continuously dirty frames, occupied bulk service, and a separate durable-image oracle.

## 9. MAJOR — Production raster defaults exceed G10 before other editor memory is counted

Locations: `src/editor/open.c:77`, `src/editor/open.c:151`, `src/font/atlas_ascii_15.h:5`, `src/raster/raster.c:328`, `src/raster/raster.c:341`.

Main uses default maximum geometry of 360×300 cells. At the default 8×15-pixel font, the backend reserves **2880×4500** pixels.

The separate 32-bpp SHM framebuffer and server pixmap require:

```text
2 × 2880 × 4500 × 4 = 103,680,000 bytes
```

That exceeds A’s 87,000,000-byte hard G10 limit before grids, workers, journal, atlas, or driver overhead. Raster also faults in the entire SHM reservation. Benchmark configurations override these maxima to their viewport geometry, so they do not exercise main’s reservation.

**Fix:** derive backend pixel limits from the supported display/work-area and memory budget, independently of generous cell-metadata reservations. Add a production-default ownership census including SHM and native graphics allocations exactly once.

**Fix:** reserve a private writable cache/journal directory at setup. Try source-directory reflink where available, then use bounded streaming into private backing there, with a securely created/unlinked temporary fallback for unsupported O_TMPFILE. Test readable sources in nonwritable parents and unsupported temporary-file operations.

## 37. MAJOR — Savectl fuzzer rejects a valid staged reload

## 41. MAJOR — Drag capture survives tab closure and can reorder the wrong tab or stop the editor

Locations: `src/editor/paint.c:163`, `src/editor/paint.c:170`, `src/editor/buffers.c:297`, `src/editor/buffers.c:224`.

Tab drag capture stores an order index and is not cleared by closure/activation. That index can now name a different tab—or lie outside the shortened order.

**Fix:** associate capture with stable tab/buffer identity and cancel it when its owner closes or activation changes its coordinate/source context. Resolve a live order index before reordering. Test close/switch/IPC activity during pointer capture.
