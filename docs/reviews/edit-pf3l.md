Static review only: no builds, tests, Linux editor, or Windows executables were run. Windows API details below were checked against Microsoft documentation. The existing uncommitted change to `fuzz/savectl_fuzz.c` was inspected to distinguish the worktree from the reviewed commit and was left untouched.

The mapping ownership part of the swap is sound under the declared API lifetimes: `open_job` registers before prefetch/publication/any application read; an unpublished mapping can be unregistered without exposing its bytes. File/tree/snapshot/backing/source references retain the same `file_map`; only its final release retires the slot, waits for admitted handlers, unmaps, and closes the descriptor. A valid retained backing therefore cannot query a retired/reused slot. `file_backing_faulted` after the final release is an invalid object access, not a supported way to query historical fault state; Windows returning zero for a retired slot does not create a valid-reader regression here. Concurrent fault epochs use release increments and acquire loads, and stay sticky during the backing's lifetime. The OS implementation retains SIG_IGN/SIG_DFL classification, masks, SA_SIGINFO, SA_RESETHAND, SA_NODEFER, SA_ONSTACK, and SA_RESTART handling; deleting file_bus does not itself delete chaining. The remaining validation-to-rename race predates this change.

Linux inotify watch sharing, detach/refresh rules, bounded dispatch, and xattr removal/copy/error propagation were moved substantially unchanged. Canonical acquisition still uses realpath semantics; NOFOLLOW/NONBLOCK remain present, and OS opens retain CLOEXEC. The duplicated map descriptor now also gets CLOEXEC. Partial reads/writes still advance by actual transfer counts; premature EOF still rejects acquisition. Timestamp casts match §9.3 within the OS contract's representable range, POSIX type encodings remain compatible, and file's comparisons include both Windows file-index words. Prefix directory rejection and shrink-before-map classification implement §§9.1/9.2. The exceptions and remaining safety gaps are below.

1. **BLOCKER — Windows save temporaries expose document bytes under inherited permissions before the source ACL is installed.** `src/file/file.c:929`, `src/file/file.c:941`, `src/file/file.c:951`; `src/file/file_win.c:254`.

   OS_OPEN_CREATE inherits the Windows directory ACL. The entire document is written before metadata_apply copies the original's DACL. A document with a protected, restrictive DACL inside a directory readable by other users therefore gets a readable temporary containing its text. A crash before metadata_apply leaves that temporary behind indefinitely. If inherited permissions allow writing, another principal can also alter the save output before it is renamed over the original. Linux's initial mode 0600 avoids this exposure.

   **Fix:** create the Windows temporary with a restrictive explicit security descriptor atomically at creation, relative to the retained parent, before exposing its name or writing data. Implement that native creation in the platform helper if the frozen OS creation API cannot express it. Merely moving SetSecurityInfo before the first write leaves an empty-file-open race: a reader can retain the previously granted handle. Preserve the final source descriptor separately. Add a multi-chunk paused-save/crash test with a restrictive source ACL and a broader parent ACL, checking access from another token. Windows documents the default inheritance at [File security and access rights](https://learn.microsoft.com/en-us/windows/win32/fileio/file-security-and-access-rights).

2. **BLOCKER — Saving an individually EFS-encrypted document silently replaces it with plaintext.** `src/file/file_win.c:274`, `src/file/file_win.c:278`; `src/file/file.c:929`, `src/file/file.c:983`.

   The attribute mask deliberately excludes FILE_ATTRIBUTE_ENCRYPTED, and no encryption operation occurs. For an encrypted source in an unencrypted directory, the newly created temporary receives decrypted snapshot bytes and remains unencrypted when renamed into place. This both leaves plaintext during preparation and removes the original's at-rest protection on a successful save. Recording encryption as “not claimed” in the worker's decision does not make the successful destructive operation safe.

   **Fix:** at minimum inspect storage attributes during metadata capture and refuse an encrypted-source save before creating/writing a plaintext temporary. Full support must establish encryption before writing any bytes, preserve the appropriate encryption state, and verify it before replacement. Add an encrypted-file-in-plain-directory case and a preparation-crash case. Microsoft's [replacement semantics](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew) explicitly treat encryption as state to preserve; this is a requirement to handle or reject, not a suggestion to substitute ReplaceFileW for the pinned-directory transaction.

3. **MAJOR — Successful Windows saves discard all named streams of the original.** `src/file/file_win.c:248`, `src/file/file.c:938`, `src/file/file.c:983`.

   The transaction writes only the piece snapshot's unnamed stream and copies only owner/group/DACL and selected DOS attributes. An original with an application data stream or Zone.Identifier is replaced by an object without those streams; closing the old handles then destroys the retained old object. This is irreversible loss of file data and can also remove origin/security metadata. The explicit omission in the decision document has no runtime rejection protecting users.

   **Fix:** enumerate streams on the captured source object and copy supported named streams to the temporary with the same validation/failure policy as other metadata. Until supported, detect additional streams and fail before replacement. Test two independently named streams, byte equality after save, and a stream-copy failure leaving the original and its streams intact. Windows exposes stream enumeration through [FileStreamInfo](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getfileinformationbyhandleex), and [ReplaceFileW's documented preserved state](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew) includes named streams.

4. **MAJOR — The saved Windows identity is published before closing the handle that can finalize its timestamps.** `src/file/file.c:987`, `src/file/file.c:990`, `src/file/file.c:993`, `src/file/file.c:995`.

   Both stats of the replacement run while tx->fd is still open for writing. The replacement callback can publish that identity, and only afterwards does close occur. Windows guarantees finalized file times after the modifying handle closes; the code assumes the earlier sample is final. A filesystem that finalizes LastWriteTime on close can make the next file_check report the editor's own save as external, or make the next ordinary save fail its expected identity. This is a contract-level race inferred from the code, not an observed native test result. [Microsoft's file-time rules](https://learn.microsoft.com/en-us/windows/win32/sysinfo/file-times) document the close requirement.

   **Fix:** retain an independent non-writing attribute handle to the actual temporary/replacement, close the writer, stat through that retained handle, and only then publish the definitive replacement identity. Preserve the replaced-but-identity-unavailable error path and avoid reopening by pathname. Port the Linux round-trip assertions at `tests/file_test.c:430`: immediately check that our save is not a change, then edit and save again, in COPY and MMAP modes, with a delayed-close timestamp fixture.

5. **MAJOR — A shared OVERLAPPED event can lose a completion wake when another directory is armed.** `src/file/file_win.c:41`, `src/file/file_win.c:42`, `src/file/file_win.c:159`, `src/file/file_win.c:180`.

   Every outstanding ReadDirectoryChangesW request uses file_watches.event. Starting pending overlapped I/O resets its event, so rearming one parent can clear another parent's already completed notification. For example, dispatch scans pending parent A; A completes and signals; dispatch processes completed parent B and rearms B, clearing the shared event. A remains completed with no wake until some unrelated event causes another dispatch. Starting a new parent watch can likewise clear a previously signaled completion. The comment about resetting before observation does not cover these subsequent kernel resets.

   **Fix:** use distinct native completion events plus a correctly aggregated service wake, or an IO completion port drained by a notification service that signals the single UI wake. A smaller repair must prove/recheck all outstanding completion state after every arm/reset and preserve a level-triggered aggregate wake; checking only the request being rearmed is insufficient. Add deterministic two-directory tests for completion-during-rearm and adding a watch while another is completed. [ReadDirectoryChangesW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-readdirectorychangesw) requires a unique event for this completion technique, and [overlapped synchronization](https://learn.microsoft.com/en-us/windows/win32/sync/synchronization-and-overlapped-input-and-output) explains the reset behavior.

6. **MAJOR — UNPROTECTED_DACL_SECURITY_INFORMATION re-inherits permissions instead of guaranteeing an exact ACL copy.** `src/file/file_win.c:266`, `src/file/file_win.c:267`; `tests/file_win_cases.inc:153`.

   An unprotected source can retain inherited ACEs from a previous parent after a same-volume move. The temporary is created under the current parent. Applying the source DACL while explicitly requesting UNPROTECTED inheritance can replace/merge inherited ACEs from that current parent, producing different effective access from the source. The code never reads the resulting DACL back, and the only equality test first protects the source DACL, bypassing this branch. A successful save can therefore widen or narrow access.

   **Fix:** restore the captured effective descriptor through a handle-based path that does not request fresh inheritance, preserve the intended control state, and verify the resulting owner/group/ACL/control before replacement. Refuse the replacement if exact preservation cannot be achieved. Do not use a pathname-based restore that loses the parent pin. Add unprotected and moved-between-different-ACL-parent fixtures. [SECURITY_INFORMATION](https://learn.microsoft.com/en-us/windows/win32/secauthz/security-information) defines UNPROTECTED as inheriting from the parent; [file security rules](https://learn.microsoft.com/en-us/windows/win32/fileio/file-security-and-access-rights) explain that moving an existing object does not assign a new default descriptor.

7. **MAJOR — Every existing-file save unnecessarily requires WRITE_OWNER on its new temporary.** `src/file/file_win.c:253`, `src/file/file_win.c:260`, `src/file/file_win.c:267`.

   Owner/group are set unconditionally, even when the source and temporary already have identical SIDs. A normal directory ACL can grant Modify/create/delete without WRITE_OWNER. The creator can own the resulting temporary without its ACL granting that additional right; reopening it with the unconditional rights mask then fails, preventing saves that require no ownership change. This is stricter than the Linux helper, which calls fchown only when uid/gid differ.

   **Fix:** query the temporary's descriptor first, compare owner/group SIDs, and request WRITE_OWNER and set OWNER/GROUP_SECURITY_INFORMATION only for actual changes. Keep genuine preservation failures fatal. Add a non-elevated fixture whose inherited ACL grants ordinary file modification but excludes WRITE_OWNER, checking both the equal-owner success case and an actual ownership-preservation refusal. The [security-information rights table](https://learn.microsoft.com/en-us/windows/win32/secauthz/security-information) identifies the distinct rights required.

8. **MAJOR — The “security descriptor” copy omits mandatory integrity labels and other security state, not just audit policy.** `src/file/file_win.c:253`, `src/file/file_win.c:255`, `src/file/file_win.c:267`.

   Only owner/group/DACL are queried and installed. The mandatory integrity label lives in the SACL, so a source with an explicit label is replaced with the temporary's inherited/default label. For example, saving a low-integrity-writable document from a medium-integrity process can make it unwritable by its original consumer. The worker's exclusion of “SACL audit policy” does not account for this non-audit access-control state. Resource attributes and explicit auditing are likewise neither preserved nor rejected.

   **Fix:** include at least LABEL_SECURITY_INFORMATION in capture/restore and validation; this uses READ_CONTROL/WRITE_OWNER rather than requiring the privilege to copy the entire audit SACL. Define an explicit preserve-or-refuse policy for additional security state that cannot be safely copied, keeping it distinct from a new-file default. Add a differing-parent/source mandatory-label fixture and injected query/set failures. [Microsoft's SECURITY_INFORMATION table](https://learn.microsoft.com/en-us/windows/win32/secauthz/security-information) locates the integrity label in the SACL and gives its access requirements.

9. **MAJOR — Moving/replacing the watched parent leaves Windows members attached to the wrong directory indefinitely.** `src/file/file_win.c:42`, `src/file/file_win.c:94`, `src/file/file_win.c:118`, `src/file/file_win.c:206`.

   ReadDirectoryChangesW reports contents, not changes to the directory being watched. Renaming parent P away and creating a new P does not give this service Linux's IN_MOVE_SELF invalidation. Its still-armed handle follows the old directory; file_watch_start and path_start return early as though coverage remained valid. Changes to P/document in the replacement directory then produce no notices, including for path-only config members.

   **Fix:** add parent/ancestor name-lifetime observation or an explicit periodic/focus refresh that compares the current pathname's parent identity to the retained watch identity and invalidates/rebinds all affected members. Schedule identity checks when that relationship changes. Add the Windows equivalent of `tests/file_test.c:2047`, including a recreated parent and a path-only member. File's save-time and existing Linux focus identity checks still catch a changed target when invoked; they prevent some stale overwrites but do not repair continuous notification coverage or keep the displayed buffer/config current. See [ReadDirectoryChangesW's scope](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-readdirectorychangesw).

10. **MAJOR — The Windows watch cache can associate one directory's identity with a different directory's handle.** `src/file/file_win.c:101`, `src/file/file_win.c:102`, `src/file/file_win.c:106`, `src/file/file_win.c:107`.

    watch_parent obtains st.id from pinned directory A, derives a pathname, closes A, then opens that pathname with CreateFileW. A rename/replacement in that interval makes the native watch refer to B while parent->identity still says A. A later member opened through A's moved pathname finds the cached A identity and shares B's watch, so A's changes are silently missed. This is separate from notification of a correctly installed watch's later parent rename.

    **Fix:** retain the original pin while obtaining the overlapped directory handle by object, for example through an appropriate ReOpenFile/native relative reopen, and verify the final handle identity against st.id before publishing/cache lookup ownership. On mismatch retry boundedly or fail setup. Add a hook between final-name lookup and native open that moves A, replaces its old name with B, then starts members through both names.

11. **MAJOR — Temporary-name byte truncation makes valid Unicode Windows documents unsavable.** `src/file/file.c:927`, `src/file/file.c:928`.

    The inherited Linux `%.*s` truncation cuts the basename at FILE_NAME_MAX_KEEP bytes, not at a UTF-8 code-point boundary. A valid basename containing 33 three-byte characters followed by another such character has a character split at the 100-byte limit (33 × 3 = 99). The generated temporary is invalid UTF-8, so Windows's strict conversion rejects creation even though opening and editing the document succeeded. The existing short `copy-ä.txt` test cannot exercise this boundary.

    **Fix:** use an ASCII-only temporary prefix/nonce independent of the basename, or truncate at a validated UTF-8 boundary while retaining the native component-length budget. Add two-, three-, and four-byte boundary cases and a basename near the supported NTFS component limit. Preserve Linux's valid byte-name behavior.

12. **MAJOR — Acquisition no longer observes cancellation between interrupted read attempts.** `src/file/file.c:338`, `src/file/file.c:423`; dependency `src/os/os_posix.c:360`.

    Both old loops performed one pread and returned to work_should_stop after EINTR. os_file_pread now retries EINTR internally without observing the worker cancellation flag. Repeated interrupted reads can keep a cancelled acquisition worker running and make file_close wait indefinitely; the prefix comment still promises cancellation on repeated EINTR. The worker corrected exactly this migration issue for writes with pwrite_once but left reads using the retrying interface. Short successful transfers are handled correctly; the regression is the hidden interruption loop.

    **Fix:** supply a file-private single-attempt positioned-read helper in the platform implementation (POSIX pread, Windows's existing completed-transfer operation), and retry OS_E_INTR only in the cancellation-aware file loops. Record that adapter explicitly while keeping os.h frozen, or obtain a separately reviewed OS-contract extension before claiming equivalent cancellation. Add deterministic prefix and COPY-suffix tests that return repeated EINTR, cancel after an attempt, and require physical completion without a subsequent successful read.

13. **MAJOR — The committed API migration leaves the savectl fuzzer uncompilable; the worktree's local fix masks it.** `src/file/file.h:166`; committed `fuzz/savectl_fuzz.c:114`, `:230`, `:310`, `:343`.

    HEAD still passes struct stat pointers to file_id_from_stat, whose parameter is now const os_stat *. These are incompatible structures and compilation fails under the project's warnings-as-errors policy. The worker report says those callers were migrated, but `git diff main...HEAD` omits the fuzzer. The four necessary call-site edits exist only as the pre-existing uncommitted modification visible in git status.     **Fix:** include the fuzzer migration in the committed change, preserving the separate native stat used by the timestamp-restoration oracle. Build the fuzzer from a clean checkout of the final commit. Do not “fix” this by casting the pointer or weakening compiler warnings.

14. **MAJOR — The Windows suite drops portable file safety regressions instead of running them against the new implementation.** `tests/file_test.c:1`, `tests/file_win_cases.inc:311`, `tests/file_win_cases.inc:314`.

    The top-level platform conditional replaces the entire Linux suite with the new small Windows suite. Only directory/shrink acquisition cases are shared. The missing behavior is broader than the printed Linux-only skips: no late-fault save refusal, second fault after a FORCE acknowledgement, retained-original/two-save validation, compromised-MMAP Keep refusal, stale/undrained mailbox close, in-flight cancellation, or cancellation/short-write/metadata-failure cleanup matrix runs on Windows. These tests mostly concern shared file semantics and can use os_fault_test_trigger/os.h rather than real truncation. The notification test uses only one parent and does not force overflow, rename-over, parent rename, failed rearm, or concurrent completions. The protected-DACL-only round trip misses inheritance/rights/label cases. The crash test writes a single small span, so its MID_WRITE hook fires after that whole document is written, not during a multi-chunk save.

    **Fix:** extract portable ownership/save/change-detection cases into shared tests and use native fault delivery and self-reexec where needed. Add deterministic Windows API shims for the notification and metadata failure branches; verify original bytes/identity/descriptor and temporary cleanup after every refusal. Include repeated saves, multi-chunk cancellation/crash points, both identity words, negative-time conversion, no-allocation status/dispatch paths, and a lost-notification test that confirms authoritative focus/save checks still reject stale data. Keep real SIGBUS/action-mask and POSIX xattr tests as additional Linux coverage. Update the worker's acceptance claims to describe actual coverage.

15. **MINOR — A directory substitution during save metadata acquisition changed from CHANGED to IO on Linux.** `src/file/file.c:888`, `src/file/file.c:889`.

    metadata_capture first observes a regular target, then opens it. If it is replaced by a readable directory in between, the old O_RDONLY open succeeded and the subsequent fstat/identity comparison returned FILE_ERR_CHANGED. os_file_open_at now rejects directories with OS_E_ISDIR, and this branch converts every open failure into FILE_ERR_IO. Prefix acquisition handles §9.1, but this other affected call site does not preserve its prior classification. The target remains safe; the user receives the wrong failure category.

    **Fix:** handle OS_E_ISDIR here as FILE_ERR_CHANGED because the already captured regular entry changed. Keep genuine access/I/O failures as IO with their native code. Add a deterministic swap between os_stat_at and os_file_open_at; do not change this save race into the initial-open NOTREG result.

16. **MINOR — Windows name filtering ignores valid short-name notifications.** `src/file/file_win.c:134`, `src/file/file_win.c:148`, `src/file/file_win.c:171`, `src/file/file_win.c:178`.

    watch_matches compares only the requested/canonical basename. Windows may report either the long name or its 8.3 alias, so an otherwise successful completion can be discarded for both file and path-only members. This is a real notification gap even without overflow or parent replacement. Authoritative identity checks mitigate later saves/focus checks, but the live buffer/config notice can be missed. The API explicitly leaves this choice unspecified in [FILE_NOTIFY_INFORMATION](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-file_notify_information).

    **Fix:** capture and match both aliases during off-path watch setup, refresh alias state after relevant renames, or conservatively schedule a parent-wide identity check when a record cannot be safely attributed. Add a fixture with an actual short alias and feed both spellings through the dispatch parser.
