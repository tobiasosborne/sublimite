### 1. BLOCKER — The implemented recovery guarantee is weaker than the PRD and “replay == model” acceptance

**Locations:** [PRD.md:80](/home/tobias/Projects/editor/PRD.md:80), [docs/decisions/P1.9.md:139](/home/tobias/Projects/editor/docs/decisions/P1.9.md:139), [tests/journal_kill_test.c:90](/home/tobias/Projects/editor/tests/journal_kill_test.c:90).

The PRD requires “no data loss on crash.” The implementation permits losing accepted edits held in either RAM buffer, and sticky FULL permits an indefinitely growing gap between the UI contents and protected contents.

The kill test explicitly accepts any replay count within `[acknowledged, issued]`. It recomputes its expected model through **`actual.edits`**, rather than through `issued`. Consequently, an empty replay passes when edits were issued but none acknowledged.

**Reproducer:** Open a journal, mutate the UI buffer, successfully append one INSERT, and SIGKILL before pumping. Replay restores zero edits. The test’s acceptance predicate permits that outcome when `ack == 0`.

The per-record comparisons do provide useful evidence that recovered operations match a prefix of the seeded script. The final content comparison uses the same `operation()` routine for both models, and the kill test never applies records through `journal_apply_piece`.

**Fix:** Resolve the frozen contract explicitly: define crash scope, the protected commit point, and any permitted loss window. If the PRD remains unchanged, protect edits before reporting them as committed and require replay to equal that committed model. Exercise actual piece-tree recovery against a separately maintained byte model.

### 2. BLOCKER — Saving destroys the journal’s base before replacement recovery information is durable

**Locations:** [docs/decisions/P1.9.md:75](/home/tobias/Projects/editor/docs/decisions/P1.9.md:75), [src/journal/journal.c:164](/home/tobias/Projects/editor/src/journal/journal.c:164).

The prescribed order is durable file replacement, followed by journal checkpoint rotation. Between those operations, the journal references the old inode and contents, which the save has replaced. Replay returns `JOURNAL_BASE_CHANGED`; retained RAM snapshots disappear on crash.

This can strand **acknowledged post-save edits**, beyond the ordinary unsynced loss window.

**Concrete argument:** Start with `abcdef`; journal DELETE `(0,3)`, producing `def`. Save that snapshot. Later journal and durably acknowledge INSERT `X` at offset zero. Crash before checkpoint rotation. The disk contains `def`, while the journal still describes operations against `abcdef`. Applying both operations to `def` produces the wrong result, and ordinary replay refuses the changed base. The journal contains no save-sequence marker establishing which operations the saved file already includes.

**Fix:** Introduce a recoverable save transaction. Persist the save sequence, new base identity, and sufficient access to the preceding base before replacing it. Retain that base version until the new journal checkpoint and directory entry are durable. Recovery must select the appropriate generation and apply only its remaining deltas.

### 3. MAJOR — A worker write error drops the active batch from retry state and permanently blocks rotation

**Locations:** [src/journal/journal.c:351](/home/tobias/Projects/editor/src/journal/journal.c:351), [src/journal/journal.c:367](/home/tobias/Projects/editor/src/journal/journal.c:367), [src/journal/journal.c:387](/home/tobias/Projects/editor/src/journal/journal.c:387).

`journal_receive` clears `b->used` and `b->sealed` even when completion reports I/O failure. The accepted sequence still includes unwritten records. Flush immediately returns the sticky error, while rotation requires `accepted == durable`.

Thus the public API cannot retry the accepted batch or replace the failed journal with a complete checkpoint.

**Reproduced:** Inject EIO on the second `pwrite` of a 200,000-byte INSERT:

```text
append=JOURNAL_OK
flush=JOURNAL_IO
rotate=JOURNAL_BUSY
accepted=1 written=0 durable=0
```

**Fix:** Preserve failed-batch state and exact write progress until explicitly resolved. Provide safe retry or allow complete checkpoint replacement from a suspended I/O state after worker ownership has returned. Preserve the old recovery prefix if replacement fails.

### 4. MAJOR — Flush reports success while sticky FULL still means recovery is incomplete

**Locations:** [src/journal/journal.c:369](/home/tobias/Projects/editor/src/journal/journal.c:369), [docs/decisions/P1.9.md:145](/home/tobias/Projects/editor/docs/decisions/P1.9.md:145).

Flush returns OK once all **accepted** records are durable, regardless of sticky FULL and omitted UI edits. The decision document instructs clean exit to check the flush return before cleanup; that check alone cannot detect this incomplete recovery state.

**Reproduced:** Accept one maximum-sized default INSERT, refuse the next, then flush:

```text
first=JOURNAL_OK second=JOURNAL_FULL
flush=JOURNAL_OK sticky=JOURNAL_FULL
accepted=1 durable=1
```

**Fix:** After draining accepted records, return `JOURNAL_FULL` while suspension remains unresolved, or return an explicit result separating prefix durability from session completeness. Document and test the exit sequence: resolve suspension with a complete checkpoint, then confirm success before cleanup.

### 5. MAJOR — Splitting a 1 MB paste does not make it journalable on the typing path

**Locations:** [src/journal/journal.c:281](/home/tobias/Projects/editor/src/journal/journal.c:281), [docs/decisions/P1.9.md:40](/home/tobias/Projects/editor/docs/decisions/P1.9.md:40).

The documentation recommends splitting large pastes. With default options, however, all append calls use the same current buffer until a pump submits it. Appends cannot switch buffers, submit work, or wait.

The maximum default INSERT payload is 262,072 bytes. Its record occupies 262,112 bytes, leaving only the reserved PAD header. The next chunk immediately triggers sticky FULL, even with an otherwise idle worker and plenty of disk space.

**Reproduced:** Two consecutive INSERTs of 262,072 bytes return OK, then FULL. A decimal 1 MB paste cannot be fully queued by the documented splitting approach during one mutation.

**Fix:** Reserve capacity for a complete logical mutation before accepting any portion. Provide a preallocated large-operation or immutable-snapshot job path, with CRC work moved off the input slice where necessary. Test the G9 1 MB paste fixture and prove complete replay protection.

### 6. MAJOR — Large untitled buffers cannot recover from FULL through the advertised checkpoint mechanism

**Locations:** [src/journal/journal.c:264](/home/tobias/Projects/editor/src/journal/journal.c:264), [src/journal/journal.c:393](/home/tobias/Projects/editor/src/journal/journal.c:393), [docs/decisions/P1.9.md:130](/home/tobias/Projects/editor/docs/decisions/P1.9.md:130).

Default disk capacity is 64 MiB. Rotation inherits that same limit. An untitled buffer larger than the limit requires more than the limit merely to encode its content, before record headers, padding, and session state.

Once such a buffer reaches FULL, a complete checkpoint cannot clear suspension through this API—even after the worker catches up.

**Reproducer:** Incrementally build an untitled buffer exceeding 64 MiB. Attempt a complete empty-BASE-plus-INSERT checkpoint. Rotation returns FULL and leaves the previous incomplete journal.

**Fix:** Support durable content checkpoints outside the bounded operation log, or permit a safely rebuilt journal with an appropriately sized limit. Define and enforce any product limit before allowing edits that cannot be protected.

### 7. MAJOR — Persisted relative paths depend on the launch directory

**Locations:** [src/journal/journal.c:184](/home/tobias/Projects/editor/src/journal/journal.c:184), [src/journal/journal.c:268](/home/tobias/Projects/editor/src/journal/journal.c:268), [src/journal/journal.c:403](/home/tobias/Projects/editor/src/journal/journal.c:403).

Base capture retains the supplied path verbatim; BASE encoding persists it verbatim. Journal setup also retains a potentially relative pathname.

**Reproducer:** Capture `notes.txt` while launched in directory A, then restart from directory B. Replay checks B’s `notes.txt`, causing a false base conflict or missing-base error. Likewise, changing cwd after opening a relative journal makes rotation operate on a different pathname from its existing fd.

Neither public API documents an absolute-path precondition.

**Fix:** Resolve and store absolute base paths during capture/setup, with explicit storage ownership. Keep a stable parent-directory fd for journal operations and use `openat`/`renameat` plus directory fsync.

### 8. MAJOR — Crash tests do not exercise the durability and rotation failure boundaries

**Locations:** [tests/journal_kill_test.c:85](/home/tobias/Projects/editor/tests/journal_kill_test.c:85), [tests/journal_test.c:81](/home/tobias/Projects/editor/tests/journal_test.c:81), [tests/journal_test.c:116](/home/tobias/Projects/editor/tests/journal_test.c:116).

SIGKILL leaves the kernel and page cache alive. It cannot establish which bytes survive loss of unsynced storage state or whether rename survives without directory fsync.

The “torn page” tests truncate an already completed byte stream. Rotation tests cover success and an invalid record, without crashes or injected failures around its barriers.

Missing cases include:

- Short writes followed by EIO, failed `fdatasync`, and retry behavior.
- A record crossing the 64 KiB sync boundary, with only its synced prefix surviving.
- Creation-directory sync failure.
- Crashes before rename, after rename, and before directory fsync.
- Directory fsync failure after replacement.
- Save/checkpoint races involving post-save edits and multiple buffers.

**Fix:** Add deterministic syscall/phase fault injection with separate volatile and durable filesystem images. At every boundary, assert the surviving prefix, durable-sequence guarantee, old/new checkpoint selection, and subsequent API behavior. Retain SIGKILL trials as additional coverage.

### 9. MAJOR — Benchmark fixtures avoid default saturation and do not establish the required workloads

**Locations:** [bench/journal_bench.c:20](/home/tobias/Projects/editor/bench/journal_bench.c:20), [bench/journal_bench.c:27](/home/tobias/Projects/editor/bench/journal_bench.c:27), [perf/01-perf-target.md:54](/home/tobias/Projects/editor/perf/01-perf-target.md:54).

The 20 µs figure is the bead’s local append budget; it is not a separate §0.2 ship gate. These rows cannot establish G1 or G9.

| Row | Fixture and measurement limitation |
|---|---|
| Append 1 B | Forces blocking flush every 1,024 edits; excludes flush cost and avoids sustained queue pressure. |
| Append 1 KiB | Forces flush every 128 edits and raises disk capacity to 256 MiB. Its 102.4 MB text fixture exceeds the default 64 MiB limit. |
| Replay, both sizes | TRACK only. Uses contiguous inserts into an empty tree; no BASE loading, random edits, multiple buffers, or session restoration. Correctness checks count and length, without comparing recovered bytes. |
| Sync, both sizes | Forced flushes dominate cadence, so these rows do not establish ordinary timer-driven behavior under competing bulk work. |
| Idle sync | Covers one tiny append after fresh open; omits the zero-data sync path after an earlier unsynced write. |

The replay MB/s numerator is **wire bytes including headers and padding**. For one-byte inserts, record overhead alone makes this at least 41 times text payload volume; label it accordingly.

Final reported results are AC measurements. Earlier battery results predate the final implementation. No row exercises the specified competing index/find/save workload. The allocation test likewise allows FULL before all 10,000 appends succeed.

**Fix:** Print options and workload conditions per row. Add successful sustained appends using normal timer pumping, default-capacity exhaustion, 1 MB paste, complete-content verification, and competing bulk jobs. Report wire and payload throughput separately. Rerun final Target A measurements on battery; keep whole-editor G1/G9 validation explicit.

### 10. MINOR — Corruption tests permit silently dropping an extra valid prefix

**Locations:** [tests/journal_test.c:79](/home/tobias/Projects/editor/tests/journal_test.c:79), [tests/journal_test.c:83](/home/tobias/Projects/editor/tests/journal_test.c:83), [fuzz/journal_fuzz.c:91](/home/tobias/Projects/editor/fuzz/journal_fuzz.c:91).

Byte-flip tests assert `valid_bytes <= record_start`, rather than equality. Truncation tests assert only `valid_bytes <= n`, then compare file parsing against the same byte parser.

The fuzz corruption oracle recomputes its expected content through `broken.edits`, so it also permits rejection of an unnecessarily short prefix. A parser that consistently discards one extra intact record can satisfy these checks.

**Fix:** Maintain independent encoded record boundaries. For each mutation or truncation, assert the exact expected surviving byte boundary, sequence, operation count, and contents. Include cuts throughout the first page and across sync boundaries.

### 11. MINOR — Session-wide records accept nonzero buffer IDs

**Locations:** [src/journal/journal.c:100](/home/tobias/Projects/editor/src/journal/journal.c:100), [docs/decisions/P1.9.md:21](/home/tobias/Projects/editor/docs/decisions/P1.9.md:21).

The wire contract requires session-wide records to use buffer ID zero. Validation checks that restriction for PAD, but does not check TABS or WINDOW. Generic append also accepts them.

**Reproduced:** A CRC-valid WINDOW record with `buffer_id=99` is accepted, replayed with `corrupt=false`, and delivered to the callback unchanged.

**Fix:** Enforce zero IDs for TABS/WINDOW in writer and parser validation. Add CRC-repaired schema tests for these invalid records.

### 12. MINOR — Unreadable base data produces IO instead of the promised base conflict

**Locations:** [src/journal/journal.c:181](/home/tobias/Projects/editor/src/journal/journal.c:181), [docs/decisions/P1.9.md:66](/home/tobias/Projects/editor/docs/decisions/P1.9.md:66).

Open/stat failures become `JOURNAL_BASE_CHANGED`, but prefix-read errors propagate `JOURNAL_IO` through capture, check, and replay. The documented contract classifies unreadable bases as conflicts.

**Reproducer:** Let open and fstat succeed for a regular base, then inject EIO from its prefix `pread`. Replay returns IO instead of BASE_CHANGED, bypassing the documented conflict-handling branch.

**Fix:** Normalize base-read failures to BASE_CHANGED, preserving an auxiliary OS error if useful. Require the expected prefix length and test missing, unreadable, replaced, and concurrently changing bases separately.

### 13. MINOR — Valid journal filenames can make rotation impossible

**Location:** [src/journal/journal.c:389](/home/tobias/Projects/editor/src/journal/journal.c:389).

Rotation appends `.new-XXXXXX` to the original basename. On the current filesystem, `NAME_MAX` is 255. A valid 245-byte journal basename becomes a 256-byte temporary basename, so `mkstemp` fails. Long full paths encounter a similar expansion problem.

**Reproducer:** Successfully open a journal with a 245-byte basename, flush it, and rotate. Rotation returns IO despite a writable directory and sufficient space.

**Fix:** Create a short, independent temporary basename inside the retained parent directory, then rename it to the original basename.
