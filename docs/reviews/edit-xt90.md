# edit-xt90 — deep review

Reviewed `git diff main...HEAD` at `95da537`, the migrated journal sources, both OS implementations against the frozen `src/os/os.h`, the migration rules, journal decisions, worker reports, and Linux/Windows tests. Static review only: no test binaries or Windows executables were run. Findings explicitly labelled **inherited** also exist in the parent implementation; they are not attributed to this commit as new regressions.

1. **BLOCKER — an interrupted inventory can delete a still-referenced recovery BASE. Inherited safety defect retained by the iterator migration.** `src/journal/retire.c:46`, `src/journal/retire.c:390`, `src/journal/retire.c:397`, `src/journal/retire.c:465`.

   `listing_next` returns NULL for both EOF and an `os_dir_next` error. The main inventory loop never checks `dir->error` after termination. If enumeration returns a retained BASE and then fails before returning its referencing journal, `inv.uncertain` stays false. With that BASE larger than `JOURNAL_ARTIFACT_BYTES`, the retirement loop concludes that it is an unreferenced, over-budget artifact and unlinks it. Its actual referencing journal survives, but its original bytes do not. This is a direct recovery-data-loss sequence, without a concurrent writer or forged journal. An error during the preliminary count is likewise not reported, and the sweep passes can return success after incomplete enumeration. Only `legacy_owner_live` consumes the iterator error correctly.

   **Fix:** check the result of every complete enumeration before resetting it with `listing_rewind`. An incomplete reference inventory must set `inv.uncertain` and return IO, or abort retirement before any BASE deletion; preferably abort the entire destructive inventory pass. Propagate errors from the count and sweep passes too. Add an iterator fault seam that yields an over-budget BASE, then fails before its referencing journal, and assert both files remain byte-for-byte intact. The old unchecked `readdir` loops had the same flaw; replacing them with an explicit error-returning API has not fixed it.

2. **BLOCKER — the directory lock and the directory being inspected/deleted can be different objects. Inherited safety defect left in the directory-relative migration.** `src/journal/retire.c:323`, `src/journal/retire.c:330`, `src/journal/retire.c:334`, `src/journal/retire.c:427`, `src/journal/retire.c:456`; related writer path: `src/journal/journal.c:1125`, `src/journal/journal.c:1130`, `src/journal/journal.c:1137`.

   Retirement pins and exclusively locks directory A, and enumerates A, but constructs `canonical/name` and then uses path-based stat, lease creation, journal scanning, rename and unlink. Rename A away and put directory B at its former pathname: these operations now select B, while the identity-keyed guard still protects A. A concrete loss case is A enumerating a BASE basename also present in B, while B's referencing journal has a different basename absent from A. Retirement stats B's BASE, never inventories B's reference, and can rename/unlink that live BASE under budget pressure. Held/named checks do not rescue this: both pathname checks select B, and the BASE branch does not acquire a session lease. The `os_dir_sync` calls then concern A rather than the directory actually mutated.

   The async copy has the same broken correspondence: it opens/locks a parent object, then `journal_temp`, promotion, recapture, synchronization and cleanup resolve full paths again. Replacing the parent pathname after lock acquisition lets a copy be created in B under A's shared guard; B's sweeper can remove a live staging file. Windows' identity-keyed directory locks intentionally retain A's identity after a rename, so they do not serialize these operations on B.

   **Fix:** retain artifact leaf names and perform metadata, lease, scan-open, rename, unlink and barriers through the same pinned `os_dir`. Reuse `journal_scan_open` for retirement, as acknowledgment already does. Give retention a directory-relative exclusive-temp helper and use the guard's directory for promotion/cleanup. Before persisting an absolute BASE path, verify that its parent pathname still denotes the pinned directory; refuse conservatively if that cannot be established. Add a deterministic parent-rename/replacement fixture with two directory identities and a live referenced BASE in the replacement. This weakness predates the bead, but the claimed pinned-parent guarantee remains unfulfilled.

3. **MAJOR — UI appends and worker flushes share a synchronous Windows file object.** `src/journal/journal.c:433`, `src/journal/journal.c:455`, `src/journal/journal.c:595`.

   Both threads use `j->disk.fd`. The frozen Windows contract uses synchronous file objects and explicitly states that positioned transfers on the same object serialize. Thus a UI append can queue behind the worker's repair write; the worker also calls `FlushFileBuffers` on that same synchronous object. Moving the flush to a worker does not isolate the typing thread from that object's synchronous I/O serialization. The general header rule also does not grant unrestricted concurrent sync/transfer use of one handle. A stalled durability operation can therefore stall the next keystroke at its one supposedly bounded append attempt. This is an additional Windows coupling, beyond the already documented general possibility of a regular-file write stalling. The allocation tests establish no-malloc behavior, not independence from a worker's synchronous I/O.

   **Fix:** give the worker an independently opened writable file object for repair writes and synchronization, opened and identity-checked while the generation's name is pinned. `os_file_dup` is insufficient: its Windows duplicates share the file object. Carry both handles through rotation and close them only after their jobs finish. This removes avoidable file-object serialization, not every possible filesystem/device stall. Verify that a fence on the worker's writable handle covers the UI's completed writes to the same stream. Add a native contention/stall regression that exercises actual synchronous-object I/O, rather than merely sleeping in a hook before entering the OS call. This is a static inference from the chosen handle model, not a measured latency result.

4. **MAJOR — Windows rotation budgets ASCII temp names against a UTF-8 buffer bound, breaking valid journal names and sole-copy set-asides.** `src/journal/journal.c:902`, `src/journal/journal.c:903`, `src/journal/journal.c:943`; consequence at `src/journal/retire.c:241`.

   `OS_NAME_MAX` is storage for the UTF-8 encoding of an NTFS component, not permission to create that many ASCII characters. On Windows `tmpname` has that larger capacity, and the decision to use the short historical fallback is based on this capacity. All generated temp characters, including the hex-encoded owner, are ASCII and each consumes one UTF-16 unit. For example, even the minimal schema prefix `.sublimite-journal-+from-1-1-1-1-1-1-0-` has (P) 39 characters; a valid (P) 128-character ASCII owner produces at least `39 + 2 * 128 = 295` temp characters, exceeding NTFS's (P) 255-unit component limit. The code does not choose its short fallback, so rotation fails with IO for a valid journal basename. Shorter temp names can fit creation but leave insufficient actual component space for `.set-aside-<time>`, despite the purported reservation. A failed/missing original's possible sole checkpoint then cannot be moved to its supported set-aside spelling.

   **Fix:** budget generated ASCII names, including the reserved aside suffix, against the actual component-unit limit. The existing Linux-sized ASCII budget suffices for these generated names on NTFS; keep a larger buffer only where decoding arbitrary UTF-8 names needs it. Select the short fallback before opening when the entire future name does not fit. Port the maximal-basename rotation test and add a temp-near-limit crash/set-aside case. Existing Windows fixtures use short owner names and cannot detect this.

5. **MAJOR — the new Windows death tests do not validate torn transports, publication failure states, or the retained-BASE save transaction.** `tests/journal_hot_exit_test.c:23`, `tests/journal_hot_exit_test.c:69`, `tests/journal_hot_exit_test.c:78`, `tests/journal_hot_exit_test.c:152`, `tests/win/journal_kill_test.c:49`, `tests/journal_os_test.c:149`, `mk/win.mk:94`.

   The rotation death seam parks before performing rename, after the temporary has been fully flushed. It never kills after replacement, after adoption/before old-handle close, or during cleanup. Its failed-original case covers append failure, not a consumed worker writeback failure. The copy death case parks after one complete chunk, and the random campaign uses tiny edit records; neither deliberately supplies a torn large record or damaged COMMIT. The portable retention test exercises async copy and manual replay, but never calls `journal_save_prepare`, `journal_save_finish` or `journal_save_cancel`. These journal-only APIs therefore have no Windows transaction/failure oracle despite being central to preserving the pre-save original.

   Linux has materially stronger independent coverage in `tests/journal_test.c:332` (durable-image/barrier failures), `:852` (retained-copy faults), `:1314` (exact torn prefixes), `:1358` (consumed writeback loss) and `tests/journal_group_test.c:129` (all byte cuts and corrupt COMMIT). Skipping editor-dependent portions does not require skipping those journal-only cases. Likewise, every normal `os_file_open` in the new tests shares deletion, so the suite does not exercise a second process opening a target without `FILE_SHARE_DELETE`, or a legacy delete-pending name. The currently safe-looking refusal/old-generation behavior is untested at the journal boundary.

   **Fix:** extract the Linux journal-only oracles into portable suites, including worker short writes/zero/error, failed full/data sync, exact file truncation after corruption, retained-BASE prepare/finish/cancel, failed and ambiguous replacement, and every relevant publication death boundary. Add Windows-native fixture helpers for sharing-denial and delete-pending states; assert source/target identities, old-handle bytes, retry behavior, no-clobber set-asides and lock release only after death/last duplicate close. Native fixture setup is appropriate in `tests/win` even where frozen `os.h` intentionally has no such API.

   Keep the oracle's durability claims precise: append success establishes the kernel/cache boundary; successful writable-handle `os_file_sync_data` establishes the file-data/size fence; a completed rename establishes the process-visible name. `TerminateProcess` leaves the kernel alive and cannot prove survival of power loss or a torn disk write. Windows' directory-sync no-op is an explicitly accepted namespace-durability gap, not a missing Linux fsync to invent here.

6. **MAJOR — Windows coverage drops session metadata and does not test preservation/clearing of the PAINT guard through checkpoints.** `tests/win/journal_kill_test.c:44`, `tests/win/journal_kill_test.c:63`, `tests/win/journal_kill_test.c:97`, `tests/journal_hot_exit_test.c:83`, `tests/journal_hot_exit_test.c:167`.

   The Linux kill campaign writes VIEW, ordered TABS/active index and WINDOW before edits and validates every field on replay (`tests/journal_kill_test.c:43`, `:95`, `:245`), including a separate legacy WINDOW check. The Windows replacement omits those records and checks only edits. It therefore does not preserve the Linux campaign's hot-exit session oracle. Its PAINT case merely appends PAINT(1) and checks that one callback saw it. It never checks PAINT(0), last-marker-wins behavior, pending PAINT carried by a checkpoint, a torn marker, or restart behavior that preserves text while closing the implicated tab. Passing that case is evidence for transporting one record, not for the crash-loop guard.

   **Fix:** restore the metadata prelude and exact field assertions in the Windows campaign. Add independent fixed wire fixtures for legacy/current BASE, SAVE, VIEW, TABS, WINDOW, groups and PAINT, and compare emitted checkpoint bytes/CRC/PAD with the fixtures instead of relying solely on an encoder-to-parser round trip. Add journal-only PAINT append/clear/rotate/torn-tail tests now; keep the actual first-paint/restart/closed-tab integration explicitly pending the editor port. The save-worker checkpoint omission is already a documented `edit-dzk1` limit; do not misclassify it as a new regression or claim this test resolves it.

7. **MINOR — directory errors for writable journal opens change on Linux.** `src/journal/journal.c:534`, `src/journal/journal.c:548`; new expectation at `tests/journal_os_test.c:59`.

   The old `journal_open_with_io` and `journal_open_checkpoint` used `open(..., O_RDWR, ...)`. On Linux, opening a directory this way fails with EISDIR, so the old `fd < 0` branch returned JOURNAL_IO. Both new branches special-case OS_E_ISDIR to JOURNAL_INVALID. This is a real module-visible return-code change; the new test fixes the new behavior as the expectation instead of demonstrating old/new equivalence. The migration rule for a successful read-only directory open followed by nonregular classification does apply to manual replay's target and acknowledgment, but does not describe these failed writable opens.

   **Fix:** preserve JOURNAL_IO for OS_E_ISDIR at these writable-open sites, or explicitly approve/document the compatibility change. Add separate old-behavior regressions for `journal_open`, `journal_open_checkpoint`, manual target and acknowledgment, because their former open modes and classifications differ.

8. **MINOR — editing the included crash suite does not rebuild the Windows kill executable.** `tests/win/journal_kill_test.c:7`, `mk/win.mk:65`, `mk/win.mk:71`; analogous inclusion at `tests/win/journal_ack_test.c:9`.

   The Windows link rules list the top-level test source, module objects and manifest as prerequisites, but do not generate dependency files for the test translation unit. `journal_kill_test.c` textually includes `tests/journal_hot_exit_test.c`; changing only the latter leaves both existing Windows kill executables up to date, so `make TARGET=win check` can report green while running the previous crash assertions. The embedded acknowledgment CLI similarly lacks its `tools/journal_replay.c` dependency.

   **Fix:** add explicit prerequisites for these included sources to both release/sanitizer executables, or generate and include dependency files for test compilation. Verify the build graph schedules relinking after an included fixture changes.

9. **MINOR — clone EINTR retries lose the old cancellation checkpoint on Linux.** `src/journal/journal.c:1049`; frozen wrapper implementation: `src/os/os_posix.c:421`.

   The old FICLONE loop retried EINTR only while `!work_should_stop(ctx)`. The replacement `os_file_clone` retries EINTR internally without access to that cancellation state. A cancellation arriving during an interrupted clone no longer escapes at the next interruption; continued interruptions can keep a cancelled retention job retrying, delaying its cleanup and a caller waiting for completion. The worker inventory's statement that the clone migration keeps cancellation is therefore too strong. This is separate from the unchanged fact that cancellation cannot bound one uninterruptible filesystem operation.

   **Fix:** preserve cancellable retention with the existing chunked-copy path when the opaque clone retry cannot meet that requirement, or explicitly settle an OS-layer single-attempt/cancellable-clone extension before retaining this optimization. A check only after `os_file_clone` returns does not restore the old interruption checkpoint. Add a Linux interrupted-clone/cancel fault case and document which frozen-wrapper retry changes are intentional.

The remaining mechanical changes checked here appear faithful: `cache_write` makes one production `os_file_pwrite_once` attempt, captures native error before another OS operation, retains short-write progress and enters sticky IO; worker transfers still loop over short results. Existing RDWR journal/copy/temp handles supply data/full-file fences. The Linux creation, rotation, retry, retained-copy, retirement and acknowledgment directory barriers remain present. Replacing ordinary calls with the frozen wrappers adopts their EINTR-retry policy; closes still do not retry, and clone failure still takes the bounded-copy fallback. Finding 9 identifies the cancellation exception to treating this as behavior-neutral. Temp EXCL flags retain the old mkstemp/exclusive-open behavior rather than adding READ to an old write-only journal temp. The rotation guard spans temp creation through cleanup, its separately opened directory does not upgrade a lock, and the Linux lease adapters preserve the editor's existing descriptor ownership/dup handoff. No newly introduced C-heap allocation was found in production append/encoding; the stdio close bridge allocates only during manual recovery. Under the frozen rename/delete contract, a third-party sharing denial makes rotation fail before adoption; the identity recheck only adopts a replacement that actually became the named inode. NOREPLACE sweeps do not intentionally overwrite a set-aside. These paths still need the Windows failure tests in finding 5. Wire field encoding is unchanged for existing representable Linux identities/timestamps; the findings about format concern missing independent Windows validation.

Fix order:

1. Prevent incomplete inventories and directory-identity mismatches from authorizing deletion (findings 1–2).
2. Fix Windows temp/aside component budgets and separate the worker's synchronous file object from UI append I/O (4, 3).
3. Bring over the journal-only durability, torn-record, save-transaction, sharing-failure, metadata and PAINT oracles before treating Windows coverage as equivalent (5–6).
4. Restore or explicitly document Linux return-code/cancellation compatibility and fix test rebuild dependencies (7–9).
