1. **MAJOR — The single-instance mutex becomes visible before the server is connectable.**  
   **Location:** `src/ipc/ipc_win.c:397`; related `src/ipc/ipc_win.c:169`.  
   Startup A creates the mutex and is descheduled before creating its first pipe. Startup B opens that mutex, returns IPC_EXISTS, and immediately attempts handoff. CreateFileW finds no pipe; the client returns IPC_IO without using its remaining deadline. The second file-open request is lost. A failing between mutex creation and pipe/thread setup gives the same false incumbent result. The existing duplicate-server test starts its competitor only after successful initialization. Mutex existence gives exclusion, but it does not publish readiness or prove a live owner; this mutex is never acquired. Microsoft's [CreateMutex contract](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-createmutexw) confirms the distinction.
   
   **Fix:** Implement bounded startup arbitration with readiness and abandonment recovery. A contender must wait for the winner to publish a usable listener, or take over after failed startup, before reporting IPC_EXISTS. Preserve an absolute client deadline while retrying the startup-only missing-name interval; WaitNamedPipe alone cannot bridge it because it returns immediately when no instances exist, as its [contract specifies](https://learn.microsoft.com/en-us/windows/win32/api/namedpipeapi/nf-namedpipeapi-waitnamedpipew). Add a barrier after mutex creation and race independent processes, including failure of the winning initializer.

2. **MAJOR — A crashed server can leave its pipe name occupied through a surviving client handle.**  
   **Location:** `src/ipc/ipc_win.c:254`; classification at `src/ipc/ipc_win.c:401`; test gap at `tests/win/ipc_transport_test.c:123`.  
   The first listener always requests FILE_FLAG_FIRST_PIPE_INSTANCE. After a crash, a client which retains its old handle can retain the pipe instance/name even though there is no server. A replacement initializer creates a fresh mutex, fails first-instance creation, and converts access denied into IPC_EXISTS. Handoff then cannot reach a listener. A paused or non-reading client can prevent restart indefinitely; ordinary waiting clients also create a restart race before they consume the failure and close. The kill test connects no client, so it cannot establish the report's broad crash-cleanup claim. The documented rules are that an instance is deleted at its [last handle close](https://learn.microsoft.com/en-us/windows/win32/devnotes/nt-create-named-pipe-file), and [first-instance creation fails for an existing pipe](https://learn.microsoft.com/en-us/windows/win32/api/namedpipeapi/nf-namedpipeapi-createnamedpipew).
   
   **Fix:** Under real exclusive arbitration, distinguish a live server from orphaned client-held instances and allow a new server instance for an authenticated, compatible orphaned pipe. Alternatively, publish a generation-specific pipe through an authenticated per-user rendezvous. Do not remove first-instance protection without authenticating the existing object and excluding another live server. Retain a raw client handle across killing the server and verify successful rebind and new handoff before closing that handle.

3. **MAJOR — The Windows launcher channel cannot cross the required process boundary through the frozen process API.**  
   **Location:** `src/ipc/ipc_win.c:507`; related `src/ipc/ipc_win.c:516`, `tests/win/ipc_win_test.c:20`.  
   The launcher exports process-local CRT descriptor numbers, wraps both handles with _O_NOINHERIT, and exposes no named reconnect/export operation. os_proc_spawn deliberately passes only standard streams, per os.h and decision §3.9. Neither passing these integers in argv nor relaxing _O_NOINHERIT transfers an endpoint into the UI process. The launcher tests use another thread in the same process, where the descriptor table is shared, so they do not test Linux-equivalent launcher/UI ownership or server death. W2.4's main implementation is explicitly deferred, but these primitives currently lack the transfer mechanism that implementation needs.
   
   **Fix:** Define and implement the cross-process launcher handoff in IPC: for example, an authenticated random named endpoint and nonce passed in argv, with the child reconnecting and adopting its own handle. Keep arbitrary handle inheritance disabled. Add self-reexecuted parent/UI tests for close success, UI death, launcher death, primary ownership, and --new-instance --wait. Coordinate the API with W2.4 rather than treating the thread fixture as verification of process handoff.

4. **MAJOR — Invalid CRT descriptors can terminate the process instead of returning an IPC error.**  
   **Location:** `src/ipc/args.c:249`; also `src/ipc/ipc_win.c:519` and `src/ipc/ipc_win.c:543`.  
   The code checks the return values of _setmode and _get_osfhandle as if those calls always return on an invalid descriptor. UCRT invokes its invalid-parameter handler first; the default handler terminates the application. A closed nonnegative launcher descriptor, or an invalid stdin descriptor, therefore bypasses IPC_IO/IPC_INVALID. Linux returns an error for these inputs. These are direct UCRT imports in this toolchain. See [_get_osfhandle](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/get-osfhandle?view=msvc-170), [_setmode](https://learn.microsoft.com/en-gb/cpp/c-runtime-library/reference/setmode), and [parameter validation](https://learn.microsoft.com/en-us/cpp/c-runtime-library/parameter-validation?view=msvc-170).
   
   **Fix:** Guard recoverable CRT descriptor operations with a scoped thread-local invalid-parameter handler, restoring the previous handler on every exit, or replace the descriptor boundary with validated native handles. Do not install a process-wide handler/global. Test negative, closed and out-of-range descriptors in child processes and require normal error returns. Cover stdin mode restoration after read failure and IPC_LIMIT as well as success.

5. **MAJOR — Client connections grant an unnecessary impersonation capability to the server.**  
   **Location:** `src/ipc/ipc_win.c:166`; also the launcher client at `src/ipc/ipc_win.c:500`.  
   CreateFileW supplies FILE_FLAG_OVERLAPPED without SECURITY_SQOS_PRESENT and a restricted impersonation level. The default permits SecurityImpersonation. The later own_peer check verifies only the account SID, so a lower-privilege process of the same account can impersonate the endpoint and receive a request from an elevated CLI. The security consequence is an inference from the API: after reading that request, such a server can obtain the client's stronger security context. Checking SID before sending protects against a foreign SID; it does not remove this same-account capability. Microsoft documents the [default and client-side control](https://learn.microsoft.com/en-us/windows/win32/ipc/impersonating-a-named-pipe-client).
   
   **Fix:** Use SECURITY_SQOS_PRESENT | SECURITY_IDENTIFICATION, or SECURITY_ANONYMOUS if no identification is needed, on every pipe-client open. This protocol needs no server impersonation. Add a test server which attempts impersonation and verifies it cannot act with the client's privileges.

6. **MAJOR — The launcher pipe omits the user-only security descriptor.**  
   **Location:** `src/ipc/ipc_win.c:497`.  
   The primary pipe passes the protected SID DACL; the launcher passes NULL security attributes. The [default named-pipe descriptor](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights) includes read access for Everyone and anonymous users. Another local, unprivileged user can request a read-only client connection during the interval before line 500, consume the sole instance, and make launcher setup fail. The random suffix reduces guessing but does not make the object's access policy user-only. PIPE_REJECT_REMOTE_CLIENTS is present and does not exclude another local account.
   
   **Fix:** Construct the launcher with the same protected current-user SID descriptor and non-inheritable handles as the main transport; authenticate its peer during the cross-process handoff. Verify that a foreign unprivileged token is denied both read-only and duplex access, and inspect the actual descriptor rather than relying solely on the post-connect SID check.

7. **MAJOR — Trailing request bytes race the UI callback and do not receive the Unix protocol rejection.**  
   **Location:** `src/ipc/ipc_win.c:308`; related `src/ipc/ipc_win.c:299` and `src/ipc/ipc_win.c:446`.  
   On receiving the declared length, the service immediately publishes READY and signals the UI, then starts a one-byte read into extra. If the sender wrote a valid frame plus another byte, UI drain can win the mutex before the extra read's completion packet is processed and invoke the open callback for malformed input. If the service wins, read_complete simply drops a READY peer, giving IPC_IO rather than an EDIR/A/IPC_PROTOCOL reply. The Unix implementation checks MSG_PEEK before invoking the callback (`src/ipc/ipc_posix.c:297`). Byte-mode pipes are the right transport for the existing stream format, but completion of the declared payload alone is not equivalent framing validation.
   
   **Fix:** Check already-buffered trailing data on the service thread before publishing READY, using a nonblocking check on the overlapped handle, and reject it with the existing protocol reply before any callback. Monitor later extra data/disconnects separately. Add raw-peer tests for a valid frame plus garbage or a second frame in one write, and deliberately pause completion processing while the UI drains; require no callback and IPC_PROTOCOL for the already-buffered trailer.

8. **MAJOR — Linux reload now requires directory read permission that the old anonymous-file creation did not require.**  
   **Location:** `src/savectl/savectl.c:196`; implementation boundary at `src/os/os_posix.c:469`.  
   Previously the source-parent attempt was open(parent, O_TMPFILE | O_RDWR, 0600), which needs search/create access to the directory. It is now preceded by os_dir_open, which opens the directory O_RDONLY | O_DIRECTORY and additionally needs read permission. With a write/search-only source parent, this silently abandons a previously usable source-filesystem backing and switches to the cache. If the configured cache is readable but unwritable, a supported reload becomes FILE_ERR_IO; even with a writable cache this can lose the source-volume clone path and introduce a full copy.
   
   **Fix:** Preserve anonymous creation through a directory reference that can be acquired with search permission, with the necessary support inside the POSIX OS implementation. An O_PATH-backed reference for this operation must retain correct sync/lock behavior for other directory users; do not put raw POSIX calls back into savectl. Add an unprivileged regression using a writable/searchable, unreadable source directory and a readable, unwritable cache, comparing the old and migrated result.

9. **MAJOR — Exclusive temporary creation can now fail after creating the name, leaving a reload temporary behind.**  
   **Location:** `src/savectl/savectl.c:159`; underlying new failure edge at `src/os/os_posix.c:287`.  
   os_file_open_at invokes finish_open, which performs an additional fstat after successful openat. If that metadata query fails, finish_open closes the newly created file and returns an error. private_reload_backing then returns at line 161 without unlinking its name. The old direct openat had no such post-creation failure edge: successful creation reached unlinkat. The Windows exclusive open also has post-create metadata/reparse checks that need the same ownership audit. Cleanup cannot infer “no file was created” from an OS open error. Separately, the explicit unlink-failure branch at line 163 still leaves a named artifact after closing; that part is inherited from the old implementation.
   
   **Fix:** Make exclusive creation preserve ownership across post-create failures and clean up the created object safely in the OS layer. On POSIX, avoid the redundant directory-classification fstat for a guaranteed newly created regular file where possible. Do not unconditionally unlink after a failed open: EEXIST names somebody else's object. Keep an explicit cleanup obligation if unlink itself fails. Force anonymous-open refusal, inject failure of the post-create fstat, and verify no owned reload name remains; also exercise unlink failure and preserve pre-existing colliding files.

11. **MAJOR — The controller discards half of the Windows file identity.**  
    **Location:** `src/savectl/savectl.c:104`; matching test adapter at `tests/win/savectl_fixture.h:34`.  
    identity copies volume and index[0], dropping index[1] from os.h's 128-bit identity. Distinct objects with equal low halves can consequently compare as the same object when other compared metadata matches. The fixture repeats that reduction, so it cannot catch disagreement with W2.1 or a high-half-only identity change. The decision document acknowledges this merge boundary; it remains required integration work, not a verified property of the current Windows reload tests.
    
    **Fix:** Use W2.1's shared conversion and final identity representation throughout controller baselines, descriptor/path comparisons and source validation, retaining both index words. Update the test adapter from that contract rather than duplicating a private conversion. Inject identities differing only in index[1] and require a changed-source refusal; run controller tests against the production converter at integration.

12. **MINOR — The wire validator accepts Windows root-relative paths as absolute.**  
    **Location:** `src/ipc/wire.c:24`.  
    The unconditional p[0] == '/' alternative admits /file on Windows even though os_path_is_absolute("/file") is false there. Such a path is rooted on the receiving process's current drive, so a direct public encoder caller or raw pipe peer can select a different file from the sender's intended drive. Normal Windows argument parsing rejects this spelling, making the parser and wire contracts inconsistent. Linux's slash rule remains correct.
    
    **Fix:** Use os_path_is_absolute as the platform-specific test, retaining Linux's existing acceptance through its implementation. Add Windows encode/decode cases for drive roots, UNC roots, root-relative /file and \file, drive-relative C:file, and valid non-ASCII absolute paths.

13. **MINOR — A UNC-resolving prefix can defeat the trailing-directory-separator check.**  
    **Location:** `src/ipc/args.c:85`; root changes at `src/ipc/args.c:77`.  
    root is overwritten with the root length of the resolved output, but the final check compares it against strlen(full), the length of the original input. A short drive path through a directory symlink to a long UNC share can produce a root longer than the complete original spelling. For an input such as C:/j/file/ resolving to a regular file under that share, strlen(full) > root is false and the parser accepts the forbidden trailing slash. Missing paths with a trailing slash have the same skipped check.
    
    **Fix:** Record whether the original input ends in a separator independently of the resolved root, and enforce the directory requirement using that fact. Test an existing regular file and a missing leaf through a drive-to-UNC directory symlink, with a share root longer than the input.

14. **MINOR — Linux reload compares differently encoded timestamps outside os.h's signed-nanosecond range.**  
    **Location:** `src/savectl/savectl.c:105`; comparison at `src/savectl/savectl.c:183`.  
    The descriptor identity now uses saturated os_stat timestamps, but disk_id still calls this tree's file_id_stat_path/file_id_from_stat, which encodes native timestamps with unsigned arithmetic (`src/file/file.c:654`). For a filesystem-supported mtime outside the signed range, such as year 2500, an unchanged file compares unequal and reload is rejected as changed. Ordinary in-range and pre-epoch timestamps retain their former encoding. This is another concrete Linux behavior change pending alignment with W2.1.
    
    **Fix:** Compare descriptor and path metadata through one consistent conversion, including the saturation policy, while preserving the correct identity installed as the baseline. Remove the private conversion when the shared converter lands. Add a Linux fixture with a supported out-of-range timestamp and verify an unchanged file can reload; explicitly handle filesystems that cannot represent that fixture.

16. **MINOR — Windows IPC tests omit several security, identity, capacity and Unicode contracts.**  
    **Location:** `tests/win/ipc_win_test.c:86`; test dispatch at `tests/win/ipc_transport_test.c:150`.  
    The cross-process request uses an ASCII filename manufactured inside the child; it does not carry a non-ASCII filename through argv, parsing and the pipe. Tests do not inspect the primary pipe DACL/remote-rejection mode, exercise a foreign token, vary LOCALAPPDATA while retaining the SID, cover runtime/display namespace separation and bounds, or fill the complete wait-client table. They also do not force pending read/write cancellation during teardown or fully occupied listeners through client connection timeouts. Those are independent gaps beyond the startup/crash/launcher tests specified above.
    
    **Fix:** Add self-reexecuted clients with UTF-8 names, spaces, quotes and backslashes, asserting exact received path bytes and coordinates. Add descriptor/access checks for both pipe kinds, SID-versus-environment endpoint tests, namespace tests, full wait-token admission/retirement and idle eviction, and deterministic overlapped cancellation tests. Exercise finite/zero/infinite connect deadlines with busy listeners and the separate unbounded post-ACK close wait. Use the existing IPC limits and deadlines rather than inventing timing gates.

Other requested checks: `ipc_posix.c` is exactly `main:src/ipc/socket.c` with the platform guard and an extra blank line; its transport body is unchanged. Linux args retain their old parser, os_cwd wraps getcwd, and the wire absolute-path test is equivalent on Linux. The reload fallback retains CREATE | EXCL | NOFOLLOW | RDWR and mode 0600; these are readable reload backings, distinct from the file module's write-only save temporaries. Positive partial pread/pwrite transfers advance the right offsets, clone failure retains copy fallback, randomness comes from os_random, and collision retries do not unlink EEXIST entries. The cleanup exceptions are finding 9.

The actual Linux save transaction remains in unchanged file.c: its temporary is O_WRONLY | O_CREAT | O_EXCL, metadata and data are flushed through that write descriptor before rename, and the pinned parent is synced after rename. Savectl's finish/cancel parent barriers retain their order; Windows directory sync is the frozen no-op. This change adds no read-only file flush and no target-sharing retry. The primary Windows endpoint derives names and its protected DACL from the process-token SID, not LOCALAPPDATA; both pipe constructors reject remote clients. IOCP waits occur outside the service/UI mutex, wake is drained before shared state is consumed, pending peer storage survives cancellation packets, and the accepted --wait client uses an unlimited close deadline. No new production global or typing-path heap allocation was identified. These static checks do not substitute for finding 10's missing native save/journal integration.

Fix first, in order:

1. Repair startup arbitration and recovery with a live client retaining a crashed server's pipe; cover both with deterministic process races.
2. Implement a real cross-process launcher handoff, restrict both pipe kinds, remove client impersonation capability, and make bad-descriptor paths return errors.
3. Repair the Linux directory-permission and exclusive-create cleanup regressions, and reject trailing wire data before callbacks.
4. Align the complete file identity and timestamp conversion with W2.1, then add and run actual Windows save/journal integration, including sharing violations and pre-rename durability.
5. Correct the remaining path-validation cases and close the transfer, Unicode, security, capacity and cancellation test gaps.
