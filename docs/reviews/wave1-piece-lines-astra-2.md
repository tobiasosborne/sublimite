# Piece-tree Lines freeze review, second read

## Question 1. Disposition of the original findings

Finding numbers identify the first review. (G) denotes a specified gate or interface rule. (P) denotes a derivation or constructed execution. All byte counts below are logical bytes read, including repeat reads, or used payload where indicated. This is a design review with no measurements or timing estimates. Write C = 65,536 B (G, `PIECE_CHUNK`) and H = C/2 = 32,768 B (P, the midpoint of a full chunk). Assume a trusted backing except in the fault traces.

1. **COUNTER-EXAMPLE — mapped reads on span insertion.** Resolve a whole mapped descriptor D with a nontrivial LF total. Insert a valid ADD span at its midpoint with `piece_replace_spans`. The inserted source needs no mapped read. The destination needs the counts of the two surviving halves. Moving an LF across the midpoint preserves every available whole-chunk total and changes both answers (P). The specified cut scans H mapped bytes. A supplied count for the ADD span says nothing about D. The same issue applies to deleting with this API. Promise zero mapped **inserted-source** reads and at most 2H = C mapped **destination** reads per replace (P, at most two cut boundaries). Also qualify the frozen Reading preamble's unconditional “piece_iter_next_span never reads a byte” with `nl == NULL`.

2. **COUNTER-EXAMPLE — exactness under replay.** The original pristine whole-chunk example closes for same-core replay. An unknown cut learns nothing, and private-copy open retains its totals. A wholly counted partial span can carry its count. A canonical span, however, can cross a counted/unknown transition *within* a chunk. The end record loses that transition, even on same-tree undo. The trace under Question 2 distinguishes restored bytes, restored counted contributions and an exact prefix. The header also needs a source-identity precondition on the record.

3. **CLOSED — which root resolve completes.** A shared path is copied before publication. A successful root replacement invalidates cached takes and live cursors. Failed admission preserves the old state. An inside snapshot keeps its old annotations, abort restores the checkpoint root without losing the source table, and a fresh sweep can refine that root. Completeness names the drained live root and snapshots of it (G, resolve contract, subject to backing validity). Implement cursor invalidation on path replacement as well if the implementation keeps an exclusive root object but swaps out a child referenced by a live iterator. Snapshot annotation stability and fault validity have different lifetimes, as finding 5 illustrates.

4. **AMEND — accounting closes, progress remains open.** Discovery charges visits including misses, COW goes through pool admission, refusal is retryable, and the maintenance order preserves typing admission (G). The pinned packed example checks out. For 1 GiB, 2³⁰/C = 16,384 descriptors, ceiling division by the signed leaf capacity 24 gives 683 leaves, and successive ceiling divisions by branch fanout 16 give 43 + 3 + 1 branches. The additional slots total (683 + 47) × 400 = 292,000 B (P, signed slot size, one old packed root held across a sweep). This example assumes no new pins during refinement. The stated restart events miss work and can starve a suffix, as shown under Question 2.

5. **AMEND — fault publication.** Bracketing mapped scans and polling cached queries close the stale-positive-answer trace when the final successful pristine poll is the answer's validation point. Adoption still says to store a successful worker result. Let the worker return true, then fault the mapping, then deliver that same backing's batch. The call meets its stated preconditions. The fault lease requires the UI to discard it at adoption. Also, an old snapshot can return an exact positive EOF rank before the fault and an inexact zero lower bound after it (P, let the repaired suffix contain the only LF). Qualify “a snapshot's answers never change” by continued trust. See the poll ordering under Question 2.

6. **CLOSED — final ORIGINAL chunk.** The chunk ends at the logical backing length. A final chunk shorter than C can be opened unknown without touching bytes and adopted as a whole. A proper subinterval remains a slice (G, Lines). Use that same extent when interpreting a carried record.

7. **CLOSED — flag capacity.** Let L denote text length. The enforced open/edit precondition gives LF sum ≤ L ≤ 2⁶⁰ < 2⁶³ (P, at most one LF per byte). Bit 63 is free (P, unsigned encoding). Change “below” to “at most” in the sum derivation. Equality is possible in the specified domain for an all-LF text at the cap. The header's illustrative address-space arithmetic gives 2⁴⁷ × C/16 = 2⁵⁹ and 2⁵⁶ × C/16 = 2⁶⁸ (P, at least one 16 B descriptor per C bytes). The explicit precondition supplies the portable proof. Check the remaining capacity before summing inserted lengths so unsigned wrap cannot satisfy the check.

8. **CLOSED — rank and select geometry.** Rank excludes the following descriptor at a boundary. Inside a descriptor it can count the terminal prefix even when the descriptor total is unknown. An unknown *wholly preceding* descriptor blocks exact rank. Select can skip counted subtrees, descend through exact leading children of a flagged subtree, and return the first blocking entry's start and the count before it. The origin needs no bytes, a trailing LF starts an empty line at EOF, and past the last known line the exact result is EOF and the total. At most C mapped bytes come from the single terminal pass (P, descriptor length ≤ C). The design's prefix invariant should distinguish intersecting the scanned terminal entry from passing a whole unknown entry. The header's rank rule already does.

## Question 2. Records, cuts, progress and publication

1. **NOTE — end geometry is sufficient for uniformly counted pieces.** For a nonempty source interval [a,b), choose the first and last *occupied* chunks, i = floor(a/C) and j = floor((b−1)/C) (P, half-open interval). Intersect the span with those chunks' logical extents. If i = j, put the intersection's count or UNKNOWN in head and zero in tail (G, single-chunk rule), including when it covers the entire chunk. Otherwise head and tail describe their respective intersections. An aligned b gives a full last occupied chunk if b reaches its logical end. It never introduces an empty next chunk. A run of entirely whole chunks can obtain every available total from the table, including both ends. A short final chunk ending at EOF uses its actual length. State whether a table-known whole overrides a stale UNKNOWN record from an older snapshot. These rules locate the fields without a shape tag (P). Whole-chunk totals say nothing about the distribution inside a partial end.

2. **COUNTER-EXAMPLE — a canonical end can have mixed knowledge.** Adopt and resolve a mapped chunk. At EOF append a counted proper slice A using its carried record, then append its source-contiguous neighbor B from the same chunk with NULL counts. Choose A containing an LF, B a proper slice, and A·B shorter than the chunk. The header makes B unknown even though the table has the whole-chunk total. Their source coordinates form one maximal span (P, consecutive offsets in the same store). Keep an unrelated known prefix before A, with a source discontinuity there. If the implementation already merges A and B into a single unknown descriptor, it loses A's contribution at that merge. Otherwise describe A·B at descriptor boundaries, delete it and undo it before resolve. Pick |A·B| ≥ 16 B so the signed rule selects a span (P, one run). Head must be UNKNOWN, since neither B nor the omitted remainder can be inferred from the whole total, and boundary-aligned description may read no text. There is no field for A's length or its known count. A known head could assert a false total. An unknown head can lose the counted LF from the EOF lower bound. Now cut away B. Before that round trip A was an exact descriptor. After replay, cutting the new unknown entry leaves A unknown and EOF rank inexact (P, unknown-cut rule). Interior rank's permission to scan a terminal prefix cannot fix rank at EOF.

   Preserve counted subranges across canonical coalescing, supply an exact source-range oracle when the chunk is adopted, or explicitly narrow the carried-exactness guarantee and its suite oracle. The record alone suffices to restore an entirely counted canonical span when its interior whole totals are available. It cannot encode arbitrary known subranges of one partial chunk.

3. **AMEND — provenance belongs to the bytes.** Describe a partial ORIGINAL containing an LF in tree X and pass the span and record to tree Y at an in-bounds ORIGINAL offset occupied by a non-LF. Both backings can be pristine. Bounds alone admit the ORIGINAL coordinates under the stated validity rule. Trusting X's record in Y gives an incorrect exact count (P). Require each supplied record to correspond to that exact, unclipped interval of the destination's same validated source generation, including the source of any interior whole totals. Moving a count to another clipped interval is equally invalid. The iterator's `end` lets the caller get the correct clipped record directly.

   For ADD, begin at mark m, append an LF, retain an inside snapshot, abort, then append a non-LF at m. The snapshot still names the LF. The existing provenance clause correctly rejects a saved interval [m,m+1) on the live tree despite regrowth (P, the abort lowered ADD below its end). Describing the *surviving snapshot after regrowth* must give the same rejection. Define validity from the lineage of the named bytes, rather than the time the descriptor or record was handed out. The abort preceded that later description. An unchanged prefix ending at or below the mark remains valid. Use the queried view's ADD directory and prefixes for reads. Attaching only an offset and a fresh description timestamp cannot establish lineage.

4. **CLOSED — arithmetic of a counted cut.** For a pristine counted parent of length d split at x, read min(x,d−x) ≤ floor(d/2) ≤ H bytes, then subtract that count from the parent for the other child (P). For two cuts in the same parent, split the remaining child using its updated total, or count an interior slice against its two disjoint outside pieces. An unknown parent can give both children UNKNOWN without reading. If a closing poll fails, discard the scan and any derived complement. Apply this rule to destination cuts in both replace functions.

   For a compound replace, keep the insertion seam through the operation. Consider two consecutive occurrences of the same full mapped chunk and replace the middle range [H,C+H) with new bytes. Each deletion endpoint costs H. The retained prefix and suffix now have consecutive source offsets, so an intermediate coalescence could join them and make insertion pay H again. That schedule reads 3H > C (P, two deletions of half a descriptor and one midpoint insertion cut). Splice at the existing seam before coalescing to obtain the stated per-call bound.

5. **COUNTER-EXAMPLE — saved sweep progress.** Save an UNKNOWN record for a proper mapped slice on an old snapshot. Adopt its chunk, drain the live root, then insert the slice behind the finished cursor using the **non-NULL** record. It is eligible immediately, yet none of the listed restart events fires. Another resolve can report done forever on a quiescent tree (P). Independently, a deletion before a saved absolute offset shifts a later unvisited entry behind it. A saved node path can instead become stale on a splice. Repair or invalidate progress on every structural change that affects it, and mark newly eligible unknowns regardless of the pointer value. A simple correct contract invalidates the cursor on any successful live edit or abort, and on adoption that adds knowledge. Define done as no eligible work remaining for the current root and table, allowing future batches to enable misses.

   Unconditional rewind on every adoption can starve a suffix even with successful admission. Re-adopt the same valid batch before each bounded slice that cannot reach the suffix (P, the header permits identical adoption). Avoid rewinding for duplicates. State liveness under a stable root/table, successful admission and sufficient visit budget, or retain a progressing pass and schedule a follow-up pass for dirtied earlier positions if fairness during churn is required. A zero budget admits zero visits (P). Even a positive budget smaller than a required atomic path walk needs resumable work or a documented minimum for progress. Charge actual ancestor visits during COW and make cursor advancement part of successful publication.

6. **AMEND — what one query poll proves.** A cached-only query can linearize at a single successful pristine validation of its held backing. For a query that scans, the opening and closing validation must enclose the mapped loads with the fault lease's ordering. The closing poll may also validate the result if it follows every dependent load. A lone entry poll followed by a fault and a terminal scan could otherwise combine a cached positive prefix with repaired zeros. No poll certifies future use after return. Fail closed on a poll error as well as on a nonzero epoch. Validate a queued batch's source identity and epoch again before installation. Taint returns a zero lower bound and the specified inexact select tuple, apart from data-independent line zero (G, Lines). Unsignalled file overwrites remain within the file owner's source-validation contract.

## Question 3. Mapped reads for delete and undo

1. **COUNTER-EXAMPLE — the worker's doubled bound is attainable.** Start with two adjacent, resolved, full mapped descriptors with nontrivial counts. Delete [H,C+H). This is one canonical span of length C (P, consecutive ORIGINAL coordinates), so undo uses a span. Description with a record clips both descriptors at their midpoints and reads H + H = C. Ordinary deletion cuts those same descriptors and reads H + H = C again. The survivors have a source gap of C bytes, so replay at their seam cuts neither. Total 2C = 4H = **131,072 B** (P). The shape-only pass for choosing the inverse uses NULL and reads zero mapped bytes (G). Warm pages still count on the second pass. Adopt the A13 figure for this sequence, amend the tightened A19 sentence and invariant, and exercise the whole sequence with the real-tree read counter. A per-replace test alone misses it.

2. **AMEND — specify the undo seam.** A canonical document boundary need not remain a descriptor boundary after a delete. For example, remove a separately sourced run inserted between two contiguous slices of one counted mapped chunk. If deletion coalesces those neighbors, undo must split the mapped chunk again. Either preserve the seam or charge that destination cut. For a one-span span-mode deletion with k interior endpoint cuts, description plus deletion costs at most 2kH (P). If k = 2, the surviving endpoint bytes belong to the deleted span's source with a nonempty coordinate gap and cannot coalesce across it. If k ≤ 1, even an extra undo split costs at most H, so 2kH + H ≤ 3H < 4H (P). This recovers the same overall upper bound without assuming every undo is boundary-aligned. The one-span literal branch instead describes shape without counts and captures L < 16 mapped bytes at most (G, signed threshold). Its cuts and possible seam split also fit 4H (P, at most 3H + L).

3. **NOTE — the smaller figure needs information reuse.** Independent calls with the current summaries have no guaranteed way to share the first cut result. A design can keep the calls separate and hand a caller-owned cut hint from description to deletion, tied to the exact parent interval, split coordinate, live revision and validated source. Carry the boundary descriptor's split counts, since an aggregated head can include other descriptors. One scan then serves each repeated split. Preserve the undo seam or reuse its complementary counts too. Another design supplies a source-range LF index with adopted counts, so both operations can answer a counted mapped cut from metadata. Either changes the stated information contract. Marking an end UNKNOWN merely to avoid its scan loses carried exactness. For the specified independent scans, retain 2C for the pair and C for the individual replace (P, midpoint witness above).

## Question 4. Literal threshold

1. **NOTE — the objectives disagree on a precise interval.** Let s be the number of nonempty canonical runs and L their total length. A span is 16 B (P, tagged coordinate and length, two 64-bit words). Its in-memory side record is 8 B (P, two 32-bit counts). The used span payload in RAM is therefore 24s B, against L B for a literal, excluding fixed fields, retained backing, slot slack and allocator rounding. The signed rule chooses literal for L < 16s and spans on equality (G, A13 and piece-pool). A threshold of 24 minimizes this used RAM payload at min(L,24s) (P). The choices differ exactly on 16s ≤ L < 24s, saving 24s−L B of RAM there. At L = 24s both choose spans (P, strict comparison). Use division for the implementation's threshold comparison.

2. **COUNTER-EXAMPLE — RAM savings do not dominate copy or journal costs.** Choose one descriptor-aligned all-mapped run of length 20 B at a document boundary. With s = 1, the signed choice uses 24 B of inverse payload, copies zero mapped bytes and needs zero mapped count reads on already counted descriptor boundaries. The alternative retains 20 B and must read and copy those 20 B at capture. It saves 4 B of used inverse payload and exceeds A13's copy cap min(20,16×1) = 16 B (all P, direct substitution). In general a literal reads the mapped portion at capture and replays its private bytes. A span copies no source payload, but clipped counted ends and destination cuts can cause the scans derived above. Mapped bytes *read* and bytes *copied into history* need separate counters.

3. **NOTE — restoration and persistence.** On valid sources either representation restores the same bytes. Capturing a literal counts it in ADD, so a previously unknown mapped fragment can return fully counted. The literal also retains its captured bytes across a later in-place source change. An ORIGINAL reference depends on its validated generation and must follow the conflict path if that source changed. Its line metadata has the separate representability condition in Question 2. The span unit remains 16 B and the 8 B cache record stays out of the journal (G, header). The durable journal encodes validated BASE references with generation and framing, and ADD/literals by value (G, signed piece-pool journal rule). The span unit alone gives no universal wire-record size. Moving the threshold changes which mapped runs replay by value. Keep 16 for the signed copy gate and journal choice, and account for 24s when admitting in-memory span inverses (P, payload derivation above). A threshold of 24 is strictly better only for used RAM in the switching interval.

**Verdict — HOLD.** Reconcile destination and round-trip read bounds, preserve or narrow mixed-span exactness, bind counts to source lineage, and settle sweep progress and fault validation before freezing Lines.
