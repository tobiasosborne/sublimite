### codex

Top gaps:
1. Character-built interaction chrome: pipe separators, bracket controls and block carets make the window read as a rendering scaffold.
2. Uncontrolled colour and lightness: vivid syntax fragments the page, while light-mode comments and syntax become too faint.
3. Unresolved proportion: inconsistent edge insets and the large-file minimap prevent the frame from feeling composed.

This does not meet the publication standard. The crisp shared typography and restrained base surfaces provide sound material, but punctuation-built tabs, block carets and prompt-like panels leave the interface visibly unresolved. Syntax colour supplies more emphasis than structure, and the light theme loses essential text contrast. Total care would require a coherent interaction vocabulary, independently calibrated theme palettes and one proportion system governing every remaining edge; these improvements largely fit the existing rendering primitives.

- **C1 3**: The native-resolution crops show crisp, even monospaced glyphs and a consistent baseline rhythm, but the tight setting gives code and labels a utilitarian typographic voice. *Change:* Replace the face with a monospace optically drawn for this text size, preserving the shared voice and integral cell dimensions. *Cost:* Asset bytes: replacement font size minus current font size, unquantifiable from pixels; 0 B atlas growth if dimensions remain fixed; 0 additional dirty pixels/keystroke; existing glyph primitive, no typing allocation or animation.
- **C2 2**: Light-mode comments and several syntax colours recede below the gutter in contrast, whereas dark-mode comments remain substantially stronger, breaking a consistent hierarchy across themes. *Change:* Rebuild the lightness ladder independently for each theme, keeping every document token at least 4.5:1 and placing gutter, minimap and hairlines progressively below it. *Cost:* 0 B additional memory: replace existing colour constants; 0 additional dirty pixels/keystroke; existing primitives, no allocation or animation.
- **C3 1**: Pink keywords, cyan functions, green strings, amber numbers and vivid orange-red operators fragment the code into conspicuously unequal colour bands in both themes. *Change:* Replace the syntax palette with five low-chroma hues of matched perceptual lightness per theme, reserving the interaction accent for focus and matches. *Cost:* 0 B additional memory: replace existing palette entries; 0 additional dirty pixels/keystroke; existing primitives, no allocation or animation.
- **C4 1**: Tabs receive horizontal padding while find and command labels begin at the leftmost pixel and palette shortcuts finish against the opposite edge. *Change:* Apply one consistent one-cell horizontal outer inset to tabs, panel labels, options and shortcut endings. *Cost:* 0 B: derive positions from existing cell metrics; 0 additional dirty pixels/keystroke with unchanged panel rows and document geometry; existing cell primitive, no allocation or animation.
- **C5 1**: Literal vertical-bar characters terminate every tab, while brighter text and a slight background difference identify the active document. *Change:* Remove the pipe separators and let the existing active-tab continuity with the page, surrounded by quiet inactive surfaces, provide the structure. *Cost:* 0 B additional memory; 0 additional dirty pixels/keystroke; fewer separator glyphs, existing cell backgrounds, no allocation or animation.
- **C6 3**: Muted, right-aligned line numbers maintain a consistent gap from text even at five digits, but the caret's line number receives no visible tonal distinction. *Change:* Lift only the current line number to the existing muted-text tone. *Cost:* 0 B: derive the line from the caret; 0 additional dirty pixels for same-line typing, at most two gutter-number runs on a line change, or 2 × digits × cell width × row height; existing glyph primitive, no allocation or animation.
- **C7 1**: The large-file minimap becomes a dense striped column in both themes, with a viewport rectangle extending substantially beyond the miniature's visible ink width. *Change:* Lower minimap ink contrast into the lowest useful neutral rung, with a separately restrained value for each theme. *Cost:* 0 B additional memory: replace existing minimap colours; 0 additional dirty pixels/keystroke; existing pixel-region primitive, no allocation or animation.
- **C8 1**: Find and Command appear as flush-left terminal prompts, while find options are compressed into cryptic bracket groups and palette shortcuts sit against the right edge. *Change:* Recompose the minibar on shared inset cell stops, using named toggle cells and a consistently inset shortcut column. *Cost:* At most 16 B static storage for Case, Word and Regex including terminators; 0 B runtime state; 0 additional dirty pixels/query keystroke at unchanged row bounds; existing cell primitive, no allocation or animation.
- **C9 1**: The caret is a full reversed character block in empty documents, code and query fields; the find scene shows a soft blue match but no distinct current-line treatment. *Change:* Replace the block caret with a precise two-native-pixel vertical bar across document and panel fields. *Cost:* 0 B additional memory; 0 additional dirty pixels/keystroke when confined to existing caret-cell damage; uses the already permitted caret-detail pixel region, no additional primitive, allocation or animation.
- **C10 3**: Empty documents retain intact chrome and calm blank space, but an isolated minimap hairline remains at the upper right; large files preserve the document layout. *Change:* Suppress the minimap and its viewport edge whenever document length is zero. *Cost:* 0 B: derive visibility from existing document length; 0 additional dirty pixels/ordinary keystroke, using existing minimap invalidation on empty/nonempty transitions; no additional primitive, allocation or animation.

### muse

Top gaps:
1. Chrome built from characters and flush to the edges - pipe tab separators, bracket find toggles, block caret, and the absence of any margin or proportion system make the window read as a terminal rather than a composed page.
2. The minimap fails at both extremes, appearing as a meaningless smudge in short files and as the loudest barcode column on screen in large files.
3. The colour and tonal system is an unedited programmer theme, with pastel syntax hues carried unchanged into the light theme where comments and keywords lose contrast, and no single accent or even lightness ladder unifies the two themes.

The instinct towards flatness and absence of ornament is the right starting point, and nothing here is gaudy. But the pixels show defaults rather than decisions: a stock mono face, a stock pastel syntax palette weakened in the light theme, characters doing the work of tab and toggle design, a block caret, and a minimap that is either debris or a barcode, all pressed against the window edges without a governing grid. Against an absolute Rams-Vignelli-restrained-Apple standard this is a competent functional editor, yet not one element has the exactness or quiet inevitability that would earn it a page as an exemplar of software made with total care.

- **C1 3**: In the 1:1 crops every label and line of code uses the same anonymous wide mono with merely adequate leading, so tabs, find field and code have no typographic voice beyond the Linux default. *Change:* Replace the default mono with a deliberately chosen text face for chrome and mono for code, set at its intended em with a whole-pixel line pitch and more generous leading *Cost:* bytes
- **C2 2**: Main text reads first in small files, but the large-file minimap becomes the brightest textured column while light-theme comments and pink keywords fall visibly below comfortable contrast against the near-white ground. *Change:* Retune all neutrals as one perceptually even OKLCH ladder, lifting comments above 4.5:1 and dropping the minimap below the gutter in both themes *Cost:* derived
- **C3 2**: The code crop shows an off-the-shelf programmer palette of pink, green, teal and orange reused unchanged in the light theme, where the same pastels wash out instead of forming an equal counterpart. *Change:* Rebuild the palette around one tinted neutral family and a single accent, reducing syntax to at most five low-chroma hues of matched lightness tuned separately for light and dark *Cost:* derived
- **C4 2**: Tab labels, line numbers, the minimap and the find line all touch the window edges with no margin system, leaving the text crowded in the top-left corner above a vast unproportioned void. *Change:* Inset the tab strip, gutter, text block, minimap and minibar from the window edges on a single shared grid, separating regions by space or one hairline only *Cost:* derived
- **C5 1**: Tabs are separated by literal | characters flush with the top edge, and the active tab in the light theme is barely distinguishable from its neighbours. *Change:* Remove the pipe separators and make the active tab continuous with the page by tone alone, with optically spaced labels and a small exact dot for unsaved state *Cost:* derived
- **C6 2**: Line numbers are suitably dim but sit hard against the left edge and code with no emphasis on the current line, and no position or status information appears in any normal editing scene. *Change:* Set the gutter to a fixed optical measure with breathing room before the code, lift the current line number one tonal step, and show position only when it is not the default *Cost:* derived
- **C7 1**: For short files the minimap is a tiny illegible grey smudge stranded at the top-right corner, while for the large file it becomes a full-height barcode of stripes that outshouts the gutter. *Change:* Hide the minimap when the file fits the viewport and otherwise render it inset from the edge at a contrast below the gutter with a calm solid viewport shape *Cost:* derived
- **C8 2**: The find line reads as a terminal prompt with cryptic bracket toggles and a 1/1 count pushed to opposite screen edges, and the palette selection is a full-bleed blue bar whose shortcut labels hug the right edge. *Change:* Recompose the minibar as one inset line on the page grid with named toggles instead of bracket glyphs and palette shortcuts set in a fixed tabular column *Cost:* derived
- **C9 1**: The caret is a solid block that obliterates the glyph beneath it on line 1 of the code crops, the find match is a plain selection-blue patch, and no current-line distinction is visible anywhere. *Change:* Replace the block caret with a fine exact bar using the existing caret pixel region, keeping selection and current match as two distinct soft tints of the single accent *Cost:* derived
- **C10 2**: The empty state is an uncomposed corner cluster of one tab, a line number and a block caret plus an unexplained hairline fragment at the top-right, floating in an otherwise featureless field. *Change:* Compose the empty window by removing the stray minimap hairline and centring a single quiet line of guidance on the page proportions, applying the same hiding rule to short files *Cost:* derived

### opus

Top gaps:
1. Characters do the work of UI: '|' tab separators, '[ ] [aa] [ ]' toggles, 'Find:' and 'Command:' prompt labels and a block caret give the frame a terminal's vocabulary.
2. There is no grid or margin system: tab labels, gutter numbers, panels and shortcuts sit flush against the window edges, the minimap's viewport overhangs its map, and a stray hairline sits in the empty state.
3. Type and colour are defaults, not choices: DejaVu Sans Mono at about 1.2 line pitch and a pink, teal, orange and green programmer palette at unequal lightness, with tinted punctuation in light.

These screens are clean and calm in tone, and the type renders crisply, but the window speaks the vocabulary of a terminal rather than of a composed object. Tabs are fenced with '|' glyphs, the find toggles are bracket characters, panels are labelled 'Find:' and 'Command:' at the window edge, and the caret is a block. No margin system exists: every label, number and prompt sits flush against the frame, and the minimap's viewport disagrees with the map's own width. The palette is a familiar set of programmer-theme hues at unequal lightness, set in the platform's default monospace with tight leading. None of this needs blur, shadow or animation to fix. Almost every remedy is a token table or a layout constant at 0 B. That makes the distance from the periodical's pages a matter of care, not of cost, and today an editor would turn the page.

- **C1 2**: In both 1:1 crops the face is DejaVu Sans Mono (the vendored Linux default) with crisp stems and no fringes, but the row pitch is about 31 px for a cap height of about 20 px, so lines nearly touch; the tab labels and the 'Find:' and 'Command:' prompts use the same face at the same weight, which gives one voice but a flat one. *Change:* Set a mono of real quality at a deliberate whole-pixel pitch with visible leading (for example, a pitch about 1.4 times the em instead of the current about 1.2), keeping one face for chrome and code. *Cost:* bytes, derived: the new TTF's file size minus DejaVuSansMono.ttf in the static binary, plus an atlas that grows with the glyph-cell area ratio; per keystroke the dirty rect is still one row, which grows in height by the pitch ratio; no allocation.
- **C2 3**: Text is the brightest element and the gutter numbers, the comment grey and the minimap all sit below it, but the ladder is uneven: in light, the semicolons and dots are tinted pink or brown at the same weight as keywords, and in 02-tabs-light the bar of inactive tabs is a mid-grey band that competes with the page while the active tab reads lighter. *Change:* Rebuild the neutrals as one OKLCH lightness ladder (text, muted, gutter, minimap, hairline) and return punctuation to the text or muted tone. *Cost:* 0 B: only the token table changes.
- **C3 2**: The 07-code crops carry pink keywords, teal functions, green strings, saturated orange numbers and operators, and grey comments: a familiar programmer-theme set at unequal lightness (the orange '*', '+' and '=' jump forward). The light theme reuses the same hues on near-white instead of being drawn as its own equal. *Change:* Derive at most five syntax hues at equal OKLCH lightness and low chroma, tint all neutrals with one hue, and keep the single accent for the caret, focus and the current match only. *Cost:* 0 B: token values only.
- **C4 1**: The labels touch the window edges: the gutter '1' sits at x≈2, 'hello.c' at the top edge, 'Find:' and 'Command:' at x=0, and 'Alt+Q' against the right edge. A stray hairline floats above the minimap at the top right in 01-empty, and in light the grey tab bar stops short of the minimap column, so the edges share no grid. *Change:* Adopt one margin unit (for example, one cell width) and inset the tab labels, gutter, panels and minimap by it, so that every edge sits on the same column and row grid. *Cost:* 0 B: fixed cell offsets in layout; the extra blank column costs no dirty pixels per keystroke.
- **C5 1**: Tabs are divided by literal '|' glyphs ('hello.c | util.py | notes.txt | readme.md |'), with a trailing '|' even on a single 'untitled' tab, and the label widths are padded arithmetically with spaces; no unsaved sign is visible. *Change:* Drop the '|' characters: separate tabs by space alone, make the active tab continuous with the page tone, and mark unsaved state with one small dot. *Cost:* 0 B: cells already drawn are reused; the dot is one glyph in the existing atlas.
- **C6 2**: The numbers are dim, but they are flush against the left window edge, and in 08-large '10000' sits one space from 'Paragraph' with no measure. The current line's number is the same grey as the rest, and no position read-out is visible anywhere except the find count '1/1'. *Change:* Give the gutter a fixed measure (an inset margin, right-aligned figures, a gap of one unit) and lift the current line's number one step on the ladder. *Cost:* 0 B: when the caret changes line, two gutter rows are redrawn (old and new), each gutter width by one row pitch, derived from the layout.
- **C7 2**: In small files the map is a quiet thumbnail, but in 08-large it becomes a barcode of vertical stripes (x≈1584–1612), and its viewport is a lighter rectangle that overhangs past the map to the window edge, so the two columns disagree in width. *Change:* Render lines as soft low-contrast blocks one step below the gutter tone, and give the viewport the map's exact width and margin as a single calm tint. *Cost:* 0 B: the existing minimap pixel region with different fill values.
- **C8 1**: Find reads as a terminal prompt: 'Find: minimap' at x=0, toggles drawn as bracket characters '[ ] [aa] [ ]', and the count '1/1' crammed against the right edge. The palette's 'Command: wrap' row and its full-bleed result rows place 'Alt+Q' and 'Ctrl+BackSpace' flush against the frame. *Change:* Compose the panel as one inset line on the page grid: the field, a quiet count, and toggles shown by tone instead of brackets, with no 'Find:' label; set the palette shortcuts in a right-aligned tabular column inside the margin. *Cost:* 0 B: existing cells and tokens; the panel stays a fixed row, so the layout does not shift.
- **C9 1**: In every scene the caret is a full white or black cell block over the first glyph ('/' and 'P' are knocked out), and the current line has no tint. The match tint is a soft blue-grey, which is good, but with one match a current match cannot be told from the others. *Change:* Replace the block with a fine whole-pixel bar in the one accent, drawn in the existing caret pixel region. *Cost:* 0 B and no new primitive (the caret detail region already exists); dirty pixels per keystroke fall from one cell to bar width by row pitch.
- **C10 2**: The empty window is a bare top-left 'untitled |', a '1' and a block caret, with a stray hairline left over at the top right. In 08-large the gutter widens to five digits that jam into the text, and the map turns into stripes. *Change:* Remove the orphan minimap hairline when there is no content and reserve the gutter measure for the maximum digit count, so that large files keep the same composition. *Cost:* 0 B: layout constants; the gutter measure is derived from log10 of the line count, computed on load and not per keystroke.

### codex

B is the stronger direction: its quieter minimap and restrained native-crop palette improve the reading surface. Neither variant approaches publication standard. The three ranked gaps are (1) chrome composition, particularly terminal-like minibars, unresolved tab separators and inconsistent edge spacing; (2) state precision, led by the cell-sized caret and undifferentiated current-line number; and (3) typographic finish, with tight leading and insufficient distinction between document and chrome. B's full code frames still show A's palette and separator while its detail crops differ, so visual consistency also remains unresolved.

- **C1 A3 B3**: Both native crops show the same crisp, even mono at approximately 28 px with a tight 31 px pitch; chrome and code have nearly identical typographic emphasis. *Change:* Use a mono optically tuned for the existing cell dimensions, with more carefully resolved punctuation and character spacing.
- **C2 A2 B3**: B quiets the large-file minimap and darkens light-theme comments in its crop, while A's pale comments weaken the hierarchy; B's full code frames retain A's treatment. *Change:* Apply B's crop neutral ladder consistently across every view.
- **C3 A1 B3**: A combines coral operators, orange numbers and pink keywords; B's crops use neutral operators and subdued lavender, green, teal and ochre, although its full code frames remain unchanged. *Change:* Unify syntax rendering around the restrained role palette visible in B's crops.
- **C4 A2 B2**: B reduces tab-strip clutter, but both variants place minibar labels against the left edge and shortcuts against the right, disconnected from the document's inset. *Change:* Apply a shared one-cell outer inset to chrome content.
- **C5 A1 B2**: A separates tabs with literal pipes; B removes them in the tabbed scenes, but its full code frames still retain a trailing pipe. *Change:* Use B's continuous active-tab fill consistently and remove every separator character.
- **C6 A3 B3**: Both gutters maintain a clear gap beside five-digit numbers, and B makes them quieter, but neither visibly distinguishes the current line's number. *Change:* Lift the current line number one step within the neutral ladder.
- **C7 A1 B3**: A's large-file map forms a conspicuous striped column; B suppresses that texture and exposes the viewport more clearly, although the viewport still meets the window edge. *Change:* Give the map and viewport a shared one-cell outer margin inside the existing minimap region.
- **C8 A1 B1**: Both variants retain terminal-like 'Find:' and 'Command:' prompts, bracket controls and edge-bound shortcuts; B changes their tone without resolving their composition. *Change:* Compose the existing minibar row as an inset field with a fixed trailing controls-and-count column.
- **C9 A1 B1**: A's white or dark caret and B's blue caret both occupy a complete character cell; the single-match find captures do not establish differentiation between current and other matches. *Change:* Replace the cell-sized caret with a precise 2 px vertical bar at 192 DPI.
- **C10 A3 B3**: B's empty views lose A's trailing pipe and its large-file map recedes, but both empty pages remain an immediate first row beneath a thin header. *Change:* Reserve one blank grid row between the tab strip and document content consistently across empty and populated states.

### muse

B is the better design in every scene because its four coordinated changes — removal of character tab separators, a single blue caret accent, calmer and more legible syntax colour, and a minimap that recedes — create a quieter and more coherent screen, but it remains an incremental token refinement rather than a publishable composition: the anonymous type, edge-hugging layout, block caret, character-built panel controls, unresolved gutter measure and uncomposed empty state are all untouched, so neither side rises above polished commercial competence on this absolute scale.

- **C1 A3 B3**: The 07-code crops show identical glyph shapes, stem weight, size and tight line pitch on both sides, with only colours differing. *Change:* Set a higher-quality monospace face at its designed size with deliberately increased whole-pixel line pitch.
- **C2 A2 B3**: In 08-large A the minimap stripes are brighter than the gutter and nearly rival the text, whereas B places the map below the gutter and also darkens the washed-out pastel syntax tokens in the light code crop. *Change:* Rebuild every neutral and syntax token on one perceptually even tonal ladder that keeps comments at or above 4.5:1 in both themes.
- **C3 A2 B3**: A speckles the code crops with saturated orange-red operators and numbers among pink, green and teal, while B uses closer muted lavender, tan and teal tones and introduces saturated blue only at the caret. *Change:* Reduce syntax to at most five quieter hues of matched lightness and reserve the blue accent exclusively for caret, focus and current match.
- **C4 A2 B2**: Both sides place tab labels, line numbers and text flush with the top and left edges and the minimap flush right, with B removing tab separators and the light tab-strip tint but leaving every margin unchanged. *Change:* Introduce one consistent inset and alignment grid for tabs, gutter, text, panels and minimap so no label touches a window edge.
- **C5 A1 B3**: A prints a vertical-bar character between every tab in the 02, 03 and 06 scenes, whereas B separates the same labels by space and tone although its active tab still has no shape joining it to the page. *Change:* Make the active tab continuous with the page through a subtle background shape and give all labels optical padding with one small exact unsaved marker.
- **C6 A2 B2**: Both sides set current and inactive line numbers in the same dim grey, and in 08-large the five-digit numbers run directly into the first text column without a breathing measure. *Change:* Right-align numbers within a deliberate gutter measure, add clear space before the text and lift only the current line number one tonal step.
- **C7 A2 B3**: A renders the 08-large minimap as a high-contrast barcode competing with the page, while B keeps the same miniature and viewport several steps dimmer but makes the light-theme texture almost too faint to read as a miniature. *Change:* Raise B's light-theme minimap texture one tonal step while keeping it below the gutter and preserving the calm filled viewport.
- **C8 A2 B2**: Both sides pin the Find and Command lines, bracket-character toggles and palette rows to the bottom and right edges, with B changing only the field caret from monochrome to blue. *Change:* Compose each minibar on the page grid with proper insets, tonal toggle states and unclipped tabular shortcuts aligned to a common right margin.
- **C9 A2 B3**: A uses a monochrome block at text brightness that covers the slash in 07-code and the initial letter in 08-large, whereas B's blue block is immediately distinct and matches the selection family but still obscures the glyph beneath it. *Change:* Replace B's blue block with a fine blue bar in the existing caret pixel region so the underlying glyph remains visible.
- **C10 A3 B3**: Both empty scenes are an uncomposed void containing only the untitled tab, line number 1 and a block caret in the top-left corner, with B differing only in the caret's blue colour. *Change:* Compose the empty buffer around the page proportions with one quiet centred instructional line that disappears on the first character.

### opus

B is the better design in every scene: it removes the '|' characters from the tab strip, moves the caret to a single blue accent, and in the crops it replaces A's high-chroma programmer palette with quieter hues of similar lightness. That lifts tabs, colour, tonal order, chrome and states by one step each. Neither side is anywhere near the pages. The three gaps that keep the screen out are, in order: (1) the panels are terminal prompts, with 'Find:' and 'Command:' labels and bracket characters standing in for toggles; (2) there is no margin system, so line numbers, panel labels, shortcuts and minimap all touch the window edge; (3) the type is the default DejaVu with tight leading and a block caret, so nothing about the page reads as set by hand. One problem with the harness: the half-size 07-code B frames in both themes look identical to A, with the '|' separator, white caret and orange operators. The 1:1 crops for the same scene show B's actual changes, so the half-size B renders look stale and should be regenerated before the council's result is trusted for that scene.

- **C1 A2 B2**: Both crops set the same DejaVu Sans Mono at a whole-pixel pitch of about 31 px, with crisp, even stems and no fringes. It is the Linux default monospace, and the leading is tight: descenders on line 7 nearly touch the ascenders of line 9's 'static'. Tab labels and code share one voice, identically on both sides. *Change:* Set code and chrome in a monospace drawn for the screen at its design size, and add deliberate leading so the pitch stays a whole number of pixels with visible air between lines.
- **C2 A2 B3**: In A's dark crop, saturated orange operators and digits ('*', '+', '=', '0', '-4') and a white block caret pull the eye off the text. A's light comments and pink keywords wash out against #f7f7f7. B makes operators plain text and keeps its hues at one lightness, so text leads, comments sit below it, and the gutter sits below the comments. *Change:* Put text, comment, gutter and minimap on explicit OKLCH lightness steps of equal size. In B's light theme, lift the gutter numbers one step above their current near-comment grey so the two no longer read as one tone.
- **C3 A2 B3**: A reads as a stock programmer theme: pink, green, orange, red-orange and teal at high chroma, with no single accent, and the caret is plain white or black. B uses muted violet, teal, ochre and green at similar lightness, keeps one blue for caret, selection, match and the active palette row, and gives the light page a cool tint. *Change:* In B, carry the light page's cool tint into every dark neutral (page, strip, gutter, panel band). Pull ochre and green closer in chroma so the syntax is a whisper of four hues, not five.
- **C4 A1 B2**: On both sides the line numbers start at x=0, 'Find:' and 'Command:' sit flush against the left edge, '1/1' and 'Alt+Q' touch the right edge, and the minimap butts against the top-right corner. A also draws '|' characters across the tab strip; B removes them. *Change:* Inset the gutter, panel lines, palette rows and minimap by one shared margin unit, such as one cell width, so no label touches the window edge and every edge sits on the same grid.
- **C5 A1 B3**: A separates tabs with '|' characters and marks the active tab only with a faint plate. In B's light theme the active tab is a page-coloured plate continuous with the text, in a grey strip with no separators. B's dark strip, however, shows the active tab only through a brighter label. *Change:* Give B's dark theme the same structure as its light theme: the strip one tonal step below the page and the active tab in page tone. Add a small, exact unsaved dot after the label.
- **C6 A2 B2**: On both sides the numbers are dim and right-aligned, but they start at x=0: the five-digit numbers in 08-large touch the window edge.
