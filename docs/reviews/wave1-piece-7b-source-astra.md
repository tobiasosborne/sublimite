## 2. Monoid and its persistence — CONFIRMED

On a trusted backing, the leaf represents either (length, LF count, false) or (length, 0, true). Private open copies and counts, mapped open initializes unknown without loading ORIGINAL, and both build one leaf entry per occupied source chunk. Appends count the bytes they write. Replayed private spans use the queried store's prefix data. For mapped replay a known whole-chunk table value wins, including a short final chunk. Otherwise only an edge carry supplies a count. An interior mapped chunk without a total remains unknown (`piece.c:699`, `piece.c:814`, `piece.c:892`, `piece.c:920`, `piece.c:933`, `piece.c:2064`). The Lines rules here are A19 and the subsequent frozen rulings. A23 in the supplied amendments concerns the save protocol.

The induction is local. Leaf get/set translate the sentinel. Summary adds masked LF counts and ORs the flags independently (`piece.c:847`, `piece.c:874`). Splice preserves the ordered entries in both halves. Structural merge transfers the children's entries, and descriptor merge requires like knowledge and source adjacency within a chunk. Root growth summarizes both children. Deletion summarizes each changed boundary before the parent splice, and root collapse promotes the surviving child. Insertion finalizes each frozen half as splits propagate and refreshes the active path bottom-up before publication (`piece.c:1659`, `piece.c:1698`, `piece.c:1710`, `piece.c:1730`, `piece.c:1813`, `piece.c:1875`, `piece.c:2039`, `piece.c:2175`). Shared-node copies retain children and preserve annotations. Abort reinstalls the checkpoint root and the matching restore directory, including its saved tail total (`piece.c:372`, `piece.c:736`, `piece.c:1169`). These arguments assume valid ownership counters, as discussed in item 6.

Width proof (P). Each LF costs one byte, so counted sum ≤ subtree bytes ≤ document length ≤ 2^60 < 2^63. The frozen cap is **inclusive** (`piece.h:118`, `piece.h:426`). Open checks it, raw replace subtracts the surviving length first, and span replace checks and deducts each input against remaining capacity before accumulating (`piece.c:990`, `piece.c:2239`, `piece.c:2251`). An actual published branch entry is a proper subtree of a non-unary root with nonempty children, so it is also strictly below the cap. A leaf count ≤ C fits below UINT32_MAX. Bit 63 is available for the branch flag even at the inclusive document bound.

## 4. Cuts, joins and read bounds — FINDING

**SHOULD-FIX C. The private cut does not implement the stated shorter-half rule.** `piece.c:1268` always selects the left half for a private source. In a private all-LF ORIGINAL of C bytes, cut at C−1 (P). The right half is one byte. The implementation reads 511 bytes to complete the left prefix, since (C−1) mod 512 = 511 (`piece.c:819`, `piece.c:827`, `piece.c:837`). Counts are correct and the mapped-read gates hold. The shorter-half instruction in `piece.h:442` applies to a counted descriptor. Use the cheaper shorter-side scan when it beats the prefix calculation, or obtain an explicit private-prefix exception to that wording. The existing erratum addresses private *inserted source*.

**CONFIRMED for mapped cuts and the pair (P).** Set H=C/2=32,768 B. For a nontrivial counted mapped piece of length d cut at x, the code reads min(x,d−x) ≤ H and subtracts from the parent count. A zero LF count needs no scan. Unknown halves inherit unknown without a byte read. Two cuts within one descriptor apply the second cut to the remaining suffix and its updated count (`piece.c:1257`, `piece.c:1395`, `piece.c:1777`). The diagnostic recount is outside the production bound.

- **Compound seam, Q2.4 (P).** In two consecutive occurrences of the same counted chunk, deleting [H,C+H) can cost H at each boundary. Compound deletion passes `join=false`; a structural child merge transfers descriptors intact. Insertion therefore lands at the existing seam and performs zero further cuts (`piece.c:1731`, `piece.c:1793`, `piece.c:2198`, `piece.c:2011`). Pure insertion makes at most one destination cut. Each replace stays within 2H = 65,536 mapped bytes, with zero mapped inserted-source reads.
- **Undo seam, Q3.2 (P).** The shape-only description bypasses counting (`piece.c:1421`). For one span with k interior endpoints, description with counts and deletion each cost at most kH. With k=2, the surviving source offsets enclose a nonempty gap, so `piece_mergeable` cannot join them and reference undo cuts nothing. With k≤1, deleting a separately sourced run can rejoin counted neighbors. Undo may cut the joined piece once, for ≤2kH+H≤3H. Two consecutive, distinct, full counted chunks and deletion of [H,C+H) attain 2H+2H+0 = **131,072 B** with positive counts at both cuts. A one-span literal has length <16 B under A13, so even charging its copy and three cuts gives <16+3H<4H. These are read counts, including repeated loads (`piece.c:1395`, `piece.c:1710`, `piece.c:1781`, `piece.c:2013`, `piece.c:2282`).
- **Record algebra (P).** Use the last occupied byte to locate each span's last chunk. A one-chunk union returns the sum of the heads and zero tail. Otherwise the left head receives the right head exactly when the right starts in the union's first chunk. The last edge uses the right head for a one-chunk right span and its tail otherwise, plus the left tail exactly when the left also ends in that last chunk. Either unknown contribution makes the sum unknown. A boundary seam adds no contribution from the adjacent chunk. A shared interior chunk has no output field and replay uses only the store table. The sum within any one chunk is ≤C (`piece.c:2105`, `piece.c:2119`, `piece.c:2071`). Description accumulates each maximal source-contiguous run in the queried view. A mixed edge becomes unknown, then eligible for resolve when its chunk is adopted. Valid ADD records track byte lineage across abort, including records described later from a surviving snapshot (`piece.c:767`, `piece.c:1403`, `piece.h:134`).

## 6. Threads and lifetime — FINDING

**MUST-FIX F. Core ownership can wrap while live owners remain.** `piece.c:122` uses `atomic_uint`, and the increment at `piece.c:1127` is unchecked. On the candidate's 32-bit unsigned ABI (P), the tree plus 2^32 distinct held snapshot headers represents 2^32+1 owners as one. Distinct versions are reachable with a leaf-sized text by replacing it by an ORIGINAL reference between takes. Every version keeps its own leaf, so a node reference counter need never approach its limit. The leaf and header cost about 2 × 400 × 2^32 B, within the stated 47-bit address space (P). Dropping the tree when the counter reads one allows `piece_core_drop` to finalize a core still owned by snapshots (`piece.c:499`, `piece.c:1232`). There is a lower-storage issue on the same API surface: retaining one cached snapshot repeatedly can reach UINT32_MAX without allocating another header, then an otherwise valid retain trips the assertion at `piece.c:1066`. The header gives no such owner-count precondition. Use ownership arithmetic with a justified representable bound and handle saturation before a destructive counter transition.

**CONFIRMED below counter limits (P).** An ordinary last release publishes one header with a release CAS loop, then drops the core owner. The UI acquires the list before draining. The thread that drops the last owner acquires exclusive access to the remaining core, releases its ADD mappings, calls the backing release hook, frees ORIGINAL, resets the private pools, publishes the extent chain with one successful release CAS, then drops the reserve's core count. Worker release never draws from or mutates the UI's free list (`piece.c:431`, `piece.c:475`, `piece.c:497`, `piece.c:1063`). The worker counter accepts a backing and caller-owned output, scans at most nC bytes and closes with the backing's poll. It has no tree, reserve or mutable chunk-table access (`piece.c:1538`). Snapshot queries read their captured nodes and captured ADD directory. An ADD prefix boundary is written before the corresponding bytes can be published. A partial-tail query avoids the changing total, and a view exposing post-mark bytes keeps the old chunk when rollback needs a writable replacement (`piece.c:707`, `piece.c:728`, `piece.c:814`, `piece.c:1112`). Production query counters compile away.

## 7. Extent retention and the memory gate — FINDING

**MUST-FIX G. Successful top-up can leave a closed core's surplus extents mapped indefinitely.** When `slots <= c->free_slots`, `piece_fund` returns at `piece.c:536` before exchanging the reserve inbox. `piece_replenish` then trims only `r->free` (`piece.c:1206`–`1210`, `piece.c:271`). Construct a foreground leaf-height tree with at least W(0)=10 holes across its nonempty core-owned pages (P). This is reachable by retaining successive small revisions, then releasing and reclaiming most revisions on each page while keeping a survivor per page. Close a large second tree with a worker snapshot outstanding. After close returns, its final worker release places the whole extent chain in the inbox (`piece.c:505`–`526`). Every subsequent foreground replenish can succeed entirely from local holes. Its target for reserve extents is zero and it repeatedly trims an empty free list while the entire orphan chain stays mapped. The signed extent-ownership rule requires surplus above the working target to return to base after orphan retirement. Drain the reserve inbox on foreground maintenance even when its slot deficit is zero.

**A20 arithmetic (P), source derivation only.** On 10,000 uncoalescable prepends the upper-midpoint split leaves a fresh left leaf needing 12 more entries for its next split, and a left branch needs eight child additions. This yields 1+ceil((10,000−24)/12)=833 leaves, then 1+ceil((833−16)/8)=104 branches, then 1+ceil((104−16)/8)=12 and one root. That is 950 slots. In the stated fixture each of 5,000 held versions followed by adjacent ADD extension incurs one header and one four-node COW path, giving 25,950 slots. With ten slots per extent this is 2,595 × 4,096 = 10,629,120 B (`piece.c:1063`, `piece.c:1687`, `piece.c:1921`, `piece.c:1980`, `piece.c:2019`). One live ADD chunk and one spare each round to 17 pages, three descriptor mappings take one page each, and W(3)=1+15+11+1=28 free slots require three spare pages when occupied pages are full. Total 10,629,120 + (2×17+3+3)×4,096 = 10,792,960 B on that ABI. This derives the fixture ledger independently of a test execution. G concerns additional pages returned asynchronously by another core.
