## Original findings

- **1 — CLOSED (G).** On the pin, a child emitting only the signed `X3 / over.roundtrip` FAIL earns XFAIL for that pair. XFAIL records no stop, so every absent twin or over control is MISSING and the gate is ERROR. With all required controls PASS, the same signed failure is accepted. A genuine FAIL explains only later omissions in its own case and retains FAIL when that is the only problem. An off-target ERROR becomes a receipt problem. Before returning PASS, the aggregate compares the exact set of scored IDs with the independently enumerated required set and admits only PASS and matched XFAIL. See `expectations.json:429–447`, `run.py:344–359,369–429,483–505` and the fixture checks in `test_run.py:292–345`.
- **2 — CLOSED (G) for the reviewed gate and atomic executable replacement.** Selection compares the measured identity with the reviewed target and builds the path-to-digest map from that target. Each editor invocation gets the serialized map in a single argv element. A replacement present at the runner’s recheck produces ERROR before the script starts. A later pathname replacement either produces a sandbox digest mismatch or leaves the launch on the already-pinned approved inode. A replacement stamp cannot change the expected digest. Start, relay and restart all use the same spawn path, which hashes a duplicate of the open fd, checks any existing pin for inode identity, and executes through the parent’s pinned fd. The oracle builder publishes by rename. See `run.py:200–245,282–309,457–463`, `sandbox.py:337–372,423–430,472–511` and `build_oracle.py:143–149`.
  
  The manifest supplies the argument to adapter, navigation, files, recovery, large-undo and capacity (`expectations.json:80–165`). Each looks up the path it is about to execute. This includes recovery’s pre-ACK stock oracle, the adapter’s stock and drop-submit controls, and X3’s stock editor. The X3 self-test supplies its own marked diagnostic stub binding. See `cases/navigation.py:467–469`, `cases/files.py:582–584`, `cases/capacity.py:718–720`, `cases/recovery.py:146–154`, `test_oracle_inspector.py:132–133,203–223,363–367,420–432,459–465`, `cases/large_undo.py:645–655` and `test_large_undo.py:399–426`. The runner fixture verified binding propagation, independence from an outer environment binding, changed-byte refusal and identical-byte acceptance (`test_run.py:388–411,442–469`).
- **16 — CLOSED (G).** Duplicate `status` keys on a RECORD line produce a malformed-record problem even if the final value is PASS. Duplicate keys in the manifest or build stamp fail selection. The same recursive object-pairs hook also checks digest argv. A record for `X3.over / roundtrip` is unowned and leaves `X3 / over.roundtrip` missing. ## B6 additions

(G) On the checked-in `R1`, `R6` and `R4` count rows, a raw PASS must carry exactly integer `allocations >= 0` and `scopes >= 1`. Booleans, missing fields and an empty measurement window yield ERROR. A valid positive allocation count passes `recorded` on the pin and fails `zero` on v2. The receipt retains both predicate and observation. The v2 identity is currently unbound. See `expectations.json:26–30,320–325,342–347,476–482`, `run.py:344–356,393–399` and `test_run.py:413–440`.
