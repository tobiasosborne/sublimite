1. **MAJOR — A sent message can enqueue an event and then leave the loop asleep indefinitely.** `src/win32/win32_plat.c:473`, `:541`.
   `PeekMessageW` dispatches pending nonqueued messages before returning whether it found a queued message. A worker's `SendMessageW(hwnd, WM_CLOSE, ...)` can therefore run `procedure`, enqueue CLOSE, and leave `PeekMessageW` returning false. `drain` reports no buffered work, and the outer loop can enter an infinite wait with CLOSE still in the private ring. Synchronous resize, focus and clipboard notifications have the same problem. Events enqueued by callbacks after the initial drain can also reach this sleep boundary. **Fix:** recheck the private queue after every potentially reentrant message-pump operation and immediately before blocking; continue draining if a sent handler produced an event. Add a helper-thread SendMessage test with blink/repeat disabled and no subsequent posted input. The callback must arrive without an unrelated wake. [PeekMessageW dispatch semantics](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-peekmessagew).

2. **MAJOR — Native move/size and system-menu modal loops suspend application delivery and can exhaust the event ring.** `src/win32/win32_plat.c:276`, `:290`, `:478`, `:18`.
   Passing nonclient move/size handling to `DefWindowProcW` enters a nested modal loop before DispatchMessage returns. That loop still invokes the window procedure, but none of `on_event`, `on_work`, owned repeat, blink, or T6 delivery runs. Resize/expose records accumulate; once the fixed ring is full, subsequent records, including the final geometry or CLOSE, can disappear. WM_PAINT has already validated the update region, so a dropped EXPOSE has no pending paint to recover it. Even before overflow, live resizing freezes editor redraw and worker progress. **Fix:** handle WM_ENTERSIZEMOVE/WM_EXITSIZEMOVE and provide a guarded, message-driven modal service path, with a modal WM_TIMER or equivalent bridge for handle wakes. Coalesce pending size/expose state and preserve control/completion events without allocating. Avoid recursively entering unrestricted application callbacks. Test a real SC_SIZE/SC_MOVE operation, work/T6 during the modal interval, and more resize notifications than the ring can hold. A SendMessage of WM_DPICHANGED does not exercise this. [WM_ENTERSIZEMOVE](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-entersizemove).

3. **MAJOR — AltGr classification depends on the next character instead of the actual modifier state.** `src/win32/win32_plat.c:55`, `:131`, `:138`, `tests/win/win32_plat_test.c:52`.
   CTRL+ALT is converted to ALTGR only inside the printable/keypad branch and only if ToUnicodeEx produces a scalar or dead key. On German, RightAlt plus an unassigned letter such as P remains CTRL+ALT and can reach the editor's Ctrl+Alt+P binding. RightAlt plus a fixed-symbol navigation key also remains a chord. Modifier events and pointer events never receive ALTGR at all. Conversely, explicit LeftCtrl+LeftAlt on a layout with a third-level character is indistinguishably turned into text. An independently held real Ctrl is also cleared when the probe succeeds. The test sets VK_RMENU for every Alt state, so it cannot distinguish these cases. **Fix:** track sided modifier transitions and the synthetic Ctrl associated with an AltGr-capable layout, normalize effective ALTGR consistently for key and pointer events, and retain independently held command modifiers. Specify the treatment of Windows' Ctrl+Alt text alias explicitly. Test RightAlt on mapped and unmapped keys, navigation/drag, ordinary right Alt on US, explicit LeftCtrl+LeftAlt, and real Ctrl held with AltGr.

4. **MAJOR — KEYDOWN and CHAR have incompatible text ownership: duplicate text on one route, lost text on the other.** `src/win32/win32_plat.c:148`, `:183`, `:239`, `:241`, `tests/win/win32_plat_test.c:81`.
   A printable KEYDOWN inserts through ToUnicodeEx, and an ensuing WM_CHAR inserts again. The supposed duplicate regression posts carriage return, whose text is always filtered, and proves nothing about printable pairing. The normal outer loop avoids TranslateMessage, but a native/host modal pump or another legitimate translating dispatcher can supply the pair. Dead-key state can then be advanced by that dispatcher and by this procedure. At the other extreme, `unicode_event` unconditionally drops bit-30 CHAR/UNICHAR input, even though independently supplied text has no `repeat_key` and no owned repeat timer to replace it; character repeat counts are ignored too. **Fix:** make text provenance and ownership explicit. Have exactly one mutating translation owner, associate any native character messages with their originating key, and distinguish committed/injected text from repeats of a platform-owned physical key. Use nonmutating probes only for symbol lookup when Windows owns text. Add printable KEYDOWN+CHAR, dead-key sequences through a translating pump, and standalone CHAR/UNICHAR with repeat metadata. [Character-message translation](https://learn.microsoft.com/en-us/windows/win32/inputdev/about-keyboard-input), [UNICHAR metadata limitations](https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-unichar).

5. **MAJOR — The omitted native translation path breaks VK_PACKET and leaves IME processing incomplete.** `src/win32/win32_plat.c:167`, `:175`, `:475`, `tests/win/win32_plat_test.c:233`.
   SendInput(KEYEVENTF_UNICODE), used by nonkeyboard text input, produces VK_PACKET key messages. Windows documents TranslateMessage as the step that turns them into WM_CHAR; this loop skips that step and instead treats VK_PACKET as an ordinary layout key, even truncating its scan information to a byte. Posting already decoded WM_CHAR/WM_UNICHAR in the test bypasses the failing route. VK_PROCESSKEY is likewise treated as an ordinary repeatable key, with no IME-specific translation or composition ownership. Default handling of some IME notifications does not establish a working input pipeline. **Fix:** route VK_PACKET and IME-processed keys through the native text/IME path exactly once, exclude them from physical-key repeat/chord dispatch, and deliver committed Unicode through the ownership scheme in finding 4. Add native KEYEVENTF_UNICODE BMP/supplementary input and a real IME compose/commit/cancel regression; verify that composing text never fires editor shortcuts. [KEYBDINPUT](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-keybdinput), [VK_PROCESSKEY/TranslateMessage](https://learn.microsoft.com/en-us/windows/win32/api/imm/nf-imm-immgetvirtualkey).

6. **MAJOR — Valid multiscalar keyboard output is silently discarded.** `src/win32/win32_plat.c:66`, `:149`, `:155`.
   `scalar` accepts one BMP scalar or one surrogate pair only. ToUnicodeEx can return multiple ordinary UTF-16 characters for a single layout key. Such a result becomes cp=0, keysym=NoSymbol and empty text, even when the complete UTF-8 string fits PLAT_UTF8_MAX. The AltGr probe also fails to recognize multiscalar printable output. This is separate from the intentional swallowing of an invalid dead-key composition. **Fix:** decode/validate the whole returned UTF-16 span, encode printable text up to the contract limit, and calculate a single keysym only when appropriate. Preserve the explicit cancelled-compose rule. Define a bounded policy for longer commits rather than silently inserting nothing. Test a ToUnicodeEx fixture returning two ordinary scalars, a supplementary scalar, and an invalid compose result. [ToUnicodeEx return contract](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-tounicodeex).

7. **MAJOR — Windows Alt+numpad character entry cannot commit.** `src/win32/win32_plat.c:145`, `:148`, `:109`.
   For ordinary Alt combinations, translation clears Alt before ToUnicodeEx, so Alt+numpad cannot maintain native numeric-entry state. Alt release has a fixed modifier keysym and never reaches ToUnicodeEx, and the scan argument never carries the break bit needed by release-sensitive translation. With no TranslateMessage fallback there is no final character. **Fix:** recognize native Alt+numpad entry as a text sequence, preserve the native modifier and release semantics on that route, and suppress intermediate digit/chord events and owned repeats. Add an Alt-code sequence with a final Alt release and verify one committed character. This must share the single translation owner from finding 4. [ToUnicodeEx release/Alt-numeric semantics](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-tounicodeex).

8. **MAJOR — System keyboard actions are swallowed, including Alt+F4.** `src/win32/win32_plat.c:239`.
   Every WM_SYSKEYDOWN/UP is consumed with return 0. The native default handler never gets the system-key sequence, and this backend does not implement its replacement. Alt+F4 consequently produces an application key event rather than the normal CLOSE request; the current key table has Ctrl+F4 but no Alt+F4 close binding. The system menu keyboard path is also lost. **Fix:** preserve Windows-reserved system actions through carefully selected DefWindowProc handling or explicit equivalent WM_SYSCOMMAND dispatch, while retaining application Alt chords and AltGr text. Add Alt+F4-to-CLOSE and Alt+Space/system-menu regressions, including cancellation without destroying the window. [System versus nonsystem keystrokes](https://learn.microsoft.com/en-gb/windows/win32/inputdev/about-keyboard-input).

9. **MAJOR — Losing capture never tells the consumer that its drag ended.** `src/win32/win32_plat.c:259`.
   WM_CAPTURECHANGED only clears the backend's button mask. If another window steals capture and the user releases outside the editor, no BUTTON release reaches the consumer. The editor's text selection code clears `text_drag` on a left release or focus event, and its motion path does not require `ev.buttons`; selection can therefore continue on later ordinary motion after capture was lost without a focus change (`src/editor/input.c:1352`, `:1362`). WM_CANCELMODE reaches the same hole through default capture release. **Fix:** enqueue releases/cancellation for all previously held buttons when capture is lost, retaining position/modifiers as available, and handle cancellation consistently. Ensure the normal last-button ReleaseCapture path does not duplicate releases. Test capture theft by another same-thread window, outside release, then motion with no button held.

10. **MAJOR — The asynchronous clipboard entry performs blocking foreign work on the UI thread.** `src/win32/win32_plat.c:411`, `:412`, `:415`, `:420`.
    `plat_clip_request` opens and reads the clipboard, scans all UTF-16, allocates, and converts the entire payload before returning. GetClipboardData can ask another process to render delayed clipboard data; the clipboard manager can wait up to 30 seconds (documented OS timeout, not a measured result of this review). That stalls input, painting, the platform deadline and work delivery inside a paste callback. Large eager payloads also receive unbounded UI-thread work. The CLIPBOARD event being queued afterwards does not make the request asynchronous. **Fix:** queue requests promptly and perform the blocking clipboard read and bulk conversion on a dedicated clipboard worker that owns any required helper window. Copy while the native handle is locked/open, then post bounded completion to the UI; never hand a borrowed HGLOBAL to later work after CloseClipboard. Add a separate delayed-rendering owner and large-payload responsiveness tests. Eager publication here does not itself require this backend to implement WM_RENDERFORMAT. [Delayed rendering](https://learn.microsoft.com/en-us/windows/win32/dataxchg/clipboard-operations), [clipboard-manager timeout](https://devblogs.microsoft.com/oldnewthing/20220609-00/?p=106731%2F).

11. **MAJOR — Transient OpenClipboard contention permanently loses copy/paste attempts.** `src/win32/win32_plat.c:399`, `:411`, `:432`.
    Another application briefly holding the clipboard makes copy return FAIL immediately and makes paste queue a permanent failed completion immediately. There is no retry state, deadline or notification-based retry. Ordinary clipboard contention, including clipboard managers, is sufficient; a missing text format is not the only failure case. **Fix:** retain the requested operation and its copied payload, schedule nonblocking bounded retries for contention, and report one final outcome when successful or expired. Preserve clipboard ownership state until EmptyClipboard actually succeeds. Test another process holding then releasing the clipboard, both successful retry and terminal failure, and cancellation/shutdown of pending operations. Do not sleep/retry inside the UI callback. [OpenClipboard failure behavior](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-openclipboard).

12. **MAJOR — Queued clipboard completions are not associated with their data.** `src/win32/win32_plat.c:431`, `:432`, `src/x11/plat.h:140`.
    A successful request stores buffer A and queues success. A second request before delivery immediately frees A and installs buffer B, or NULL for PRIMARY/failure. The callback for the first success then observes B/NULL through plat_clip_data. A request issued inside a clipboard callback can also invalidate that callback's borrowed data before it finishes. The X11 implementation deliberately retains result blobs until the corresponding completion is emitted. **Fix:** serialize pending requests/completions, or retain each result with its queued completion and publish it as the current receive buffer only at the delivery boundary. Until a completion is delivered, later requests must not replace that result. If overlap is unsupported, reject it explicitly before changing data. Test two requests before pumping, a successful request followed by PRIMARY/failure, and a request issued from the first callback.

13. **MAJOR — Exported CF_UNICODETEXT violates the required newline format.** `src/win32/win32_plat.c:393`, `:398`.
    UTF-8 is converted verbatim, so copying normal LF editor text publishes bare LF in CF_UNICODETEXT. Windows specifies CRLF for that format; a self-round-trip of a single line cannot detect this interoperability bug. **Fix:** expand lone LF to CRLF when constructing the outbound UTF-16 buffer, leave existing CRLF pairs intact, and use checked length calculations. Inbound WideCharToMultiByte correctly preserves CRLF; the existing editor clipboard normalization already adapts received newlines to the destination style (`src/editor/clip.c:113`), so an extra destructive inbound normalization is unnecessary. Test external UTF-16 CRLF input and inspect externally published multiline text, including mixed LF/CRLF and supplementary characters. [CF_UNICODETEXT](https://learn.microsoft.com/en-us/windows/win32/dataxchg/standard-clipboard-formats).

14. **MAJOR — No enforced or documented HWND thread affinity; wrong-thread shutdown leaves live userdata pointing to freed memory.** `src/win32/win32_plat.c:363`, `:380`, `:385`, `:518`.
    This is conditional on a caller using a different thread, which the API currently does not reject or explicitly forbid. Windows requires pumping and destruction on the creating thread. A different-thread plat_run_for pumps the wrong queue; different-thread shutdown makes DestroyWindow fail, then ignores that failure, fails to unregister a class with a live window, closes the timers and frees `s`. The surviving HWND still has that freed address in GWLP_USERDATA. **Fix:** store the creating thread ID, document the affinity of the UI entries, reject wrong-thread run/configuration calls, and marshal destruction to the owner thread or retain state on destruction failure. Never free state while its HWND is live. Keep the documented T6 producer as an explicit cross-thread exception. Test wrong-thread run and shutdown without actually allowing a stale HWND pointer. [DestroyWindow thread restriction](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-destroywindow).

15. **MAJOR — Display interval is global composition timing, not the window's monitor timing.** `src/win32/win32_plat.c:454`.
    The function ignores `p` after its validity check and asks DWM for global timing. On a mixed-refresh desktop the result cannot describe the selected window's output; moving the window to another output still follows the same global query. Add two outputs with different rates and query each window/output association. 27. **MINOR — The live suite overstates native input and lifecycle coverage.** `tests/win/win32_plat_test.c:50`, `:95`, `:153`, `:209`, `:233`, `:241`.
    Most cases post one synthetic message, immediately pump it, and install keyboard state manually. The only SendInput check is F12 and may skip. The German branch may skip; no third layout or IME is tested. The DPI test edits cached DPI through a fabricated message on one monitor, which does not change Windows' actual monitor/DPI association. Handle-count checks cover successful lifecycle only and may hide a small leak behind unrelated handle retirement. T6 tests cover one producer record but not saturation, concurrent reset/disable, ordering, or retry. **Fix:** add focused regressions described above and API-shim fault injection for each CreateWaitableTimer/CreateEvent/RegisterClass/title-conversion/CreateWindow stage, GlobalAlloc/GlobalLock/EmptyClipboard/SetClipboardData, and timer arms. Verify exact owned-resource balances, event/data association, and pending-operation shutdown. Add ring/mailbox saturation and competing-producer tests. Add a real mixed-DPI/mixed-refresh monitor run, capture theft, system modal operation, Shift+Tab, CapsLock/NumLock effective modifiers, and non-German/IME text. Declare unavailable hardware/layout cases explicitly. Focus tests must also cover holding a key across loss and regain: current code cancels repeat and drops every subsequent bit-30 down until a fresh physical press; the desired regain policy needs an assertion. Desktop automation should show fixtures without activating them, per the Windows test design, with native foreground-only injection confined to an explicit interactive path.

The audited wait flags themselves are appropriate: QS_ALLINPUT includes sent-message/paint work, MWMO_INPUTAVAILABLE avoids sleeping over previously inspected input, and no WAITALL/APC requirement is introduced here. BeginPaint/EndPaint validates WM_PAINT; its delivery failure is the overflow/modal issue above. WM_DPICHANGED consumes the suggested RECT while it is valid. Signed wheel remainders retain fractional distance independently on both axes, including reversals; no rounding-loss or overflow defect was found for the signed native wheel range. Successful GlobalLock calls have matching GlobalUnlock calls, and opened clipboards are closed on the examined paths; the eagerly published HGLOBAL correctly transfers to Windows. Focus/activation default handling is retained, and focus changes cancel repeat/composition. No project allocation was found on the ordinary key-to-queue path.

The T6 SRW lock and reset-under-lock protocol protect the mailbox while the platform is alive. They do not protect backend_state from concurrent destruction: `src/win32/private.h:47` explicitly requires stopping/joining the renderer before shutdown. That precondition is adequate if integration enforces it; no unsupported concurrent-shutdown guarantee is assumed here. The borrowed work wake must likewise outlive the loop and be drained by its callback before mailbox consumption. Editor font/metric rescaling and the renderer/editor T6 wiring are already assigned to integration in the coordinator decisions; they are not counted again as new defects in this bead.

**Fix first, in order:**

1. Repair sent-message draining and modal servicing, preserving final geometry and control events; enforce HWND thread lifetime.
2. Establish one keyboard/text translation owner, then fix AltGr, VK_PACKET/IME, multiscalar input, Alt codes and native system keys.
3. Make clipboard operations asynchronous and retryable, preserve result lifetimes, and publish valid multiline Windows text.
4. Deliver capture cancellation and use the window's actual output for DPI/refresh and initial client sizing.
5. Add native-route, nested-loop, concurrency and failure-injection regressions; finish the smaller timestamp, timer, trace and coverage gaps.
