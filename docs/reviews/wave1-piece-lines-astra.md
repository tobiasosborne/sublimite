# Piece-tree line counts — freeze review

Let `C = 65,536 B` (P, the signed descriptor width, `2^16`). LF means the byte `'\n'`. The A13 gate covers a one-span mapped delete and its undo (G). The frozen header makes a stronger promise for general reference replacement. The traces below use its public inputs.

1. **COUNTER-EXAMPLE — source ends and destination cuts spend the same read budget.** Before worker adoption, insert ORIGINAL span `[1, 2C−1)` at the midpoint of a third untouched mapped chunk. Counting the span reads `2(C−1)` bytes. Splitting the unknown destination reads `C` more. Total `3C−2 = 196,606 B > 2C = 131,072 B` (P, two nearly full source ends and one whole destination). Even at EOF, where the ends alone fit A13's numerical bound, reading them contradicts `piece_replace_spans`’s promise of no source-byte reads. A vector can name arbitrarily many distinct partial ends up to the document limit. This does not require a failing one-span delete/undo fixture. To keep the general promise, allow unknown mapped *slices* until off-path metadata can answer source-range counts. Whole-chunk totals alone cannot do that even after adoption. Alternatively narrow the public promise explicitly and derive a bound for the whole call, including both deletion and insertion.

2. **COUNTER-EXAMPLE — replay can forget counted text.** Insert an ADD byte inside an unknown ORIGINAL chunk. A single pass over that chunk can count both halves (P, disjoint partition of `C` bytes). Remove the ADD byte. The halves now describe one canonical ORIGINAL span whether or not the tree coalesces them. Delete it, then undo before its worker batch arrives. If only worker adoption populates the table, replay makes the whole span unknown. The exact EOF prefix just before deletion is now inexact for identical restored text. Retain a validated whole total whenever a cut learns it, including on reassembly of counted halves. For a pristine *counted* cut, scan the shorter half and subtract from the parent, at most `⌊C/2⌋` bytes (P, complementary lengths). A private-copy open must retain the ORIGINAL chunk totals it learns while copying so whole-span replay is always exact. ADD range counts must use the queried view's chunk and prefixes. After an unaligned checkpoint abort, a surviving inside snapshot can have an LF where the regrown live ADD store has a different byte at the same logical offset.

3. **AMEND — define which root resolve completes.** Take snapshot S of an unknown root, begin a checkpoint there, then resolve the live tree while a worker queries S. Ordinary writes to shared fields race in C11. With immutable snapshots, only the UI rewrites, copying each shared path before publication. S keeps its previous answers, including inexact ones, even after close. A later take must expose the refined live root. Make a successful root replacement invalidate the snapshot cache and require a seek on live iterators holding old node pointers, even though the text revision is unchanged. A failed admission changes neither. Abort can restore the checkpoint's unknown root *after* the resolver reported done. Keep the source table, invalidate the traversal cursor and make that root eligible for resolve without allocating in abort. Scope completeness to the drained live root and snapshots taken from it. If it includes previously issued S, live-only COW cannot deliver it. Exercise both handles across resolve and abort.

4. **AMEND — charge discovery and COW separately.** A packed GiB has `2^30/C = 16,384` descriptors. Successive ceiling divisions by leaf capacity `24` and branch fanout `16` give `683` leaves and `43 + 3 + 1` branches (all P, signed packed builder). With the initial root pinned, resolving the entire live root can require `730 × 400 = 292,000 B` of additional node slots (P, one copy of each node, excluding headers and extent rounding). A located leaf costs O(h) to update, with at most `h+1` COW slots for its path (P, no split or growth). Reinsert the same whole uncounted chunk at many document positions. Its count can affect *every* leaf containing an occurrence, up to all leaves. Tiny counted fragments of that chunk require no rewrite under the proposed invariant. The source table has no occurrence addresses. A per-chunk search can revisit every unresolved leaf for every batch. A budgeted document-order sweep after table completion suffices for eventual live completeness. Charge visited nodes/entries including misses, retain safe progress across slices, and admit shared-path copies through the pool before publishing. On refusal leave the step retryable. Run maintenance before the post-submit top-up or restore the typing reserve afterward. `piece_reclaim`’s allocation-free contract does not transfer to COW resolve.

5. **COUNTER-EXAMPLE — a cached count outlives the bytes it counted.** Count an LF in a mapped suffix, queue its worker batch, then truncate and trigger SIGBUS in that suffix. L0 advances the epoch before replacing the suffix with zeros. A previously cached positive count can now exceed the actual count even as a *lower bound*. Bracket worker scans and UI cut/terminal scans with successful pristine polls (G, fault-lease “Read bytes”). Validate backing identity and pristine state again at adoption and at query publication, including cache-only queries on old snapshots. Discard tainted batches and cut counts before subtraction or publication. A conservative total query returns `exact=false` and lower bound zero on taint (P, LF counts are nonnegative). Select must report inexact too when it depends on that backing. L0 repairs addressability. Piece gates derived answers for every view. The file owner handles change detection and reload onto a fresh validated backing. The epoch supplies no affected offset and cannot certify an undetected same-size overwrite. State completeness and monotonicity for a trusted backing only.

6. **AMEND — define the final source chunk by its logical extent.** Open a one-byte mapping ending in LF (P, shortest nonempty LF file). The frozen mapped open reads zero bytes (G), so its tail cannot be counted there, yet it is shorter than `C`. Treat the entire interval `[kC, min((k+1)C, source_length))` as a whole chunk for open, adoption and replay. A subinterval of a short final chunk is still a slice.

7. **COUNTER-EXAMPLE — the branch flag consumes a valid count bit.** The signed document maximum is `2^64−1` bytes (G, frozen length domain). In that domain a child covering `2^47` repeated all-LF chunks has exactly `2^47 × 2^16 = 2^63` LFs (P, repeated source references are legal). This fits beside a nonempty sibling. Encoding unknown in bit 63 interprets its exact sum as unknown. This is a representation counter-example, independent of whether a machine admits that many descriptors. Preserve a full-width sum and encode unknown separately within a proved slot layout. Exercise the combine operation with synthetic full-width summaries.

8. **AMEND — rank and select need terminal-byte rules.** A counted descriptor's total cannot distinguish LF at its first byte from LF at its last. Rank at an interior offset needs a bounded prefix scan or source-rank metadata. At a boundary exclude the following entry, even if unknown. Select can descend an unknown-marked ancestor to find a target in its exact leading children. Once an unresolved preceding entry prevents locating the target, return inexact without scanning successive unknown entries. Specify the inexact offset, line origin, trailing-LF empty line and beyond-EOF result. A single-pass terminal search reads at most `C` bytes per query (P, one descriptor). A preliminary full count followed by a full search can read `2C` (P, two passes). Count query reads separately from edit reads, and count both if the edit itself calls the query.

9. **NOTE — simpler candidates still need document-order information.** Withhold exact mapped answers until the worker finishes, then publish only its chunk totals. While it works, replace the live text with slices from many distinct chunks. Move each chunk's sole LF inside or outside its selected slice. All published totals stay identical while the live EOF rank changes. With no counts for those slices, a terminal scan cannot recover the sum. Retaining counts only in leaves makes select near EOF visit every preceding leaf on an all-LF tree, violating A19's O(h) node-visit gate (G). A Fenwick tree over ORIGINAL plus ADD prefixes gives source order. Texts `A·B` and `B·A` over the same chunks, with an LF only in A, have identical source tables and different first LF offsets. Duplicating A repeats its contribution. Such an index can serve as a source-range oracle if it also indexes interiors. Document-order summaries still have a job.

**Verdict.** Hold the Lines freeze. Keep the document-order sums for rank and select. Settle the source-slice read contract, full-width representation and fault validity before promising exact answers. Name the root that resolve completes and fund the path copies that make that promise safe for snapshot readers.
