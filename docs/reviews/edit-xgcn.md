1. **BLOCKER — Disabled scrolling can overrun both caller cells and the backend instance allocation.** `src/d3d11/d3d11_win.c:344`, `:355`, `:363`, `:364`, `:409`.

   `render.h:72` says that zero `scroll.cols` disables the transform. Accordingly, `render_grid_storage` (`render.c:30`) validates/reserves an overscan row only when `cols` is nonzero; the other scroll fields are irrelevant when disabled. D3D11 instead tests `origin_y_q8` alone, requires a full frame, and expands its reads to `dims.rows + 1`. A valid full frame with `scroll.cols = 0`, a leftover nonzero origin, exactly `cols * rows` cells, and `max_cells` equal to that visible count passes the adapter and overruns both arrays in submit. Unvalidated extra cells can also supply arbitrary atlas indices. Disabled scrolling with `origin_y_q8 = INT64_MIN` reaches signed-overflow UB when draw negates it. A partial frame with the same disabled transform is incorrectly rejected even before these accesses. GL has the same origin-only expansion pattern; copying that pattern does not satisfy the frozen contract.

   **Fix:** Derive one enabled-transform predicate from `scroll.cols != 0`; normalize disabled scroll to a zero value in the snapshot. Gate fractional expansion, the full-frame restriction, and shift arithmetic on the enabled predicate. Add full/partial/zero-damage cases with disabled scrolling, nonzero unused fields, and exact visible-cell/instance capacities; include the signed minimum origin with scrolling disabled.

2. **BLOCKER — Copying whole atlas pages races the existing asynchronous font writer.** `src/d3d11/d3d11_win.c:348-352`.

   The contract freezes referenced glyph rectangles through T5, while permitting disjoint appends (`render.h:49-52`). It does not grant exclusive access to every byte in every page during submit. The production font worker writes an unretained tile at `src/font/async.c:393-398` before publishing its descriptor; the UI may submit already published glyphs meanwhile. All reserved pages are exposed by `async.c:201-206`. The unconditional page-wide `memcpy` therefore reads the tile concurrently with the worker's write, even though no cell references it. This is a C data race and undefined behavior. It also makes even a zero-damage submission scan every page. The test's unchanged, single-threaded atlas fixtures cannot reveal this problem.

   **Fix:** Follow GL's referenced-rectangle snapshot approach (`renderer.inc:1022-1037`, `:1079-1088`): reserve a glyph-seen bitmap and upload-damage metadata at init, copy only unique glyph rectangles used by the submitted draw strips, and upload only the affected cached spans. Do not solve this by blocking the font worker on UI. Add a synchronized concurrent-disjoint-append test with a portable snapshot helper under a race detector, plus a test that changes referenced coverage after the preceding T5 and immediately reuses caller metadata after submit. The current early copy does correctly avoid borrowing pixel pointers after submit; the problem is which bytes it reads during submit.

3. **MAJOR — Ordinary initialization advertises present timing without validating that it is available.** `src/d3d11/d3d11_win.c:306-315`, `:568-570`; `docs/decisions/edit-xgcn.md:9`.

   Both statistics calls discard their HRESULTs and data, init always succeeds, and `RENDER_CAP_PRESENT_TIMING` is always advertised. `background_init` is never examined. On a configuration where statistics are unsupported or permanently empty, ordinary init therefore adopts a backend that cannot finish its first real frame; event later fails or reaches the completion watchdog. `render.h:263-267` requires unsupported completion capability to fail init and explicitly permits deferred first-real-frame validation for background init. GL distinguishes those paths and probes ordinary init. The decision to defer both modes changes this behavior without changing the frozen contract. Every successful test init sets `background_init = true` (`tests/win/d3d11_test.c:229`), so ordinary init has no coverage.

   **Fix:** For ordinary init, validate query completion and matching present statistics on the init worker and return `RENDER_ERR_UNSUPPORTED` with full rollback when that cannot be established. Keep background init free of diagnostic presentations and retain its first-real-frame guard. Add both init modes, unsupported statistics, permanent empty statistics, and successful retry after such a failure. If another strategy avoids diagnostic presents, it still needs evidence sufficient to reject unsupported ordinary init before adoption.

4. **MAJOR — Passive polling is insufficient to update statistics on documented Hardware Flip Queue systems.** `src/d3d11/d3d11_win.c:537-560`.

   This path repeatedly calls the two statistics interfaces and then declares device failure if the exact record does not appear. Microsoft documents that Hardware Flip Queue systems may require `DwmFlush` before `GetFrameStatistics` updates. There is no such progress mechanism here, nor evidence that polling `GetFrameStatisticsMedia` removes that requirement. Thus a completed, displayed frame can leave the adapter busy until the watchdog disables a healthy backend. This is separate from rejecting genuinely unsupported capability at init: the display/presentation path may change later. The report's earlier unexplained all-zero statistics (`docs/worker-reports/edit-xgcn-s12.md`, “Found, not fixed”) remain relevant; keeping the test display on does not resolve the API limitation. [Microsoft: GetFrameStatistics](https://learn.microsoft.com/en-us/windows/win32/api/dxgi/nf-dxgi-idxgiswapchain-getframestatistics).

   **Fix:** Provide an ordered, non-UI-blocking way to obtain fresh statistics on affected systems, for example a reserved worker continuation that performs the required DWM synchronization and publishes an authenticated frame/generation result through `src/work`, followed by the UI statistics check. Otherwise explicitly reject the unsupported observation path and retain a usable fallback. Do not call blocking `DwmFlush` in present/event or substitute latency readiness for T6. Add a deterministic shim where statistics remain stale until the synchronization step and check the original ID and exactly-once hooks.

5. **MAJOR — Wall-clock expiry turns suspension or an undisplayed frame into permanent device failure without a recovery protocol.** `src/d3d11/d3d11_win.c:486-487`, `:510-512`, `:523`, `:549-560`.

   After one BUSY present, delay the UI beyond `D3D11_COMPLETION_NS` and retry. The retry fails before inspecting a now-signaled handle or completed query. The same occurs if `d3d11_poll_completions` runs first while the frame has not swapped. This can happen across system suspend or a native modal interaction without device removal. After a successful Present, an unavailable exact statistics record, including a frame suppressed during a visibility/session transition, also permanently latches `failed`. There is no visibility/session state or resume handling. The `DXGI_STATUS_OCCLUDED` branch cannot provide the intended visibility protocol: Microsoft specifies that flip-model chains do not return that status. `D3D11_COMPLETION_NS` is copied from GL, but GL's current X11 watchdog distinguishes a stalled server and rearms after a liveness round trip (`renderer.inc:1178-1205`). [Microsoft: DXGI status codes](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/dxgi-status).

   **Fix:** Define the W1.1 visibility, session, suspend/resume, and completion-recovery protocol. Avoid starting invisible work, suspend/rebase the relevant watchdog during known suspension, and observe actual readiness before expiring a retry merely because UI was absent. If an already submitted frame cannot receive matching T6, preserve that truth: retire the failed backend through quiescent shutdown and rebuild/repaint on a worker under an explicit caller recovery path. Never acknowledge a different frame or release the slot using the latency signal. Add delayed BUSY retries, minimize/restore, lock/unlock, and a deliberately missing/dropped statistics record; verify usable rendering after recovery. With the current code, the concrete dropped-frame outcome is bounded terminal failure, not a fabricated T6 or an infinite BUSY loop.

6. **MAJOR — Moving, shrinking, or disabling the RGB region leaves its old pixels in the retained output.** `src/d3d11/d3d11_win.c:377-385`, `:445-452`, `:467-472`.

   The region is baked into `s->target`, but only cell strips restore underlying pixels. Start with a full frame containing a region, then submit zero cell damage with `region.pixels = NULL`: submit and present succeed, yet the old region remains indefinitely. Moving the region with `dirty = true` similarly paints the new location and leaves the old location behind; shrinking leaves its removed edges. These are valid independent-region changes under `render.h:80-85`, and the scalar oracle reconstructs the correct scene without those stale pixels. An enable/resize/reposition with zero cell damage and `dirty = false` is also skipped because the upload predicate ignores the preceding region's existence and geometry. Conversely, any cell damage forces a full CPU region copy and GPU upload even when its pixels are unchanged. GL separates upload decisions from its final region blit, although its retained-region removal behavior also needs care.

   **Fix:** Keep the preceding enabled state and bounds. Recompose exposed old bounds from the retained uncomposited scene, with the current scroll transform, independently of caller cell strips. Separate “upload changed region pixels” from “composite the cached region over newly composed output”; initialize/reupload for first enable or size changes. An unchanged region covering a damaged cell still needs composition, not another pixel upload. Add zero-cell-damage enable, move, shrink, disable, and re-enable cases, checking the entire old/new bounds against `raster_kernel.c` and `raster_blit_pixels`.

7. **MAJOR — Teardown flushes before releasing resources, so it does not guarantee destruction before replacing the flip swapchain.** `src/d3d11/d3d11_win.c:68-98`.

   `ClearState` and `Flush` run while all explicit texture/view/swapchain references are still held. The releases follow, with no final flush on the surviving immediate context. D3D11 permits deferred destruction; releasing the last application references is not enough to guarantee that another flip chain can immediately attach to the same HWND. This matters for failure rollback, device recovery, and repeated init/shutdown, especially when diagnostic interfaces keep the old device alive, as this test intentionally does. It is a destruction-order issue rather than an obvious missing `Release`. A driver that destroys these objects eagerly can pass the existing test. Microsoft prescribes releasing references and then clearing/flushing before creating a replacement chain. [Microsoft: Flush and deferred flip-swapchain destruction](https://learn.microsoft.com/en-us/windows/win32/api/d3d11/nf-d3d11-id3d11devicecontext-flush).

   **Fix:** Preserve the initial drain as needed, release views/textures/backbuffer and both swapchain interface references while the immediate context remains alive, then perform the final `ClearState`/`Flush` before releasing context/device. Apply the same order to partial-init rollback. Test immediate same-HWND reinitialization after a presented frame and after a failure occurring after swapchain creation, including while a diagnostic device interface remains retained. Check DXGI objects as well as D3D device children.

8. **MINOR — The HWND binding API omits essential lifetime and message-pump obligations for W1.1.** `src/d3d11/d3d11.h:6-9`, `:14-21`; `src/d3d11/d3d11_win.c:280-283`, `:303`, `:573-577`.

   The header specifies state lifetime but not HWND lifetime or who must dispatch its messages during init/failed-init cleanup. `IsWindow` is only a momentary check; it cannot pin a window against `WM_CLOSE`/destruction while the worker proceeds into DXGI. A platform implementation following only this public header can destroy/reuse the handle during init or block the window thread waiting for a worker that synchronously messages it. The test and decision document know to pump; the integration contract needs to say so. Background init also needs an explicit ownership arrangement if a bootstrap already owns a flip chain: DXGI permits one such chain per HWND, and this backend creates its chain in initial init with no `finish_init`. [Microsoft: DXGI multithreading](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/d3d10-graphics-programming-guide-dxgi), [CreateSwapChainForHwnd](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_2/nf-dxgi1_2-idxgifactory2-createswapchainforhwnd).

   **Fix:** Document a borrowed HWND that survives physical worker completion, any failed-init native cleanup, and successful quiescent shutdown; keep the owner thread pumping while joining. Define close-during-init cancellation/adoption behavior and removal of the borrowed latency handle from the UI wait set before shutdown closes it. State the supported bootstrap arrangement; if it owns a flip chain, share/transfer that chain or defer acquisition until it has been destroyed. Add close-during-init and bootstrap-adoption integration tests. Exclusive worker-to-UI handoff of the immediate context itself is sound; it does not require use forever on its creating thread.

9. **MINOR — Native initialization failures discard the information needed to diagnose or choose recovery.** `src/d3d11/d3d11_win.c:64-65`, `:149-161`, `:194-220`, `:300-319`, `:334-335`; `tests/win/d3d11_test.c:244`.

   Device/resource/swapchain helpers collapse HRESULTs to `bool`; compile errors are released without retaining their text; missing `d3dcompiler_47.dll` and shader/resource failures all become generic init errors. `d3d11_fail` also loses the reason on several runtime paths, leaving `present_info.status` stale or unrelated. The test then prints `GetLastError`, which is not the HRESULT result of these COM methods. An absent compiler DLL does unwind through the cleanup path, and both compiler blobs appear balanced; the missing behavior is an actionable failure record, not a demonstrated blob leak.

   **Fix:** Preserve an operation tag plus HRESULT, and capture Win32 error values immediately for loader/wait failures. Copy a bounded compiler diagnostic into init-reserved state before releasing its blob. Make this diagnostic accessible after failed init using caller-owned storage or a D3D-specific result API without changing `render.h`, and preserve the actual device-removal reason before teardown. Exercise absent DLL, absent export, compile failure with an error blob, shader creation failure, and resize/device errors. Keep formatting/reporting outside UI render calls.

10. **MINOR — The suite does not exercise native acquisition failures, retry sequencing, or the full lifetime inventory it claims to verify.** `tests/win/d3d11_test.c:81-116`, `:125-188`, `:234-247`, `:295-319`.

    The explicit failed-init/retry case is NULL platform identity, rejected before arena/native acquisition. Forcing WARP does not exercise failed hardware creation followed by WARP, or a missing-debug-layer retry. Success on the desktop therefore provides no failure-path evidence for COM/handle/compiler cleanup, caller-arena rollback, device loss, resize failure, or a failure of `GetLastPresentCount` after Present has committed. The leak census covers D3D11 children, not DXGI swapchains/factories, compiler blobs/libraries, or the latency handle. Its deliberately visible, topmost, display-kept-on window and blocking diagnostic readback also leave the liveness problems above untested.

    **Fix:** Add a deterministic C-vtable/native-call fault harness alongside real hardware/WARP pixel tests. Fail every acquisition stage after earlier successful acquisitions; check reference and handle balances, supplied-arena marks, successful retry on the same HWND, and absence of callbacks after shutdown. Script `GetData` pending/ready/error and repeated `DXGI_ERROR_WAS_STILL_DRAWING`, asserting one draw/query issuance and one successful native Present per frame. Inject device-removed/reset at Map/GetData/Present/ResizeBuffers and verify the documented worker reinitialization path without UI allocation. Make `GetLastPresentCount` fail after successful Present and assert that retry cannot submit it again. Exercise stale, disjoint, empty, and skipped-count statistics and UI-owned readiness consumption. Include native counter zero/wrap cases or enforce and test a pre-wrap reinitialization invariant; application frame IDs and DXGI present IDs are separate domains. The current `!= 0` and raw `>` checks (`d3d11_win.c:549`, `:556`) are not general modular-counter handling. A natural counter wrap is not demonstrated reachable here: a fresh chain issues one successful Present per adapter frame, performs no init Presents, and the adapter requires restart before its own IDs wrap. Do not present that conditional hardening issue as a reproduced ordinary-session failure.

Other audited paths: the explicit C COM acquisitions for device/context, temporary DXGI device/adapter/factory/chain, textures/views/buffers/shaders/query, and both compiler blobs have corresponding releases in the inspected success/error branches. The backbuffer has no RTV/SRV in this implementation; resize clears bindings and releases its texture reference before `ResizeBuffers`, preserves the waitable flag, then reacquires the buffer. There is no evidence for a blanket missing-backbuffer-view-release finding. The latency handle is caller-owned and closed, as required by [GetFrameLatencyWaitableObject](https://learn.microsoft.com/en-us/windows/win32/api/dxgi1_3/nf-dxgi1_3-idxgiswapchain2-getframelatencywaitableobject). Its wait precedes the first and later draws. `SetMaximumFrameLatency(1)` is applied to the swapchain itself. Together with the adapter's one active frame through both hooks, this supports the promised application queue depth; the two flip buffers are not evidence of two queued frames. A single query is sufficient under that ownership rule. Query readiness precedes successful Present, T4 precedes UI hook delivery, and capturing `GetLastPresentCount` after the successful Present is the appropriate correlation source. Observation time avoids misusing `SyncQPCTime`. `WAS_STILL_DRAWING` retains the existing draw, and failure after a committed Present does not invite a duplicate submission. No explicit application allocation or native resource creation was found on submit/present/event; diagnostic readback is explicitly blocking and test-only. Native runtime/driver allocation is outside the Windows malloc guard's stated coverage.
