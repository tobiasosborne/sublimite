# edit-3620 (s9) worker report

## Cause
`editor_check_sources` Keep branch (src/editor/buffers.c): `if (stat == FILE_OK
&& rebase_kept_target(...)) return 0;` — a stat error (FILE_ERR_IO, e.g.
EACCES) skipped both the rebase and the early return, so Keep dismissed the
prompt with the controller still on the pre-rename baseline. Deterministic for
a Save As (rebound) COPY buffer without a journal, where this stat is the
first one Keep makes.

## Fix
Stat failure now takes the refused-rebase exit (prompt retained), and both set
the notice `Keep failed: R reload / K keep` (the save overlay draws notices
over the prompt row, so it repeats the choices). Cleared on a later
successful Keep or on Reload. See docs/decisions/edit-3620.md.

## Files touched
- src/editor/buffers.c (Keep branch, notice string, clear on Reload)
- tests/editor_session_test.c (`kept_target_unreadable`, `--edit-3620`, in main)
- docs/decisions/edit-3620.md, this report

## Outside scope (observed, not fixed)
After Save As (COPY, no journal), a plain Ctrl+S is followed by a clean reload
that replaces the editor_buffer (e->buffer != the pre-save pointer), and Ctrl+Z
afterwards no longer undoes the pre-save edit (probe: type 'x', save, Ctrl+Z,
first byte still 'x'). Likely the target watch sees the save's own rename and
flags FILE_MSG_OPEN_FAILED before the controller baseline is updated
(buffers.c around the target_watch loop). Undo history loss on save in a
Save-As'd file could affect trial use. Probe was a temporary test edit, removed.
